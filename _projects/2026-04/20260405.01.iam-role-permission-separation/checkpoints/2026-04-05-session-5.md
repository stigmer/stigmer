## Decisions Made

- **Pure JUnit 5, no Mockito**: `ValidateGrantableRole` has zero constructor dependencies and reads from a static utility backed by proto metadata. Testing with real protobuf objects and real proto metadata is cleaner, faster, and provides better coverage than mocking. It also avoids introducing Mockito as a new build dependency.
- **Tests as contract tests**: By testing against real proto metadata (grantable_roles configured per ApiResourceKind), the tests double as contract tests for the authorization model. If someone changes agent's grantable roles in the proto, the test will break — this is intentional and desirable.
- **Pipeline construction tests deferred**: Verifying step count and ordering requires instantiating `IamPolicyCreateHandler` with all 9 constructor dependencies, which means mocking interfaces. Since Mockito is not in the Bazel build graph, this is a follow-up task paired with build infra work.
- **Selective commit**: Only committing the test file and BUILD.bazel changes (iam-role-permission-separation scope). The `ValidateSsoFields.java` bug fix lives in an untracked file from the identity-provider-flow and will be committed with that feature.

## Key Code Changes

- **`ValidateSsoFields.java`** (bug fix): `.formatted(org)` was applied to only the second string literal due to Java operator precedence. Added parentheses around the concatenated string.

## Learnings

- **Bazel strict deps**: Bazel enforces that every type used in a compilation unit must come from a direct dependency, not a transitive one. Even though `stigmer_service_lib` transitively depends on `grpc-request` and `grpc_api`, the test target must declare them directly.
- **Dead test code**: Several existing test files (`IdentityProviderDeleteHandlerTest`, `SearchHandlerTest`, workflow execution handler tests) import Mockito and have well-structured tests, but they have no `java_junit5_test` targets in `BUILD.bazel`. They are never compiled or run by `make test-backend`. This is a build infra gap worth addressing.
- **Java `.formatted()` operator precedence**: `"A" + "B".formatted(arg)` applies `.formatted()` to `"B"` only, not `"A" + "B"`. Must wrap in parentheses: `("A" + "B").formatted(arg)`. This is a common Java footgun that error-prone catches with its `FormatString` check.
