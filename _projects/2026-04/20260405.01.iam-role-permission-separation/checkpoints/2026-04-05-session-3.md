## Learnings

- Proto file-level imports and Go package-level imports are fundamentally different. A proto file can be a "leaf" with zero imports, but if it shares a package with files that have imports, the entire Go package inherits those dependencies. Session 2's verification ("enum.proto is a leaf with zero imports") was correct at the proto level but insufficient for Go.
- The `iampolicy/v1` package is "fat" — it contains `api.proto`, `command.proto`, `query.proto`, `io.proto`, `spec.proto` which import from `apiresource`, `apiresourcekind`, `rpc`. Any package importing `iampolicy/v1` for the enums also inherits these transitive Go dependencies.
- Vocabulary types (enums that many packages need) should live in their own leaf package to avoid import cycles in Go. This is a Go-specific concern — Java, Python, and TypeScript don't have this problem because they resolve imports per-class or per-file.
