## Decisions Made

- **IamRoleMetadata as utility class**: Roles are a fixed, small set (owner/admin/member/viewer). No need for database storage — immutable map in Java is simpler and faster than a MongoDB collection.
- **In-application enrichment over denormalized index**: Batch-loading from `IdentityAccountRepo` avoids write-time synchronization complexity of maintaining an `api_resource_index` collection. Acceptable for access-list views which typically have bounded result sets.
- **Application-level hierarchy traversal**: Resource ownership chains are shallow (typically 2-3 levels: platform -> org -> resource). Simple loop with capped iteration (max 10 hops) is clearer and more maintainable than MongoDB's `$graphLookup` aggregation for this use case.
- **Scope tuple convention**: Hierarchy is determined by IAM policies with structural relations matching the parent's `ApiResourceKind` name (e.g., an organization's scope tuple has relation "platform" pointing to the platform resource). `findScopeTuple` queries these.
