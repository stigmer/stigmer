## Decisions Made

- **Provider tree bifurcation over AuthGuard bypass**: Instead of adding `/login` to an AuthGuard bypass list (which would still render OrgProvider, StigmerTransportBridge with their unauthenticated failure modes), the login page gets an entirely separate provider tree. This avoids the cascade: OrgProvider fails → onUnauthenticated fires → logout() redirects away.
- **SDK component boundary**: `SsoLoginPrompt` (org discovery + SSO button) lives in `@stigmer/react`. OIDC redirect mechanics (oidc-client-ts) stay in Console. Platform builders get the UI; they bring their own auth library.
- **Shared `/auth/callback` with sessionStorage routing**: SSO and Auth0 share the same callback URL. Two sessionStorage keys (`stigmer:sso:login` for ephemeral pre-callback state, `stigmer:sso:session` for persistent session) distinguish the flows. No new route needed.
- **Local-only logout for SSO**: No RP-initiated logout with the SSO IdP (avoids IdP-specific endpoint complexity). Clear sessionStorage, `removeUser()`, redirect to `/login?org=...`.
- **Unauthenticated Stigmer client via `getAccessToken: () => null`**: The SDK's `validateConfig` accepts this (it checks `typeof getAccessToken === "function"`), and the auth interceptor skips the Authorization header when token is null. Clean pattern for pre-auth pages.

## Learnings

- `oidc-client-ts` `UserManager` stores sessions in sessionStorage keyed by `authority + client_id`. Auth0 and SSO managers have different keys, so they coexist without conflict. The `UserManager` created for `signinRedirect()` stores PKCE state, and a different `UserManager` instance (same config) can retrieve it via `signinRedirectCallback()`.
- The SDK's `TokenProvider` returning `null` is a documented, intentional pattern — not a workaround. It enables unauthenticated API calls through the same client infrastructure.
- Next.js `useSearchParams()` in static export requires a `Suspense` boundary. The login page wraps the inner component in `<Suspense>` to satisfy this.
- The existing `OrgProvider` and `StigmerTransportBridge` are tightly coupled to authenticated state via their `onUnauthenticated` interceptor. Any pre-auth page must bypass them entirely, not just bypass AuthGuard.

## Open Questions

- Token refresh for SSO sessions: depends on whether the SSO IdP honors `offline_access` scope and issues refresh tokens. If not, the token expires and the user must re-authenticate.
- RP-initiated logout with SSO IdP: deferred. Most enterprise IdPs require specific logout endpoint configuration. Local-only logout is sufficient for now.
- "Already authenticated" redirect on `/login`: if a user navigates to `/login` while already authenticated, they currently see the login form. Could redirect to `/` instead (follow-up).
