## Decisions Made

- **Separate SsoAutoProvisioner component**: Instead of modifying `FederatedIdentityResolverImpl` (as originally suggested in the plan), introduced a new `SsoAutoProvisioner` interface to preserve the resolver's read-only contract. The mapper orchestrates the fallback.
- **Backward-compatible constructor**: Added 5-arg `FederatedAuthenticationToken` constructor (defaults `isSsoProvider` to `false`) to avoid breaking existing code like `AuthenticationTokenParserTest`.
- **IamRole.viewer (not IamPermission)**: The viewer concept lives in `IamRole` enum, not `IamPermission`. Fixed after initial compilation error.
- **System credentials for provisioning**: `SsoAutoProvisionerImpl` uses `IdentityAccountGrpcRepo` and `IamPolicyGrpcRepo` which both use `inProcessChannelAsSystem` — correct for system-level operations during the authentication flow where no user context exists yet.
- **Best-effort role grant and caching**: Role assignment and Redis caching failures are logged as warnings but don't fail the provisioning — the account is still created successfully.

## Learnings

- The `IdentityProviderIssuerCache` already holds the full `IdentityProvider` document, so checking `is_sso_provider` doesn't require a separate cache — it's available from the `FederatedJwtAuthenticationProvider` which reads the spec directly.
- `@Autowired(required = false)` is the right pattern for optional dependencies like `SsoAutoProvisioner` — the mapper degrades gracefully if no provisioner is configured.
- Mockito tests in this repo were previously not in the Bazel build cycle. Adding `mockito-core` and `mockito-junit-jupiter` to `MODULE.bazel` enables all Mockito-based tests to be registered as Bazel targets.
- Race condition handling via `ALREADY_EXISTS` + re-query is a well-established pattern in this codebase (similar to invitation redemption).

## Open Questions

- Auto-provisioning vs deprovision tension remains: a revoke-only deprovisioned user could re-provision via SSO on next login. This may be acceptable (org admin must delete, not just revoke, for permanent removal) but should be documented in Phase 6.
