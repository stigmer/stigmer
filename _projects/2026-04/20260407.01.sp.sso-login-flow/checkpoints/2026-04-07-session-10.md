## Decisions Made

- **SSO as a parallel path, not a sequential step**: The federation overview now presents two distinct tracks (platform-managed and self-managed SSO) rather than treating SSO as an extension of the existing federation flow. This reflects the fundamentally different audience (platform developers vs org admins) and onboarding patterns.
- **Heading "Revoke" instead of "Deprovision"**: Vale flagged "Deprovision" as a spelling error. Rather than suppressing, we renamed the heading to "Revoke a federated account" — clearer for readers and avoids the lint issue. The API method name `deprovisionFederatedAccount` is retained in backticks.
- **4-step demo (not more)**: Each step introduces a new surface (ManagementShell, login page, external IdP, console). Two cursor moments match the two user actions. No repeated views, no filler steps.
- **Mock content for demo**: Both `IdentityProviderDetailPanel` and `SsoLoginPrompt` require live protobuf/hook infrastructure. Following the same pattern as `register-idp-playback` and `provision-grant-playback` — static mocks where backend state is needed.

## Learnings

- Vale's `Microsoft.Auto` rule flags all hyphenated "auto-" compounds in prose. Rephrasing to "creates automatically" or "automatic provisioning" consistently passes without needing comment-based suppression.
- Vale comment-based suppression (`<!-- vale off -->`) is unreliable for MDX headings. Rephrasing is always the safer approach.
- The `onStepChange` callback in `ScenarioPlayer` has signature `(data: T, index: number)` — both parameters must be accepted even if index is unused.
