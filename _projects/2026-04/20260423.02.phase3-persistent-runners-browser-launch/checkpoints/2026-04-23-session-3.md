## Decisions Made

- **DD-T05-01: exec.Command over Docker SDK** — Shell out to `docker` binary instead of using the Go Docker SDK. Rationale: the operations are trivially simple (run, stop, rm, inspect), the SDK adds a massive dependency tree (~15MB+), and shelling out provides free Podman/nerdctl compatibility. Wrapped behind a `DockerClient` interface for testability and future swap.
- **DD-T05-02: CLI-local runtime type** — Runtime (native/docker) is stored only in the local state file. The server sees an identical runner regardless of how it was started. Proto modeling deferred until user feedback reveals what the server/UI needs to know. This keeps the beta lean and avoids premature contract commitment.
- **DD-T05-03: Backward-compatible state extension** — `RunnerState` gains `Runtime` and `ContainerID` with `omitempty` JSON tags. Old state files without these fields deserialize with empty strings, which `IsDocker()` treats as native. Zero migration needed.
- **DD-T05-04: Container naming** — `stigmer-runner-<slug>` convention makes containers discoverable via `docker ps`.
- **DD-T05-05: Version-tied image default** — `ghcr.io/stigmer/agent-runner:<cli-version>` with `--image` override. Reduces version skew between CLI and agent-runner.

## Key Code Changes

- `docker.go` (new): DockerClient interface + execDockerClient implementation with 7 methods, plus WaitUntilRunning, IsContainerAlive, DefaultImage helpers
- `state.go`: RuntimeNative/RuntimeDocker constants, IsDocker() method, isRunnerAlive() dispatcher replacing direct isProcessAlive() calls
- `start.go`: Strategy pattern — Start() dispatches to startNativeRunner() or startDockerRunner() via registeredRunner struct. buildDockerEnv() mirrors key vars from BuildRunnerEnv as a map for -e flags
- `stop.go`: StopRunner dispatches to stopNativeRunner (SIGTERM/SIGKILL) or stopDockerRunner (docker stop + docker rm)
- `up.go`: --runtime and --image flags on both `stigmer up` and `stigmer up runner`

## Learnings

- The existing `Start()` function was a single monolithic flow mixing registration, Python bootstrap, process management, and stream lifecycle. The strategy pattern refactoring cleanly separated concerns while preserving identical behavior for the native path.
- Docker container health polling via `docker inspect --format '{{.State.Running}}'` combined with `docker wait` for exit blocking provides a clean lifecycle model parallel to the native PID-based approach.
