## Decisions Made

- **Dedicated `stop` RPC over `sendCommand` routing** — `can_edit` vs `can_view` authorization mismatch, `Runner` vs `RunnerCommandResponse` return type, cleaner API boundary between lifecycle ops and operational commands.
- **Python agent-runner out of scope** — Go CLI daemon manages the bidi stream and child process lifecycle. Python has no involvement in stop signaling.

## Learnings

- The `commandResult` pattern (pairing response + side-effect flag) is a clean way to handle "command dispatch returns a response but also needs to trigger control flow changes" without channels or callbacks.
- `ErrServerRequestedStop` as a sentinel error propagating from `recvLoop` → `streamLoop` → `Run` provides clean layering: each level reacts appropriately (ack → graceful stop → exit without reconnect).
