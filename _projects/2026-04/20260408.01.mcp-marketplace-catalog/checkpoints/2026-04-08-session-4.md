## Decisions Made

| Decision | Rationale |
|----------|-----------|
| Automate via Temporal workflow, not CLI command | Scheduled, reliable, observable, no manual trigger needed |
| Official MCP Registry is Phase 1 source | Only source with structured REST API + `server.json` schema; others lack APIs or overlap |
| Synced servers go to DB, not seedpack | Seedpack is compile-time embedded; DB is the right place for continuously-updated catalog |
| Delete all handcrafted marketplace YAMLs | They'll be auto-synced from registry; keeping them causes duplication |
| `metadata.name` from registry `title` field | Human-friendly display; raw registry name preserved in `source.registry_name` |
| `metadata.slug` as dot-separated form | `ai.exa/exa` → `ai.exa-exa` (replace `/` with `-`) |
| All synced servers `visibility_public` | Marketplace entries should be visible to everyone |
| Leave `stigmer.ai/category` empty | No auto-classification; avoids unnecessary complexity |
| Deprecation via `stigmer.ai/deprecated` label | Servers removed from registry get labeled, not deleted |
| Preserve `default_tool_approvals` and `discovered_capabilities` on upsert | Sync updates registry-sourced fields only; hand-edited and discovered data is never overwritten |

## Learnings

- The official MCP Registry API is at `/v0/servers` (not `/v0.1/servers` as previously noted)
- Registry entries use reverse-DNS naming (`ai.exa/exa`) and include multiple versions per server; `_meta.isLatest` is the dedup signal
- Most registry entries are remote HTTP servers; `packages[]` (npm/pypi) provides structured env var data; `remotes[]` provides header-level auth info
- Other directories (Smithery, mcp.so, etc.) either lack public APIs or overlap significantly with the official registry
- The `save()` method in `AbstractMongoApiResourceRepository` does `replaceOne` with upsert on `metadata.id` — works for both create and update
