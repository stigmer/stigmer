## Decisions Made

| Decision | Rationale |
|----------|-----------|
| Strict mode for stdio arg interpolation | Lenient mode (used by HTTP) would silently pass `${VAR}` as literal to subprocess, causing confusing failures. Strict mode gives clear "Missing required environment variable" errors. |
| Only interpolate `args`, not `command` or `working_dir` | `command` is a fixed executable name; `working_dir` is a deployment concern. Neither should contain per-user values. |
| `go run` for official GitHub MCP server | Docker requires Docker; HTTP remote requires Copilot infra. Go toolchain already present on agent-runner (used by `mcp-server-stigmer`). Consistent with existing pattern. |
| Added `GITHUB_HOST` and `GITHUB_TOOLSETS` to `github.yaml` env_spec | Optional entries that surface Enterprise and toolset filtering in the UI. Better to declare than hide. |
| Documented argv security note | Process args visible via `/proc/<pid>/cmdline`; env vars restricted to `/proc/<pid>/environ`. Not a practical risk in containerized agent-runner, but worth documenting. |

## Learnings

- The `PlaceholderResolver` class was already well-designed for reuse — strict vs lenient mode, context strings for error messages, and metadata tracking. Adding stdio interpolation required only 1 new function and wiring it in.
- The official `github/github-mcp-server` is Go-only. No npm distribution. `go run` with `@latest` is consistent with the `mcp-server-stigmer` pattern.
- `env_spec` is a beautifully clean abstraction: it declares "what does the server need from the user?" without coupling to how the server consumes the values (env vars vs CLI args vs HTTP headers). The interpolation change preserves this abstraction.
