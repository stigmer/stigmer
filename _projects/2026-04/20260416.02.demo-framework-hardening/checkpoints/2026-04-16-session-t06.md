## Decisions Made

- **`showRipple` prop (not mode enum)**: Chose a simple boolean prop on Cursor rather than a `mode: "click" | "hover"` enum. Simpler API, more precise about what it controls, and fully backward-compatible.
- **Separate `setShowRipple` callback**: Added as an optional callback to `UseStepInteractionsOptions` rather than extending the `setCursorTarget` signature. Zero changes to existing scenarios.
- **Dual event families**: Dispatch both `PointerEvent` and `MouseEvent` instances because Radix uses pointer events while many custom components use mouse events.
- **`data-hover` attribute pattern**: Follows the existing `data-cursor-target` / `data-scroll-target` convention. Progressive enhancement -- zero cost for components that don't opt in.
- **1500ms default hold**: Long enough for tooltip readability, short enough to not stall demos.

## Learnings

- CSS `:hover` cannot be triggered by JavaScript -- the `data-hover` attribute pattern is a clean workaround that follows existing conventions
- React 18 batches state updates from setTimeout callbacks, so `setShowRipple(false)` and `setCursorTarget(target)` in the same timer are atomic from the render perspective
- The Cursor's live-site useEffect intentionally does NOT include `showRipple` in its dependency array -- this prevents unwanted ripples when `showRipple` is restored to `true` during hover leave
