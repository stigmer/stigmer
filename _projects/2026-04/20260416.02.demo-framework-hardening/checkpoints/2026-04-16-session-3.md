## Decisions Made

1. **Action name `"type"`** — Shortest, most natural verb. `type: "type"` is visually quirky but syntactically unambiguous. Consistent with the brevity of `"click"`, `"scroll-to"`.
2. **Auto-move cursor (three-phase, consistent with `click`)** — Phase 1: cursor moves at `atPercent`. Phase 2: typing starts after `CLICK_DELAY_MS` (450ms). Phase 3+: characters at `typeDelay` intervals. The 450ms pause mimics real human behavior.
3. **Reuse `data-cursor-target` (no new `data-type-target`)** — Unified targeting model. `resolveInput` finds the actual input inside the target element, so SDK components don't need modification.
4. **No contenteditable support in V1** — Current demos use `<input>` and `<textarea>` only. Defer contenteditable until a real use case arises.
5. **No text-cursor visual variant in V1** — Pointer cursor stays during typing. Native input caret provides visual. Custom blinking-caret is a future enhancement.
6. **`typeDelay` overridable per-action** — Default 50ms from timing constant, but scenarios can set `typeDelay` for faster/slower typing speed.

## Learnings

- The `nativeInputValueSetter` pattern (`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set`) was already proven in two places (`TypingComposer`, `PrefilledCreateForm`). Extracting it into the engine as `typeTextIntoTarget` was straightforward.
- The three-phase model extends naturally from `click`'s two-phase model — the cursor move logic is identical, only the post-arrival behavior differs (click dispatch vs character-by-character typing).
- Pre-scheduling all N character timers upfront (browser path) is consistent with the existing pattern and cleans up properly via the effect's teardown function. No interval or recursive timeout needed.
- In the video path, computing `charCount` from elapsed time (`Math.floor((elapsed - typingStart) / charDelay) + 1`) is more natural than tracking N separate threshold keys, but using `firedRef` per-character-count avoids redundant DOM updates on the same frame.
- Pre-existing test failures from `multi-tenant-setup.mdx:542` (MDX syntax error) affect all page-load tests when a fresh WebServer compiles. Not related to T05.
