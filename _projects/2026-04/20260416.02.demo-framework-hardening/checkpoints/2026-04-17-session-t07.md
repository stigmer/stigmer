## Decisions Made

1. **Pointer events, not HTML5 drag events**: Modern drag libraries (dnd-kit, react-beautiful-dnd) use pointer events. HTML5 drag events require `DataTransfer` objects that have browser limitations when synthesized. Pointer events are reliably synthesizable and forward-compatible.

2. **`data-cursor-target` for both source and destination**: Rejected the T07 plan's proposal for `data-drag-source` and `data-drag-target` attributes. All existing actions use `data-cursor-target` for element lookup. The unified targeting model is preserved — `target` field maps to source, new `dragTarget` field maps to destination, both resolve via `data-cursor-target`.

3. **Straight-line cursor path for V1**: The T07 plan mentioned curved paths for natural feel. Used the same Framer Motion spring animation as all other cursor movements. Curved paths add complexity (custom animation interpolation) for marginal visual benefit. Flagged as future enhancement.

4. **Reuse existing Cursor animation infrastructure**: Phase 1 calls `setCursorTarget(source)`, phase 3 calls `setCursorTarget(dragTarget)`. The existing spring animation handles both movements. Only new Cursor concern is the icon swap (`isDragging` prop).

5. **`setDragging` callback (same pattern as `setShowRipple`)**: Added as an optional callback to `UseStepInteractionsOptions`. Zero changes to existing scenarios. Follows the exact precedent set by T06's `setShowRipple`.

6. **`DRAG_SETTLE_MS = 200`**: Brief pause between pointerdown and the start of cursor movement. Mimics the human hesitation between pressing and dragging. Short enough to not stall the demo, long enough to be perceptible.

7. **Validation via new scenario, not existing scenario modification**: No existing scenario has a natural drag use case. Created `drag-reorder-validation` as a purpose-built validation fixture. Not registered in SCENARIO_REGISTRY — it's not a recordable demo.

## Learnings

- The four-phase model extends naturally from the patterns established by click (2-phase), type (3-phase), and hover (3-phase). The key insight is that the cursor's target can be changed mid-action to drive movement between source and destination — no custom animation infrastructure needed.
- The `setDragging`/`isDragging` pattern mirrors `setShowRipple`/`showRipple` exactly. Both are optional callbacks that coordinate visual state between the hook and the Cursor component. This consistency means future interaction types can follow the same pattern.
- React 18 batches the `setShowRipple(false)` and `setCursorTarget(target)` calls in phase 1's setTimeout callback, so they are atomic from the render perspective (same learning as T06).

## Open Questions

- The `GrabCursorIcon` SVG is hand-crafted. Visual fidelity should be verified in the browser at different zoom levels and against both light and dark themes.
- Whether `pointermove` events should be dispatched during the cursor's travel from source to destination (not implemented in V1 — no current use case requires it).
- Whether the straight-line spring animation looks natural enough for real demos or if a curved path should be prioritized.
