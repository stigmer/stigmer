# Session Notes: 2026-04-03, Session 5 — Last-Step Narration Cutoff Fix

## Accomplishments

- Identified and fixed a timing bug where the final step's narration audio was immediately paused after starting
- Root cause: the auto-advance timer effect in `ScenarioPlayer.tsx` called `setPlaying(false)` synchronously when `stepIndex >= lastIndex`, which triggered the narration playback hook to call `audio.pause()` in the next render cycle (~16ms later)
- Fix: delay `setPlaying(false)` by the final step's `narrationDuration` when unmuted; immediate stop when muted or no narration (preserves existing behavior)
- All 10 scenarios benefit — every one has narration on its last step

## Decisions Made

- **Fix location**: ScenarioPlayer auto-advance effect only — no changes needed in `useNarrationPlayback.ts`. The hook's contract (pause when `playing` is false) is correct; the bug was in when ScenarioPlayer decided playback was over.
- **No artificial buffer**: No extra padding added after narration ends. If a clip feels abrupt, the fix is better narration text, not a code-level hack.

## Key Code Changes

- `site/src/components/docs/demos/engine/ScenarioPlayer.tsx`: Modified the `stepIndex >= lastIndex` branch in the auto-advance timer effect to check for active narration and defer `setPlaying(false)` by `durationMs`

## Learnings

- React effect execution order matters across hooks: `useNarrationPlayback` effects register before ScenarioPlayer body effects because the hook is called first. The step-change effect (play audio) fires before the auto-advance effect (set playing false), but the state update from `setPlaying(false)` batches into the next render, where the playing-state effect fires and pauses audio.
- The `durationMs`-based timing for non-final steps was already correct — the gap was only in the final-step branch which had no timer at all.
