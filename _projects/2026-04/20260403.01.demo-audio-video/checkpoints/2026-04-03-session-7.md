# Session Notes: 2026-04-03 (Session 7 — Narration Audio Cutting Fix)

## Accomplishments

- Identified and fixed audio clipping during step transitions in the ScenarioPlayer narration engine
- Root cause analysis revealed two contributing factors: (1) `setTimeout` and `playClip()` fire in the same React effect flush, but audio needs time to load/decode before becoming audible, causing the last ~50-150ms of each clip to be cut; (2) Edge TTS `durationMs` metadata is computed from word boundaries and may undercount actual MP3 duration by ~50-200ms
- Added `NARRATION_SAFETY_BUFFER_MS` (250ms) constant to compensate for load/decode latency and metadata inaccuracy
- Added `prefetchManifestClips()` helper that warms the browser HTTP cache on unmute, eliminating network latency at step transitions
- TypeScript and ESLint pass clean on both modified files

## Decisions Made

- **Buffer-based over event-driven timing**: Evaluated listening for the audio `playing` event to defer the step timer until audio is actually audible. Rejected because it couples the audio hook to step orchestration and adds async complexity to effect cleanup. The clips are small static MP3 files served from the same origin — load/decode latency is bounded and a 250ms buffer is sufficient.
- **Pre-fetch on unmute, not on manifest load**: Avoids unnecessary network requests for users who never click the volume button. Video export mode (initialMuted=false) pre-fetches at mount via a separate effect.
- **No ffprobe dependency for duration accuracy**: The 250ms buffer compensates for TTS metadata inaccuracy at the playback layer, keeping the `generate-narration.ts` build script dependency-free. Can be added later if 250ms proves insufficient.

## Key Code Changes

- `ScenarioPlayer.tsx`: Added `NARRATION_SAFETY_BUFFER_MS = 250` constant. Applied to both the final-step branch (`setTimeout(() => setPlaying(false), finalNarrationMs + BUFFER)`) and non-final-step branch (`Math.max(baseDelay, narrationDuration + BUFFER)` when narration is active).
- `useNarrationPlayback.ts`: Added `prefetchManifestClips()` helper, `prefetchedRef` guard, pre-fetch effect for video export mode, and pre-fetch call inside `toggleMute` for interactive unmute. Added `manifest` to `toggleMute`'s dependency array.

## Learnings

- The `setTimeout` in a React effect and `audio.play()` in another effect start at the same wall-clock instant during the effect flush, but audio has variable latency (fetch + decode + buffer) before it becomes audible. This systematic offset means every narration clip effectively plays shorter than its `durationMs`.
- Edge TTS word-boundary metadata captures when the last word ends, not the actual end of the MP3 waveform. MP3 encoding adds trailing frames, and natural speech has trailing resonance beyond the last word boundary.
- A `prefetchedRef` boolean guard is sufficient since `fetch()` is idempotent for cached resources — no need for per-URL tracking.

## Open Questions

- None for this fix. The 250ms buffer is generous for same-origin static files with pre-fetching; if future scenarios use longer or higher-bitrate clips, the value may need tuning.
