## Decisions Made

- **Manifest prop over inline `narrationSrc`**: Instead of putting `narrationSrc` (audio URL) on `ScenarioStep<T>`, we use a separate `narrationManifest` prop on ScenarioPlayer. This separates authored content (narration text written by step author) from build artifacts (audio URLs and durations generated by TTS script). Approved before implementation.
- **Custom hook extraction**: Audio playback logic lives in `useNarrationPlayback.ts`, keeping ScenarioPlayer focused on step orchestration. The hook manages a single `<audio>` element via ref.
- **Browser autoplay strategy**: Default to muted, catch rejected `play()` promises silently. The unmute click provides the user gesture context. Start with HTMLAudioElement; upgrade to Web Audio API only if Safari proves problematic.
- **Icon choice**: `Volume2`/`VolumeX` from lucide-react for mute toggle, consistent with existing icon library usage. No emoji icons.

## Key Code Changes

- `engine/narration.ts`: `NarrationEntry` and `NarrationManifest` type definitions shared between runtime (ScenarioPlayer) and build time (Phase 2 TTS script)
- `engine/useNarrationPlayback.ts`: Custom hook with `safePlay`, `playClip`, `stopAudio` helpers. Manages mute state, step-synced playback, pause/resume on player state changes, cleanup on unmount
- `engine/ScenarioPlayer.tsx`: Added `narration?: string` to `ScenarioStep<T>`, `narrationManifest?: NarrationManifest` to props, integrated hook, rendered hidden `<audio>` and mute toggle button conditionally

## Learnings

- The site uses `output: "export"` (static export) — no server routes at runtime. Phase 5 video export will need a separate dev server approach for Playwright recording.
- The `jsx-a11y/media-has-caption` ESLint rule is not active in this project, so the eslint-disable comment was unnecessary and caused a lint warning.
- React's `react-hooks/exhaustive-deps` rule correctly catches stale ref values in cleanup functions — the ref must be copied to a local variable inside the effect body.
