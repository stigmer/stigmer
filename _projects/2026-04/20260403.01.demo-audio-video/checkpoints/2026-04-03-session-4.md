## Decisions Made

- **Runtime fetch over static import**: Manifests load via `fetch()` from `/demos/{id}/manifest.json` rather than static import. This works with `output: "export"`, degrades gracefully when narration hasn't been generated, and avoids coupling component code to build-time artifacts or fragile relative paths into `public/`.
- **Timer reset on mute toggle**: Adding `muted` to the auto-advance effect's dependency array causes the timer to reset from scratch when the user toggles mute. This naturally syncs with `useNarrationPlayback`, which also restarts/stops the clip on toggle. The reset-from-scratch behavior is correct because the narration clip also starts from scratch when unmuting.
- **No padding after narration**: Edge TTS word-boundary metadata marks the end of the last word; the MP3 file has natural trailing silence beyond that. Advancing at `durationMs` produces a perceived breathing pause without explicit padding.
- **No hard cap on duration**: Narration was authored at 1-2 sentences per step. If a step feels too long, the fix is shorter text, not a code-level truncation.

## Key Code Changes

- `engine/useNarrationManifest.ts` (new): Hook that fetches `/demos/{scenarioId}/manifest.json` on mount, returns `NarrationManifest | undefined`. Handles 404 silently.
- `engine/ScenarioPlayer.tsx`: Auto-advance effect now computes `Math.max(baseDelay, narrationDuration)` when unmuted. `muted` and `narrationManifest` added to dependency array.
- 10 scenario `index.tsx` files: Each now imports `useNarrationManifest`, calls it with the scenario directory name, and passes the result as `narrationManifest` to `ScenarioPlayer`.

## Learnings

- The manifest wiring was a gap from Phase 1 that was never called out in the original plan. The `narrationManifest` prop existed on ScenarioPlayer, but no scenario loaded or passed a manifest. All Phase 1 audio infrastructure (mute toggle, audio playback, narration hook) was completely dormant. This was discovered during Phase 4 planning and addressed together.
- The "no race condition by design" pattern is worth remembering: since the mute toggle only renders when `narrationManifest` is truthy, the user literally cannot interact with audio before the manifest arrives. No loading states, no disabled buttons, no spinners needed.
