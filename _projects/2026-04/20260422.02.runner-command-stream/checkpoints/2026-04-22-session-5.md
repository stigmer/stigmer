## Decisions Made

1. **Immediate STOPPED on disconnect (matching OSS)**: No grace period in Cloud. Behavioral consistency is a hard invariant. Runner reconnects within seconds; grace period would show stale READY status.
2. **Redis pub/sub included in T06** (not deferred to T07): StreamRegistry is incomplete without SendCommand. Keeps T07 thin and symmetric across editions.
3. **Deleted DeprovisionInfrastructureStep**: Not planned, but it referenced deleted `RunnerHeartbeatInput` type. Logic moved into `RunnerHeartbeatService.triggerDeprovisionIfNeeded()`.
4. **CompletableFuture for command correlation** (Java) vs channels (Go): Idiomatic Java equivalent of Go's buffered channels for request/response correlation.
5. **Base64 encoding for Redis payloads**: Protobuf bytes → Base64 string, since Redis Pub/Sub uses string serialization throughout the codebase.

## Learnings

- gRPC-Java bidi signature is `StreamObserver<I> method(StreamObserver<O>)` — the return is the client-to-server observer
- Java generic type erasure makes `noOpStreamObserver()` casts tricky — removing explicit casts and relying on return-type inference works
- `AutoGrpcRouterControllerProcessor` already handles bidi dispatch in codegen (`return requestRouter.route(responseObserver)`) — the framework just needed the runtime method
- `RedisMessageListenerContainer` from Spring Data Redis manages subscription lifecycle cleanly

## Open Questions

- gRPC-Java `onNext`/`onError`/`onCompleted` run on transport threads. MongoDB writes and FGA checks inline should be fine (single-digit ms), but worth monitoring under load. Offloading to a separate executor is the mitigation if needed.
