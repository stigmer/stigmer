## Decisions Made

- **Color mode control via props, not SDK context**: `useColorMode()` is read-only. Rather than modifying `StigmerProvider` to manage color mode state with a setter (which would change the provider's API contract), UserMenu accepts controlled `colorMode` + `onColorModeChange` props. The web bridges via `next-themes`, the desktop will bridge via its own state. Follows the callback-based pattern from OrgSwitcher.

- **Flattened color scheme (no submenu)**: With preset picker removed per plan, only 3 radio items remain. Hick's Law — 3 items don't justify an extra interaction layer. Placed directly in the menu body with a MenuLabel section header. Avoids adding submenu primitives to internal/menu.tsx.

- **Console wrapper (not delete)**: Unlike prior extractions (OrgSwitcher, settings-nav) where the web file was deleted because the SDK component is self-contained, UserMenu requires Console-specific data (useAuth, useTheme, useRouter, desktop download). The web file was rewritten as a bridge, preserving import paths in Sidebar.tsx and ManagementSidebar.tsx — zero consumer changes.

- **Preset picker removed**: Per T01 plan. Web users lose ability to switch presets from UserMenu. Can be reintroduced later as `extraItems` or in a dedicated Appearance settings page.

## Learnings

- `useColorMode()` in the SDK is intentionally read-only — it returns the resolved mode from `StigmerProvider`'s context, which is controlled by the host application via the `colorMode` prop. This is by design: the host manages color mode persistence and toggling (via next-themes, localStorage, or OS preference), and the SDK just consumes the result. The UserMenu's controlled props fit this model perfectly.

- Web's `DropdownMenuItem` (from `@/domain/_shared/ui/dropdown-menu`) is compatible with the SDK's internal `Menu` (from `@base-ui/react/menu`) because both are thin wrappers over the same `@base-ui/react` primitives. The Menu.Item registers with the nearest Menu.Root context regardless of which wrapper created it. This makes the `extraItems: ReactNode` slot safe for mixing web and SDK menu items.

- The eslint-disable directive for `stigmer/no-main-tokens-in-sidebar` was unnecessary in the new Console wrapper because the lint rule's scope no longer flags the `DesktopAppItem`'s `text-muted-foreground` in the rewritten file. The original file needed it because the entire component was in a sidebar-context file.
