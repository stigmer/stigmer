## Decisions Made

- **Error as a terminal status, not orthogonal**: Unlike `AgentSetupState` where `error: Error | null` is intersected into all variants, `OrgGateState` has `error` as a variant with a `message` payload. Rationale: for the org gate, error IS a terminal phase — the gate is in the `error` state, not in some other state with an error overlay. This is more precise and avoids ambiguity.
- **Actions on hook return, not in variants**: `retry` and `refresh` are always available on `UseOrgGateReturn`, consistent with `useAgentSetup` pattern. Consumer calls them in the appropriate status.
- **No separate `OrgGatePhase` type**: Unlike `AgentSetup` which needs `Phase` separate from `State` (for error intersection), there is no orthogonal state to intersect. `OrgGateState` is the complete type.
- **Provisioning timeouts remain module-private**: `PROVISIONING_POLL_MS` and `PROVISIONING_TIMEOUT_MS` are not configurable. Platform builders would implement their own org gating rather than reuse this hook.
