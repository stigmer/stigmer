## Decisions Made

- **SDK-internal Menu primitives over inline @base-ui/react usage**: Created `sdk/react/src/internal/menu.tsx` as a non-exported shared wrapper over `@base-ui/react/menu`. Rationale: both T01-C (OrgSwitcher) and T01-E (UserMenu) need styled menus — visual consistency between SDK dropdown menus is a quality requirement. The web app solved this exact problem with its `dropdown-menu.tsx` wrapper; the SDK faces the same problem. The primitives are NOT exported from `@stigmer/react` — they're internal implementation details.
- **Inline Dialog over shared wrapper**: The Dialog for "Create organization" is used by OrgSwitcher only. No other T01 subtask needs it. Inlined `@base-ui/react/dialog` directly (~30 lines). Will extract to `internal/dialog.tsx` if a second consumer appears.
- **`onOrgChanged` callback with semantic meaning**: Added `onOrgChanged?: (org: Organization) => void` to `OrgSwitcherProps`. This is NOT syntactic sugar over watching `useOrg().activeOrg` — it fires only on user-initiated actions (explicit switch or create), not on initial load, background refresh, or programmatic context updates. This enables "navigate home on org switch" without fragile useEffect guards.
- **Token context correctness**: Fixed the web's OrgLabel which used `text-sidebar-muted-foreground` for the slug in both the sidebar trigger AND portaled dropdown items. The SDK version correctly uses `text-sidebar-muted-foreground` in the trigger (sidebar context) and `text-muted-foreground` in dropdown radio items (popover context). OrgLabel accepts a `slugClassName` prop to handle both contexts.
- **eslint-disable block for portaled dialog**: The `stigmer/no-main-tokens-in-sidebar` rule flags main-area tokens (`bg-background`, `text-foreground`, `text-muted-foreground`) in the OrgSwitcher file because it also contains sidebar tokens. The Dialog is portaled outside the sidebar, so main-area tokens are correct per DD-005. Used an `eslint-disable` / `eslint-enable` block around the entire dialog popup with justification.

## Learnings

- The `stigmer/no-main-tokens-in-sidebar` ESLint rule scans the entire file for sidebar-vs-main token usage. When a file contains BOTH sidebar tokens (trigger) and main-area tokens (portaled dialog), the rule flags the main-area tokens. The correct fix is `eslint-disable` / `eslint-enable` blocks around portaled sections, not suppressing individual lines (which doesn't work for multi-line className expressions).
- The web's OrgLabel used sidebar tokens for the slug text everywhere, including inside portaled dropdown items — a latent theming bug that would surface in presets with contrasting sidebar/popover surfaces. Fixed during extraction by making OrgLabel accept a `slugClassName` parameter.
- `@base-ui/react` was already in the monorepo's node_modules from the web app. Adding it to desktop's package.json was a declaration change, not a fresh install.
