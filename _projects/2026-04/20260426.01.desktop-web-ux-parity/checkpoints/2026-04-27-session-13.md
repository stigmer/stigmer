# Session Notes: 2026-04-27, Session 13 — Runners Page UX Redesign

## Accomplishments

- Redesigned the desktop Runners page layout: replaced the broken 50/50 horizontal log panel with a resizable bottom panel (VS Code-style)
- Implemented drag-to-resize handle with pointer events — no external library
- Added localStorage persistence for the log panel height ratio (`stigmer:runner-log-panel-ratio`)
- Added Escape key to close the log panel
- Enhanced RunnerLogViewer header: now shows phase pill, execution count, os/arch, and runner version
- Added smart auto-scroll to log output (sticks to bottom, disengages on user scroll-up)
- Refactored RunnerRow to a two-line card layout in both the desktop app and the SDK `RunnerListPanel`
- Removed `max-w-4xl` wrapper from desktop runners route — page now fills viewport height
- Fixed 2 newly introduced opacity modifier lint warnings (`bg-primary/5`, `bg-primary/10` → `bg-primary-subtle`)
- All verification targets pass: SDK lint + typecheck (clean), desktop lint + typecheck + cargo check (0 errors, 5 pre-existing warnings)

## Decisions Made

- **Bottom panel over side panel**: Logs go at the bottom, matching developer tool conventions (Jakob's Law). Log lines are wide — horizontal space matters more than vertical.
- **Two-line row for SDK**: The RunnerListPanel in `@stigmer/react` was updated (not just the desktop copy), so the web console also benefits. No API-breaking changes.
- **No resize library**: Drag-to-resize is ~30 lines of pointer event handling. Adding a library for this would be over-engineering.
- **bg-primary-subtle for selection**: Used `bg-primary-subtle` and `border-primary` tokens instead of opacity modifiers for the selected runner row — theme token compliance (DD-005).
