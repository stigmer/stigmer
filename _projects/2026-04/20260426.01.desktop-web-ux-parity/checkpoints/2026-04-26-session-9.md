## Decisions Made

- **Page headers stay inline, not a shared component.** The "Add" action uses app-specific routing primitives (react-router Link vs Next.js Link), making it an app-shell concern per DD-002. ~10 lines of JSX per page does not justify extraction.

- **Same localStorage key convention as web.** Keys follow `stigmer:library:{type}:scope` pattern. A user switching between desktop and web on the same machine gets consistent scope preferences.

- **SSR guard omitted in desktop.** The web pattern includes `if (typeof window === "undefined") return "org"` for Next.js server rendering. Desktop runs entirely in a Tauri webview — the guard would be dead code.

- **"Add" actions use `/?draft={type}` URLs.** The desktop SessionLauncher (index route) already parses draft params via `parseDraftParams` from `@stigmer/react`. No new routing needed.

## Learnings

- All five features were already built in the SDK. The gaps were purely wiring — the desktop pages simply weren't consuming the SDK capabilities. This validates the SDK-first architecture: once a feature is in the SDK, adding it to a new consumer is trivial.

- The web `AgentDetailPage` has an "Edit" button that wasn't in the original 4-gap audit list. Cross-referencing web and desktop page-by-page during implementation caught this additional gap.
