## Decisions Made

- **`lucide-react` as non-optional peer dependency**: The SDK was already importing Lucide icons in `OrgSwitcher.tsx` and `internal/menu.tsx` without declaring the dependency. This worked by accident via monorepo hoisting but would break for external platform builders. Added `">=0.400.0"` as a non-optional peer dependency (unlike `@base-ui/react` which is optional, Lucide icons are used in data constants and styled components alike — cannot be avoided). The floor of `>=0.400.0` gives broad compatibility since the icon component API has been stable.
- **Settings as a new SDK domain directory**: Created `sdk/react/src/settings/` rather than placing `settings-nav.ts` in an existing directory. Settings navigation is its own bounded concern — it doesn't belong in `organization/` (it covers billing, infra, config too) or a generic `layout/` (SDK doesn't have layout concerns). T01 plan specified `sdk/react/src/settings/` as the target; this follows the existing pattern of one domain directory per barrel.

- Git correctly detects a file copy+delete as a rename when the content is identical — the commit shows `renamed: client-apps/web/.../settings-nav.ts -> sdk/react/src/settings/settings-nav.ts` which preserves blame history.
