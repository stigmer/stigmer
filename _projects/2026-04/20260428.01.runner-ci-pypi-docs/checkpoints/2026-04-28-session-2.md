## Decisions Made

- **No path filters on push-to-main trigger**: The desktop build depends on files across 7+ directories. Path filters would be fragile and risk recreating silent breakage. Accepted full build cost per push to main, matching the CLI workflow pattern.
- **Keep redundant `shell: bash` annotations**: Several steps in the `build` job have explicit `shell: bash` despite the job-level default. Left them in place — they serve as documentation for future readers.
- **Exact copy of CLI lint job**: The `lint-and-typecheck-agent-runner` job is identical to the CLI workflow's version. No customization needed — both workflows lint the same agent-runner code.

## Key Code Changes

- `.github/workflows/release.desktop.yaml`:
  - Added `push: branches: [main]` trigger
  - Added `else` branch in `determine-version` for push-to-main events
  - Added `lint-and-typecheck-agent-runner` job (MyPy + Ruff)
  - Updated `build.needs` to gate behind the lint job

## Learnings

- The desktop `generate-protos` already packages `apis/stubs/` which includes the Python proto stubs needed by the agent-runner lint job — no change to proto generation was needed.
- The `determine-version` step had a latent bug: no `else` branch meant push-to-main events would leave `VERSION` and `SHOULD_RELEASE` unset. This was discovered during planning and fixed proactively.
