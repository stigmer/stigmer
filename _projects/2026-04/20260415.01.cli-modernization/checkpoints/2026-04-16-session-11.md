# Session Notes: 2026-04-16 (Session 11)

## Accomplishments

- Changed `stigmer-ink.tsx` shebang from `node` to `tsx` as a safety net

## Decisions Made

- **CWD walk-up over env var**: Rather than requiring a `STIGMER_WORKSPACE_ROOT` env var, we walk up from the current working directory looking for workspace markers. This is automatic and handles the common dev case where users install the binary to `~/bin` or `$GOPATH/bin` but run it from within the monorepo.
- **Keep both detection strategies**: Binary-relative detection (tier 2a) remains for `make build` installs to `<repo>/bin/stigmer`. CWD walk-up (tier 2b) handles all other install locations. Neither is removed.
- **Shebang change is safe for published package**: The `publishConfig` in `package.json` overrides `bin` to point at compiled `dist/cli/stigmer-ink.js`, so the `.tsx` shebang never affects production installs.

## Learnings

- `os.Executable()` returns the actual binary path, not the symlinked path. When binaries are installed via `cp` to `~/bin/`, the workspace root detection based on `filepath.Dir(exePath)/..` will compute a wrong root.
- `npx` in a Yarn workspace resolves local workspace packages, so `npx --yes @stigmer/ink@0.0.0-dev` will find the local `@stigmer/ink` and run its `bin` entry — which points at source `.tsx` with a `#!/usr/bin/env node` shebang that Node.js v23 can't handle.
