## Decisions Made

1. **npx over bun compile**: Dogfoods the npm SDK distribution model. No custom build pipeline, no WASM risks, boring and proven. Node.js is a reasonable dependency for platform builder users.
2. **Workspace auto-detection**: Go binary at `bin/stigmer` looks for `../node_modules/.bin/tsx` + `../sdk/ink/src/cli/stigmer-ink.tsx`. Mirrors how the web app resolves `@stigmer/react` via yarn workspace.
3. **Full TUI replacement (no fallback)**: Go TUI was not well-tested and had many issues. Ink becomes the sole interactive renderer. Go keeps JSON mode and plain text for non-TTY.
4. **Release coordination via npm poll**: CLI `release` job polls npm until `@stigmer/ink@<version>` is available before creating GitHub Release. Build jobs run in parallel; only the final release is gated.
5. **Tool streaming deltas skipped**: Go-only feature (event-based, not in subscribe API). Snapshot updates from `useSessionConversation` are sufficient, matching web SDK behavior.

## Learnings

- Yarn Berry (v3) copies workspace packages into `node_modules` at install time. If you build a package after `yarn install`, the `node_modules` copy is stale. Using `npm install` creates proper symlinks.
- The `stigmer-ink.tsx` entry point has `#!/usr/bin/env node` shebang but is TypeScript — requires `tsx` for development workflow. Production path via npx uses compiled JS.
- The Go test binary runs from a temp directory, so workspace auto-detection in `resolveInkCommand()` doesn't find the monorepo. Tests use `STIGMER_INK_CMD` override or walk up from `cwd` to find the workspace root.
