## Decisions Made

- **Keep single `Apply` method**: Instead of adding proto-accepting `Apply` alongside Input-based `Apply`, we generate `FromProto` converters. The CLI converts parsed protos to `*Input` types like any other SDK consumer. This keeps the SDK API clean and avoids a confusing two-tier API.
- **Thread `*stigmer.Client` everywhere**: Domain packages and the ApplyHandler interface accept the full client, not per-resource sub-clients. These are internal packages — the cost of wider dependency is negligible vs the simplicity gain.
- **Error bridge in `clierr.go`**: SDK `*stigmer.Error` carries `GRPCCode`, so we reconstruct a `*status.Status` from it and reuse the existing `classifyGRPCCode` function. No duplication of error classification logic.

## Learnings

- Proto oneof fields in nested type schemas need special handling in `FromProto` generation — the `oneofGroup` field must not prevent recursion into variant types for converter function generation
- The existing `toProto` generation deliberately skips deeply nested message fields (returns empty structs). The `fromProto` generation handles them correctly, which means `fromProto ∘ toProto` is NOT an identity — `fromProto` is strictly more complete.
- The `*grpc.ClientConn` type assertion pattern (`client.Conn().(*grpc.ClientConn)`) was used in 10+ files. Eliminating it made the CLI resilient to connection type changes.
