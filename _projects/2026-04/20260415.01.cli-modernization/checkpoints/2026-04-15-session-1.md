## Decisions Made

- **Package naming**: `applier` (not `apply`) to distinguish from existing `internal/cli/apply/` synthesis package
- **No `init()` registration**: explicit `newApplyHandlerRegistry()` factory per coding guidelines
- **`Metadata()` on interface**: enables framework to handle org mismatch/injection/reference-building — avoids duplicating these across handlers
- **`dryRun` NOT on `Apply()`**: framework handles dry-run branching, handler only does real applies
- **MCP discovery stays in orchestrator**: only one kind needs post-apply processing; PostApplyHook interface would be YAGNI
- **Apply ordering centralized**: `DefaultApplyOrder` map in framework, not on individual handlers
- **Type assertions over generics**: conscious trade-off — Go generics can't store different concrete types in a single registry without a wrapper; type assertions are trivial one-liners
