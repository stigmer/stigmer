## Decisions Made

- **Workflow-runner entry point**: Use root `main.go` (`backend/services/workflow-runner/main.go`) instead of `cmd/zigflow`. Rationale: the root package is lean, env-var-configured, purpose-built for the Stigmer daemon. The `cmd/zigflow` Cobra CLI carries unnecessary surface area (standalone DSL execution, third-party telemetry, TLS flags) that the daemon never uses.
- **Single tarball**: All three binaries ship in one tarball (not separate downloads). `findSiblingBinary` already looks in the same directory as the CLI first, so extracting the tarball gives a working installation immediately.
- **OAuth ldflags placement**: Moved to `stigmer-server` build step (the binary that actually imports `stigmer-server/pkg/config`). Confirmed the CLI no longer imports this package after the Session 6 SDK refactor.

## Learnings

- Go's linker silently ignores `-X` flags for packages not in the binary's dependency tree. The OAuth ldflags on the CLI build were dead code with no error or warning — easy to miss.
- The workflow-runner has two separate `main` packages (`cmd/zigflow` for standalone Zigflow CLI, root `main.go` for Stigmer integration). Choosing the right one matters for security and surface area.
