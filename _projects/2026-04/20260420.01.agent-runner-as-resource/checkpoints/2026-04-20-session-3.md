## Learnings

- Daytona sandbox create_from_snapshot is remarkably fast (~1s) regardless of data size — the snapshot mechanism is very efficient.
- Archiving race condition is safe — Daytona queues the start() and succeeds, even with data. This is important for HITL approval flows where sandbox may be archiving when user approves.
- The `daytona_stdio_client` transport has a startup detection issue with commands that produce no initial output (`cat`). The real MCP server tests work fine because servers emit initialization messages.
- 500MB workspace archive takes ~61s and restore takes ~21s — this is the cost of cold-storage hibernation. For HITL pauses, `stop` (1.8s) + `start_from_stopped` (1.4s) is much faster.
