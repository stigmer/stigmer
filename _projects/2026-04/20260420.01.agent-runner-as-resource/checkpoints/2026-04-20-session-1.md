## Decisions Made

1. HTTP proxy on existing `api.stigmer.ai` with path-based routing (`/v1/proxy` -> port 8081) — not a separate hostname, not cluster-internal, not gRPC adapters
2. Single hostname with path-based routing — not per-concern hostnames
3. Tomcat on port 8081 alongside gRPC Netty on port 8080 — `spring-boot-starter-web` coexistence pattern
4. Gateway API resources created manually in `_ops/planton/infra-hub/kubernetes/` — OpenMCF module only supports one hostname
5. Ollama excluded, Temporal direct connection — both confirmed with user
6. Provider API keys in stigmer-service env vars for now — vault integration later

## Learnings

- stigmer-service was purely gRPC-only — no HTTP capability existed before this session
- Redis in agent-runner was completely dead code — connected at startup, never read/written
- MACHINE_ACCOUNT_CLIENT_ID/SECRET referenced in README but not used in Python code — actual auth is API key + OBO header
- KubernetesDeployment module's ingress supports only `string hostname` (singular) — need manual Gateway API for additional hostnames
- Daytona sandboxes run OUTSIDE K8s — cluster-internal-only endpoints don't work for them
