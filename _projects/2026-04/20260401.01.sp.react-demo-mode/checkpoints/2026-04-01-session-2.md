## Decisions Made

1. **Composable primitives over fixed scenarios**: User challenged the original plan for a fixed `skillCreationScenario`. Redesigned so data is defined at the point of use, not pre-packaged. The reference scenario is an example, not the primary artifact.

2. **Full RPC surface coverage**: User questioned tracing only 5 components. Since DemoTransport mocks at the transport layer (inherently supporting all components), the fixture helpers cover all ~42 RPCs called by exported hooks — not just a subset.

3. **`buildScenario()` for search multiplexing**: Discovered that `agent.list()`, `skill.list()`, and `mcpServer.list()` all route through `SearchService/search` with different `ApiResourceKind` values. This means they share the same fixture key and would silently collide in a raw `Map`. Introduced `buildScenario(...specs)` that merges search handlers into a dispatch function routing by kind.

4. **Flat override interfaces for samples**: Instead of nested protobuf init objects, sample factories take flat override objects (`{ name, org, subject }`) and handle the `metadata`/`spec` nesting internally. Best DX — users don't need to know proto structure.

5. **Proto imports confirmed acceptable**: `fixtures.ts` imports proto service descriptors and `samples.ts` imports `create()` + proto schemas. Both `@stigmer/protos` and `@bufbuild/protobuf` are already peer dependencies of `@stigmer/react`.

## Learnings

- The SDK's `list()` methods on `AgentClient`, `SkillClient`, and `McpServerClient` delegate to `SearchService.search` with a `kinds` filter. This is an internal implementation detail that fixture consumers shouldn't need to know about — `buildScenario()` abstracts it away.
- protobuf-es v2's `create(Schema, init)` handles nested message initialization from plain objects — no need for explicit `create()` calls on every nested message.
- The `fixtures` object mirrors the SDK client shape (`fixtures.session.get` ↔ `client.session.get`) which makes the API intuitive for developers who already know the SDK.
