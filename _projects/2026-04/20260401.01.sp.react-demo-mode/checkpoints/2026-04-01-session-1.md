## Decisions Made

- **Custom DemoTransport over createRouterTransport**: `@connectrpc/connect` ships `createRouterTransport` as an official mock utility, but using it would require adding `@connectrpc/connect` as a runtime dependency of `@stigmer/react`. The custom DemoTransport uses only type imports (erased at compile time), keeping the dependency graph clean.

- **Structural typing over Stigmer class modification**: The `Stigmer` class has no transport injection point. Rather than modifying the `@stigmer/sdk` public API, `createDemoClient()` constructs a plain object with all 19 client properties and uses `as Stigmer`. This works because `Stigmer` has no private/protected members — TypeScript structural typing makes the object assignable.

- **Fixture key format**: `"<proto service typeName>/<method name>"` (e.g., `"ai.stigmer.agentic.session.v1.SessionQueryController/get"`). The `rpcKey()` helper constructs keys from proto service descriptors for ergonomic scenario building.

- **Stream handler receives unwrapped request**: For server-streaming RPCs, `createClient` wraps the single request in an `AsyncIterable`. The DemoTransport extracts the first message before passing to the fixture handler, so handlers receive the plain request — not the async iterable wrapper.

## Learnings

- The `@connectrpc/connect` v2.1.1 `Transport` interface has only 2 methods (`unary` and `stream`), not the 4 gRPC-style methods. All streaming types go through `stream` with `DescMethodStreaming`.
- Type-only imports from `@connectrpc/connect` resolve correctly through the hoisted monorepo `node_modules` without needing to declare it as a dependency of `@stigmer/react`.
- The existing test pattern in `sdk/typescript/src/__tests__/gen/session-client.test.ts` uses the same `as unknown as Transport` cast — our approach is consistent with established codebase patterns.
