## Decisions Made

- **`getCompositions()` over registry import** — Discovers scenario IDs from the Remotion bundle at runtime, avoiding the need to import React component modules in a Node.js script context
- **Sequential rendering** — `renderMedia` already parallelizes frame rendering internally; adding scenario-level parallelism would multiply memory usage without proportional benefit
- **No quality presets** — CRF 18 is fast enough for iteration and high enough quality for production; presets are a one-line addition if needed later
- **`deps` only dependency** — Remotion bundles from source, so no `build` step or static server needed — a significant simplification over the Playwright pipeline

## Learnings

- **`@remotion/bundler`'s `bundle()` does not read `remotion.config.ts`** — The CLI reads the config automatically, but the programmatic API requires `webpackOverride` to be passed explicitly. This makes sharing the override essential.
- **`getCompositions()` is the clean discovery path** — Importing `PLAYBACK_SCENARIO_IDS` from the registry would transitively pull in all React scenario components, which fail to resolve in a Node.js script context. Runtime discovery from the bundle avoids this entirely.
