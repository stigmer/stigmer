## Decisions Made

1. **No MongoDB for snapshot state**: Instead of storing the active snapshot name in MongoDB, query Daytona's snapshot.list() API directly with prefix-based filtering. This makes Daytona the single source of truth and avoids a new MongoDB collection.

2. **SnapshotResolver as module-level singleton**: Initialized once at worker startup, cached in `worker/snapshot_resolver.py`. This ensures the in-memory cache survives across activity executions (unlike placing it on SandboxManager which is recreated per activity).

3. **Separate env vars for sandbox images**: `STIGMER_SANDBOX_IMAGE` remains for OSS/local usage (defaults to basic). `STIGMER_MCP_SNAPSHOT_BASE_IMAGE` controls the cloud snapshot builder base (defaults to full).

4. **Full image is amd64-only**: Several tools in Dockerfile.sandbox.full bundle x86_64 binaries (yq, kubectl, AWS CLI, Tekton CLI), so the CI builds it as linux/amd64 only.

5. **Python symlink needed**: `Dockerfile.sandbox.full` uses `debian:bookworm-slim` which installs `python3` but not `python`. Daytona's `Image.pip_install()` generates `RUN python -m pip install ...`, so we need `ln -sf /usr/bin/python3 /usr/bin/python`.
