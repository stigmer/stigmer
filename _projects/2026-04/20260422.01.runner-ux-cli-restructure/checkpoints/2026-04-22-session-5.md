## Decisions Made
- **Card-row list, not HTML table**: Settings pages consistently use card-based `role="list"` layouts (ApiKeyListPanel pattern). Mixing in a `<table>` would break visual consistency. Runner metadata fits naturally into flex rows with responsive `hidden sm:flex`.
- **New "Infrastructure" nav group**: Runners are infrastructure, not configuration or organization. Creating a dedicated group provides clean taxonomy and is forward-looking for future infra items (storage, proxies, etc.).
- **SDK placement**: `RunnerListPanel` belongs in `@stigmer/react` — any platform builder running their own Stigmer deployment needs runner fleet visibility. Zero Console dependencies.
- **Phase utility extraction**: Phase labels, colors, sort order, and active-phase checks were inline in `RunnerPicker`. Extracting to `phase.ts` eliminates duplication and makes phase semantics a single source of truth. Exported as public API for platform builders who build custom runner UIs.
- **`includeSystemManaged: true` default**: Admin views should show all runners by default. System-managed runners get a "System" badge to distinguish from user-created.
- **Read-only v1**: No create/delete actions — runners are created via `stigmer up` (CLI) or auto-provisioned (cloud). Delete may come later.

## Learnings
- The settings pages follow a very consistent pattern: thin route → section component → SDK panel. The pattern makes adding new settings pages mechanical.
