## Decisions Made
- Workflow-runner is excluded in server-only mode (both runners omitted, not just agent-runner) — the server is purely the API + Temporal coordinator
- Server-only mode is communicated to the daemon process via `STIGMER_SERVER_ONLY=true` env var, following the existing env-based config pattern
- Python runtime bootstrap is entirely skipped in server-only mode (no venv, no pip)

## Key Code Changes
- `daemon.go`: `StartOptions.ServerOnly`, conditional Python bootstrap, conditional runner env vars, `STIGMER_SERVER_ONLY` propagation, `StartupConfig.ServerOnly`
- `daemon_process.go`: `buildComponents(... serverOnly bool)`, `RunDaemonProcess` reads `STIGMER_SERVER_ONLY`
- `startup_config.go`: `ServerOnly bool` field

## Learnings
- The daemon spawns `stigmer internal-daemon` as a separate process with all config passed via env vars — this is a clean boundary that made adding ServerOnly straightforward
- `buildComponents` returns a slice that's iterated everywhere (startup, health monitor, shutdown) — filtering at construction time means all downstream logic works without modification
