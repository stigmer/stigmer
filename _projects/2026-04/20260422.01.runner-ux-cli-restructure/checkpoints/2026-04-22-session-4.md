## Decisions Made
- **Tier 1 not Configure menu**: Runner is a simple execution parameter (like model), not a complex config flow. Placed alongside ModelSelector.
- **`null` = Auto**: Default lets backend decide. Platform builders who omit `onRunnerIdChange` never see the picker.
- **Client-side system-managed filtering**: `useRunnerList` filters ephemeral cloud runners by default via `stigmer.ai/system-managed` label. `includeSystemManaged: true` for admin views.
- **No chip in Zone 2**: Runner selection is dropdown state, not additive context. Keeps UI clean when "Auto" selected.
- **No polling in v1**: Fetch on mount + `refetch()`. Runner list is stable enough.
- **Phase-aware grouping**: Available (READY/BUSY) vs Offline (STOPPED/PENDING/FAILED) with phase dots (green/yellow/gray).

## Learnings
- Base UI Select doesn't support `null` values directly — used `__auto__` sentinel string mapped to/from `null` at the component boundary
- The TS SDK's `SessionInput.runnerId` was already wired end-to-end (proto → Go → TS stub) — React layer was the only gap
- SessionComposer's opt-in pattern (provide callback → feature appears) is clean and scales well for new toolbar items
