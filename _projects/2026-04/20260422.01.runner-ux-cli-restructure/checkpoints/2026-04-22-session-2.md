## Decisions Made

- **Cloud-first `stigmer up`**: `stigmer up` now starts a runner (was: start server+runner). Cloud users are the primary audience. OSS users use `stigmer up server`.
- **Portable credentials**: `--endpoint` and `--token` flags make `stigmer up` work from any machine, CI/CD, container, or sandbox without a config file.
- **No auto-restart**: Foreground process, user sees crash. Auto-restart deferred to the runner-command-stream project (Go supervisor model).
- **Forward-compatible heartbeat**: Passes `STIGMER_RUNNER_ID` to Python for HeartbeatEmitter. When bidi stream lands, Go supervisor takes over heartbeat. Clean transition.
- **Task queue from Apply**: Uses `task_queue` from Apply response. Falls back to fixed `agent_execution_runner` if server doesn't set it.

## Learnings

- The daemon's `bootstrapRunnerRuntime` and `buildRunnerEnv` are not exported but the underlying primitives (`pythonrt.Manager`, env var patterns) are reusable. The runner package mirrors the same patterns with explicit parameterization instead of `os.Getenv`.
- `ServerOnly` mode (T02) still works but is now internal — `stigmer up server` passes `serverOnly=false` (full stack).
