## Decisions Made

- **SDK-first placement**: Consistent with IdentityProvider/ApiKey/OAuthApp patterns. Platform builders *could* embed admin CRUD; even if they don't, SDK placement keeps one rule for all admin CRUD and makes docs easier.
- **IdentityProvider as reference pattern**: ApiKey is too simple (no edit, no detail). IdentityProvider has the full CRUD shape needed.
- **Dropped PlatformClientQuickStart component**: The create-reveal screen doesn't show code snippets. Platform builders create PlatformClients via the Console and follow `docs/guides/platform-client-auth.mdx` for integration.
- **Single PlatformClientSecretAlert for both create and rotate**: DRY component, `context: "created" | "rotated"` prop differentiates messaging.
- **Default create form state**: `autoProvisionAccounts: true`, `autoGrantOnOrg: true`, `neverExpires: true` — matches the primary use case (embed Stigmer with JIT users).

## Learnings

- The codegen file `sdk/typescript/src/gen/platformclient.ts` has a pre-existing import bug: `MintUserTokenRequest`/`MintUserTokenResponse` are imported from `io_pb` but live in `token_pb`. This was introduced when `token.proto` was split from `io.proto` but codegen wasn't re-run for the OSS repo stubs. Needs `make codegen` to fix.
- `sdk/react` has no dedicated eslint config — lint is done at the Console level or monorepo level.
- The generated client property is `stigmer.platformclient` (all lowercase), not `stigmer.platformClient`. This is codegen-driven and consistent across all resources.

## Open Questions

- Secret fingerprint display format: currently showing `••••{last-4}`. May want a more structured format like `stgm_pc_••••abcd`.
- Expiry modification post-creation: currently allowed in the edit form. May want to freeze after creation to match API key conventions.
- Allowed origins validation: currently client-side accepts any string. Could add URL origin validation (block paths, require scheme).
