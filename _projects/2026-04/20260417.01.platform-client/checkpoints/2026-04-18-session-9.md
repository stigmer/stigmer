## Decisions Made

- **PlatformClient-provisioned accounts are a fourth account type ("Platform"), not a sub-category of "Federated"**: Different trust model (Stigmer signs tokens vs external IdP), different auth chain (PlatformClientTokenAuthenticationProvider vs FederatedIdentityResolver), different idp_id encoding (composite stgm_pc|{org}|{user_id} vs raw OIDC sub). Calling them "Federated" would confuse readers who actually set up OIDC federation.
- **Kept PlatformClient as a single-page guide (not 4 pages)**: The original plan called for overview + quick-start + token-endpoint + auto-provisioning. Pushed back — PlatformClient's value is simplicity, and the documentation structure should reflect that. Federation has 7 pages because it has 3 provisioning modes and multiple use cases. PlatformClient has ONE workflow.
- **Renamed "JIT provisioning" to "Automatic account creation"**: Plainer language per the doc writer role. JIT is jargon for a guide context.
- **Deferred demo components**: Doc writer role mandates live demos for Console-visible features. PlatformClient has Console UI. But creating demo components is significant engineering work (fixtures, scenario player, etc.) — separate task.
