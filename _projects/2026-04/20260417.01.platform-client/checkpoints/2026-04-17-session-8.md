## Decisions Made

- **Org-scoped identity**: Same user_id across any PlatformClient in the same org = one IdentityAccount. The multi-app scenario (dashboard + mobile + admin) is the common case, and per-PlatformClient scoping was creating 3x identity entries for the same human.
- **Keep PlatformClient name**: Evaluated EmbedApp, IntegrationApp, HostApp, StigmerApp. Current name is defensible and not worth the migration churn across 5 stub languages, SDKs, console, and docs.
- **Email is never a key**: Profile data only. Updated on each mint. Two different users can share the same email within an org. Identity resolution uses only `(org, external_user_id)`.
- **No migration needed**: Pre-GA feature on feature branch. Any existing test data is expendable.

## Learnings

- Auth0 Custom Token Exchange is the closest IDP-provided equivalent to PlatformClient, but locked behind $800+/month B2B Professional. WorkOS has no equivalent at any tier.
- PlatformClient is a genuine product differentiator, not a build-vs-buy mistake.
- The `idp_id` composite key design is elegant: changing one segment (platform_client_id -> org) changes the entire identity resolution model without touching any schema, FGA model, or RPC signature.
