- Wrote DD-005 (`design-decisions/005-t05-sdk-design-supersedes-original-plan.md`) documenting why the original T05_0_plan.md is superseded: no OAuth2 client_credentials grant (gRPC pivot), no SDK-level token caching, `mintUserToken` naming, and Java SDK inclusion.

- `sdk/typescript/src/platform-client-auth.ts` — `PlatformClientAuth` class and `createPlatformClientAuth(config)` factory.
- Exports `PlatformClientAuthConfig`, `MintUserTokenInput`, `MintUserTokenResult`.
- Uses `@connectrpc/connect-node` transport with RPC metadata + error-strip interceptors (no auth interceptor — `mintUserToken` is public).
- Exported via `@stigmer/sdk/node` barrel (`node.ts`). NOT exported from the default browser entry (`index.ts`).
- Tests: `__tests__/platform-client-auth.test.ts` — 6 tests, all passing.
- Example: `examples/mint-user-token.ts` — Express endpoint showing the full pattern.

## Key Design Decisions (Session 5)

- **Separate helper, not a new auth mode.** PlatformClient credentials do not replace `apiKey` for server-to-server calls. Adding them to the main client config would imply they do.
- **No SDK-level token caching.** The token is user-keyed; caching belongs to the platform builder's backend. Adding it later is non-breaking.
- **`mintUserToken`, not `createUserToken`.** Mirrors the proto and the Session 1 naming decision.
- **Java included as a first-class peer.** The original T05 plan omitted it. Codegen already produced the wire method; the ergonomic layer was the only gap.
- **Server-only by construction (TypeScript).** Exported from `@stigmer/sdk/node`, not the browser entry. No runtime guards needed.
