## Decisions Made

- **Minimal ESLint config for SDK**: Only stigmer plugin rules, no `@typescript-eslint/*`. Rationale: `tsc --noEmit` with strict mode already enforces type safety. ESLint is specifically for boundary enforcement. TypeScript ESLint rules can be added later as a separate initiative.
- **`@typescript-eslint/parser` needed**: ESLint can't parse TypeScript without it. Added as explicit devDependency rather than relying on workspace hoisting from the web app.
- **`projectService: false`**: Set in parser options to avoid type-aware linting overhead since we're only running custom rules that don't need type information.
- **312 opacity modifier warnings are pre-existing tech debt**: These are `warn` level and don't block the lint. Remediating them requires proposing new theme tokens — a separate initiative.
