## Decisions Made

- **`auth/` stays top-level** — It's infrastructure with a clean barrel export, not a product area. Moving to `domain/auth/` would add depth without adding clarity.
- **Colocated `app/` components moved** — SessionPage, AgentListPage, LibraryLanding etc. extracted from `app/` routes into `domain/` so app/ is truly routes-only.
- **`InvitePageClient.tsx` kept in `app/`** — Single-use file with no reuse elsewhere. Moving it would add structure without adding value.
- **`settings-nav.ts` kept in layout** — Consumed by both ManagementSidebar (layout) and settings/page.tsx (route). Keeping with layout avoids cross-domain imports.
- **Library preserves resource-type subdirs** — `domain/library/agents/`, `/skills/`, `/mcp-servers/` mirrors the route structure for navigability.
