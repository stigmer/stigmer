## Decisions Made

- **Diataxis type**: Reference — same register as SDK Overview. Precise technical language, assumes familiarity. Not a tutorial, not a how-to.
- **Sidebar ordering**: React SDK placed before Streaming (`["react", "streaming", "resources"]`). Setup pages come first, then how-to guides, then reference.
- **No SDKTabs**: React-only page uses plain tsx/typescript code blocks, not the multi-language SDKTabs component.
- **No live demos**: This is a setup and orientation page. Demos belong on the per-domain reference pages (future sub-project work).
- **Domain table approach**: 16 domains with counts and descriptions, not exhaustive hook/component lists. Verified 67 hooks and 59 components against `sdk/react/src/index.ts`. Keeps the page maintainable while giving readers enough to find what they need.
- **Scope boundary**: Page does not try to list every hook or component. That work is deferred to auto-generated per-domain pages from the sub-project.
- **Peer dep install command**: Single `npm install` with all 4 required packages. Noted `@base-ui/react` as optional. Briefly explained why `@stigmer/protos` and `@bufbuild/protobuf` are needed.
- **Auth deferral**: Setup example uses `apiKey` (matching SDK Overview primary example). Added note pointing to SDK Overview > Authentication for browser token patterns.

## Learnings

- The React SDK has grown to 67 hooks and 59 components across 16 domain folders — significantly more than the "61+ hooks and 55+ components" estimate in earlier planning
- `@base-ui/react` is the only optional peer dependency (marked in `peerDependenciesMeta`)
- `StigmerProvider` renders a `<div class="stgm">` for CSS isolation — this is a key detail for the docs because it means the SDK styles don't conflict with the host app
- The `preset` prop accepts a `ThemePresetId` from `@stigmer/theme` — theming is more than just className customization
