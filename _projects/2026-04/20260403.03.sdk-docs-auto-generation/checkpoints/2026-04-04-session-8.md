## Decisions Made

- **Diataxis type**: How-to guide ("Here is how to consume real-time execution updates"), not Reference (the generated pages already cover the reference)
- **Scope boundaries**: Focused on production patterns not covered elsewhere — phase-aware subscribe loops, snapshot field orientation, terminal phase detection, stream error handling, client-side cancellation, and Workflow Execution streaming. Explicitly out of scope: basic subscribe (Quickstart covers it), approval handling (Connect Tools covers it), full type tables (auto-generated reference pages cover them)
- **Section structure**: Six focused sections — Subscribe, Read the snapshot, Detect completion, Handle stream errors, Cancel a stream, Subscribe to a Workflow Execution — plus opening paragraph and What's next cards
- **Accessor names**: Used correct plural names from actual SDK source (Python `client.agent_executions`, Java `client.agentExecutions()`) consistent with SDK Overview page, not the singular names from the codegen bug in generated pages
- **API asymmetry documented clearly**: AgentExecution subscribe takes a bare string ID; WorkflowExecution subscribe takes a `SubscribeWorkflowExecutionRequest` object with `executionId` field. Called out explicitly with numbered differences
- **Resources separator**: Added `"---Resources---"` separator in meta.json between hand-written pages (streaming) and auto-generated resource pages, following the root docs/meta.json convention (`"---Learn---"`, `"---Reference---"`)
- **Cancellation callout**: Added a warning callout clarifying that cancelling a stream does not cancel the execution itself — links to `cancel` and `terminate` methods
- **Error distinction**: Separated transport-level stream errors (caught by SDK exceptions) from execution-level failures (reported in `status.error` with phase `EXECUTION_FAILED`)

## Learnings

- Go SDK phase constants follow the connect-tools tutorial convention (`stigmer.ExecutionCompleted` etc.) even though the underlying proto has `ExecutionPhase_EXECUTION_COMPLETED` — maintained consistency with existing docs
- Java `StigmerStream<T>` implements `Iterator<T>` and wraps `StatusRuntimeException` into `StigmerException` in both `hasNext()` and `next()`
- TypeScript subscribe accepts an optional `AbortSignal` as a second parameter for client-side cancellation
- WorkflowExecution status tracks progress through `tasks` (a list of `WorkflowTask` with individual status) rather than `messages`
