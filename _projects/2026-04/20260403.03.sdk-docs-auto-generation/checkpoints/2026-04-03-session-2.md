## Decisions Made

1. **Description extraction strategy**: Extract only the first paragraph from proto comments. Do not attempt to parse or filter markdown subheadings, tables, or structured sections within proto comments. This keeps the template simple and predictable, and makes T05 (proto comment audit) about improving first paragraphs rather than restructuring entire comments.

2. **T03-T05 dependency resolution**: Acknowledged the coupling between template design and proto comment standardization. Pragmatic approach: T03 defines a stable, simple extraction rule (first paragraph), T05 then improves the quality of those first paragraphs. Avoids over-standardization of proto comments.

3. **Method ordering**: User confirmed queries-first ordering. Sort key: get/list/subscribe (priority 1) → create/update/delete (priority 2) → pause/resume/cancel/terminate/recover (priority 3) → everything else (priority 4).

4. **Streaming code examples**: Language-idiomatic patterns rather than abstract pseudo-code. Go uses `Recv()` loop with error check, TypeScript uses `for await...of`, Python uses `for ... in` iterator, Java uses callback pattern.

5. **Example value format**: Full slug-based IDs ("agent-execution-abc123") and prefixed resource names ("my-agent-execution") rather than short codes. Eliminates collision risk between similar resource types.

## Learnings

1. **Proto comment verbosity varies wildly**: Some resources have massive proto comments with embedded YAML examples, instance resolution patterns, and internal developer documentation. The first-paragraph extraction strategy cleanly handles this without needing to parse or understand the structure of these comments.

2. **Streaming methods are identifiable by `ServerStreaming` field**: The `MethodSchema` struct already includes a `ServerStreaming bool` field, populated from proto definitions. No additional schema changes needed.

3. **Method ordering matters for usability**: Placing read operations before write operations follows the common "CRUD" pattern expectation but prioritizes the more frequently used operations (reading data) above less frequent ones (mutations).

4. **Example ID collisions**: Simple prefix-based IDs (e.g., "age-" for both Agent and AgentExecution) cause confusion. Full slug-based IDs ("agent-abc123", "agent-execution-abc123") are clearer and collision-free.
