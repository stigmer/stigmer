## Decisions Made

1. **Internal methods included**: All methods (including operator/system-level RPCs like `bootstrapPolicy`, `simulateSignupWebhook`, `updateStatus`, `cleanupResourcePolicies`) remain in the SDK reference. Rationale: the SDK reference is a reference — it should be complete. Platform operators who need these methods should find docs for them. The descriptions already communicate audience (e.g., "system-level RPC", "platform operators only"). Filtering would prevent operators from finding docs for methods they legitimately need.

2. **No proto annotation for internal methods**: Considered adding an `is_internal` proto option (similar to the existing `is_skip_authorization`), but deferred. The effort of changing proto definitions, updating `proto2schema` to extract the field, and filtering in the generator is disproportionate to the benefit, especially given Decision 1.

3. **Prettier exclusion for generated files**: Auto-generated `docs/sdk/*.mdx` files are excluded from Prettier via root `.prettierignore`. The generator emits correct multi-line fenced code blocks; Prettier's `proseWrap: "always"` and JSX-aware formatting was collapsing short code blocks onto single lines, breaking Markdown fence syntax.

## Learnings

1. **Prettier + generated MDX conflict**: Prettier's JSX-aware formatting treats `<Tab>` content as prose and collapses short fenced code blocks onto single lines. This is technically valid JSX but produces invalid Markdown fenced blocks. The cleanest fix is exclusion via `.prettierignore` rather than working around Prettier's formatting rules in the generator.

2. **Abbreviation-aware sentence splitting is common NLP territory**: A simple skip-list approach (checking if the period follows known abbreviations) handles 95% of cases without introducing an NLP dependency. The abbreviations `e.g.`, `i.e.`, and `etc.` cover most occurrences in technical documentation.

3. **Non-standard CRUD patterns are well-handled**: The generator's input-type detection logic (empty, ID, resource, delete, default) already handles all 17 resources correctly, including Skill's push-based API, IamPolicy's spec-based delete, ExecutionContext's no-update pattern, and IdentityAccount's WhoAmI empty-input pattern.
