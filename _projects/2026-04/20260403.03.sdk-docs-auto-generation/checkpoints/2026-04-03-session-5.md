## Decisions Made

- **SDK docs belong in `protos`**: Added generation as the last step of `make protos` rather than a separate `codegen` dependency, because SDK docs derive from the same proto→schema pipeline as SDK clients.
- **Per-file comparison for staleness**: Used a per-file diff loop instead of `diff -r` to avoid false failures from extra files in `docs/sdk/` (untracked `.go` artifacts, future manual pages from T06).
- **CLI docs deferred**: Removed `gen-cli-docs` and `gen-cli-docs-check` entirely. CLI docs will be rebuilt with improved quality in a separate project.

## Key Code Changes

- `Makefile`: Added `gen-sdk-docs` (runs generator), `gen-sdk-docs-check` (per-file staleness check), updated `protos` to include `$(MAKE) gen-sdk-docs`, simplified `codegen` to just `protos`, removed CLI docs targets.
- `.github/workflows/ci.docs.yaml`: Replaced `cli-docs-freshness` job with `sdk-docs-freshness` using `tools/go.mod`. Added `apis/**` and `tools/codegen/**` path triggers, removed `client-apps/cli/**`.

## Learnings

- The original CLI docs staleness check had a shell logic bug: `exit 1` inside a subshell `(...)` followed by `;` doesn't propagate the exit code -- the subsequent commands run regardless. The per-file loop approach with explicit `exit 1` at the top level avoids this.
- `diff -r dir1 dir2` reports files only in dir2 as differences, which would cause false failures when `docs/sdk/` contains manual pages or stale artifacts not produced by the generator.
