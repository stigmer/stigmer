## Decisions Made

- **`@internal` as the audience separator**: A single `// @internal` line in proto comments separates SDK-facing text (above) from internal developer notes (below). Simple, grep-able, zero tooling overhead.
- **Full content over truncation**: Replaced `docMethodSummary()` (first-paragraph-only) with `docSDKContent()` which preserves all paragraphs before `@internal`. Richer docs for SDK users.
- **Authorization notes are SDK-facing**: Permission requirements like "Requires can_edit permission" are useful for SDK users and kept above `@internal`.
- **`--comprehensive` flag required**: Discovered that `--target=sdk-docs` only works with `--comprehensive`. Without it, the default SDK code generation runs (Go structs), not MDX docs.

## Learnings

- The `proto2schema` tool faithfully copies proto comments into JSON schemas, including `@internal` markers. The stripping happens at the generator level, keeping schemas as a faithful intermediate representation.
- The generator's `--target=sdk-docs` path is gated behind `--comprehensive`. Running without it silently succeeds but produces Go code instead of MDX.
- Some proto comments had descriptions that were literally just "Custom authorization in handler." -- these needed full rewrites to be meaningful for SDK users.
