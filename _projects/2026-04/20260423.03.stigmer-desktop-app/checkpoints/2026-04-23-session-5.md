## Decisions Made

- **DD-T08-01**: SDK callback pattern for native dialogs — `onBrowseLocalFolder` prop on `WorkspaceEditor` / `SessionComposer` keeps the SDK framework-agnostic while enabling native desktop integration
- **DD-T08-02**: App-level shortcuts over global shortcuts — rejected the original T01 plan's global OS-wide hotkeys; app-level shortcuts are less invasive and follow platform conventions
- **DD-T08-03**: Notifications scoped to runner events only — execution-level notifications deferred to avoid gRPC stream wiring complexity
- **DD-T08-04**: Focus-gated notifications — `document.hasFocus()` check prevents redundant alerts
- **DD-T08-05**: Explicit window state save in `ExitRequested` handler — ensures state is saved despite the hide-to-tray close prevention
- **DD-T08-06**: Route persistence via `router.subscribe()` + localStorage — pure React, independent of window-state plugin

## Learnings

1. `tauri-plugin-window-state` auto-saves on window close events, but our `prevent_close()` + hide pattern may bypass this — explicit `save_window_state()` in `ExitRequested` is the safety net
2. Tauri 2 capability schemas (`gen/schemas/*.json`) auto-regenerate when new plugin permissions are added to `capabilities/default.json`
3. `npm install` resolves `"^2"` more aggressively than Cargo's `"2"` — the former pins to a specific minor version in package.json
4. `tauri-plugin-dialog` transitively depends on `tauri-plugin-fs`
5. react-router-dom v7's `createHashRouter` returns a router with `subscribe()` and `navigate()` methods that work before React mounts — perfect for route persistence
