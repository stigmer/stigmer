## Decisions Made

- **Frontend directory naming**: Standard Tauri convention (`src/` not `src-frontend/`) — the community, docs, and tooling all expect this
- **Tailwind integration**: `@tailwindcss/vite` plugin (not PostCSS) — first-party Vite plugin, same Tailwind 4 as web console
- **No path aliases**: Imports use `@stigmer/*` package names directly (no `@/` alias like the web console)
- **Proof of life scope**: `Stigmer` client with `getAccessToken: () => null` and `deploymentMode: "local"` — proves SDK integration without needing auth

## Surprises / Issues Resolved

- Rust 1.86.0 was insufficient — Tauri transitive deps (`darling`, `serde_with`, `time`) require Rust 1.88+. Upgraded to 1.95.0.
- `tauri.conf.json` rejected `app.title` — in Tauri 2.x, `title` is a window-level property only (inside `app.windows[]`).
- Pre-existing typecheck error in `sdk/typescript/src/gen/runner.ts` (`RunnerStreamServerMessage` duplicate identifier) — not introduced by our changes, exists in `@stigmer/sdk` already.

## Early Flags for Future Tasks

- **Auth in Tauri webview (T03)**: OIDC redirect flows are blocked by many IdPs in embedded webviews. Desktop auth will likely need system-browser-based OIDC with token callback via deep link or local HTTP server. This creates a dependency between T03 (auth) and T05 (URL scheme handler) that was not in the original T01 task graph.
- **`"use client"` directives**: SDK components have these for Next.js — harmless in Vite (ignored), no action needed.
