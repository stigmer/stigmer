# Session Notes: 2026-04-24

## Accomplishments

- Diagnosed production startup crash: `VaultEndpoint.from(URI.create(""))` — "Scheme must not be empty"
- Added `stigmer.vault.enabled` flag (default `false`) to gate all vault bean creation
- Added `@ConditionalOnBean(VaultTemplate.class)` on `VaultClient` as safety net

- Commented out `VAULT_ADDR` and `VAULT_TOKEN` in prod overlay (infra not deployed)

## Decisions Made

- **Explicit enabled flag over URI-presence check**: `@ConditionalOnProperty` with `havingValue = "true"` is unambiguous. The old `prefix`/`name` approach silently matched empty strings.
- **Non-destructive fix**: All vault code preserved. Re-enabling is a single `VAULT_ENABLED=true` env var + uncommenting two kustomize entries.
- **No new secrets group for LLM proxy**: Reused existing `openai` and `anthropic` secrets groups rather than creating a separate `stigmer-llm-proxy-credentials` group.

## Key Code Changes

- `vault-starter/VaultConfig.java`: `@ConditionalOnProperty(name = "stigmer.vault.enabled", havingValue = "true")`
- `vault-starter/VaultClient.java`: Added `@ConditionalOnBean(VaultTemplate.class)`
- `application-vault.yaml`: Added `enabled: ${VAULT_ENABLED:false}`
- `_kustomize/base/service.yaml`: Fixed proxy secret refs to `$secrets-group/openai/prod.api-key` and `$secrets-group/anthropic/prod.api-key`
- `_kustomize/overlays/prod/service.yaml`: Commented out `VAULT_ADDR` and `VAULT_TOKEN` with `TODO(vault-migration)` markers

## Learnings

- Spring Boot's `@ConditionalOnProperty` without `havingValue` matches empty strings — it only rejects the literal `"false"`. Use `havingValue = "true"` for explicit opt-in.
- `@Component` classes with constructor-injected dependencies will fail if the dependency bean doesn't exist, even if the dependency's config class is skipped. Always pair `@ConditionalOnBean` on the consumer.
