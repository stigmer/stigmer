## Decisions Made

- **SettingsView is layout-only**: No business logic; all domain UI comes from SDK components (`ApiKeyListPanel`, `CreateApiKeyForm`, `ApiKeyCreatedAlert`, `EnvironmentVariableEditor`). This follows the platform's anti-custom-component policy.
- **PrefilledCreateForm uses native setter technique**: Same pattern as `TypingComposer` — uses `Object.getOwnPropertyDescriptor` on `HTMLInputElement.prototype` to programmatically set input value and dispatch a synthetic `input` event. This ensures React controlled inputs pick up the value.
- **UserMenu as internal AppShell component**: The user menu overlay lives inside `AppShell.tsx` as a private component, controlled via `showUserMenu` prop. Not extracted into its own file since it's tightly coupled to AppShell's layout.
- **Selective staging**: Only the API key setup files were committed; unrelated backend and project files were left unstaged.

## Learnings

- The `site` package uses `file:` dependencies for the SDK, which means `node_modules/@stigmer/react` is a **copy** of the SDK `dist/`, not a symlink. Any type changes in SDK source require a full rebuild (`npm run build` in `sdk/react`) followed by `npm install` in `site/` to copy the new artifacts.
- `EnvironmentVariableEditor` calls `stigmer.environment.get(id)` internally, not `getByReference`. The fixture infrastructure only had the latter, so we had to add the former.
- Pre-existing React ref type incompatibilities in `sdk/react/src/internal/markdown-components.tsx` show up in the `tsc` output but are unrelated to the current work.
