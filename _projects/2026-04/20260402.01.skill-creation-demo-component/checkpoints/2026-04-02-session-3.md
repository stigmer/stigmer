# Session 3 Checkpoint — ScenarioPlayer Scroll-Trap Fix

**Date**: 2026-04-02

## What Changed

Fixed a scroll-trap UX bug in `ScenarioPlayer.tsx` where the
IntersectionObserver reset loop prevented users from scrolling past
auto-playing demo scenarios on documentation pages.

**Single file changed**: `site/src/components/docs/demos/engine/ScenarioPlayer.tsx`

## Root Cause

Two behaviors combined into a layout-shift feedback loop:

1. At `stepIndex === -1`, children were not rendered — container collapsed to ~40px
2. IntersectionObserver reset `stepIndex` to `-1` on every viewport enter and exit

Scrolling away collapsed the container, yanking page content upward,
which pulled the demo back into the viewport and re-triggered auto-play.

## Fix Applied

Switched from reset-on-intersection to pause/resume:

- Initial `stepIndex` changed from `-1` to `0` — first frame always rendered
- IntersectionObserver simplified to `setPlaying(entry.isIntersecting)`
- Removed `isStarted` concept and all `-1` sentinel logic
- Replay resets to step `0` instead of `-1`

## Key Decisions

| Decision | Rationale |
|----------|-----------|
| Start at step 0, not -1 | Eliminates layout collapse; both scenarios use `delayMs: 0` for step 0 so functionally identical |
| Pause on exit, don't reset | Users retain playback progress; no jarring restart on scroll-back |
| Remove `isStarted` entirely | With `stepIndex` always >= 0, the guard is dead code; removing simplifies state model |
