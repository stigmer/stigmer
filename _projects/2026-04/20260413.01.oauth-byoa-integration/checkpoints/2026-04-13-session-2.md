## Decisions Made

- **GAP 4 — targeted exception propagation**: Only `McpOAuthException` becomes a hard failure from `refreshIfExpired`. Other exceptions (e.g. transient managed env read errors) remain non-fatal. This is because `McpOAuthException` means "token is definitively expired and unrecoverable" — the refresh service already formats these with user-friendly messages. The downstream `McpEnvironmentValidator` handles missing-key cases from transient failures correctly, but cannot detect expired-but-readable tokens.

- **GAP 8 — message wording**: Error message says "Please enter a token manually instead" rather than referencing BYOA, since BYOA (T04/T05/T07) doesn't exist yet. Will be updated when BYOA ships.

- **GAP 9 — status code mapping**: `WorkflowFailedException` maps to `INTERNAL` (not `FAILED_PRECONDITION`) because the failure is from the runner workflow, not a caller precondition. `WorkflowServiceException` maps to `UNAVAILABLE` following the established codebase pattern in pause/resume/terminate handlers.

## Key Discovery

The "non-fatal" design in `injectMcpOAuthFromManagedEnvironment` had a subtle bug: when refresh fails but the expired token is still physically stored in the managed environment, the token gets read and injected successfully. The `McpEnvironmentValidator` only checks key presence, not value validity, so validation passes and the agent runs with an expired token leading to a confusing 401 at runtime. This justified making `McpOAuthException` a hard failure.
