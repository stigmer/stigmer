## Decisions Made

- **Idempotent disconnect (desired-state semantics)**: The original proto specified NOT_FOUND for missing grants. During planning, this was changed to return `disconnected: false` without error. Rationale: Stigmer is a declarative platform, disconnect expresses desired state ("no connection"), and idempotent semantics handle race conditions, retries, and partial failures. Proto comments updated to match.

- **Delete order (environment first, then grant)**: Environment holds secrets (tokens) — delete it first to eliminate sensitive data. If grant delete subsequently fails, the orphaned grant is harmless metadata pointing to a deleted environment. If environment delete fails, the grant still has the `environment_id` for retry.

- **EXPIRY_BUFFER_SECONDS = 60 (independent constant)**: Health evaluation uses the same 60-second buffer as `OAuthTokenRefreshService.EXPIRY_BUFFER_SECONDS`. Defined independently in `LookupGrant` with a comment noting alignment — avoids coupling a handler step to a service class for a single constant.

- **Files NOT modified (correcting task plan)**: `McpServerCommandController.java` and `McpServerGrpcAutoController.java` are auto-generated by the annotation processor — no manual changes needed.
