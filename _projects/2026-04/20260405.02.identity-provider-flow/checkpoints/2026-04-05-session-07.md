## Decisions Made

- **Template-based presets, not discovery-based**: For known providers, URLs are constructed from user input (tenant name, region, etc.) without any network call. OIDC Discovery is only used for the "Custom OIDC" path. This avoids CORS issues entirely for the 5 most popular providers.
- **Wizard augments, doesn't replace**: `CreateIdentityProviderForm` (Phase 6) is kept as the low-level primitive. The wizard is the opinionated, guided alternative. Platform builders choose which fits their needs.
- **Detail panel is inline, not a separate route**: IdPs are small cardinality (1-3 per org). Inline view/edit in the same settings page is simpler than sub-routing. Matches Members and API Keys patterns.
- **Discovery hook is internal**: `useOidcDiscovery` is not exported from the public barrel initially. Available for promotion if platform builders need it.
- **SSO login flow deferred**: The SSO OIDC RP login flow (redirect to corporate IdP, handle callback) was explicitly deferred. Only the IdP management CRUD pages were built. SSO will need auto-provisioning of federated accounts (different trust model from platform-managed).
- **Imperative discovery pattern**: `useOidcDiscovery` returns a `discover()` function (like mutation hooks) rather than an effect-based pattern, because discovery is triggered by user action ("Continue"), not by render.
