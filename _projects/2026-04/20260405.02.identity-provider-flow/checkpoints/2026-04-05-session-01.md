## Decisions Made

- **No `external_sub` field**: `idp_id` already serves as the identity provider's subject identifier for all provisioning modes. For federated accounts, we'll store the raw OIDC `sub` in `idp_id` (removing the compound `federated:` prefix). The `identity_provider_ref` field (already on IdentityAccountSpec) provides IdP scoping. Compound uniqueness index on `(identity_provider_ref, idp_id)` deferred to Phase 3.

- **Phase 1 scoped to email fix only**: The T01 plan proposed also adding the compound index in Phase 1, but since the data model for raw `external_sub` storage doesn't exist yet, the compound index was deferred to Phase 3 where it belongs.

- **Dropped `sparse` on email index**: The replacement index is non-sparse, allowing future queries for accounts without email addresses (e.g., data quality audits).

## Key Code Changes

- `stigmer-cloud/.../migrations/U20260405_FixEmailUniqueness.java`: New Mongock migration. Drops unique sparse email index, creates non-unique ascending. Idempotent forward, honest rollback.

## Learnings

- Mongock migrations are identified by their `id` string (not class name) — once applied, they're immutable. Corrective migrations must be new change units.
- The `search_text_index` from U20260308 also covers `spec.email` but is a separate text index type — not affected by B-tree index changes.
- The 52 modified handler files in stigmer-cloud are from the IAM role/permission separation project, not this session. Selective staging was critical.
