## Decisions Made

- **listByOrg over SearchService**: SearchService only indexes `agent, skill, mcp_server, workflow` — identity providers are not searchable. A dedicated `listByOrg` RPC is the correct approach since IdPs are small cardinality (1-3 per org) and always org-scoped.
- **Proper proto message construction**: Hooks use `create(Schema, { ... })` from `@bufbuild/protobuf` instead of plain objects — TypeScript requires `$typeName` from the `Message` base type.
- **NOT_FOUND as absence**: `useSsoProvider` uses `isNotFound()` from `@stigmer/sdk` to treat NOT_FOUND as "no SSO configured" (null) rather than an error — critical for unauthenticated login page rendering.
- **DeleteResourceInput for delete hook**: Uses the SDK's simplified `DeleteResourceInput` type (resourceId + optional versionMessage/force) rather than raw proto construction — matches the `useDeleteApiKey` pattern.
- **Both hooks and components**: Even though IdP management is admin-only, we build both hooks and styled components for pattern consistency across all feature folders.
- **IAM policy reuse, not rebuild**: The `iam-policy/` feature folder already exists from the IAM role/permission separation project. Phase 7 (web app) will compose identity-provider and iam-policy components together.
