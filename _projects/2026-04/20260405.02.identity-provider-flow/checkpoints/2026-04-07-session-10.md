## Decisions Made

- **Global issuer uniqueness, not org-scoped**: The `iss` claim is the sole JWT routing key. The issuer cache is a flat `issuer -> IdP` map with no secondary disambiguation. Global uniqueness is the only correct constraint.
- **Defense in depth**: Application-level validation (clear error messages) + MongoDB unique index (race condition protection). Both layers are needed.
- **Synchronous cache invalidation, not event-driven**: The `ApiResourceEventPublisher` is a no-op (NATS not on classpath). Direct cache calls from the pipeline are simpler and correct for low-cardinality admin resources.
- **Always invalidate all, not selectively**: `issuerCache.invalidate()` + `decoderCache.evictAll()` on every mutation. IdPs are single-digit cardinality, so the cost is negligible. Simplicity over optimization.
- **Best-effort cache invalidation**: The step catches exceptions and always returns success. Cache issues should never roll back a successful mutation. Caches self-heal on TTL expiry.

## Learnings

- The `CheckDuplicate` step in the framework only checks `org + slug` uniqueness — it's a general-purpose step for API resources. Domain-specific uniqueness (like issuer uniqueness) requires custom validation steps.
- The `ApiResourceEventPublisher` has a no-op fallback (`PublisherFallbackAutoConfiguration`) when NATS is not on the classpath. Event-driven cache invalidation is not viable in the current setup.
- MongoDB multikey indexes on array fields create separate index entries per array element. With `unique: true`, no two documents can share the same array element value — exactly what's needed for issuer uniqueness.
- The partial filter `{ "spec.allowedIssuers.0": { $exists: true } }` is needed because IdPs with empty `allowedIssuers` arrays should not be constrained.
