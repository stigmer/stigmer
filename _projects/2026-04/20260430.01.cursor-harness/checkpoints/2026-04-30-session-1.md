## Decisions Made

- **Field number 10** (corrected from plan's field 11): SessionSpec fields are 1-9 with no gaps or reserved declarations. Using 10 avoids creating an unexplained gap that would confuse future maintainers.
- **Enum in `enum.proto`** (not inline in spec): Follows the package convention where shared enums live in a dedicated `enum.proto` file, alongside `GitWriteBackMode`.
- **NATIVE not LANGGRAPH**: Renamed `HARNESS_LANGGRAPH` to `HARNESS_NATIVE` -- LangGraph is an implementation framework, "native" names what the harness IS to the user (Stigmer's own engine). Keeps enum values at the same abstraction level as `HARNESS_CURSOR`.
- **No validation constraints**: All `Harness` enum values are valid at the proto layer. `UNSPECIFIED` defaulting to native is handled in server logic (T04).
- **No Runner proto changes**: The Runner is infrastructure-level and remains harness-agnostic. The harness concept lives on Session only.
- **MESSAGE_THINKING is harness-agnostic**: Not Cursor-specific. The native engine with Claude extended thinking can also emit thinking events.
