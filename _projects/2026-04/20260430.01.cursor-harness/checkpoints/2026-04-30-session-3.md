## Decisions Made

- **Activity signature**: `ExecuteCursor(executionId, threadId)` -- mirrors ExecuteGraphton. threadId stores Cursor agentId in the existing `SessionSpec.thread_id` field. No new proto fields.
- **Durable HITL**: The T02 design proposed a blocking model (hook blocks while waiting for approval). The user correctly identified this is NOT durable (process dies = approval lost). Redesigned to hook-deny + return to workflow + reinvoke pattern. Same `approvalGateResolved` signal as LangGraph.
- **No HTTP server for hooks**: T02 proposed a local HTTP server for hook IPC. Simplified to file-based state (hook reads a JSON state file written before agent.send()). No server, no port, no IPC.
- **Pause/resume**: Supported via `run.cancel()` + `Agent.resume()`. Maps naturally to workflow signals. Not skipped for MVP.
- **Approval notification**: No polling needed. Workflow uses same signal pattern. Activity reads decisions from DB on reinvocation.

## Learnings

- Cursor Agent is durable on Cursor's backend -- `Agent.resume(agentId)` works across process restarts, making checkpoint-equivalent behavior possible without LangGraph-style checkpoints
- The "soft guarantee" of prompt-guided re-execution (telling the agent "tool X was approved, execute it") is reliable because the agent has full conversation context
- The T02 blocking HITL model was a design flaw (not durable). Always validate designs against the "what if the process dies after 10 days" test.
- `SessionSpec.thread_id` (field 3) is a perfect reuse for Cursor agentId -- the proto comment already says "carries conversation history across executions"
