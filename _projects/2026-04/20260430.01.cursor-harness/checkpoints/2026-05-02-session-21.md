## Decisions Made

- **Data source strategy**: Keep `run.stream()` (SDKMessage) as primary source. Defer `onDelta` enrichment to a separate conversation. The stream provides sufficient data for tool call attachment, sub-agent tracking, and thinking blocks.
- **No proto changes needed**: The existing `AgentMessage.tool_calls`, `SubAgentExecution`, and `MESSAGE_THINKING` enum already support all the data we need. The fix was purely in the TypeScript translator and React rendering.
- **Tool call attachment model**: On "running" events, create new ToolCall and append to parent AI message. On "completed"/"error", find existing ToolCall by `call_id` and update in place. Edge case: tool call before any AI text creates an empty AI message.
- **Sub-agent tracking**: Parse `args.subagentType`, `args.description`, `args.prompt` from the task tool call event. Track via internal Map keyed by `call_id`.

## Learnings

- `Agent.create()` returns a Promise (not a synchronous object) — the Cursor SDK skill documentation doesn't make this obvious
- The SDK's `tool_call` stream events for `read` and `glob` only emit "running" status, no "completed" event (they complete instantly). Only `shell` had both running and completed events in the test capture.
- `run.conversation()` IS supported on local runs and returns typed ConversationStep data including full tool call args/results
- The `onDelta` channel provides 436 events vs 245 in the stream — significantly richer, including `token-delta`, `shell-output-delta`, and `step-completed` with timing
