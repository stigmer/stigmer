## Decisions Made

- **Message-based instruction injection (not rules files)**: Agent instructions are prepended to the first user message rather than written as `.cursor/rules/` files, avoiding workspace pollution. Cursor maintains conversation state across `Agent.resume()` calls, so instructions persist.
- **Platform mount for skills**: Skills are written to `~/.stigmer/sessions/{id}/platform/skills/` with a symlink from the workspace `.stigmer/` directory, replicating the Python agent-runner's virtual platform mount pattern.
- **MCP merge semantics**: Session-level MCP usages override agent-level on slug collision (same as Python runner's `merge_mcp_server_usages`). Skill refs are unioned and deduplicated by slug (same as `merge_skill_refs`).
- **Multi-workspace**: `session.spec.workspaceEntries` resolved to `string[]` and passed to `Agent.create({ local: { cwd } })`. Primary workspace (first entry) used for platform files.

## Learnings

- The Cursor SDK has no `systemPrompt` parameter — instructions must be delivered via user message or rules files
- `Agent.resume()` doesn't persist mcpServers — they must be re-passed on every resume
- The Python agent-runner's platform mount uses path interception (not symlinks), but Cursor reads files directly from the filesystem, so symlinks are the right approach for the TS runner
