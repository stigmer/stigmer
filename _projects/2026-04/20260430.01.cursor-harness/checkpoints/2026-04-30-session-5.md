## What Was Done

Added cursor-runner as an optional second managed worker in both the CLI daemon (`stigmer up server`) and the standalone runner path (`stigmer up` / `stigmer up runner`). Also resolved the critical proxy architecture question: `global.fetch` interception enables credential-free runners in cloud mode, maintaining architectural parity with the LLM proxy pattern.

### Step 0: Cursor SDK Proxy Research

- Verified that `@cursor/sdk` does NOT support custom `baseURL` or proxy configuration
- The `AgentOptions` interface only accepts `apiKey`, `model`, `local`/`cloud`, `mcpServers`, `agents`, `name`, `agentId`
- Decision: Cloud mode uses key injection at deploy time (k8s secret), NOT proxy. Local mode uses direct user-provided `CURSOR_API_KEY`.
- Documented in `design-decisions/cursor-sdk-proxy-support.md`

### Step 1: cursor-runner config.ts Alignment

- Made `STIGMER_TOKEN` optional in local mode (`string | null` type, cloud-only `requireEnv`)
- Added `normalizeEndpoint()` function to handle both `host:port` and `http://host:port` formats
- Updated `StigmerClient` to conditionally add auth header (no `Bearer null` in local mode)

### Step 2: embedded/cursorrunner/ Package

- Created `cursorrunner.go`: `SourceFS()`, `IsAvailable()`, `SourceDir()`, `DevRepoRoot()`
- Created `cursorrunner_dev.go`: dev-mode source locator (walk from executable, env override)
- Created `cursorrunner_embed.go`: placeholder for T09 embedding

Key difference from agentrunner: added `SourceDir()` returning the absolute filesystem path (npm install and tsx need real FS, not just `fs.FS`).

### Step 3: Node.js Bootstrap + Env Builders

- Created `nodert/bootstrap.go`: shared `EnsureNodeAvailable()` (version >= 20), `EnsureDepsInstalled()` (npm install with staleness check), `TsxArgs()` (resolve tsx from node_modules)
- Created `daemon/runner_cursor.go`: `bootstrapCursorRunnerRuntime()` and `buildCursorRunnerEnv()` for daemon path
- Created `runner/cursor.go`: `IsCursorRunnerAvailable()`, `BootstrapCursorRunnerRuntime()`, `BuildCursorRunnerEnv()` with `CursorEnvParams` for standalone path

### Step 4: Daemon Wiring

- Added `CursorRunnerPIDFileName` constant
- Added cursor-runner to orphan cleanup PID map and log rotation file list
- Extended `buildComponents` to conditionally include cursor-runner after agent-runner
- Both workers share the same `embeddedIdentity` (runner ID, task queue)
- Cursor-runner component only registered when `STIGMER_CURSOR_RUNNER_NODE_BIN` and `STIGMER_CURSOR_RUNNER_APP_DIR` env vars are set

### Step 5: Standalone Runner Wiring

- Modified `startNativeRunner` to optionally start cursor-runner alongside Python agent-runner
- `startCursorRunnerProcess()` handles bootstrap, env, tsx invocation, log file
- Signal handling: SIGTERM sent to cursor-runner when agent-runner exits
- Added `CursorRunnerPID` field to `RunnerState`

### Step 6: Secrets + Progress

- `CURSOR_API_KEY` detected from env or secrets map in `StartWithOptions`
- Non-fatal: if bootstrap fails, daemon continues without cursor-runner
- Progress: "Bootstrapping Node.js runtime" phase when cursor-runner available
- Log messages: "Cursor harness: enabled" / "Cursor harness: skipped (CURSOR_API_KEY not set)"

## Key Decisions

- **Cursor SDK has no baseURL support** → Key injection at deploy time for cloud, direct user key for local
- **Cursor harness is optional** → Env-var driven detection, non-fatal bootstrap
- **Node.js from system PATH** → Require >= 20, npm install for deps. Embedding deferred to T09
- **Both runner paths covered** → Daemon (`stigmer up server`) and standalone (`stigmer up` / `stigmer up runner`)
- **Docker runner path deferred** → Multi-process container pattern not in T05 scope
- **Non-fatal failures** → If cursor-runner bootstrap fails, agent-runner continues normally
