## What Was Done

Implemented the embedded cursor-runner packaging, mirroring the Python agentrunner pattern. The cursor-runner TypeScript service can now be compiled to JavaScript at build time, embedded in the CLI binary via `go:embed`, and bootstrapped at runtime with a managed Node.js download + npm install for platform-specific native dependencies.

### Critical Discovery: Bun Compile Not Viable

The original plan assumed `bun build --compile`. Research revealed that `@temporalio/worker` depends on Node-API native modules, `worker_threads`, `vm`, and `async_hooks` -- all Node.js-specific APIs that Bun does not support. Temporal officially states workers in Bun are unsupported. Node.js SEA was also evaluated but rejected due to fragile cross-platform native module handling.

## Key Decisions

- **Bun compile invalidated**: Temporal Worker SDK requires Node.js-specific APIs (Node-API native modules, worker_threads, vm). Bun is unsupported.
- **Mirror Python agentrunner pattern**: Embed source via go:embed, download managed Node.js at first bootstrap, npm install for native deps. Same UX as Python runtime.
- **Node.js 22.22.2 LTS**: Active LTS through April 2027. Cursor SDK requires >= 20. Official pre-built binaries for all platforms.
- **Two-mode bootstrap**: Dev mode (system Node.js + tsx) preserved for developers. Embed mode (managed Node.js + compiled JS) for release binaries.
- **Entry args via env var**: `STIGMER_CURSOR_RUNNER_ENTRY_ARGS` communicates the entry point from bootstrap to the daemon process. Dev mode passes tsx args, embed mode passes `dist/main.js`.
- **tsc at build time, npm at runtime**: TypeScript compiled to JavaScript during sync.sh. npm install runs at runtime because native modules (@temporalio/core-bridge) are platform-specific.
