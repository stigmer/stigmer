## Learnings

- Cursor SDK reports MCP tool calls with generic `name: "mcp"` — the actual tool details are nested inside `event.args` as `{ providerIdentifier, toolName, args }`. The preToolUse hook receives the actual tool name though.
- The LangGraph runner has a 24-hour staleness threshold for connect backfill — stale servers get re-discovered automatically. The cursor-runner currently only checks for empty capabilities.
- The `PendingApprovalComputer` on the Java backend is purely reflective — it scans `ToolCall` entries for `requires_approval == true && status == WAITING_APPROVAL`. If the runner doesn't set these fields, the approval flow is invisible to the server.

## Open Questions

- **Hook timing**: Need to verify that Cursor loads `.cursor/hooks.json` on each `agent.send()` call, not just at `Agent.create()` time. If hooks are only loaded at creation, the state file updates between runs may not take effect.
- **Staleness backfill**: The Python runner re-discovers MCP servers older than 24h. The cursor-runner currently only handles never-discovered servers. Consider adding staleness check.
