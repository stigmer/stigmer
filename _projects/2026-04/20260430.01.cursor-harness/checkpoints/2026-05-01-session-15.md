# Session Notes: May 1, 2026 — Session 15

## Accomplishments

- Fixed the 60-120 second dev-mode runner startup delay
- Root cause: `setup-sidecar-dev.sh` didn't set `buildVersion`, so both Python and Node.js runtime managers ran `refreshDevSource()` unconditionally on every restart
- Solution: inject a content hash of embedded source as `buildVersion` via ldflags

## Key Code Changes

- **`client-apps/desktop/scripts/setup-sidecar-dev.sh`**: Added content hash computation (`find | sort | xargs shasum | shasum | cut`) and injected it as `buildVersion` via `-X` ldflags. Versions now look like `dev-a4baea168b83` — stable across restarts but change when source is modified.

## Decisions Made

- **Content hash over timestamp**: A timestamp would invalidate the cache on every build even if source is unchanged. A content hash only changes when files actually change, which is the correct invalidation signal.
- **12-character hash prefix**: Sufficient for uniqueness while keeping the version string readable in logs.
- **No runtime manager changes**: The existing `CLIVersion == "dev"` check and version-based caching in both `pythonrt` and `nodert` work correctly once the build version is not the literal string `"dev"`.

## Learnings

- The `embedded.GetBuildVersion()` function returns `"dev"` by default, and both runtime managers treat this as "always re-bootstrap." This was intentional for development convenience (always get latest), but becomes a major performance problem when the desktop app restarts frequently.
- The `needsExtraction()` function in `embedded/version.go` also has a `currentVersion == "dev"` fast path that forces re-extraction. Our fix bypasses this too.
