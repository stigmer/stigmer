## Decisions Made

- **No text-delta processing**: The MessageAccumulator already provides token-level streaming via the stream channel. text-delta events are redundant for content building.
- **Buffer-then-apply pattern**: Deltas buffer internally; stream loop drains. Respects Node.js single-threaded model with zero synchronization overhead.
- **500ms persist debounce**: Matches Python agent-runner's update_scheduler interval. Prevents backend write storms during rapid shell output.
- **Shell callId fallback**: Tracks lastShellCallId from tool-call-started events for shell-output-delta payloads that lack explicit callId.
- **No proto changes**: Uses existing ToolCall.is_streaming, ToolCall.streaming_source (OUTPUT), ToolCall.result fields.
- **Thinking duration logged only**: No proto field exists; logged for observability. Adding a field is a future enhancement.

## Learnings

- The Cursor SDK's InteractionUpdate is a Zod discriminated union with 14 event types (not a TypeScript enum)
- `shell-output-delta` carries `event: Record<string, unknown>` — the internal structure varies; defensive extraction is essential
- The ToolCallStreamingSource enum uses short names (UNSPECIFIED, INPUT, OUTPUT) not proto-prefixed names in the TypeScript stubs
- `tool-call-started` / `tool-call-completed` carry `toolCall` (discriminated by tool type) and `modelCallId` fields
