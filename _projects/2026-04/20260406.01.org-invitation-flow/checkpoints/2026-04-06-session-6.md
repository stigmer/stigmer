## Decisions Made

- **`createPolicy()` over `bootstrapPolicy()`**: Bootstrap is for chicken-and-egg during resource creation. Redemption creates a standard user-facing IAM policy through the full pipeline.
- **`ALREADY_EXISTS` for existing members**: Check `can_view` (lowest permission) before creating policy. Prevents wasted redemption slots and redundant policies. Semantically correct per gRPC spec.
- **Policy-first atomicity**: Create IAM policy before recording redemption. If recording fails, user has access. Retry hits `ALREADY_EXISTS` safely.
- **Atomic MongoDB `$inc`/`$push`**: Avoids read-modify-write race for concurrent redemptions.
- **OrgGate bypass over route group refactor**: Modifying `OrgGate` to check pathname is much less invasive than restructuring the entire app into `(authenticated)` and `(public)` route groups. The bypass is a targeted, well-documented exception.
- **`login()` for `onAuthRequired`**: Delegates to the auth system's login function rather than hardcoding an auth URL. OIDC library preserves the return URL automatically.

## Learnings

- React rules of hooks: Can't early-return before `useState`/`useEffect` calls. The bypass check in `OrgGate` must come after all hooks are called, using a `const isBypassed` flag instead.
- The `AuthGuard` auto-redirects to login for unauthenticated users, so the invite page flow is: click link → auth redirect → login → redirect back → see invite page (authenticated). The `isAuthenticated` prop on `InvitationRedemption` is still useful as a safety net but won't typically be `false` in the Console context.
- Pre-existing Go codegen error (`invitationv1.IamRole` undefined in `sdk/go/internal/gen/invitation.go`) is unrelated to this work — it's a codegen issue to track separately.
