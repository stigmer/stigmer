## Decisions Made

- **`is_skip_authorization` for `getByToken`**: The proto defines `is_public` (never-used) and `is_skip_authorization`. We chose `is_skip_authorization` following the `getSsoProvider` precedent since `is_public` is untested in the backend interceptor. If this causes issues for unauthenticated invite-link visitors, it will surface in Track 2 (backend).
- **`invitation.json` is auto-generated**: The codegen schema JSON files in `tools/codegen/schemas/services/` are generated by `make codegen`, not manually authored. The pipeline reads proto definitions and produces these schemas automatically.
- **No `grantable_roles`**: Invitations use org-level permissions (`can_grant_access`, `can_view_access`) rather than resource-level IAM roles. Nobody grants roles ON an invitation.
- **`org` field (slug) not `org_id`**: `ListInvitationsByOrgInput` uses `org` (slug string) matching the `ListIdentityProvidersByOrgInput` pattern and the auth interceptor's field resolution convention.

## Learnings

- The codegen schema JSON files are auto-generated, not hand-maintained. The `make codegen` pipeline reads proto definitions and generates these schemas alongside SDK clients and docs.
- `is_public` method option (field 50057) exists in the proto definition but has never been used in any RPC annotation across the codebase. All "public" endpoints use `is_skip_authorization` instead. This may indicate the backend interceptor doesn't handle `is_public`, or it was added speculatively and never wired up.
- The codegen pipeline is impressively comprehensive: a single `make codegen` invocation generates stubs, SDK clients in 4 languages, codegen schemas, MCP server code, and SDK documentation from proto definitions.

## Open Questions
