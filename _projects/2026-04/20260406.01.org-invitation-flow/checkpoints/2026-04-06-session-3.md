## Hooks Created

|------|------|-----------|
| `useOrgInvitations` | Data | `(org: string \| null)` — lists org invitations, fetchKey/refetch |
| `useCreateInvitation` | Mutation | `()` — creates invitation, returns token in `status.token` |
| `useRevokeInvitation` | Mutation | `()` — revokes by ID, idempotent |
| `useInvitationPreview` | Data | `(token: string \| null)` — public endpoint, safe projection |
| `useRedeemInvitation` | Mutation | `()` — redeems by token, internal proto construction |

## Decisions Made

- **Parameter simplification**: Hooks accept primitives (`string`, `string | null`), construct proto messages internally. Follows `useDeleteApiKey` and `useRevokeOrgAccess` precedent.
- **No `isRedeemed` success state**: Mutation hooks don't track success — callers handle via resolved promise or component-level state. Consistent with all existing mutation hooks.
- **No `useInvitationGet(id)`**: Not needed by Phase 4B components. Avoids shipping unused API surface.
- **`org` not `orgId`**: The parameter is a slug, not a resource ID. Matches proto field name and `useAgent(org, slug)` precedent.
- **`useInvitationPreview` still needs StigmerProvider**: Even though `getByToken` is unauthenticated, the hook needs the transport (API base URL). Documented in JSDoc.
