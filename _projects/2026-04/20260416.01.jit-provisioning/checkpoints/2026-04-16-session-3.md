## Decisions Made

- **DD-003: Reject when tenant org not found**: When `tenant_org_claim` is configured and `auto_grant_on_org` is true, if the JWT claim value does not resolve to a known platform-managed organization, authentication is rejected with a descriptive error. Rationale: fail-closed is correct because (a) the platform's contract is to pre-create tenant orgs, (b) auto-creating orgs from a JWT claim lacks sufficient metadata (slug, name, owner), (c) creating an account without intended access is silently incorrect.
- **SSO vs JIT grant separation**: SSO always grants viewer on IdP's owning org (backward compatible, no behavior change). JIT uses the new configurable logic (`autoGrantOnOrg`, `autoGrantRole`, `tenantOrgClaim`). SSO ignores all JIT fields even if set — this prevents surprising behavior if a provider is both SSO and has JIT fields configured.
- **`resolveRole()` default**: Empty `autoGrantRole` (mapped from `iam_role_unspecified` in T02) defaults to `"viewer"` in the provisioner. The default lives in the implementation, not in the proto or the auth token.

## Learnings

- The `OrganizationRepo.findByExternalOrgId(idpOrg, idpSlug, externalOrgId)` query already exists and is indexed — adding it to the provisioner required only a constructor dependency, no new queries or migrations.
- The SSO backward-compat test `sso_ignoresJitFields` (which sets all JIT fields on an SSO context and verifies they're ignored) is an important regression safety net. It documents the architectural decision that SSO mode has fixed semantics regardless of JIT field values.
- The `SsoAutoProvisioningException` was caught by `GrpcRequestContextBuilderInterceptor` in the `grpc-request` library — a cross-library dependency that was easy to miss during rename. Grepping for all references before starting was essential.
