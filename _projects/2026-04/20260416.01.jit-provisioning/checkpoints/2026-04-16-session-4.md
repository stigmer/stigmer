## Decisions Made

- **DD-004: Reject JIT authorization fields on SSO providers**: When `is_sso_provider = true`, the JIT authorization fields (`auto_grant_on_org`, `auto_grant_role`, `tenant_org_claim`) must be empty/default. `auto_provision_accounts` is allowed (redundant but not misleading). Rationale: no phantom config, prevents debugging traps, SSO and JIT are separate trust models.
- **Tenant claim requires grants**: `tenant_org_claim` requires `auto_grant_on_org = true` — tenant org resolution without granting is dead config. Catches the likely misconfiguration of setting up multi-tenant routing but forgetting to enable grants.
- **Orphaned role requires grants**: `auto_grant_role` (non-default) requires `auto_grant_on_org = true` — catches the oversight of specifying a role without enabling grants.

## Key Code Changes

- `ValidateJitFields.java` (NEW): Pure field-level validation step, no DB dependencies. Six rules evaluated in order: SSO/JIT separation, grant requires provisioning, tenant claim requires provisioning, tenant claim requires grants, orphaned role, owner not auto-grantable.

## Learnings

- `RequestPipelineStepResultV2` uses Lombok `@Data`, so the field `grpcStatus` generates getter `getGrpcStatus()` — not `getErrorStatus()` as the existing `ValidateIssuerUniquenessTest` seemed to suggest. The existing test file in the repo may have been written against a different version of the class. Always verify the actual API before writing tests.
- Production sources use `glob(["src/main/java/**/*.java"])` in BUILD.bazel, so new Java source files are auto-included. Only test targets need explicit registration.
- The validation step pattern (`@Component` + `RequestPipelineStepV2<ContextBase<...>>`) is clean and composable. No DB dependencies needed for pure cross-field validation — the step only reads the request proto.
