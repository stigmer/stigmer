## Decisions Made

- **`autoGrantRole` as String**: Preserves proto-free layering in the `api-authentication` library. The `IamRole` enum -> String conversion happens in `FederatedJwtAuthenticationProvider` at the proto boundary. `iam_role_unspecified` maps to empty string; the provisioner (T03) will apply the "viewer" default.
- **`IdentityProviderContext` record**: Groups all 8 IdP-related fields (id, org, slug, isSsoProvider, autoProvisionAccounts, autoGrantOnOrg, autoGrantRole, tenantOrgClaim) into a single immutable concept. Replaces the 4 individual fields on `FederatedAuthenticationToken`. Includes `shouldAutoProvision()` to encapsulate the SSO-or-JIT decision.
- **Delegate getters retained**: `FederatedAuthenticationToken` still exposes `getIdentityProviderId()`, `getIdentityProviderOrg()`, etc. as delegates to the context record. This avoids updating all downstream consumers (e.g., `SsoAutoProvisionerImpl`) in the same task — that happens in T03.

## Key Code Changes

- `IdentityProviderContext.java` (NEW): Java record with 8 fields + `shouldAutoProvision()`. Lives in `api-authentication` lib alongside `FederatedAuthenticationToken`.

## Learnings

- The `api-authentication` library is a clean abstraction boundary: it carries no proto type dependencies. Introducing `IdentityProviderContext` as a record with primitive/String fields preserves this layering. The proto -> record conversion happens in `stigmer-service` (the domain layer), which already imports proto types.
- Bazel test targets compile and run in ~35s from cold start with remote cache. Test-only rebuilds are fast (~5s) once the dep graph is cached.
- The `SsoAutoProvisionerImpl` already queries `issuerCache` to resolve `userinfoEndpoint` — so it has access to the full IdP spec at runtime. The JIT fields on the token are an explicit design choice (self-contained token) rather than a technical necessity.
