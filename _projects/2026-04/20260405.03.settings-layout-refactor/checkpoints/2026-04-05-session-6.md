## Decisions Made

- **Layer 1 only (remember last session path) — Layer 2 (keep SessionZoneContent mounted) deferred**: Layer 1 addresses the primary UX issue (losing your place) with minimal complexity. Layer 2 would preserve transient state (composer draft, streaming, scroll position) but adds significant complexity: streaming connections stay open while in settings, hidden DOM nodes consume memory, and AppShell rendering logic becomes more complex. If users frequently need full state preservation, Layer 2 can be added later — the Layer 1 design does not preclude it.
- **State over ref for `currentSessionZonePath`**: The `react-hooks/refs` lint rule prohibits reading/writing `.current` during render. Since the render-time pathname sync block reads this value, it must be `useState` (same pattern used for `prevPathname`, `isSessionZone`, and `activeSessionId`). This causes an extra state variable but only updates on zone transitions and in-zone session switches — rare events with negligible performance impact.
- **Separate `currentSessionZonePath` tracking**: `prevPathname` from `usePathname()` only reflects Next.js router navigations, not `pushState` updates. If a user clicks a session in the sidebar (pushState to `/sessions/abc`), `prevPathname` still shows the last Next.js pathname (`/`). A separate `currentSessionZonePath` state tracks the true session-zone path across both navigation mechanisms — updated by `navigateToSession`, `navigateToHome`, `popstate` handler, and Next.js pathname sync.
