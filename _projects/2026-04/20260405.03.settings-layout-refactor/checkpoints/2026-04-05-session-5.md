## Decisions Made

- **Effect-based ref reset over render-time ref access**: The `react-hooks/refs` lint rule prohibits reading/writing `.current` during render. Used a `useEffect` keyed on `org` to reset `bootstrapAttempted`, declared before the bootstrap effect so React executes the reset first (effects run in declaration order). This avoids the lint violation while maintaining correct semantics.
- **Browser Back/Forward testing deferred**: The OIDC auth flow injects Auth0 pages into the browser history stack. Testing back/forward in the embedded browser hits Auth0 pages rather than app pages. This is a test-environment limitation — real users build a clean history stack via client-side `<Link>` navigation. The back/forward verification is Phase 5 item 2, a separate task.

## Key Code Changes

- `client-apps/web/src/components/settings/EnvironmentsSection.tsx`: Added 5 lines — a `useEffect` keyed on `org` that resets `bootstrapAttempted.current = false`, enabling the bootstrap auto-create to fire when the user switches to a new org

## Key Finding

The `bootstrapAttempted` ref in `PersonalEnvironmentCard` was initialized once and never reset when `org` changed. Because the component doesn't unmount on org switch (it re-renders with a new `org` prop), the ref persisted its `true` value across org changes, silently short-circuiting the auto-create guard for every subsequent org.
