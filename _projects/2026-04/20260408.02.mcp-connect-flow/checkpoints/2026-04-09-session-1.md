## Decisions Made

1. **Deleted `updateDiscoveredCapabilities` entirely** instead of renaming to `observeMcpServerStatus`. Rationale: only one caller (CLI discover), and the `connect` RPC already handles the complete flow. Simplifies the API surface.

2. **CLI `discover` now delegates to backend** via `Connect` RPC with `runtime_env`. The CLI resolves credentials locally (OS env + well-known vars like `gh auth token`) and sends them as `runtime_env`. DryRun still uses local `mcpdiscovery.Discover()` for preview.

3. **`SetDiscoveryDependencies` renamed to `SetConnectDependencies`** on the controller, matching the new semantics.

4. **Added `can_connect = 22` to `IamPermission` enum** — this was missing from the original plan and blocked proto compilation.

5. **Minimal React SDK fixes** applied (T04 scope items done early to make `make check` pass): renamed `defaultToolApprovals` → `pinnedToolApprovals` and `discoverCapabilities` → `connect` in 5 React files.

## Learnings

- The `IamPermission` enum must be updated in lockstep with proto RPC config `permission` values — the proto linter validates this at build time.
