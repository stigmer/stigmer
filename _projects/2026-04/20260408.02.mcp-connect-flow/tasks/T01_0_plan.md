# Task T01: Proto Model + FGA + Codegen

**Created**: 2026-04-08
**Status**: PENDING REVIEW
**Scope**: stigmer OSS (apis/, sdk/) + stigmer-cloud (FGA models)
**Estimated effort**: Substantial — proto changes cascade into generated code across Go, Java, TypeScript, Python

## Objective

Restructure the MCP server proto model: move tool approvals from `spec` to `status` (system-generated), rename discovery RPCs to the new Connect semantics, and add proper FGA permissions (`can_connect`, `can_update_mcp_server_status`).

This is the foundation task — all other tasks depend on these proto and FGA changes.

## Background / Design Decisions

These decisions were made during the planning session (chat: [MCP Connect Flow Plan](../../20260408.01.mcp-marketplace-catalog)):

- **`default_tool_approvals` was in the wrong place**: It lived in `McpServerSpec` (user-authored) but is system-generated by a classifier. Moving to `status` solves the authorization problem and respects the blueprint/runtime boundary.
- **No backward compatibility**: `default_tool_approvals` deleted outright, no reserved, no migration. Low current usage.
- **RPC renames, not additions**: `discoverCapabilities` → `connect`, `updateDiscoveredCapabilities` → `observeMcpServerStatus`.
- **`can_connect` permission**: Derived from `viewer` — more intuitive than overloading `can_view`. Semantically says "user can connect to this server."
- **`can_update_mcp_server_status`**: Platform-level operator permission, mirrors existing `can_update_execution_status` pattern for agent-runner service identity.

## Detailed Changes

### 1. spec.proto (`apis/ai/stigmer/agentic/mcpserver/v1/spec.proto`)

- **DELETE** `repeated ToolApprovalPolicy default_tool_approvals = 7;` — no reserved, clean delete
- **ADD** `repeated ToolApprovalPolicy pinned_tool_approvals = 11;` — manual overrides set by MCP server owner, never auto-modified, takes precedence over system-generated `status.tool_approvals`

### 2. status.proto (`apis/ai/stigmer/agentic/mcpserver/v1/status.proto`)

- **ADD** `repeated ToolApprovalPolicy tool_approvals = <next_available>;` — system-generated by classifier during Connect flow and first-time-use backfill. Overwritten on each reconnect. Never manually edited.
- Check existing field numbers in `McpServerStatus` to pick the correct next available number.

### 3. command.proto (`apis/ai/stigmer/agentic/mcpserver/v1/command.proto`)

**Rename `discoverCapabilities` → `connect`**:
```protobuf
rpc connect(ConnectInput) returns (McpServer) {
  option (ai.stigmer.commons.rpc.config).resource_kind = mcp_server;
  option (ai.stigmer.commons.rpc.config).permission = can_connect;
  option (ai.stigmer.commons.rpc.config).field_path = "mcp_server_id";
  option (ai.stigmer.commons.rpc.config).error_msg = "unauthorized to connect to mcp server";
}
```

**Rename `updateDiscoveredCapabilities` → `observeMcpServerStatus`**:
```protobuf
rpc observeMcpServerStatus(ObserveMcpServerStatusInput) returns (McpServer) {
  option (ai.stigmer.commons.rpc.is_skip_authorization) = true;
  // Handler checks platform:stigmer#can_update_mcp_server_status manually
}
```

Update the doc comments to reflect new semantics.

### 4. io.proto (`apis/ai/stigmer/agentic/mcpserver/v1/io.proto`)

**Rename `DiscoverCapabilitiesInput` → `ConnectInput`** (same fields: `mcp_server_id` + `runtime_env`)

**Rename `UpdateDiscoveredCapabilitiesInput` → `ObserveMcpServerStatusInput`**:
```protobuf
message ObserveMcpServerStatusInput {
  string mcp_server_id = 1 [(buf.validate.field).required = true];
  DiscoveredCapabilities discovered_capabilities = 2;
  repeated ToolApprovalPolicy tool_approvals = 3;
}
```
