## Decisions Made

- **research-analyst scoped to methodology**: Focused on systematic research methodology and source evaluation rather than general summarization, because LLMs already summarize well -- the skill's value is in teaching structured process, source credibility assessment, and citation discipline.
- **data-analyst scoped to analytical thinking**: Focused on analytical methodology and insight communication rather than computation, because computation requires tools (pandas, SQL) that live at the agent layer. The skill teaches how to frame questions, assess data quality, and communicate findings.
- **Domain skills are tool-agnostic**: All 5 skills work without MCP tools. They acknowledge tool capabilities where relevant ("if you have access to customer history, query it before responding") but the methodology stands on its own. Tool integration happens at the agent layer (Task 3).
- **Consistent structural pattern across all 5**: YAML frontmatter (name, description as folded string with trigger phrases), `## Workflow` with `### Step N: Verb Phrase`, `## Key Principles` (6-7 non-platitude rules), `## Reference Files` table, and `references/` directory with 2 files each.
- **Progressive disclosure via references/**: SKILL.md stays lean (133-216 lines) with the core workflow and principles. Reference files hold checklists, templates, example patterns, and detailed frameworks loaded on demand.
- **Trigger-focused frontmatter description**: Following the agent-creator/mcp-server-creator pattern, each skill's `description` field specifies when to activate with 6 concrete trigger phrases.

## Learnings

- Domain-expertise skills are fundamentally different from platform-authoring skills (agent-creator, mcp-server-creator). Platform skills reference Stigmer APIs, MCP tools, and YAML schemas. Domain skills teach methodology that's portable across any context.
- The anti-platitude test ("can you disagree with this principle?") is an effective quality filter. It forced sharpening vague guidance like "be helpful" into specific, actionable rules like "one apology, sincerely -- then demonstrate care through action, not words."
- 2 reference files per skill is the right balance. Each reference file serves a distinct purpose (one for the "what to do" detail, one for the "how to communicate" detail). More would dilute; fewer would overload the SKILL.md.
