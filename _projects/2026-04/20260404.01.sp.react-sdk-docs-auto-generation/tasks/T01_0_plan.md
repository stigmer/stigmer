## Background

The React SDK (`@stigmer/react`) has **61 hooks**, **~55 public components**, and **~192 source files**. TSDoc/JSDoc comments already exist across much of the codebase but coverage is not uniform and no doc generation tooling is configured.

The existing proto-based SDK docs are auto-generated by `tools/codegen/generator/sdk_docs.go` into Fumadocs MDX. This sub-project creates a parallel pipeline for the React SDK, following the same codegen philosophy: **source code is the single source of truth, docs are generated, CI catches staleness**.

## Strategy: Two-Layer Documentation

### Layer 1: Hand-written overview page (`docs/sdk/react.mdx`)

A concise landing page covering:
- `@stigmer/react` installation and peer deps
- `StigmerProvider` setup with `deploymentMode`
- How the SDK is organized by domain (session, execution, agent, etc.)
- Styles import
- Links into the auto-generated per-domain reference pages

Diataxis type: **Reference** (light). Does not try to list every hook or component.

### Layer 2: Auto-generated per-domain reference pages (`docs/sdk/react/`)

Generated from TSDoc in the source code. One page per domain, matching the folder structure in `sdk/react/src/`:

```
docs/sdk/react/
  meta.json              ← generated sidebar
  session.mdx            ← 10 hooks + session components
  execution.mdx          ← 8 hooks + execution components
  agent.mdx              ← 6 hooks + agent components
  mcp-server.mdx         ← 8 hooks + MCP components
  skill.mdx              ← 4 hooks + skill components
  environment.mdx        ← 8 hooks + environment components
  composer.mdx           ← useComposer + SessionComposer + toolbar
  workspace.mdx          ← workspace hooks + components
  api-key.mdx            ← API key hooks + components
  attachment.mdx         ← useAttachments + AttachmentChipList
  organization.mdx       ← useCreateOrganization + form
  github.mdx             ← GitHub hooks + RepoPicker
  library.mdx            ← library/resource hooks + components
  models.mdx             ← useModelRegistry + ModelSelector
  core.mdx               ← StigmerProvider, useStigmer, deployment mode hooks
```

Each page contains:
- **Hooks** section: signature, parameters table, return type, description, `@example` if present
- **Components** section: props table (from interface), description, `@example` if present
- **Types** section: key interfaces/types used by the hooks and components on that page

## Pipeline Architecture

```
sdk/react/src/**/*.ts(x)
    ↓
TypeDoc --json (extracts TSDoc + TypeScript type info)
    ↓
gen-react-sdk-docs script (TypeScript, in tools/codegen/react-sdk-docs/)
    ↓  reads TypeDoc JSON
    ↓  groups exports by domain folder
    ↓  renders Fumadocs MDX (TypeTable, code blocks)
    ↓
docs/sdk/react/*.mdx + docs/sdk/react/meta.json
```

Integrated into `make gen-sdk-docs` alongside the proto-based generator.

## Task Breakdown

### T01: TypeDoc setup + proof of concept (this task)

**Goal**: Get TypeDoc producing JSON from the React SDK and verify the output contains what we need.

**Steps**:
1. Add `typedoc` as a devDependency in `sdk/react/package.json`
2. Create `sdk/react/typedoc.json` configuration targeting `src/index.ts` (public API only)
3. Add a `typedoc:json` script to package.json that outputs `dist/api.json`
4. Run TypeDoc, examine the JSON structure for a few hooks and components
5. Validate: does the JSON contain signatures, param types, return types, TSDoc descriptions, `@example` blocks?
6. Document findings: what's in the JSON, what's missing, any gaps in TSDoc coverage

**Success criteria**: TypeDoc JSON output for the full public API, with a sample analysis showing we can extract what we need for MDX generation.

### T02: TSDoc coverage audit + writing guidelines

**Goal**: Understand current TSDoc coverage gaps and establish the standard for what every public export must have.

**Steps**:
1. Analyze TypeDoc JSON output for missing/empty descriptions
2. Categorize: which domains have good coverage vs. sparse
3. Write a TSDoc writing guideline (in `coding-guidelines/`) covering:
   - Required tags for hooks: `@param`, `@returns`, `@example`
   - Required tags for components: props interface doc, `@example`
   - How to write descriptions (match the Document Writer role register for SDK reference)
   - How to document generic types and callback patterns
4. Add `eslint-plugin-tsdoc` to enforce TSDoc on public exports
5. Prioritize which domains to fill in first (start with most-used: session, execution, agent)

**Success criteria**: Coverage report, writing guideline document, eslint enforcement configured.

### T03: MDX generator script

**Goal**: Build the TypeScript script that reads TypeDoc JSON and produces Fumadocs MDX pages.

**Steps**:
1. Create `tools/codegen/react-sdk-docs/` directory with a TypeScript project
2. Read TypeDoc JSON and build a domain-grouped data model
3. Map `sdk/react/src/<domain>/` folders to output pages
4. Generate MDX per domain with:
   - Hooks section using `TypeTable` for params and return types
   - Components section using `TypeTable` for props
   - Type definitions section for key interfaces
   - Code blocks for `@example` content
5. Generate `docs/sdk/react/meta.json` with sorted domain slugs
6. Handle edge cases: generics, union types, callback props, optional fields, default values
7. Test with the full SDK -- verify all 61 hooks and ~55 components appear in output

**Success criteria**: Running the script produces correct, complete MDX pages for all domains. Pages render in Fumadocs dev server.

### T04: Makefile integration + CI staleness check

**Goal**: Wire the React SDK docs generator into the build pipeline.

**Steps**:
1. Add `gen-react-sdk-docs` make target
2. Wire it into the existing `gen-sdk-docs` target (so `make gen-sdk-docs` generates both proto and React docs)
3. Add `gen-react-sdk-docs-check` staleness check (same diff pattern as `gen-sdk-docs-check`)
4. Verify `make protos` still runs clean end-to-end
5. Add CI integration (the check target runs in CI)

**Success criteria**: `make gen-sdk-docs` regenerates React SDK docs. `make gen-sdk-docs-check` catches stale docs. CI passes.

### T05: TSDoc backfill for priority domains

**Goal**: Fill in missing TSDoc across the most important domains so the generated pages have real content.

**Steps**:
1. Backfill TSDoc for `session/` domain (10 hooks, key components)
2. Backfill TSDoc for `execution/` domain (8 hooks, many components)
3. Backfill TSDoc for `agent/` domain (6 hooks, agent components)
4. Backfill TSDoc for `composer/` domain (useComposer, SessionComposer)
5. Backfill TSDoc for core exports (StigmerProvider, useStigmer, deployment mode)
6. Regenerate docs and verify quality

**Success criteria**: Priority domains have complete TSDoc. Generated pages read well.

### T06: Hand-written `react.mdx` overview page

**Goal**: Write the landing page for the React SDK section.

**Steps**:
1. Write `docs/sdk/react.mdx` covering installation, provider setup, deployment modes, styles, SDK organization
2. Update `docs/sdk/meta.json` to add the `react` page and `react/` folder
3. Add "What's next" cards linking to the auto-generated domain pages
4. Verify the page renders correctly and the sidebar navigation works

**Success criteria**: `react.mdx` renders as the React SDK landing page, with working links to generated sub-pages.

### T07: Remaining TSDoc backfill + polish

**Goal**: Complete TSDoc coverage for remaining domains and polish the full set of pages.

**Steps**:
1. Backfill TSDoc for remaining domains (mcp-server, skill, environment, workspace, api-key, github, library, organization, models, attachment)
2. Regenerate all pages
3. Review cross-links between pages
4. Verify sidebar navigation
5. Final quality pass: check for rendering issues, missing types, broken links

**Success criteria**: All domains have complete TSDoc. All generated pages render correctly. Full React SDK reference is navigable.

## Out of Scope

- Modifying the existing proto-based SDK docs generator (`sdk_docs.go`)
- Documenting internal/non-exported components
- Building live demos for the React SDK reference pages (that's a separate concern)
- React SDK tutorial content (belongs in getting-started or tutorials)
- The `demo/` subpath (`@stigmer/react/demo`) -- fixtures/demo client are internal

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| TypeDoc JSON doesn't capture what we need (e.g., React-specific patterns) | T01 is specifically a proof-of-concept to validate this before building the generator |
| TSDoc backfill is a large effort | Prioritized by domain importance (T05 vs T07). Generator works even with sparse TSDoc -- pages just show less prose |
| MDX output doesn't match Fumadocs component expectations | Generator uses the same components (TypeTable) as the proven proto-based generator |
| Maintenance burden of a second generator | The React generator is TypeScript (not Go), matching the site's tech stack. It reads structured JSON, not raw AST |
