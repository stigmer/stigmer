## Decisions Made

- **Data-driven over per-component files**: Single `preview-configs.ts` file vs separate `.tsx` files per component — reduces maintenance, adding a preview is one object entry
- **Click-to-reveal UX**: Previews collapsed by default with Eye+Chevron toggle bar — defers mounting, keeps pages clean, lets readers opt in
- **Per-preview width control**: Added `previewClassName` to `PreviewConfig` interface — allows each component preview to set realistic width constraints
- **Full toolbar via props**: SessionComposer's toolbar items are prop-driven — providing `onAgentRefChange`, `onMcpServerUsagesChange`, `onSkillRefsChange` + `org` enables the full Configure menu

## Learnings

- SessionComposer toolbar visibility is entirely prop-driven: `showAgent = onAgentRefChange != null && org != null` pattern
- `usePersonalEnvironment` fires when agent or MCP pickers are enabled, requiring an `environment.list` fixture to avoid real API calls
- `EnvironmentListSchema` from the proto stubs can create empty list responses: `create(EnvironmentListSchema, { items: [], totalCount: 0 })`
- The demo infrastructure (`@stigmer/react/demo`) works seamlessly for isolated component rendering in docs context
