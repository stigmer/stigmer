- **Folder page convention**: Moved `docs/sdk/react.mdx` → `docs/sdk/react/index.mdx` so Fumadocs treats the directory as a navigable folder with children

## Edge Cases Discovered and Fixed

1. **Domain misclassification**: Re-exported proto types (`ExecutionArtifact`) got wrong domain — fixed `getDomain` to check `sdk/react/src/` prefix
2. **Utility function misclassification**: camelCase functions (e.g., `formatDuration`) were classified as components — added PascalCase check, treat camelCase as TypeDefs with signatures
3. **Unhandled enum kinds**: Proto re-exported enums (Kind 8/16) caused warnings — added silent skip
4. **MDX parsing error**: `aria-label` in TypeTable is invalid JS identifier — added auto-quoting for non-identifier prop names
5. **Fumadocs sidebar**: `react.mdx` alongside `react/` directory made "React SDK" a flat link instead of expandable folder — moved to `react/index.mdx`

## Learnings

- Fumadocs folder page convention: `X.mdx` alongside `X/` directory creates a flat link; `X/index.mdx` creates a folder with index page
- TypeDoc JSON v2 schema has Kind 8 (Enum) and Kind 16 (EnumMember) for re-exported enums — not in the initial classification plan
- TypeDoc classifies all Functions as Kind 64 regardless of PascalCase/camelCase — need application-level heuristics to distinguish components from utilities
