## Decisions Made

- **Dedicated tsconfig for TypeDoc**: Created `tsconfig.typedoc.json` that extends `tsconfig.json` but excludes `src/**/__tests__/**`. Test files have pre-existing TS errors and are not part of the public API.
- **`skipErrorChecking: true`**: Two pre-existing type errors in `systemEnvVars.ts` (SDK interface drift) would block TypeDoc. Since the errors are pre-existing and the function signatures are still extractable, skipping error checking is the pragmatic choice.
- **`excludeExternals: true`**: Re-exported types from `@stigmer/protos` and `@stigmer/sdk` (5 types) are excluded from the JSON. The generator will link to existing proto-based resource pages instead of duplicating documentation.

## Learnings

- TypeDoc 0.28 treats both hooks and React components as `kind: 64` (Function). The generator must distinguish them by naming convention (`use*` = hook) or return type (`JSX.Element` = component).
- React components that destructure props show `__namedParameters` as the parameter name. The generator must follow the type reference to find the props interface.
- Domain grouping via `sources[0].fileName` is reliable — the first path segment maps to the SDK domain folder.
- TSDoc coverage is strong for functions (98.7%) but weak for interfaces (20.1%). The biggest gap is missing top-level summaries on `*Props` and `*Return` interfaces.
