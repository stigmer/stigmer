## Decisions Made

- **Navigation pattern:** Remove both Home and Docs tabs; the logo is the sole path back to the marketing site. GitHub stays as an icon link.
- **Content philosophy:** Write for a "smart person who is not technical." YAML is explained inline. Technical terms (API, Environment, MCP Server, Skill, Execution) get plain-language definitions on first use. No analogies to other software systems.
- **Code example approach:** Keep the YAML Agent definition example but introduce it gently ("Here is what a definition file looks like") and explain YAML itself as "a text format that uses indentation to show structure."
- **Technology references removed:** SQLite, MongoDB, Ollama, Anthropic, Temporal all removed from the overview page. These belong in deeper pages (architecture, deployment).

## Learnings

- Fumadocs' `nav.url` defaults to `'/'`, which naturally sends users to the marketing homepage. No explicit configuration needed.
- The `site/src/lib/` directory has a gitignore conflict — `git add` rejects it without `-f`, but `git check-ignore` reports it as not ignored and `git ls-files` confirms it's tracked. Root cause unclear; `-f` works fine for tracked files.
- Vale's `Stigmer.terms` rule flags lowercase "environment" and "workspace" even in non-Stigmer contexts (e.g., "the kitchen where you cook"). Fixed by rephrasing to avoid the trigger words in generic contexts.
