## Decisions Made

- **Post-build script over route handlers**: `fumadocs-core@15.8.5` does not have the `llms()` function or `getText('processed')` API (those are v16+ features). Per-page `.md` files require writing to `out/` with specific file extensions, which isn't achievable via route handlers + static export (no `rewrites()` support). A single post-build script is simpler, testable, and version-independent.
- **Raw MDX with light cleaning over `includeProcessedMarkdown`**: The `includeProcessedMarkdown` option exists in `fumadocs-mdx@13.0.8` types but `_markdown` is not surfaced on page objects at this version. Additionally, "processed" markdown runs AFTER remark plugins, so our `remarkMermaid` plugin would convert mermaid code blocks into `<Mermaid chart="..." />` JSX — making output worse. Raw MDX with light cleaning produces better LLM output because JSX tags carry semantic information.
- **Content cleaning preserves semantic JSX**: `<Callout>`, `<Tabs>`, `<Term>` tags are deliberately kept because LLMs understand them as semantic markup (warnings, alternatives, glossary terms). Only noise is removed: frontmatter, imports, exports, MDX comments.
- **CLI commands in Optional section**: Individual CLI command reference pages (20 pages) and contributing section are placed in the "Optional" section of `llms.txt` per the spec — they can be skipped for shorter context.
- **`gray-matter` for frontmatter parsing**: Well-established package (12M+ weekly downloads), added as devDependency since it's only used by the build script.
