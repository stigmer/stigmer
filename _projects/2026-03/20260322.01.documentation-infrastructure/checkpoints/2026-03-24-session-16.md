## Decisions Made

- **Simplified from thumbs up/down to single issue link**: The site uses `output: "export"` (fully static). Thumbs up/down without a backend is decorative -- positive clicks are lost on page navigation, and there's no persistence layer. A single "Report an issue" link is honest, actionable, and matches what Terraform, Kubernetes, and other production docs ship.
- **Positive feedback should NOT go to GitHub Issues**: Issues are a work tracker, not a compliment box. "This page was helpful!" issues create triage noise. If someone is genuinely motivated to say something positive, they'll find a channel.
- **Server component, not client component**: No `"use client"` needed. The component just renders an `<a>` tag with a constructed URL. No state, no interactivity, no JavaScript shipped to the browser for this feature.
- **Used `URLSearchParams` for URL construction**: Handles encoding correctly for page titles with special characters, spaces, etc. Cleaner than manual `encodeURIComponent` concatenation.

## Learnings

- Static export (`output: "export"`) fundamentally constrains feedback features. Any data collection requires an external target. GitHub Issues via pre-filled URL is the zero-infrastructure option.
- `URLSearchParams` encodes `+` as `%2B` and spaces as `+`, which GitHub's issue creation endpoint handles correctly.
