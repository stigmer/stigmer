## Decisions Made

- **ExecutionContext is the single source of truth**: The workflow always creates ExecutionContext with pre-merged env vars before the activity starts. Legacy 3-layer merge was dead code and removed entirely.
- **Function + frozen dataclass pattern**: Used `perform_setup() → SetupResult` and `resolve_resume_input() → ResumeResult` rather than classes, matching existing project patterns (`resolve_environment()` + `EnvironmentResult`, `process_post_stream()` + `PostStreamResult`).
- **HITL resume separated from setup**: Early-return failure path in resume logic would have added accidental complexity to the setup pipeline.
- **Re-exports for backward compatibility**: Added `noqa: F401` re-exports in `execute_graphton.py` for moved functions/constants to avoid breaking existing tests.
- **grpc_provider and exit_stack owned by orchestrator**: Created before `perform_setup()` so they're always available in the `finally` block regardless of setup success.

## Learnings

- `_perform_setup_core` needed to return `workspace_backend` and `agent_graph` separately from `SetupResult` for partial-cleanup in the `except` block — `locals()` returns a copy, not a live reference
- Environment resolution had a hidden dependency: the `EnvironmentClient` was fetching `Environment` resources directly, bypassing the intended `ExecutionContext` contract. This was legacy code predating `ExecutionContext`.
