## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Field name on SessionSpec | `workspace_entries` | Matches `WorkspaceEntry` type, avoids naming mismatch across 5 language stubs, future-proof as entries gain more fields |
| Wrapper message | No `Workspace` wrapper | YAGNI — session IS the workspace container; wrapping adds indirection for no benefit at this stage |
| Reserved fields | Reserved field 6 + name | Protobuf best practice for wire-format safety, even though backward compat not required |
| New field number | 7 (not reusing 6) | Avoids silent conflicts with any residual serialized data |
| `WorkspaceSource` message | Unchanged | Remains a clean source-definition type; `WorkspaceEntry` adds identity on top |

## Learnings

- The field naming decision (`workspace_entries` vs `workspace_sources`) matters at the proto layer because it propagates to every language stub (Go, Python, Java, TS, Dart). Getting it right at this layer saves confusion downstream.
