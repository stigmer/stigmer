## Decisions Made

- **Real cursor (not virtual)**: `SetVirtualCursor(false)` for consistency with Phase 2's `tea.View.Cursor` pattern. Virtual cursor mode renders a styled character in the string; real cursor uses the native terminal cursor.
- **Ctrl+D dual behavior (Unix convention)**: Empty input = EOF (exit). Non-empty input = delete character forward (delegated to textinput). This matches shell behavior.
- **Reuse `promptStyle` from `run_display.go`**: Instead of duplicating `lipgloss.NewStyle().Bold(true).Foreground(lipgloss.Color("12"))`, the factory references the existing package-level style. Eliminates the need for a lipgloss import in the bubbletea file.
- **`tea.PasteMsg` explicit routing**: Added a dedicated case in `Update()` rather than a catch-all default, to avoid unexpected message forwarding.

## Learnings

- `textinput.Model.View()` returns `string` (not `tea.View`) -- designed as a child component whose output is composed into the parent's view
- `textinput.Model.Cursor()` returns `*tea.Cursor` only when `SetVirtualCursor(false)` AND `Focused()` -- returns nil otherwise
- `textinput.Model.Focus()` is a pointer receiver but works correctly on value-type fields within value-type structs in Go (the field is addressable in a local copy)
- `tea.KeyPressMsg{Code: tea.KeySpace}` needs `Text: " "` set explicitly in tests for the textinput to see the character -- Bubbletea populates this automatically in real terminal input
- `textinput.Cursor()` computes X using rune count (not visual column width) for the value portion -- a known library limitation for CJK double-width characters, irrelevant for typical English follow-up prompts
