## Decisions Made

- **Follow-up prompt always visible**: Ctrl+O during follow-up re-commits history in the toggled mode, but the follow-up prompt itself stays visible in both compact and expanded modes. No "read mode" hiding of active input.
- **Extend renderer, not model**: Chose to keep history, expandMode, and re-commit logic on `inlineRenderer` rather than migrating to the Bubbletea model. This preserves the existing model/renderer boundary and SRP.
- **Nil-channel pattern for conditional select cases**: Rather than adding a boolean flag and if-checks around each select case, setting channels to nil cleanly disables them at the language level.

## Learnings

- `textInputStartMsg.inputCh` is `chan<- string` (send-only) — the test model receives this direction. The renderer holds the bidirectional channel and reads from the `<-chan string` side.
- Bubbletea v2's `View()` returns `tea.View` (via `tea.NewView(content)`), not `string` — test models must match this interface.
- Go's `select` with a nil channel case effectively disables that case (blocks forever), making it a clean alternative to boolean guards around channel reads.
- `tea.Program.Send()` is safe to call from any goroutine — the message is queued and processed by the program's event loop.
