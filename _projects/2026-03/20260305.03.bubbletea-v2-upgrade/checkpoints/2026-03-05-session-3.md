## Decisions Made

- **`\033[3J` via direct write (Option 1)**: Chosen over prepending to `tea.Println` content. Rationale: explicit, doesn't fight the renderer, idempotent, 4-byte atomic write. The renderer has no scrollback concept.
- **`followUpSepWidth` kept as fallback**: Not removed because legacy paths (`promptFollowUpDirect`, `promptFollowUpViaKeyReader`) still need a fixed-width separator. Also used as default when `termWidth` is 0 (tests, startup before first `WindowSizeMsg`).
- **Hint below input**: Moved from above to below the input line, matching Claude Code's UX pattern. Only applies to the Bubbletea `textInputActive` path -- legacy paths keep hint-above-input since they can't do cursor positioning.
- **Prompt style color**: Kept existing bold blue (`promptStyle`) -- no change. Deferred color evaluation to visual testing.

## Learnings

- `ansi.StringWidth()` from `github.com/charmbracelet/x/ansi@v0.11.6` handles ANSI escape codes correctly for cursor positioning -- it returns the *visual* width ignoring escape sequences
- `tea.WindowSizeMsg` is sent at Bubbletea program startup and on resize -- reliable for tracking width
- `tea.View.Cursor` with `Shape: tea.CursorBar` and `Blink: true` provides native terminal cursor in inline mode
- Legacy follow-up paths (direct-write, key-reader) should keep their existing layout -- cursor APIs are only available through the Bubbletea model
