## Decisions Made

| Decision | Rationale |
|----------|-----------|
| `client.AgentExecution` (not `client.Execution`) | Domain term is "AgentExecution" per architect role ubiquitous language |
| Singular client fields (`client.Agent`) | Reads naturally: `client.Agent.Create(...)` |
| `AgentInput` (not `CreateAgentInput`) | Same input used for Create, Update, Apply — "Create" prefix misleads |
| `internal/gen/` for all generated code | Clean segregation; wipe and regenerate; users import via type aliases |
| Proto types for responses, Go types for inputs | Responses are read-only (proto works); inputs need ergonomic constructors |
| gRPC transport (not Connect-RPC) | Server exposes standard gRPC; Connect-RPC only used by web frontend |
| Flat root package + `internal/` | Standard Go SDK pattern (Stripe, Google Cloud) |
| `search.go` handwritten (not generated) | Cross-resource search is too specialized for codegen complexity trade-off |
| `types.go` handwritten (not generated) | Small stable bridge file; generating into root would break wipe-regenerate |

## Key Code Changes

- `tools/codegen/generator/sdk_client.go`: New file — generates resource clients, input types with `toProto()`, shared types, error types from JSON schemas
- `tools/codegen/proto2schema/main.go`: Enhanced to extract service schemas (RPC method signatures) alongside message specs
- `sdk/go/internal/gen/`: 7 generated files (agent, skill, mcpserver, session, execution, errors, types)
- `sdk/go/internal/transport/`: New package for gRPC connection management
- `sdk/go/client.go`: Top-level `Client` struct with resource sub-clients and `NewClient` constructor
- `sdk/go/Makefile`: Full codegen pipeline (`codegen-schemas`, `codegen-clients`, `codegen-verify`)
- `Makefile`: Root `protos` target now chains `make -C sdk/go codegen`

## Learnings

- Session resource has no spec schema in the proto definitions — its SDK methods must take proto types directly rather than generated input structs
- `ExecutionValue` lives in `executioncontext.v1` package, not `agentexecution.v1` — cross-package message references need special handling in codegen
- Metadata fields (Name, Org, Tags, Visibility) can conflict with spec fields of the same name — codegen must filter duplicates
- `EnvSpecInput.toProto()` was being generated in multiple resource files — centralized into `gen/types.go`
