## Decisions Made

- **CSS Layers + namespaced tokens instead of CSS Modules**: CSS Modules only scopes class names and would require rewriting 22 component files while losing Tailwind DX. CSS Layers solve cascade conflicts, namespaced tokens prevent variable collisions, and scoped preflight prevents reset leakage — all without touching component code.
- **`@layer stgm` with granular Tailwind imports**: Wrapping all Stigmer CSS in a single cascade layer gives host applications automatic cascade precedence over Stigmer styles at equal specificity.
- **Omit preflight entirely**: Tailwind v4 does not support scoped preflight natively. A minimal hand-written reset for `.stgm *` provides the essential `box-sizing: border-box` normalization without resetting the host page.
- **`--stgm-` token prefix**: Short, consistent with the `stgm` class and layer naming convention.

## Learnings

- Tailwind CSS v4 supports `@import "tailwindcss/theme.css" layer(name)` for granular layer-scoped imports — theme, utilities, and preflight can be imported independently
- CSS Cascade Layers (`@layer`) are the modern standard for embed-safe component isolation — used by Stripe, Clerk, Mantine
- Omitting `preflight.css` and providing a minimal scoped reset (`box-sizing`, `border-width`, `font-smoothing`) on a container class is the correct pattern for embeddable widget libraries
- `sideEffects: ["*.css"]` in `package.json` is essential — without it, bundlers may tree-shake CSS imports since they have no JavaScript exports
