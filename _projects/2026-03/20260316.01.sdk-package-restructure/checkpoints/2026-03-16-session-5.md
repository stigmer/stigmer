## Decisions Made

- **`_libs/README.md` kept (not deleted)**: The `_libs/` directory still contains `@stigmer/theme`, so a README documenting the current state is warranted. Rewritten to describe only theme, with pointers to `sdk/` for SDK and React packages.
- **`next build` Turbopack issue not fixed here**: Pre-existing from Session 2 codegen. The `.js` extensions in TypeScript imports are standard ESM convention but Turbopack doesn't resolve them for source-only packages. Tracked as a separate task.

## Learnings

- `@stigmer/theme` never had a `tsconfig.build.json` because it was always consumed source-only via Next.js `transpilePackages`. The publish pipeline requires standalone compilation, which exposed this gap.
- Turbopack in Next.js 16 does not resolve `.js` → `.ts` for source-only workspace packages, even though `tsc` handles it correctly with `moduleResolution: "bundler"`. This affects all codegen-produced imports in `@stigmer/sdk` and `@stigmer/react`.

## Open Questions

- Should the Turbopack `.js` extension fix be done by removing extensions from source imports (breaking ESM convention but pragmatic for Next.js), or by configuring Turbopack's module resolution? The codegen generator would need updating if we strip extensions.
