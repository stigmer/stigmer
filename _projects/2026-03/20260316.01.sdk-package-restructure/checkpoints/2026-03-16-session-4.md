## Decisions Made

- **Error utilities in SDK, not React**: Framework-agnostic error classification belongs in `@stigmer/sdk` so non-React consumers (CLI, Node scripts) can use it. React-specific error boundaries and display components can consume these utilities.

- **CSS strategy deferred to Phase 2B**: Migrating from Tailwind to CSS Modules for proper style encapsulation in embeddable components is a separate workstream. Phase 2 focused purely on package consolidation and SDK integration to minimize blast radius.

- **`@stigmer/protos` as peer dependency**: Prevents duplicate protobuf runtimes. Consumers must install protos alongside SDK and React packages.

- **`useStigmer()` as the universal data access pattern**: All React hooks that need API access call `useStigmer()` to get the SDK client, then call methods directly. Eliminates domain-specific service factory hooks entirely.
