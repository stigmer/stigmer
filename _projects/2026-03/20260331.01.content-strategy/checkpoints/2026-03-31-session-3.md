## What Was Created

### Vocabulary Guide (702 lines)

Three-part structure:

1. **Writing contexts** — five registers defining when to use which language:
   - Sales site (business-outcome, no jargon)
   - Quickstart/tutorials (action-oriented, introduce terms with plain gloss)
   - Concepts/how-to (explanatory, Stigmer terms as proper nouns)
   - Reference/SDK (precise, API field names, assume developer familiarity)
   - README/GitHub (developer-direct, CLI-first, technical credibility)

2. **Term entries** — 19 terms across three tiers, each with:
   - Plain-language definition
   - User-facing alternative per context
   - API surface (proto messages, CLI commands, YAML fields)
   - Good/bad copy examples per context
   - Capitalization rules

3. **Inconsistency register** — 6 documented issues pending review

### Quick-Reference Table

A scannable table at the top mapping every term to the correct phrasing per writing context. Writers can look up any term and immediately know what to write.

## Decisions Made

1. **Location**: `docs/vocabulary.md` (not inside `_projects/`) — permanent repo artifact that any documentation file can reference
2. **Single source of truth**: Other files (`STYLE.md`, `002_document_writer.md`, `glossary.ts`, T01 plan) now reference the vocabulary guide instead of maintaining their own terminology sections
3. **glossary.ts kept as derived artifact**: Runtime tooltip definitions stay inline for performance, but the header comment directs maintainers to update the vocabulary guide first
