## Decisions Made

- **Cloud quickstart structure**: Combined the original quickstart + Skill creation into one flow. The reader both evaluates AND integrates in a single sitting — no separate "try the console" vs "use the SDK" pages.
- **`stigmer run` syntax**: Used `-m` flag for the message (not positional arg). Verified against CLI source: single positional arg is the agent slug, message is always `--message` / `-m`.
- **Agent YAML `skill_refs` format**: Verified against proto definitions — uses `kind: skill` and `slug: <name>` (not `kind: Skill` with capital S).
- **SKILL.md frontmatter**: Uses `name` and `description` fields (verified against `seedpack/skills/` examples). No `license` field in quickstart example to keep it minimal.
- **Demo component approach**: `DemoSkillCreation` wraps `MessageThread` (presentational) with pre-built execution data inside a `StigmerProvider` for consistency with the established pattern and to support any future hook-based sub-components.
- **Scenarios live in site/, not SDK**: Demo scenarios are documentation-specific content (conversation text, policy copy, fixture wiring for a specific page). The generic tooling (`createDemoClient`, `buildScenario`, `fixtures`, `samples`) stays in `@stigmer/react/demo`. Scenarios live in `site/src/components/docs/demos/scenarios/` where consumers create their own. A platform builder using the demo API would write their own scenarios — they wouldn't reuse Stigmer's docs-specific ones.
- **Next.js cache**: Stale `.next/` cache caused false webpack import errors after re-installing `@stigmer/react`. Fixed by deleting `.next/` before build.

## SDK boundary audit

Post-implementation, audited the `@stigmer/react/demo` module against the
principle: "Would a platform builder embedding Stigmer into their product need
this?" Results:

- **Moved to site/**: Both demo scenarios (`quickstart.ts`, `skill-creation.ts`)
  — these are docs-specific narrative content, not generic tooling.
- **Stays in SDK**: `DemoTransport`, `createDemoClient`, `fixtures`, `samples`,
  types, tests — all generic mock infrastructure a platform builder would use
  for Storybook, testing, or their own demo pages.
- **Clean boundary confirmed**: No imports from `site/`, MDX, or Next.js exist
  in the SDK demo module. Scenarios in `site/` import from `@stigmer/react/demo`
  as any external consumer would.
