# Session Notes: 2026-03-18 (Session 7)

## Accomplishments

- Fixed follow-up input staying disabled after execution completes

## Decisions Made

- Chose to refetch the executions list on terminal phase rather than patching the local execution array, keeping the single-source-of-truth in the server response
- Placed the refetch effect in `useSessionConversation` (the orchestrator) rather than in `useExecutionStream` (low-level stream hook) to preserve separation of concerns

## Key Code Changes

- `sdk/react/src/session/useSessionConversation.ts`: Added `useEffect` that calls `refetch()` when `activeExecutionId` is non-null and `stream.phase` is terminal. This closes the gap where the fetched executions list retained stale non-terminal phase data after the stream completed.

## Root Cause Analysis

1. `canSendFollowUp` = `!isCreating && activeExecutionId === null`
2. `activeExecutionId` = `pendingExecutionId ?? listActiveId`
3. `listActiveId` scans the fetched `executions` array for any execution NOT in a terminal phase
4. When the stream detected terminal phase and stopped, `useSessionExecutions` was never re-triggered
5. The fetched list retained the old non-terminal phase, so `listActiveId` kept returning the ID
6. `canSendFollowUp` stayed `false`, keeping the `FollowUpInput` disabled
