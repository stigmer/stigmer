## Decisions Made

- **SDK-first placement**: `SessionComposer` and `useComposer` live in `@stigmer/react`, not `client-apps/web` -- platform builders get the unified component out of the box
- **Layout-agnostic design**: `SessionComposer` does not dictate centering or bottom-pinning; consumers control placement via `className`
- **Session-level workspace updates**: Workspace changes in follow-up trigger `session.update()` before execution creation, affecting all future executions in the session
- **`buildUpdateInput` helper**: Reconstructs full `SessionInput` from existing `Session` proto to prevent field loss during partial updates (preserves `agentInstanceId`, `subject`, `threadId`, `sandboxId`, `metadata`, `mcpServerUsages`, `skillRefs`)
- **One-time initialization guard**: `useRef(initialSyncDone)` prevents re-populating `useWorkspaceEntries` from proto entries on re-renders

## Learnings

- Backend `session.update()` RPC uses `name` + `org` from metadata for resource identification, not an explicit `id` field in the input
- Proto3 default values + `stripUndefined` could silently clear existing spec fields during partial updates -- must always reconstruct the full input object from existing session state
