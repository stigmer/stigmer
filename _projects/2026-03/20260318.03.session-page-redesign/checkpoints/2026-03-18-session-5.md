# Session Notes: 2026-03-18 (Session 5)

## Accomplishments

- Fixed FollowUpInput widget visibility — inner card now uses `bg-card` instead of `bg-background`, which was invisible in dark mode (both resolved to the same oklch(0.145) luminance). Outer wrapper stripped of `border-t` and `bg-card` bar chrome to render as a floating widget by default.
- Added human message left indentation (`ms-[20%]`) to `HumanMessage` in `MessageEntry` and `pending-message` in `MessageThread`, creating strong visual differentiation between user and AI/system messages (matching Claude Code's layout pattern).
- Removed the `className="border-t-0 bg-transparent"` override from `SessionPage.tsx` since SDK defaults now produce the correct floating widget appearance.

## Decisions Made

- **20% margin-inline-start for human messages**: Uses `ms-[20%]` (logical property for RTL support). On the ~888px thread column, this yields ~177px indent — proportionally matching Claude Code's observed ~25% indent on its ~680px content area.
- **FollowUpInput floating widget as default**: Removed `border-t` and `bg-card` from the outer wrapper default. A floating widget is the correct default for an embeddable SDK component. Platform builders who need bar mode can add those classes via `className`.
- **bg-card over bg-background for inner card**: In dark mode, `bg-card` (oklch 0.205) provides visible contrast against page `bg-background` (oklch 0.145). Light mode: bg-card (white) vs bg-background (off-white) also creates subtle but visible card definition.

## Learnings

- When composing SDK components with transparent outer wrappers, the inner card's background must contrast against the page background, not just the outer wrapper. The two-level nesting (outer bg-card + inner bg-background) pattern works for bar mode but fails for floating widget mode.
- Percentage-based margins (`ms-[20%]`) are responsive to container width, making them better than fixed values for components that may be embedded in various container sizes.
