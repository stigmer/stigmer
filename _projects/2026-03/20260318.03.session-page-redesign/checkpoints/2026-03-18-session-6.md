## Decisions Made

- **Empty-content AI message for orphan tool calls**: When a tool call (e.g., thinking) starts before any text, create an AI message with empty content rather than creating a special message type or splitting tool calls into separate rendering paths. This keeps the data model and rendering logic uniform.
- **No `MESSAGE_TOOL` backward compatibility**: Since no consumers depended on `MESSAGE_TOOL` messages, we removed their creation entirely rather than maintaining dual paths.
- **Protobuf copy sync**: Tool calls exist in both the AI message's `tool_calls[]` and the flat `status.tool_calls[]` list. Updates must be applied to both copies explicitly.
- **User toggle override for auto-expand**: `userToggledRef` tracks whether the user manually toggled a tool group, preventing auto-collapse from fighting user intent.

## Learnings

- Protobuf `repeated` field `append()` in Python creates independent copies — mutations to one don't propagate to the other. Any shared data must be explicitly synced.
- The `_find_tool_call_by_id` helper searches the flat list; a separate scan of AI messages is needed to update the message copy.
- The LLM event flow is strictly sequential per namespace: thinking → text → tool calls. Empty-content AI messages naturally slot into this timeline.
