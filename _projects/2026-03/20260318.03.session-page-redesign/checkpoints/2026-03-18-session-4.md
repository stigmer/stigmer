## Decisions Made

- **Invert direction, not just reduce gap**: The original plan framed this as "reducing the luminance gap." Analysis of all five themes revealed the issue was directional: the base theme was the only one where the sidebar was lighter than the background. The fix inverts the relationship to match all four presets.
- **Sidebar at L=0.12 (delta -0.025 from background)**: Chose a delta consistent with the preset range (-0.02 to -0.04). This places the sidebar as the darkest ground surface in the hierarchy.
- **Sidebar-accent at L=0.20 (delta +0.08 from sidebar)**: Adjusted the hover/active accent to maintain a visible but non-jarring highlight, consistent with preset hover deltas (+0.07 to +0.09).
- **Six tokens left unchanged**: Evaluated all eight sidebar tokens; only two needed adjustment. The remaining six (foreground, primary, primary-foreground, accent-foreground, border, ring) work correctly at the new luminance.

## Key Code Changes

- `sdk/theme/src/tokens.css` (`.dark` block):
  - `--stgm-sidebar`: `oklch(0.205 0 0)` -> `oklch(0.12 0 0)`
  - `--stgm-sidebar-accent`: `oklch(0.269 0 0)` -> `oklch(0.20 0 0)`

## Learnings

- The base theme's dark sidebar value (0.205) matched `--stgm-card` (0.205) — this was likely inherited from shadcn/ui defaults where the sidebar was treated as a card-level surface. All four presets treat the sidebar as the deepest ground surface instead, which is the convention in VS Code, Discord, Linear, and Slack dark themes.
- Light mode was already correct across all themes (sidebar subtly darker than background), so no light mode changes were needed.
- Presets override all sidebar tokens independently, so this change only affects the base (no-preset) theme.
