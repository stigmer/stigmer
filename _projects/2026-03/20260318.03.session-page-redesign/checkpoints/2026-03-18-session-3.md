## Decisions Made

- **Static right column over floating overlay**: Widgets sit in a `<aside>` column next to MessageThread, not as absolutely-positioned overlays. Avoids content overlap, z-index complexity, and accessibility concerns with obscured text. The column shares the same background as the main content area — no panel chrome.
- **Hidden on narrow screens (< lg)**: Widgets are `hidden lg:flex`. The conversation thread itself conveys execution status via inline phase badges and streaming content. Mobile is a secondary monitoring context — developers running agents are at desks. Context window utilization and token costs are actionable on desktop, not on phones.
- **Always reserve column space**: The widget column is present on lg screens regardless of content. The "truly empty" state (no execution, no workspace entries) is transient (sub-second during initial load). Layout stability outweighs marginal horizontal space savings.
- **displayExecution fallback**: `activeStreamExecution ?? completedExecutions[last]`. Shows the last completed execution's final metrics (cost, tokens, context window) when idle, so users see post-execution data without navigating away.
- **FollowUpInput restyled via className override**: `border-t-0 bg-transparent` removes the separator bar feel. The SDK default (`border-t bg-card`) remains sensible for platform builders — the Console overrides for its single-canvas design. No SDK component changes needed; `cn()` (tailwind-merge) handles the class merging.
- **Conditional card rendering**: Each widget is wrapped in a card container (`rounded-lg border border-border bg-card p-3`) that renders only when the widget has data. ExecutionSummary when displayExecution is non-null, ContextWindowMeter when contextInfo exists, WorkspaceSummary when entries are non-empty.

## Learnings

- MessageThread has its own internal scroll container (`overflow-y-auto` with `scrollRef`). This means sticky positioning inside a shared scroll context isn't possible without modifying the SDK component. The static right column approach works because the widgets don't need to scroll — they need to be always visible.
- `cn()` from `@stigmer/theme` (clsx + tailwind-merge) correctly handles class overrides: `border-t-0` overrides `border-t`, `bg-transparent` overrides `bg-card` in the merged output.
- The protobuf `workspaceEntries` on `session.spec` is always available after the early returns (which guard against null session), so no additional null checks needed.
