## Production Bugs Fixed

1. **`uint32` kind not handled**: `goType()` and `genFromProtoField()` panicked on `uint32` — used by `Duration` type in `tasks/types/duration.json` (5 fields). Added `case "uint32": return "uint32"` to `goType()` and corresponding `uint32(val.GetNumberValue())` conversion to `genFromProtoField()`.

2. **`timestamp` kind not handled**: `goType()` and `genFromProtoField()` panicked on `timestamp` — used by `WaitTaskConfig` and `ApiKeySpec`. Added `case "timestamp"` to `goType()` (returns `*timestamppb.Timestamp` with import) and full RFC3339/struct-based parsing to `genFromProtoField()`.

## Key Code Changes

- `tools/codegen/generator/main.go`: Added `uint32` and `timestamp` kind support to `goType()` switch (+5 lines) and `genFromProtoField()` switch (+20 lines)
- `tools/codegen/generator/integration_test.go`: New file, 7 test functions covering end-to-end generation pipeline

## Decisions Made

- **Temp dir + chdir approach**: Integration tests create temp directories with JSON schemas and `os.Chdir` to the temp dir so the generator's hardcoded relative output paths (`sdk/go/gen/types/`, `sdk/go/gen/<subdomain>/`) resolve correctly
- **go/parser.ParseFile verification**: All generated files pass through `go/parser.ParseFile` for syntax validation, on top of the `go/format.Source()` that the generator already calls internally
- **Real schemas test**: `TestIntegrationRealSchemas` uses the actual production `tools/codegen/schemas/` directory — this is the most valuable test because it catches regressions when schemas change

## Learnings

- The `TypeSpec.Kind` doc comment lists `uint32` and `timestamp` as valid kinds, but neither was implemented in `goType()` — the existing code generation apparently never exercised these paths because the schemas using them were shared types generated via a different code path
- `scalarGoType()` in `mcp.go` already handled `uint32` correctly — the inconsistency was only in `main.go`'s `goType()`
