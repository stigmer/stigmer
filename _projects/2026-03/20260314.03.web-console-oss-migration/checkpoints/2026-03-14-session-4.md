## Decisions Made

- **Server/client split for dynamic routes**: Next.js 16 (Turbopack) explicitly rejects `generateStaticParams` in `"use client"` files. Each dynamic route was split into a server `page.tsx` (exports `generateStaticParams`, renders client component) and a colocated client component file (has `"use client"`, uses `useParams()`).
- **Placeholder params instead of empty arrays**: Next.js 16's Cache Components feature (enabled by default) rejects `generateStaticParams` returning `[]`. Each route returns `[{ id: "__placeholder__" }]` instead. This generates a pre-rendered page at `/<route>/__placeholder__` which is harmless — the client component will attempt an API fetch for a non-existent ID and show its error state.
- **Runtime config deferred to T05**: Build-time `NEXT_PUBLIC_*` env vars are sufficient for both local and cloud builds. Runtime config will be implemented alongside Go embedding.
- **Dockerfile not touched**: Still references Yarn and standalone mode — will be fully rewritten in T05/T07.

## Surprises Discovered

- **`generateStaticParams` + `"use client"` incompatibility**: The plan anticipated this as a risk and prepared a mitigation (server/client split). Next.js 16 with Turbopack rejects the combination at compile time: "App pages cannot use both 'use client' and export function 'generateStaticParams()'."
- **Empty `generateStaticParams` array rejected**: This was NOT anticipated. Next.js 16's Cache Components (enabled by default) requires `generateStaticParams` to return at least one param set for build-time validation. The error message is misleading — it says "missing generateStaticParams()" instead of indicating the empty array is the problem. This required iterative debugging to identify the root cause.

## Learnings

- Next.js 16 has Cache Components enabled by default. This changes build-time validation behavior for `generateStaticParams` — empty arrays are no longer valid, even when you genuinely have no build-time-known IDs.
- The error message "Page is missing generateStaticParams()" can mean either (a) the function is truly not exported, or (b) it returns an empty array with Cache Components enabled. The misleading error message cost significant debugging time.
- The `__placeholder__` pattern from the Next.js docs is the official workaround for this limitation.
- `npx serve` handles clean URLs automatically (redirects `/agents.html` to `/agents`), making it suitable for quick local testing of static exports.
