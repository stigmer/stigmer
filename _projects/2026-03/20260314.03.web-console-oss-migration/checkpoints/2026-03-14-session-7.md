## Decisions Made

- **No `release.web.yaml`**: Confirmed stigmer-cloud has no web release workflow — cloud deployment handled by Planton. No need to create one in OSS.
- **Build-once CI pattern**: Web console built once in dedicated `build-web-console` job, uploaded as CI artifact, downloaded by each platform build job. Saves CI minutes and keeps Go jobs focused.
- **`ARG`→`ENV` Dockerfile pattern**: `NEXT_PUBLIC_*` variables are build-time only for static exports. Docker `ARG` values must be explicitly promoted to `ENV` for `npm run build` to pick them up.
- **nginx over Node.js runtime**: Static export doesn't need a Node.js server. `nginx:alpine` is ~5x smaller and purpose-built for serving static files.
- **Resource right-sizing**: nginx serving static HTML needs 64-128Mi memory, not the 500Mi-2Gi previously allocated for Node.js SSR.
- **Kustomize env var cleanup**: Removed all stale Auth0/NextAuth references and misleading `NEXT_PUBLIC_*` runtime overrides (they're build-time only).

## Learnings

- `NEXT_PUBLIC_*` environment variables are baked into the JavaScript bundle at build time when using `output: "export"`. They cannot be overridden at runtime via Kubernetes env vars or Docker environment variables. The only way to configure them is via Docker build args or CI environment variables.
- Docker `ARG` values are NOT automatically available as environment variables in `RUN` commands. They must be explicitly set via `ENV VAR=$ARG` for child processes like `npm run build` to see them.
