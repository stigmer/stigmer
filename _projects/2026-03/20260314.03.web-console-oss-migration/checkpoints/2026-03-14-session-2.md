## Decisions Made

- **npm workspaces** chosen over Yarn/pnpm — zero extra tooling, aligns with OSS philosophy
- **Auth stubs are no-ops** — T02 gets the app compiling; T03 designs the proper auth abstraction
- **Dockerfile and _kustomize/ included** — corrected initial plan to exclude them; single codebase means deployment artifacts belong with the code
- **`force-dynamic` removed** — was needed for auth-dependent server rendering; will be unnecessary after T04 static export
- **`shadcn` moved to devDeps** — CLI tool, not a runtime dependency

## Learnings

- npm workspaces resolve `"@stigmer/protos": "*"` to the local workspace package automatically via symlink — no special protocol needed (unlike Yarn's `workspace:*`)
- The web app's auth layer has a clean boundary: `Providers.tsx` wraps everything, `transport.ts` reads from a standalone `auth-token.ts` module. This made stripping auth surgical rather than invasive.
- Pre-existing code quality issue: every service file casts Connect-RPC client to `any` with "codegenv1 type-inference workaround" — flagged for separate cleanup
