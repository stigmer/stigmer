## Decisions Made

- **`--web-port` deferred**: Port customization requires runtime config injection into the static export, CORS changes, and API port coordination. Ship when someone actually needs it (YAGNI).
- **`--open` over auto-open**: Browser auto-open rejected as default behavior — annoying on restarts, breaks CI, terminal-first users don't want it. Explicit `--open` flag is CI-safe and opt-in.
- **Web console optional in status display**: Unlike infrastructure components (temporal, stigmer-server, etc.) which always show "Not Running" when absent, web-console only appears in `stigmer server status` when it has a health state entry. This avoids confusing "Not Running" for dev builds without `embed_webconsole`.
- **`--no-web` records `stopped` state**: When `--no-web` is used, the daemon records `web-console: stopped` in health state (not absent). This lets `stigmer server status` show it was intentionally disabled.
- **Fallback health probe is one-shot, not periodic**: Web console runs in-process as a static file server — it either starts or it doesn't. TCP probe in `createBasicHealthState` is sufficient without adding it to the health monitor loop.

## Learnings

- The `startServerFresh` function is shared by both `stigmer server` and `stigmer server reset`. Adding parameters to it requires updating both callers — caught this via `grep` before it would have broken the build.
- The health state design has a subtle distinction: infrastructure components (temporal, stigmer-server, etc.) always appear in the status even when absent (shows "Not Running"), but optional components like web-console should only appear when they have a health state entry. This required an explicit `continue` in the component iteration loop.
