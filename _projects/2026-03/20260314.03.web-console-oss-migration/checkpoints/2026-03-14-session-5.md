## Decisions Made

- **Embed in daemon, not stigmer-server**: Mirrors cloud topology where frontend and backend are separate services. Web console on 8234, API on 7234.
- **gRPC-Web on stigmer-server**: Browsers cannot speak native gRPC. The `improbable-eng/grpc-web` wrapper translates gRPC-Web requests to native gRPC calls. This was a critical discovery not covered in the original project plan.
- **In-process goroutine, not subprocess**: The web console is a lightweight static file server — doesn't warrant subprocess overhead or independent crash recovery.
- **h2c for protocol multiplexing**: HTTP/2 cleartext allows native gRPC clients (CLI, runners) and HTTP/1.1 clients (browser gRPC-Web) on the same port without TLS.
- **CORS allow-all for local**: Cloud handles CORS at the proxy layer. Locally, `improbable-eng/grpc-web` allows all origins for cross-port requests.
- **Build tag gating**: `embed_webconsole` tag keeps development builds lean; production builds include both agent-runner and web console.
- **StartHTTP as shared library method**: The h2c server logic is generic and lives in `backend/libs/go/grpc/`, while the gRPC-Web wrapper is specific to stigmer-server.

## Surprises Discovered

- **gRPC-Web protocol gap**: The biggest surprise. `stigmer-server` only spoke native gRPC over HTTP/2. The web console uses `createGrpcWebTransport` (HTTP/1.1 compatible). Without a translation layer, the browser can never reach the API. This required architectural collaboration with the user before proceeding.
- **CORS needed for cross-port**: Web console on 8234 calling API on 7234 is a cross-origin request. Browsers enforce CORS preflight. The `improbable-eng/grpc-web` library handles this natively.

## Learnings

- `improbable-eng/grpc-web` is the Go-native solution for gRPC-Web (vs Envoy proxy in production). It wraps a `*grpc.Server` and translates wire formats transparently.
- h2c (`golang.org/x/net/http2/h2c`) enables HTTP/2 without TLS — essential for local dev where gRPC clients expect HTTP/2 but browsers don't use TLS.
- SPA routing for static exports needs fallback to `index.html` for any path that doesn't match a file in the FS — standard pattern but critical for Next.js client-side routing.
- Next.js static export `_next/static/` assets include content hashes and are safe for immutable caching.
