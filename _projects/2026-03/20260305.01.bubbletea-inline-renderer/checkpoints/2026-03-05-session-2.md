## Decisions Made
- **Bubbletea tea.Tick Cmd** over goroutine hybrid: The event loop sends spinnerStartMsg/spinnerStopMsg to Bubbletea via program.Send(). The model's Update() manages a self-propagating 80ms tick chain. View() renders the frame. This is fully idiomatic Bubbletea and sets the pattern for all future phases.
- **Export spinner constants**: Frames, FrameInterval, FormatElapsed exported from pkg/spinner so the Bubbletea model produces identical output without duplicating. The Spinner type stays for workflow execution.
- **Async stop is safe**: program.Send() is async (unlike old synchronous spinner.Stop()), but all subsequent status output also goes through program.Println() (also async), preserving ordering within Bubbletea's render cycle. The approval flow edge case was analyzed -- preceding events always reset the idle timer before ApprovalNeededEvent arrives.

## Learnings
- The Bubbletea tea.Tick pattern (self-propagating tick chain) is clean and avoids all goroutine coordination. Each tick returns the next tick as a Cmd; setting active=false terminates the chain naturally.
- View() rendering the spinner means Bubbletea accurately tracks the spinner's row count. When the spinner stops, View() returns "" and Bubbletea clears the line automatically.
- The dual-path (program.Send when TTY, no-op when non-TTY) keeps tests simple: no program means no spinner, which is correct for CI/piped environments.
