## Decisions Made

- **View() approach for the prompt**: The follow-up prompt renders through Bubbletea's View() when program is non-nil. User-typed text echoes via terminal driver (outside Bubbletea's control), which works correctly in the common case because no messages are sent during typing — no re-renders occur. The known edge case (very long wrapping input) has the same limitation as the current `EraseLines(4)` approach and will be fully resolved by the next project (20260305.02) when Bubbletea takes stdin ownership.
- **Clean function decomposition**: `readFollowUpInput` was split into three single-responsibility functions: `formatFollowUpPrompt` (pure string builder), `readStdinLine` (stdin I/O only), `readFollowUpInputDirect` (compose both for direct-write path). This matches the Phase 4-5 pattern of `*ViaBubbletea` / `*Direct` helpers.
