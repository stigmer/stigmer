## Decisions Made
- **File size thresholds are guidelines, not hard rules**: Several files (render.go 283, approval.go 278, bubbletea.go 275, streaming.go 340) exceed 250 lines by modest margins. In each case, splitting further would separate tightly cohesive code (methods operating on a single type, or a complete rendering pipeline) without reducing complexity.
- **Pre-existing test failures left untouched**: `TestHandleApproval_DoesNotSuppressOnReject` and `TestInlineRenderer_ToolCompleted_ShowsBadge` were failing before cleanup. They involve `trackSuppression` not checking action type and `RenderCompact` badge rendering -- both outside the cleanup scope.
- **`program == nil` fallback paths are NOT dead code**: They serve non-TTY environments (pipes, CI) and unit tests. Explicitly preserved.

## Learnings
- `git stash` does NOT stash untracked files by default. Using `git stash` to test old code against new untracked files causes compilation redeclaration errors.
- The 250-line file limit guideline works well for new code but requires judgment when splitting existing cohesive modules. Navigation cost of splitting tightly coupled methods can exceed the benefit of smaller files.
