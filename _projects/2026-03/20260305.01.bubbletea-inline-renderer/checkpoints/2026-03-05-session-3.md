## Decisions Made
- **Header stays as committed content**: Bubbletea's `View()` renders at the bottom; putting the header there would invert the display order. The header is top-of-session content and should remain a direct stderr write before Bubbletea starts. See `design-decisions/002-header-stays-committed.md`.
- **Subject field omitted from new sessions**: No placeholder dash, no in-place update. Subject appears on session resume when resolved. This is the cleanest deletion of all cursor math.
- **Future option acknowledged**: `lineCountingWriter` can be reintroduced later as a small contained hack if in-place subject update is desired.

## Key Code Changes

- `run_stream_inline_header_update.go`: Deleted entirely
- `run_stream_inline_header_update_test.go`: Deleted entirely

## Learnings
- Bubbletea's `View()` is always at the bottom. `Println()` commits above it. There is no mechanism for "top-of-scrollback updateable content." This is a fundamental layout constraint that future phases should not try to work around.
- The distinction between committed content (permanent, scrolls up) and active content (re-rendered in place at bottom) maps cleanly to the Bubbletea model: Println for committed, View for active.
