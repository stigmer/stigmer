## Decisions Made

- **Hybrid over full-async**: The blocking event loop + Bubbletea rendering approach is the simplest correct solution. Full-async (Bubbletea owns stdin via `WithInput`) would require fighting the framework for scenarios where the event loop has nothing else to do during approval. The hybrid approach can evolve to full-async later if concurrent requirements emerge.
- **Pre-approval streaming erasure stays**: The `EraseLines` calls for streaming content (written directly to stderr, bypassing Bubbletea) remain as a temporary bridge. They restore cursor sync so Bubbletea can take over. Phase 5 moves streaming into View(), eliminating these.
- **Approval panel takes View() priority over spinner**: When `approvalActive`, View() renders the panel; spinner is hidden but its state is preserved. After `approvalHideMsg`, spinner resumes if still active.
- **Collapsed result via tea.Println Cmd**: `approvalHideMsg` with a non-empty `collapsedResult` returns `tea.Println()` as a Cmd from Update(). Bubbletea's FIFO processing guarantees: (1) panel cleared, (2) collapsed result committed above.
