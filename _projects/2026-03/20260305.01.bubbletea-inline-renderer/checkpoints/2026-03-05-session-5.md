## Decisions Made

- **Both pre-approval and post-approval streaming moved to View()** (Option A from planning). This is simpler and consistent, eliminates all 4 target EraseLines. Post-approval shell output is typically short-running; performance optimizations like progressive commitment can be added later if needed.
- **Atomic streaming→approval transition**: `approvalShowMsg` clears streaming state as a side effect in `handleApprovalShow`, so View() transitions directly from streaming to approval without an empty frame. No explicit `streamingHideMsg` is needed between streaming and approval.
- **Full content in `streamingUpdateMsg`**: The model receives the full accumulated content (not deltas). View() formats the entire content on each render. This is simpler than incremental state tracking and works well with Bubbletea's 60fps rendering cap.
- **Width captured at start time**: Terminal width is stored in `streamingShowMsg` and used for the duration of the streaming session. Mid-streaming resize is an extreme edge case; worst case is slightly misformatted lines.
