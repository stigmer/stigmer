## Decisions Made

1. **`instanceof UpdateContextV2` for accessing existing resource in `EncryptSecretValues`**: The `ContextBase` interface does not expose `getExistingResource()` — only `UpdateContextV2` does. Rather than adding a default method to `ContextBase` (which would leak update-pipeline concerns into every context type), we use a targeted `instanceof` check. This keeps the sentinel defense domain-specific.

2. **`RedactedMarker` constant in Go steps package**: Defined `const RedactedMarker = "***REDACTED***"` in the environment controller steps package. Go OSS does not redact secrets (single-user local mode), but the constant is needed for the defense-in-depth check. It matches the Java Cloud `RedactSecretValues.REDACTED_MARKER`.

3. **`INVALID_ARGUMENT` error for marker on non-existent keys**: When a client sends the redaction marker for a key that doesn't exist in the existing resource, this is an unambiguous client error (there's no secret to preserve). Both Java and Go return `INVALID_ARGUMENT` with a clear message.

4. **Friendly input types for React hooks**: The hooks accept `UpdateEnvironmentVariablesInput` and `RemoveEnvironmentVariablesInput` (using `EnvVarInput` from `@stigmer/sdk`) rather than raw proto types. This is consistent with how `useUpdateEnvironment` accepts `EnvironmentInput`, and shields platform builders from `@bufbuild/protobuf` schema imports.

5. **State naming convention**: `isUpdatingVariables` and `isRemovingVariables` follow the established `is{Verb}ing` pattern (see `isUpdating`, `isCreating`, `isRevealing` in existing hooks).

## Learnings

- `ContextBase` in the Java Cloud pipeline framework is intentionally minimal — it doesn't expose `getExistingResource()`. The `instanceof` pattern for accessing context-specific data in shared steps is the idiomatic approach.
- Go OSS's `grpclib.InvalidArgumentError` takes `(format string, args ...interface{})`, not `(error, string)` like `InternalError`. The signatures differ by design — `InvalidArgumentError` is client-facing (no internal error to wrap), while `InternalError` wraps an internal error with a user-facing message.
- The `@stigmer/react` package already imports from both `@bufbuild/protobuf` and `@stigmer/protos` in many hooks, so proto construction in the new hooks is consistent with established patterns.
