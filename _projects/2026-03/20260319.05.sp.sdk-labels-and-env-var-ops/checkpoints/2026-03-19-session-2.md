## Decisions Made

1. **Pipeline type = request proto, not resource**: For non-CRUD RPCs, the pipeline generic type is the request message (e.g., `UpdateEnvironmentVariablesRequest`), not the `Environment` resource. Consistent with the existing `GetSecretValue` pattern.

2. **Self-contained custom steps**: Each step (merge/remove) handles loading, domain logic, audit timestamps, and persistence in one step. The modified `Environment` is stored in the request context for the handler to return. This avoids fighting the generic pipeline abstractions.

3. **Generalized `LoadEnvironmentByIDStep`**: Introduced `HasEnvironmentId` interface (`proto.Message + GetEnvironmentId() string`) to make the step work with any request proto that carries `environment_id`. Now supports 3 proto types.

4. **No IndexSearchStep for variable ops**: The search extractor only indexes metadata, not `spec.data` (where variables live). Including `IndexSearchStep` would have required workarounds for type compatibility with no real benefit.

5. **Go OSS skips encryption**: Existing OSS `create` and `update` handlers don't encrypt `is_secret` values. Maintaining this consistency for the new variable ops handlers avoids breaking the local single-user deployment model.

6. **Java Cloud encrypts on merge**: The `EnvironmentUpdateVariablesHandler` encrypts incoming secrets via `EnvironmentSecretService.encrypt()` for each variable with `is_secret=true`, consistent with the Cloud multi-tenant security model.

7. **Authorization via `field_path = "environment_id"`**: Both new RPCs use `can_edit` permission with `field_path` pointing to `environment_id` on the request, since the request is not the resource itself. The interceptor resolves the environment's org/project context from this field.

## Learnings

- `CustomOperationHandlerV2` in Java Cloud provides excellent extensibility for non-CRUD operations — the inner step pattern keeps domain logic encapsulated while reusing the standard authorize/validate/redact pipeline stages
- Go's interface constraints with generics make reusable pipeline steps clean — `HasEnvironmentId` is a pattern worth replicating for other resource-scoped non-CRUD operations
- The `proto2schema --comprehensive` → SDK codegen pipeline is fully automated; manual schema edits are never needed
