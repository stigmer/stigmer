- Created `StigmerTransportBridge` component bridging `useAuth()` + `getApiBaseUrl()` into `StigmerTransportProvider`

- Net result: 31 files changed, 53 insertions, 1,208 deletions

## Decisions Made

- **Two transport paths (temporary)**: Execution services use `StigmerTransportProvider` (IoC). Six non-execution services still use singleton `transport.ts` + `token-store.ts`. Unifying is out of scope — it would require migrating session, draft, catalog, auth, and agent services, which are not part of T05.
- **`useSessionDetail` structural refactor**: Changed from calling `listExecutionsBySession` as a bare function to calling it via `useExecutionService()` hook. This was the right approach — the library exposes service objects through hooks, not standalone functions.
- **`lib/utils.ts` and `lib/execution.ts` already absent**: These files referenced in the plan never existed on this branch. No action needed.
- **`transport.ts` and `token-store.ts` kept**: Still depended on by 6 non-execution services. Removing them would break the app.

## Learnings

- The proxy re-export pattern from T04 (`src/components/execution/index.ts`) was a good intermediate step — it meant page imports mostly just needed path changes, not API changes
- React Context IoC bridge pattern works cleanly: auth context → bridge component → transport provider → library hooks. Each layer has a single responsibility.
- `components.json` alias update is important for future shadcn adds — without it, newly generated components would use the old `@/lib/utils` path
