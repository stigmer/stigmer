## Decisions Made

- **Ship source (Option A)**: `src/` copied into `dist/src/` for declaration map resolution. Package sizes small enough (11-44KB) to justify including source for IDE DX.
- **CI owns publishing**: `make release` only pushes tags. `release.npm-libs.yaml` CI workflow does the actual `npm publish`. No local publishing path.
- **`buf/` stays in protos**: Multiple generated stubs depend on `buf/validate/` imports. Removing it from `tsconfig.build.json` would break the build.
- **`module: "ES2022"` over `"esnext"`**: `"esnext"` is a moving target — `"ES2022"` pins the emit behavior for stable published packages.

## Key Code Changes

- `Makefile`: Removed `libs-publish` call from `release` target; added comment explaining CI ownership
- `scripts/publish-libs.mjs`: Added `copySrcForDeclarationMaps()`, LICENSE copying, `engines`/`keywords` propagation in `generateDistPackageJson()`

- New: `README.md` for all 4 packages

## Learnings

- npm auto-corrects `repository.url` from `https://` to `git+ssh://` during `npm pack` — fixing the format to `git+https://` eliminates the warning
- `npx @tailwindcss/cli` is unnecessary overhead when `tailwindcss` is available via the workspace root's `@tailwindcss/cli` devDependency
- Declaration maps (`.d.ts.map`) only enable "Go to Definition" if the source files they reference are physically present in the package
