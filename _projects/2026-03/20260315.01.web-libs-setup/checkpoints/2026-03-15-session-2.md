## Decisions Made

1. **React Context + Imperative Factory** (architecture decision for T02):
   - `createStigmerTransport(config)` for non-React usage (tests, scripts)
   - `StigmerTransportProvider` + `useServiceClient()` for React component trees
   - Replaces module-level singleton transport and mutable token store

2. **`DescService` from `@bufbuild/protobuf`** (discovered during build):
   - The `createClient` function in `@connectrpc/connect` uses `DescService` from `@bufbuild/protobuf` as the service descriptor type
   - `@connectrpc/connect` does not re-export `DescService` — must import from `@bufbuild/protobuf` directly

3. **No ref-based callback pattern** (React 19 surprise):
   - React 19's `react-hooks/refs` ESLint rule forbids reading/writing `ref.current` during render
   - The planned ref pattern for `getAccessToken` (stable closure with latest callback) triggers lint errors
   - Simpler approach: `useMemo` with explicit deps; consumers wrap callbacks in `useCallback`
   - Documented in the provider's JSDoc

4. **env.ts NOT extracted** (IoC improvement):
   - Server URL provided by consumer via `serverUrl` prop, not read from env vars
   - `getApiBaseUrl()` stays in the console — it's a Next.js-specific concern

5. **Lean scope** (deliberate omission):
   - No event buses, notification integration, environment info, local error scopes
   - These are Planton patterns that Stigmer doesn't need yet

## Learnings

- React 19's ESLint plugin is significantly stricter about refs than React 18. The `react-hooks/refs` rule is new and catches patterns that were previously common (writing `ref.current` during render, passing ref-reading callbacks to functions during render).
- `@connectrpc/connect` v2's type exports are minimal — `DescService`, `DescMessage`, etc. live in `@bufbuild/protobuf`. Always check `node_modules` type definitions rather than guessing import paths.
