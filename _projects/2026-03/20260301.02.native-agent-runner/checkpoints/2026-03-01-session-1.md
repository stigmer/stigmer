## Decisions Made

1. **Daemon owns native agent-runner, not supervisor**: StartWithOptions() starts agent-runner natively and passes `STIGMER_SKIP_AGENT_RUNNER=true` to prevent supervisor's Docker startup
2. **Auto mode viability probe runs before server start**: Prevents the dual-start race condition
3. **`SANDBOX_ROOT_DIR` not `WORKSPACE_ROOT`**: Fixed existing env var mismatch for native mode
4. **Build-tagged source resolution**: Dev mode uses `os.DirFS` with repo tree walk; production uses `//go:embed` after sync.sh — avoids fighting Go's embed path restrictions
5. **Supervisor out of scope except minimal guard**: 3-line env var check to prevent conflicts, no native mode support in supervisor

## Learnings

- `startHealthMonitoring()` in daemon's health_integration.go is **never called** — the entire daemon health monitoring system is dead code. All component management goes through supervisor.
- `startAgentRunner()` and `startWorkflowRunner()` in daemon.go were only called from the never-invoked health monitoring restart path, not from the initial startup flow.
- Go's `//go:embed` cannot reference parent directories — requires build-time copy for cross-directory embedding.

## Open Questions

- Is supervisor for cloud and daemon for local, or is one legacy?
- Should health monitoring be wired up in the daemon, or should it all live in supervisor?
