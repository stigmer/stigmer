- **Fixed the `ModuleNotFoundError: No module named 'dotenv'` crash**: Root cause was `bootstrapAgentRunnerRuntime()` creating `pythonrt.Manager` without setting `DepsSource`, so the venv was created empty.
- **Generated `requirements.txt` (131 packages)**: Used `poetry show --only main` to extract pinned production dependencies. Added `pathspec==1.0.3` manually (runtime dep of graphton that poetry miscategorizes). Added `make update-agent-runner-deps` target for regeneration.
- **Reordered bootstrap pipeline**: `pythonrt.Manager.bootstrap()` now runs `extractAppSource()` before `setupVenv()` so `requirements.txt` and path deps are on disk when pip runs.
- **Wired dependency installation**: `bootstrapAgentRunnerRuntime()` calls `mgr.SetDeps()` with `app/requirements.txt` for PyPI deps and `PostInstallCmds` for `graphton` and `stigmer-stubs` (installed with `--no-deps` since transitive deps are already covered).
- **Added `PreInstallFn` to `pythonrt.Config`**: Hook for copying monorepo path dependencies into the app directory in dev mode, before pip runs.
- **Fixed `sync.sh` graphton path**: Was `$GRAPHTON/graphton` (wrong), now `$GRAPHTON/src/graphton` (matches pyproject.toml `packages` config).
- **Added startup health reporting**: `handleServerStart()` reads `health-state.json` after `WaitForReady()` and warns about any failed components. Previously, "Ready!" was printed even with crashed components.
- **Rapid-crash detection**: Components crashing within 5 seconds of starting are immediately marked as `"failed"` (no retry), with specific error messaging.
- **Dead code cleanup**: Removed ~1,350 lines — `startAgentRunnerNative()`, `buildNativeAgentRunnerEnv()`, `tailBytes()`, their test file, the entire `health/` package, and Docker-era comments.

## Decisions Made

- `requirements.txt` is the dependency format for hermetic installs (not `pyproject.toml` or `poetry.lock`) — it's universally understood by pip and avoids Poetry/plugin installation as a prerequisite.
- Path dependencies (`graphton`, `stigmer-stubs`) are installed separately via `PostInstallCmds` with `--no-deps` because their transitive deps are already included in `requirements.txt`.
- `PreInstallFn` is a closure-based hook rather than an interface because there's exactly one call site and the behavior is mode-dependent (dev copies files, production is a no-op since sync.sh already bundled them).
- The rapid-crash window (5 seconds) is intentionally conservative — any structural issue (missing deps, import errors) will crash Python in <1 second.

## Learnings

- `poetry export` requires an optional plugin (`poetry-plugin-export`) which conflicts with Homebrew-installed Poetry on macOS. `poetry show --only main` + manual curation is a reliable alternative.
- `pathspec` is a transitive runtime dependency of `graphton` that `poetry show --only main` misses because poetry categorizes it differently. This was caught during manual verification.
- The `health/` package (~1,350 lines across 6 files) was completely unused dead code — no Go file in the entire repo imported it.
