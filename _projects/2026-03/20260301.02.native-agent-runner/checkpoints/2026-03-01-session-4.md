# Session Notes: 2026-03-01 (Session 4)

## Accomplishments

- Fixed dev-mode agent-runner source detection bug that caused `make release-local && stigmer server` to fail with "agent-runner Python source is not available"

## Root Cause

`make release-local` builds the CLI binary without the `embed_agentrunner` build tag (dev mode) and copies it to `~/bin/stigmer`. The dev-mode init in `agentrunner_dev.go` uses `os.Executable()` to find the binary's location and walks up the directory tree looking for `backend/services/agent-runner/main.py`. Since `~/bin/` is outside the repo tree, the walk never finds the source, `sourceFS` stays nil, and the server fails to start.

## Fix Applied

Added a `devSourceDir` variable to `agentrunner_dev.go` that is injected at build time via `-ldflags` in the Makefile's `release-local` target. This follows the exact same pattern already used by `version.go` for `buildVersion`.

Resolution order in `locateRepoSource()`:
1. `devSourceDir` (ldflags-injected, set by `make release-local`)
2. Walk up from `os.Executable()` (works when binary is inside repo tree)
3. `STIGMER_AGENT_RUNNER_SOURCE_DIR` env var (manual override)

## Key Code Changes

- `Makefile`: Added `DEV_LDFLAGS` variable and updated `release-local` to pass `-ldflags` to `go build`
- `client-apps/cli/embedded/agentrunner/agentrunner_dev.go`: Added `devSourceDir` var, restructured `locateRepoSource()` with 3-tier resolution, added debug logging for all paths

## Learnings

- When a binary is installed outside the repo tree (common pattern: `~/bin/`), executable-path-based source detection fails silently
- The `-ldflags` injection pattern is a clean way to bake build-time knowledge into the binary without environment variables or config files
