# Industry Patterns for Conversational Agent CLI/TUI Interfaces

## Streaming conversation UX in leading AI CLIs

Most “agentic” developer CLIs now converge on a recognizable conversation loop: a transcript view (assistant + tools), a live “work in progress” indicator, and a clear handoff back to the user when the agent is idle. The differentiator is not *whether* they stream, but **how they segment the stream into readable units (turns, tool events, diffs) and how they preserve control (interrupt, approve, resume)**. citeturn5view0turn13view1turn8view0

**Claude Code** emphasizes a “terminal-native REPL with rich pickers/menus.” Its interactive mode has a large shortcut surface area (help overlay via `?`, history search via `Ctrl+R`, verbose toggle for tool details via `Ctrl+O`, and tabbed dialogs/pickers navigated with arrow keys). citeturn5view0 It also has a strong “secondary UI” story inside the terminal: a session picker (`/resume`) with preview/rename/search, an interactive diff viewer (`/diff`) with per-turn diffs, and a status/settings UI (`/config`, `/status`). citeturn6view1turn5view0 In long-running workflows, it explicitly supports backgrounding (return a task ID; buffer output; retrieve with a tool) and has a task list that lives in the terminal “status area,” with a toggle (`Ctrl+T`). citeturn5view0

**Codex CLI** makes the “agent transcript” itself the primary UI artifact. It launches into a **full-screen terminal UI** and treats everything (file reads, diffs, reviews, web searches) as items that appear as turns/events in the transcript. citeturn13view1 It also invests in polish for scanning: fenced code blocks and diffs are syntax-highlighted; themes are managed in a picker (`/theme`). citeturn13view3 Its “stream control” is particularly explicit: you can inject instructions mid-run (Enter) or queue a follow-up prompt (Tab), and you can fork by editing a previous user message via repeated `Esc`. citeturn13view1

**GitHub Copilot CLI** (the newer `copilot` interactive interface) surfaces a split between “Ask/execute” and “Plan mode” (cycle with `Shift+Tab`), and it treats tool usage as a first-class moment that always requires explicit approval unless the user opts into broader allowances. citeturn8view0turn9view1 It also supports “steering while thinking”: users can press `Esc` to stop a running operation, or send follow-ups while the agent is thinking so the agent processes them after finishing the current response. citeturn8view0

**The older `gh copilot` experience (gh-copilot extension)** is closer to “prompt → suggestion → optional execution,” with explicit prompts to execute and confirm. It’s notably not a streaming transcript interface; it’s an interactive prompt flow that ends in an “execute command?” confirmation. citeturn7view1

**Aider** stays closer to a classic inline REPL rather than a full-screen TUI, teaching a different lesson: conversational flow can remain “native” if you minimize persistent chrome and invest in great diffs, history, and commands. It has extensive slash commands for conversation control (`/diff`, `/undo`, `/run`, `/test`, `/save`, etc.) and supports opening an external editor to draft prompts (`/editor`)—a pragmatic terminal-native solution to long messages. citeturn10view0 It supports streaming by default (`--stream`), and it has explicit fallbacks for less capable terminals (for example, disabling “pretty” output and falling back to simpler prompts in some environments). citeturn11view1turn10view2

**Cursor Agent CLI** is optimized for automation and integration, which shows up as “output contract” documentation: one format aggregates deltas into a single line per assistant message (messages between tool calls), while a streaming JSON format is positioned for message-level progress tracking; optional flags enable “partial output” as individual deltas. citeturn15search0turn15search2turn15search12 This is a strong pattern to emulate when you want both a crafted TUI and a robust non-TTY surface.

**Warp’s AI integration** isn’t a traditional CLI: it’s a terminal application that “productizes” conversational help as *contextual actions on terminal blocks*. It highlights an important pattern for your design: **grouping input+output into navigable blocks, and attaching AI actions (explain error, generate command) to those blocks**. citeturn22view0turn22view1 It explicitly calls out “Blocks” as a core navigation primitive. citeturn22view0

**Open Interpreter** demonstrates the “execution-first” agent conversation: it streams model messages, code, and system outputs to the terminal as Markdown, and it makes “approve before executing” a core guardrail (with opt-out flags). citeturn12view2turn12view0

**Sourcegraph’s Cody CLI** (as described in the VS Code v1.16 release note) is explicitly framed as “trigger chat from the command line” and is “only intended for human interactive usage,” which suggests a lightweight, inline interaction rather than a heavy conversational TUI. citeturn24view1

Best-in-class takeaway for streaming: **Codex CLI is the clearest “full transcript as UI,” while Claude Code is the clearest “terminal OS” with pickers, task list, and session tooling.** citeturn13view1turn5view0turn6view1

Anti-patterns seen in the wild: “silent running” (no output during a hang or during long tool execution) is repeatedly called out by users of Cursor Agent’s headless/print modes—your instinct to add connection health and progress is aligned with real pain. citeturn15search23turn15search24

## Conversational TUI design principles emerging from real tools

A conversational TUI is not “chat UI in a terminal” so much as **a logbook with agency**: it must preserve the readability of a transcript while handling interruptions, approvals, and tool bursts without losing the user. Codex and Claude Code offer concrete patterns that feel stable in daily use: structured turns, explicit tools/transcript items, and dedicated UIs (picker, diff viewer) when the abstraction needs more space. citeturn13view1turn5view0turn6view1

**Progressive disclosure in tool output** has three recurring heuristics:

First, show *summaries by default*, but make detail easy and immediate. Codex frames tool usage as transcript items and leans on the transcript as a stable audit trail. citeturn13view1turn13view3 Claude Code reinforces this by offering “verbose output” toggles for deeper tool usage details without forcing verbosity always-on. citeturn5view0

Second, only “expand” by default when something is wrong. Aider’s `/test` command (run a shell command and only add output to chat on non-zero exit) is an explicit expression of that heuristic. citeturn10view0

Third, put diffs in a dedicated affordance rather than dumping them inline every time. Claude Code’s `/diff` viewer and Codex’s syntax-highlighted diffs reflect this “separate the review surface from the narrative surface” approach. citeturn5view0turn13view3

**Visual hierarchy** tends to be built from a very small vocabulary:

A single “assistant voice” style for narrative text, plus visually distinct tool events (often with icons/labels), plus system/status messages in a quieter palette. Claude Code exposes a theme picker (including ANSI themes) and has explicit commands for statusline customization, indicating an intentional separation between “content” and “chrome.” citeturn5view0turn18search9 Codex similarly treats theme choice as a first-class concern via `/theme`. citeturn13view3

**Streaming granularity** varies, but the best tools expose an explicit engineering stance:

*Chunked streaming with optional partial deltas* is increasingly common. Cursor explicitly documents formats that either aggregate deltas into coherent message lines or emit incremental deltas for stream processing. citeturn15search0turn15search2turn15search12 Claude Code similarly gates “partial streaming events” behind flags for stream-json output. citeturn17view2 This matters because “character-by-character” streaming often feels jittery and makes selection/scroll stability harder; chunked streaming makes UI smoother during bursts.

**“Agent is thinking” indicators** are most effective when they are not “just a spinner,” but part of a stable state model:

Copilot CLI refers to a “Thinking” state and supports `Esc` to stop while thinking, which implies users need both the indicator and the control path tightly coupled. citeturn8view0 Claude Code complements “thinking” with task lists and background tasks, which changes the mental model from “spinner” to “work queue.” citeturn5view0

Best-in-class takeaway for conversational TUI: **make the transcript the stable backbone, and treat “specialized views” (diff, picker, status/context) as temporary lenses rather than permanent panes.** citeturn5view0turn13view1turn6view1

Anti-pattern: conflating “more data” with “more trust.” Claude Code’s own docs warn that bash wildcard permission patterns are fragile and recommend higher-level controls (deny risky network tools; prefer WebFetch with domain rules; use hooks)—a direct example of mature thinking about what to surface vs what to abstract. citeturn16view0

## Approval and human-in-the-loop patterns in terminal agents

Across tools, approvals are evolving from “Y/n prompts” into **policy systems** that answer: *what is the agent allowed to do, where, and for how long?* Claude Code, Copilot CLI, and Codex CLI each represent a distinct approach.

**Claude Code** uses a tiered model and treats “approval persistence” as part of the UX contract:

Its permissions doc describes three tiers: read-only operations require no approval; bash commands require approval with “don’t ask again” behavior scoped *per project directory and command*; file modification approvals last until session end. citeturn16view0 It also provides permission rules (`allow/ask/deny`) and multiple permission modes (`default`, `acceptEdits`, `plan`, `dontAsk`, `bypassPermissions`). citeturn16view0turn4view2 Importantly for your “dangerous tools” channel: it explicitly warns that bypassing permissions can grant subagents autonomous system access, and that subagents inherit bypass modes. citeturn4view2

**Copilot CLI** makes approval prompts readable and offers a “session-scoped remember” affordance at the exact moment of friction:

When Copilot wants to use a tool, it offers: `Yes` (approve once), `Yes, and approve TOOL for the rest of the running session` (session-scoped allow), or `No, and tell Copilot what to do differently (Esc)` (deny + immediate redirection). citeturn8view0turn9view2 It then extends this into CLI flags for automation: `--allow-all-tools`, `--allow-tool`, `--deny-tool`, with patterned syntax like `shell(rm)` or `shell(git push)` to constrain command families. citeturn9view2turn9view1 It also gates usage by directory trust, prompting users to trust the current directory (session-only vs “remember this folder”), and warns that scoping is heuristic and not guaranteed. citeturn8view0turn9view2 This “trust directory” pattern is a practical answer to “approval fatigue”: reduce prompts by shrinking the risk surface (trusted roots) rather than auto-approving everything.

**Codex CLI** frames approval in both a human-facing and a systems-facing way:

It defines modes (Auto, Read-only, Full Access) and emphasizes that even Auto asks before touching outside the working directory or using network. citeturn13view1 In the CLI reference, it exposes flags like `--ask-for-approval` with enumerated policies (`untrusted | on-request | never`) and explicit “danger” switches (`--yolo`, `--dangerously-bypass-approvals-and-sandbox`). citeturn13view2turn13view1 It pairs approvals with sandbox policies (`read-only | workspace-write | danger-full-access`), which is a strong “defense-in-depth” stance: approvals are not the only safety net. citeturn13view2

**Open Interpreter** is the clearest example of “approval as last line before execution”:

It explicitly lists “requiring confirmation before code is run” as a primary safety mechanism and provides `--auto-run` as an opt-out, while also offering safe mode (code scanning) and sandboxed execution options (Docker, E2B). citeturn12view0turn12view1

**Cursor Agent CLI** documents a straightforward approve/reject prompt for terminal commands (`y` to approve, `n` to reject). citeturn15search9turn15search1

Best-in-class approval UX: **Copilot CLI’s “No, and tell Copilot what to do differently” is a particularly good “denial without dead-end,” because it keeps flow while preserving user control.** citeturn8view0

Anti-pattern to avoid: offering “YOLO”/full bypass without relentless signaling. Codex and Claude Code both ship such modes, but both surround them with explicit warnings and recommend isolated environments; your UI should similarly make “danger modes” visually unmistakable and difficult to mis-enter. citeturn13view2turn16view0turn4view2

## Session resume, pending approvals, and re-attachment

Session persistence is increasingly a differentiator for “daily driver” agent CLIs, and the most mature tools treat it as more than “save transcript.” They add **session navigation**, **recovery**, and **attention routing**.

**Claude Code** has the most explicit “session UX stack” among the tools reviewed:

It supports resuming sessions (`--continue` for most recent in directory; `--resume` for picker or by name/ID). citeturn6view3turn17view2 The session picker has keyboard shortcuts for preview, rename, filtering, and scoping to repo/branch contexts. citeturn6view1 Beyond transcript, it provides *checkpointing*: it tracks file edits and can rewind code and/or conversation from an interactive menu, with options like “restore,” “summarize from here,” and “fork.” citeturn5view1turn5view0 Checkpoints persist across sessions and are cleaned up after a retention period (30 days, configurable). citeturn5view1 This matters directly for your “detach/reattach” patterns: it’s not enough to re-render state; users need a way to *undo* or *jump*.

Claude Code also directly addresses “the agent needs me” via notifications: a `Notification` hook event can fire when Claude is waiting for permission, idle and ready for a new prompt, or completing auth, with matchers like `permission_prompt` and `idle_prompt`. citeturn6view0 This is a strong pattern for your “approval prompts can get lost on resume” issue: **treat “pending approval” as a routing state, not just a message in the log.**

**Copilot CLI** also supports resuming sessions (`--resume`, `/resume`, `--continue`) and explicitly frames resume as “pick up right where you left off, with saved context,” including bridging work started in a remote “coding agent session” back into local context. citeturn8view0

**Codex CLI** suggests a complementary approach: rather than “detach from a local run,” it supports “cloud tasks” and provides an interactive picker (`codex cloud`) to browse tasks and apply changes locally. citeturn13view1 This is effectively “reattach later” but shifted from local process management to task management.

**Aider** uses a lighter-weight persistence model: chat history can be stored in files and restored (`--restore-chat-history`), with input history stored separately. citeturn11view1turn10view0 That pattern is easier to implement than full “session objects,” and it works well for teams that value transparency and greppability.

Best-in-class resume UX: **Claude Code’s session picker + checkpointing is the strongest concrete reference for “reattach + recover,” especially under long, multi-step tasks.** citeturn6view1turn5view1

Anti-pattern: “resume without a highlighted attention state.” Tools that treat “approval needed” as a line in the transcript risk the exact bug you described (approval prompt lost in scroll). Claude Code’s notification hooks suggest a better abstraction: “waiting for permission” as a first-class lifecycle state. citeturn6view0

## Alt-screen TUI vs inline rendering and non-TTY fallbacks

There is no universal winner between alt-screen and inline, but the market is gravitating toward **hybrid capability**: a “crafted” interactive UI for TTYs and a structured, automatable stream for non-TTY outputs.

**Codex CLI** is the clearest example of committing to alt-screen while still respecting escape hatches:

It launches “full-screen terminal UI” for interactive mode, but (a) supports non-interactive runs that stream the response and exit, and (b) exposes a `--no-alt-screen` flag to disable alternate screen mode. citeturn13view1turn13view2 It also supports “exec” scripting and JSON output (`codex exec --json` mentioned in docs as an output surface for events like web_search). citeturn13view1turn13view3

**Claude Code** is a useful cautionary tale because its TUI rendering strategy appears to have evolved and drawn tradeoffs:

In mid-2025, users reported the CLI clearing terminal scrollback in certain situations (resize, `/clear`, switching views) and suggested using alternate screen to avoid destroying scrollback. citeturn19view0 By early 2026, users reported behaviors consistent with terminal mode/rendering regressions in certain emulators (for example, rendering at row 0 and not restoring terminal state in KDE Konsole). citeturn19view2 By Feb 2026, at least some users reported that “TUI mode” uses the alternate screen buffer and therefore bypasses the terminal’s scrollback, making older messages inaccessible. citeturn19view1 Read together, these reflect the fundamental tradeoff: alt-screen prevents scrollback loss/flicker but can create “history access” and terminal-integration pain if virtual scrolling isn’t robust.

**Cursor Agent CLI** shows the automation-first route: provide explicit output formats. It documents stream-json as a progress tracking surface and supports partial streaming for deltas, which naturally serves non-TTY use cases. citeturn15search2turn15search12

**Copilot CLI** explicitly supports both interactive and programmatic interfaces: interactive sessions for back-and-forth, and `-p/--prompt` for one-off usage, with token-based auth via environment variables recommended for CI/non-interactive environments. citeturn9view1turn7view2

**Aider** similarly acknowledges terminal capability diversity via flags like `--pretty/--no-pretty` and notes fallbacks to simpler input methods in less capable environments. citeturn11view1turn10view2

Best-in-class pattern: **the “two-lane” design—interactive TUI plus structured stream output—is the most robust and aligns directly with your need for graceful non-TTY fallback.** Codex CLI (`--no-alt-screen`, non-interactive runs) and Cursor’s format contract are strong references here. citeturn13view2turn13view1turn15search0turn15search2

Anti-pattern: “alt-screen without scrollback replacement.” Claude Code user reports show that once you bypass native terminal scrollback, you must implement virtualized scrolling well—or users lose critical context. citeturn19view1

## What makes a CLI feel crafted rather than generic

The “crafted” feeling emerges from **discipline and state clarity**, not from maximal UI features. The tools above suggest several concrete, borrowable practices.

**State is explicit and queryable.** Claude Code makes version/account/connectivity status a dedicated surface (`/status` opens a Status tab), and it provides `/doctor` for diagnosing installation. citeturn5view0 This is directly relevant to your “leaking gRPC internals” and “no connection health monitoring” issues: a crafted tool gives users a predictable place to look, rather than dumping low-level errors into the transcript.

**Attention routing is intentional.** Claude Code’s notification hook events (“permission prompt,” “idle prompt,” “auth success”) emphasize that in long-running tasks, the user’s attention is the scarce resource; the agent should request it sparingly but unmistakably. citeturn6view0 Aider’s optional terminal bell or external notification command is a similar pattern. citeturn11view3

**The UI favors scanning over decoration.** Codex emphasizes syntax highlighting for code blocks/diffs and a theme system; Claude Code exposes a theme picker including ANSI themes. citeturn13view3turn5view0 Both imply a design stance: readability and terminal compatibility are first-order concerns, not afterthoughts.

**“Polish” often means fewer surprises in terminal behavior.** Claude Code issues around scrollback clearing and terminal state restoration show how quickly trust erodes when the tool disrupts basic terminal expectations. citeturn19view0turn19view2 This aligns with your instinct that “functional but AI-generated” is often really “no sharp edges sanded down.”

**Micro-interactions that matter in terminals are mostly about safety and recovery.** Claude Code supports “kill all background agents” with a double-press confirm (`Ctrl+F`, “press twice within 3 seconds”)—a small but meaningful safety affordance. citeturn5view0 Aider’s `--yes-always` is the opposite: powerful, but it underscores why “fast paths” must be explicit and opt-in. citeturn11view0

A useful open-source example of “craft as resilience” is the oh-my-pi agent UI, which explicitly advertises “emergency terminal restore” crash handlers and “scrollback preservation” behaviors—small touches that prevent terminal corruption in failure states. citeturn15search16

Best-in-class “crafted” benchmark: **Warp’s “Blocks” concept shows how much perceived quality can come from navigation primitives and interaction design, even without a full-screen ASCII UI.** citeturn22view0turn22view1

Anti-pattern: “silent hangs” and “no intermediate progress.” Cursor Agent CLI users complaining about “sits there saying nothing” or headless modes hanging with no output illustrate exactly why your TUI must have heartbeat/progress semantics and why your stream should include explicit lifecycle events. citeturn15search24turn15search23

## Visualizing sub-agents and nested execution

Sub-agents are becoming standard, but visualization is not. The most actionable patterns come from tools that treat delegation as part of permissions and as part of transcript structure.

**Claude Code + Claude Agent SDK** highlight a critical security insight: subagents inherit certain permission modes (notably bypass modes) and may have different prompts/constraints; therefore, delegation must be visible and permission-aware. citeturn4view2turn16view0 Claude Code’s permission system even includes explicit rules for controlling which subagents can be used (`Agent(AgentName)` deny rules). citeturn16view0 That is an important UI implication: if subagents exist, users need to *see* which agent is acting and under what permission context.

**Copilot CLI** explicitly describes “custom agents” and states that the model may delegate work to a subsidiary subagent process using a specialized agent profile to keep the main conversation focused. citeturn8view0 It also distinguishes a “Task” agent that executes tests/builds and provides “brief summaries on success and full output on failure,” which is essentially progressive disclosure applied at the subagent boundary. citeturn8view0

**Codex CLI** advertises experimental multi-agent collaboration as a feature and reinforces the “transcript as audit trail” approach: each run of workflows like code review shows up as its own turn so you can compare results across runs. citeturn13view0turn13view1

**Cursor** positions parallel agents as a product capability, including the ability to run multiple agents in parallel “in the terminal or remotely,” and it warns that the CLI can read/modify/delete files and execute commands you approve—so parallelism increases the importance of clear, collapsible per-agent logs. citeturn14view3turn15search1

Best-in-class sub-agent control: **Claude Code’s explicit permission rules for subagents (and the Agent SDK’s warning about inherited bypass permissions) provide the strongest “policy + UI” foundation.** citeturn16view0turn4view2

Anti-pattern: delegation that is invisible or permission-ambiguous. The moment subagents exist, “one approval prompt” can silently authorize more than the user believes. Claude’s docs explicitly warn about this inheritance risk. citeturn4view2
