# Session Notes: 2026-03-03 (Session 8) — Phase 2.3: Retry on Approval Submission Failure

## Decisions Made

- **Pure functions over dependency injection**: `retryWithBackoff` and `isRetryableSubmitError` are independently testable without gRPC mocks. No structural changes to `streamToEventsConfig`.
- **Interface type assertion for Unwrap()**: Used `e.(interface{ Unwrap() error })` instead of importing standard `"errors"` to avoid alias conflict with existing `github.com/pkg/errors` import.
- **Non-gRPC errors default to retryable**: Raw network/io errors lack gRPC status codes but are typically transient. Conservative default favors retry over silent failure.
- **3 attempts with 1s/2s backoff**: Total worst-case 3s wait. Balances resilience (survives brief network blips) against user experience (doesn't block for minutes on persistent failures).

## Key Code Changes

- **`run_stream_events.go`** (modified): Added `approvalRetryMaxAttempts` (3) and `approvalRetryBaseDelay` (1s) constants. Added `isRetryableSubmitError` and `retryWithBackoff`. Modified `emitAndWaitApproval` to wrap submission in retry loop with improved error message.
- **`run_stream_events_test.go`** (modified): Added 13 tests — 7 for `isRetryableSubmitError` (retryable codes, non-retryable codes, wrapped errors, non-gRPC errors, IO errors, nil) and 6 for `retryWithBackoff` (first-attempt success, retry-then-success, exhaustion, non-retryable bail-out, context cancellation during backoff, pre-cancelled context).

## Learnings

- `status.FromError(wrappedErr)` only checks the outermost error for `GRPCStatus()` — must walk the chain manually for wrapped errors (consistent with Phase 2.1's `extractGRPCStatus` discovery)
- gRPC returns `codes.Canceled` when parent context is cancelled during an RPC, and `codes.DeadlineExceeded` when the per-call timeout expires — the retry loop's context-aware sleep naturally handles both cases correctly
- `retryWithBackoff`'s generic `func() error` signature makes it reusable for other retry needs without importing approval-specific types
