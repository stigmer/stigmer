# Session Notes: 2026-03-03 (Session 7) — Phase 2.2: Two-Lane Output Design

## Accomplishments

- Completed Phase 2.2: Two-Lane Output Design — the **second Phase 2 (High) item**
- Implemented three output modes for agent execution: Interactive TUI (default), Inline streaming, and JSON (NDJSON)
- Auto-detection of non-TTY / `TERM=dumb` environments to fall back from TUI to inline streaming
- Correct stdout/stderr separation in inline and JSON modes (subsumes Phase 3.1 for these paths)
- Added `--json` and `--no-tui` flags to `run` and `draft` commands
- Disabled follow-up / conversational continuation in non-interactive modes
- Wrote 33 new unit tests — all passing alongside the full existing suite

## Decisions Made

- **`--json` (boolean) over `--output json` (enum)**: Avoids collision with `draft --output` (directory path flag)
- **`--no-tui` naming**: More user-friendly than `--no-alt-screen` or `--plain`
- **New renderers instead of reusing `messageStreamRenderer`**: Different input types (proto vs events) make reuse impractical
- **stdout/stderr discipline baked in immediately**: No point deferring to Phase 3.1 since inline/JSON are fresh code
- **Follow-up disabled in non-interactive modes**: Scripting/pipe contexts should run to completion and exit
