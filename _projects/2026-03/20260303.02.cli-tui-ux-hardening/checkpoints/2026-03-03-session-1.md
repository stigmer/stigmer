## Decisions Made

- **Stream path, not snapshot path**: The initial plan targeted
  `run_stream_snapshot.go`. During architecture review, discovered that the
  snapshot path only processes terminal executions and lacks gRPC plumbing for
  approval submission. Emitting `ApprovalNeededEvent` there would deadlock.
  Redirected the fix to `run_stream_events.go` where live stream + approval
  response channels exist. User agreed with this change.
- **Defense-in-depth over replacement**: Rather than replacing the
  `pending_approvals` primary path, the fix adds a fallback that only activates
  when `pending_approvals` is empty AND phase is `WAITING_FOR_APPROVAL`. This
  preserves backward compatibility.
- **Multi-result scan**: `findAllUnpromptedApprovals` returns all matches (not
  just the first) to handle edge cases where multiple tools are pending approval
  simultaneously (e.g., parallel sub-agents).

## Learnings

- The backend's `Subscribe` handler reads from MongoDB for the initial snapshot
  but publishes events to Redis. Write-ordering between these two stores can
  cause `pending_approvals` to be empty in the first update even when the
  execution is in `WAITING_FOR_APPROVAL` phase.
- The `>` offset in Redis stream means previously published messages are not
  replayed on re-attach — the client only sees messages published after the
  subscription starts.
