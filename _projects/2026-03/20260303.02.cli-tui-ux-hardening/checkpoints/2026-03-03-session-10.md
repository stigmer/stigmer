## Phase 2.5: stigmer doctor Diagnostic Command

### Accomplishments

- Implemented `stigmer doctor` as a self-service diagnostic command under the config group
- Seven checks in dependency order: config, server (gRPC + Ping, 5s timeout), auth, org, agents (Search API when conn+org), MCP health (explicit skip), terminal (TTY, TERM, dimensions, NO_COLOR)
- Added `doctor.go`, `doctor_checks.go`, `doctor_checks_runtime.go`, `doctor_test.go`; registered command in root.go; added `backend.Client.Conn()` for checkAgents
- Output via `clioutput.CommandResult` (human/JSON/quiet); exit 0 when no fail, 1 otherwise
- 22 unit tests; all production files under 250 lines
- Created changelog and updated next-task.md

### Decisions Made

- **checkResult as internal abstraction**: Check functions return a value type; `buildDoctorResult` converts to CommandResult. Keeps checks independent of rendering and tests data-only.
- **Split doctor_checks vs doctor_checks_runtime**: Pure checks (config, auth, org, agents, MCP) in one file; server and terminal (OS/network) in runtime file for clarity and line limits.
- **5s server timeout**: Shorter than NewConnection’s 10s for faster diagnostic failure.
- **MCP health always skip**: Honest “not yet implemented” instead of a fake check.
- **Auth reports presence only**: Cloud token validity not verified (addAuthHeader still stub); local reports “not applicable”.
