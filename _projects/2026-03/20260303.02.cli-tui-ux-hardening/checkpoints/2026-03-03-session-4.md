- Added Esc as an alternative cancel trigger in the execution TUI

## Decisions Made

- **Esc reuses existing cancel-confirm flow**: No new model state needed. The `cancelConfirm` bool and `handleCancelConfirmKey` handler are reused exactly as-is.
- **Esc during approval does NOT trigger cancel**: During approval, Esc falls through to `handleNavigationKey` via `handleApprovalKey`'s default case. Cancel is inappropriate when the user is deciding on a tool call.
- **Footer shows `Esc/c cancel`**: Both keys are documented. Esc is listed first as the primary (universally expected) key; `c` is preserved as the legacy binding.
- **Help panel shows `Esc / c`**: Consistent with footer, spaced for readability in the structured help layout.

## Learnings

- The existing key routing in `handleKeyPress` is well-partitioned by state priority. Esc already had meaning in input, cancel-confirm, and help states — the gap was only in the normal running state, making this a clean slot-in.
- The Esc → Esc two-step pattern (enter cancel, then dismiss) emerged naturally from the existing `handleCancelConfirmKey` which already accepts Esc as a dismiss key. No additional logic was needed.
