## Decisions Made

| Decision | Rationale |
|----------|-----------|
| PerRPCCredentials over unary interceptor | `stigmer run` uses server-streaming; interceptors only cover unary RPCs |
| No auto-login on missing auth | Avoid surprising browser launches in CI/CD pipelines |
| Eager token resolution (at NewClient) | Simpler; matches cloud CLI pattern |
| Accept tokenAuth duplication | `auth/whoami.go` and `backend/client.go` each have their own copy — shared package would risk circular deps |
| Auto-init nil CloudBackendConfig | Config may be nil when using only `STIGMER_API_KEY` env var |

## Critical Finding

`grpc.WithUnaryInterceptor` does NOT cover streaming RPCs. This was the original plan's approach but would have left `stigmer run` (agent execution events) unauthenticated in cloud mode. Caught during analysis and fixed before implementation.

## Learnings

- gRPC's `PerRPCCredentials` interface is the correct mechanism for per-call auth that must work across all RPC types
- `RequireTransportSecurity()` can return `false` when TLS is enforced separately at the dial level
