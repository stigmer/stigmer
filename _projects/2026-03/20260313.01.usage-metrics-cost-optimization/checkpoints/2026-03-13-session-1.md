## Decisions Made

- **Same-package file split over sub-packages**: All types in `agentexecution/v1/api.proto` are value objects and child entities of the `AgentExecution` aggregate root. Sub-packages would create circular deps, split generated packages, and violate DDD boundaries. Multiple files in the same package is the correct solution.
- **ModelUsage.input_tokens = non-cached input only**: Follows Anthropic provider convention. Creates 4 disjoint token buckets (input, output, cache_creation, cache_read) for clean cost math. `UsageMetrics.prompt_tokens` (aggregate) stays as total input for backward compat.
- **Usage report RPCs in query.proto**: Data-colocated with AgentExecution, consistent with existing `listBySession` pattern. Avoids cross-package dependencies.
- **ApprovalAction enum moved to enum.proto**: All other package enums already live there. Keeps a single canonical location.

## Learnings

- `buf breaking` with `FILE` mode flags file-level moves as breaking changes. This is by design — it tracks per-file stability. `PACKAGE` mode correctly reports zero breaking changes for same-package file reorganizations.
- Proto allows multiple `.proto` files within the same package and they all compile into a single generated package. This is the idiomatic way to manage large proto packages.
