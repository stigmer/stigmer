# Session Notes: 2026-03-14, Session 12

## Phase 8: Diff-Based Output Optimization — COMPLETED

## Accomplishments

- Audited existing sandbox tools (`read`, `write`, `edit`) and confirmed all required capabilities already exist — `edit` has search-and-replace, `read` supports line ranges, `ToolTruncationMiddleware` is wired
- Enhanced `write` tool docstring in `tool_wrappers.py` to clearly signal full-file overwrite behavior and redirect users toward `edit` for targeted changes
- Enhanced `edit` tool docstring in `tool_wrappers.py` to position it as the preferred modification tool with guidance on minimal `old_text` context selection
- Added "Editing Efficiency" sub-section (~65 words) to `FILESYSTEM_CAPABILITY` in `prompt_enhancement.py` — dual-layer guidance: system prompt + tool descriptions
- Added 2 new tests to `test_prompt_enhancement.py` validating the editing efficiency content
- Bumped `test_prompt_size_reasonable` upper bound from 1500 to 1600 words to accommodate the intentional prompt growth

## Decisions Made

- **Scope narrowing**: Phase 8 originally suggested potential new tool parameters; audit revealed everything was already in place. Scope narrowed to prompt engineering only — the right call.
- **Guidance placement**: Embedded in existing `FILESYSTEM_CAPABILITY` section rather than creating a new top-level prompt constant — avoids prompt fragmentation.
- **Fast-apply deferred**: Two-model architecture (small model for diffs, large model for planning) deferred to P2 — it's a separate design concern, not a prompt tweak.
- **Prompt budget**: ~65 words (~0.3% of context) is acceptable for the expected token savings from fewer full-file rewrites.

## Key Code Changes

- `backend/libs/python/graphton/src/graphton/core/prompt_enhancement.py`: Added "Editing Efficiency" block to FILESYSTEM_CAPABILITY
- `backend/libs/python/graphton/src/graphton/core/tool_wrappers.py`: Enhanced docstrings for `write` and `edit` tools
- `backend/libs/python/graphton/tests/core/test_prompt_enhancement.py`: 2 new tests + test bound adjustment

## Learnings

- Tool descriptions (docstrings) are the highest-signal channel for influencing LLM tool selection — the model reads these for every tool call decision
- System prompt additions are secondary reinforcement — they provide context but tool descriptions are the action layer
- Phase 8 is fundamentally prompt engineering; impact is probabilistic and needs operational validation (monitoring edit vs write usage patterns in production)

## Open Questions

- How to measure the actual impact? Need to track edit-to-write ratio in production executions before and after this change
- Phase 9 (Smart Context / Selective Inclusion) scope needs planning — skill relevance filtering and tool schema pruning are substantial design problems
