## Accomplishments

### Phase 5: Server Usage Report RPCs — COMPLETED (Go)

Implemented all three Usage Report RPCs in the stigmer OSS Go server:

- **`GetSessionUsageReport`** — Aggregates cost/token data across all executions in a session with per-execution breakdown.
- **`GetAgentUsageReport`** — Aggregates across all sessions for an agent within an optional date range, with per-session summaries and agent name resolution.
- **`GetOrgUsageReport`** — Aggregates across all agents in an organization within a required date range, with top-10 agents by cost, daily cost trend, and per-model breakdown.

- Date range filtering (ISO 8601 string comparison)
- Grouping by session, agent, and date
- Daily cost entries and top-N agent selection
- Organization and agent ID filtering

## Decisions Made

1. **In-memory aggregation for Go (OSS)**: Follows existing codebase pattern — `store.ListResources` + filter/group in memory. Appropriate for local single-user SQLite store.
2. **Agent name resolution from store**: Agent and org report handlers look up the Agent resource from the store to resolve human-readable names. Falls back to agent ID if not found.
3. **Sub-agent cost inclusion**: `executionTotalCost()` sums main agent + all sub-agent usage, matching the proto documentation.
4. **Model breakdown sorted by cost descending**: Most expensive models appear first in reports.
5. **org_id validated via `strings.EqualFold`**: Case-insensitive org matching for robustness.
