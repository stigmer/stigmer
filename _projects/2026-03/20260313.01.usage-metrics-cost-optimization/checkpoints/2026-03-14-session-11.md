## Decisions Made

- **Fail-fast on invalid model_override**: Sub-agent is skipped entirely and an error is logged. Rationale: silent fallback to parent model would hide misconfigurations and lead to unexpectedly high costs — the opposite of what model routing is meant to achieve. User explicitly chose this strategy.
- **Two-step validation**: `ModelRegistry.is_registered(candidate)` then `ModelRegistry.get_by_api_model_id(candidate)`. This accepts both platform-friendly names (e.g. `claude-haiku-4.5`) and raw API model IDs (e.g. `claude-4-5-haiku-20260314`) without requiring the user to know which namespace they're using.
- **No UsageTracker changes needed**: The tracker already resolves model metadata from the actual model name in `on_chat_model_end` events, so per-sub-agent cost attribution is automatically correct regardless of which model was routed.
- **Cost cap conservatively overestimates**: `CostCapMiddleware` uses the parent model's pricing for estimates. When sub-agents use cheaper models, this means the cap fires early (safe direction). Accepted as-is.

## Learnings

- DeepAgents' `SubAgent` TypedDict already supports `model: NotRequired[str | BaseChatModel]` — the non-HITL path works out-of-the-box with just the transformer change
- The HITL path requires explicit resolution because `compile_subagent_with_proxy()` takes a `BaseChatModel` instance, not a string
- `parse_model_string()` handles all the complexity of provider detection, Anthropic thinking config, and cache control — reusing it for sub-agents keeps behavior consistent with parent model instantiation
- MagicMock's automatic attribute generation caused all existing tests to break initially — any `if sub_agent.model_override:` check on a MagicMock returns truthy. Required explicit `sub_agent.model_override = ""` on all mock fixtures.
