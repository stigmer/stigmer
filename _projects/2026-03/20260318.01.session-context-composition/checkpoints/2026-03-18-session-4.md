## Decisions Made

- **Unified popover pattern** over inline expansion: all three context types (workspace, MCP servers, skills) use the same toolbar-trigger + popover + chip pattern for consistency (Jakob's Law) and scalability
- **Chips inside the card** between textarea and toolbar: provides immediate visibility, direct manipulation, and grows naturally with selection count
- **Always show all chips** in v1: no collapsing or "+N more" logic — simplicity over premature optimization
- **Implicit picker enablement**: presence of `onChange` callbacks enables pickers, avoiding extra boolean props
- **Internal `_useResourceSearch`**: prefixed with underscore, not exported — avoids locking public API to implementation details while enabling code reuse
- **`align="start"` not `alignment="start"`**: discovered `@base-ui/react/popover` uses `align` prop on `Positioner`, fixed type error during build verification

## Learnings

- `@base-ui/react/popover` `Positioner` uses `align` (not `alignment`) and `sideOffset` for positioning — always check `.d.ts` files for headless component prop names rather than guessing
- The existing `WorkspaceEditor` component worked as-is inside a popover without any refactoring — the abstraction was clean enough to move from inline to floating context seamlessly
