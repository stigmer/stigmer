## Decisions Made

- **Mid-conversation MCP/skill changes**: Allowed. Follows the same pattern as workspace entries — `sendFollowUp` can modify all three session-level collections.
- **Options-object refactor**: Breaking change to `sendFollowUp` approved. Positional args were already unwieldy at 3 optional params; extensibility demands a clean interface.
- **Override semantics in `buildUpdateInput`**: Explicitly provided fields replace session values; omitted fields are preserved by converting proto back to input format. This is consistent with the update RPC's replace semantics.

## Learnings

- The `buildUpdateInput` function already preserved MCP/skill fields when updating workspace, but only from the session proto (no external overrides). Adding override support required extracting the proto-to-input conversions into standalone helpers.
- The `SessionComposer` unification (from a prior session) meant T01.6 scope expanded to cover the update path, not just creation — a good catch from the project context.
