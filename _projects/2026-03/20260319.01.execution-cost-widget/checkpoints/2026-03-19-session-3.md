## Decisions Made

### Duration metrics excluded from v1
The component is `ExecutionCostSummary` — its job is cost and resource consumption, not timing. Duration fields (`totalDurationMs`, `llmDurationMs`, `toolDurationMs`) belong in a future `ExecutionTimingBreakdown` component. Additionally, `total_duration_ms` is derived from `(completed_at - started_at)` and may not be meaningfully populated during streaming.

### Flat layout, no expand/collapse
Information density for power users over interactive complexity. The sidebar widget shows at most 7-8 lines. Adding expand/collapse state increases component complexity and creates an interaction pattern platform builders would need to override.

### Sub-agent display: aggregated total with annotation
When `hasSubAgentUsage` is true, show "Includes N sub-agents" annotation. No per-sub-agent cost breakdown in v1 — the hook returns aggregated totals, and breaking it down would require reaching around the hook abstraction.

### Model breakdown: conditional inline
- Single model (common case): model name and provider inline
- Multiple models: compact per-model line with model name and cost, displayed as an accessible list

### Number formatting
- Cost: `$X.XXXX` for < $1, `$X.XX` for >= $1, `$0.00` for zero
- Tokens: comma-separated integers via `Intl.NumberFormat("en-US")` — power users want precision

### No animation libraries
The "alive during streaming" feel comes from numbers naturally changing on every streaming update plus `tabular-nums` preventing layout shift. No CSS animation or spring physics — embeddability liability.

### Formatting utilities: internal to start
`formatCost()` and `formatTokenCount()` are exported from the file for direct testability but NOT re-exported from barrel `index.ts`. Keeps public API surface minimal. Can be promoted to barrel exports later following the `formatDuration` precedent.

## Learnings

- `@testing-library/react` with Vitest (without `globals: true`) requires explicit `afterEach(cleanup)` in component test files. The `useExecutionUsage` tests using `renderHook` didn't surface this because `renderHook` doesn't accumulate DOM elements the same way.
- The `create()` function from `@bufbuild/protobuf` accepts repeated message fields (like `modelBreakdown`) in its init parameter — `ModelUsage[]` instances work directly.
- Pre-existing type errors exist in `useExecutionUsage.test.tsx` where the `makeUsage` helper's narrow type definition doesn't include `modelBreakdown` or `llmCalls` fields, yet the tests use them successfully at runtime.
