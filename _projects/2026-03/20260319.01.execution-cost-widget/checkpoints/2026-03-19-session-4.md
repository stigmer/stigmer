## Decisions Made

### Separate cards, not merged
`ExecutionProgress` (lifecycle phases) and `ExecutionCostSummary` (cost/tokens) are semantically distinct regions. Separate cards provide visual separation, preserve each component's `role="region"` + `aria-label` semantics, and leverage the sidebar's `flex-col gap-3` layout. Merging would conflate independent concerns.

### Progress above, cost below
During active streaming, "what is happening" (progress) is the primary concern; "how much is it costing" (cost) is secondary. This follows progressive disclosure: status first, metrics second.

### Accepted brief empty card on initial stream
When an execution first starts and usage data hasn't arrived yet, `ExecutionCostSummary` returns `null` but the wrapping card div still renders briefly as an empty bordered box. Accepted this (Option A) because streaming updates fill it within 1-2 seconds, and the alternatives (component-owned chrome or hook-in-page guard) add complexity not justified by a momentary visual artifact.

### Sidebar aria-label update
Changed from `"Execution progress"` to `"Execution details"` because the sidebar now contains both progress and cost information — the original label no longer accurately described the composite content.
