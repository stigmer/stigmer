## Decisions Made

- **Phase 6 before Phase 5**: Moved enforcement (Cursor rules) ahead of additional standards (Component Standards). Rationale: the standards documents from Phases 1-4 are only valuable if the AI knows about them automatically. Phase 6 turns passive files into active guardrails. Phase 5 can be done any time since it is a standalone file with no downstream blockers.
- **Auto-apply on `site/src/**` edits**: The `website-standards.mdc` rule uses glob patterns `site/src/**/*.{tsx,ts,css}` so it fires on component, page, and style edits — the files where standards violations actually happen.
- **Content Brief process (parallel to Doc Blueprint)**: The `write-website-content.mdc` rule requires a 5-step Content Brief (Page Type → Audience/Funnel → Template Compliance → Copy Brief → Confirmation) before any drafting. This mirrors the Doc Blueprint process in `write-documentation.mdc`.
- **Severity levels in review rule**: Review findings are categorized as Blocker/Major/Minor. Banned phrases, missing required sections, accessibility violations, and performance budget violations are always Blocker severity.

## Key Code Changes

- `.cursor/rules/site/website-standards.mdc`: Auto-apply rule with condensed standards (7 mandates, 9 page types, 8 section types, copy rules with 16 banned phrases, design rules with token references, performance budget hard limits, accessibility checklist, SEO requirements). References all full standards files by path.
- `.cursor/rules/site/write-website-content.mdc`: Action rule defining Content Brief process. Includes page type identification table, audience/funnel audit questions, template compliance check procedure, copy brief structure, implementation guide with file structure conventions, and a pre-submission self-check.
- `.cursor/rules/site/review-website-content.mdc`: Action rule with 34-item quality checklist organized into 7 categories (Content Structure, Copy Quality, Comparison Pages, Design Quality, Performance, Accessibility, SEO). Defines structured review output format with pass/fail table and fix instructions.

## Learnings

- The auto-apply rule (`website-standards.mdc`) must be comprehensive enough to prevent violations but compact enough to not bloat context. The condensed version is ~180 lines vs. the full `website-standards.md` at 568 lines — a 3:1 compression ratio.
- The full JSON files (`content-requirements.json`, `copy-guidelines.json`, `performance-budget.json`) are referenced by path rather than inlined. The AI can read them on demand when needed for specific checks.
- The three rules form a layered enforcement system: auto-apply (passive, fires on every edit) → write action (active, fires when creating a page) → review action (active, fires before merge).
