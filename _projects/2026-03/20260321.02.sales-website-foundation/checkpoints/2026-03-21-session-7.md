## Decisions Made

- **Grounded in actual code**: Every pattern in the document references the existing canonical implementation (e.g., `button.tsx` for `cva` variant system, `motion.tsx` for animation wrappers, `Hero.tsx` for section `aria-labelledby`)
- **Concrete decision boundaries**: Rather than abstract definitions, used observable criteria — "if it owns a scroll-anchor `id` and occupies full viewport width, it is an organism"
- **12 inconsistencies vs 10 in plan**: The component audit surfaced 12 issues instead of the 10 originally estimated. The two additional issues are: MDX components skip site patterns (issue #11) and CodeBlock `sm` uses non-standard font size separate from the arbitrary value issue (issue #12)
- **Audit is non-normative**: Explicitly marked as informational only — existing components are not required to be retroactively compliant, matching the project decision (task plan line 360)

## Key Changes

- `site/standards/component-standards.md`: New file. Structure: 7 sections + quality checklist + appendix audit.
  - Section 1 (Component Taxonomy): atoms, molecules, organisms, pages with decision boundaries
  - Section 2 (Naming Conventions): files, components, props types, variants, internal subcomponents
  - Section 3 (Required Props Interface): className, id, HTML attribute spread, forwardRef/displayName, organism-specific requirements
  - Section 4 (Styling Rules): Tailwind-only, full token inventory from globals.css, cva pattern, cn() merging, no inline styles, dark theme first
  - Section 5 (Animation Rules): variant catalog, stagger containers, transition presets, wrapper components, viewport triggers, GPU-only, reduced motion, new variant process
  - Section 6 (Responsive Requirements): mobile-first, 4 breakpoints, touch targets, code block scrolling, image handling, content max-width
  - Section 7 (Accessibility Requirements): semantic HTML, heading hierarchy, ARIA patterns, keyboard nav, contrast, color independence, alt text, displayName
  - Quality Checklist: 30-item pass/fail checklist across structure, styling, animation, responsive, accessibility
  - Appendix: 12 specific inconsistencies cataloged across 19 existing components

## Learnings

- The codebase exploration revealed a `layout/` directory not mentioned in `website-standards.md` — Header, Footer, and MobileMenu live there rather than in `sections/` or `ui/`. The component standards document acknowledges this as-is rather than prescribing a reorganization.
- The `mdx/` directory (LanguageIcons, Mermaid) follows entirely different patterns from the rest of the site — no `cn()`, no Tailwind in some cases, inline styles. These are documentation-specific components that leaked into the site codebase. Noted in the audit but not targeted for standards since they serve a different purpose.
- The existing component library is already well-structured. Most inconsistencies are minor (missing `className`/`id`, hardcoded colors) rather than architectural. The standards document codifies what already works and closes the gaps.
