## Decisions Made

- **Plain markdown with HTML comments over MDX**: Section and page templates use `<!-- instruction comments -->` instead of the MDX `{/* */}` syntax used in docs templates. Rationale: these are specifications consumed by Cursor rules and reviewers, not actual page source files.
- **Consistent internal structure across all templates**: Section templates follow a 7-part structure (Job, Funnel Stage, Required Elements, Constraints, Copy Guidance, Design Notes, Accessibility, Quality Checklist). Page templates follow an 8-part structure (Page Metadata, Required Metadata, Structured Data, Narrative Arc, Section Sequence, CTA Strategy, Internal Linking Requirements, Quality Checklist).
- **Section templates first, then page templates**: Page templates reference section templates (e.g., homepage.md references `section-hero.md`, `section-features.md`, etc.), so section templates were created first.
- **Page templates ordered by priority tier**: P0/P1 pages (homepage, use-case, comparison, feature, landing) were written first, then P2/P3 (pricing, changelog, blog, community).
- **Page-specific overrides in section references**: Each page template's section sequence includes "Page-specific" guidance that extends the section template with requirements unique to that page type (e.g., the homepage hero requires path-discovery hints for all three personas, while the comparison page hero must name both tools).

## Key Code Changes

- `site/standards/templates/section-hero.md`: Hero section spec — 8-word headline constraint, CTA hierarchy, visual anchor rules (code/terminal/badges only)
- `site/standards/templates/section-features.md`: Features section spec — 3-6 cards, Benefit→Feature→Proof pattern, proof point per card
- `site/standards/templates/section-how-it-works.md`: How It Works spec — 3-5 numbered steps, progressive disclosure, artifact per step
- `site/standards/templates/section-code-showcase.md`: Code Showcase spec — minimal/self-explanatory code, copy button, context label above
- `site/standards/templates/section-comparison.md`: Comparison spec — must acknowledge competitor strengths, "when to use each" required
- `site/standards/templates/section-social-proof.md`: Social Proof spec — auditable metrics only, no vanity numbers, honest early-stage framing
- `site/standards/templates/section-cta-band.md`: CTA Band spec — context-specific headline, "Learn More" prohibited as primary CTA
- `site/standards/templates/section-faq.md`: FAQ spec — real questions in visitor's voice, 3-sentence max, FAQPage JSON-LD required
- `site/standards/templates/homepage.md`: Homepage spec — 5 required sections, code within 2 viewports, all-persona paths
- `site/standards/templates/use-case-page.md`: Use-Case spec — single persona, Problem→Solution→Proof→Action arc, persona-specific CTAs
- `site/standards/templates/comparison-page.md`: Comparison spec — equivalent-depth overviews, fair table, genuine "use alternative" recommendations
- `site/standards/templates/feature-page.md`: Feature spec — benefit-first headline, architecture diagram, runnable code showcase
- `site/standards/templates/landing-page.md`: Landing spec — single message, ≤5 viewports, simplified nav option
- `site/standards/templates/pricing-page.md`: Pricing spec — crystal-clear open-core boundary, genuine OSS tier, parallel CTAs
- `site/standards/templates/changelog-page.md`: Changelog spec — categorized changes (Added/Changed/Fixed/Breaking), migration guides for breaking changes
- `site/standards/templates/blog-page.md`: Blog spec — teach first promote second, max 1 soft CTA, Article/BlogPosting JSON-LD
- `site/standards/templates/community-page.md`: Community spec — contribution paths ordered by commitment level, Code of Conduct required

## Learnings

- All structural data for the templates was already codified in Phases 1-3. No ambiguity or missing information required going back to roles/reminders.
- The forward-reference in `website-standards.md` line 7 (`templates/`) now resolves to a populated directory — no edits to Phase 1 deliverables were needed.
- The blog and changelog page templates diverge structurally from other page types: they do not use a hero section, and the changelog is chronological rather than narrative. The template format accommodates this by defining page-specific section types rather than forcing all pages into the hero→content→CTA mold.
