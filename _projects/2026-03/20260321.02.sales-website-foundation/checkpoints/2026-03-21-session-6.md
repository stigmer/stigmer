## Decisions Made

- **Terminology entries with exceptions are skipped by lint-copy**: Terms like "execute", "invoke", and "trigger" have exceptions for general programming contexts. Since the lint cannot determine context from regex alone, these are left to the `@review-website-content` Cursor rule for human judgment. Only terms without exceptions (e.g., "agent run" → "AgentExecution", "bot" → "Agent") are flagged.
- **Passive voice detection uses an exclusion list, not AST**: Rather than parsing JSX to find string literals, the passive voice checker uses regex with an extensive false-positive exclusion list (75+ entries) for technical state descriptions common in code comments and UI state descriptions (e.g., "is disabled", "is controlled", "are isolated"). The `get + participle` pattern was removed entirely since "Get Started" and "Getting Started" are imperatives, not passive voice.
- **Section detection scoped to sections/ imports only**: The lint-pages script detects section components by scanning only imports from `components/sections/`, not all JSX components. This prevents false positives from layout, UI, and other non-section components.
- **lint-website runs fast lints only**: The composite `lint-website` target runs `lint-copy` + `lint-pages` (no build required). The heavier `lint-performance` is a separate target that depends on `build`. The `check` target runs `lint` + `typecheck` + `lint-website` — all fast checks suitable for pre-commit.
- **Page type mapping uses multi-variant lookup**: `HomePage` → tries "home", "homepage", "home" (compound) against known types. This handles the fact that content-requirements.json uses "homepage" (compound) while the component suffix is "Home" (single word).

## Key Code Changes

- `site/scripts/lint-copy.ts`: Scans site/src/**/*.{tsx,ts} for banned phrases (16), prohibited terminology (entries without exceptions), and passive voice. Reads copy-guidelines.json at runtime. Reports file:line:column with violation details and suggested replacements.
- `site/scripts/lint-pages.ts`: Validates *Page.tsx files against content-requirements.json. Detects page type from component name, checks required sections via section import analysis, checks metadata in route/layout files. Includes SECTION_ALIASES map for Architecture → how-it-works.
- `site/scripts/lint-performance.sh`: Validates build output against performance-budget.json. Checks gzipped JS/CSS bundle sizes, individual image sizes, prohibited formats, font family count. Reads thresholds from JSON via node -e. Gracefully skips bundle checks if no build output exists.
- `site/Makefile`: Added lint-copy, lint-pages, lint-performance, lint-website, check targets.
- `site/package.json`: Added lint:copy, lint:pages, lint:performance, lint:website, check scripts.

## Learnings

- Word-boundary regex matching is effective for banned phrases and terminology but insufficient for context-dependent terms. When a terminology entry has exceptions (like "execute is OK in general programming"), automated linting cannot reliably determine context — human review is necessary.
- The `get + past-participle` pattern is not passive voice (it's imperative/causative), and should not be included in passive voice detection. "Get started", "get configured", "get deployed" are all active constructions.
- Technical codebases have an enormous number of participial state descriptions ("is disabled", "is handled", "is controlled") that are not marketing passive voice. The false-positive exclusion list needs to be comprehensive to avoid noise.
- Page type mapping between component names and JSON keys is not always 1:1 (e.g., "Home" vs "homepage"). A multi-variant lookup strategy handles this gracefully.
