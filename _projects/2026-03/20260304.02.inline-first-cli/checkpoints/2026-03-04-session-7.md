### Decisions Made

- **Count-only for discovery tools**: Discovery is reconnaissance input to the agent, not primary user output. Count provides sufficient scope awareness. Analysed from UX (signal-to-noise), Engineering (format inconsistency across backends), and Architecture (visual density hierarchy) perspectives. User approved.
- **`countResultEntries` separate from `countLines`**: Discovery results need non-empty line counting (differs from file-content counting).
- **Think bypasses `resolveDisplayContent`**: The think tool's `tc.Result` is a meaningless "ok" acknowledgment. Direct extraction from the "thought" argument prevents displaying "ok" when thought is empty.
- **Think header drops `Label(arg)` pattern**: `● Thinking` instead of `● Thinking()`. Thought is a body, not a parameter.
- **Pattern-based vs path-based**: `isPatternBasedLabel` distinguishes Find/Search (glob/regex patterns, not hyperlinked) from List/Delete (file paths, hyperlinked via OSC 8).
- **Switch-on-label routing**: Replaced if-cascade in `RenderCompact` for clarity and extensibility. Default branch handles future "Task" and unknown MCP tools via `RenderWithBadge`.

### Learnings

- `resolveDisplayContent` has a fallback from input content to `tc.Result` that can produce misleading output for tools where the result is a status acknowledgment (like "ok") rather than meaningful content. Each renderer should validate whether this fallback makes sense for its tool category.
- The graduated routing pattern continues to prove its value — zero integration changes needed in `run_stream_inline.go` for Phase 2.4.
