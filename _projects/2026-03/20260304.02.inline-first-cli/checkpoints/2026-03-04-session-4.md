## Decisions Made

- **Consecutive-event grouping over time-based**: Events arrive from a remote gRPC backend. Network latency makes arrival time unreliable for grouping. Consecutive-event ordering is deterministic, testable, and semantically correct.
- **Smart truncation (maxVisible=3, cutoff at 5+)**: Show all files when count <= 4 to avoid the pointless "+ 1 more" line. Truncate to 3 + "… +N more" for 5+.
- **ToolStreamDeltaEvent excluded from flush triggers**: A concurrent streaming tool (shell) sending stream deltas between read completions would break grouping. Since stream deltas produce no visible output, they should not flush the buffer.
- **File paths in normal style within groups**: Path text stands out (normal weight), metadata (line count, error) is dim. Matches the scanability pattern of the individual compact read format.
- **IsReadTool check removed from renderToolRunning**: Reads are intercepted before the switch, so they never reach the render methods. Cleaner separation.

## Learnings

- Pre-switch interception in `handleEvent` creates a clean pattern: silent events (read running, stream deltas) and buffered events (read completed) are handled before the main dispatch. The switch only sees events that produce visible output.
- `r.pendingReads = r.pendingReads[:0]` resets the buffer without deallocating — good for hot paths with frequent read bursts.
