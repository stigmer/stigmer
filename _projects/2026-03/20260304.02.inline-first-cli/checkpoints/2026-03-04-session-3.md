## Decisions Made

- **Graduated `RenderCompact` entry point**: Dispatches to compact format for implemented tools (currently: reads), falls through to `RenderWithBadge` for all others. This avoids a "big bang" migration — each phase adds a branch, and the fallback shrinks until all tools are compact.
- **`ToolRunningEvent` suppression for reads**: Reads complete in <100ms; rendering both running and completed events was redundant noise. The pattern should be evaluated per-tool-type in subsequent phases (e.g., shell commands benefit from the running indicator since they can take seconds).
- **`CompactOptions` as DI struct**: `HyperlinksEnabled` queried once at `renderInline()` init, `WorkingDir` left empty for now. Follows the established pattern of `FileHyperlink(displayPath, absolutePath, enabled bool)` — pure functions, no env var reads.
- **`IsReadTool` via label matching**: Derives from `toolDisplayMap` entry label == "Read", consistent with `IsShellTool`'s `primaryField == "command"` pattern. Auto-extends if new read tool names are added to the map.
- **`buildHyperlinkedPath` as standalone helper**: Extracted to be reusable by Phase 2.2+ compact renderers, not inlined into `renderCompactRead`.
- **Read grouping deferred to Phase 2.1b**: Buffering sequential reads adds state management complexity (flush mechanism, timer or next-non-read detection) that is a different concern from format-level compact rendering.
- **OSC 8 integration concerns confirmed NOT blockers**: Compact output goes to stderr via `statusf`, never through `MeasureColorizedString` or `TrimColorizedString`. The `stripANSI` OSC gap and `ansi.StringWidth()` verification remain deferred.

## Learnings

- The graduated fallback pattern (`RenderCompact` → `RenderWithBadge`) is a good incremental migration strategy for multi-phase UI changes. It keeps the codebase functional at every phase boundary.
- `IsReadTool`/`IsShellTool` via label/field matching on `toolDisplayMap` is more maintainable than hardcoded name lists — new tool aliases auto-extend.
- Test `stripANSI` helper (regex `\x1b\[[0-9;]*m`) in `render_test.go` doesn't strip OSC 8 sequences (`\x1b]`). For compact tests, hyperlink assertions use raw `strings.Contains` on OSC 8 markers, while content assertions use `stripANSI` + `assertContains`. Works cleanly when these concerns are separated.

## Open Questions

- `WorkingDir` for `CompactOptions`: The inline renderer doesn't currently have access to the agent's working directory. Most backend paths are absolute, so this isn't blocking. When `inlineRenderConfig` gains a `WorkingDir` field (perhaps from execution context), it should be wired through.
- Should `ToolRunningEvent` suppression also apply to write/edit tools in Phase 2.2? Writes are also fast, but the user may want to see that a write is about to happen (especially for destructive operations).
