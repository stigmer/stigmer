## Decisions Made

- **Detection function placement**: `HyperlinksEnabled` co-located in `toolrender/hyperlink.go` rather than `display/terminal.go`. Rationale: self-contained feature boundary, avoids unnecessary cross-package coupling, matches `spinner` package's precedent of local TTY detection. Extraction to `display` is trivial if other packages need it later.
- **Pure function design**: `FileHyperlink` takes an explicit `enabled bool` — no env var reads inside the function, per DI coding guidelines. Callers query `HyperlinksEnabled` once at init and thread the boolean through.
- **Generic `Hyperlink` function**: Exposed publicly alongside `FileHyperlink` for future non-file links (HTTP URLs, issue tracker links).
- **NO_COLOR disables hyperlinks**: Conservative interpretation — while NO_COLOR spec targets color codes, OSC 8 is an escape sequence, and users who set NO_COLOR expect clean plain text.
- **ESC+backslash as String Terminator**: Per modern OSC 8 spec, not BEL (`\007`).
- **file:// works for local+cloud**: The CLI always runs locally, so file:// URIs point to local files regardless of where the backend runs. Future cloud-workspace scenarios can set `enabled=false` for graceful degradation.

## Learnings

- OSC 8 uses `\033]` (not CSI `\033[`), so existing ANSI string measurement in `display/colors.go` (`stripANSI`) won't handle hyperlinked strings correctly. This is flagged for Phase 2.1 integration.
- Go's `net/url.URL{Scheme: "file", Path: absPath}` handles percent-encoding of spaces, unicode, and URI-significant characters (`#`, `%`, `?`) correctly.
- Bazel external repo resolution has a pre-existing issue with `com_github_alecthomas_chroma_v2` — `go vet` and `go test` work fine as verification alternatives.
