## Decisions Made

| Decision | Rationale |
|---|---|
| Batch 3 components (not 1, not 8) | These 3 are the bookends of every concept page — opening definition, comparison, closing navigation. Low risk, obvious APIs. Enough for Phase 3 proof. |
| DefinitionBanner: analogy as badge prop | Analogy is metadata about the definition (classifies the concept). Badge creates a scannable pattern. Definition text stands alone without it. |
| ComparisonTable: rows as typed props | Table data is data, not composition. Props give build-time type safety. More AI-friendly than nested JSX children. |
| RelatedDocs: heading outside component | Fumadocs extracts TOC headings from MDX AST at compile time. A heading inside a React component would NOT appear in the sidebar TOC. Hard constraint. |
| `fd-` tokens for structure, Stigmer tokens for accents | Components live inside Fumadocs docs layout. `fd-` tokens ensure visual consistency with Callout/Card. Stigmer `accent`/`primary` for brand identity only. |

## Learnings

- Fumadocs uses `fd-` prefixed Tailwind theme tokens (defined in `fumadocs-ui/css/neutral.css`). These are neutral grays. Stigmer's own tokens are the colorful brand palette. The two coexist and serve different purposes.
- Fumadocs extracts TOC headings from the MDX AST at compile time using remark/rehype plugins. Headings rendered inside React components at runtime do NOT appear in the sidebar TOC — this is a hard constraint that drove the RelatedDocs heading-outside decision.
- `prose-no-margin` is a Fumadocs utility that removes first/last child margins — useful for custom components inside the prose context.
- `not-prose` is needed on custom components to opt out of Fumadocs prose auto-styling (especially tables).
