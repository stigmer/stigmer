# Session 5 — March 22, 2026

## Phase 3: Rewrite what-is-stigmer.mdx with Components

### What was done

Rewrote `docs/concepts/what-is-stigmer.mdx` using all four custom doc components — the first page to use the component framework against real content.

**Component integrations:**

| Section | Before | After |
|---|---|---|
| Intro | Bold paragraph + explanatory paragraph | `<DefinitionBanner analogy="Kubernetes for containers">` — single condensed definition |
| The problem Stigmer solves | Raw markdown (narrative + code + bullets) | `<ProblemStatement>` wrapping all content; H2 stays outside for TOC |
| How it compares | Markdown table (7 rows) | `<ComparisonTable rows={[...]} />` with default labels |
| Further reading | Bullet list of links | `<RelatedDocs links={[...]} />` card grid |
| What Stigmer provides | 5 H3 subsections | Unchanged — plain MDX is appropriate |
| How it works | Mermaid + markdown tables | Unchanged — PropertyTable deferred |
| Getting started | Bash code block | Unchanged — QuickExample deferred |

**Structural cleanup:**
- Removed all `---` horizontal rules — components provide sufficient visual separation

### Design decisions

| Decision | Rationale |
|---|---|
| PropertyTable deferred | Tables vary 2–4 columns across pages. Generic component adds API complexity without clear benefit over Fumadocs-styled markdown tables. |
| Agent-vs-Workflow table stays markdown | ComparisonTable's muted-before/full-after visual treatment misleads when comparing features (neither is "worse"). |
| Structure-only, not content rewrite | Isolates structural validation from content editing. Keeps diff reviewable. |
| Removed `---` horizontal rules | Bordered/shadowed components create sufficient visual breaks. `<hr>` between them is redundant. |
| Banner condensed to one paragraph | DefinitionBanner renders children in `<p>`. Two MDX paragraphs would produce nested `<p>` — invalid HTML. |
