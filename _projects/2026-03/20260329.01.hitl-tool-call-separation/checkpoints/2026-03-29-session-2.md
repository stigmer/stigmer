## Decisions Made

- **Snapshot-then-apply pattern**: Rather than doing a per-field merge, we snapshot the full existing message list before replacement, build an index of approved tool calls, then apply. This is simpler and has clear O(n) complexity.
- **Only preserve UNSPECIFIED → decided**: If an incoming tool call already has a non-UNSPECIFIED `approval_action`, it is left as-is. This is defensive — Python doesn't send non-UNSPECIFIED today, but if it ever does, we respect the sender's intent.
- **Flat index across scopes**: The `tool_call_id` index is global (not scoped to root vs sub-agent). Since tool_call_ids are UUIDs, there is no collision risk, and this naturally handles the case where a tool call might move between scopes (unlikely but safe).

## Learnings

- Go test files in the same package share function names — `makeToolCall` was already defined in `compute_test.go`, so `preserve_test.go` needed a differently-named wrapper (`makeApprovalToolCall`) instead of a redefinition
- Java protobuf immutability means the preserve step must reconstruct entire message lists rather than mutating in place — the `toBuilder()` → `setApprovalAction()` → `build()` pattern is the standard approach
- The preservation must happen after replacement but before `ComputePendingApprovals` to ensure the derived `pending_approvals` field reflects the preserved decisions
