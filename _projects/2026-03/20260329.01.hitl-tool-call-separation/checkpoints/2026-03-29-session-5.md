## Decisions Made

- **Signal behavior**: Always send signal on gate resolution (REJECT or all-decided), regardless of phase. Temporal buffers signals if the workflow hasn't entered the approval loop yet. Accepted rare spurious wake-up (one extra no-op Python invocation in multi-cycle scenarios).
- **Allowed phases**: Only `EXECUTION_IN_PROGRESS` and `EXECUTION_WAITING_FOR_APPROVAL`. Pre-start (`PENDING`, `PAUSED`) and terminal phases remain rejected.
- **Java stale projection fix**: Added tool-call-centric fallback in `handleNotInPendingApprovals` — if a tool call has `TOOL_CALL_WAITING_APPROVAL` status but isn't in `pending_approvals`, allow the approval. This benefits both `IN_PROGRESS` (stale projection) and `WAITING_FOR_APPROVAL` (recomputation lag).
