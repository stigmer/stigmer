## Decisions Made

- **T01 scope = atomic DB write only**: Changing Temporal signal behavior (batching into a single signal) requires coordinated deployment with T03 (workflow changes). T01 is independently deployable.
- **Two-phase pending_approvals (Java)**: The `$set` atomically updates `approvalAction` + `approvalDecidedAt` on the specific tool call. `pendingApprovals` is recomputed via re-read + separate `$set`. Brief staleness of the derived field is acceptable — the next read or broadcast corrects it.
- **TOCTOU guard (Go)**: The modify callback defensively re-checks that the tool call still exists and has `APPROVAL_ACTION_UNSPECIFIED` before writing, catching races between the validation step and the locked update.

## Learnings

- `JsonFormat.printer()` (default, no configuration) produces lowerCamelCase for field names and string names for enums. MongoDB documents follow this convention.
- MongoDB array filters use a dot-separated identifier syntax (`$[msg]`, `$[tc]`) with filter documents that reference the identifier prefix (e.g., `{ "tc.id": toolCallId }`).
- The existing Go `writeMu` mutex serialized writes but not reads — the race window was between an unprotected read and a locked write. `UpdateResource` closes this by holding the lock for the entire cycle.
