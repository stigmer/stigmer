## Decisions Made

- **`ai.stigmer.sdk.gen` over `ai.stigmer.sdk`**: Generated code needs its own directory for safe `rm -rf` during codegen. Hand-written sources (`StigmerClient`, `SearchClient`) live in the parent `ai.stigmer.sdk` package. A flat package would require fragile selective deletion.
- **Go, Python, TypeScript unchanged**: Go's `internal/` is compiler-enforced with a public facade. Python re-exports via `__init__.py`. TypeScript barrel-exports via `index.ts`. Only Java lacked both enforcement and facade.
- **`internal/transport/` stays**: `StigmerChannel` and `ApiKeyInterceptor` are genuinely internal -- users instantiate `StigmerClient` via the builder, never touching transport directly.

## Learnings

- Java has no language-level `internal` enforcement (unlike Go's compiler-enforced `internal/` directory). Package naming is purely convention, so misleading names directly impact user experience.
- Git detected all 46 file moves as renames (98-99% similarity) because only the `package` declaration line changed -- clean history.
- Stale `.class` files in `target/` cause `NoSuchMethodError` at test time when return types change package. Always `mvn clean test` after package moves.
