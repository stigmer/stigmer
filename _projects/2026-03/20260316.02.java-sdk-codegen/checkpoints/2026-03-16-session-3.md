## Decisions Made

1. **Skipped `StigmerClientOptions.java`** — builder on `StigmerClient` is sufficient; separate class adds indirection without benefit. Matches Go SDK's private `clientConfig` pattern.
2. **Skipped handwritten `StigmerException.java` and `ErrorCode.java`** — generated versions in `internal.gen` are already well-designed. Duplication would create import confusion.
3. **API key as required builder constructor param** — `StigmerClient.builder("key")` provides compile-time enforcement that the key is present.
4. **`grpc-netty-shaded` for transport** — shaded variant avoids Netty version conflicts with user dependencies.
5. **Deferred `internal` -> public package rename** to Task 4 when wiring codegen pipeline.
6. **Deferred examples/ and README.md** to Task 5 (Maven Central publishing).

## Learnings

- gRPC-Java's `ClientInterceptor` handles both unary and streaming calls in a single implementation via `SimpleForwardingClientCall` (unlike Go which needs separate unary + stream interceptors).
- `NettyChannelBuilder.useTransportSecurity()` uses the system trust store automatically — no custom `SslContext` needed for default TLS.
- JUnit 5's `junit-jupiter` single dependency pulls in api, params, and engine — simpler than the separate artifact approach.
