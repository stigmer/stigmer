## Decisions Made

- **Individual count hooks over combined hook**: The original plan called for a single `useResourceCount` in `library/` returning all three counts. After architectural analysis, individual hooks were chosen:
  - Follows established pattern (internal shared hook + thin domain wrappers)
  - More composable for platform builders
  - Independent loading/error states per resource type
  - Non-breaking to extend (adding a 4th type is additive)
  - Keeps `library/` module reserved for cross-resource UI components, not data hooks

## Key Code Changes

- `sdk/react/src/search/useResourceCount.ts`: Internal hook using `useState`/`useEffect` pattern. Calls `list()` with `page: { num: 1, size: 1 }` and reads only `totalCount`. Does not store entries — simpler state than `useResourceList`.
- `sdk/react/src/agent/useAgentCount.ts`: Thin wrapper — `useStigmer()` + `useCallback` + delegates to `useResourceCount`. Returns `{ count, isLoading, error, refetch }`.
- `sdk/react/src/skill/useSkillCount.ts`: Same pattern for skills.
- `sdk/react/src/mcp-server/useMcpServerCount.ts`: Same pattern for MCP servers.
- 5 barrel export files updated with new hooks and types.

## Learnings

- `page.size: 0` behavior is unknown — used `size: 1` as safe default. Can optimize later (internal, non-breaking).
- Count hooks accept optional `query` parameter even though the landing page won't use it — enables "3 of 15 match" patterns for platform builders at zero cost.

## Open Questions

- Should `page.size: 0` be tested against the backend? Would eliminate the single wasted entry in count calls.
