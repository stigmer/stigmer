## Decisions Made

- **Range-read optimization in Java R2 store**: Uses S3 `HEAD` to get total size, then `Range`-limited `GET` (`bytes=0-{maxBytes-1}`) when content exceeds the limit. This avoids loading arbitrarily large artifacts into memory — only the requested window is transferred.
- **Duplicated validation step in Java handler**: `ValidateStorageKeyPrefixStep` could not be shared with the existing `AgentExecutionGetArtifactDownloadUrlHandler` due to Java generics constraints on `RequestPipelineStepV2<CustomOperationContextV2<Req, Resp>>`. Duplicated the step as an inner class for self-containment.
- **Consistent content type detection**: Both Go and Java handlers use identical 17-entry extension-to-MIME maps. Go supplements with `mime.TypeByExtension()` fallback; Java uses map-only with `application/octet-stream` default.

## Key Code Changes

## Learnings

- The `ArtifactStorage` interface in Go already had a `Download()` method — no new interface method needed
- The Java `AgentExecutionArtifactR2Store` did NOT have a read method — only `save()` and `getSignedUrl()` existed. Added `get()` with the range-read pattern.
- Pipeline step sharing across handlers with different request/response generic types is not feasible in the current framework without a common request interface or reflection
