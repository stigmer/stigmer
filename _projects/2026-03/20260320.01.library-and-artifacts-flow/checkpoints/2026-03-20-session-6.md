## Key Design Decisions

- **Self-contained card, not content-only**: Unlike `ExecutionCostSummary` (content-only, consumer wraps), `ResourceCountCard` includes its own card chrome because the card surface IS the interaction unit. Splitting content from container would force consumers to wire click, keyboard, focus, and hover states — the "200 lines of glue code" anti-pattern.

- **Polymorphic root element**: Root adapts to provided props:
  - `href` → `<a>` (link semantics: right-click → new tab, Enter to follow)
  - `onClick` only → `<button>` (action semantics: Enter/Space to activate)
  - Neither → `<div>` (static display)
  - Console wires SPA routing via `href + onClick(preventDefault)`

- **Progressive loading**: Icon and label visible immediately; count shows skeleton pulse only when `isLoading && count === undefined`. Existing count stays visible during refresh (no flash).

- **Icons as `ReactNode`**: Consumer provides icons, not baked into the component. Console uses lucide-react; platform builders use their own.
