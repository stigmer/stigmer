## Decisions Made

- **SearchResult-typed, not generic `<T>`**: All three resource types return the same `SearchResult[]` from the Search API. Typing the component to this enables a built-in default row renderer and avoids premature abstraction. Platform builders with different data types would build their own list — `ResourceListView` is a Library domain component, not a generic primitive.

- **Component-managed search debouncing (300ms)**: Raw input state lives inside the component. Parent only receives debounced values via `onSearchChange`. Uses stable callback refs (`useRef` updated on render) so the debounce timer doesn't reset when the parent re-renders with new callback identities.

- **Automatic page reset on filter change**: When debounced search fires or scope changes, the component calls `onPageChange(1)` alongside the filter callback. Prevents the class of bugs where a user is on page 5, changes a filter, and gets empty results.

- **Simple rows for Phase 1**: Confirmed with user that `SearchResult` fields are sufficient (name, org, description, visibility, tags). The wireframe's version numbers and dependency counts are not available in `SearchResult` — deferred to Phase 5.

- **ARIA structure**: `role="list"` only wraps actual list items. Skeleton/error/empty states render as sibling blocks, not as pseudo-listitems. This is semantically correct — a list with zero items during loading is valid, and error/empty states have their own roles (`role="alert"`, `role="status"`).

## Learnings

1. **`SearchResult` data shape is consistent**: All three resource types (agents, skills, MCP servers) go through the same Search API and return identical `SearchResult` projections. This makes a shared component natural — no per-type adaptation needed for rendering.

2. **Stable callback refs for effects**: When an effect uses callbacks from props (like `onSearchChange`) but shouldn't re-run when callback identity changes, the pattern is: `const ref = useRef(callback); ref.current = callback;` — update on every render (no effect), use `ref.current` inside the effect. This avoids the `exhaustive-deps` lint issue while keeping the timer stable.

3. **`ApiResourceKind` and `ApiResourceVisibility` are numeric enums**: Values like `ApiResourceKind.agent = 40`, `ApiResourceVisibility.visibility_public = 2`. First component in the SDK to import runtime enum values (not just types) from `@stigmer/protos` for switch/comparison.

4. **Top-level barrel was already updated**: The `sdk/react/src/index.ts` already had `ResourceListView` exports at HEAD, likely from a parallel session. Only `library/index.ts` needed updating in this commit.
