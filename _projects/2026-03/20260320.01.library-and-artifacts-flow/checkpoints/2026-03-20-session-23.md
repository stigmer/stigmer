## Decisions Made

- **Client-side YAML serialization**: Implemented `serializeAgentYaml` and `serializeMcpServerYaml` as inverse functions to `parseResourceYaml`, avoiding backend API changes. The `yaml` package was already a dependency.
- **Uniform edit pattern**: Agent and McpServer resources are serialized to YAML files, Skills are downloaded as ZIP packages. All three attach to the session composer, and creator agent instructions handle the modification. Output flows through existing Phase 2 artifact detection and apply/push pipeline.
- **`initialAttachments` as SDK prop**: Placed on `SessionComposer` (not Console-only) because platform builders embedding Stigmer need the same programmatic file attachment capability.
- **Interim edit buttons on list pages**: Since Skill and McpServer detail pages don't exist yet, `onItemClick` on list pages navigates to an edit session URL. Agent has a dedicated "Edit" button on its detail page header.
- **No `initialMessage` needed**: Attachment chips visible in the composer + edit-mode placeholder text + agent instructions together provide sufficient context for users to understand the edit flow.

## Learnings

- Proto message construction requires `create(Schema, data)` from `@bufbuild/protobuf`, not plain objects — TypeScript types enforce `$typeName` property.
- `Uint8Array<ArrayBufferLike>` isn't directly assignable to `BlobPart` due to potential `SharedArrayBuffer` backing. Explicit copy to `ArrayBuffer` resolves the type issue.
