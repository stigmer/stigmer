## Decisions Made

- **Explicit per-field converters over generic snake-to-camel recursion**: Chosen because map-type fields (`labels`, `env_spec.data`, `headers`) must preserve their keys. The `env_spec.data` → `envSpec.variables` naming mismatch is handled naturally. Type-safe at compile time.
- **Org override is mandatory**: The `org` parameter to `applyYamlResource()` always overrides `metadata.org` in the YAML. Matches the "Apply to [my-org]" UX intent.
- **No stored result in hook state**: Follows the existing mutation pattern (`useCreateOrganization`, etc.). Components store the result from the returned promise in their own state.
- **Both snake_case and camelCase accepted**: YAML field extraction tries the snake_case proto name first, then the camelCase SDK name as fallback. This makes the converter resilient to either YAML format.
- **Skill push surface elevated to top-level barrel**: `isSkillPackage`, `detectSkillPackage`, `useDetectSkillPackage`, and related types were added to `sdk/react/src/index.ts` — they were previously only in the `library/index.ts` barrel.

## Learnings

- The `AgentInput` and `McpServerInput` SDK types don't have index signatures, so you can't cast them to `Record<string, unknown>` for mutation. Conditional spread (`...optionalField("key", value)`) is the clean pattern for constructing typed objects with optional fields.
- The proto field `env_spec.data` maps to the SDK's `envSpec.variables` — a naming mismatch that must be handled explicitly in any YAML → SDK conversion.
- McpServer proto has `tags` field but `McpServerInput` does not — this field is silently dropped during conversion.
