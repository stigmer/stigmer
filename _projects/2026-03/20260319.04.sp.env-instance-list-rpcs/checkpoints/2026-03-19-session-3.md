## Decisions Made

1. **No secret redaction in Go OSS list handler**: Existing `Get` and `GetByReference` handlers in Go OSS return plaintext secrets (no `RedactSecretValues` step exists anywhere in Go OSS). Adding redaction only to `list` would create an inconsistency. OSS is single-user local — redaction is a Cloud concern handled by the Java `EnvironmentListHandler`.

2. **No pagination in Go OSS**: All existing Go OSS list handlers (`Session.list`, `AgentExecution.list`, `AgentInstance.getByAgent`) ignore pagination and return all results. Followed the same convention for consistency.

3. **ListResources + in-memory filter over FindAllByLabel**: `FindAllByLabel` only supports a single label key-value pair. For multi-label queries, we'd still need in-memory filtering. Using `ListResources` + full in-memory filter is simpler and consistent with all other Go OSS list handlers.
