## Decisions Made

1. **`react-markdown` as regular `dependencies`** — Not peer dep. Tree-shaking via `sideEffects: ["*.css"]` protects hook-only consumers. Simplest DX for styled component consumers.
2. **Inline SVG icons** — Continued established SDK pattern (ModelSelector, WorkspaceEditor). No lucide-react dependency added. Six purpose-built icons across two components.
3. **Tool call summary: honest defaults + pluggable `formatSummary`** — Default never guesses categories ("3 tool calls" not "Ran 2 commands"). Platform builders provide custom formatter when they know their tool names.
4. **Discriminated-union `ThreadItem` type** — Three kinds (`message`, `tool-group`, `phase-badge`) for zero-ambiguity render loop.
5. **`MessageThread` accepts `AgentExecution[]`** — Preserves execution-level context. Flattening is internal. Future SP4 can add execution boundary rendering.
6. **Auto-scroll via `isNearBottomRef`** — Ref-based to avoid re-renders. 80px threshold. `useEffect` on `items` array triggers scroll.
7. **`MARKDOWN_COMPONENTS` as module-level constant** — Object created once, not per-render. Avoids unnecessary react-markdown re-initialization.

- Discriminated-union item types for render loops (ThreadItem with `kind` discriminator)
- Map-based config lookup for enum-to-rendering mappings (PHASE_CONFIG)

- Module-level constant objects for react-markdown `components` prop (avoid per-render allocation)
- Inline SVG icon functions co-located with their consuming component
- `formatSummary` prop pattern for pluggable text formatting in SDK components
