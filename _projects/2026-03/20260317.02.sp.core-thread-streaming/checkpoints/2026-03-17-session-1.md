## Decisions Made

1. **`string | null` parameter type** over plain `string` — Null-means-skip convention for consistent hook API across the SDK. Platform builders may not have IDs on first render.
2. **Full proto return types** — Return `Session` and `AgentExecution` directly, not simplified wrappers. Data hooks exist to expose the full resource to rendering layers.
3. **`fetchKey` counter for `refetch()`** — Chosen over external state tracking for simplicity and testability. Triggers effect re-execution cleanly.
4. **`pageSize: 100` without pagination** — Sessions rarely exceed a few executions. Full cursor-based pagination is premature and can be added later without breaking the return type.
5. **Both hooks under `session/`** — Grouped by consumption context (the session view), not by the underlying resource type.

## Patterns Established

- Data hooks follow the `cancelled` flag pattern from `useGitHubConnection` for stale response suppression
- Error extraction: `err instanceof Error ? err.message : "fallback"` — consistent across all hooks
- Return interfaces use `readonly` fields to prevent accidental mutation by consumers
- Proto request construction: `create(SchemaConstant, { fields })` from `@bufbuild/protobuf`
