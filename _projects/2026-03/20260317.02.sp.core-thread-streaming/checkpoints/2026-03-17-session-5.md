## What Was Built

### `isTerminalPhase()` — Shared SDK Utility

Extracted the `TERMINAL_PHASES` constant (duplicated in 3 files) into a single source of truth:

- **New file**: `sdk/react/src/execution/execution-phases.ts`
- **Public API**: `isTerminalPhase(phase: ExecutionPhase): boolean`
- **Internal**: `TERMINAL_PHASES` Set is unexported — implementation detail
- **Exported**: via `sdk/react/src/execution/index.ts` and `sdk/react/src/index.ts`

### Consumer Updates

| File | Before | After |
|------|--------|-------|
| `useExecutionStream.ts` | Local `TERMINAL_PHASES` + `TERMINAL_PHASES.has()` | `import { isTerminalPhase }` |
| `MessageThread.tsx` | Local `TERMINAL_PHASES` + `TERMINAL_PHASES.has()` | `import { isTerminalPhase }` |
| `SessionPage.tsx` | Local `TERMINAL_PHASES` + `ExecutionPhase` import from protos | `import { isTerminalPhase } from "@stigmer/react"` |

### Layering Improvement

`SessionPage.tsx` no longer imports from `@stigmer/protos` for execution phase logic. It consumes the SDK utility, which is the correct architectural layering: Console -> SDK -> Protos.

## Decisions Made

1. **`isTerminalPhase` in `@stigmer/react`, not `@stigmer/sdk`** — All consumers are React-based. `@stigmer/sdk` is for typed API clients. If Vue/Svelte SDK needs this later, trivial migration.
2. **Function over raw Set** — Function is the public API. Set is implementation detail. Better intellisense, documentation, and encapsulation.
3. **`undefined` check replaces UNSPECIFIED fallback** — In SessionPage, `phase === undefined` is cleaner than `?? ExecutionPhase.EXECUTION_PHASE_UNSPECIFIED`. Eliminates proto import.
