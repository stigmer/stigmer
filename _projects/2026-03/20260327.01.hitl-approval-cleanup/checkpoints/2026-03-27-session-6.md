## Decisions Made

- **Remove both polling AND staleness detection**: User decided to trust the stream entirely. If a Temporal signal fails, the approval stays in `pending_approvals` on subsequent stream snapshots. When the user navigates away and back, `dismissedApprovalIds` (transient React state) resets and the card reappears naturally. Revisit if signal failures surface in production.
- **Keep optimistic dismissal without timestamps**: The pattern of hiding the approval card immediately after submit is still valuable for UX. Removed the timestamp tracking (`Date.now()`) since staleness recovery no longer uses it — `Set<string>` is sufficient.
- **No changes to downstream consumers**: `useExecutionStream`, `useSubmitApproval`, `MessageThread`, and `ApprovalCard` all consume `PendingApproval` fields (`toolCallId`, `toolName`, `message`, etc.) that are unchanged in the proto. Zero ripple.

## Learnings

- The `ApprovalLifecycleState` import was already a compile-breaking issue before T06 — T02 deleted the proto enum but no one had updated the React SDK yet. T06 was partially a "fix the build" task, not just a cleanup.
- The `approvalLoadFailed` state was returned in the implementation but never declared in `UseSessionConversationReturn`. This type drift meant TypeScript wouldn't catch consumers trying to use it (they'd need to cast). Removing it was the right fix.
