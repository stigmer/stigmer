## Decisions Made

- **In-memory index via protobuf reference semantics**: When a ToolCall is appended to `parent_ai.tool_calls` (a protobuf repeated field), protobuf copies the object. But `parent_ai.tool_calls[-1]` gives a reference to that copy inside the message. Storing this reference in `_tool_call_index` enables O(1) lookups and in-place mutation that automatically propagates to the serialized status — no explicit sync needed.
- **Fingerprinting retained for event deduplication**: The master plan initially proposed removing `populate_fingerprints_from_existing_tool_calls`. During investigation, discovered it's still crucial for LangGraph replay deduplication on resume (prevents duplicate tool call entries), even though it's no longer needed for HITL matching. Modified to scan messages instead of deleted.
- **`args_preview` populated at creation time**: Set when the ToolCall is first created in `_handle_tool_start_event`, not computed later.
- **`TestTryEnrichPhase1Entry` deleted entirely**: 6 tests removed since `InterruptCapture` no longer exists.
- **Sub-agent tool call assertions updated**: Tests now check `[tc for m in sub_agent.messages for tc in m.tool_calls]` instead of `sub_agent.tool_calls` (proto field removed in T02).
