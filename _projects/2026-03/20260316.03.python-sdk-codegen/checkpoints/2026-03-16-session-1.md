## Decisions Made
- **Import paths**: Use `from ai.stigmer.agentic...` (not `from stigmer.ai.stigmer...`) — the proto stubs' `pyproject.toml` puts `ai` as a top-level package
- **Keyword escaping**: Python keywords in proto field names (e.g., `as`) are escaped with a trailing underscore (`as_`) in dataclass fields, and `setattr(msg, "as", self.as_)` is used for proto assignment
- **Target naming**: `sdk-client-python` to match the `sdk-client` / `sdk-client-ts` convention
- **Enum defaults**: Enum fields default to `0` (int) since Python SDK represents them as `int`
- **Inline `_to_proto()`**: Conversion methods are generated as instance methods on each `@dataclass`, not in a separate converter module

## Learnings
- Python gRPC stubs use lowerCamelCase method names (e.g., `getByReference`) while the proto definitions use PascalCase — the Python SDK must call stubs with lowerCamelCase
- Proto field names are already snake_case in Python stubs, so no field name conversion is needed for proto assignment (except keyword collisions)
- The `io_pb2` module name appears in both commons and resource-specific packages — import aliasing (`apiresource_io_pb2`) is required for the commons variant
