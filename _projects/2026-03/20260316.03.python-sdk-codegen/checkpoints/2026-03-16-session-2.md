## Decisions Made

- **Transport approach**: `grpc.intercept_channel()` with custom interceptors (not `composite_channel_credentials`). Rationale: works with both secure and insecure channels, matches Go SDK pattern, extensible for future interceptors (logging, retries).
- **No `_options.py`**: Python keyword args on `StigmerClient.__init__()` eliminate the need for Go-style functional options. If config grows complex, an options dataclass can be introduced without breaking the API.
- **No handwritten `errors.py`**: Generated `_gen/_errors.py` already provides everything. TypeScript's extra `ErrorCategory`/`getUserMessage` layer targets browser UI — Python SDK targets backend/scripting.
- **Public API boundary**: `wrap_error` and `GeneratedClient` excluded from `__all__` — internal implementation details users shouldn't depend on.
- **Build backend**: `hatchling` over `poetry-core` — lighter, PEP 621 native, no lockfile.
- **Interceptor scope**: Only `UnaryUnaryClientInterceptor` and `UnaryStreamClientInterceptor` — covers all current RPC patterns (unary for CRUD, server-streaming for `subscribe()`).

## Learnings

- Python gRPC interceptor API requires a `_ClientCallDetails` wrapper class to modify metadata — `grpc.ClientCallDetails` is read-only. This is a well-known pattern in the gRPC Python ecosystem.
- `grpc.intercept_channel()` returns a `_Channel` object that is type-compatible with `grpc.Channel` — generated stubs accept it without issues.
- Python 3.14 is available on the dev machine (Homebrew). The SDK targets 3.11+ which is the same as `stigmer-stubs`.
- `stigmer-stubs` installs `protobuf 6.33.5` and `grpcio 1.78.0` — these are the effective runtime versions.
