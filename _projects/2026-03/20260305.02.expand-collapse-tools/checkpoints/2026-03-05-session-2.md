## Decisions Made

1. **Expanded read groups: show all entries, no file content** — each entry has a hyperlinked path that opens the file when clicked. Showing file content would clutter the expanded view. Expanded mode is a quick, scannable list of everything the agent read.

2. **Read/write/delete identical in both modes** — these tools have no truncation in compact mode, so `RenderExpanded` delegates directly to the corresponding compact renderer. Zero code duplication, zero risk of divergence.

3. **Separate expanded renderers (not parameterized compact)** — considered adding a `maxLines int` parameter to compact renderers, but separate functions are safer: no risk of breaking existing compact behavior, easy to test independently, explicit about mode differences.

4. **Discovery expanded shows individual entries, not count** — compact shows "Found 12 matches"; expanded shows all 12 entries one per line. Empty lines from results are filtered out.

5. **`triggerReCommit` sends `expanded: false` for now** — Phase 1's subject update mechanism always uses compact mode. Phase 3 will thread the renderer's actual expand state.

## Learnings

- The expanded rendering is straightforward because the compact renderers already separate header-building from truncation. The expanded variants reuse headers and only differ in the content display loop (no truncation cap).

- Discovery tools in compact mode show only a count summary ("Found 12 matches"), not truncated lines. The expanded renderer needed a different approach — show actual result entries, filtering blank lines.
