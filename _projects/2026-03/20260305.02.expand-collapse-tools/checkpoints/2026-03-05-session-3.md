## Decisions Made

1. **Full Bubbletea stdin ownership** — removed `tea.WithInput(nil)` so Bubbletea reads `os.Stdin` directly. All keystrokes arrive as `tea.KeyMsg` in `Update()`. This was chosen over a pipe-forwarding approach for its cleaner architecture.

2. **Channel-based inter-goroutine communication** — the model and event loop communicate via typed Go channels (`approvalDecisionCh`, `textInputCh`, `toggleExpandCh`, `cancelCh`). No shared mutable state, no locks.

3. **Legacy fallback retained** — `approvalShowMsg`, `approvalSelectMsg`, and `followUpShowMsg` kept for the `program == nil` path (tests, CI, non-TTY, resumed sessions). New flow gated on `cancelCh != nil`.

4. **Explicit Ctrl+C handling** — raw mode means no OS SIGINT. Three states: idle → cancel via `cancelCh`, approval → `ErrSessionExit` via decision channel, text input → submit empty string.

5. **Header mode indicator in panel title** — `"Stigmer · expanded"` appears in the panel title when expanded mode is active. Subtle but visible.

## Learnings

- Unbuffered channels are essential for deterministic test ordering when multiple channels interact with the same select loop. Buffered channels lead to random select ordering.
- `tea.WithInput(nil)` completely prevents `tea.KeyMsg` from ever arriving — if you need any keyboard input through Bubbletea, you must remove it.
- The approval flow's `PromptKeyOnly` + `keyReader` goroutine reads from `os.Stdin` directly, which conflicts with Bubbletea's own stdin reader. The channel-based approach cleanly separates concerns.
