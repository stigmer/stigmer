## Decisions Made

1. **History on `inlineRenderer`, not Bubbletea model** — synchronous appends from the event processing goroutine eliminate races. Model stays lean (only active `View()` state).

2. **AI content replayed to stderr during re-commit** — normal operation sends AI to stdout for pipe compatibility. During re-commit, ALL content (including AI messages) replays to stderr via `tea.Println`. Pipe consumers unaffected.

3. **Pre-rendered text for mode-invariant items; structured data for mode-variable items** — tool calls, read groups, approvals, and headers store structured data for future expand/collapse rendering. All other items store pre-rendered text since they render identically in all modes.

4. **`sessionSubject` dead parameter replaced with `sessionHeaderInfo`** — the dead string param on `streamAgentExecution` was replaced with a full struct, threaded through to the renderer config.

5. **`subjectUpdate` channel set to nil after first receive** — disables the select case after subject resolves, preventing further polling overhead.

- **`run_stream_inline.go`**: `renderInline` initializes `history[0]` as `kindHeader` pointing at `cfg.headerInfo`. New select case for `subjectUpdate` mutates the header subject and calls `triggerReCommit`.

## Learnings

- `tea.ClearScreen` erases the ENTIRE terminal, including content written to stdout. This was not explicit in the T01 plan and required the decision to replay AI content to stderr during re-commit.

- `resumeSession` completely bypasses Bubbletea (no `tea.Program`). Subject update is irrelevant there (subject already resolved by session fetch), but future Phase 4 features (Ctrl+O) will need Bubbletea in the resume path too.

- Two pre-existing test failures exist on the base commit (`TestHandleApproval_DoesNotSuppressOnReject`, `TestInlineRenderer_ToolCompleted_ShowsBadge`). Verified by stashing all changes and running tests — they fail identically. Not related to this work.
