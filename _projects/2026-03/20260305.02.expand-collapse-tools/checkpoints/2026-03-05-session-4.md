## Decisions Made

1. **Explicit history return from `renderInline`** — changed return signature from `(phase, exitErr string)` to `(phase string, exitErr string, history []committedItem)`. History is an output, not smuggled through the input config. Cleaner data flow, easier testing.

2. **`initialHistory` field on config** — when non-nil, the renderer seeds its buffer from this slice instead of creating a fresh `[{kindHeader}]`. Used by the follow-up loop to pass accumulated history into each successive execution.

3. **Follow-up human message recorded by the loop, not the renderer** — the `runInlineFollowUpLoop` appends `kindHumanMessage` to the accumulated history after a successful prompt, before passing it to the next `renderInline`. Combined with `suppressHumanEcho = true`, this prevents duplicate human messages in history (the backend echo is suppressed).

4. **Ctrl+O during follow-up prompt deferred** — documented as a known limitation in `design-decisions/ctrl-o-during-follow-up-prompt.md`. The toggle is buffered (not lost) and processed when the next `renderInline` starts.

## Learnings

- `inlineRenderConfig` is passed by value to `runInlineFollowUpLoop`. Internal mutations to `cfg.initialHistory` are invisible to the caller. Tests must verify behavior (output, side effects) rather than inspecting the caller's copy of the struct.
- The streaming tool history gap was a subtle bug: `completeStreamingTool` rendered the compact result via Bubbletea's `streamingHideMsg` but never appended to `r.history`. This meant shell tools that streamed post-approval output (the most common streaming case) disappeared on Ctrl+O toggle.
