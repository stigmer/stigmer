## Decisions Made

- **Config-driven creator tuple (Option A)**: Chose to extend `AuthorizationConfig` proto with `requires_creator_tuple` field rather than hardcoding a kind-check or adding a custom pipeline step. Rationale: aligns with the proto's stated design principle ("Configuration-driven: Service reads config, no hardcoded logic"), and any future resource needing creator tuples can opt in with a single proto field.
- **`can_read_secrets = 25`**: Added as new enum value in `ApiResourceIamPermission` to enable standard RPC authorization annotations (consistent with `can_view`, `can_edit`, etc.)
- **`EnvironmentSecretValueInput` naming**: Follows existing pattern (`[Resource][Action]Input`) seen in `ApiResourceDeleteInput` and others
- **`getSecretValue` returns `EnvironmentValue`**: Reuses existing message (value + is_secret + description) rather than creating a new response type — minimal exposure, maximum type reuse
