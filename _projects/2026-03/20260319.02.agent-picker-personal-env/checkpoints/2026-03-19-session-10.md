## Decisions Made

- **Agent resolution in Layer 1 hook**: Adding `agentRef` resolution (single `agent.getByReference()` lookup) to `useCreateSession` is a mild departure from "one thing per hook" but justified:
  - Serves both Profile A (platform builders who know slug but not instance ID) and Profile B Phase 1 (Console users who picked an agent)
  - Avoids leaking SDK logic into Console's `SessionLauncher`
  - Phase 2 bypasses this path entirely — orchestration hooks resolve to `agentInstanceId` before calling `createSession`

  - Resolution priority inside `create()`: explicit `agentInstanceId` > `agentRef` (via `agent.getByReference()` → `status.defaultInstanceId`) > omitted (backend default)
  - Defensive error for missing default instance: `"Agent 'org/slug' does not have a default instance. Pass an explicit agentInstanceId instead."`

  - Hook JSDoc: documents three resolution strategies with `@example` for each

## Learnings

- `Agent.status.defaultInstanceId` is always auto-populated when an agent is created (confirmed via proto comment). The defensive error guard is for edge cases only.
- `SessionInput` in `@stigmer/sdk` already had `agentInstanceId?: string` — the React hook's `CreateSessionInput` simply never exposed it. The change was a matter of surfacing an existing capability.
