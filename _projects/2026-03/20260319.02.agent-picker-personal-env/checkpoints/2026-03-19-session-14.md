## Decisions Made

- **Separate function, not a parameter change**: `FilterByEnvSpec` is a standalone function, not merged into `MergeEnvironmentLayers`. Single responsibility preserved.
- **Whitelist includes schema-only declarations**: Keys with empty values in env_spec are still valid whitelist entries. This ensures vars declared in env_spec but only provided via Environment resources pass through.
- **Return excluded keys for observability**: Both implementations return excluded keys as a sorted list for deterministic warn-level logging at call sites.
- **Java filter goes BETWEEN merge and MCP validation**: The `McpEnvironmentValidator` now validates against the filtered result, acting as a safety net for misconfigured agents.
- **Apply to both agent and workflow executions**: Consistent security boundary across both resource types. Backward compat guard (nil/empty env_spec = pass all) protects legacy resources.

## Learnings

- The Go `envmerge` package had zero test coverage prior to this session — retroactive testing revealed the function was well-implemented but the gap was a quality concern for a security-critical path.
- The Java service has `McpEnvironmentValidator` that the Go service lacks. The filter ordering matters: filter BEFORE MCP validation creates a safety net for misconfigured agents (env_spec missing MCP server vars).
- The `environment_keys` in `ResolvedExecutionContext` is populated downstream by the Python agent runner from the `ExecutionContext` — the Go/Java filter is the single enforcement point.
