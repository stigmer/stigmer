# Session Notes: 2026-03-19 (Session 4)

## Accomplishments

- Implemented T01.4: `useCreateEnvironment` behavior hook — wraps `stigmer.environment.create()` with `isCreating` / `error` / `clearError` state management

## Decisions Made

- **Use `EnvironmentInput` from `@stigmer/sdk` directly**: Follows the `useUpdateSession` pattern (which uses `SessionInput` directly). No wrapper type needed — this is a Layer 1 building-block hook, not an abstraction layer. Platform builders already know this type from the SDK.
- **Return full `Environment` proto**: Gives callers immediate access to server-generated fields (metadata.id, version, timestamps). The Layer 2 orchestration hook (`usePersonalEnvironment`) will need this to extract the resource reference for agent instance wiring.
- **No auto-naming**: Unlike `useCreateSession` (which generates `session-${Date.now()}`), environments are named resources with semantic identifiers. The "personal" naming convention belongs in Layer 2's `usePersonalEnvironment`.

## Key Code Changes

- `sdk/react/src/environment/useCreateEnvironment.ts`: New behavior hook (~75 lines). Follows `useUpdateSession` structure exactly. Accepts `EnvironmentInput`, calls `stigmer.environment.create(input)`, returns `{ create, isCreating, error, clearError }`. Full JSDoc with consumer profile, layer designation, usage example, and cross-reference to future `usePersonalEnvironment`.
- `sdk/react/src/environment/index.ts`: Added `useCreateEnvironment` and `UseCreateEnvironmentReturn` barrel exports.

## Learnings

- The behavior hook pattern is highly mechanical — `useUpdateSession`, `useCreateSession`, `useCreateAgentExecution`, and now `useCreateEnvironment` all follow the same structure: `useState` for loading/error, `useCallback` for the mutation, try/catch/finally. T01.5 (`useUpdateEnvironment`) will be structurally identical.
- `EnvironmentInput` from the SDK doesn't support labels in its current shape (metadata labels are not exposed). This is fine for T01.4 (Layer 1 building block) but Phase 2's `usePersonalEnvironment` will need labels (`stigmer.ai/personal: "true"`) — it may need to call the SDK client directly or the `EnvironmentInput` type may need extending.
