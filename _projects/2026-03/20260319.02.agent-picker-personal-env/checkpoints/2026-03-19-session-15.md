## Decisions Made

- **Dual-source mount**: localStorage as instant fast cache, personal environment as source of truth. Preserves zero-latency mount UX while migrating to encrypted server storage.
- **handleCallback unchanged**: Still stages token to localStorage. The next page mount handles migration. Avoids race condition with personal environment loading on callback page.
- **Direct SDK call for getSecretValue**: Not `useRevealSecretValue` (30s auto-clear timer doesn't fit — token must persist in memory for the page lifetime).
- **getOrCreate(initialData) for migration**: When personal env doesn't exist, passes GITHUB_TOKEN as initialData to create in single call. When env exists but lacks the key, uses addVariables. Avoids ref-timing issue.
- **org: string | null parameter**: Breaking API change. `null` gives localStorage-only fallback for backward compatibility.
- **Key name GITHUB_TOKEN**: Stored with `isSecret: true`. Phase 3 env_spec filter excludes it from agent executions unless explicitly declared.

## Learnings

- `getOrCreate` in `usePersonalEnvironment` fires `refetch()` as fire-and-forget after creation, meaning `environmentRef.current` isn't updated synchronously. Calling `addVariables` immediately after `getOrCreate` would fail because the ref is still null. Solution: pass initial data to `getOrCreate`, only use `addVariables` when the env already existed.
- The `getSecretValue` SDK method was already generated — the TODO cast in `useRevealSecretValue` was stale from before SDK regeneration in sub-project .05.
- `useActiveOrgSlug()` returns `""` (not `null`) when no org is selected. Using `org || null` in the hook correctly converts empty string to null for the localStorage-only fallback.
