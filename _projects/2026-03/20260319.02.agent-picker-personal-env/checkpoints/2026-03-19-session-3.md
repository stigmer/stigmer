## Decisions Made

- **Primitive destructuring for `useEffect` deps**: Since `ResourceRef` is an object, placing it directly in the dependency array would cause infinite re-fetches when consumers create inline object literals. The hook destructures into `org`, `slug`, `version` primitives — re-fetching when meaningful identity changes, not when object reference changes.
- **`refetch()` included (unlike `useSession`)**: The Phase 2 orchestration hook `usePersonalEnvironment` needs to re-fetch after mutating the environment. Added via `fetchKey` increment pattern from `useSessionList`.
- **Error as `string | null` (not typed error codes)**: Consistent with all existing hooks. Phase 2 orchestration hook will call the SDK client directly for get-or-create logic where 404 detection is needed — the Layer 1 hook's string error is appropriate for its use case (displaying/consuming environment data).

## Key Code Changes

Full JSDoc with consumer profile, layer designation, usage example, and cross-reference to future `usePersonalEnvironment`.
- `sdk/react/src/environment/index.ts`: Barrel export for `useEnvironment` and `UseEnvironmentReturn`.

## Learnings

- This is the first hook in the SDK that fetches by `ResourceRef` rather than by ID string. The pattern of destructuring a ref object into primitives for `useEffect` deps will be reused by `useAgentInstance` (T01.6).
- The `EnvironmentClient` has both `get(id)` and `getByReference(ref)` but no `list()` method — unlike agents, skills, and MCP servers which use the search service. This means there's no `useEnvironmentSearch` equivalent; environments are fetched individually by reference.
