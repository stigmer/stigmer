## Decisions Made

- **AgentEnvForm is Layer 1 (pure presentational)**: No API calls, no env knowledge. Takes `variables[]`, emits `Record<string, EnvVarInput>`. Platform builders can use it standalone for any env-var-like form.
- **useAgentSetup is imperative, not reactive**: Exposes `resolveAgent(ref)` and `submitEnvVars(values)` instead of reactive data fetching. Avoids conditional hook issues and unnecessary API calls on every render.
- **Controlled popover only for Agent**: Other ContextPopovers remain uncontrolled. Agent popover needs programmatic open/close and view switching (picker ↔ form).
- **Display name from full agent metadata**: `resolveAgent` fetches the full agent and extracts display name, rather than relying only on the picker's `onDisplayNameResolved`. Ensures correct name even when env form is shown.
- **onAgentInstanceIdChange as the bridge**: SessionComposer resolves to an instanceId via useAgentSetup; SessionLauncher stores it in state; createSession uses it with priority over agentRef.
- **Width matching**: AgentEnvForm uses `w-72` to match AgentPicker, so the popover doesn't resize during transition.

## Learnings

- `@base-ui/react/popover` supports controlled mode via `open`/`onOpenChange` on `Popover.Root` — straightforward integration
- The `ContextPopover` wrapper needed optional `open`/`onOpenChange` props forwarded to `Popover.Root` — minimal change to shared component
- Secret redaction in `usePersonalEnvironment` returns `***REDACTED***` — we only need key existence (not values) for the env diff, so redaction doesn't affect the missing-variables calculation
