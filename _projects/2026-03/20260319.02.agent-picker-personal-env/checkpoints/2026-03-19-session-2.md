## Decisions Made

- **Self-contained pickers over shared abstraction**: Analyzed the duplication across SkillPicker, McpServerPicker, and AgentPicker. Decided to keep each picker self-contained because:
  - Single-select (AgentPicker) vs multi-select (others) is a fundamental behavioral difference, not a superficial one
  - McpServerPicker will diverge further with per-tool selection
  - The duplicated utilities (HighlightMatch, XIcon, etc.) are each under 15 lines — indirection cost exceeds duplication cost
  - Self-contained files are easier to understand for new engineers (5-minute rule)
  - Rule of Three: 3 pickers is the threshold for *considering* extraction, not a mandate — especially when the third has different semantics

## Key Code Changes

- `sdk/react/src/agent/AgentPicker.tsx`: New single-select picker component (~280 lines). Uses `useAgentSearch` internally. Props: `value: ResourceRef | null`, `onChange: (ref: ResourceRef | null) => void`. Full keyboard navigation, scroll shadows, ARIA accessibility, theme compliance. Three contextual empty states. Self-contained private helpers (HighlightMatch, LoadingSkeleton, AgentIcon, XIcon).
- `sdk/react/src/agent/index.ts`: Added `AgentPicker` and `AgentPickerProps` exports.

## Learnings

- The single-select variant simplifies the picker logic: no `selectedKeys` Set, no array filtering for `handleRemove`, simpler `availableResults` filter (check against one key instead of a Set). The component is ~70 lines shorter than the multi-select SkillPicker.
- The `onDisplayNameResolved` callback pattern is well-designed for the chip rendering use case — the picker resolves display names at selection time, the composer caches them for chip labels.
