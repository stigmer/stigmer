## Decisions Made

- **`onResourceLoad` callback over duplicate hook call**: Instead of having Console pages also call the data hook (which would duplicate the gRPC request), the SDK component fires a callback when data loads. Zero extra API calls, minimal SDK surface addition.
- **Stable ref pattern for callback**: Used `useRef` to store the callback, preventing the effect from re-running when consumers pass inline functions. Effect depends only on the resource object.
- **Progressive enhancement UX**: Breadcrumb shows slug initially (same as before), transitions to display name after data loads. Not-found and error states gracefully fall back to the slug.
- **Override applies only to slug segments**: The breadcrumb context override is only used for the last segment when it's NOT a known category (like "Agents", "Skills", "MCP Servers"). Category segments always use the static label.

## Learnings

- The SDK hooks use `useState`/`useEffect` (not TanStack Query), so each hook instance makes its own API call. A shared cache layer would eliminate this concern entirely, but that's a broader architectural decision for the future.
- The `onResourceLoad` callback is genuinely useful for platform builders beyond breadcrumbs: setting document titles, analytics, conditional rendering.
