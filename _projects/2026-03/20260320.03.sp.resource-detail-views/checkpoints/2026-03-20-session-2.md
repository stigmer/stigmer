## Decisions Made

- **2-round approach**: AgentDetailView first (establishes patterns), SkillDetailView + McpServerDetailView together in Round 2
- **No premature abstraction**: No shared `ResourceDetailHeader` extracted yet — will evaluate after building Skill + McpServer views
- **Instructions collapsible**: Line-count based (split by `\n`, threshold of 8 lines) rather than height-based — simpler, predictable for system prompts which are typically multi-line
- **Sub-agent expansion**: `useState<Set<number>>` with `aria-expanded` attribute, border-left indentation for visual nesting
- **Cross-resource link org fallback**: When `ref.org` is empty (same-org reference), uses the agent's own org in the click callback; display shows slug only (less noise)
- **Dropped `onSubAgentMcpServerClick`**: Sub-agent MCP access entries have only slug (not full ApiResourceReference), so they're informational display, not navigational links
- **Section component**: Reusable internal `Section` wrapper with uppercase tracking title + bordered rounded card, applied consistently across all 6 section types
- **Env spec**: Entries sorted alphabetically, "secret"/"config" pill badge, no color distinction (just text difference) for simplicity

## Key Code Changes

- `sdk/react/src/agent/AgentDetailView.tsx`: Self-contained SDK component. Uses `useAgent` hook internally. Renders Header, Instructions (collapsible), MCP Server Usages (cross-linked), Skills (cross-linked), Sub-Agents (expandable), Env Spec. Handles loading/error/not-found. - `client-apps/web/src/app/library/agents/AgentListPage.tsx`: Added `useRouter` import and `onItemClick={(item) => router.push(...)}` to `ResourceListView`.
- `sdk/react/src/agent/index.ts` + `sdk/react/src/index.ts`: Added `AgentDetailView` and `AgentDetailViewProps` to barrel exports.

## Learnings

- `react-markdown` v10.1.0 is already in `sdk/react/package.json` and used in `MessageEntry.tsx` — no new dependency needed for SkillDetailView
- The `stgm-prose` CSS class used in `MessageEntry.tsx` may not be defined in `@stigmer/theme` — needs investigation in Round 2
- `McpAccess` (sub-agent MCP references) only has `mcpServer` (slug string), not a full `ApiResourceReference` with org — different from top-level `McpServerUsage` which has `mcpServerRef` (full ref with org + slug)
