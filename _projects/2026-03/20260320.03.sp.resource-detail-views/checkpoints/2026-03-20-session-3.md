## Decisions Made

- **Shared markdown module**: Extracted to `internal/markdown-components.tsx` rather than duplicating across `MessageEntry` and `SkillDetailView`. Internal-only, not part of public SDK API.
- **Deferred `ResourceDetailHeader` extraction**: Overlap between Agent/Skill/McpServer headers is ~70-75% — below the 80% threshold for extraction. Type-specific badges create enough variation that a shared component would need render-prop slots, adding complexity exceeding the duplication cost.
- **`stgm-prose` finding**: Not defined in `@stigmer/theme`. All markdown styling comes from `MARKDOWN_COMPONENTS` element overrides. Left as-is in `MessageEntry` (harmless), not used in new components.
- **No cross-resource click callbacks**: Unlike `AgentDetailView`, neither `SkillDetailView` nor `McpServerDetailView` reference other resources, so no click callbacks are needed — simpler props interface.
- **List page navigation consistency**: Changed Skill and MCP Server list pages to navigate to detail views (matching the Agent list page pattern) instead of edit sessions.
- **Breadcrumb polish deferred**: `T01.12` left as optional — slug is already human-readable.

## Learnings

- Proto `oneof` fields in connect-es generated TypeScript use a `{ case: string, value: T }` discriminated union pattern — clean conditional rendering.
- `SkillState` enum values are `UPLOADING`, `READY`, `FAILED` (not the more common `ACTIVE`/`INACTIVE` pattern).
- `McpServerSpec.envSpec` uses a `Struct` (proto well-known type) — accessed via `.data` property containing `Record<string, Value>`.
- Git provenance `remote_url` can be in SSH (`git@github.com:...`) or HTTPS format — normalization needed for URL linking.
