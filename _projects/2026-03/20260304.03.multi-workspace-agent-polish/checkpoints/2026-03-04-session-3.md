## Decisions Made

- **Auto-discovery over explicit configuration**: Chose to scan immediate subdirectories for `.gitignore` files rather than accepting entry roots as a constructor parameter. Zero API change, self-contained within `FilesystemBackend`, mirrors real git semantics (nested `.gitignore` applies to subtree).
- **Additive filtering**: Root filter and entry filter are both applied — if either says "ignored", the file is excluded. This matches how git layered `.gitignore` works.
- **Test directory naming**: Initial tests used `dist/` as a test directory — failed because `dist` is in `_SKIP_DIR_NAMES` and gets filtered regardless of gitignore. Switched to `build_output/` which is not in the skip list.

## Key Code Changes

- `filesystem.py`: Added `_discover_entry_gitignores()` method (scans immediate subdirs for `.gitignore`), `_entry_gitignores` dict field, extended `_should_include()` with entry-level filter check using `rel_path.split("/", 1)` guard
- `test_filesystem_backend.py`: Added `multi_entry_sandbox` fixture (container root with two entries, each with `.gitignore`), `TestMultiEntryGitignore` class with 11 tests

## Learnings

- `_SKIP_DIR_NAMES` includes `dist` — tests that rely on gitignore filtering for `dist/` will never trigger because the skip-dir layer catches it first. Always use non-skip directory names in gitignore-specific tests.
- The `rel_path.split("/", 1)` pattern is clean for "first path component" extraction — `len(parts) == 2` naturally guards against applying entry filters to the entry directory name itself.
