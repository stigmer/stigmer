## Decisions Made

- **Prompt-builder-only approach**: Chose not to modify source provisioners (`local_path.py`, `git.py`, `empty.py`). The prompt builder generates multi-workspace descriptions from structured `ProvisionResult` fields rather than threading `is_multi_entry` through four layers of provisioner code. This is a separation-of-concerns win: provisioners own data, the prompt builder owns presentation.
- **Unknown source fallback**: `_format_entry_description()` falls back to `workspace_description` for unrecognized source types, so new source types added later work without changes to the prompt builder.
- **Em-dash over double-dash**: Used `—` (em-dash) in the description text for "changes are immediate and persistent" to match the Unicode convention used elsewhere in the codebase.
