## Decisions Made

- **Value object over tuple**: Chose `WorkspaceRoot(name, root_dir)` frozen dataclass over `tuple[str, str]`. Follows the same pattern as `ResolvedPath` in the module and is self-documenting.
- **Module-local type**: `WorkspaceRoot` lives in `relevance.py`, not imported from provisioner. Keeps the relevance module dependency-free — the caller in `execute_graphton.py` maps `ProvisionResult` to `WorkspaceRoot`.
- **First-match-wins**: When the same relative path exists in multiple entries (e.g. `README.md`), the first root in provision order wins. This is deterministic, avoids duplicates, and matches the user's `--workspace` flag ordering.
- **Test helper**: Added `_single_root()` module-level helper in tests to concisely wrap a path as a single unnamed workspace root. Keeps backward-compat test updates clean without adding fixture complexity.

## Learnings

- The `resolve_workspace_paths` function is purely stat-based — the inner loop over roots adds negligible cost (N is typically 1-3)
- Container-relative paths (e.g. `svc-api/src/main.go`) are not resolved by the current design — this is a known limitation documented in the plan, addressed by T04's prompt guidance
