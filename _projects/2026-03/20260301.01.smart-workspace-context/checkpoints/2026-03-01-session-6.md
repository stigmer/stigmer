## Decisions Made

- **Lazy indexing over eager**: Index built on first `search` call, cached in tool closure for execution lifetime.  Avoids provisioning latency for executions that never search.  Matches how `grep`/`glob` walk the filesystem on demand.

- **No index invalidation**: Once built, the index is immutable for the execution.  If the agent writes code, it already knows what it wrote — it won't search for its own modifications.  Stale results for deleted definitions are handled gracefully via existing error-recovery strategies.

- **Module in graphton, not agent-runner**: Unlike `tree.py` and `relevance.py` (which produce one-time prompt sections), the search tool is a runtime platform tool.  All platform tools live in graphton, so the index lives there too.  No changes to `execute_graphton.py` needed.

- **Regex-based parsing, not tree-sitter**: Zero new dependencies.  Simple per-language regex patterns that catch 80%+ of definitions.  Each language gets 3-7 patterns.  Adding a language is adding a `LanguageSpec` entry.

- **Token-aware fuzzy matching, not TF-IDF**: Split identifiers by camelCase/snake_case boundaries, match query tokens against symbol tokens with exact (1.0) > prefix (0.7) > substring (0.4) scoring.  Simple, fast, zero-dependency.

- **Fixed pre-existing test failures**: The tool count tests in both graphton and agent-runner were failing since session 1 (expected 7 but got 10 after aliases were added).  Updated to expect 11 (8 primary + 3 aliases) and added `search` to expected tool names.

## Learnings

- Pre-existing test failures accumulate silently.  The tool count tests were wrong since aliases were added in a previous session but never updated.  Fixing them alongside T07 prevents further drift.
- Scoring test assertions need to account for tokenization.  `"auth"` against `AuthMiddleware` is an exact match (score 1.0), not a prefix — because the tokenizer splits `AuthMiddleware` into `["auth", "middleware"]`.
