## Decisions Made

- **Tree generation centralized in provisioner, not distributed across source handlers**: Avoids backward import dependencies (sources → activities) and keeps source handlers focused on their specific provisioning logic. The tree is a cross-cutting enrichment, not source-specific.

- **Two walker strategies behind one API**: Local mode uses `os.*` calls (reliable on macOS + Linux). Remote/Daytona mode uses `backend.execute("find -printf ...")` (GNU find, Linux-only — fine for Daytona containers). Both produce the same DFS dirs-first output format.

- **`dataclasses.replace()` for all ProvisionResult mutations**: The existing explicit field-by-field reconstruction pattern silently drops new fields. Switched to `dataclasses.replace()` which copies all fields by default.

- **No modification of source handler descriptions**: The "Start by listing the root directory" text in git.py's `_build_description()` becomes redundant when tree is present, but we deliberately leave it unchanged. The tree section naturally supersedes it. This avoids fragile string replacement coupling between the prompt builder and source handler wording.

## Learnings

- Pre-existing stash from test verification must be explicitly popped — `git stash pop` in a chained command can silently fail to execute or its output gets swallowed by pipe redirections.
- The `build_referenced_files_prompt_section()` function in execute_graphton.py uses the same tree-building primitives, so the extraction to `tree.py` benefited both features (workspace tree AND referenced files directory expansion).
