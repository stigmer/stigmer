## Decisions Made

- **Remove `aafter_step` entirely** (not keep as deprecated): Dead code that was never invoked. Keeping as "deprecated" would imply it once worked, which is misleading.
- **Two-hook design** (`aafter_model` + `awrap_tool_call`): Discovered during research that `aafter_model` cannot prevent tool execution for the current turn — the routing edge checks the last AIMessage regardless of injected SystemMessages. `awrap_tool_call` provides true enforcement at the hard stop threshold.
- **Keep current escalation strategy** (1 warning at consecutive threshold, 1 stop at total threshold): Simplest approach. Hard stop now has real teeth via `awrap_tool_call`. Can revisit escalation later.
- **Return `{"messages": [intervention]}` not full state**: The `add_messages` reducer appends; returning only the new message is cleaner and avoids state mutation.

## Learnings

- `aafter_step` does not exist in LangChain's `AgentMiddleware` — the only valid hooks are: `abefore_agent`, `abefore_model`, `aafter_model`, `aafter_agent`, `awrap_model_call`, `awrap_tool_call`
- LangGraph's routing edge (`_make_model_to_tools_edge`) scans backwards for the last `AIMessage` to decide tool routing — injected SystemMessages from `aafter_model` do not affect routing
- `awrap_tool_call` can short-circuit tool execution by returning a `ToolMessage` without calling the handler — this is the intended use case per LangChain docs
- LangGraph's factory detects hook overrides via `m.__class__.aafter_model is not AgentMiddleware.aafter_model`
- `add_messages` reducer appends new messages (by ID); returning only the new intervention message is sufficient
- `asyncio_mode = "auto"` in pyproject.toml means async tests don't need `@pytest.mark.asyncio`
