## Decisions Made

- **Recursion limit value (100)**: Justified via industry comparison — Cursor uses 25 tool calls/message, Claude Code is unlimited but script-gated, OpenAI Agents SDK defaults to 10. Our 100 super-steps ≈ 50 model+tool rounds is 2x Cursor's limit, appropriate for complex sub-agent workflows.
- **GraphRecursionError handling included in PR3**: Lowering the limit and handling the error at that limit are the same concern. User explicitly chose to ship them together.
- **Proto configurability deferred**: Adding `max_tool_calls` to `ExecutionConfig` proto is deferred to a follow-up PR. PR3 focuses on fixing the default.
- **Catch via type-name check**: `GraphRecursionError` caught via `type(stream_err).__name__` rather than import, consistent with the lazy-import pattern used throughout `execute_graphton.py`.

## Learnings

- LangGraph `recursion_limit` counts graph **super-steps**, not individual tool calls. A model-call + tool-execution cycle is typically 2 super-steps, so `recursion_limit=100` ≈ 50 effective tool-call rounds.
- LangGraph's `merge_configs` strips `recursion_limit` values equal to `DEFAULT_RECURSION_LIMIT` (10,000) but preserves non-default values. Our 100 survives merging without an invoke-time override.
- Cursor rule files and documentation were silently propagating the wrong value (1000), which would have caused AI assistants to re-introduce the bug.
