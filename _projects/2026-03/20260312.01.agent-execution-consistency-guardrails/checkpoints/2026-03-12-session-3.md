## Decisions Made

- **`awrap_model_call` for compaction, not `aafter_model`**: `awrap_model_call` receives a `ModelRequest` with messages and allows creating a modified request via `dataclasses.replace()`. This modifies what the model sees without touching graph state. The `add_messages` reducer limitation (append-only) does not apply because we're modifying the request, not returning a state update.
- **`dataclasses.replace()` instead of `request.override()`**: The plan referenced `request.override()` but `ModelRequest` is a plain dataclass without an `override()` method. Used `dataclasses.replace(request, messages=compacted)` for idiomatic immutable modification.
- **Emergency brake only when compaction fails**: The brake only engages when `_compaction_failed` is True AND tokens are critically high. During normal operation with successful compaction, the brake never fires.
- **Deferred user-visible notifications**: StatusBuilder + gRPC source field and CLI Bubbletea rendering deferred to keep PR2 focused on the middleware. Documented as follow-ups in plan and next-task.md.
- **`patch.object` for integration tests**: Discovered that `summarize_messages` is imported locally inside `_perform_summarization`, so module-level patching fails. Used `patch.object(middleware, '_perform_summarization')` for new tests to correctly intercept the method.

## Learnings

- `ModelRequest` is a plain dataclass — use `dataclasses.replace()` for immutable modification, not a custom `.override()` method
- `summarize_messages` from `langmem.short_term` is imported lazily inside `_perform_summarization` — module-level patching doesn't work for tests; must use `patch.object` on the method itself
- The two-layer defense (proactive compaction + emergency brake) mirrors Claude Code's auto-compaction architecture while adapting to LangGraph's middleware model
- `awrap_model_call` is the ideal hook for context compaction: it has access to the full message payload and can modify it before the model sees it, without mutating graph state
