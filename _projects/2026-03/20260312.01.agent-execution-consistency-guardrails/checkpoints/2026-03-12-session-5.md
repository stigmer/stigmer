## Decisions Made

- **Two separate lists over a completed flag**: `completedSubAgentEntries` is a separate slice from `activeSubAgentEntries`. Active entries have animated spinners and long lifecycles; completed entries are static and auto-dismiss after 1.5s. Mixing them couples unrelated lifecycles and complicates the tick chain termination logic.
- **1.5 second dismiss duration**: Long enough for the eye to register the completion, short enough not to feel sluggish. Defined as a named constant (`subAgentCompletionVisibleDuration`) for easy tuning.
- **Fallback preserves original behavior**: When `displayLine` is empty in `subAgentCompleteMsg`, the handler falls back to immediate scrollback commit — the original atomic hide-and-println path. This ensures backward compatibility with any code paths that don't produce a displayLine.
- **Scrollback deferred, not duplicated**: Scrollback is committed when the dismiss timer fires (not on completion). Avoids double-display where both scrollback and live indicator would be visible simultaneously.
- **No transfer needed for re-commit**: The renderer's `history` already contains the `kindSubAgentBlock` item before sending `subAgentCompleteMsg`. Re-commits replay history, so scrollback is reconstructed correctly regardless of completed entries in the model.

## Learnings

- The Bubbletea rendering has TWO paths: legacy `View()` (flat switch, used when `inputBarMode == inputBarHidden`) and `renderComposedView()` (uses `renderTransientContent()`, used for interactive mode). Both paths must be fixed for any priority cascade change.
- The approval case already renders sub-agents alongside with the `renderSubAgentLine() + "\n\n" + approvalView` pattern. The AI stream fix follows the exact same pattern — consistent architecture.
- `tea.Tick` returns a Cmd that fires a message after a duration — the idiomatic Bubbletea way to implement timers without goroutines or channels.
