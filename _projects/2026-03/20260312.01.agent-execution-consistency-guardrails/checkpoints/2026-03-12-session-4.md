## Decisions Made

- **Use `EXECUTION_FAILED` (not a new phase)**: Reuse existing proto phase with a descriptive error message. A new `EXECUTION_TERMINATED` phase can be added later if UX needs warrant it.
- **Differentiated sub-agent finalization**: Zero-message sub-agents (spawned but never executed) get `SUB_AGENT_CANCELLED`; mid-execution sub-agents get `SUB_AGENT_FAILED`. This gives the user accurate information about what happened to each sub-agent.
- **Preserve original `finalize_active_sub_agents()`**: The new `finalize_active_sub_agents_differentiated()` is used only in the post-stream reconciliation path. Existing error handlers (stall, recursion limit, generic exception) continue using the original method.

## Learnings

- `astream_events` can end without raising an exception when the graph crashes internally (context overflow, unhandled exception inside a node). This is the "silent termination" scenario.
- Sub-agent execution model is architecturally sound — sub-agents are synchronous subgraphs. Failures propagate to the parent as error ToolMessages via LangGraph's ToolNode. This is identical to how Cursor handles sub-agents.
- The bug was in the observation layer, not the execution model. Active sub-agents at stream end is always abnormal in a healthy execution.
- Fingerprint deduplication in `_handle_tool_start_event` can silently skip events with identical tool arguments — tests need unique descriptions per sub-agent.

## Open Questions

- Should a new `EXECUTION_TERMINATED` phase be introduced later for better UX differentiation between "agent was stopped" vs "something broke"?
- Should incomplete todos also be used as a signal for abnormal termination? (Deferred — orphaned sub-agents is the strongest and most reliable signal)
