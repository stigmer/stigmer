## Decisions Made

- **Unconditional `aget_state()` post-stream**: Cost is <10ms (single MongoDB document lookup). The validation value justifies this over the previous conditional-only call.
- **Pure function over StatusBuilder method**: The validator reads from two sources (checkpoint + StatusBuilder). Standalone function with explicit parameters keeps it testable and avoids giving StatusBuilder knowledge of LangGraph internals.
- **Count-based V3 cross-reference**: Without ID-level mapping between checkpoint tool_call_ids and StatusBuilder run_ids, count-based comparison is the most reliable approach. The finalization helper handles the three cases (all missed events, all orphans, mixed) with appropriate heuristics.
- **Missed events → COMPLETED, not FAILED**: When the checkpoint confirms a sub-agent's task tool completed (ToolMessage exists), the sub-agent actually succeeded. This is a correctness improvement over the previous blanket FAILED/CANCELLED marking.
- **Defense-in-depth fallback**: `has_orphaned_sub_agents` retained as a last-resort check — only fires when `aget_state()` itself failed and validation was skipped. Prevents regression if checkpoint query is unavailable.
- **Finalization method on StatusBuilder** (not in checkpoint_validator): Sub-agent state mutation belongs in StatusBuilder since it accesses `_active_sub_agents` and `_completed_sub_agents` internal dicts. Keeps checkpoint_validator pure.

## Learnings

- The V3 sub-agent cross-reference cannot do precise ID-level matching because the checkpoint stores tool_call_ids while StatusBuilder indexes sub-agents by LangGraph run_ids. These are different identifiers that require `_run_id_aliases` to map. Count-based comparison is the pragmatic middle ground.
- The stall timeout and recursion limit handlers both `return` immediately — they never reach the post-stream reconciliation. This means V1 (graph termination check) only fires when the stream completes without exception, which is the correct behavior.
