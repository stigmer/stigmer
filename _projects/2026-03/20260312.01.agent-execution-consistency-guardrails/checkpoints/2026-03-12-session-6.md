## Accomplishments

- **D2 — ExecutionBudgetMiddleware** (PR6):
  - New middleware at `graphton/core/execution_budget.py` — tracks model rounds via `aafter_model` hook
  - Injects a single SystemMessage at ~80% of budget telling the model to wrap up gracefully
  - Separate from `LoopDetectionMiddleware` by design: resource management (budget) vs behavioral detection (loops)
  - `budget_warning_pct` added to `AgentConfig` with Pydantic validation (50–95 range)
  - Wired into `create_deep_agent()` middleware chain alongside existing loop detection and summarization
  - 39 unit tests in `test_execution_budget.py`

- **D1 — max_tool_rounds Proto Field** (PR7):
  - Added `int32 max_tool_rounds = 3` to `ExecutionConfig` proto message
  - Mapping: `recursion_limit = max_tool_rounds * 2` (each "round" = model call + tool execution = 2 super-steps)
  - Default: `0` = use platform default (50 rounds / 100 super-steps)
  - Valid range: 10–250 rounds; out-of-range values clamped with warning log
  - Orchestrator (`execute_graphton.py`) reads the field, computes, and passes to `create_deep_agent()`
  - Regenerated Python and Go stubs (buf generate + gazelle)
  - 10 new tests in `test_recursion_limit.py` (custom limit flow + budget_warning_pct validation)

- **Deferred Items Inventory**: Consolidated all deferred items from sessions 1–5 into a single D1–D10 inventory in `next-task.md`

## Decisions Made

- **`max_tool_rounds` over `max_tool_calls`**: "Tool rounds" is the correct domain term — each round is one model→tools reasoning cycle. `max_tool_calls` is ambiguous because a single round can invoke multiple tools in parallel. `recursion_limit` leaks the LangGraph implementation.
- **Separate middleware**: `ExecutionBudgetMiddleware` is a distinct concern from `LoopDetectionMiddleware`. Loops detect degenerate behavioral patterns; budget tracks resource consumption. Combining them would violate SRP and make each harder to test, configure, and evolve independently.
- **Warning via SystemMessage injection**: Rather than just logging, the middleware injects a SystemMessage into the conversation history so the LLM can adapt its behavior (prioritize wrapping up). This mirrors Cursor's "Continue" pattern.
- **PR ordering (PR6 before PR7)**: PR6 (D2: middleware) provides immediate value with the existing hardcoded recursion limit. PR7 (D1: proto configurability) naturally extends PR6 by allowing the limit to vary.
