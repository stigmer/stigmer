## Decisions Made

- **Option A chosen**: Broaden EXECUTION_TERMINATED semantics rather than adding error_code metadata (Option B). Rationale: (1) proto comment was already inaccurate — "no checkpoint, cannot recover" is wrong even for external Terminate RPC, (2) phase-level distinction gives immediate UX value (yellow vs red) without new API surface, (3) stall and recursion already match TERMINATED's documented use cases, (4) Option B is premature abstraction for two cases, (5) recovery is checkpoint-dependent not phase-dependent.
- **Three-way terminal taxonomy**: FAILED (red, something broke) / TERMINATED (yellow, platform stopped it) / CANCELLED (yellow, user stopped it)
- **Sub-agent status for stall**: Changed from `SUB_AGENT_FAILED` to `SUB_AGENT_CANCELLED` — the sub-agent didn't fail, the parent was stopped
- **Orphaned sub-agents remain EXECUTION_FAILED**: Silent graph crash is "something broke," not "platform stopped it"
- **TERMINATED is follow-up eligible**: Stall/recursion leave valid checkpoints; the recursion handler already says "Send another message to continue"
