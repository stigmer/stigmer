## Decisions Made

1. **`useId()` for element IDs**: Replaced the hardcoded `"stgm-env-save-toggle"` and `"stgm-env-{key}"` patterns with React's `useId()` hook. This is critical for the MCP server flow where multiple `EnvVarForm` instances may coexist in the same popover (each server's config panel has its own form). Without unique IDs, `htmlFor`/`id` associations break and accessibility degrades.

2. **Optional header via `title` prop**: `EnvVarForm` only renders the header block when `title` is provided. This lets `McpServerConfigPanel` embed the form without a redundant header (the panel has its own header with the server name and back button).

3. **`submitLabel` / `cancelLabel` customization**: Added these props because the MCP config panel will use "Apply" instead of "Save"/"Use once", and "Back" may not be the right label in all embedding contexts.

4. **Deprecated type aliases, not removed**: `AgentEnvFormVariable` and `AgentEnvFormSubmitOptions` are kept as `@deprecated` type aliases pointing to `EnvVarFormVariable` and `EnvVarFormSubmitOptions`. This maintains backward compatibility for any platform builders already using the agent-prefixed types.

5. **`diffEnvSpec` dual-export path**: The function is canonically exported from `environment/`, but re-exported from `agent/` for backward compatibility. The top-level barrel (`src/index.ts`) exports it from the agent section (existing) to avoid a duplicate named export.
