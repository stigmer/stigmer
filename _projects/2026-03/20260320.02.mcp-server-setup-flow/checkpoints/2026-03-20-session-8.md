## Decisions Made

### DD-T03.4: Two-signal blocking — `allReady` for button, `needsSetupCount` for warning

`allReady` gates the send button (catches all non-ready states: `loading`, `needsSetup`, `submitting`). `needsSetupCount > 0` controls warning banner visibility (only shown for user-actionable states).

**Rationale**: Transient states (`loading`, `submitting`) should block submission silently — they resolve within seconds and don't require user action. Only `needsSetup` deserves a visible warning.

### DD-T03.5: `onKeyDown` override in SessionComposer — no changes to `useComposer`

Override the textarea's `onKeyDown` at the SessionComposer level to intercept Enter-to-submit when MCP servers aren't ready, rather than adding a `blocked` parameter to `useComposer`.

**Rationale**: `useComposer` is a stable public API for platform builders. Submission blocking is domain-specific to SessionComposer's MCP integration. Keeps the hook single-responsibility and avoids public API surface expansion.

### DD-T03.6: Warning placement — Zone 2.5 between chips and toolbar

The amber warning bar sits between the context chips area and the toolbar, contextually close to both the MCP chips (showing problematic servers) and the send button (which is blocked).

**Rationale**: The warning needs to explain why the send button is disabled. Positioning between the chips (cause) and the button (effect) creates a clear visual narrative. Does not displace existing UI when not active.

## Key Code Changes

### `sdk/react/src/composer/SessionComposer.tsx` (+64/-2)

1. **Import**: Added `type KeyboardEvent` from React
2. **Blocking signals**: `mcpBlocked = showMcp && !mcpSetup.allReady`, `canSend = composer.canSubmit && !mcpBlocked`
3. **Keyboard handler**: `handleTextareaKeyDown` — intercepts Enter when `!canSend`, delegates to composer's handler otherwise
4. **Textarea**: `onKeyDown={handleTextareaKeyDown}` after spread overrides the default handler
5. **Send button**: `disabled={!canSend}` replaces `disabled={!composer.canSubmit}`
6. **Warning banner**: Amber `bg-warning/10` bar with `AlertTriangleIcon`, pluralized message, and "Configure" button that opens MCP popover
7. **AlertTriangleIcon**: New 14x14 SVG matching existing icon conventions

## Learnings

- The `onKeyDown` override pattern (spread then override) is the cleanest way to add submission guards without modifying the headless `useComposer` hook. The spread sets the default, the explicit prop overrides it — standard React JSX merge semantics.
- Two-signal approach (blocking vs. warning visibility) handles the transient/actionable distinction cleanly. Users aren't alarmed by brief loading states, but are clearly informed when credentials are required.
- The "Configure" button in the warning banner reuses the existing `setMcpPopoverOpen(true)` state, creating a zero-cost navigation shortcut to the MCP setup flow.
