## Decisions Made

- **DD-T3.1**: Grouped `setup?: McpServerSetupIntegration` sub-object instead of 5 flat optional props — prevents invalid partial states at compile time, matches `credentials?` pattern from McpServerConfigPanel (DD-R13)
- **DD-T3.2**: `value` and `onChange` become optional — not needed in setup mode, avoids forcing `onChange={() => {}}` DX smell
- **DD-T3.3**: Drill-in owned by picker via local `useState<PickerView>` — multi-select navigation is picker-internal, DD-R2 already excluded `configuring` from reducer
- **DD-T3.4**: Per-row status indicators (no full overlay) — respects multi-select independence unlike agent's single-select overlay
- **DD-T3.5**: Loading errors show retry + remove — retry re-calls `onServerAdded`, no drill-in for loading entries (no mcpServer data)
- **DD-T3.6**: `useId()` replaces hardcoded `LIST_ID` — SSR-safe, multiple-picker safe for platform builders
- **DD-T3.7**: Keep `w-72` width throughout — consistent with agent popover, avoids popover resize jitter

## Learnings

- The grouped sub-object pattern (`setup?` with all callbacks required inside) is strictly better than flat optional props for modal component behavior — TypeScript enforces complete configuration at compile time
- Deriving `selectedKeys` from `setup.entries` keys instead of `value` is essential: loading/needsSetup servers aren't in `usageInputs` (which is what `value` would be derived from), so they'd reappear in search results if we used `value`
- The `handleRemove` callback needs to reset the view if the user removes the server they're currently configuring — edge case that would leave a stale config panel visible
