## Decisions Made
- **`metadata.org: default` on stigmer.yaml**: Instead of depending on T01.7's CLI default change, the seedpack project manifest declares its own org. The CLI already reads `proj.Metadata.Org` and uses it for all resources in the session. This makes the seedpack self-contained and sets the correct example for user-authored projects — declare org once in stigmer.yaml, not in every resource.
- **T01.7 scope narrowed**: With the seedpack declaring its org, T01.7 only needs to change the CLI fallback default (when no project/flag/config provides an org). This is a cleaner separation of concerns.
- **Agent instruction text left as-is**: System prompt strings like "local for local dev" and "apiVersion: agentic.stigmer.ai/v1" are documentation text, not structural references. Deferred to T01.8.
- **Skill reference docs deferred**: 47 occurrences of `org: local` in skill references/SKILL.md files are T01.8 scope.
- **Apply ordering is safe**: `os.ReadDir` scans `agents/` before `organizations/` alphabetically, but this doesn't matter — `metadata.org` is a string namespace, not a foreign key.

## Learnings
- Go's `//go:embed` requires explicit directives per top-level entry — can't do `//go:embed .` to embed everything. A `content/` subdirectory pattern would allow a single directive, but the current approach has low maintenance cost.
- The `resolveApplyOrganization()` priority chain (flag > project metadata > cloud context > fallback) makes it natural for projects to declare their own org — the seedpack should lead by example.
