## Decisions Made

- **Organization is NOT a project member**: The hierarchy is Platform -> Organization -> Project -> Resources. Organization sits above Project and must never be tracked in `Project.Spec.Members` or subject to orphan deletion during reconciliation. The original T01.2 plan incorrectly suggested modifying `reconcile/service.go` — this was caught during review and rejected.
- **No changes to reconcile/service.go**: Organization is infrastructure, not a member. Confirmed with user.
- **Organization tier changed to open_source**: Required for CLI to recognize Organization. The proto enum is the source of truth for availability context.
- **Explicit membership filtering**: Rather than implicitly returning nil references from handlers, a new `IsProjectMemberKind()` function makes the member/non-member distinction self-documenting. The declarative flow uses it.
- **Server-side controller deferred to T01.5**: CLI is fully wired; gRPC calls will fail with a clear error until T01.5 implements the Organization command/query controllers. Acceptable for incremental delivery.
- **ResourceTier enum values renamed**: From SCREAMING_CASE (`TIER_CLOUD_ONLY`) to lowercase (`cloud_only`). Prefix `TIER_` removed; unspecified value renamed to `resource_tier_unspecified`.

## Learnings

- The original T01.2 plan had an architectural error: it suggested adding Organization to `reconcile/service.go`'s `newProtoForKind`. This would have made Organization subject to orphan deletion by project reconciliation — architecturally wrong since Organization is a parent of Project, not a child.
- Organization proto had `tier: TIER_CLOUD_ONLY` which would have prevented the CLI from recognizing it. The tier needed changing as a prerequisite.
- The `cliRelevantKinds` comment said "filtered from all TIER_OPEN_SOURCE kinds" but the actual filtering is done by the hardcoded map, not by runtime tier checks. No CLI code reads the tier value at runtime.
