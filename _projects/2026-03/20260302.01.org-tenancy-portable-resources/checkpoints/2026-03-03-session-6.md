## Decisions Made

- **Delete DependencyGraph infrastructure**: Unused code is a maintenance burden; git history preserves it. ~1,250 lines of tests were creating false confidence over dead code paths.
- **Keep server-side dry-run**: Costs nothing, provides defense-in-depth. `ReconciliationOptions.dryRun` returns what would be deleted without executing.
- **Add `deleteByOrgAndSlug` method**: Clean single-call orphan deletion rather than look-up-then-delete. Added to the shared `ApiResourceRepository` interface and `AbstractMongoApiResourceRepository` base class.

## Learnings

- The reconciliation subsystem was significantly over-engineered for the old embedded-resource model. The new CLI-driven apply model (resources applied individually, server only prunes orphans) reduced reconciliation to a simple set-difference operation.
- `ApiResourceRepositoryRegistry` provides a clean way to look up repositories dynamically by `ApiResourceKind`, avoiding direct injection of individual repos.
- Pre-existing build failures were spread across 6 unrelated files, all caused by upstream proto changes that weren't propagated to the cloud codebase.
