## Decisions Made
- **Delete follows Project pattern, not McpServer**: `OrganizationId` implements `GetValue() string`, so `ExtractResourceIdStep` works natively. McpServer uses `ApiResourceDeleteInput` which requires different wiring.
- **getByExternalOrgId left Unimplemented**: Cloud-only IdentityProvider feature. The embedded `UnimplementedOrganizationQueryControllerServer` returns `codes.Unimplemented` automatically — clean and honest.
- **Organization slug is REQUIRED, not auto-generated**: Proto CEL rules enforce 2-15 chars with specific pattern. Unlike other resources, org slugs must be deliberately chosen by the caller.
- **FindApiResourcesRequest.org ignored for Organization find**: Organizations are the top-level scope — filtering by org is semantically circular.
- **Search extractor included but NOT in ValidateExpectedKinds**: Organization is an administrative resource, not a primary searchable entity. FTS5 indexing is wired up for completeness.
- **management_mode immutability deferred**: Not enforced in update pipeline. OSS primarily deals with `self_managed` organizations.
- **Slug uniqueness is global**: `CheckDuplicateStep` scans all resources of the kind — correct since org slugs must be globally unique.

## Learnings
- The pipeline framework is remarkably composable — Organization controller took ~1 hour by following McpServer as template
- Delete pipeline type parameterization differs by ID wrapper type: resources with `GetValue()` (OrganizationId, ProjectId) use `ExtractResourceIdStep`, while `ApiResourceDeleteInput` requires a different extraction pattern
- Organization is a top-level infrastructure resource — its CRUD semantics are simpler than project-scoped resources because there's no parent context to validate
