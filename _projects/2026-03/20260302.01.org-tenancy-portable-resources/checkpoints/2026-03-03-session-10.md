## Decisions Made
- **Unified org resolution chain**: `--org flag > stigmer.yaml metadata.org > config context.organization > Backend.Cloud.OrgID (compat) > error` — same chain for local AND cloud. Backend type determines connectivity, not tenancy. These are orthogonal concerns.
- **`ContextConfig.Organization` is the canonical source**: The field existed since the original config design but was dead code. Now it's the single source of truth for the active org. `Backend.Cloud.OrgID` retained as backward-compat fallback.
- **Auto-detection during server startup**: After seedpack bootstrap, `autoSetOrgContext` queries `findMyOrganizations`. If exactly 1 org exists, it's auto-set. If multiple, the user is warned to choose. This means zero manual steps for the normal `stigmer server` flow.
- **`stigmer context` in Configuration group (not verb-first)**: Context switching is a configuration concern, not a resource operation. The existing `backend` and `config` commands in the Configuration group are also noun-first. Organization CRUD uses the existing verb-first commands (`stigmer get organization`, `stigmer list organizations`, etc.) since Organization is already in the type registry.
- **`EnsureOrgContext` in `EnsureRunning`**: Commands that auto-start the daemon (via `EnsureRunning`) also get org auto-detection. This covers edge cases where users skip `stigmer server` and go directly to `stigmer apply`.
- **No hardcoded `"default"` in CLI code**: The string `"default"` only exists in seedpack data files (`organizations/default.yaml`, `stigmer.yaml`). The CLI has zero knowledge of what the default org slug is — it discovers it at runtime.

## Learnings
- `ContextConfig` was architecturally correct from the beginning but never wired up — sometimes the right abstraction is already there, just unused.
- Three resolution functions with different priority chains was a maintenance trap; each new call site had to remember which variant to use and whether to branch on backend type.
- The existing `resolveOrganization()` in verb_helpers.go had a bug: it ignored the `--org` flag for local backend. The unified approach fixed this automatically.
