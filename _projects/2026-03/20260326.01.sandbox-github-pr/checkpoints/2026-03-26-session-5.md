## Decisions Made
- **PR URL as artifact: Dropped.** The artifact system only supports `FILE` and `DIRECTORY` kinds. Adding a `LINK` kind would be over-engineering for zero user value — the agent already communicates the PR URL in its conversational response.
- **`.patch` artifact: Removed.** It was a stopgap from before PR creation existed (Phase 3). With the `create_pull_request` platform tool now available, the diff lives on GitHub. The `_auto_publish_written_files` safety net remains for write/edit tool outputs.

## Key Code Changes
- `execute_graphton.py`: Removed `_generate_git_diff_artifact` function definition (lines ~945-1047) and the `for pr in provision_results` call loop in the post-stream safety net block. The `_auto_publish_written_files` call and the rest of the safety net are untouched.
- `test_platform_mount_integration.py`: Removed `test_git_diff_with_no_platform_dir` — it was a duplicate of `test_platform_dir_property_is_none` with a stale comment referencing the removed function.
- `test_git_diff_artifact.py`: Deleted entirely.

## Learnings
- The artifact system is file-centric (`FILE`, `DIRECTORY` proto kinds). Links or URLs don't fit naturally — if needed in the future, a separate mechanism (e.g., structured metadata on the execution status) would be more appropriate than forcing a URL into the artifact model.
