### Phase 3: `create_pull_request` Platform Tool — COMPLETE

Implemented a new platform tool that enables agents to create GitHub pull requests
after pushing their changes. The tool sits alongside `read`, `write`, `execute` in
the Graphton platform tool suite.

**New file**: `backend/libs/python/graphton/src/graphton/core/git_tools.py`
- `_create_create_pull_request_tool(backend, approval_checker, sub_agent_name)` factory
- `_parse_github_repo(remote_url)` — parses HTTPS and SSH GitHub URLs
- `_parse_token_from_credentials(content)` — extracts token from git-credential-store
- `_github_create_pr(token, owner, repo, title, body, head, base)` — async GitHub API call
- Rich error handling: no credentials, non-GitHub repo, same-branch guard, API 422/403/timeout

**Wired into platform tools**: `tool_wrappers.py` now creates 12 tools (9 primary + 3 aliases).

**Approval policy**: `create_pull_request` is auto-approved by default — a PR is a

## Decisions Made

1. **New file in `core/`, not `tool_wrappers.py`**: The PR tool calls an external HTTP API,
   which is fundamentally different from sandbox-only platform tools. Follows the pattern of
   `think_tool.py` and `resource_tools.py` (separate files for distinct tool categories).

2. **Self-discovering at invocation time**: The tool does not receive repo URL or token at
   creation time. It runs `git remote get-url origin`, `git rev-parse --abbrev-ref HEAD`,
   and reads `~/.git-credentials` from the sandbox at each invocation. This keeps the tool
   stateless and works in multi-workspace scenarios.

3. **Worker-side HTTP call via httpx**: Token is read from the sandbox, then the GitHub API
   call is made from the worker process. Avoids fragile curl-in-sandbox parsing.

4. **No HITL by default**: The push operation (via `execute`) is already HITL-gated. Creating
   a PR is a non-destructive proposal. Users can close it in one click. The override mechanism
   (`tool_approval_overrides`) still allows gating if desired.

5. **No auto-commit/push**: The tool only creates the PR. The agent is responsible for the
   full git workflow (branch, commit, push) via `execute`.

6. **Original plan deviation — file location**: Plan suggested `core/tools/git_tools.py`
   (new subdirectory). Codebase has no `tools/` directory — all modules are flat in `core/`.
   Used `core/git_tools.py` instead.
