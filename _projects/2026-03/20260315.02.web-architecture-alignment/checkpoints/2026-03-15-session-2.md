## Decisions Made

1. **Teal as brand color (OKLCH hue 190)**: Chosen for differentiation from competitors, semantic fit with network/execution domain, and strong OKLCH gamut characteristics. Light: `oklch(0.55 0.12 190)`, Dark: `oklch(0.72 0.12 190)`.

2. **`next-themes` Console-only**: The `ThemeProvider` lives in the Console's `Providers.tsx`, not in `@stigmer/theme`. The theme package stays framework-agnostic (CSS variables + `cn()` utility). This preserves the platform-for-platforms mandate — embeddable components consume CSS variables and are inherently theme-able by any host application.

3. **Three-way theme toggle in sidebar footer**: Temporary placement. The global header (T09) will be the permanent home.

4. **Neutral structural tokens unchanged**: `--accent`, `--muted`, `--secondary` stay gray. Brand identity flows through `--primary` alone, keeping the structural palette versatile.

5. **`resolvedTheme` over `useState`/`useEffect` mount pattern**: ESLint caught `set-state-in-effect`. Using `resolvedTheme` directly from `next-themes` is both cleaner and avoids the lint violation.

## Learnings

- `resolvedTheme` from `next-themes` returns `undefined` during SSR/before hydration — this is the correct signal to render a skeleton, rather than managing a `mounted` boolean with `useEffect`.
- OKLCH makes brand color tuning straightforward: changing the hue parameter is a single number edit per token. Lightness and chroma can be tuned independently for accessibility.
