## Decisions Made

25. **Connect-RPC types work correctly** — The `any` casts on `createClient()` calls were completely unnecessary. `GenService` from protobuf-es codegenv1 extends `DescService`, and `Client<T>` maps each method to properly typed input/output via `MessageInitShape`/`MessageShape`. No `eslint-disable`, no `as Promise<T>` assertions needed. The comment claiming "generic inference loss" was incorrect.

26. **All `@stigmer/*` packages are source-only** — Every package points `main` and `exports` at `./src/index.ts`. Next.js compiles them via `transpilePackages`. The `tsconfig.build.json` + `dist/` pattern in older packages was vestigial from an earlier setup.

27. **Dashboard stat and draft page errors left as-is** — `ResourceOverview` "—" display is appropriate for a compact dashboard stat card. `DraftPage` system agent error is a configuration error, not a transport error. Both are contextually appropriate and don't warrant `ErrorMessage`.

## Learnings

- Connect-RPC + protobuf-es codegenv1 types work better than assumed. The `any` casts were likely added during initial prototyping and never revisited. Lesson: periodically re-test type workarounds — library types improve across versions.
- Source-only workspace packages with `transpilePackages` is a clean pattern for monorepo domain libraries. No build step, no stale artifacts, no declaration files to maintain.
