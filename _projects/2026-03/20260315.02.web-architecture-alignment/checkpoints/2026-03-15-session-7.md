## Decisions Made

1. **Header-above-sidebar layout** (Planton/Linear pattern) — header spans full width at top, sidebar starts below header
2. **OrgSwitcher as interactive control in header** — not a passive badge (original plan said "badge" but downgrading loses functionality)
3. **UserMenu: static icon in disabled auth, dropdown in OIDC** — disabled mode shows no dropdown since there's nothing to display or sign out from
4. **Sidebar collapse included** — standard pattern for developer tools, uses `useSyncExternalStore` + localStorage
5. **Breadcrumbs replace ArrowLeft** — proper hierarchical navigation trail with clickable segments
6. **Deferred Cmd+K and notifications** — agreed with user to keep them as separate future tasks after the layout foundation is solid
7. **Native `<select>` kept for OrgSwitcher** — functional, accessible, zero-dependency; cosmetic upgrade to popover is a follow-up
8. **`useSyncExternalStore` over `useState` + `useEffect`** — the `react-hooks/set-state-in-effect` ESLint rule caught the initial implementation (same rule that caught ThemeToggle in Session 2)

## Surprise Encountered

The `react-hooks/set-state-in-effect` ESLint rule caught `setState` inside `useEffect` in the initial `useSidebarCollapse` implementation. This is the same rule that caught the ThemeToggle issue in Session 2 (noted in project surprises). Refactored to `useSyncExternalStore`, which is the correct React API for syncing with external storage. This avoids the cascading render and the lint violation.
