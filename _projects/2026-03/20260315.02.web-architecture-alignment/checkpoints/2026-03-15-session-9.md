## Decisions Made

1. **Server API gap blocks status widgets** — the original T13 scope called for "active executions, failures, pending approvals" cards. No aggregate execution endpoints exist (`ListActiveExecutions`, `CountExecutionsByPhase`, etc.). Built what the API supports (resource counts), documented the rest as server-blocked future work.

2. **Resource counts via SearchService** — each domain service's `search()` calls `SearchService` with `page: { num: 1, size: 1 }` to minimize payload. Only `totalCount` is extracted via `select`. This is a valid use — empty-query search is effectively "list all," and `totalCount` exists for this purpose.

3. **3 parallel queries vs 1 multi-kind query** — `SearchService` supports multiple `kinds` in a single request (returns `counts_by_kind`). Chose 3 parallel queries through existing Layer 2 service hooks to respect the three-layer architecture and provide independent failure isolation per resource type. Optimization to single-request deferred.

4. **Dashboard keys separate from domain keys** — `dashboardKeys` is its own factory, not nested under `agentKeys`/`skillKeys`. Cache invalidation relies on stale time (30s) + `refetchOnWindowFocus` rather than cross-key invalidation. Acceptable for dashboard counts.

5. **Browse Agents removed from quick actions** — triple-redundant with sidebar nav + resource stat card link. Quick actions trimmed to 2: Run Agent (primary action) and Draft Resource (unique dashboard-only entry point).

6. **`useSessionList` error type changed** — from `string | null` to `Error | null`. Only consumer is `RecentSessions`. Consistent with `useSessionPage` which already returns raw Error. Enables `ErrorMessage` component usage with full error classification.

## Learnings

- The server API has no aggregate/stats endpoints at all — no cross-session execution listing, no counts by phase, no dashboard-specific RPC. All status-oriented dashboard widgets are blocked on server work.
- The three-layer service architecture (T06) scales well to cross-domain hooks. `useDashboardCounts` composes 3 Layer 2 service hooks cleanly without architectural compromise.
- Pre-existing prettier formatting drift exists in 3 files (`error.tsx`, `error-message.tsx`, `useDraftAgent.ts`) — not caused by T13 changes.
