# DD-02: `subject` Generated via Economy-Tier LLM from Task Prompt

**Date**: 2026-03-09  
**Status**: SUPERSEDED (2026-03-11)

## Original Decision (2026-03-09)

The `subject` field on `SubAgentExecution` was populated directly from
`tool_args.get("description", "")` — assumed to be a concise 3-10 word label.

## Why It Was Wrong

The deepagents `task` tool has only two user-facing parameters: `description`
(the full task prompt) and `subagent_type`. The `description` parameter IS the
`HumanMessage` sent to the sub-agent — it is NOT a short label. There is no
separate `prompt`, `input`, or `task` parameter.

This meant `subject` contained the entire multi-line task prompt, and
`input` was always empty (the `input`/`task`/`prompt` keys don't exist
in deepagents' tool args).

## Corrected Decision (2026-03-11)

1. **`input`** is populated from `tool_args["description"]` (the full prompt),
   with fallbacks to `input`, `task`, `prompt` for compatibility.
2. **`subject`** is generated by `_generate_sub_agent_subject()` using an
   economy-tier LLM (claude-haiku-4.5 / gpt-4o-mini), producing a 3-7 word
   title from the full prompt. Graceful fallback to empty string on failure.
3. **CLI defense-in-depth**: `renderSubAgentLine()` and all history views
   truncate subject to first line / 80 chars via `toolrender.FirstLine()` +
   `toolrender.Truncate()`.

## Runner Changes

- `_handle_sub_agent_start` is `async` again (LLM call)
- `sub_agent_input` prefers `description` key (deepagents), falls back to
  `input`/`task`/`prompt`
- `subject = await _generate_sub_agent_subject(sub_agent_input, sub_agent_name)`
- `_generate_sub_agent_subject()` restored as module-level async function

## CLI Changes

- `renderSubAgentLine()`: `toolrender.Truncate(toolrender.FirstLine(label), 80)`
- `renderSubAgentStarted()`: truncates before sending to Bubbletea or printing
- `renderSubAgentBlockItem()`: truncates in history header
- `FirstLine()` added to `toolrender/format.go`
