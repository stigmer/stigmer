# Session Notes: 2026-03-17 (Session 15)

## Accomplishments

- Fixed critical Tailwind CSS infrastructure bug: SDK's `styles.css` was missing `@source` directive, causing all layout-critical utility classes in SDK `.tsx` files to be silently dropped from generated CSS
- Rewrote `GitHubRepoPicker` with owner-grouped sections, recent repos (localStorage), keyboard navigation, scroll shadows, and search highlighting
- Simplified scroll layout from complex flex nesting (`flex-col max-h-[300px]` + `flex-1 min-h-0` + `h-full`) to simple `max-h-64 overflow-y-auto` matching `FolderBrowser`'s proven pattern

## Decisions Made

- **`@source` directive in SDK styles.css** — Tailwind v4 requires explicit source paths for content detection. Without this, SDK component class names are invisible to the Tailwind compiler. This was the root cause of multiple layout failures.
- **Simple scroll pattern over complex flex nesting** — `max-h-64 overflow-y-auto` directly on the listbox (matching `FolderBrowser`) instead of `flex-col max-h-[300px]` + `flex-1 min-h-0` + `h-full`. The simple pattern is robust, portable, and uses only standard Tailwind utilities.
- **No custom CSS** — All layout uses standard Tailwind utilities. The only `style={{}}` attributes are for scroll shadow gradients (linear-gradient with CSS custom properties), which cannot be expressed as Tailwind utilities.
- **Home directory as default** — Changed from CWD because users may launch `stigmer` from non-project directories. Home is a more universal starting point.

## Learnings

- Tailwind v4's `@source` directive is critical in monorepo setups where component libraries live in separate packages. Without it, Tailwind only scans the consuming app's source files.
- Complex CSS patterns (flex nesting with `min-h-0` + `h-full`) can fail silently in certain layout contexts. The simplest pattern that works (`max-h` + `overflow-y-auto`) should always be preferred.
- `absolute inset-0` inside a flex child collapses the parent to zero height because absolutely positioned children don't contribute to parent sizing.
