## Decisions Made

1. **No MCP server usages**: The assistant is purely general-purpose. Platform discovery tools would bias it toward "help desk" behavior and waste tokens on 90% of interactions. Platform browsing belongs in the UI, not the agent.

2. **Minimal instructions (5 lines)**: The best general-purpose assistants have minimal system prompts. Enumerating capabilities constrains the LLM. The runtime injects tool descriptions — the agent adapts to whatever tools are available.

3. **No skill_refs, sub_agents, or env_spec**: The assistant is a clean slate. No platform coupling, no delegation complexity, no environment requirements.

4. **Two labels**: `stigmer.ai/system: "true"` (consistent with all seedpack agents) and `stigmer.ai/default-agent: "true"` (behavioral marker for backend resolution in T01.2).

## Key Code Changes

- `seedpack/agents/assistant.yaml` (new): 16-line agent definition with minimal instructions, two labels, no MCP server usages

## Learnings

- Initial instinct was to write a detailed 60-line system prompt documenting every tool and capability. User feedback corrected this — the agent should be general-purpose, not a platform guide. Less is more for default agents.
- MCP tool descriptions consume context window tokens on every interaction. For a general-purpose agent, this is waste.
