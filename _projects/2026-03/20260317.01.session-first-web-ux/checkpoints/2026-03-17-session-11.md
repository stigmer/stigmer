# Session Notes: 2026-03-17 (Session 11)

## Accomplishments

- Diagnosed root cause of invisible surface hierarchy in light mode: base theme tokens in `tokens.css` had zero gap between `card` and `background`, dangerously low-contrast borders, and near-invisible muted elements.
- Implemented fix: adjusted 15 token values (12 light, 3 dark) in `sdk/theme/src/tokens.css`.
- Fixed 3 token bypasses in Console layout: `AppShell.tsx` and `Sidebar.tsx` replaced `foreground/10` with proper `sidebar-border` token.
- Visually verified both light and dark modes in the browser — surface hierarchy, borders, input fields, sidebar separation all confirmed working.

## Decisions Made

- Base theme stays achromatic (no hue) — hue tinting is a preset concern, not a base theme concern.
- Surface hierarchy follows the pattern: `popover/card (1.0) > background (0.98) > sidebar (0.97) > muted (0.94) > border (0.885) > input (0.87)`.
- Dark mode only needed border/input opacity bumps (10→14%, 15→20%) — the existing background/card/muted separation was adequate.
- The fix is purely token values — no component architecture changes, no new CSS classes, no preset file changes.

## Key Code Changes

- `sdk/theme/src/tokens.css`: 12 light-mode + 3 dark-mode token value adjustments
- `client-apps/web/src/components/layout/AppShell.tsx`: 1 class replacement (token bypass)
- `client-apps/web/src/components/layout/Sidebar.tsx`: 2 class replacements (token bypasses)

## Learnings

- The preset themes (corporate, startup, friendly, fintech) all had proper surface hierarchy because they introduced background/card gaps. The base theme was the outlier.
- OKLCH lightness differences below ~0.03 are not reliably perceptible for surface distinction. The presets use 0.02–0.03 gaps, which is the minimum.
- `foreground/10` opacity classes are a pattern smell in the codebase — they bypass the token system and don't respond to preset overrides. Should watch for this in future code.
