- Validated that `output: "export"` + `__placeholder__` is the correct architecture for the single-binary distribution model — not tech debt

## Decisions Made

- **`output: "export"` stays**: The web console is embedded as static files in the Go CLI binary. The `spaHandler` in `client-apps/cli/embedded/webconsole/handler.go` explicitly handles dynamic route rewriting via `__placeholder__` variants. Switching to `output: "standalone"` would break the single-binary distribution model (`stigmer server` gives you everything) and require users to install Node.js separately or manage a child process. Not worth it.
- **Dynamic route pattern for static export**: Server component `page.tsx` exports `generateStaticParams()` with a sentinel `[{ id: "__placeholder__" }]`. Client component reads the real ID via `useParams()` at runtime. The Go `spaHandler` rewrites `/sessions/abc123` to `/sessions/__placeholder__.html` transparently.

## Key Code Changes

- `client-apps/web/src/app/sessions/[id]/page.tsx`: Rewritten as server component exporting `generateStaticParams()` with `__placeholder__` param, delegates rendering to `SessionPage` client component
- `client-apps/web/src/app/sessions/[id]/SessionPage.tsx`: New client component using `useParams<{ id: string }>()` for runtime ID resolution

## Learnings

- The `output: "export"` + `__placeholder__` pattern in this codebase is NOT a hack — it's backed by a well-engineered `spaHandler` Go package with explicit dynamic route rewriting, cache control, and SPA fallback logic. Always examine the full serving pipeline before judging a pattern.
- Next.js `generateStaticParams` cannot be exported from a `"use client"` component. It must be in a server component. Dynamic routes that need client-side state require the split pattern: server `page.tsx` + client child component.
