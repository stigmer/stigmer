## Decisions Made

- **Hooks follow aggregate boundaries**: `useCreateSession` maps 1:1 to Session aggregate, `useCreateAgentExecution` maps 1:1 to AgentExecution aggregate. No cross-aggregate orchestration hidden in hooks. Platform builders compose them however they need.
- **Always two-step flow**: Session is always created explicitly before execution, even when there are no workspace entries. Removes branching logic, provides sessionId upfront, and makes the flow consistent and predictable.
- **`useCreateAgentExecution` not `useCreateExecution`**: Named with the `Agent` qualifier to leave room for future `useCreateWorkflowExecution`. The `execution/` folder remains the namespace for all execution types.
- **`SessionLauncher` stays in Console**: It composes Console-specific concerns (org context via `useActiveOrgSlug`, Next.js routing via `useRouter`, toast notifications via `sonner`). SDK provides the building blocks; Console assembles them. This aligns with platform-for-platforms: other consumers would compose the same SDK hooks with their own routing and notification systems.
- **`agent_instance_id` optional in proto**: Backend resolves default agent instance when omitted. The frontend never needs to know which agent or instance is being used for the default flow.
- **Model registry hardcoded for now**: 22 models in `sdk/react/src/models/registry.ts`. Future backend RPC will replace with a dynamic list. The `useModelRegistry()` hook abstracts the data source so consumers won't need to change when the backend endpoint is ready.
- **`@base-ui/react` as SDK peer dependency**: Provides accessible UI primitives (Select, Popover) without pulling in opinionated styling. SDK components use `--stgm-*` design tokens for theming.

## Learnings

- Hooks that orchestrate across aggregate boundaries create hidden coupling. Keeping hooks pure to their aggregate makes them composable and testable — consumers choose how to compose them.
- Naming matters for disambiguation: `useCreateExecution` is ambiguous when workflow executions exist. Using domain-qualified names (`useCreateAgentExecution`) prevents future naming collisions.
- The "always create session first" pattern is simpler than conditional branching and has negligible cost for in-process gRPC calls. Simplicity in the SDK hook layer pays dividends for platform consumers.
- `@base-ui/react`'s `Select.Root` `onValueChange` passes `string | null` (null when cleared). SDK components must handle nullable callbacks even when the domain doesn't allow null.
