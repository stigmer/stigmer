## Decisions Made

- **SDK components must not use `<form>` elements**: Since SDK components can be embedded inside a host application's own `<form>`, they must avoid `<form>` to prevent HTML nesting violations. Use `<div>` with explicit `onClick`/`onKeyDown` handlers instead.
- **Fix belongs in SDK, not Console**: The `SessionLauncher` (Console) correctly uses a `<form>`. The bug was in the SDK component (`WorkspaceEditor`) which must be host-element-agnostic per the platform-for-platforms contract.

## Key Code Changes

- `sdk/react/src/workspace/WorkspaceEditor.tsx`:
  - Replaced `<form>` with `<div>` for the add-workspace panel
  - Renamed `handleSubmit(FormEvent)` to `handleAdd()` (plain callback)
  - Added `handleKeyDown(KeyboardEvent<HTMLInputElement>)` for Enter-to-submit
  - Changed Add button from `type="submit"` to `type="button"` with `onClick={handleAdd}`
  - Removed `required` attributes from inputs (no `<form>` to validate against)
  - Updated import from `FormEvent` to `KeyboardEvent`

## Learnings

- SDK components must be defensive about HTML element usage: any element that has nesting restrictions (`<form>`, `<table>`, `<p>`, etc.) should be avoided or used with caution, because the host application context is unknown.
- The `required` HTML attribute only works with native form submission -- when replacing `<form>` with `<div>`, input validation must be handled programmatically (already was in `handleAdd`).
