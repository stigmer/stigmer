## Decisions Made

- **Option B (handwritten clients)**: After analysis, confirmed that `GitHubService` and `SearchService` don't fit the CRUD-focused codegen pipeline. Will maintain them manually until the number of utility services justifies extending codegen.
- **Authorization model clarified**: `is_skip_authorization` skips FGA-based authorization but NOT authentication. The global gRPC interceptor still enforces JWT/API-key authentication. SDK doesn't need to handle this distinction.
- **Consistent patterns**: Each SDK's `GitHubClient` follows the exact same conventions as its `SearchClient` (dataclasses in Python, structs in Go, inner builders in Java).

## Learnings

- The existing codegen pipeline (`tools/codegen/generator/`) explicitly skips `search` service in all four SDK generators. Adding GitHub would require structural changes to handle non-CRUD service patterns.
- There's a clear distinction between `is_skip_authorization` and `is_public` proto options in the backend security model. `is_public` removes authentication entirely; `is_skip_authorization` only removes FGA resource-level checks.
