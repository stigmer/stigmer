## Design Decisions Made

- **Placement in `execution/`** — runtimeEnv is execution-scoped, co-located with `useCreateAgentExecution` and `CreateAgentExecutionInput`. Not `environment/` (which is for persisted environments).
- **Controlled-prop pattern** — Consumer manages hook state externally and passes to SessionComposer, identical to `useWorkspaceEntries` / `workspace` prop. Consistent with all other context triggers.
- **No `onSubmit` signature change** — SessionComposer's `onSubmit: (message, modelName?) => void` stays unchanged. Consumer reads `secrets.toRuntimeEnv()` and calls `secrets.clear()` in its `handleSubmit`.
- **Auto-clear after submission** — Consumer calls `secrets.clear()` explicitly (not magic `takeRuntimeEnv()` semantics). Matches the ephemeral-by-design nature.
- **`isSecret: true` default** — Safer default for credentials. Users can toggle to "plain" for non-sensitive values.
- **Chips show key names only** — Never display secret values in the toolbar chips. "1-time" type label differentiates from session-level context.
- **Freeform editor (no env_spec guidance)** — Follow-up secrets have no schema; the user supplies variable names. Future enhancement: autocomplete from the session's agent `env_spec`.
