## Decisions Made

- **`Error | null` over `string | null`**: Breaking change justified because all consumers are internal, SDK is pre-1.0, and `StigmerError` provides `code`, `connectCode`, and metadata that string discards
- **`getUserMessage()` at rendering boundary only**: Hooks preserve the full error object; only JSX rendering calls `getUserMessage()`. This keeps classification, retry detection, and RPC metadata available to consumers
- **Backend messages unchanged**: `McpEnvironmentValidator` messages are correct for the API surface. UI-layer `SecretFlowErrorGuide` translates for end-users — each layer adds value for its audience
- **`toError()` utility over inline patterns**: Small utility in `internal/` avoids repeating `err instanceof Error ? err : new Error(...)` in 18 hooks while preserving `StigmerError` identity via `instanceof` check

## Learnings

- The error infrastructure in `sdk/typescript/src/errors.ts` is well-designed but was completely disconnected from the React SDK — the gap was wiring, not capability
- `getUserMessage()` already handles infra noise sanitization (ECONNREFUSED, ETIMEDOUT, etc.) — the pattern just wasn't being used
- Storing `Error | null` instead of `string | null` is a zero-overhead change that unlocks the entire classification system
