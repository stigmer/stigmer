## Accomplishments

- Replaced fragile ref-based state (`useRef(pendingRef)` + `useState(isResolving)` + `useState(error)`) with a `useReducer` state machine in `useAgentSetup`
- Designed and implemented 5-phase state machine: `idle → resolving → needsEnvVars → submitting → ready`
- Extracted `diffEnvSpec` as a pure function for independent testability
- Added `saveForFuture` dual-path to `submitEnvVars`:
  - `true` (default): persist to personal environment + create instance → `{ mode: "saved", instanceId }`
  - `false`: instant (no network calls) → `{ mode: "oneTime", runtimeEnv }`
- Updated `AgentEnvForm` with accessible "Save for future runs" toggle (default ON)
- Replaced `onAgentInstanceIdChange` with `onAgentResolutionChange` in `SessionComposer`
- Eliminated `pendingEnvRef` and `agentPopoverView` from `SessionComposer` — both now derived from hook state
- Updated `SessionLauncher` with exhaustive `switch (resolution.mode)` routing across all three paths
- Updated barrel exports for all new types

## Design Decisions Made

- **Three resolution modes** (`saved` | `oneTime` | `direct`): Most explicit and self-documenting for platform builders. Each mode has a distinct semantic that TypeScript can enforce exhaustively.
- **No hook composition of `usePersonalAgentInstance`**: The imperative/reactive timing mismatch makes true hook composition impractical. `resolveAgent` runs in a single async callback and needs immediate results; hook state updates require a render cycle. `buildPersonalInstanceInput` remains the shared surface. Documented in a code comment.
- **`onAgentResolutionChange` replaces `onAgentInstanceIdChange`**: Single callback carries the full routing information (mode + payload). No external consumers yet, so this breaking change is safe.
- **Verified isSecret bug doesn't exist**: The explore agent initially reported `isSecret: v.description` in `usePersonalEnvironment`, but the actual code has `isSecret: v.isSecret` (correct). No fix needed.
