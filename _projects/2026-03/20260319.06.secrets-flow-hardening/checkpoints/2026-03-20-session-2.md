## Decisions Made

- **Drop the "neither agent" path**: The current API supported a third path where neither `agentInstanceId` nor `agentRef` was provided (backend picks a default). We decided to remove this from the React hook because:
  - Implicit defaults violate visibility-of-system-status for platform builders
  - T02's two-path model (saved vs one-time) both require explicit agent selection
  - Platform builders who need the backend's implicit resolution can drop to `@stigmer/sdk` directly
  - This respects the layered architecture: `@stigmer/sdk` mirrors the proto faithfully, `@stigmer/react` adds opinionated guardrails
- **`?: never` pattern over `via` discriminator**: Kept the approved pattern from T04 spec — no runtime discriminant field, TypeScript enforces at compile time
- **Defensive runtime guard**: Added `else` branch with actionable error message for JavaScript callers or edge cases that bypass the type system

## Key Code Changes

- `sdk/react/src/session/useCreateSession.ts`:
  - `CreateSessionInput` changed from flat `interface` to `type` union with `SharedSessionFields` extraction
  - Implementation uses `resolvedInstanceId: string` with explicit `if/else if/else` branches
  - JSDoc updated: two strategies (not three), fixed `@link` to `useCreateAgentExecution`
- `client-apps/web/src/components/session/SessionLauncher.tsx`:
  - Agent-selection guard before `createSession` call
  - Ternary with two separate `createSession` calls, one per union variant

## Learnings

- TypeScript's `?: never` mutual-exclusion pattern works well for two-variant unions but doesn't give automatic narrowing in `else` branches after truthiness checks — needed to structure the code with `else if (input.agentRef)` for proper narrowing
- The "neither" path (backend default agent) was live in the Console today — users could submit without selecting an agent. This was a UX gap, not a feature.
