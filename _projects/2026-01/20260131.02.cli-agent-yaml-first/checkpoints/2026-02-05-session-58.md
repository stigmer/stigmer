## Decisions Made

### 1. Stub Execution in D4
**Decision**: Defer actual resource creation/update/deletion to future phase E2
**Rationale**: Focus on clean architecture and integration patterns first; execution is complex and deserves focused implementation
**Impact**: `executePlan()` returns success without side effects; clear integration point for E2

### 2. Dependency Injection Pattern
**Decision**: Use constructor injection for ReconciliationService with nil-safe fallback
**Rationale**: Enables clean testing with mocks while providing simple production setup
**Impact**: Tests can inject mock services; production code uses default implementation effortlessly

### 3. Graceful Reconciliation Error Handling
**Decision**: Apply succeeds even if reconciliation fails (logs error, omits summary from response)
**Rationale**: Persistence shouldn't be blocked by reconciliation issues; reconciliation is enhancement, not requirement
**Impact**: Robust error handling; project creation/update never fails due to reconciliation

### 4. Non-Persisted ReconciliationSummary
**Decision**: Populate `status.last_reconciliation` in response but don't save to database
**Rationale**: Treat reconciliation summary as computed metadata, not persistent state
**Impact**: Cleaner data model; summary is transient per-request information

### 5. Store Annotation Pattern
**Decision**: Use `stigmer.ai/sdk.project` annotation to identify project-owned resources
**Rationale**: Standard pattern for resource ownership; enables efficient queries
**Impact**: Established pattern for future resource ownership queries across system

## Learnings

### 1. Proto Validation Rules Matter
**Discovery**: Initial tests failed due to incomplete test data not meeting `buf.validate` rules
**Resolution**: Updated test helpers to include required fields (oneof server_type, regex-compliant names, minimum lengths)
**Takeaway**: Always respect proto validation in test fixtures; it catches real issues

### 2. Pipeline Pattern Scales Well
**Discovery**: Minimal pipeline (2 steps) sufficient for Apply handler
**Insight**: Pattern adapts to handler needs; no need for complex pipelines when simple checks suffice
**Takeaway**: Use pipeline for what you need; don't over-engineer

### 3. Dependency Injection with Fallbacks
**Discovery**: Nil-safe fallback pattern (`if service == nil { service = NewDefault() }`) works excellently
**Benefit**: Tests inject mocks easily; production code simple and clean
**Takeaway**: Fallback pattern balances testability with production simplicity

### 4. Graceful Degradation is Powerful
**Discovery**: Apply succeeding despite reconciliation failure provides excellent robustness
**Trade-off**: Lose reconciliation summary in response, but never lose persistence
**Takeaway**: Core operations (persistence) should never fail due to enhancement failures (reconciliation)

### 5. Store Annotation Queries
**Discovery**: `FindAllByField()` with annotation key/value pairs works smoothly
**Pattern**: `ProjectOwnershipAnnotation` → store query → filter by type
**Takeaway**: Annotation-based ownership is clean and efficient
