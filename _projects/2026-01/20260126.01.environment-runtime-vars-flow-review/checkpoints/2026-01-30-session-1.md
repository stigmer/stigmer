## Decisions Made

### Technical Decisions
1. **Versioned format** (`enc:v1:`) - Supports future key rotation without breaking changes
2. **Redaction by default** - API responses redact secrets, internal services decrypt
3. **Backward compatible** - Non-encrypted values pass through unchanged during migration
4. **Fail-fast validation** - Invalid keys cause startup failure, preventing production issues
5. **Context-aware pipeline steps** - Steps handle both `target` and `newState` contexts elegantly

### Security Decisions
1. **No double-encryption** - Service detects already-encrypted values
2. **Unique nonce per encryption** - Uses `SecureRandom.getInstanceStrong()` (Java) and `crypto/rand` (Go)
3. **128-bit auth tag** - Maximum GCM security
4. **Secure key storage** - `0600` permissions on Go key files
5. **No plaintext in logs** - Secrets never logged in any form

## Learnings

### Pattern Insights
1. **Pipeline step pattern is powerful** - Clean separation of concerns, easy to test
2. **Context flexibility required** - Different contexts (`CreateContextV2`, `GetContextV2`, `CustomOperationContextV2`) need different accessor methods
3. **Spring Boot validation** - `@PostConstruct` enables fail-fast startup validation
4. **GCM nonce handling** - 12 bytes prepended, tag appended by GCM automatically

### Cross-Platform Challenges
1. **Base64 encoding** - Must use standard encoding (not URL-safe) for compatibility
2. **Nonce placement** - Prepend to ciphertext before encoding (GCM appends tag automatically)
3. **UTF-8 encoding** - Must be consistent across languages for plaintext

1. **No shortcuts taken** - Full documentation, comprehensive tests, proper error handling
2. **No technical debt** - Follows existing patterns perfectly
3. **Production-ready** - All edge cases handled, security hardened
4. **Maintainable** - Clear code, excellent logging, self-documenting
