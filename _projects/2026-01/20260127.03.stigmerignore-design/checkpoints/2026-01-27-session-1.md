### Architectural Decisions (ADRs)

**ADR-000: CLI vs Backend Filtering**
- Decision: Both, via shared library
- Rationale: Local push needs CLI filtering; remote git push needs backend filtering
- Solution: Create `pkg/ignore` as shared Go package

**ADR-001: Respect .gitignore?**
- Decision: Yes, with layered override capability
- Rationale: Reduces duplication, users already maintain .gitignore
- Override: Use `!pattern` in `.stigmerignore` to re-include

**ADR-002: File vs Config?**
- Decision: Create `.stigmerignore` file
- Rationale: Familiar pattern (like .gitignore, .dockerignore)

**ADR-003: Pattern Syntax?**
- Decision: Full gitignore syntax via go-git library
- Rationale: Actively maintained, developers already know syntax, full compatibility

**ADR-004: Precedence Order**
- Decision: Built-in defaults < .gitignore < .stigmerignore < CLI flags
- Rationale: Most specific wins, mirrors Git behavior

## Learnings

### Critical Insights

1. **Industry Standard = Client-Side**: Git, Docker, and Buf all filter client-side. No server-side filtering. This is for performance and privacy.

2. **Git's Gotcha**: Cannot re-include a file if parent directory is excluded. Git stops traversing ignored directories for performance. Workaround: Use progressive inclusion patterns.

3. **Docker's Different Semantics**: `*.txt` in .dockerignore matches root only. Need `**/*.txt` for recursive. This differs from Git and causes user confusion.

4. **Buf's Philosophy**: No wildcards at all - exact paths only. Good for protobuf APIs, not suitable for skills with diverse file types.

5. **Shared Library Value**: Stigmer's remote git push mode requires backend filtering. Shared library ensures consistency between CLI and backend.

6. **npm's Elegant Fallback**: If .npmignore missing, use .gitignore. We're adopting similar: always respect .gitignore, use .stigmerignore for overrides.

### Library Selection

**Chosen**: `github.com/go-git/go-git/v5/plumbing/format/gitignore`
- v5.16.4 (November 2025) - actively maintained
- 176 known importers - battle-tested
- Full gitignore spec compliance
- Wildmatch algorithm (same as Git)

**Alternatives Considered**:
- `sabhiram/go-git-ignore` - Good but less maintained
- Custom implementation - Too complex, not worth reinventing

## Technical References

### Data Flow Diagram
```
┌─────────────────────────────────────┐
│       LOCAL PUSH FLOW               │
│  User's Machine → CLI filters →    │
│  ZIP → Backend stores as-is         │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│      REMOTE GIT PUSH FLOW           │
│  Backend fetches → Backend filters  │
│  → ZIP → Backend stores             │
└─────────────────────────────────────┘
```

### Precedence Model (Low to High)
```
1. Built-in defaults (security-first)
   ↓
2. .gitignore (if present, respects user's Git config)
   ↓
3. .stigmerignore (Stigmer-specific overrides)
   ↓
4. CLI flags (one-off overrides, highest priority)
```

### Pattern Examples
```gitignore
# Exclude directory
tests/

# Exclude files recursively
**/*.log

# Exclude at root only
/config.yaml

# Negation (re-include)
!important.log

# Directory-only matching (trailing slash)
build/
```
