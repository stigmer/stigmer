## Decisions Made

### 1. Proto Design Patterns
- **Decision**: Use `oneof` for `SkillSource` (local vs git)
- **Rationale**: Extensibility for future source types (tar.gz, npm package, etc.)
- **Alternative considered**: Separate optional fields (rejected - less type-safe)

### 2. Skill Naming Strategy
- **Decision**: Skill name MUST come from SKILL.md YAML frontmatter (required)
- **Rationale**: Folder names are arbitrary; YAML is canonical source of truth
- **Alternative considered**: Folder name with fallback (rejected - inconsistent)

### 3. Git Detection Approach
- **Decision**: Automatic git detection for local pushes (non-intrusive)
- **Rationale**: Users shouldn't need to specify git info manually
- **Implementation**: Silent fallback if not a git repo

### 4. Remote Push Implementation
- **Decision**: Shallow clone (`--depth 1`) for remote repos
- **Rationale**: Performance - most skills are small, don't need full history
- **Fallback**: Full clone if shallow fails (e.g., specific commit SHA)

## Learnings

### 1. Buf Proto Patterns
Studying buf's `git_repo` input pattern was valuable:
- They use URL + tag/branch + subdir
- Simple and effective for remote sources
- We replicated this in `GitSource`

### 2. YAML Frontmatter Parsing
- Markdown YAML frontmatter is straightforward: `---\n...\n---`
- `gopkg.in/yaml.v3` handles parsing well
- Important to validate and provide clear errors

### 3. Git CLI Integration
- `git rev-parse --show-toplevel` for repo root
- `git remote get-url origin` for remote URL
- `git rev-parse HEAD` for commit SHA
- All commands are stable and widely supported

### 4. Proto Field Numbering
- Used fields 3-4 for SkillSpec (1-2 already taken)
- Used field 6 for PushSkillRequest (1-5 already taken)
- Backward compatible - all new fields are optional

## Open Questions

- Tar.gz URL?

- Docker image with skill?
**Answer**: Not for now - `oneof` allows adding these later

### Q2: Should git ref default to "main" if not specified?
- Current: Empty string if not provided
- Alternative: Auto-detect default branch
**Decision**: Keep empty for now - explicit is better

### Q3: Should we validate git URL format?
- Current: No validation, just pass to git clone
- Alternative: Regex validation for URL format
**Decision**: Let git CLI handle validation (better error messages)
