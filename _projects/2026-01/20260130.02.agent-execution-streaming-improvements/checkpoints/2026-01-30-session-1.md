## Decisions Made

### 1. Multi-Format Usage Metadata Support

**Decision**: Support both LangChain object format and dict format for usage metadata

**Rationale**: Different LLM providers return usage in different formats:
- Anthropic: `usage_metadata.input_tokens`, `usage_metadata.output_tokens`
- OpenAI: `usage.prompt_tokens`, `usage.completion_tokens`
- Dict vs object varies by LangChain version

**Implementation**: Handler checks for both object attributes (`hasattr`) and dict keys (`get`)

### 2. Message Index as Timing Key

**Decision**: Use message index (position in messages list) as key for timing tracking

**Rationale**:
- Messages don't have unique run_ids like tool calls
- Message indices are stable during streaming
- Index corresponds to physical position in status
- Simple cleanup: just delete by index when done

### 3. Cumulative Token Tracking

**Decision**: Track total tokens at execution level, not just per-message

**Rationale**:
- Enables cost calculation for entire execution
- Useful for rate limiting and billing
- Matches how usage is typically reported
- Individual message tokens can be added in Phase 2.1 (proto fields)

### 4. Structured Logging Format

**Decision**: Use `[USAGE]` prefix with key=value pairs

**Format**: `[USAGE] execution=<id> prompt_tokens=X completion_tokens=Y total_tokens=Z duration_ms=N model=<name> cumulative_prompt=X cumulative_completion=Y`

**Rationale**:
- Easy to grep in logs: `grep "\[USAGE\]"`
- Structured format for log aggregation tools
- All metrics in single line
- Includes both call-level and cumulative stats

## Learnings

### 1. LangChain Usage Metadata Variations

LangChain's response format varies significantly:
- **Anthropic models**: `usage_metadata.{input_tokens, output_tokens, total_tokens}`
- **OpenAI models**: `usage.{prompt_tokens, completion_tokens, total_tokens}`
- **Some models**: Dict format instead of object attributes
- **Fallback**: Calculate `total_tokens` from prompt + completion if not provided

### 2. Event Ordering Guarantees

From LangGraph v2 astream_events:
- `on_chat_model_stream` events arrive in order
- `on_chat_model_end` always comes after all stream events for that message
- Safe to use "most recent AI message" pattern
- No race conditions with proper reverse iteration

### 3. Test Coverage Best Practices

Key testing patterns discovered:
- Mock both object attributes AND dict keys for format flexibility
- Test error paths (missing message, empty output, None values)
- Verify cleanup (start times deleted after use)
- Test accumulation across multiple calls
