## Key Technical Decisions

### 1. Pipeline Pattern for All Operations

Every operation uses the pipeline pattern with reusable steps:

```go
pipeline.NewPipeline[*mcpserverv1.McpServer]("mcpserver-create").
    AddStep(steps.NewValidateProtoStep[*mcpserverv1.McpServer]()).
    AddStep(steps.NewResolveSlugStep[*mcpserverv1.McpServer]()).
    AddStep(steps.NewCheckDuplicateStep[*mcpserverv1.McpServer](c.store)).
    AddStep(steps.NewBuildNewStateStep[*mcpserverv1.McpServer]()).
    AddStep(steps.NewPersistStep[*mcpserverv1.McpServer](c.store)).
    Build()
```

### 2. Server Type Validation

Validation enforced via buf.validate proto constraints:
- `server_type` oneof is required (exactly one of stdio/http/docker)
- `stdio.command` required
- `http.url` must be valid URI
- `docker.image` required with min_len=1

All validation happens automatically in ValidateProtoStep.

### 3. No OSS-Specific Customization

Unlike the cloud version with tri-scope support (platform, org, identity_account), the OSS version treats all resources as local. This simplification is appropriate for single-user usage.
