## Key Design Decisions

### Decision 1: Single Slug Identifier (UX-First Design)

**Problem Identified:**
Original plan had THREE levels of naming:
1. McpServer's `slug` (e.g., "github")
2. McpServerUsage's `name` (e.g., "gh-read") ← Extra naming!
3. McpAccess's `name` (references the usage name)

This created cognitive overload - users had to name things twice.

**Solution:**
Use ONE slug throughout the entire system:
```
McpServer.slug: "github"
    ↓
Agent.mcp_server_usages[].mcp_server_ref.slug: "github"
    ↓
SubAgent.mcp_access[].mcp_server: "github"
```

**Rationale:**
- Users already named their McpServer with a meaningful slug
- Matches industry patterns (Cursor MCP config, Claude Desktop)
- Eliminates redundant naming
- Cleaner mental model

### Decision 2: McpAccess Instead of Two-Field Pattern

**Problem Identified:**
Original inline design used two coordinated fields:
```protobuf
repeated string mcp_server_aliases = 4;
map<string, McpToolSelection> mcp_tool_selections = 5;
```

Issues:
- Two fields must stay synchronized
- Implicit relationship between fields
- Awkward empty entries for "all tools"

**Solution:**
Single `McpAccess` message combining both concerns:
```protobuf
repeated McpAccess mcp_access = 4;
```

**Benefits:**
- Single field - no coordination needed
- Clear semantics per entry
- Properly models permission hierarchy
- SubAgent can only restrict parent's tools (not expand)

### Decision 3: No Backward Compatibility

**Context:**
Platform is still in development, not in production yet.

**Decision:**
Clean slate - delete all inline definitions, renumber fields sequentially.

**Result:**
- Clean, sequential field numbers (1, 2, 3, 4, 5)
- No deprecated fields
- No technical debt
- Foundation-quality code

## Permission Model Implemented

```
McpServer Resource (external)
    └── McpServerUsage (parent agent declares)
            name: determined by slug
            enabled_tools: [search, create_pr, get_file] (max set)
                └── McpAccess (sub-agent grants)
                        mcp_server: slug reference
                        enabled_tools: [search] (subset only)
```

**Key characteristics:**
- SubAgent can ONLY access parent's MCP servers
- SubAgent can ONLY restrict tools (not expand)
- Clean permission hierarchy enforced by structure

## Learnings

### Design Process Matters

Initial design had complexity (three-level naming). User pushed back asking "Is this the best UX?" 

This prompted complete redesign from first principles:
- How do other tools do it? (researched Cursor, Claude)
- What's the simplest possible model?
- Can we eliminate any cognitive overhead?

Result: Much better design that users will love.

### Simplicity is Hard Work

The final design looks obvious in hindsight:
- One slug, used everywhere
- Single access field instead of two

But it took multiple iterations and critical thinking to get there.

### No Backward Compatibility When Not Needed

Since platform is pre-production, we could delete everything and start clean.

Result: Foundation-quality code with no technical debt.
