## Decisions Made

### 1. Semantic Correctness: `apply` not `push`
**Decision:** Use `apply` for McpServer, not `push`

**Rationale:**
- `skill push` is artifact-based (uploads directory of files, like `git push`)
- `mcpserver apply` is state-based (declares desired state, like `kubectl apply`)
- Follows Kubernetes conventions for declarative resource management
- User requested this alignment after discussion

**Impact:**
- More intuitive for users familiar with Kubernetes
- Clear semantic distinction between artifact publishing and state declaration
- Consistent with existing `stigmer apply` command for agents/workflows

### 2. Auto-Detection Pattern
**Decision:** Auto-detect `mcpserver.yaml` or `MCPSERVER.yaml` in current directory

**Rationale:**
- Follows convention from Docker (`Dockerfile`), Kubernetes (`kubeconfig.yaml`)
- Reduces typing for common case
- Explicit path still supported for non-standard locations

### 3. Smart Reference Resolution
**Decision:** Automatically detect if argument is ID or slug

**Implementation:**
```go
isID := strings.HasPrefix(ref, "mcp-") || strings.HasPrefix(ref, "mcp_") || isUUID(ref)
```

**Rationale:**
- Better UX - users don't need to specify type
- IDs have clear prefixes or UUID format
- Falls back to slug lookup for everything else

### 4. Output Formats for Get
**Decision:** Support table (default), yaml, json output formats

**Rationale:**
- Table: Human-readable for interactive use
- YAML: Configuration-friendly, matches input format
- JSON: Machine-readable for scripts/automation

## Learnings

### 1. YAML to Proto Conversion
- Use `protojson.UnmarshalOptions` with `DiscardUnknown: false` for strict parsing
- Convert YAML to intermediate map, then to JSON, then to proto
- Handle `map[interface{}]interface{}` from YAML parser

### 2. CLI Pattern Consistency
- Follow existing patterns from skill/apply commands
- Use `clierr.Handle()` for all errors (converts gRPC errors to user-friendly messages)
- Use `cliprint` for colored output
- Organization resolution: check override, then context, then config

### 3. Semantic Naming Matters
- `push` implies artifact upload (imperative)
- `apply` implies state reconciliation (declarative)
- Choose command names that match semantics
