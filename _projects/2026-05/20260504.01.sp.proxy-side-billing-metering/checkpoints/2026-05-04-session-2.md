## Key Decisions

- **Separate collection for per-call records** — eliminates race condition with `updateStatus`
- **Integer micros, not float USD** — `provider_cost_micros` and `customer_billable_amount_micros`
- **Explicit trust/source fields** — `UsageMeteringSource`, `UsageTrustLevel` on every record
- **Handle incomplete streams** — `UsageCompletionStatus.STREAM_INTERRUPTED` = not billable
- **Billing signal NOT in updateUsage response** — flows through updateStatus (proxy can't act)
- **Legacy messages kept deprecated** — `UsageMetrics`/`ModelUsage`/`LlmCallMetrics` for wire compat

## Architecture (Final)

```
Proxy observes SSE → updateUsage RPC (operator-only)
    → ComputeAndInsertUsageRecordStep (pricing lookup + insert LlmCallUsageRecord)
    → DebitBillingStep (ExecutionBillingService, non-critical)
    → UpdateExecutionAggregateStep (atomic $inc on status.usage_summary, non-critical)
    → Empty response

Runner calls updateStatus every 2-3s
    → BuildUpdateStatusResponseStep queries billing state → returns signal to runner
```

## Open Questions

- `updateStatus.PersistStep` still does full doc `replaceOne`. It should use `$set` to avoid overwriting `status.usage_summary`. Small scope fix needed (not blocking).
- `customer_billable_amount_micros` is currently set to 0 in the handler (markup is applied inside `ExecutionBillingService`). The per-call record should be updated after billing returns. Consider enriching the record post-debit.
