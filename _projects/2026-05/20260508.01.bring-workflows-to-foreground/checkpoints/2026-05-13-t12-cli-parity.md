## Design Decisions

### DD-T12-001: Execution type auto-detection from ID prefix
Both execution types have distinct ID prefixes (aex_ vs wex_). The CLI auto-routes to the correct API using existing `reference.IsAgentExecutionID` / `IsWorkflowExecutionID` helpers. No `--type` flag needed for ID-based commands.

### DD-T12-002: `stigmer execution` as noun-group (hybrid CLI pattern)
Existing verb-first CRUD stays untouched. The new noun-group handles specialized lifecycle/observability operations. Follows kubectl precedent: verb-first for CRUD + noun-group for resource-specific operations.

### DD-T12-003: `validate` and `diff` as generic top-level verbs
Both auto-detect resource kind from YAML. Extensible to any resource type.

## Learnings

1. `validate.go` already existed with full YAML validation — no need to create T12.6
2. `delete_cancel.go` referenced `execution.CancelWithResult` which didn't exist — had to create `cancel_result.go` to fix pre-existing compilation dependency
3. Function naming collision between `executeCancelExecution` in `delete_cancel.go` and new execution commands — resolved by prefixing new handlers with `run*`
4. Proto field names don't always match intuition — `AgentMessage` has no `GetToolName`, tool calls are in `GetToolCalls()` on AI messages; `SubmitApprovalInput` uses `AgentExecutionId` not `ExecutionId`; deny action is `APPROVAL_ACTION_REJECT` not `DENY`
