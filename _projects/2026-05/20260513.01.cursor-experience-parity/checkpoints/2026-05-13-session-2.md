## Decisions Made

- **Server-reported over URL-based**: The server declares its edition rather than the client guessing from the hostname. This correctly handles reverse proxies, containers, LAN deployments.
- **Unauthenticated RPC**: Marked `is_public = true` so clients can detect edition before login (needed for login page rendering decisions).
- **Graceful fallback**: Both client apps start with URL-based fallback and upgrade asynchronously when the server responds. Older servers that don't implement the RPC keep working.
- **Edition enum, not boolean**: Used `ServerEdition` enum (oss/cloud) rather than a boolean, allowing future editions if needed.
- **PlatformClient on SDK**: Exposed as `client.platform.getServerInfo()` so platform builders can programmatically detect edition.

## Learnings

- The `@AutoGrpcRouterController` annotation in the Java cloud server auto-generates method constants and gRPC routing from the stub class — no manual wiring needed beyond the handler
- The React `useMemo` wrapping of the optional client parameter prevents unnecessary re-fetches while maintaining hook rules compliance
- The existing `ResourceTier` system in protos (open_source vs cloud_only) is a per-resource-kind metadata, while the new `ServerEdition` is a per-server identity — they complement each other
