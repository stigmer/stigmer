## Decisions Made

- **Usage gate removal**: The `mode === "local"` gate in `UsageSection` was incorrect — the OSS server has a complete pipeline at `backend/services/stigmer-server/pkg/domain/agentexecution/controller/get_org_usage_report.go` with validation, execution loading, and report building. No server changes needed.
- **Billing gate kept**: Billing is legitimately cloud-only — the OSS backend has zero billing implementation (no Stripe, no credits). Only the messaging was improved.
- **Workflows desktop parity deferred**: The workflow UI is still under active development in `20260508.01.bring-workflows-to-foreground`. Desktop parity should be part of that project's Phase 1 deliverables (T08-T11).
- **Cloud IAM settings gates confirmed correct**: API Keys, Members, Invitations, Identity Providers, Platform Clients, OAuth Apps — all correctly gated because the OSS Go server has no implementation of those RPCs.

## Learnings

- The `deploymentMode` system is purely URL-based (`localhost` = local, anything else = cloud). Both web and desktop use the same detection — the apparent web-vs-desktop gap was actually a local-vs-cloud gap.
- The OSS Go server has more capability than the frontend exposes. `getOrgUsageReport` was fully implemented but hidden behind a frontend gate.
- `CloudFeatureNotice` is used by 8 settings sections. Only `UsageSection` was incorrectly gated.
