# Session Notes: May 13, 2026 — Session 3

## Accomplishments

- Confirmed Cursor SDK returns real usage data via `onDelta` callback (`turn-ended.usage`: inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens)
- Discovered Cursor SDK streaming bypasses `globalThis.fetch` entirely — the proxy CANNOT observe main agent turns (only sidecar auth/models/analytics calls use fetch)
- Queried prod MongoDB: 47 `llm_call_usage_record` docs exist, all `harness: "native"`, all `customer_billable_amount_micros: 0`
- Found 14 of those belong to Cursor execution sessions — but they're small MCP classifier Haiku calls, not main agent turns
- Commissioned and received Deep Research report on tamper-resistant usage reporting from untrusted runners
- Implemented the Usage MVP: runner-side `onDelta` capture, harness labeling fix, billable persistence fix
- Verified with real Cursor API call: accumulator captures 9,930 input tokens, 30 output tokens, estimated $0.013 — instead of $0.00

## Root Causes Identified

1. **Cursor turns not captured by proxy**: SDK uses internal transport (not `globalThis.fetch`) for main agent streaming. Proxy only sees sidecar calls. Fixed by capturing `onDelta` usage in cursor-runner (DISPLAY_ONLY trust level).
2. **Harness always "native"**: `RecordLlmCallUsageHandler` derived harness from `ModelPricingService`, not from the proxy controller. Fixed by adding `harness` field to `RecordLlmCallUsageInput` and having each proxy controller pass its identity.
3. **Billable amount always 0**: `customer_billable_amount_micros` was set to 0 at insert time and never updated after `DebitBillingStep`. Fixed by writing billable amount back to MongoDB after debit. Backfilled all 47 existing records.

## Decisions Made

- **Runner-reported usage is DISPLAY_ONLY**: Not billing-authoritative per Deep Research findings. Industry consensus: untrusted client telemetry cannot be billing authority. Billing settlement requires Cursor Admin API reconciliation (future work) or Cursor-signed receipts (vendor ask).
- **MVP approach**: Show estimated usage immediately, label as "Estimated". Don't block UX fix waiting for tamper resistance. Phase reconciliation in later.
- **Proto placement**: `RunnerUsageSummary` message in `usage.proto`, field 20 on `AgentExecutionStatus` in `api.proto`.

## Learnings

- Cursor SDK uses internal transport (not fetch) for main agent streaming — discovered via traffic probe test that logged all HTTP calls during a real SDK session
- Proto `int64` maps to `bigint` in TypeScript (protobuf-es), not `number` — needed conversion in accumulator
- MongoDB stores proto int64 as strings (JSON serialization), so `$sum` aggregation on these fields returns 0 — backfill had to use string values
- The `model-pricing.ts` module in cursor-runner already had `computeTurnCost()` wired for tests but not production — no new pricing infrastructure needed
