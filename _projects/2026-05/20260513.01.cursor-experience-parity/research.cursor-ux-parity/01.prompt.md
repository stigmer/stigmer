# Deep Research: Achieving Cursor-Quality UX in a Third-Party AI Agent Platform

## Research Objective

We are building **Stigmer**, an AI agent orchestration platform that wraps the **Cursor TypeScript SDK** (`@cursor/sdk`, public beta since April 29, 2026) and **LangGraph** as execution harnesses. Users interact with Stigmer through a React-based web interface (not the Cursor IDE directly). We want to achieve maximum UX parity with the Cursor IDE experience — including features like chat summarization, planning mode, context management, checkpoints, tool call visualization, and agent observability.

**The core question**: What Cursor IDE UX features can we replicate using the Cursor SDK, what gaps exist, and what do we need to implement natively in Stigmer to close those gaps?

## Known Information (Starting Points)

### Cursor IDE Features We Want to Match

Based on analysis of Cursor's current feature set (as of May 2026):

#### 1. Chat Summarization
- **What Cursor does**: When context window fills, triggers a summarization step. The model generates a "I have summarized the conversation" message, then continues with a fresh context window containing a structured summary (~1,000 tokens).
- **How it works**: Cursor's Composer model is trained via reinforcement learning with "compaction-in-the-loop" (self-summarization). The summary includes: user goal, what was implemented, errors/fixes, next steps.
- **Dynamic context discovery**: Chat history is saved as files that the agent can reference during and after summarization to recover lost details.
- **What Stigmer has**: Session memory extraction (changed files, tool observations, recent turns, decisions, failed attempts, open tasks, durable summary). But NO active summarization during a running conversation — memory is only built after execution completes.

#### 2. Planning Mode
- **What Cursor does**: Users can switch agent mode (Agent mode for full tool access, Plan mode for read-only collaborative design). The mode affects which tools are available and how the agent behaves.
- **What Stigmer has**: No planning mode concept. Sessions run in a single mode with full tool access.

#### 3. Context Window Telemetry
- **What Cursor does**: Shows a circular gauge with breakdown (System prompt, Tools, Rules, Skills, MCP, Subagents, Conversation) and total vs max tokens.
- **What Stigmer has**: Some token info at widget level but no aggregate context state visualization.

#### 4. Checkpoints
- **What Cursor does**: Automatically creates snapshots of the codebase before significant changes. Users can click any checkpoint to preview file state and restore. Stored locally, separate from git.
- **What Stigmer has**: Git-based change tracking (branch_at_deny, head_sha_at_deny for HITL). No checkpoint/snapshot concept.

#### 5. Tool Call Visualization
- **What Cursor does**: Rich display of tool calls — file edits shown as diffs, terminal commands shown with output, search results displayed with snippets, browser screenshots shown inline.
- **What Stigmer has**: Tool calls are captured in `SDKMessage` events with type, args, and results. React SDK displays them but unclear how rich the rendering is.

#### 6. Queued Messages
- **What Cursor does**: Users can queue follow-up messages while the agent is working. Messages wait in line and execute sequentially. Drag-to-reorder supported. Cmd+Enter sends immediately.
- **What Stigmer has**: Unclear if message queuing is supported during active execution.

#### 7. Agent Skills / Dynamic Context Discovery
- **What Cursor does**: Supports the Agent Skills open standard. Skills are files with name/description that the agent can discover dynamically via search. MCP tool descriptions are synced to folders. Terminal sessions are files.
- **What Stigmer has**: MCP server configuration passed to Cursor agents. Skills/rules configured in the session blueprint.

#### 8. Browser Tool
- **What Cursor does**: Agent can control a browser — navigate, interact with elements, take screenshots, verify visual changes.
- **What Stigmer has**: Depends on what MCP servers are configured for the session.

### Cursor SDK Available Data

The SDK streams these `SDKMessage` types:
- `assistant` — AI text responses (content blocks: text, thinking)
- `tool_call` — Tool invocations with name, args, result
- `thinking` — Model reasoning (extended thinking)
- `system` — System messages
- `user` — User messages
- `status` — Run status changes
- `task` — Task/subtask information
- `request` — Request metadata

Low-level `InteractionUpdate` events via `onDelta`:
- `text-delta`, `thinking-delta`, `thinking-completed`
- `tool-call-started`, `tool-call-completed`, `partial-tool-call`
- `token-delta`, `step-started`, `step-completed`, `turn-ended`
- Summary and shell-output deltas

`Run` operations: `stream()`, `wait()`, `cancel()`, `conversation()`

### Our Current Architecture

- **cursor-runner** (TypeScript, Temporal activity) — wraps Cursor SDK, handles streaming, message accumulation, HITL approval, session memory
- **agent-runner** (Go, Temporal activity) — wraps LangGraph for standard harness
- **stigmer-service** (Java) — orchestrates via Temporal workflows, handles execution lifecycle
- **React SDK** (`sdk/react/`) — React hooks and components for rendering sessions, messages, tool calls, streaming
- **Session memory** — Extracted after execution: summary, decisions, failures, changed files, recent turns, tool observations

## Specific Areas to Investigate

### 1. Chat Summarization Implementation
- Can we detect when Cursor's agent performs self-summarization through SDK events? (Is there a specific `SDKMessage` type or `InteractionUpdate` for summarization?)
- If the SDK doesn't expose summarization events, can we implement our own summarization layer?
  - What models/approaches work best for conversation summarization in coding contexts?
  - Should we use the same LLM (e.g., Cursor's model) or a cheaper model for summarization?
  - How do other platforms (ChatGPT, Claude) handle conversation summarization in their APIs?
- Can we trigger Cursor's built-in summarization via the SDK, or is it fully automatic?
- For LangGraph: What are the best practices for implementing conversation summarization in a LangGraph agent?
- What is the optimal summarization trigger? (Token count threshold? Message count? Time-based?)
- How should the summarized content be displayed to the user? (Inline message? Collapsible section? Side panel?)

### 2. Planning / Mode Switching
- Does the Cursor SDK support mode switching (Agent mode vs Plan mode)?
- If not, can we emulate planning mode by:
  - Creating a read-only Cursor agent with restricted tool access?
  - Using a different system prompt that instructs the agent to plan without executing?
  - Switching models (e.g., use a cheaper model for planning)?
- For LangGraph: How can we implement a planning node/subgraph that generates a plan before execution?
- What UI patterns work best for mode switching in an AI agent interface?
- How should plan output differ visually from execution output?

### 3. Checkpoint / Restore Functionality
- Does the Cursor SDK expose checkpoint data from agent runs?
- Can we access the file state at different points during a Cursor agent run?
- For cloud agents: Is there a way to get snapshots of the workspace at different stages?
- What alternative approaches exist for implementing checkpoint/restore in a web-based platform?
  - Git-based checkpoints (auto-commit before significant changes)?
  - File system snapshots?
  - State serialization?
- How should checkpoints be displayed in the UI (timeline, list, tree)?

### 4. Rich Tool Call Rendering
- What data does the Cursor SDK provide for each tool call type?
  - File edits: Do we get before/after content, or just the edit operation?
  - Terminal commands: Do we get real-time output or only the final result?
  - Search results: What format are codebase search results in?
  - Browser actions: Screenshots, page state?
- How can we render diffs, terminal output, and search results in a React web app?
- What existing React libraries support rich code diff rendering, terminal emulation, and file tree visualization?
- How does Cursor handle large tool call results (truncation, pagination, lazy loading)?

### 5. Message Queuing and Immediate Messaging
- Does the Cursor SDK support sending messages while a run is in progress?
- Can we call `agent.send()` while a previous run is still streaming?
- If not, how should we implement client-side message queuing?
- What UI patterns work for showing queued messages and their execution order?
- How does the "Cmd+Enter to send immediately" pattern work technically — does it append to the current run or start a new one?

### 6. Streaming UX Optimization
- What is the optimal way to process and display Cursor SDK stream events in a React web app?
- How should thinking/reasoning tokens be displayed (collapsible, streamed, hidden)?
- What are best practices for handling long-running tool calls (progress indicators, partial results)?
- How should we handle tool call approval (HITL) — inline in the chat flow or as a modal/sidebar?
- What debouncing/batching strategies work best for high-frequency stream events?

### 7. Agent Observability Dashboard
- What metrics should be visible for a running/completed agent session?
  - Token usage over time
  - Tool call count and types
  - Files modified
  - Time spent per step
  - Error count and types
  - Cost breakdown
- How do other AI agent platforms (Cursor, Devin, GitHub Copilot Workspace, Windsurf, Cody) present agent observability?
- What time-series visualization works best for real-time agent monitoring?

### 8. Features Missing from Cursor SDK That Need Native Implementation
- What Cursor IDE features are NOT accessible through the SDK?
- For each missing feature, what is the best native implementation approach?
- Are there SDK feature requests or roadmap items that would close these gaps?
- Should we file feature requests with the Cursor team for specific SDK capabilities?

### 9. Cross-Platform Comparison
- How do competing platforms handle these UX features?
  - **Devin** — Session management, planning, execution visualization
  - **GitHub Copilot Workspace** — Plan-then-execute, diff preview, iteration
  - **Windsurf (Codeium)** — Cascade flow, context management, multi-file editing
  - **Cody (Sourcegraph)** — Context awareness, code search integration
  - **Replit Agent** — Web-based agent UX, deployment integration
  - **v0 (Vercel)** — Component generation, preview, iteration
- What UX patterns are emerging as standards across AI coding platforms?
- What differentiating UX features could Stigmer offer beyond Cursor parity?

## Why This Matters

We're positioning Stigmer as a platform that gives users a "Cursor-quality" AI agent experience through any interface (web, API, SDK), not just the Cursor IDE. Our early adopters are comparing Stigmer's UX directly to Cursor and finding gaps — specifically chat summarization ("I see in Cursor that chat summarization happens, I can see 'Hey, I have summarized a message,' but that does not happen in our case"). We need to close these gaps to retain users and compete with native IDE experiences. The Cursor SDK backend is available — we need to extract maximum value from it and fill remaining gaps with native implementations.
