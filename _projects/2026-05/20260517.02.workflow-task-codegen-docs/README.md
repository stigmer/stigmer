# Per-Task Codegen Reference Documentation

## Goal

Extend the existing `tools/codegen/generator` to auto-generate one MDX documentation page per workflow task kind (20 pages total), so that field-level task reference stays in sync with proto definitions automatically.

## Context

The handwritten workflow documentation was completed in a prior session:

- `docs/concepts/workflows.mdx` -- full concept page (anatomy, resource chain, task categories, execution model, budgets, HITL)
- `docs/getting-started/first-workflow.mdx` -- 5-minute quick start
- `docs/guides/workflows.mdx` -- comprehensive authoring guide (YAML structure, data flow, branching, loops, errors, validation)
- `docs/guides/workflow-tasks.mdx` -- handwritten overview of all 20 task kinds with descriptions, key fields, YAML examples
- `docs/guides/workflow-execution.mdx` -- execution lifecycle (create, monitor, approve, signal, cancel, recover)
- `docs/guides/workflow-patterns.mdx` -- 5 production patterns + anti-patterns

The handwritten `guides/workflow-tasks.mdx` covers "when to use" and key fields per kind but does **not** provide exhaustive field-level reference. That is what this project adds — auto-generated per-task pages with full `<TypeTable>` field tables, nested types, enums, and output shapes.

## Existing codegen pipeline (what to follow)

The SDK resource docs are already auto-generated by the same pattern:

- **Generator entry**: `tools/codegen/generator/main.go` dispatches `--target=sdk-docs` to `runSDKDocsGeneration()`
- **Core logic**: `tools/codegen/generator/sdk_docs.go` reads `tools/codegen/schemas/services/*.json`, loads spec schemas + types, and writes MDX using `<SDKTabs>`, `<TypeTable>`, etc.
- **Task schemas**: `tools/codegen/schemas/tasks/*.json` (one per task kind, e.g. `agentcall.json`, `for.json`, `eval.json`) + `tools/codegen/schemas/tasks/types/*.json` (shared nested types like `catchblock.json`, `evalcriterion.json`, `workflowtask.json`)
- **Task registry**: `tools/codegen/generator/task_registry.go` already loads all task schemas + sidecar YAML metadata (display names, categories, icons, `yaml_examples`, `output_schema`, `field_groups`)
- **Makefile**: `gen-proto-sdk-docs` / `gen-proto-sdk-docs-check` targets exist as the model

The task JSON schemas carry: `name`, `kind`, `discriminatorValue` (YAML kind string), `description` (rich, often with embedded YAML examples), `protoType`, `protoFile`, `fields[]` (each with `name`, `jsonName`, `type`, `description`, `required`, `isExpression`, `validation`, `enumType`, `enumValues`, etc.).

The `TaskKindDescriptor` proto (`apis/ai/stigmer/agentic/workflow/v1/task_kind_descriptor.proto`) has a `documentation_url` field designed to link to these generated pages.

## What to build

### 1. New codegen target: `task-docs`

- Add a new case in `tools/codegen/generator/main.go` for `--target=task-docs`
- New file: `tools/codegen/generator/task_docs.go` (follow the pattern of `sdk_docs.go`)
- Input: `tools/codegen/schemas/tasks/*.json` + `tools/codegen/schemas/tasks/types/*.json` (same data the task registry already loads)
- Output: `docs/guides/workflow-tasks/<kind>.mdx` (one page per task kind) + `docs/guides/workflow-tasks/meta.json` (nav, grouped by category)

### 3. Index page: `docs/guides/workflow-tasks/index.mdx` (generated)

- Grouped by `TaskKindCategory` (AI, Control Flow, Data, Governance, Invocation, Event)
- Card links to each per-task page using `<Cards>` / `<Card>` components

### 4. Makefile integration

- New target: `gen-task-docs` calling `go run ./tools/codegen/generator --comprehensive --target=task-docs --schema-dir tools/codegen/schemas --output-dir docs/guides/workflow-tasks`
- New check target: `gen-task-docs-check` (diff-based, same pattern as `gen-proto-sdk-docs-check`)
- Wire both into `gen-sdk-docs` / `check`

### 5. Wire `documentation_url`

- In the task registry sidecar YAML (or in `task_registry.go` logic), set `TaskKindDescriptor.documentation_url` for each kind to the generated page path (e.g. `/docs/guides/workflow-tasks/agent-call`)
- This makes the `GetTaskKindRegistry` API return doc links that the visual canvas inspector can use to link users to documentation

### 6. Update handwritten pages to cross-link

- `docs/guides/workflow-tasks.mdx`: add links from each task section heading to the generated per-task page (e.g. `[Full reference](/docs/guides/workflow-tasks/agent-call)`)
- `docs/concepts/workflows.mdx`: update "Task types at a glance" table to link to generated pages

## Data flow

```
apis/.../tasks/*.proto
        |
        v  (buf generate + proto2schema)
tools/codegen/schemas/tasks/*.json  +  tasks/types/*.json
        |
        +-- sidecar YAML metadata (display_name, category, yaml_examples, output_schema)
        |
        v  (generator --target=task-docs)
docs/guides/workflow-tasks/<kind>.mdx  +  index.mdx  +  meta.json
```

## Estimated scope

- Generator code: ~300-400 lines of Go (following `sdk_docs.go` patterns)
- Makefile + CI: ~20 lines
- Output: 20 MDX files + 1 index + 1 meta.json (all generated, zero maintenance)
- Cross-linking updates: minor edits to 2 handwritten files

## Success criteria

1. `make gen-task-docs` generates 20 per-task `.mdx` files + `index.mdx` + `meta.json` under `docs/guides/workflow-tasks/`
2. `make gen-task-docs-check` passes (generated files match committed files)
3. Each generated page has: overview, kind string, YAML example, TypeTable for fields, nested types, enums, output shape, see-also links
4. `make site` builds successfully with the new pages in the nav
5. `documentation_url` is populated for all 20 task kinds in the registry
6. Handwritten `workflow-tasks.mdx` and `concepts/workflows.mdx` link to the generated pages
