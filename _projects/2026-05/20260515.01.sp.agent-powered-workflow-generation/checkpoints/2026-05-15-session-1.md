## Decisions Made

- **Keep `taskkindregistry` HTTP handler**: The task kind registry serves the frontend workflow editor independently of LLM generation. Only the LLM wiring that injected it into the workflow controller was removed.
- **Keep `buf/validate/validate.proto` import**: `WorkflowId.value` uses `buf.validate.field` validation, so the import stays.
- **SDK codegen requires separate command**: The top-level `make codegen` does not regenerate `sdk/go/` stubs. `make -C sdk/go codegen` is needed separately.
- **No frontend changes needed**: None of the planned SDK/React/Console deletion targets existed — these features were never built in the UI layer.

## Key Discoveries

- **Subagent file existence reports were unreliable**: Initial automated exploration incorrectly reported that several Go and Java files didn't exist. Manual `ls -la` and `Read` confirmed they were all present. Lesson: verify existence claims directly for critical files.
- **Pre-existing Bazel/Gazelle issue**: `make codegen` fails at the Gazelle BUILD generation step due to a missing `test/integration` BUILD file. This is unrelated to our changes. Proto stubs generate correctly before that step.
- **SDK proto stubs are separate**: The Go SDK maintains its own copy of proto stubs at `sdk/go/proto/`, not shared with `apis/stubs/go/`. The SDK's codegen tool also generates a facade file (`sdk/go/internal/gen/workflow.go`) that must be regenerated separately.
