- Completed WI-1 (Anthropic Prompt Caching) from the Harness Cost Economics project

- Validated all 3 caching layers via code analysis and Anthropic API docs
- Ran `make benchmark-cost` and confirmed 97-100% cache hit rates on the stable prefix (10.8k tokens)
- Fixed CostCapMiddleware to use 4-bucket pricing (regular input, cache creation, cache read, output) instead of the previous 3-bucket formula that undercharged cache writes
- Passed `cache_creation_price_per_million` from ModelRegistry through `setup.py` → `create_deep_agent` → `CostCapMiddleware`

## Decisions Made

- **Layer 3 (extra_body cache_control) is correct**: Anthropic docs explicitly show top-level `cache_control` as the official automatic caching mechanism. No fix needed.
- **Pre-warming skipped**: Adding a `max_tokens: 1` warm-up call would add complexity for marginal latency benefit. Cache writes happen on first real call regardless.
- **CostCapMiddleware: Option A (4-bucket formula) chosen over Option B (document underestimate)**: The data was already available in ModelMetadata, the change was small, and correctness matters even for safety mechanisms.

- `graphton/core/cost_cap.py`: Added `cache_creation_price_per_million` parameter, expanded `_extract_usage` to 4 return values, updated `_compute_call_cost` with proper `regular_input = total_input - cache_creation - cache_read`
