## Learnings

- `ModelSelection` from the Cursor SDK is `{ id: string; params?: ModelParameterValue[] }` — the `id` field is the model slug
- The server's `ModelPricingService.findByModelAndProvider` already tries `apiModelId` then `id`, so Cursor models that match our registry work without changes
- For the "default" (auto-select) model, `RunResult.model?.id` could reveal the actual model Cursor chose — this creates observability into Cursor's routing behavior
- The `COST_CALCULATION_STATUS_ESTIMATED` enum value already existed and is semantically correct for fallback-priced records
