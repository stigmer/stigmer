# Project: 20260503.02.oss-positioning-strategy-shift

## Overview
Shift Stigmer's positioning from 'cloud-primary, OSS as trust signal' to 'OSS-led discovery, cloud-led monetization' — updating website, README, docs, governance docs, community channels, and contribution pathways based on the deep research report on open-source strategy for AI agent platforms.

**Created**: 2026-05-03
**Status**: Active 🟢

## Project Information

### Primary Goal
Reposition Stigmer as 'the open-source infrastructure platform for production AI agents' across all public surfaces — homepage, README, docs, community channels — while keeping cloud as the recommended production path. Establish governance docs, community contribution surfaces, and the open-vs-cloud boundary.

### Timeline
**Target Completion**: 6 weeks — phased: Week 1-2 positioning changes, Week 3-4 governance and community, Week 5-6 content and contributor program

### Technology Stack
Next.js (site), MDX (docs), Markdown, Go (CLI README), TypeScript (SDK docs), GitHub (Discussions, labels), Discord

### Project Type
Feature Development

### Affected Components
site (homepage, pricing, open-source page), docs (concepts, getting-started, guides), README.md, CONTRIBUTING.md, SDK docs, CLI docs, GitHub repo settings (Discussions, labels, templates)

## Project Context

### Dependencies
Research report completed at _projects/2026-05/research.open-source-strategy-for-ai-agent-platforms/04.report.gpt.md. Existing positioning doc at _projects/2026-03/20260331.01.content-strategy/design-decisions/positioning.md. No external blockers.

### Success Criteria
- 1) Homepage hero leads with open-source identity
- not cloud-first. 2) Open Source Philosophy page published. 3) Cloud vs Self-Hosted comparison page published with honest feature boundaries. 4) README rewritten to emphasize OSS-first with local success path. 5) Governance docs published: contribution guide
- security policy
- DCO
- trademark. 6) GitHub Discussions enabled with structured categories. 7) 5 high-quality agent examples published. 8) Public roadmap visible. 9) Positioning doc updated to reflect new strategy.

### Known Risks & Mitigations
1) Messaging change may confuse existing cloud-first prospects — mitigate with hybrid positioning (OSS hero on dev surfaces, cloud hero on sales/enterprise surfaces). 2) Community contribution surfaces need maintainer capacity — start with low-maintenance contribution types (examples, docs, MCP connectors). 3) Internal team alignment needed on what stays open vs. commercial.
