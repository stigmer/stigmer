## Decisions Made

1. **Baggage set in activities, not workflows** — Temporal's `workflow.Context` is deterministic and cannot call OTel APIs. Baggage is set in activity functions where regular `context.Context` is available.
2. **Reused existing `toInt64`** — The `tasks` package already had a `toInt64` helper with a single-return signature; reused it instead of adding a conflicting two-return version.
3. **Deferred Python/TS application spans** — MCP tool calls happen inside `graphton` (a separate library) through LangGraph's `astream_events`, requiring callback-based instrumentation, not direct wrapping. Cursor SDK's `Agent.prompt()` is opaque. Both deferred to follow-up sessions.
4. **Guard baggage with try/catch** — Python and TypeScript baggage calls are wrapped in try/except to avoid breaking the activity when OTel is not initialized.

## Learnings

1. Temporal Go SDK's `workflow.Context` is not a standard `context.Context` — cannot use OTel APIs directly in workflow functions
2. The `tasks` package already had a `toInt64` helper — same package, different file, name collision caught at compile time
3. `LlmCallTaskConfig.Temperature` is `float32` in the proto-generated Go code, requiring explicit cast for `attribute.Key.Float64()`
4. Python `opentelemetry.baggage` module uses `context.attach()` pattern — must call `attach` to make the updated context current
