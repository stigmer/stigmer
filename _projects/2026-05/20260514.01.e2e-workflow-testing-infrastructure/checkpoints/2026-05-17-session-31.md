## Key Decisions

1. **`stigmer.cursor.turn` not `stigmer.llm.call`** — distinct span name for cursor-runner because it represents a coarse-grained Cursor SDK turn, not an individual LLM API call; avoids misleading comparisons in dashboards
2. **LangChain `BaseCallbackHandler` over middleware** — registered on model instance, fires for all LLM calls (including sub-agents, summarization) without interfering with existing graphton middleware (CostCap, LoopDetection, etc.)
3. **Tool-server reverse lookup for MCP span filtering** — only MCP tools in `tool_server_map` produce spans; platform tools (read, write, execute) are excluded since they don't go through MCP servers
4. **Low-cardinality metric attributes** — only `provider`, `model`, `service.name` on metrics; execution_id/session_id stay on traces/baggage to avoid cardinality explosion
5. **ManualReader for test assertions** — in-memory metric reader over Prometheus container; keeps tests fast and avoids another Testcontainer

## Learnings

- LangChain's `on_chat_model_start` (not `on_llm_start`) is the callback for chat models
- Token usage fields differ by provider: Anthropic uses `input_tokens`/`output_tokens`, OpenAI uses `prompt_tokens`/`completion_tokens`
- The cursor-runner files had macOS quarantine xattr that blocked file write tools; shell writes worked as a workaround
- OTel API package (`opentelemetry-api`) is designed as a safe library dependency — returns no-ops when no SDK is configured
