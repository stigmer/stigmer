## Bugs Fixed

### 1. Missing IdentityAccount Seed Data
- **Symptom**: `identity account not found: test-identity-account-id` in RequestPipeline
- **Root Cause**: The `ApiResourceAuditActorCacheProxy` tried to resolve actor info but no IdentityAccount existed in the fresh MongoDB
- **Fix**: Created `IntegrationTestDataSeeder.java` — conditional `@PostConstruct` seeder activated by `stigmer.security.mode=test`

### 2. Protobuf Version Field Type Mismatch
- **Symptom**: `InvalidProtocolBufferException: Expect message object but got: 1`
- **Root Cause**: `metadata.version` is a nested `ApiResourceMetadataVersion` message, not an integer
- **Fix**: Removed the `version` field from the seeder (optional, not needed for test)

### 3. Temporal Workflow Deadlock (Java)
- **Symptom**: Workflow stuck in `EXECUTION_PENDING`, never reached `ExecuteWorkflow` activity
- **Root Cause**: `Workflow.newDetachedCancellationScope(...).run()` executed synchronously, blocking the main thread before `activityScope.run()` could execute
- **Fix**: Changed to `Async.procedure()` for concurrent execution of the pause monitor

### 4. Polyglot Serialization Mismatch (Java → Go)
- **Symptom**: `Error execution ID is required` from Go activity
- **Root Cause**: Java record serialized fields as camelCase (`executionId`), Go struct expected snake_case (`execution_id`)
- **Fix**: Added `@JsonNaming(PropertyNamingStrategies.SnakeCaseStrategy.class)` to Java record

### 5. Protobuf oneof Deserialization Failure
- **Symptom**: `json: cannot unmarshal object into Go struct field ... of type workflowexecutionv1.isWorkflowExecutionEvent_Payload`
- **Root Cause**: Temporal's default JSON converter uses `encoding/json` which can't round-trip protobuf `oneof` fields (Go interface types)
- **Fix**: Pre-serialize events with `protojson` as `[][]byte` before passing through Temporal boundary

### 6. Missing Task Status for Inline Tasks
- **Symptom**: `tasks=1` but `task "setGreeting" not found` — the task was named `"FlushEventsActivity"`
- **Root Cause**: Two issues: (a) `ProgressReportingInterceptor` didn't skip `FlushEventsActivity`, reporting it as a user task; (b) inline tasks like `set_vars` run in-workflow and bypass the interceptor entirely
- **Fix**: (a) Added `FlushEventsActivity` to interceptor skip list; (b) Added `taskMap` to `DoTaskBuilder` that accumulates `WorkflowTask` entries from events and includes them in every flush

## Decisions Made

- **protojson for Temporal boundary**: Any Go struct containing protobuf messages with `oneof` fields must serialize them with `protojson` before crossing Temporal's data converter — `encoding/json` fundamentally cannot handle Go interface types
- **Event-driven task status snapshots**: The `DoTaskBuilder.taskMap` accumulates task status from emitted events and sends the snapshot alongside every event flush — this fills the gap for inline tasks invisible to the interceptor
- **Conditional data seeder pattern**: `@PostConstruct` + `@ConditionalOnProperty` is a clean pattern for bootstrapping test fixture data

## Learnings

- Temporal's Go SDK uses `encoding/json` for non-`proto.Message` types in the default data converter — if a plain struct wraps proto messages with `oneof`, the nested protos break during round-trip
- Java Temporal's `Workflow.newDetachedCancellationScope(...).run()` is synchronous — it blocks the calling thread; use `Async.procedure()` for concurrent execution
- Jackson's default naming strategy for Java records is camelCase, which doesn't match Go's snake_case json tags — explicit `@JsonNaming` annotation is required for polyglot Temporal activities
- The `ProgressReportingInterceptor` only sees Temporal activities, not inline workflow logic — any task that runs synchronously in the workflow thread (set_vars, switch, etc.) needs a separate reporting mechanism
