## Bugs Fixed

### Bug 1: Harness Enum Normalization in Validation Path

**Symptom**: `invalid value for enum field harness: "cursor"` when creating cursor call workflows

**Root cause**: The workflow validation pipeline (test → Java `Apply` → `validateSpec` RPC → Go `UnmarshalTaskConfig` → `protojson.Unmarshal`) requires canonical proto enum names like `HARNESS_CURSOR`, but the test config uses friendly shorthand `"cursor"`. The execution path in `task_builder_call_agent.go:parseConfig()` already normalized this, but the validation path in `unmarshal.go` did not.

**Fix**: Added `normalizeEnumShorthands()` function in `unmarshal.go` that rewrites `"cursor"` → `"HARNESS_CURSOR"` and `"native"` → `"HARNESS_NATIVE"` before `protojson.Unmarshal` for `agent_call` tasks.

### Bug 2: Cursor-Runner Node.js TypeScript Import Failure

**Symptom**: `ERR_UNKNOWN_FILE_EXTENSION: Unknown file extension ".ts"` on cursor-runner startup

**Root cause**: The `@stigmer/protos` package.json exports `.ts` files in dev mode (`"exports": { "./*": "./*.ts" }`). When the harness ran `node dist/main.js`, the compiled JS imports `@stigmer/protos/...` which Node.js resolves to `.ts` files that it cannot load natively.

**Fix**: Changed the cursor-runner harness to use `tsx src/main.ts` (TypeScript eXecute) instead of `node dist/main.js`. Removed the now-unnecessary `ensureCursorRunnerBuilt` function and `build-cursor-runner` Makefile prerequisite.
