## Decisions Made

- **Replay tests live in workflow-runner module** (not integration test module) — they're unit-level and need no infrastructure
- **Activities are NOT registered with the replayer** — Temporal replay only verifies the workflow's command sequence, not activity execution
- **Gold master approach** — histories committed to repo, not generated dynamically in CI
- **Scoped to Go inner workflow only** — Java outer workflow (`InvokeWorkflowExecutionWorkflow`) excluded from T15

## Learnings

1. `WorkflowReplayer` interface only has `RegisterWorkflow*` methods — activities don't need to be registered for replay since replay never executes activity code
2. Proto registration conflict between `apis/stubs/go` and `sdk/go/proto` causes panics when both are imported in the same binary — fixed with `GOLANG_PROTOBUF_REGISTRATION_CONFLICT=warn`
3. Transform task requires `engine` field ("TRANSFORM_ENGINE_JQ"), HTTP call requires `timeout_seconds` (1-300), for_each requires `each` field — discovered via validation errors during capture
4. Temporal's history iterator API (`client.GetWorkflowHistory()`) returns `*historypb.HistoryEvent` values that can be marshaled with `protojson` for replay-compatible JSON
5. Gold master history files are ~22-42KB each — reasonable for git
