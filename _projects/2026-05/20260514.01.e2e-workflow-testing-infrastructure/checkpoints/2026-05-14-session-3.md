## Decisions Made

| Decision | Choice | Rationale |
|---|---|---|
| Suite scope | TestMain starts infra once | 10-15s startup per test is unacceptable for 10+ tests |
| Fixture deployer abstraction level | Thin wrapper, proto types as-is | Proto types ARE the domain types; custom abstraction drifts |
| Assertions approach | Polling-first | Streaming adds lifecycle complexity; deferred to T07 |
| Workflow-runner requirement | Confirmed needed as child process | Java dispatches ExecuteWorkflow activity to Go runner task queues |
| WorkflowExecution creation | Use spec.workflow_id shortcut | Auto-resolves to default instance; skip explicit instance creation for simple tests |

## Learnings

1. `WorkflowExecutionSpec` supports `workflow_id` directly (without explicit instance) — system auto-creates default instance
2. `WorkflowExecutionStatus` has no `GetCompletedTasks()`/`GetTotalTasks()` — count from `GetTasks()` slice
3. The workflow-runner has no port to health-check — it's a Temporal worker polling task queues; just verify process is still alive after startup
4. `WorkflowExecution.delete()` takes `ApiResourceId` (not `WorkflowExecutionId`) — different from `get()` which takes `WorkflowExecutionId`
