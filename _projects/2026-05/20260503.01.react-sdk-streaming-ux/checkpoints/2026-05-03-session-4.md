## Decisions Made

1. **React.memo over store-backed subscriptions**: The original T05 plan proposed each `ThreadRow` subscribing to the `ConversationStore` independently. Rejected because the store holds domain state (`AgentExecution`) while thread items are presentation — conflating the two layers violates domain purity. `React.memo` achieves the same optimization outcome with zero new abstractions. Store-backed subscriptions deferred to T11 where virtualization demands per-row independent data access.

2. **Custom `areEqual` for ToolCallGroup**: `buildThreadItems` creates a new `regularTools` subset array (filtering `task` calls), so the array container is always new even when individual ToolCall objects are stable. Custom `toolCallGroupPropsEqual` compares elements by reference. Optimization: when no `task` tools exist (common case), `msg.toolCalls` is passed directly, making custom comparison unnecessary.

3. **ApprovalCardRow extraction**: The `onSubmit` prop on `ApprovalCard` was an inline closure in `MessageThread`'s render loop — new function per render, defeating `React.memo`. Extracted a memoized `ApprovalCardRow` wrapper that receives stable `onApprovalSubmit` + `toolCallId` and composes the callback via `useCallback`. This avoids changing `ApprovalCard`'s public API.

## Learnings

- `React.memo` with structural sharing is a powerful combination. The structural sharing from T04 guarantees reference stability for unchanged entities, and `React.memo` exploits this to skip re-renders. No store subscription infrastructure needed.
- The `buildThreadItems` function creates new wrapper objects (`ThreadItem`) on every call, but the domain objects inside them (message, toolCalls, subAgentExecution) ARE stable. `React.memo` on the leaf components compares these inner props, not the wrapper.
- Inline closures in render loops are the primary enemy of `React.memo`. The `ApprovalCardRow` extraction pattern is the standard fix: extract a component that receives stable props and composes the callback internally.
