## Decisions Made

- **Challenged the original T08 plan** — rejected TanStack Query in Console (deep SDK composition makes it impractical), rejected cache in ConversationStore (wrong responsibility), rejected TanStack Query adapter export (premature)
- **Chose SDK-level FetchCache** — lightweight cross-mount data survival layer, no new dependencies, benefits all 27+ useFetch consumers
- **Kept `key={activeSessionId}`** — correct React pattern for clean state reset; cache makes it fast for revisited sessions
- **Scoped to two hooks** — only `useSession` and `useSessionExecutions` get cache keys in T08; other hooks can be added incrementally
- **Exported `FetchCacheContext`** for test-level injection — tests need to share a cache instance across independent `renderHook` calls to simulate cross-mount behavior

## Learnings

- Each `renderHook` call creates an independent React tree — `useRef`-based providers don't share state across trees; tests need direct context injection with a shared instance
- `Map` insertion order in JS provides free LRU semantics: delete-then-set moves a key to the tail, iterator yields oldest first
- The `useState` initializer function is the correct hook for cache seeding — runs once on mount, before the first render
