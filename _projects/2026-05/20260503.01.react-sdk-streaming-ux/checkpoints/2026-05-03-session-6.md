## Decisions Made

1. **Streamdown for AiMessage only (not all markdown consumers)**: `SkillDetailView` and `ArtifactContentRenderer` render static, complete markdown — `react-markdown` is fine for them. Streamdown is only needed where content streams incrementally. This keeps the blast radius minimal. Future migration possible via `mode="static"`.

2. **Keep `react-markdown` and `remark-gfm` as dependencies**: Still consumed by `SkillDetailView`, `ArtifactContentRenderer`, and the shared `markdown-components.tsx` type import. Removing them is out of T07 scope.

3. **Use Streamdown's built-in block caret instead of custom pulsing bar**: The old caret was a 2px `<span>` with `animate-pulse`. Streamdown's `caret="block"` renders `▋` (U+258B) as a CSS `::after` pseudo-element. This is the standard AI chat pattern (ChatGPT, Claude). No extra DOM element, no animation spans. Appears only when `isAnimating` is true.

4. **No word animation in T07**: Streamdown offers per-word fade-in via the `animated` prop (separate from `isAnimating`). Deferred to T12 (Animation & Polish). T07 only enables the streaming-aware parsing pipeline.

5. **No Streamdown plugins in T07**: `@streamdown/code` (Shiki), `@streamdown/math` (KaTeX), `@streamdown/mermaid` are all out of scope. Our existing CSS-only code styling via `MARKDOWN_COMPONENTS` is preserved.

## Learnings

- Streamdown's `Components` type and `react-markdown`'s `Components` type are structurally compatible. The `MARKDOWN_COMPONENTS` object (typed as `import type { Components } from "react-markdown"`) passes TypeScript's structural type check when assigned to Streamdown's `components` prop. No type assertion needed.
- Streamdown hoists to root `node_modules` in a monorepo workspace — the `@source` directive path needs to account for this. Using `../node_modules/streamdown/dist/*.js` from `sdk/react/src/styles.css` resolves correctly.
- `@testing-library/react` in vitest + happy-dom does not auto-cleanup between tests. Explicit `afterEach(cleanup)` is needed, or use container-scoped queries instead of `screen.*`.
