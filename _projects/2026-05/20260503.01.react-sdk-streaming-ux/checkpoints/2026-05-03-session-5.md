## Decisions Made

1. **Optional store parameter (not context-based)**: `useExecutionStream(id, { store })` accepts an external store for shared usage. When omitted, creates an internal fallback store automatically. This preserves backward compatibility for standalone usage while enabling `useSessionConversation` to share its store instance. Context-based injection rejected because it creates implicit coupling and forces every consumer to have a provider ancestor.

2. **Standalone StreamController class**: Placed in `sdk/react/src/internal/stream-controller.ts` rather than inlined in the hook. Follows the same pattern as `ConversationStore` (pure class + React hooks that wire it). Enables unit testing without renderHook/act/waitFor overhead. Reusable if multi-execution streaming is needed later.

3. **startTransition wrapping store mutations**: The rAF callback calls `startTransition(() => store.ingestSnapshot(buffered))`. This marks the resulting `useSyncExternalStore` re-render as non-urgent. React can interrupt thread renders for urgent work (composer typing). Safe because the store is the truth and the next frame's flush will deliver the latest data.

4. **Terminal snapshots bypass rAF**: When a terminal phase (complete/failed/cancelled/terminated) arrives, the snapshot is flushed immediately to the store without waiting for the next rAF callback. No 16ms delay for the "done" state.

## Learnings

- `useStreamRate()` returns a new object per render (ref-backed internal state but unstable container). Including ref-unstable values in effect deps creates infinite loops when the effect triggers re-renders via external store mutations. Solution: store in a stable `useRef` and read via `.current`.
- `startTransition` + `useSyncExternalStore` works correctly together — the store mutation triggers listeners synchronously, but React processes the re-render as non-urgent. No tearing issues.
- In vitest jsdom environment, `requestAnimationFrame` is a `setTimeout` shim and works correctly for rAF-based coalescing tests. Fake timers (`vi.useFakeTimers()`) conflict with React's internal scheduler when `startTransition` is used — avoid them for hook integration tests.
