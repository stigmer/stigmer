# Deep Research: deepagents JS + LangGraph JS Feasibility for Python-to-TypeScript Agent Runner Migration

## Research Objective

We are migrating a production Python agent-runner service to TypeScript. The Python service is built on:
- **`deepagents` Python SDK** (v0.4.0) — provides `create_deep_agent`, middleware hooks, sub-agent delegation, MCP tool loading, and agent lifecycle management
- **`graphton`** — our internal Python library (37 modules) built on top of deepagents Python and LangGraph Python, providing middleware like loop detection, execution budgets, tool truncation, graceful stop, cost caps, HITL approval wrappers, MCP tool management, summarization, and more
- **LangGraph Python** — provides checkpointers (MemorySaver, MongoDB) and the `interrupt()` / `Command(resume=...)` mechanism for human-in-the-loop (HITL) flows

We need to determine whether **`deepagents` npm package** (JavaScript/TypeScript) and **`@langchain/langgraph` JS** provide sufficient capabilities to replace the Python stack.

## Known Starting Points

- `deepagents` npm package exists (we believe v1.10.2 or similar)
- `@langchain/langgraph` JS exists as a published npm package
- `@langchain/langgraph-checkpoint-mongodb` may exist for MongoDB checkpointing
- LangGraph JS has been catching up to Python feature parity but historically lagged

## Specific Areas to Investigate

### 1. deepagents JavaScript/TypeScript SDK

- **What is the current version and release cadence?** Is it actively maintained?
- **Core API**: Does it have `createDeepAgent` (or equivalent)? What parameters does it accept — `checkpointer`, `subagents`, `middleware`, `backend`?
- **Middleware system**: Does it support `AgentMiddleware` with lifecycle hooks like `beforeAgent`, `afterStep`, `beforeToolCall`? Can middleware be composed/chained?
- **MCP integration**: How does MCP (Model Context Protocol) tool loading work? Is there an `McpToolsLoader` equivalent? Does it support stdio and SSE transports?
- **Sub-agent delegation**: Can agents spawn sub-agents with scoped tools and instructions? Is there a `task` tool for delegation?
- **Streaming**: What is the streaming API? Does it provide `streamEvents` or an equivalent that emits tool calls, assistant messages, and token-level events?
- **HITL / Approval**: Is there a built-in interrupt/approval mechanism for tool calls?
- **Known limitations or gaps** compared to the Python deepagents SDK

### 2. LangGraph JavaScript/TypeScript

- **Current version and maturity** compared to LangGraph Python
- **Checkpointers**: Does `@langchain/langgraph` have `MemorySaver`? What about persistent checkpointers — MongoDB (`@langchain/langgraph-checkpoint-mongodb`), PostgreSQL, SQLite?
- **HITL mechanism**: Does LangGraph JS support `interrupt()` and `Command({ resume: ... })`? How mature is this compared to Python?
- **Custom checkpointers**: Can we implement a custom HTTP-based checkpointer that proxies to our platform API?
- **Compatibility with deepagents JS**: Do LangGraph JS checkpointers work with deepagents JS's `createDeepAgent`?
- **Known issues**: Any community-reported bugs or limitations with checkpointers, interrupt/resume, or streaming in LangGraph JS?

### 3. Python → JS Migration Experiences

- Has anyone in the community migrated a LangGraph Python agent system to JavaScript/TypeScript? What were the pain points?
- Are there known feature parity gaps between LangGraph Python and LangGraph JS as of 2026?
- What middleware/capabilities commonly need to be rebuilt when moving from Python to JS in the LangChain ecosystem?

### 4. Ecosystem & Community Health

- How active are the GitHub repositories for deepagents JS and LangGraph JS?
- What is the issue/PR activity like? Are bugs being addressed promptly?
- Are there alternative JS agent frameworks we should consider if deepagents JS is insufficient (e.g., Vercel AI SDK, mastra, etc.)?

## Context for Why This Matters

This is a **hard gate decision**. If the JS ecosystem can't support our needs, we either:
- Wait for upstream improvements
- Contribute the missing pieces upstream
- Abort the migration and keep the Python service

The migration would eliminate Python from our agent execution path, unify two separate TypeScript and Python services into one, simplify our sandbox Docker image, and reduce operational complexity. But we won't proceed unless the JS ecosystem is ready.
