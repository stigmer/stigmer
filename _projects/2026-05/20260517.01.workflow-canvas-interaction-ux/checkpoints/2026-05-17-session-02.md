## Decisions Made

- **`@base-ui/react/popover`** as the popover primitive: MIT license (DD-012), headless-first (DD-003), no framework deps (DD-004). Already a peer dependency but first actual usage in the SDK. Pattern matches `ContextPopover` and `ModelSelector` in the composer module.
- **Per-node popover state** (DD-T02-002): Each node owns its own `useState<boolean>` + `useRef`. Base UI Popup doesn't mount DOM when `open=false`, so 50 idle nodes have zero DOM cost. Simpler than lifting to a shared singleton at the editor level.
- **`anchor` prop on `Popover.Positioner`** (not `Popover.Anchor` component): Base UI v1.3.0 does not export `Popover.Anchor`. The `anchor` prop on `Positioner` accepts a `RefObject<Element | null>` directly. Also, the prop is `align` not `alignment`.
- **Edge "+" button stays visible while picker is open**: Added `pickerOpen` to the visibility condition (`hovered || selected || pickerOpen`) so the button doesn't disappear when the user is choosing a task type.

## Learnings

- Base UI v1.3.0 API differs from docs: no `Popover.Anchor` export, use `anchor` prop on `Positioner`. The `alignment` prop is named `align`. Always read the actual `.d.ts` files from `node_modules` before coding.
- The `Popover.Positioner` `anchor` prop accepts `React.RefObject<Element | null>` directly — no need for a wrapper component or callback ref.
- `useStigmerPortalContainer()` is the canonical way to portal Base UI content so it inherits `--stgm-*` tokens (including dark mode). Matches existing `ContextPopover` pattern.

## Open Questions

- The task picker currently shows all 20 task kinds in a flat categorized list. For workflows with many common patterns, we may want to show "recently used" or "suggested" kinds at the top — defer to user feedback.
