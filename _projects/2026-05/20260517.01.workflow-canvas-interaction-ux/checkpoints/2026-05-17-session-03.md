## Decisions Made

- **`@base-ui/react/menu`** (not `@base-ui/react/context-menu`): React Flow provides `onNodeContextMenu`/`onEdgeContextMenu`/`onPaneContextMenu` callbacks with precise hit detection. Using controlled `Menu.Root` with virtual anchor avoids DOM wrapper interference with React Flow's layout.
- **Virtual anchor positioning**: `Menu.Positioner` receives a `VirtualElement` with `getBoundingClientRect()` returning the right-click coordinates. Same pattern for the pending `TaskPickerPopover`.
- **No edge duplication on duplicate**: Only the node and its config are cloned. Duplicating edges would create ambiguous graph topology. Matches n8n and Retool behavior.
- **Config deep-clone via `structuredClone`**: Safe deep copy of JsonObject configs without manual traversal.
- **Two-step picker flow via `pendingPicker` state**: Context menu item sets `pendingPicker = { purpose, sourceId?, position }`, which triggers a `TaskPickerPopover` at the stored coordinates. Single render cycle transition.
- **Copy/Paste deferred**: Clipboard support is substantially more complex (serialization format, Ctrl+V, multi-node). Deferred to T07 or beyond.
- **`modal={false}` on Menu.Root**: Non-modal menu allows interaction with canvas while menu is open, matching native OS context menu behavior.

## Learnings

- React Flow's `onPaneContextMenu` signature includes `MouseEvent | React.MouseEvent` (union with native MouseEvent), not just `React.MouseEvent`. Must match the wider type in both the inner component props and the editor handler.
- Base UI's `Menu.Positioner` accepts `VirtualElement` (from Floating UI) on its `anchor` prop — same as `Popover.Positioner`. A simple object with `getBoundingClientRect()` returning click coordinates works for context menu positioning.
- For the two-step picker flow, creating a detached `HTMLButtonElement` with overridden `getBoundingClientRect` satisfies `React.RefObject<HTMLElement | null>` type constraint while providing virtual positioning.
