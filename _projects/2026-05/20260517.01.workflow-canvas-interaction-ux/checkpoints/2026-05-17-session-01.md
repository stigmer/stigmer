## Decisions Made

- **CSS-only hover visibility**: Used Tailwind `group`/`group-hover:` instead of React state (`useState`/`onMouseEnter`) to avoid re-renders across the node tree. Critical for 50+ node performance.
- **Simple append for "+" button**: When clicking "+" on a node that already has outgoing edges, the new node is added as an additional successor (new edge appended). The existing edge is NOT replaced or spliced. This matches drag-from-palette behavior and keeps T01 simple. Refinement deferred to T02 when the task picker lands.
- **Hardcoded `agent_call` for "+"**: The quick-add button creates an `agent_call` task by default. T02 will introduce a `TaskPickerPopover` to let users choose the task type.
- **Button positioning**: Delete at top-right (`-right-2 -top-2`), "+" at bottom-center (`-bottom-3 left-1/2`). Matches the visual language of the existing edge "+" button in `CanvasTransitionEdge`.
- **Sentinel nodes excluded**: Start/End nodes render via the separate `SentinelNode` component and do not get hover actions.

## Learnings

- The existing `insertTaskOnEdge` implementation is a reliable template for new node-creation methods — same pattern of CompoundCommand + rAF layout + selection
- React Flow's `NodeProps` provides `id` as a top-level prop, making it straightforward to access the node identifier for action dispatch
- The `group`/`group-hover:` Tailwind pattern works well for per-node hover affordances without any performance penalty
