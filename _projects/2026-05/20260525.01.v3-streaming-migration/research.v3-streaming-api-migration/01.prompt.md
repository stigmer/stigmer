# Deep Research: LangGraph streamEvents v2 → v3 Migration for an Agentic AI Platform

## Research Objective

We are building **Stigmer**, an open-source agentic AI platform that runs LLM-powered agents orchestrated by Temporal workflows. The agent execution runtime (TypeScript) uses **deepagents** (v1.10.2) — a library built on top of **@langchain/langgraph** (v1.3.2) and **@langchain/core** (v1.1.47) — to create and stream ReAct-style agents with tool calling capabilities.

We are currently consuming the LangGraph streaming API at **v2** (`streamEvents(input, config, { version: "v2" })`), which returns an `AsyncIterable<StreamEvent>` of LangChain callback-style events. We need to migrate to **v3** (`streamEvents(input, config, { version: "v3" })`) which returns a `GraphRunStream` object with structured sub-streams (`run.values`, `run.output`, `run.updates`, `run.subagents`).

This migration is critical because:
1. **Structured output extraction is broken on v2** — The agent's `structuredResponse` (produced by a `generate_structured_response` graph node) is stored as a LangGraph `UntrackedValue` that is never checkpointed and is invisible to v2 streaming events. v3's `run.output` resolves to the full in-memory state including `structuredResponse`.
2. **We may be missing data/signals that v3 exposes** — v3 introduces protocol-level events, per-node state updates, subagent streams, and potentially richer metadata that we're not capturing today.
3. **deepagents' stream transformers only activate fully in v3** — The library applies custom stream transformation logic for v3 that is skipped in v2 mode.

We need a comprehensive technical report covering the v3 API surface, migration patterns, pitfalls, and any additional capabilities we should be capturing for our users.

## Our Current Architecture (What We Have Today on v2)

### Streaming Pipeline

Our runner service has a streaming execution loop that:

1. **Calls** `agentGraph.streamEvents(input, config, { version: "v2" })` → gets `AsyncIterable<StreamEvent>`
2. **Iterates** each event through a `StatusBuilder` that maps LangChain callback events to a protobuf `AgentExecutionStatus` structure
3. **Persists** status updates to the backend server on a schedule (hybrid time + event threshold: 500ms min interval, 5s max interval, 50-event burst threshold)
4. **Handles** Temporal heartbeats (every 2s), stall detection (120s timeout), cancellation checks, and a graceful STOP signal from the platform
5. **Triggers** inline artifact publishing and incremental git writeback on file-modifying tool completions (`on_tool_end` events)
6. **Processes** post-stream operations (artifact upload, writeback completion)

### v2 Event Types We Currently Consume

Our `StatusBuilder` maps these v2 LangChain callback events to protobuf status:

| v2 Event | What We Extract |
|----------|----------------|
| `on_chat_model_stream` | Token-by-token text streaming + thinking blocks (Anthropic extended thinking). Content is appended to AI messages, thinking to separate thinking messages. |
| `on_chat_model_end` | Mark message streaming as complete. Extract `usage_metadata` (input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens) for real-time usage tracking. |
| `on_tool_start` | Create tool call records with name, args, approval policy checks. Triggers WAITING_FOR_APPROVAL phase if tool requires human approval. |
| `on_tool_end` | Mark tool as completed/failed, extract result (truncated to 50K chars). Trigger inline publish + writeback for file-modifying tools. |

Events we receive but currently **ignore**: `on_chain_start`, `on_chain_end`, `on_llm_end`.

### Data We Surface to Users

Through our React SDK and web UI, we show users:
- **Real-time token streaming** with thinking/reasoning separation
- **Tool call timeline** with names, arguments, status, results, approval gates
- **Token usage metrics** (input, output, cache read, cache write, per-turn and cumulative)
- **Execution artifacts** (files created/modified during execution)
- **Workspace writebacks** (git commits pushed back to user's repo)
- **Execution phases** (IN_PROGRESS, WAITING_FOR_APPROVAL, PAUSED, COMPLETED, FAILED, TERMINATED)

### The Structured Output Problem

When a user provides a JSON schema for structured output:
1. `createDeepAgent` receives a `responseFormat` (Zod schema)
2. Internally, LangGraph adds a `generate_structured_response` node that calls `model.withStructuredOutput(responseFormat)` (Anthropic's function calling with an `extract` tool)
3. The result is stored as `{ structuredResponse: parsedResult }` in the agent state
4. **Problem**: `structuredResponse` uses `Annotation<T>` without a reducer — it's an `UntrackedValue` that is NEVER written to checkpoints
5. **Problem**: v2 `streamEvents()` returns callback events but no final state object — there's no way to access the in-memory state
6. **Problem**: `getState()` reads from checkpoints, which have already stripped the `UntrackedValue`
7. **Problem**: The `generate_structured_response` node's events are completely filtered out by deepagents' stream transformers — zero events containing the structured data are visible

**Result**: Structured output is completely inaccessible in v2 mode. We've confirmed this through extensive debugging:
- `getState()` returns keys: `messages, todos, files, _summarizationSessionId, _summarizationEvent` — no `structuredResponse`
- Root `on_chain_end` returns the same keys — no `structuredResponse`
- Zero events across all event types contain anything related to `extract` or structured response

## Technical Context for Reference

**Versions**:
- deepagents: 1.10.2
- @langchain/langgraph: 1.3.2
- @langchain/core: 1.1.47
- Runtime: Node.js (TypeScript)
- Orchestration: Temporal (heartbeats, cancellation, checkpointing)
- Protobuf: @bufbuild/protobuf (ConnectRPC)

**Key deepagents APIs we use**:
- `createDeepAgent({ model, checkpointer, backend, systemPrompt, tools, middleware, subagents, responseFormat })` — creates the agent graph
- `agentGraph.streamEvents(input, config, { version: "v2" })` — streaming execution (what we're migrating FROM)
- `agentGraph.getState(config)` — checkpoint state retrieval (for HITL interrupt detection)

**Our streaming StatusBuilder maps events to a protobuf schema** (`AgentExecutionStatus`) that includes:
- Execution phase tracking
- AI messages with token-by-token streaming
- Thinking/reasoning messages (Anthropic extended thinking)
- Tool call lifecycle (start → running/waiting_approval → completed/failed)
- Token usage accumulation (input, output, cache read, cache write)
- Execution artifacts
- Workspace writebacks
