## Decisions Made

- **DD-T05D-001**: `useSkillDiff` takes artifact storage keys directly (not version hashes). Consumer does hash-to-key lookup via `getArtifactKey()`.
- **DD-T05D-002**: `diff` (jsdiff) as a direct dependency (~8KB gzip, MIT). Provides `structuredPatch()` for hunk-level unified diffs.
- **DD-T05D-003**: Multi-file diff with file navigation (GitHub PR-like). Summary bar + file list + per-file unified diff. SKILL.md prioritized in sort order.
- **DD-T05D-004**: Shared `fetchAndUnpackArtifact()` utility extracted. `useSkillArtifact` refactored to use it. Zero regression.
- **DD-T05D-005**: Unified diff only in v1. Side-by-side deferred — `DiffViewer` accepts `mode` prop for future extension.
- **DD-T05D-006**: Compare-mode UX — info bar with cancel button, first-selection dashed border + "A" badge.
- **Theme tokens inherit**: Diff tokens defined in `tokens.css` only (not per-preset) — semantic meaning is universal like status colors.

## Learnings

- Diff tokens don't need per-preset overrides — green/red carry universal meaning like destructive/success
- jsdiff v8 ships its own TypeScript types (no @types/diff needed)
- The `fetchAndUnpackArtifact` extraction made the useSkillDiff implementation trivially clean — parallel `Promise.all` with two calls
- `VersionTimelineEntry` already had `isSelected` but needed `isCompareSource` as a distinct visual state — dashed border vs solid provides clear affordance

## Open Questions

- Historical artifact storage on the backend: if old artifacts are garbage-collected, diff will show a clear error — need to confirm retention policy
- Side-by-side diff mode deferred to future — `DiffViewer` already accepts `mode` prop as extension point
