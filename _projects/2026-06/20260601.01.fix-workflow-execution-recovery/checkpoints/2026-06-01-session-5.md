## Decisions Made

- **Helper extraction over naive append**: The existing Go code had `return nil` on NOT_FOUND at line 649, which would skip child termination if code was naively appended. The fix required restructuring the function into a helper + two calls.
- **Same step, not a new step**: The step's contract is "clear old Temporal state so recovery can proceed." Orchestrator and child are parts of the same execution tree — splitting into two steps would introduce implicit coupling.
- **Orchestrator first, then child**: Terminates the parent first (stops any further signal relaying), then hard-terminates the child regardless of ParentClosePolicy timing.
- **Helper naming convention**: Go uses `terminateWorkflow` (unexported method on the step). Java uses `terminateWorkflowIfExists` (private method). Both return nil/null on success (including NOT_FOUND), error/failure result on real failure.
- **Follows recreateExecutionContextStep precedent**: That step already extracts `deleteStaleEC` and `resolveEnvironments` as private helpers for sub-operations.
- **Test fake over mock framework (Go)**: A minimal `fakeTemporalClient` struct with a `calls` slice and `errors` map is simpler and more readable than pulling in a mock framework. Follows the codebase convention of no existing Temporal client mock.
- **Stale cleanup included**: Removed broken `CTX_NEW_RUN_ID`/`CTX_RESET_EVENT_ID` references in Java test (deferred since Session 3). Also removed unused `StepResult` import.

## Learnings

- No existing codebase precedent for multi-workflow termination in a single step — T06 sets the pattern. Agent execution uses a flat model (no child workflow), so its cancel/terminate only targets one workflow ID.
- The Go controller test package has a pre-existing broken file (`update_status_test.go`) with a stale import (`backend/libs/go/grpclib/pipeline` — should be `backend/libs/go/grpc/request/pipeline`). This prevents `go test ./...` from running on the full package. Not related to T06.
- The Java test target has a pre-existing Bazel strict-deps issue with `ObjectMapper` in `WorkflowInputTests`. Not related to T06.
- `WorkflowIDReusePolicy` is not explicitly set on the child workflow options (uses Temporal default: `ALLOW_DUPLICATE` — requires previous run in terminal state). This is why explicit child termination is necessary for the workflow ID to be reusable.
