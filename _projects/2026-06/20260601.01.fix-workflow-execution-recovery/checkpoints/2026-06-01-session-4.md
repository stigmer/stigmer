## Decisions Made

- **`useRef` over `useState` for previous phase tracking**: The transition drives an effect-time side effect (store mutation + gRPC subscription), not a rendered value. This is distinct from the `useState`-based "adjust state during render" pattern used in `useSessionInspector` and `ExecutionInspector` for synchronous tab switching.
- **No store reset in effect cleanup**: Intentionally different from `useExecutionStream` (agent execution). The workflow event stream's effect deps include `connectKey` (reconnect counter). Resetting on cleanup would destroy accumulated events when the user clicks Reconnect — wrong behavior for an append-only event store.
- **Post-reset subscription from sequence 0**: After `store.reset()`, `getLatestSequence()` returns 0. `subscribeEvents(afterSequence: 0)` replays the full event history (old run + new run). `deriveTaskStates` processes in sequence order so the last event per task wins. This is correct: `task_skipped` events override old `task_completed`, `task_started` overrides old `task_failed`.
- **`isRecoveryTransition` not barrel-exported**: Follows the `computeFollowCenter`/`computeFollowSelection` precedent — exported from the hook file for direct test imports, not re-exported from `workflow/index.ts`. It's a testing helper, not public SDK API.

## Learnings

- The codebase has two distinct patterns for tracking value transitions: `useState` for render-time decisions (tabs) and `useRef` for effect-time decisions (subscriptions). The choice is not stylistic — it follows from the timing requirement.
- `useFetch` with `cacheKey` preserves stale data during refetch (stale-while-revalidate), so the phase transitions atomically from FAILED to IN_PROGRESS without an intermediate `undefined`. No race condition possible.
- `vi.fn(async function* () {})` produces a typed mock with empty tuple args. Accessing `mock.calls[0][0]` requires a cast through `unknown[][]` to avoid TypeScript tuple length errors in strict mode.
