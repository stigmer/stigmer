## Decisions Made

- **climsg stays format-agnostic**: `--json`/`--quiet` flags control Command Result formatting only, not operational progress. climsg writes to stderr in all modes. This follows bounded context separation — format flags belong to the Command Result context, not the Operational Progress context. Consistent with Unix conventions (kubectl, docker emit progress to stderr alongside structured stdout).
- **handleLLMPull warning paths use CommandResult for all modes**: Migrated from bare climsg to CommandResult+Renderer even in human mode, matching `handleLLMList` patterns. Visual output is equivalent (styled text to stderr), code is cleaner.
- **handleServerStart human mode unchanged**: The server start flow is complex with many climsg calls during the operation. Human mode preserves the exact existing UX. Only the final output section (PID/port/data) branches on format.
