## Decisions Made

- **Safety-first validation**: Validation runs in Python before ANY extraction regardless of mode — ensures consistent safety for both Daytona and local
- **File-by-file extraction (local)**: Uses `zipfile.ZipFile.open()` per entry, not `extractall()`, to maintain safety guarantees from validation
- **Daytona follows skill_writer pattern**: Upload zip as `__attachment__.zip`, batch upload, then `unzip -o` + cleanup — consistent with established codebase patterns
- **Return type `list[tuple[str, int]]`**: Validation function returns `(path, uncompressed_size)` tuples so both extraction modes can report accurate file sizes in `injected_files`
- **Three helper functions**: Extracted `_validate_zip_for_extraction`, `_extract_zip_local`, and `_prepare_daytona_extraction` to keep `inject_attachments()` readable
- **No changes to resume fast-path or system prompt**: Both already handle directory mount_paths correctly

## Learnings

- `skill_writer.py` uses `zf.extractall()` without path traversal protection — acceptable for trusted platform artifacts but a known concern. Our implementation intentionally avoids this pattern for untrusted user attachments.
- The Daytona batch upload API (`sandbox.fs.upload_files()`) can include both regular files and zip archives in the same batch — the post-upload extraction step only applies to zip entries.
- `os.path.normpath()` combined with a `.startswith("..")` check is the standard Python approach for path traversal detection.
