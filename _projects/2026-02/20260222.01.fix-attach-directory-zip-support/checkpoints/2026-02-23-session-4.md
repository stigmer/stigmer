## Decisions Made

- **Unit tests over E2E**: True end-to-end testing requires a live gRPC server, artifact storage, and Daytona sandbox — belongs in CI/CD. Unit tests for the safety-critical pure functions provide the most value now.
- **Fake daytona module via sys.modules**: `inject_attachments()` does a dynamic `from daytona import FileUpload` inside the function body. Used a pytest fixture that injects a fake daytona module into `sys.modules` for clean Daytona mode testing.
- **Platform-aware MIME type tests**: Go's `mime.TypeByExtension` reads OS MIME databases (platform-dependent). Tests assert exact values only for extensions handled by our custom switch statement; for OS-handled extensions, we just verify non-empty return.

## Learnings

- Go's `mime.TypeByExtension` on macOS knows about `.csv`, `.tsv`, `.log`, `.sql`, and even `.xyz` (mapped to `chemical/x-xyz`), so the custom switch cases for these in `detectContentType` are effectively dead code on macOS. Tests account for this platform dependency.
- Python's `zipfile.ZipFile.mkdir()` (added in 3.11) creates directory-only entries — useful for testing that validators skip directory entries.
