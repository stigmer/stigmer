## Decisions Made

1. **`entry_point` as single SDK signal**: Rather than maintaining a separate `runtime` enum field, the CLI infers runtime from the `entry_point` file extension (`.go` -> Go, `.py` -> Python, `.ts`/`.js` -> Node). Absent `entry_point` means declarative track. This eliminates cross-field validation complexity.

2. **`ApiResourceReference` replaces `ResourceChangeRecord`**: The existing `ApiResourceReference` (org/kind/slug/version) already uniquely identifies a resource. Having a bespoke `ResourceChangeRecord` (kind/slug/resource_id) was redundant type proliferation. Using the same type in both `spec.members` and `ReconciliationSummary.deleted` makes the API more consistent.

3. **Clean field renumbering**: With no users and no stored data, we renumbered `ProjectSpec` fields to clean sequential 1/2/3 instead of leaving gaps from removed fields. No `reserved` directives needed.

4. **Accept downstream breakage**: Backend reconciliation service and CLI code will fail to compile after these proto changes. This is expected and will be addressed in Phases 2-4.
