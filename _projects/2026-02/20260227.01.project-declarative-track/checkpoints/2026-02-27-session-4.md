## Decisions Made

1. **Runtime as local value object** — Rather than creating a new proto enum or using raw strings, `Runtime` is a typed string constant with an `InferRuntime` factory function. This keeps the domain pure (no proto dependency for a CLI-internal concept) and prevents invalid states at the type level.

2. **Skill slug from backend response** — During implementation, discovered that building `ApiResourceReference` for skills requires the slug. Rather than computing it locally (fragile, would need to match backend slugification), the slug is obtained from `Skill.Metadata.Slug` in the backend's Push RPC response. This required adding a `Slug` field to `SkillArtifactResult`.

3. **Relative path resolution** — `SkillSynth_Local.Path` from SDK synthesis may be relative. The `pushSkillSynth` function resolves these against the project directory (`detectResult.ConfigDir`) before calling `skill.Push`.

4. **File extraction for line count** — `apply_project.go` was at ~363 lines. Extracted `executeSDKDryRun` and `buildSDKResult` into `apply_project_result.go`, bringing the main file to ~282 lines (consistent with `apply_declarative.go` at ~300).

## Learnings

- The existing `skill.Push` and `skill.PushRemote` functions return `artifact.SkillArtifactResult`, not a `skill.PushResult` type. Important to check actual return types rather than assuming naming conventions.
- The declarative track (`apply_declarative.go`) served as an excellent pattern for the SDK track — both follow the same structure of "apply individually, collect references, apply project".
- Proto enum removal has cascading effects through test files — test fixtures and assertions need thorough updates, not just production code.
