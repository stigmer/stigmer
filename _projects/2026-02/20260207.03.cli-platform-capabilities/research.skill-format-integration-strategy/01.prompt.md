# Deep Research: Self-Bootstrapping AI Agent & Skill System Architecture

## Research Objective

We need authoritative guidance on how to build a **self-bootstrapping AI agent and skill system** where:
- Skills are used by agents (not standalone)
- Agents create new skills using a meta-skill (skill-creator)
- Newly created skills are coupled with agents to create more capabilities
- The entire workflow requires proper infrastructure (database, invocations, executions)

This is a foundational architectural decision. We want to understand industry patterns, avoid technical debt, and build a system that can evolve organically.

## The Big Picture: What We're Trying to Build

### Stigmer Platform Overview

**Stigmer** is an AI orchestration platform with:
- **Agents**: AI agents that can be invoked to perform tasks
- **Skills**: Reusable capabilities that agents can use (SKILL.md format)
- **Workflows**: Multi-step orchestrations of agents
- **MCP Servers**: Model Context Protocol servers for tool integration
- **CLI**: Command-line tool for managing all of the above

All resources are stored in a **database** and can be:
- Created, updated, deleted via CLI or API
- Invoked/executed with inputs and produce outputs
- Versioned and managed

### The Bootstrapping Challenge

We want to build AI-powered "draft" commands:
```
stigmer draft agent      # AI creates agent YAML
stigmer draft workflow   # AI creates workflow YAML
stigmer draft skill      # AI creates skill YAML
stigmer draft mcpserver  # AI creates MCP server YAML
```

**The key insight**: These draft commands need to use **agents + skills** internally. We're not just embedding prompts—we need actual agents executing with skills.

## Critical Questions for Research

### 1. End-to-End Self-Bootstrapping Systems

**Core Question**: How do AI platforms implement self-bootstrapping systems where AI creates AI capabilities?

- Are there examples of platforms where "agents create skills that create agents"?
- How do platforms like OpenAI, Anthropic, or enterprise tools handle this recursive capability creation?
- What are the proven patterns for meta-systems (systems that build themselves)?
- What are the failure modes and risks of self-referential AI systems?

### 2. Agent + Skill Coupling Architecture

**Core Question**: What's the best architecture for coupling agents with skills?

- How do skills get loaded into agent context? (At invocation time? Embedded? Fetched?)
- How does an agent "use" a skill during execution?
- Should skills be stored in database as first-class resources, or as embedded content?
- How do platforms like Codex, Copilot, Claude handle agent-skill binding?

### 3. Skill Creation Workflow

**Core Question**: When an agent creates a skill, what's the full workflow?

- How does the created skill get validated?
- How does it get persisted (database, file system, registry)?
- How does it become available to other agents?
- What's the feedback loop for iterating on created skills?
- How do you handle versioning of created skills?

### 4. Invocation and Execution Infrastructure

**Core Question**: What infrastructure is needed to support this workflow?

- How should agent invocations be structured?
- How are artifacts (schemas, examples, context) passed to agents?
- How are outputs (created skills, YAML) captured and persisted?
- What's the execution model? (Sync? Async? Streaming?)
- How do you handle long-running skill creation sessions?

### 5. Anthropic SKILL.md Format Deep Dive

**Core Question**: Is Anthropic's SKILL.md format suitable for this architecture?

- Is SKILL.md designed for runtime agent use, or just development-time guidance?
- How do other platforms that use SKILL.md load and execute skills?
- What's the relationship between SKILL.md and agent system prompts?
- Can SKILL.md skills be stored in a database and loaded dynamically?

### 6. Industry Patterns for AI Capability Bootstrapping

**Core Question**: How do industry leaders handle the "cold start" problem?

- How does OpenAI Codex bootstrap its skill-creator and skill-installer?
- How does GitHub Copilot set up its default agents?
- How do enterprise platforms provision initial AI capabilities?
- Is there a "seed skill" or "bootstrap agent" pattern?

### 7. Embedding vs Database-Driven Architecture

**Core Question**: Should platform skills be embedded in CLI or stored in database?

Scenario A: **Embedded Skills**
- Skills compiled into CLI binary via go:embed
- Works offline, version-locked to CLI
- Can't be updated without CLI release

Scenario B: **Database-Driven Skills**
- Skills stored in database as resources
- Loaded at invocation time
- Can be updated independently
- Requires database connectivity

Scenario C: **Hybrid**
- Embedded baseline for offline/bootstrap
- Database takes precedence when available
- Sync mechanism between embedded and database

Which approach is used by industry leaders? What are the tradeoffs?

### 8. Licensing and Derivative Works

**Core Question**: Can we use Anthropic's skill-creator to create new skills?

- What license does anthropics/skills use?
- If we use skill-creator (the skill) to create new skills, are those derivative works?
- If we create agent-drafter-skill using skill-creator's guidance, what attribution is needed?
- Are there precedents for "AI-generated from AI prompt" licensing?

### 9. Security and Trust Boundaries

**Core Question**: What security considerations exist for self-bootstrapping AI systems?

- If an agent creates a skill, how do you validate it's not malicious?
- How do you prevent prompt injection in created skills?
- What sandboxing is needed for agent-created capabilities?
- How do enterprise platforms handle trust for AI-generated code/prompts?

### 10. Evolution and Maintenance

**Core Question**: How do you evolve a self-bootstrapped system?

- When skill-creator is updated upstream, how do you propagate changes?
- How do you version skills created by agents?
- How do you handle breaking changes in skill format?
- What's the migration strategy for existing skills?

## Known Information

### Anthropic SKILL.md Structure

From https://github.com/anthropics/skills:

```
skill-name/
├── SKILL.md (required)
│   ├── YAML frontmatter (name, description)
│   └── Markdown body (instructions for the AI)
└── Optional bundled resources
    ├── scripts/      # Executable code (Python/Bash)
    ├── references/   # Documentation loaded as needed
    └── assets/       # Files used in output (templates)
```

### Anthropic's skill-creator Skill

The skill-creator is a meta-skill that:
- Guides creation of new skills
- Defines skill anatomy and structure
- Provides patterns for progressive disclosure
- Includes quality guidelines

Key feature: "Skills are modular, self-contained packages that extend Claude's capabilities by providing specialized knowledge, workflows, and tools."

### Stigmer's Current Architecture

- **CLI**: Go-based, uses Cobra for commands
- **Backend**: gRPC APIs for managing resources
- **Database**: Stores agents, skills, workflows, executions
- **Execution Model**: Agents can be invoked, executions are tracked

### Our Previous Research Findings

Earlier research on "platform capabilities" recommended:
- Hybrid model: Embed baseline + allow updates from registry
- System scope separation (capabilities ≠ user skills)
- Explicit update UX

But it focused on **embedding prompts** rather than the full **agent + skill execution** workflow we're now considering.
