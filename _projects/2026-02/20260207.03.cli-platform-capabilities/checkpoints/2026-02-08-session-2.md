## Decisions Made

### 1. SDK Approach Over Static YAML

**Decision**: Create `skill-creator-agent` programmatically using proto structs, not static YAML.

**Rationale**:
- Follows existing Stigmer patterns (test files already use this approach)
- Provides compile-time type safety
- Easier to refactor when proto changes
- Consistent with how server creates resources internally

**Implementation**: Phase 2's `bootstrap.go` will use:
```go
agent := &agentv1.Agent{
    Metadata: &apiresource.ApiResourceMetadata{
        Name: "skill-creator-agent",
        Org:  "stigmer",
    },
    Spec: &agentv1.AgentSpec{
        Description:  "Creates new skills using the SKILL.md format",
        Instructions: "...",
        SkillRefs:    []*apiresource.ApiResourceReference{{Org: "stigmer", Slug: "skill-creator"}},
    },
}
```

### 2. Shared Location for Seedpack

**Decision**: Move seedpack to `backend/libs/go/seedpack/` (not CLI-specific).

**Rationale**:
- Both CLI and server need access to embedded content
- CLI already imports from `backend/libs/go/` (established pattern)
- Centralizes the source of truth for system resources

### 3. Inline SKILL.md Parsing

**Decision**: Duplicate SKILL.md parsing logic in seedpack package (not extract to shared lib).

**Rationale**:
- Parsing logic is simple (~100 lines)
- Avoids premature abstraction
- Keeps seedpack self-contained
- Can refactor later if more packages need it

### 4. Comprehensive Manifest Schema

**Decision**: Include `system_agents` in manifest.json with metadata only.

**Rationale**:
- Manifest describes what will be bootstrapped
- Actual agent creation happens in bootstrap.go
- Provides documentation of system resources
- Enables future validation and tooling

## Learnings

### 1. Go Embed with Bazel

**Discovery**: Bazel requires explicit `embedsrcs` attribute to include embedded files in the build.

**Pattern**:
```python
go_library(
    embedsrcs = [
        "manifest.json",
    ] + glob(["skills/**"]),
    ...
)
```

### 2. Content Digest Verification

**Discovery**: The vendoring script already generates per-file digests in `provenance.json`.

**Application**: Added `TestVerifyContentDigest` to ensure file integrity after relocation.

**Result**: All 7 files verified correctly (no corruption during move).

### 3. Dual Test Support

**Discovery**: Tests work in both `go test` and `bazel test` without modification.

**Pattern**: Tests use embed.FS directly, no special path handling needed for Bazel.

### 4. Error Message Quality

**Pattern**: Validation errors include context and examples:
```go
return nil, fmt.Errorf("SKILL.md is missing required 'name' field in YAML frontmatter\n\n" +
    "Expected format:\n" +
    "---\n" +
    "name: my-skill-name\n" +
    "---")
```

**Benefit**: Clear, actionable error messages that guide users to the fix.
