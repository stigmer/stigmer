# Deep Research: Self-Bootstrapping Skill System Architecture

## Research Objective

Validate and improve our architecture for building a **self-bootstrapping AI skill system** where the platform uses its own agents and skills to create more agents and skills. We need deep research on how similar platforms solve this bootstrap problem and whether our proposed approach aligns with industry best practices.

## Platform Context: What We're Building

**Stigmer** is an agentic AI platform (think Temporal + AI agents) that allows users to:

1. **Define Agents** - AI assistants with specific instructions, skills, and MCP server integrations
2. **Define Skills** - Reusable knowledge packages (following the SKILL.md format popularized by Anthropic/Claude)
3. **Define Workflows** - Multi-step orchestrations that can invoke agents
4. **Execute via CLI** - `stigmer run agent <name>`, `stigmer run workflow <name>`

The platform has:
- **Go CLI** (`stigmer`) with SDK for defining resources
- **Backend Server** (`stigmer-server`) - local-first, runs on developer machine
- **Temporal** for durable workflow execution
- **Python agent-runner** for LLM interactions

Resources are defined using a **Pulumi-like SDK pattern**:

```go
stigmer.Run(func(ctx *stigmer.Context) error {
    agent.New(ctx, "my-agent", &agent.AgentArgs{
        Instructions: "...",
        Description: "...",
    })
    return nil
})
```

## The Goal: AI-Powered Draft Commands

We want to implement commands like:

```bash
stigmer draft agent      # AI helps create Agent YAML
stigmer draft workflow   # AI helps create Workflow YAML
stigmer draft skill      # AI helps create Skill packages
stigmer draft mcpserver  # AI helps create MCP Server configs
```

These commands invoke specialized "drafter agents" that use "drafter skills" to guide the AI in creating valid configurations through conversational Q&A.

## The Bootstrap Problem

To have `stigmer draft agent` work, we need:

1. An `agent-drafter-agent` (Agent resource)
2. An `agent-drafter-skill` (Skill resource with instructions for creating agents)
3. A `yaml-validator-skill` (Skill resource for schema validation)

**But how do we create these initial skills?** The system needs skills to create skills - this is the chicken-and-egg problem.

## Prior Research Summary

We conducted deep research on skill systems (Claude, Codex, Copilot) and found:

1. **Anthropic publishes `skill-creator`** - A meta-skill at `https://github.com/anthropics/skills/tree/main/skills/skill-creator` that teaches Claude how to create new skills

2. **Progressive Disclosure Pattern** - Skills have metadata (always loaded), instructions (loaded on trigger), and resources (loaded on demand)

3. **Trust Boundaries** - AI-generated skills should start in DRAFT state until reviewed

4. **Hybrid Distribution** - Embed baseline skills in binary, sync to database, allow override

## Our Proposed Architecture: Seedpack Bootstrap

### Core Concept

Instead of manually writing skills, we:

1. **Import Anthropic's `skill-creator`** from their git repository
2. **Define `skill-creator-agent`** that uses this skill
3. **Embed this as a "seedpack" project** in the CLI binary
4. **Bootstrap on server startup** - automatically apply seedpack resources

### Seedpack Structure

```
client-apps/cli/internal/seedpack/
└── project/
    ├── stigmer.yaml     # Project manifest
    └── main.go          # SDK synthesis
```

### SDK Synthesis (main.go)

```go
package main

import (
    "github.com/stigmer/stigmer/sdk/go/agent"
    "github.com/stigmer/stigmer/sdk/go/skill"
    "github.com/stigmer/stigmer/sdk/go/stigmer"
)

func main() {
    stigmer.Run(func(ctx *stigmer.Context) error {
        // Import skill-creator from Anthropic's repo
        _, err := skill.FromGit(ctx, "https://github.com/anthropics/skills",
            skill.WithRef("main"),
            skill.WithSubdir("skills/skill-creator"),
            skill.WithGitTag("latest"),
        )
        if err != nil {
            return err
        }

        // Create agent that uses the skill
        ag, err := agent.New(ctx, "skill-creator-agent", &agent.AgentArgs{
            Description:  "Creates new skills using the SKILL.md format",
            Instructions: "Use the skill-creator skill to help users create SKILL.md packages",
        })
        if err != nil {
            return err
        }
        ag.Org = "stigmer"
        ag.AddSkill("stigmer/skill-creator")

        return nil
    })
}
```

### Bootstrap Flow

```
stigmer server start
       │
       ▼
Check bootstrap state (is seedpack applied?)
       │
       ├── No: Extract embedded seedpack
       │       Run SDK synthesis
       │       Clone Anthropic repo (skill-creator)
       │       Push skill to registry
       │       Create skill-creator-agent
       │       Mark bootstrap complete
       │
       └── Yes: Skip, server ready
```

### Self-Bootstrapping Sequence (After Initial Bootstrap)

```
1. User: stigmer run agent skill-creator-agent -m "Create a yaml-validator skill"
2. Agent uses skill-creator instructions to create yaml-validator/SKILL.md
3. User: stigmer push skill ./yaml-validator
4. User: stigmer run agent skill-creator-agent -m "Create an agent-drafter skill"
5. Agent creates agent-drafter/SKILL.md
6. User: stigmer push skill ./agent-drafter
7. User creates agent-drafter-agent that uses agent-drafter + yaml-validator
8. Now: stigmer draft agent works!
```

## What We Need Research On

### 1. Architecture Validation

- Is the "seedpack embedded in binary, bootstrap on server start" pattern used by other platforms?
- What are the alternatives to this approach?
- Are there better patterns for bootstrapping a self-referential AI system?

### 2. Skill Import Best Practices

- How do other platforms handle importing skills from external sources (git repos)?
- Should skills be stored as artifacts (our current approach: ZIP with content) or as references to source?
- How do platforms handle version pinning and updates for imported skills?

### 3. Server Bootstrap Patterns

- How do developer tools like Ollama, LocalAI, or other local-first platforms handle initial setup?
- Should bootstrap block server startup or run in background?
- How to handle bootstrap failures gracefully (network unavailable, etc.)?

### 4. Trust and Provenance

- How should we track that `skill-creator` came from Anthropic's repo?
- What attestation or signing mechanisms do similar platforms use?
- Should users be able to override system skills?

### 5. Comparable Platforms

Research these platforms for similar patterns:
- **Anthropic Claude Skills** - How does Claude.ai bootstrap its skill system?
- **OpenAI GPT Actions/Plugins** - How are built-in capabilities bootstrapped?
- **GitHub Copilot Extensions** - How does Copilot handle built-in vs user-added capabilities?
- **Cursor IDE Skills** - How does Cursor's AI handle capability loading?
- **Continue.dev** - Open source AI code assistant - how does it handle built-in tools?
- **Aider** - Command-line AI coding assistant - bootstrapping approach?

### 6. Risk Assessment

- What could go wrong with this approach?
- What are the security implications of auto-cloning from a git repo on server start?
- How do we handle breaking changes in Anthropic's skill-creator format?
