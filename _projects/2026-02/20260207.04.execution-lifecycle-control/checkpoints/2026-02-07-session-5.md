## Problem Solved

**Issue**: `java.lang.ClassCastException: class com.sun.tools.javac.code.Attribute$UnresolvedClass cannot be cast to class com.sun.tools.javac.code.Attribute$Class`

**Root Cause**: The annotation processor used `getAnnotation()` which attempts to instantiate the annotation and load all referenced classes. When the annotation references gRPC stub classes that haven't been compiled yet (like `ProjectCommandControllerGrpc.ProjectCommandControllerImplBase.class`), the JDK throws this exception.

**Solution**: Replaced `getAnnotation()` with the `AnnotationMirror` API, which is the standard pattern for annotation processors. This API works with the AST directly without attempting to load classes.

## Decisions Made

1. **Use AnnotationMirror API**: Industry-standard approach used by production annotation processors (AutoValue, Dagger, MapStruct, etc.)
   
2. **Context.Key Pattern for Handlers**: Use typed `Context.Key<T>` for passing data between pipeline steps instead of string-based `setAttribute/getAttribute`
   
3. **Verified Pre-existing Issue**: Tested on clean branch to confirm the annotation processor issue existed before T4 work, validating that the fix addresses the root cause

Set<String> excluded = new HashSet<>();
Object excludeValue = getAnnotationValue(mirror, "excludeMethods");
if (excludeValue instanceof List<?> list) {
    for (Object item : list) {
        if (item instanceof AnnotationValue av) {
            excluded.add(av.getValue().toString());
        }
    }

// Extract stubs as TypeMirrors via AnnotationMirror API
List<TypeMirror> stubMirrors = new ArrayList<>();
Object stubsValue = getAnnotationValue(mirror, "stubs");
if (stubsValue instanceof List<?> list) {

        if (item instanceof AnnotationValue av && av.getValue() instanceof TypeMirror tm) {
            stubMirrors.add(tm);
        }
    }

## Learnings

1. **Annotation Processors and Compilation Order**: Annotation processors run during compilation and cannot use reflection to load classes that haven't been compiled yet. Always use the `AnnotationMirror` API.

2. **JDK 21 Strictness**: Newer JDKs are stricter about internal class handling, making issues like this more common. Following standard patterns (AnnotationMirror) ensures compatibility.

3. **Test on Clean Branch**: When encountering mysterious build failures, always test on a clean branch to distinguish pre-existing issues from new changes.

4. **Type Safety Matters**: The `Context.Key<T>` pattern prevents runtime type errors when passing data between pipeline steps.
