# Deep Research: Making Stigmer a Fully Durable Agentic Workflow Platform

## Research Objective

Help us understand what it takes to legitimately position and technically deliver **Stigmer as a "Durable Agentic Workflow" platform** — combining the reliability guarantees of durable execution (à la Temporal) with first-class AI agent orchestration.

We want to claim "durable agentic workflows" as our category — but we need to understand:
1. What does "durable" actually mean for agentic systems specifically?
2. What gaps exist in our current implementation?
3. What do we need to build to truthfully claim this positioning?
4. How do competitors approach durability in the agentic context?

---

## What We're Building: Stigmer Platform Overview

**Stigmer** is an open-source platform for building and running AI-powered automation workflows. The platform combines two proven technologies:

### Two-Layer Architecture

**Layer 1: Agent Execution via LangGraph (Already Solved)**
- Stigmer uses **LangGraph** for agent execution — the actual AI reasoning, tool calling, and MCP server management
- LangGraph handles: agent state, tool call sequencing, interrupt/resume within an agent run, checkpointing
- We transform Stigmer's declarative agent specs into LangGraph-compatible configurations
- **This layer is NOT the focus of this research** — LangGraph handles agent execution well

**Layer 2: Workflow Durability via Temporal (Foundation Built)**
- Stigmer uses **Temporal** for workflow orchestration — the long-running, "set it and forget it" execution
- Temporal handles: state persistence, failure recovery, timers that last months, retries, audit history
- **This is Temporal's core promise**: "What if your code never failed?" / workflows that survive any failure
- **This research is about making this layer work seamlessly for workflows containing agent tasks**

### What "Durable Workflow" Means (The Temporal Promise)

The core value proposition of durable execution is:

> **Users should be able to start a workflow and not worry about how long it takes to complete.**
> 
> Whether it takes 5 minutes or 3 months, the workflow will:
> - Survive server restarts, crashes, and deployments
> - Resume from exactly where it left off after any failure
> - Wait for weeks/months without consuming resources
> - Never lose state or progress
> - Provide full audit history of what happened

This is exactly what Temporal provides. The question is: **how do we extend this promise to workflows that contain AI agent tasks?**

### Core Components (Already Built)

1. **Declarative Agent Definitions**
   - YAML-based agent specifications with instructions, model selection, and tool configuration
   - MCP (Model Context Protocol) server integration for tool access
   - Agents as first-class resources with versioning and lifecycle management
   - **Agent execution handled by LangGraph** (transforms specs → LangGraph format)

2. **Workflow Engine (Built on Temporal)**
   - Sequential and parallel task execution
   - Conditional branching and loops
   - Event-driven waits (signals, queries, updates)
   - Error handling with try/catch semantics
   - Basic human approval gates
   - **Long-running execution handled by Temporal** (the durability layer)

3. **Agent Tasks Within Workflows**
   - Workflows can invoke agents as tasks (Temporal Activity → LangGraph execution)
   - Agent outputs feed into subsequent workflow steps
   - Support for multi-agent orchestration patterns
   - **The handoff: Temporal (durable) → LangGraph (agent execution) → Temporal (continues)**

4. **Local-First Development**
   - SQLite for local storage
   - Ollama integration for local LLM inference
   - Same workflow definitions work locally and in production

5. **Integration Layer**
   - MCP servers for tool integration (GitHub, filesystem, databases, etc.)
   - gRPC APIs for external system integration
   - Webhook support for external event ingestion

### What's Already Implemented (Core Durability Infrastructure)

From our internal review, Stigmer has already implemented these critical durability features:

| Capability | Status | Details |
|------------|--------|---------|
| **Continue-As-New** | ✅ **IMPLEMENTED** | Uses Temporal's `continueAsNewSuggested` flag (~10K events threshold); custom threshold via metadata; state preservation via `__continue_as_new_from__` marker |
| **Claim Check (large payloads)** | ✅ **IMPLEMENTED** | Intercepts outputs >50KB, stores in R2/filesystem, auto-retrieves; survives Continue-As-New |
| **Search Attributes** | ✅ **IMPLEMENTED** | Auto-creates `WorkflowExecutionID`; supports all Temporal types; metadata-driven |
| **Signal/Update handling** | ✅ **IMPLEMENTED** | Listen task with `signal`, `query`, `update` modes; `one`/`all` waiting; timeout + `acceptIf` conditions |

### What Gaps Remain (From Previous Research)

| Capability | Current State | Gap |
|------------|---------------|-----|
| **Wait semantics** | Proto limited to `int32 seconds` (executor supports full durations) | Need ISO 8601 duration strings, `wait until` timestamps, business calendars at proto level |
| **Human tasks** | Single approval gates only | Need assignments, deadlines, escalations, reassignment, external inbox integration |
| **Signal-With-Start** | ❌ Not implemented | Need race-proof event delivery for "start workflow if not exists + send signal" |
| **Event correlation/idempotency** | ❌ Not implemented | Need ingress gateway, correlation strategy, dedupe infrastructure |
| **User-facing lifecycle control** | Internal only (WorkflowRunner has methods) | Need user APIs/CLI for cancel, retry, pause, resume |
| **EXECUTION_PAUSED phase** | ❌ Missing from enum | Need explicit paused state in proto |
| **Saga/compensation** | `try_catch` exists | Need compensation stack semantics, deterministic rollback |
| **Workflow versioning** | Not explicitly handled at Stigmer layer | Need definition versioning + migration controls |

## The Core Research Question: Durable Long-Running Agentic Workflows

### What We Mean by "Durable"

The term "durable" in the context of Temporal means:

> **A workflow that users can start and walk away from, regardless of how long it takes to complete.**

Examples of what users should be able to do:
- Start an employee onboarding workflow that runs for **3 months** (background checks, IT provisioning, training schedules)
- Start a compliance review workflow that waits **weeks** for human approvals across departments
- Start a release pipeline that runs for **hours/days** with multiple agent-driven code reviews and fixes
- **Never worry** about server restarts, crashes, deployments, or infrastructure failures

This is exactly what Temporal provides for regular workflows. The question is: **does this work seamlessly when those workflows contain AI agent tasks?**

### Agent Tasks Within Durable Workflows

In Stigmer's architecture:
- A **workflow** runs on Temporal (durable, long-running)
- An **agent task** within that workflow invokes LangGraph (agent execution)
- The workflow waits for the agent to complete, then continues

The Temporal workflow is already durable. The agent execution (via LangGraph) has its own checkpointing. But:

1. **What happens if the agent task takes hours?** (large codebase analysis, complex reasoning)
2. **What happens if the workflow waits weeks between agent tasks?** (human approval, external events)
3. **What happens if an agent task fails after 30 minutes of work?**
4. **What state crosses the boundary between Temporal and LangGraph?**

### Specific Research Questions

1. **Long-Running Agent Tasks**
   - If an agent task runs for hours, does Temporal handle this gracefully?
   - What are the timeout/heartbeat considerations?
   - Should we break long agent tasks into checkpointed sub-tasks?

2. **Workflow-Level Durability for Agentic Patterns**
   - Does Continue-As-New work correctly when the workflow contains many agent invocations?
   - How should agent outputs (potentially large) be stored durably?
   - What Search Attributes make sense for agent-containing workflows?

3. **Multi-Agent Workflow Patterns**
   - Agent A completes, workflow waits 2 weeks, then invokes Agent B
   - Does Agent B have access to Agent A's outputs?
   - How is this state managed durably across the wait?

4. **Human-in-the-Loop at Workflow Level**
   - Human approves at workflow level (not agent level)
   - Workflow waits weeks for approval
   - Does the agent context survive this wait?

5. **The "Set It and Forget It" Promise**
   - Can a user truly start an agentic workflow and not worry about its duration?
   - What infrastructure requirements exist for month-long agentic workflows?
   - What's different about agent-containing workflows vs. regular Temporal workflows?

## Competitive Landscape Context

### Our Technology Stack (Not Competitors — We Use Them)

- **LangGraph**: We use LangGraph for agent execution. It handles agent-level concerns well (tool calling, checkpointing within agent runs, MCP integration). **This is solved.**
- **Temporal**: We use Temporal for workflow durability. It handles long-running workflow concerns well (state persistence, timers, failure recovery). **This is our foundation.**

### The Integration Question

The research question is about the **integration** of these two layers:
- How do LangGraph agent tasks behave within Temporal durable workflows?
- What patterns are needed for month-long workflows containing agent tasks?
- Does the combination provide true "durable agentic workflows"?

### Other Agent Frameworks (No Durable Workflow Layer)

- **CrewAI**: Multi-agent orchestration with "flows" — but no Temporal-grade durability for long-running execution
- **AutoGen**: Multi-agent conversation patterns — research-oriented, no long-running workflow story
- **Semantic Kernel**: Enterprise middleware — no durable long-running execution

### Workflow Engines (No Agent-Native Abstractions)

- **Temporal (standalone)**: Gold standard for durability, but agents would be generic "activities" — no declarative agent definitions, no MCP integration
- **Airflow**: Batch DAGs — not suitable for interactive agent patterns or month-long waits
- **Prefect**: Python automation — adding AI but not agent-native
- **Dagster**: Data pipelines — asset-oriented, not agent workflow-oriented

### The Gap We're Filling

Stigmer combines:
- **LangGraph** for agent execution (declarative specs → agent runs)
- **Temporal** for workflow durability (long-running, failure-proof)
- **Declarative agent definitions** (YAML specs, versioned, MCP-integrated)
- **The question**: Does this combination deliver true "durable agentic workflows" for month-long execution?
