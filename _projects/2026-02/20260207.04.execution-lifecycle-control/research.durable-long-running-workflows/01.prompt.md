# Deep Research: Fully Durable Long-Running Workflow Execution

## Research Objective

Investigate how to make **Stigmer workflow executions truly durable for long-running workflows** that span weeks or months (e.g., employee onboarding, compliance processes, multi-stage hiring pipelines).

We need to understand:
1. What "durable execution" means in the context of long-running workflows
2. Best practices from Temporal, Cadence, and other workflow engines
3. What architectural patterns are required
4. What we currently have vs. what we need to implement

---

## Context: What Stigmer Currently Has

### Execution Engine
- **Temporal** as the underlying workflow execution engine
- CNCF Serverless Workflow DSL 1.0.0 for workflow definitions
- Workflows are converted to Temporal workflows for execution

### Task Types Available

| Task Type | Description | Current Status |
|-----------|-------------|----------------|
| `wait` | Sleep/delay using Temporal timer | Seconds-based only (int32) |
| `listen` | Wait for external signals/events | Signal types: signal, query, update |
| `agent_call` | Invoke AI agents | Implemented |
| `http_call` | HTTP requests | Implemented |
| `grpc_call` | gRPC requests | Implemented |
| `switch_case` | Conditional branching | Implemented |
| `for_each` | Iteration | Implemented |
| `fork` | Parallel execution | Implemented |
| `try_catch` | Error handling | Implemented |
| `run_workflow` | Sub-workflow execution | Implemented |
| `activity_call` | Temporal activity | Implemented |

### What We Know Works
- Short-running workflows (seconds to hours)
- Human-in-the-loop approval gates (WAITING_FOR_APPROVAL phase)
- Signal handling via `listen` task
- Timer-based waits (seconds)

### What's Unclear/Missing
- Workflows that run for weeks/months
- Calendar/date-based scheduling (wait until specific date)
- Handling Temporal event history limits
- Continue-as-new pattern for very long workflows
- State checkpointing for resumption
- Human task assignment (not just approval, but work assignment)
- External event ingestion at scale
- Saga pattern for distributed transactions

## Specific Research Questions

### 1. Temporal Event History Limits

**Question**: Temporal has a limit on event history size. What happens when a workflow runs for weeks/months and accumulates thousands of events?

**Investigate**:
- What is the current limit?
- How does continue-as-new work?
- When should we automatically use continue-as-new?
- How do other platforms (Cadence, Step Functions) handle this?

### 2. Long-Duration Timers

**Question**: Our current `wait` task only supports seconds (int32). For month-long workflows, we need:
- Wait until a specific date/time
- Wait for business days (skip weekends/holidays)
- Wait for calendar events

**Investigate**:
- How does Temporal handle long-duration timers internally?
- Best practices for date-based waiting
- Should timers be stored in database vs. Temporal timers?

### 3. Human Task Management vs. Approval Gates

**Question**: Our current approval system is a single approval gate. Real HR/onboarding workflows need:
- Task assignment to specific people
- Deadline tracking
- Escalation if not completed
- Parallel human tasks
- Task reassignment

**Investigate**:
- How do workflow engines model human tasks?
- Temporal patterns for human-in-the-loop
- BPMN human task patterns
- How to integrate with external task management (Jira, ServiceNow)?

### 4. State Persistence and Checkpointing

**Question**: For month-long workflows, we need:
- Clear visibility into current state
- Ability to inspect and potentially modify state
- Recovery from infrastructure failures
- Audit trail of all state changes

**Investigate**:
- How does Temporal persist workflow state?
- Best practices for state visibility
- Should we maintain our own state mirror in MongoDB?
- Checkpointing patterns

### 5. External Event Ingestion

**Question**: Long-running workflows need to react to external events:
- Webhook from HR system (background check completed)
- Email response (offer accepted/rejected)
- Calendar event (meeting scheduled)
- Third-party API callback

**Investigate**:
- Temporal signal patterns for external events
- Event-driven workflow patterns
- How to correlate events to running workflows
- Idempotency for event processing

### 6. Saga Pattern and Compensation

**Question**: If step 47 of a 60-step onboarding fails after 3 weeks, how do we:
- Roll back completed steps that can be rolled back
- Notify stakeholders of partial failure
- Resume from a checkpoint after manual intervention

**Investigate**:
- Saga pattern implementation in Temporal
- Compensation activities
- Partial rollback strategies
- Manual intervention patterns

### 7. Workflow Versioning and Migration

**Question**: A workflow runs for 3 months. In month 2, we update the workflow definition. What happens to running instances?

**Investigate**:
- Temporal workflow versioning
- Migration patterns for long-running workflows
- Best practices for backward compatibility

### 8. Visibility and Monitoring

**Question**: How do operators track hundreds of month-long workflows?

**Investigate**:
- Dashboard patterns for long-running workflows
- Alert strategies (stuck workflows, SLA violations)
- Reporting on workflow progress

## Real-World Use Case: Employee Onboarding

An employee onboarding workflow might include:

1. **Week 1**: 
   - HR creates employee record
   - Background check initiated (external API)
   - Wait for background check completion (external signal, could be days)

2. **Week 2**:
   - Send offer letter
   - Wait for signed offer (human task with deadline)
   - If not signed in 5 days, escalate

3. **Week 3-4**:
   - IT provisions accounts
   - Manager schedules 1:1s
   - Equipment ordered

4. **Week 4+**:
   - Employee start date reached (date-based timer)
   - Day 1 tasks triggered
   - 30/60/90 day check-ins scheduled

**This workflow could run 2-3 months and include:**
- Multiple human tasks (not just approvals)
- External system integrations
- Date-based scheduling
- Conditional branching based on role/location
- Parallel task execution
- Error handling and retry

## Why This Matters

Our landing page positions Stigmer as providing "durable agentic workflows." If we claim durability but can't actually run a 3-month onboarding workflow without issues, we're making false promises.

This research will inform:
1. What features we need to implement
2. What claims we can legitimately make on our landing page
3. What use cases we should highlight vs. avoid
