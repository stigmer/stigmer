## Decisions Made

### 1. Composition Over Duplication

**Decision**: Use composition pattern (Args as single source of truth) for all SDK resources

**Rationale**:
- Eliminates field sync bugs
- Simpler conversion logic
- Easier to maintain
- Consistent with MCPServer pattern

**Trade-off**: Adds accessor methods, but cleaner architecture worth it

### 2. Accessor Methods for Args Fields

**Decision**: Provide accessor methods like `Instructions()`, `Description()` instead of exposing Args fields directly

**Rationale**:
- Clean public API
- Nil-safety in accessors
- Flexibility to change implementation later

**Open Question**: Should we reconsider and just expose `Args` fields directly?

### 3. Proto Stub Types in Args

**Decision**: Args structs use proto stub types directly

**Rationale**:
- No intermediate type conversions needed
- Single canonical type system
- Simpler, more efficient code

### 4. Workflow Refactoring Cancelled

**Decision**: Don't attempt to work around workflow codegen issues

**Rationale**:
- Pre-existing bugs need proper fix, not workarounds
- Blocking issues clearly documented
- Agent refactoring provides template for Workflow when unblocked

**Before**:
```go
type Agent struct {
    Name         string
    Slug         string

    Description  string        // DUPLICATED
    IconURL      string        // DUPLICATED
    SkillRefs    []*apiresource.ApiResourceReference  // DUPLICATED

    SubAgents    []subagent.SubAgent
    EnvironmentVariables []environment.Variable

```

**After**:
```go
type Agent struct {
    Name string          // Identity
    Slug string          // Identity
    Org  string          // Metadata
    Args *AgentArgs      // Single source of truth
    SubAgents []subagent.SubAgent
    EnvironmentVariables []environment.Variable
    ctx  Context
    mu   sync.Mutex
}

// Accessor methods
func (a *Agent) Instructions() string { return a.Args.Instructions }
func (a *Agent) Description() string  { return a.Args.Description }
func (a *Agent) SkillRefs() []*apiresource.ApiResourceReference { return a.Args.SkillRefs }
func (a *Agent) McpServerUsages() []*agentv1.McpServerUsage { return a.Args.McpServerUsages }
```

### Codegen Well-Known Type Handling

**Added**:
```go
func wellKnownProtoType(messageType string) (string, bool) {
    switch messageType {
    case "google.protobuf.Timestamp":
        return "*timestamppb.Timestamp", true
    case "google.protobuf.Duration":
        return "*durationpb.Duration", true
    // ... other types
    }
}
```

**Impact**: All generated types now use correct Go types for protobuf well-known types

## Learnings

### 1. Composition Pattern is Powerful

**What Worked**:
- Single source of truth eliminates entire class of bugs
- Simpler conversion logic in `ToProto()`
- Clearer intent and architecture

**Caveat**: Requires accessor methods, but worth the trade-off

### 2. Well-Known Types Need Special Handling

**Discovery**: Protobuf well-known types aren't like custom message types

**Solution**: 
- Special detection in `goType()`
- Correct import paths and package aliases
- Type-specific conversion logic

**Learning**: Code generators must handle special cases explicitly

### 3. Test Updates Can Be Extensive

**Reality**: Changing from direct field access to accessor methods required updating ~400 test assertions

**Impact**: Test compilation successful, validates pattern works

**Note**: Tests can't run due to workflow dependency (pre-existing issue)

### 4. Pre-existing Issues Can Block Progress

**Situation**: Workflow codegen bugs prevent running any tests that import workflow

**Response**: Document clearly, don't attempt workarounds

**Learning**: Sometimes you must stop and fix root cause

## Open Questions

### 1. Should We Use Accessor Methods?

**Current**: Provide accessor methods for all Args fields

**Alternative**: Expose Args directly, let users access `agent.Args.Instructions`

**Trade-offs**:
- Accessors: Cleaner API, nil-safety, flexibility
- Direct: Simpler, less indirection, more obvious

**Decision Needed**: After Workflow refactoring, revisit this choice

### 2. How to Fix Workflow Codegen?

**Issue**: Generator creates references to types that don't exist

**Unknown**: Where should these types be defined?
- In proto?
- In shared types?
- Generated automatically?

**Action**: Needs separate investigation

### 3. Should SubAgents Use Composition Too?

**Current**: SubAgents are `[]subagent.SubAgent` (interface)

**Question**: Should SubAgent also use Args pattern?

**Consider**: When refactoring Workflow, also evaluate SubAgent pattern
