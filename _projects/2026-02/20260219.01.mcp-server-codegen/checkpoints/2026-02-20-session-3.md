## Decisions Made

- **SDK pattern over proto-mirroring**: Flat input with `toProto()` conversion, not raw proto structure. Rationale: same philosophy as `sdk/go/agent/agent.go` — hide boilerplate from consumers.
- **`ResourceIdentity` in shared `domains/` package**: Common identity fields (name, slug, org, visibility, labels, tags) pulled into a reusable embedded struct. Future domains can compose this.
- **Auto-populate enum kinds**: `toProto()` sets `apiresourcekind.ApiResourceKind_skill` (43) and `apiresourcekind.ApiResourceKind_mcp_server` (44) automatically — LLM never sees enum values.
- **Local `generateSlug`**: Chose not to import SDK's `naming` package. Slug algorithm is simple enough to inline and avoids a cross-module dependency.
- **Agent domain diverges from `CallApply`**: `agents/tools.go` handler directly calls `Apply(ctx, addr, agent)` instead of `domains.CallApply`. This is intentional — the typed proto input doesn't fit the `ApplyFunc` signature.

## Learnings

- `jsonschema-go` flattens embedded structs into the parent schema, which makes `ResourceIdentity` embedding work seamlessly for JSON Schema generation
- The MCP Go SDK uses `jsonschema-go` under the hood for auto-generating `inputSchema` from handler input types
- The distinction between "proto structure for backend" vs "friendly structure for consumers" is the same problem at both SDK and MCP layers
