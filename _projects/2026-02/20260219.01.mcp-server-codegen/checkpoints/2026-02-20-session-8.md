## Decisions Made

- **Proto as single source of truth**: Custom options on proto fields/messages declare
  discriminated union relationships, eliminating CLI flags and naming conventions
- **Skip composite resources**: `project` resource skipped from MCP codegen because it
  embeds full resource wrappers causing naming collisions. Documented in generator's
  `skipResources` map with clear comments
- **Domain-scoped gen/ layout**: `gen/agentic/agent/` not `gen/agent/` — mirrors
  schema directory structure and proto namespace hierarchy
- **Satellite directory pattern**: Non-domain directories (tasks/) are indexed as
  satellites and matched to resources via discriminatorValue metadata

## Learnings

- protowire-based string extraction from unknown fields works cleanly for custom options
  (same pattern as the existing reference_kind varint extraction, but for BytesType)
- Composite resources (Project) that embed full API resource wrappers (Agent with
  metadata+spec+status) create naming collisions in the input type generator because
  AgentSpec and Agent both become AgentInput
- Satellite schema pattern (separate directories for variant schemas) works well for
  auto-detection — the generator matches discriminatorValue in satellites to
  discriminatedBy on shared types
