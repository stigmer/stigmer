## Decisions Made

- **Proto stays untouched**: `kind + structpb.Struct` wire format preserved — avoids proto circular deps
- **Codegen-only change**: Typed structs live only at the MCP input layer, auto-regenerated from protos
- **`protojson` marshal path**: Used `protojson.Marshal` on the typed config's `toProto()` output rather
  than a naive `json.Marshal` + `structpb.NewStruct` roundtrip — ensures proto field name conventions
  and well-known type encoding are correct for the Temporal workflow executor
- **`kindToEnum` mapping**: Built using word-subset matching between config schema `Kind` (UPPER_SNAKE_CASE
  like `HTTP_CALL`) and proto enum values (lowercase like `http_call`) — robust against naming variations

## Learnings

- `google.protobuf.Timestamp` requires special handling in codegen: must map to `string` in MCP input
  (ISO 8601), then parse and wrap as `timestamppb.Timestamp` in `ToProto()`
- `oneof` + `Timestamp` is a compound edge case: the generated field assignment must produce
  `&proto.Message_OneofField{Field: timestamppb.New(t)}` — both the oneof wrapper and timestamp parse
- `proto2schema` comprehensive mode was producing `signal.json` in the workflow schema directory —
  this required the `GenerateMCP` promotion logic to be robust about which schema is the "primary" one
- The `--no-edit` style of `go vet` struct tag warnings from `jsonschema-go`'s `\,` escape pattern
  are pre-existing in all generated code; the Makefile `vet` target correctly excludes `gen/` packages
