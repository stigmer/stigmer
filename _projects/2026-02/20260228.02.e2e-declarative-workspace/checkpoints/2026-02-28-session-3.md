## Decisions Made

### DD-03: Explicit Session Creation (not proto passthrough)
- **Context**: `workspace_source` lives on `SessionSpec`, not `AgentExecutionSpec`. Backend's auto-create-session flow has no workspace passthrough.
- **Option A (chosen)**: CLI creates Session explicitly via `SessionCommandController.Create()`, then creates execution with `session_id`. Zero backend changes.
- **Option B (rejected)**: Add `workspace_source` to `AgentExecutionSpec` as pass-through. Domain leakage, requires proto + backend changes.
- **Rationale**: Respects domain boundaries. Workspace is a session concept. The gRPC stub and `agent.Status.DefaultInstanceId` were already available.

### DD-04: Separate flags (not single --workspace with embedded syntax)
- **Context**: T04 plan originally suggested `--workspace https://repo#branch@commit` with embedded syntax.
- **Chosen**: Separate `--workspace`, `--branch`, `--commit` flags mapping 1:1 to proto fields.
- **Rationale**: Avoids ambiguous URL parsing, follows `git clone --branch` conventions, scales cleanly to future fields like `--depth`.

## Learnings

- The backend's `createSessionIfNeededStep` builds sessions with a hardcoded spec (lines 344-358 of `create.go`). - `agent.Status.DefaultInstanceId` is populated after agent creation and available from the resolve step -- no extra RPC needed.
- The `"Auto-created session"` subject sentinel must match the backend's constant exactly for the LLM title generation activity to work.
