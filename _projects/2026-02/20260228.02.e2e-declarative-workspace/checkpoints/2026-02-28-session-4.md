## Decisions Made

1. **Transport vs attention separation**: `--attach` conflates transport (make file available) and attention (focus agent). For workspace files, only attention is needed. This is the domain-level insight that drove the entire design.

2. **Simple `repeated string` over rich message**: The proto field is just workspace-relative path strings. The backend stats files from the workspace to get size info for the prompt. Avoids proto bloat and keeps the API clean.

3. **Automatic detection, not a new flag**: The CLI detects containment automatically. No `--ref` or `--focus` flag. Users don't need to know whether a file is inside the workspace -- `--attach` just works optimally.

4. **Output optimization deferred**: With local workspaces, agent writes go directly to user's filesystem. The `publish_artifact` + `--download` R2 round-trip is redundant but not harmful. Deferring to a separate task to keep scope clean.

5. **EvalSymlinks for security**: Containment check uses `filepath.EvalSymlinks` to prevent symlinks that escape the workspace from being treated as workspace files.

## Learnings

- The `--attach` flag's dual purpose (transport + attention) is a domain modeling insight. When a richer concept (workspace) satisfies the transport concern, the remaining concern (attention) can be expressed much more simply.
- The `## Input Files` prompt section's claim that files are "NOT part of the project source tree" was a semantic lie when workspace files were uploaded. Fixing this lie is the user-facing improvement that matters most.
- Forward-slash normalization via `filepath.ToSlash` in `workspaceRelativePath` ensures consistent paths across platforms.

## Open Questions

- Output optimization (skipping R2 upload for artifacts in local workspace) is deferred but may be worth pursuing if users report redundant artifact downloads.
- For git workspaces, could the CLI detect containment post-clone? Currently only local workspaces get the optimization.
