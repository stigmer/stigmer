## Decisions Made

### DD01: Output Format Architecture — Two Separate Systems

The CLI has two fundamentally distinct output systems that serve different command
categories. They should never coexist on the same command:

1. **System 1**: `clioutput.CommandResult` + `Renderer` (human/json/quiet) for
   mutating commands (delete, apply, server, config set)
2. **System 2**: `--output table/yaml/json` for read commands (get, list, search)

This decision was reached after analyzing every display.go file, the clioutput package,
the get/list command handlers, and the cliprint package. The key insight is that merging
them would break piping (`stigmer get agent foo -o json | jq '.spec'`), lose YAML
support, and mismodel tabular list data as key-value sections.

- The original T01 plan assumed a single unified output pipeline for all commands.
  Actual implementation experience through Phases 1-3.3 revealed this was wrong for
  read commands. The design decision formalizes what the code already showed.
- The `Displayable` interface from T01 was speculative abstraction. The real
  consolidation opportunity is much simpler: extract duplicated proto YAML/JSON
  boilerplate (~240 lines total across 8 files).
