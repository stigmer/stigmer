## Decisions Made

1. **`--json` (no short flag) and `--quiet` / `-q`**: Mutually exclusive flags. `--json` outputs CommandResult as JSON to stdout. `--quiet` prints status line only. Named to avoid collision with `--output table/yaml/json` on get/list commands.

2. **Cobra mutual exclusivity**: Using `cmd.MarkFlagsMutuallyExclusive("json", "quiet")` — built-in cobra feature, no custom validation needed.

3. **`resolveApplyOrganization` to stderr**: `cliprint.PrintInfo` writes to stdout via `color.Printf`. In `--json` mode, this would corrupt the JSON output stream. Migrated to `fmt.Fprintf(os.Stderr, ...)` following the same pattern already used by `apply_project.go`. This also removed the last `cliprint` import from `apply.go`.

4. **`getSnapshot` unexported**: `ProgressState.GetSnapshot` had zero external callers and its return type includes the unexported `phaseStatus`. Unexported to `getSnapshot` for clean API surface.

5. **Config get / config path excluded from --json/--quiet**: These output raw values for piping (`stigmer config get llm.provider | xargs ...`). Wrapping in CommandResult would break this use case. Design decision #10 preserved.

6. **Server start / llm pull excluded**: ProgressDisplay flow (BubbleTea). Deferred to separate project per agreement. Design decision #11 preserved.

## Learnings

- Subcommand factory functions like `newServerStopCommand()` that return inline `&cobra.Command{...}` must be expanded to named `cmd` variables when flags need to be registered. Mechanical but requires touching every affected command definition.
- `cliprint.PrintInfo` writes to stdout (via `color.Printf`), not stderr. This was a latent bug for any future `--json` support — caught during planning audit.
