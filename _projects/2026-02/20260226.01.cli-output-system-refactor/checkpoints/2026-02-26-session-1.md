## Decisions Made

1. **`[]*Section` over `[]Section`**: Using pointer slice prevents dangling pointer bugs when the backing array is reallocated on subsequent `AddSection()` calls. Discovered during implementation that the original plan's `[]Section` approach had a subtle correctness issue.

2. **`InteractiveConfirmer.In` is `*os.File` not `io.Reader`**: `term.IsTerminal()` requires a file descriptor (`Fd()`) to check TTY status. An `io.Reader` doesn't expose this. This is the right trade-off: testability via pipe-based `*os.File` in tests, safety via real TTY detection in production.

3. **Non-terminal stdin defaults to deny**: User confirmed this design. When stdin is piped (not a terminal), `InteractiveConfirmer.Confirm()` returns `(false, nil)` without prompting. Forces `--force` for scripted destructive operations.

4. **Deferred Phase 1.2 (`Displayable`) and 1.3 (`--output` flag)**: User agreed to keep Phase 1 focused. `Displayable` is better designed when we actually migrate resources in Phase 4. `--output` flag adds dead code until commands use the renderer.

5. **Renderers take both `stdout` and `stderr`**: `NewRenderer(format, stdout, stderr)` allows each renderer to route output correctly. Human renderer writes everything to stderr (decorative). JSON renderer writes data to stdout, status to stderr.

## Key Code Patterns

### Builder API usage
```go
r := clioutput.Success("Agent deleted")
r.AddSection("Resource Details").
    Field("ID", agent.Metadata.Id).
    Field("Name", agent.Metadata.Name)
r.Hint("View agents: stigmer list agents")

renderer := clioutput.NewRenderer(clioutput.FormatHuman, os.Stdout, os.Stderr)
renderer.Render(r)
```

### Confirmer factory
```go
confirmer := clioutput.NewConfirmer(forceFlag, os.Stderr)
confirmed, err := confirmer.Confirm("Delete this agent? [y/N]")
```
