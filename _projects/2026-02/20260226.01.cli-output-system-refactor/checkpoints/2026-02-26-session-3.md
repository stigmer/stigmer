## Decisions Made

1. **Export `formatPhase` → `FormatPhase` in execution package**: The cancel handler in the command layer needs to format execution phases for display. Rather than duplicating the mapping or using proto `.String()` (which gives ugly `EXECUTION_CANCELLED` names), we exported the existing `formatPhase` function. This is a legitimate public API -- "given a phase enum, return a human-readable string."

2. **Skill handler preserves domain-specific detail**: The skill delete confirmation includes an optional Tag field and two hints ("delete all versions" + "cannot be undone") unlike the other 4 resources which have a uniform single hint. This resource-specific variance is preserved in the handler rather than being genericized prematurely.

3. **`executeCancelExecution` creates its own renderer inline**: Consistent with Phase 2's decision that this function manages its own connection and confirmer (since it doesn't go through `deleteContext`). The renderer follows the same inline pattern.

4. **Test cleanup -- removed tests for deleted functions**: Three display_test.go files had `TestDisplayDeleteResult_NoPanic` and `TestDisplayDeleteConfirmation_NoPanic` tests that were deleted along with the functions they tested.

## Design Surprise (Logged)

Discovered during planning that `--output table/yaml/json` on get/list is a **data serialization format** (raw resource YAML/JSON), fundamentally different from `clioutput.OutputFormat` (`human/json/quiet`) which is **CLI chrome format**. This scoped Phase 3.1 to delete-only. Phase 3.2 requires a design decision on how these two concepts coexist before migrating get/list/apply.
