## Decisions Made

1. **Keep existing `DisplayDeleteConfirmation` functions as-is**: Proposed and agreed to NOT migrate the confirmation display to `CommandResult` in Phase 2. Rationale: avoids a mixed output system (new for confirmation, old for success display) within the same command flow. Full migration deferred to Phase 3 where ALL displays get migrated together.

2. **`deleteContext` struct**: Introduced an unexported struct bundling `ref`, `orgID`, `force`, `confirmer`, and `conn`. Avoids parameter explosion (5+ params) and is extensible for Phase 3 (`renderer` field). Replaces flat parameter lists on `routeDelete` and all 5 resource handlers.

3. **Remove `--force` hint from confirmation flow**: Removed `cliprint.PrintInfo("Use --force to skip this confirmation")` from all handlers. The `--force` flag is documented in command help. Real-world CLIs (terraform, gh) don't mention skip flags in interactive prompts.

4. **Abort returns `nil`, not an error**: When the user types "N" at the confirmation prompt, the handler returns `nil`. Aborting is a valid user choice, not a failure. `clierr.Handle(nil)` is a no-op.

5. **Execution cancel stays as a separate flow**: `executeCancelExecution` creates its own backend connection (separate from the resource delete flow), so it creates its own `InteractiveConfirmer` inline rather than sharing `deleteContext`.
