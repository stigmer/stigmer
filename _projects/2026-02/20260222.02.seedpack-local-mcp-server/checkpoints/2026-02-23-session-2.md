## Decisions Made

- **Combined Phase 2 + Phase 3**: Changing `NewBootstrapper`'s signature in Phase 2 would immediately break `server.go`. The server.go fix was a single-line change (the `mcpServerClient` variable already existed on line 361), so combining them avoided a broken intermediate state.
- **Content hash strategy**: `calculateMcpServerHash` hashes selected key fields (name, description, transport config, tags) rather than the full proto. This matches the `calculateAgentHash` pattern and avoids false positives from system-populated fields (id, audit timestamps) that change across restarts.
- **State key prefix**: `"mcpserver:"` — follows the pattern of `"skill:"` and `"agent:"`

## Learnings

- The downstream mcpserver client was created for the reconciliation engine (which uses CRUD), so `Apply` was never needed until bootstrap. This is the kind of gap that appears when a resource type is added incrementally.
- The pattern for extending the bootstrap is very clean: interface + method + constructor parameter + Run() loop + hash function. The existing agent implementation serves as a precise template.
