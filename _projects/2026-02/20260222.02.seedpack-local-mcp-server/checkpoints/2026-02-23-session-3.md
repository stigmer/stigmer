## Decisions Made

- **No binaries in agent-runner**: MCP servers are spawned dynamically using their native runtime tools, not pre-compiled into the image
- **Four runtime tools**: npx (Node.js), uvx (Python), go (Go modules), docker (containers) cover the vast majority of STDIO MCP servers in the ecosystem
- **`go run` in seedpack YAML**: The built-in MCP server uses `go run …@latest` rather than a pre-installed binary, making it consistent with user-defined MCP servers
- **Docker socket reuse**: The agent-runner already has `/var/run/docker.sock` mounted, so Docker CLI works without Docker-in-Docker
- **Module tagging strategy**: Tagged `apis/stubs/go/v0.0.1` on a stable `main` commit; `mcp-server/v0.1.0` to be tagged after merge

## Learnings

- The Go module proxy will only index a module once it has been tagged and explicitly requested via `go list -m`
- Monorepo sub-module tagging uses the path prefix convention: `apis/stubs/go/v0.0.1`
- Docker CLI can be injected into images via `COPY --from=docker:27-cli` without any daemon — clean and lightweight
- uv/uvx from `ghcr.io/astral-sh/uv:latest` provides a single-binary Python package runner, analogous to npx for Node
