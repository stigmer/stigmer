## Decisions Made

- **Dynamic discovery over static seedpack**: Originally planned to put static tool lists in seedpack YAML. Revised to dynamic discovery — tools come from the MCP server itself via CLI command. Seedpack stays lean (transport config only).
- **Custom pipeline steps (Go)**: `UpdateDiscoveredCapabilitiesInput` doesn't fit standard `LoadTargetStep` (uses `mcp_server_id` field, not embedded resource value) or `PersistStep` (input type differs from persisted type). Custom load/update/persist steps were required.
- **`CustomOperationHandlerV2` (Java)**: Selected over standard CRUD handlers because the RPC has non-standard input/output types. Used `GetByReference` handler as the primary reference pattern.

## Learnings

- Go request pipeline's `LoadTargetStep` requires input to implement `HasIdValue` interface (returns ID from embedded resource metadata). For RPCs where the target ID is in a separate field (like `mcp_server_id`), custom loading steps are needed.
- Java's `CustomOperationHandlerV2<I, O>` with `CustomOperationContextV2` is the correct base for non-CRUD operations. The `getByReference` handler pattern is the best reference for custom load + authorize + transform flows.
- Both repos have pre-existing Bazel build failures in unrelated packages — important to verify only the files touched in the session.
