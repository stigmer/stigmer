## Decisions Made

- **Agent-runner for discovery**: Both Go and Java backends offload discovery to Python agent-runner via Temporal, avoiding MCP runtime requirements in backend containers
- **Blocking RPC**: `discoverCapabilities` blocks until Temporal workflow completes (~30s timeout) — simpler than polling
- **Always-save credentials**: Discovery flow always saves to personal environment (no one-time option) — no execution context exists for one-time use
- **`api = 4` for DiscoverySource**: Used value 4 since `cli = 2` was already taken (discovered during implementation)
- **Single Python workflow**: Both backends start the same `stigmer/mcp-server/discover` workflow, centralizing MCP protocol logic
- **Standard gRPC errors over custom helpers**: Used `status.Errorf(codes.DeadlineExceeded, ...)` instead of non-existent `grpclib.DeadlineExceededError`

## Learnings

- `ExecutionProgress` takes `execution: AgentExecution | null`, not a phase string
- `MessageThread` takes `executions: readonly AgentExecution[]` + optional `activeStreamExecution`, not messages directly
- The existing `usePersonalEnvironment` + `diffEnvSpec` pattern handles credential resolution cleanly — no new credential hook architecture needed
- `serializeMcpServerYaml` already exists in `@stigmer/react` for YAML serialization
- `isTerminalPhase` from `execution-phases.ts` is the canonical way to check completion
