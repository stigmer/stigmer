## Decisions Made

1. **discovered_capabilities in status** — Updated the status.proto comment that said "tool discovery happens at RUNTIME, not here" to reflect the new CLI-driven model. Validated with user before proceeding.

2. **DiscoverySource as enum** — Chose enum over string for type safety. Values: seedpack, cli, agent_runner.

3. **google.protobuf.Struct for input_schema** — Chose Struct over string for natural YAML representation in seedpack and to avoid escaped JSON strings.

4. **DiscoveredResourceTemplate naming** — Matches MCP spec distinction between resources and resource templates. Forward-compatible.

5. **Lowercase enum values** — User requested removing prefixes and using lowercase. Applied to both ValidationState and DiscoverySource. Verified no code references to old mcpserver ValidationState values. Workflow's ValidationState already used this pattern (PENDING, VALID, INVALID).

## Learnings

- The workflow domain's `ValidationState` enum already used the short-form style (no prefix for non-zero values). This set precedent for our enum naming.
- The mcpserver `ValidationState` enum values had no hand-written code references (all references were to the workflow's separate `ValidationState`), making the rename safe.
- `buf.yaml` already has lint exceptions for `ENUM_VALUE_UPPER_SNAKE_CASE`, `ENUM_VALUE_PREFIX`, and `ENUM_ZERO_VALUE_SUFFIX`, so lowercase values pass lint.
