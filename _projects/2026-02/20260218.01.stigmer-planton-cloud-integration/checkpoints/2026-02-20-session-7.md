## Decisions Made

- **Create authorization for platform_managed**: Custom `can_edit` check on the referenced IdentityProvider (not in proto options — `is_skip_authorization = true` skips framework auto-authz, custom handler authz is written separately)
- **external_org_id uniqueness**: Scoped to IdentityProvider (different platforms may have overlapping org IDs)
- **Immutability strategy**: Reject explicit change attempts with INVALID_ARGUMENT, then always copy from existing state (handles proto3 default-value zeroing)
- **getByExternalOrgId authz**: `can_view` on IdentityProvider (caller doesn't know org ID yet)
- **Cross-domain queries**: MongoTemplate direct (follows CheckNoReferencingOrgs pattern, avoids cross-domain repo injection)

## Learnings

- The `buildNewState` step in the update pipeline replaces the entire spec from the request. Without explicit preservation, proto3 default values silently zero out immutable fields. This is a latent risk for any proto field that carries meaning.
- `is_skip_authorization = true` in proto options means "skip the framework's automatic authorization" — custom authorization must still be written in handler pipeline steps.
