## Decisions Made

- **Unit tests only (no integration tests)**: Given the Bazel/JUnit 5 runner incompatibility, focused on high-quality unit tests that compile and can be run outside Bazel. Integration tests with real infrastructure deferred.
- **Step-level execution testing**: Followed existing codebase pattern of testing individual `RequestPipelineStepV2` steps in isolation with Mockito mocks, rather than full pipeline integration.
- **UserInfoClient HTTP tests deferred**: `RestTemplate` is instantiated inline in the production code, making HTTP-level mocking impractical for unit tests. Noted as an integration test concern.
- **FederatedJwtDecoderCache creation tests deferred**: `NimbusJwtDecoder` creation involves external JWKS HTTP fetching — tested eviction semantics only.

## Learnings

- The existing test patterns in the codebase use step-level execution testing (instantiate step, call `execute()` with mocked context) rather than full pipeline integration. This provides good isolation but doesn't verify step ordering within pipelines.
- Pipeline construction tests (verifying step count and order) are a separate category used alongside step execution tests.
- Proto3 default-value semantics require special testing attention — immutability tests must verify that both explicit changes AND proto3 zero-value defaults are handled correctly.
