## Decisions Made

### `service_credential_ref` type: `ApiResourceReference` (not string)
Using the same `ApiResourceReference` message type that `AgentSpec` uses for `skill_refs` and `mcp_server_ref`. This gives us org + kind + slug fields, consistent with the rest of the platform.

### ServiceCredential is org-scoped
Initial thinking incorrectly treated ServiceCredential as a platform-level resource. Corrected: a ServiceCredential is created inside an org (e.g., the `planton` org owns its `cloud-integration` credential). This fits cleanly into the existing `ApiResourceMetadata` structure and org-scoped authorization.

### `external_org_id` retained
Serves as the reverse-lookup key for Planton's own org identifier, needed when the Stigmer slug had to be made unique (e.g., `planton-1` instead of `planton`). Planton looks up its mirror org using this field.

### All Phase 1 implementation targets `stigmer-cloud` (Java)
Organization and ServiceCredential are both `TIER_CLOUD_ONLY`. Proto definitions live in `stigmer/apis/` (shared) but controllers, Temporal workflows, MongoDB repositories, and FGA tuple registration all go in `stigmer-cloud`. No Go controllers belong in the OSS server.

### ID prefix for ServiceCredential: `svc`
Short, distinctive, collision-free with existing prefixes (`org`, `agt`, `crd`, etc.).

### Enum naming: no per-enum prefix except `_unspecified`
`management_mode_unspecified = 0`, `self_managed = 1`, `platform_managed = 2`. The containing enum name already provides the namespace. `_managed` suffix is intentionally kept as it reads naturally for humans ("this org is platform-managed").

## Learnings

- `TIER_CLOUD_ONLY` resources must not have controllers in the OSS Go server — always verify tier before implementing controllers
- `ApiResourceReference` is the canonical way to reference other resources cross-org by kind+slug — prefer it over bare strings or ID fields
- `buf generate` with remote plugins produces nested paths when the local `go.mod` isn't recognized; the `go-stubs-fix-structure` Makefile target handles cleanup
