## Decisions Made

**Use `modelcontextprotocol/go-sdk` v1.3.0 (official) not `mark3labs/mcp-go` (community)**
- Typed tool handlers: Go structs with `json`/`jsonschema` tags → auto JSON Schema
- Native `mcp.NewStreamableHTTPHandler` — no SSE proxy workaround
- Context propagation: `ctx` flows from transport → `server.Run()` → every tool handler
- Maintained by Anthropic + Google; forward-compatible with MCP spec evolution

**Place server at `mcp-server/` (repo root), not `backend/services/`**
- Not a backend service (it's client-facing infrastructure)
- Not a client app (it's not user-interactive)
- Root-level keeps it peer to `sdk/go`, `client-apps/cli`

**Use unified `search` tool instead of `list_agents` + `list_skills` + `list_workflows`**
- Critical discovery: `AgentQueryController`, `SkillQueryController`, `WorkflowQueryController` have NO list/find RPCs — only `get(ID)` and `getByReference(org/slug)`
- `SearchService.search` covers all list/search/discover patterns in a single RPC
- Tool surface: `search`, `get_agent`, `get_skill`, `get_workflow` (4 tools, not 6)

**Context-based API key propagation (no global state)**
- STDIO mode: `auth.WithAPIKey(ctx, cfg.APIKey)` injected into `server.Run(ctx, ...)` base context
- HTTP mode: `authMiddleware` extracts `Authorization: Bearer <token>` per-request
- Both paths make the key available to tool handlers via `auth.GetAPIKey(ctx)`
- gRPC calls attach it via `grpc.WithPerRPCCredentials(auth.NewTokenAuth(apiKey))`

**Convention-based TLS in gRPC client**
- `:443` endpoint → `credentials.NewTLS(nil)` (system root CAs)
- Any other port → `insecure.NewCredentials()`
- Simple, predictable, follows the same pattern as the CLI

**Shared `domains/jsonutil.go` for protojson serialization**
- `UseProtoNames: true` — proto field names (snake_case) instead of Go names (camelCase)
- `EmitUnpopulated: false` — omit zero-value fields for cleaner output
- `Multiline: true, Indent: "  "` — human-readable for AI tool output

## Key Code Patterns

**Tool handler shape (official SDK):**
```go
func Handler(serverAddress string) func(context.Context, *mcp.CallToolRequest, *InputStruct) (*mcp.CallToolResult, any, error) {
    return func(ctx context.Context, req *mcp.CallToolRequest, input *InputStruct) (*mcp.CallToolResult, any, error) {
        apiKey, err := auth.GetAPIKey(ctx)
        conn, err := stigmergrpc.NewConnection(serverAddress, apiKey)
        defer conn.Close()
        // ... call gRPC, marshal response
    }
}
```

**HTTP transport (official SDK):**
```go
handler := mcp.NewStreamableHTTPHandler(func(_ *http.Request) *mcp.Server { return s.mcp }, nil)
```

**STDIO transport (official SDK):**
```go
ctx = auth.WithAPIKey(ctx, s.config.APIKey)
return s.mcp.Run(ctx, &mcp.StdioTransport{})
```

## Key Discoveries

- The official MCP Go SDK's `NewStreamableHTTPHandler` takes a factory function `func(*http.Request) *mcp.Server` — stateless, clean
- `mcp.AddTool` is a generic function: `mcp.AddTool(srv, tool, handler)` — handler is statically typed
- The `SearchService.search` RPC supports list/search/discover with a single request type; kind enum values: `ApiResourceKind_agent=40`, `ApiResourceKind_skill=43`, `ApiResourceKind_mcp_server=44`, `ApiResourceKind_workflow=50`
- `ApiResourceReference.version` field supports empty (latest), tag name, or SHA-256 hash — only skills use this
- `go build ./cmd/mcp-server-stigmer` (without `-o`) drops binary in CWD — added to `.gitignore`
- Dockerfile must be built from repo root: `docker build -f mcp-server/Dockerfile .` because the build context needs `apis/stubs/go/`

## Open Questions / Future Work

- **T03 Tests**: No tests written yet. Need unit tests for `config`, `auth`, `domains/search` (kind parsing), and integration tests with a mock gRPC server.
- **gRPC connection reuse**: Currently each tool call creates a new connection and closes it. Fine for low volume; if profiling reveals bottlenecks, a connection pool can be introduced without changing tool handler signatures.
- **HTTP graceful shutdown**: `http.ListenAndServe` blocks indefinitely. When running in `TransportBoth` mode with a signal, the HTTP server doesn't shut down gracefully. A follow-up task should use `http.Server.Shutdown(ctx)`.
- **Versioning**: `buildVersion` is set via ldflags in the Dockerfile but returns "dev" in development. Consider embedding `debug.ReadBuildInfo()` as a fallback.
