## Decisions Made

### Auth is a property of the target, not the tool

Researched industry precedent before designing. kubectl, Pulumi, Terraform, and the MCP spec itself all follow the same pattern: authentication is optional and determined by the target backend, not enforced globally by the tool. Local development works without auth; cloud requires a token. The "fail at first call" approach (not at startup) is standard.

### Two-layer architecture

- **Layer 1 (MCP server core)**: Auth is now optional. No knowledge of CLI config files.
- **Layer 2 (CLI command only)**: Reads `~/.stigmer/config.yaml` and bridges backend settings. The standalone binary is unaffected.

### `auth.APIKey(ctx)` vs `auth.GetAPIKey(ctx)`

Added `APIKey(ctx) string` (returns empty string, no error) for use in fetch handlers that target either authenticated or unauthenticated backends. Kept `GetAPIKey(ctx) (string, error)` for strict callers (HTTP middleware). Both coexist cleanly.

### `applyCLIConfig` as a pure function

The config bridging logic was extracted into `applyCLIConfig(cfg *mcpserver.Config, cliCfg *config.Config)` so it can be tested in isolation without touching the filesystem. `applyCLIConfigDefaults` is the thin I/O wrapper that loads `~/.stigmer/config.yaml` and delegates.

### Default address for local backend

`localhost:7234` (the local daemon port) rather than the MCP server's generic default of `localhost:9090`. This aligns with how `backend.client.go` in the CLI already uses `localhost:7234`.

## Learnings

- The MCP spec explicitly makes auth optional. STDIO transport with no auth is a first-class use case, not an edge case.
- Splitting I/O (file loading) from pure logic (config bridging) makes functions trivially testable without mocking.
- `git diff HEAD --stat` run from a subdirectory only shows changes within that subdirectory — always run from repo root for the full picture.
