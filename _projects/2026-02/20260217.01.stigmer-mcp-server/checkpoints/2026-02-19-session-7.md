## Decisions Made

- **Two templates, not one**: Kept `stigmer://skills/{org}/{slug}` (latest) and added the versioned variant as a separate registration. Breaking the shorter URI would have been a regression; splitting them makes intent unambiguous in `ListResourceTemplates`.
- **New `ParseVersionedResourceURI`, existing `ParseResourceURI` untouched**: Agents and workflows use the strict 2-segment parser. Rather than changing its signature or relaxing its validation, a new function was added that accepts 2 *or* 3 segments. When 2 segments are present, `version=""` (latest). This function is already positioned to serve agents/workflows when they gain versioning.
- **Corrected next-task.md note**: The plan file described the versioned URI as "4 segments instead of 2". The actual split is `Host="skills"` (authority) + `Path="/acme/slug/stable"` = 3 path segments. The correction is documented so future work starts with accurate mental model.
- **Zero changes to existing code paths**: All existing tool/resource handlers, `Fetch()`, agents, workflows, and tests are completely untouched. The new feature is purely additive.

## Learnings

- `url.Parse` on `stigmer://skills/acme/slug/stable` yields `Host="skills"`, `Path="/acme/slug/stable"` — 3 path segments, not 4. The kind lives in the Host (authority) component, not the path. Good to have this cemented before tackling write operations.
- The versioned URI pattern is now established for skills. The same `ParseVersionedResourceURI` function can serve agents/workflows when they add versioning — no new plumbing required.
