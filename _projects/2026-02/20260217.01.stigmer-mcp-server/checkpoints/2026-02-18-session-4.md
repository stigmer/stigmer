## Decisions Made

- **Templates-only, no static list resources**: `search` tool handles discovery adequately; a static `stigmer://agents` resource cannot filter by org or paginate.
- **Skills return latest version only**: Versioned skill URIs (`stigmer://skills/{org}/{slug}/{version}`) deferred to a future task — no current use case for pinned-version resource reads established.
- **`Fetch()` returns `(string, error)` not proto**: Both tool and resource handlers need text JSON. Returning the proto would add unnecessary protojson round-trips.
- **Plain error for gRPC NotFound**: `mcp.ResourceNotFoundError(uri)` is reserved for unregistered templates. Handler-level NotFound errors use `domains.RPCError()` for consistent user-facing messages.

## Learnings

- The SDK's `AddResourceTemplate` panics on invalid URI templates — worth noting in future: register templates only with compile-time-known strings, not user input.
- The `ServerRequest[P]` generic type means `ReadResourceRequest = ServerRequest[*ReadResourceParams]` — the URI lives at `req.Params.URI`, not `req.URI`.
- `ResourceContents` uses `Text` for JSON payloads (not `Blob`) — `Blob` is for binary data.
