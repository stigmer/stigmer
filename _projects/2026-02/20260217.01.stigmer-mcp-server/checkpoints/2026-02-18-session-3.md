## Decisions Made

### Structured logging
- Chose `log/slog` (stdlib, Go 1.21+) — no new dependency, future-proof, structured output.
- All log output directed to stderr — critical invariant for STDIO transport where stdout carries the MCP protocol.
- Two new env vars: `STIGMER_MCP_LOG_FORMAT` (text/json) and `STIGMER_MCP_LOG_LEVEL` (debug/info/warn/error). Both normalized to lowercase and fully validated.
- Bootstrap problem: `fmt.Fprintf(os.Stderr, ...)` used for config parse failures that happen before slog is initialized. Clean and simple.
- Request-ID generation uses `crypto/rand` (8 bytes → 16 hex chars) rather than a UUID library dependency.

### Graceful HTTP shutdown
- `ServeHTTP()` signature changed to `ServeHTTP(ctx context.Context)` — the context flows all the way from `main.go`'s signal handler.
- 5-second grace period on shutdown (`shutdownGracePeriod` constant).
- Added `ReadHeaderTimeout: 10s` to the `http.Server` for slowloris protection — a small hardening win bundled in for free.

### gRPC error classification
- `internal/domains/rpcerr.go` — single `RPCError(err, resourceDesc)` function, keeps domain handlers clean.
- Seven code mappings cover the realistic failure modes for this server. Raw gRPC error logged at WARN for operators; user-facing message is friendly and actionable.
- `InvalidArgument` passes through the server's message verbatim — server-validated messages are already user-friendly and more specific than we can be at this layer.
- Non-gRPC errors classified as "unexpected error" with original message included.

### RPC timeout
- `DefaultRPCTimeout = 30 * time.Second` exported from `internal/grpc/` — co-located with the gRPC client factory where it semantically belongs.
- T04.2 and T04.4 were applied to domain handlers in a single pass to avoid double-editing.

## Learnings

- The MCP SDK's `ToolHandlerFor` already wraps handler errors into `CallToolResult.IsError=true` — returning a raw error from a handler is semantically correct and maps to a tool error (not a protocol crash). The improvement in T04.2 is purely about message quality, not the error routing mechanism.
- `http.ErrServerClosed` must be explicitly excluded from the error channel check in the graceful shutdown goroutine — `ListenAndServe` always returns this when `Shutdown()` is called.
- Cursor IDE's bundled Go language server is v1.23.12 but the project uses Go 1.25.6; the IDE linter shows `go.work requires go >= 1.25.6` warnings that are pre-existing and unrelated to this session's changes.
