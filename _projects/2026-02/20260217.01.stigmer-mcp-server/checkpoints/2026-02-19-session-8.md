## Decisions Made

- **Option B (versioned templates for agents/workflows) skipped**: The proto `kind_meta` explicitly marks `agent` and `workflow` as `is_versioned: false`, and `ApiResourceReference.version` docs say the field is ignored for non-versioned resources. Adding versioned URI templates would silently return the latest version regardless of requested version — a false API surface. Deferred until agents/workflows gain versioning support.

- **URI construction belongs in the MCP layer, not the proto**: The `stigmer://` scheme is MCP-specific. Adding `resource_uri` to the `SearchResult` proto would couple the core backend to MCP concerns. Presentation-layer enrichment in the search handler is the right boundary.

- **`BuildResourceURI` added to `uriutil.go`**: The inverse of `ParseResourceURI` — constructs a `stigmer://` URI from kind, org, slug. Returns empty for unsupported kinds (`mcp_server`, unknown), preserving forward compatibility as new kinds are added to the enum.

- **JSON round-trip enrichment in `enrichSearchResponse`**: The handler marshals the proto via `protojson` (to preserve proto field names, enum string names, RFC 3339 timestamps), unmarshals to `map[string]any`, injects `resource_uri` into each qualifying entry, then re-marshals with `encoding/json`. The trade-off is alphabetically sorted keys vs proto-field order — cosmetically different, semantically identical.

- **Short-circuit for empty responses**: When `len(resp.Entries) == 0`, `enrichSearchResponse` falls directly through to `domains.MarshalJSON` to avoid the round-trip overhead. Common case for queries that return no results.

- **`mcp_server` entries intentionally omit `resource_uri`**: There is no registered resource template for `mcp_server` today. The `kindToAuthority` map acts as the source of truth — if a kind isn't in the map, no URI is produced. When an `mcp_server` template is added, a single-line map entry wires it up.

## Learnings

- The `ApiResourceKind` proto's `kind_meta` option (`is_versioned`) is the authoritative source on versioning capability. Always check this before building versioned URI templates for a domain — a false API surface (silently ignoring the version) is worse than no surface at all.
- `enrichSearchResponse` uses the proto objects (type-safe) for URI construction and the JSON map for output mutation. This avoids the awkwardness of either parsing the kind string from JSON or changing the proto serialization path.
