### 3. New gRPC Endpoints for CLI

#### `uploadAttachment` RPC (command.proto)

**Purpose**: Pre-upload large files before creating agent execution.

**Handler**: `upload_attachment.go`

**Flow**:
```
1. CLI sends: { filename, content, content_type }
2. Server generates ULID for uniqueness
3. Server uploads to: attachments/{ulid}/{filename}
4. Server returns: { storage_key }
5. CLI uses storage_key in Attachment message
```

**Security**: No authorization (storage_key acts as capability token)

**Implementation Highlights**:
```go
func (c *AgentExecutionController) UploadAttachment(ctx context.Context, req *UploadAttachmentRequest) (*UploadAttachmentResponse, error) {
    uploadID := ulid.Make().String()
    storageKey := fmt.Sprintf("attachments/%s/%s", uploadID, req.Filename)
    
    // Upload with 60s timeout
    if err := c.artifactStorage.Upload(ctx, storageKey, req.Content, contentType); err != nil {
        return nil, status.Errorf(codes.Internal, "failed to upload: %v", err)
    }
    
    return &UploadAttachmentResponse{StorageKey: storageKey}, nil
}
```

#### `getArtifactDownloadUrl` RPC (query.proto)

**Purpose**: Generate presigned download URLs for execution artifacts.

**Handler**: `get_artifact_download_url.go`

**Flow**:
```
1. CLI sends: { execution_id, storage_key }
2. Server validates: execution exists
3. Server validates: storage_key starts with "artifacts/{execution_id}/"
4. Server generates presigned URL (7-day expiry)
5. Server returns: { download_url, expires_at }
6. CLI uses URL for HTTP GET download
```

**Security**: Requires `can_view` permission on execution (via proto authorization)

**Path Traversal Prevention**:
```go
// Critical security check
expectedPrefix := "artifacts/" + req.ExecutionId + "/"
if !strings.HasPrefix(req.StorageKey, expectedPrefix) {
    return nil, status.Error(codes.InvalidArgument, "storage_key does not belong to this execution")
}
```

### 4. Critical Bug Fix

**Issue**: Agent-published artifacts weren't being persisted to the database.

**Root Cause**: `update_status.go` merged `messages`, `tool_calls`, `todos` but NOT `artifacts`.

**Fix** (update_status.go:183-188):
```go
// Merge artifacts (replace with latest from request)
// Artifacts are published by agents via the publish_artifact tool during execution.
// When Python agent-runner sends artifacts via updateStatus RPC, they are persisted here.
if len(requestStatus.Artifacts) > 0 {
    updated.Status.Artifacts = requestStatus.Artifacts
}
```

**Impact**: Without this fix, agents could publish artifacts but users would never see them.

## Technical Decisions

### Why ULID for Attachment Keys?

**Considered**:
- UUID v4: Random but not sortable
- Timestamp + random: Sortable but collision risk
- ULID: Best of both worlds

**Chosen**: ULID
- **Uniqueness**: 128-bit random component
- **Sortability**: Time-ordered prefix (useful for cleanup policies)
- **URL-safe**: Works in storage paths and URLs
- **Monotonic**: Within same millisecond, maintains order

### Why Separate Upload/Download Endpoints?

**Alternative**: Stream through gRPC

**Chosen**: Presigned URLs
- **gRPC limits**: 4MB message size limit
- **Performance**: Direct S3/R2 downloads faster than server proxy
- **Cost**: Reduces server load and egress costs
- **Scalability**: Offloads transfer to cloud storage CDN

### Why 7-Day Expiration?

**Constraints**:
- R2/S3 maximum: 7 days (604,800 seconds)
- Shorter: More frequent refresh requests
- Longer: Security risk for leaked URLs

**Chosen**: 7 days (R2 maximum)
- **Convenience**: Long enough for most workflows
- **Security**: Still time-limited
- **Refresh**: CLI can call `getArtifactDownloadUrl` again if expired

## Data Flow (Complete)

### Upload Flow (CLI → Storage)
```
1. User: stigmer run agent --attach large-file.csv
2. CLI: uploadAttachment(filename="large-file.csv", content=<bytes>)
3. Server: Generate ULID, upload to attachments/{ulid}/large-file.csv
4. Server: Return storage_key
5. CLI: Create execution with Attachment.storage_key
```

### Publish Flow (Agent → Storage)
```
1. Agent: publish_artifact(path="/workspace/output.txt", name="result")
2. Python: Upload to artifacts/{execution_id}/output.txt
3. Python: Create ExecutionArtifact proto
4. Python: updateStatus RPC with artifacts[] in status
5. Go: Merge artifacts into execution.status.artifacts
6. Go: Persist to database
```

### Download Flow (Storage → CLI)
```
1. User: stigmer execution artifacts <execution-id>
2. CLI: Get execution, extract storage_keys from artifacts[]
3. User: stigmer execution download <execution-id> <storage-key>
4. CLI: getArtifactDownloadUrl(execution_id, storage_key)
5. Server: Validate ownership, generate presigned URL
6. Server: Return { download_url, expires_at }
7. CLI: HTTP GET to download_url
8. CLI: Save to local filesystem
```

## Key Learnings

### Go Backend Patterns

**Pipeline Pattern**: Other handlers use pipeline steps, but for simple operations like upload/download, direct implementation is cleaner.

**Store Interface**: Must use `GetResource()` with `apiresourcekind`, not a generic `Get()`.

**Context Timeouts**: Always use context timeouts for external operations (storage, network).

### Security Considerations

**Path Traversal**: Critical to validate storage_key prefix to prevent access to other executions' artifacts.

**Authorization Separation**:
- Upload: No auth (capability-based)
- Download: `can_view` permission (prevents unauthorized access)

**Presigned URLs**: Time-limited to reduce risk of URL leakage.

### Proto Best Practices

**Comprehensive Documentation**: Include examples, use cases, and security considerations in proto comments.

**Consistent Naming**: Follow established patterns (e.g., `Get*DownloadUrl` not `Download*`).

**Request/Response Pairs**: Clear separation of input and output messages.
