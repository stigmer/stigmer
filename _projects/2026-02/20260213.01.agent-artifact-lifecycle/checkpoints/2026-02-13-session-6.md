## Decisions Made

### 1. Complete Removal vs Deprecation

**Decision**: Remove the `content` field entirely (breaking change) rather than deprecate.

**Rationale**:
- Cleanest long-term solution
- Avoids maintaining dual paths during deprecation period
- Forces coordinated deployment (more reliable than gradual migration)
- Platform is early enough that breaking changes are acceptable

### 2. Proto Field Handling

**Decision**: Use `reserved 2` for the removed field.

**Rationale**:
- Documents that field 2 was previously used
- Prevents accidental field reuse
- Proto best practice for field removal

### 3. Backend Validation Approach

**Decision**: Simplified `processAttachmentsStep` to only validate, removed upload fallback.

**Rationale**:
- Step had single responsibility (validate)
- No longer needs artifact storage dependency
- Cleaner separation of concerns
- Upload happens at CLI, not backend

### 4. Scope Beyond Plan

**Discovery**: Found Go backend also had inline content handling (not in original plan).

**Decision**: Updated it as part of the same refactoring.

**Rationale**:
- Would leave inconsistent codebase if skipped
- Related to same architectural change
- Better to fix comprehensively now

## Learnings

### 1. Proto Changes Ripple Through Stubs

Generated stubs automatically updated when proto changed:
- Go structs no longer have `Content` field
- Python proto classes updated
- Build succeeds immediately after regeneration

### 2. Size-Based Logic Was Everywhere

Found conditional size logic in unexpected places:
- CLI attachment processor (expected)
- Backend validation step (discovered during search)
- Comments and documentation throughout

Comprehensive grep search was essential.

### 3. Breaking Changes Require Coordination

This change requires coordinated deployment:
1. Deploy CLI (always uploads)
2. Deploy backend (validates storage_key)
3. Deploy agent-runner (expects storage_key)

Out-of-order deployment will cause failures.

### 4. Function Signatures Can Simplify

`inject_attachments()` signature improved:
- **Before**: `storage: ArtifactStorage | None` (optional)
- **After**: `storage: ArtifactStorage` (required)

Type signature now matches actual usage - clearer contract.
