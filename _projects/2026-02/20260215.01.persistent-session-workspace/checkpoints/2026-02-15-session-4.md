## Decisions Made

- **Header spinner over content blocks**: Reusing the existing spinner in the header bar avoids ephemeral content blocks that would complicate block indexing. The header naturally re-renders on every Bubbletea View() cycle.
- **Separate timestamps for activity vs liveness**: `lastEventAt` tracks meaningful events (messages, tool calls), `lastBackendUpdate` tracks all stream updates (including keepalives). This allows the thinking indicator to stay visible during keepalive-only periods while still confirming the backend is alive.
- **Three-constant timing model**: `activityTickInterval=1s`, `idleThreshold=2s`, `connectionStaleThreshold=15s`. The 2s idle threshold avoids flicker during brief inter-event gaps while providing fast feedback for real thinking periods.
- **HeartbeatEvent as early return**: Handled before the main event dispatch to avoid resetting the activity tracker or touching the viewport.

## Key Code Changes

- `model.go`: Added `lastEventAt`, `thinkingVisible`, `lastBackendUpdate` fields. Spinner comment updated to reflect dual-purpose (pending + thinking).
- `update.go`: Core activity tick logic — `handleActivityTick()` checks idle threshold, `scheduleActivityTick()` returns periodic tea.Cmd. Extended spinner.TickMsg to forward during `thinkingVisible`.
- `handle_events.go`: Every event updates `lastBackendUpdate`. HeartbeatEvent returns early (liveness only). All other events reset `lastEventAt` and clear `thinkingVisible`.
- `view.go`: Header renders spinner when `pending || thinkingVisible`. Footer adds "Connection may be interrupted" case when `isConnectionStale()`.
- `run_stream_events.go`: Emits `HeartbeatEvent{}` after every `stream.Recv()` before processing messages.

## Learnings

- The backend's `StreamingUpdateScheduler` sends keepalive updates every 5 seconds, but the CLI's `streamToEvents` bridge was silently dropping them because they contained no content changes. The HeartbeatEvent bridges this gap.
- Bubbletea's `spinner.Model` can be restarted after stopping by issuing a new `m.spinner.Tick` command. The spinner naturally dies when its tick commands are no longer forwarded.

## Open Questions

- **Future enhancement**: Should the backend add an `activity_hint` field to status updates (e.g., "thinking", "generating", "executing_tool")? This would let the CLI show more specific messages instead of a generic thinking indicator.
- **`on_llm_start` capture**: LangGraph emits `on_llm_start` when the LLM call begins (before tokens). Capturing this in StatusBuilder could provide an earlier signal than waiting for the first token.
