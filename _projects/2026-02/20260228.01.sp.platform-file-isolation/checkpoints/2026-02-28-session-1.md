## Decisions Made

1. **DRY over convenience**: Extracted routing decision into shared module rather than inlining in each backend. Two copies needed (agent-runner and graphton can't share imports) but logic is identical.
2. **WorkspaceInitResult over tuple**: Positional tuple was fragile at 3 elements and would become worse at 4. Named fields are self-documenting and extensible.
3. **Cloud mode = Option 2 (physical dirs)**: Virtual mount in Daytona adds complexity for zero benefit since sandboxes are disposable. The path change alone (`bin/skills` → `.stigmer/skills`) already makes cloud mode work.
4. **Backward compatible by default**: When `platform_dir` is `None` (no session_id, or feature gated), all behavior is identical to pre-change. No flag needed — it's structurally gated.
5. **Fixed `find -o` bug**: Pre-existing bug where `-name '*.sh' -name '*.py'` (AND) should be `-name '*.sh' -o -name '*.py'` (OR). Previously masked because path comparisons failed first.

## Learnings

- The `find` command's default behavior is AND for multiple `-name` predicates — you need explicit `-o` for OR. This is easy to miss in code review.
- The virtual mount pattern (path routing at the resolution layer) is clean and doesn't require changes to the protocol surface — callers use the same paths regardless of whether the mount is active.
- Cloud mode's disposable nature means many isolation concerns simply don't apply. Don't over-engineer for parity when the deployment models have fundamentally different threat surfaces.
