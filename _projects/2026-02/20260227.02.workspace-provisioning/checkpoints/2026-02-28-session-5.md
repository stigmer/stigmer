## Decisions Made

1. **Idempotent provisioning over workspace_state**: Ground-truth detection (`.git` exists?) instead of a recorded state flag. More robust, self-healing, zero proto changes.

2. **Platform-file isolation is Phase 4** (AD-11): The user rejected the "git excludes for local_path" band-aid approach. Platform files (`bin/skills/`, `.stigmer-inputs/`) must live outside the workspace root entirely. This is the correct long-term architecture for a world-class platform.

3. **`.stigmer-inputs/` path change is universal**: Applied to all executions regardless of provisioning flag. Cleaner namespace, no collision with user project directories.

4. **`provision()` is sync, not async**: All underlying operations (`backend.execute()`, path checks) are synchronous. Fixed the misleading `async def` declaration.

## Learnings

- The `async def` on `provision()` was a latent bug — calling a sync function without `await` in an async context returns the value directly (by accident), but it's misleading. Always match the function signature to the reality of what it does.
- Platform-file placement is a foundational architecture concern. The "write into workspace + exclude from git" pattern works for git_repo but fundamentally breaks for local_path. The user's instinct to not accept the band-aid was correct — these filesystem foundations need to be right.
