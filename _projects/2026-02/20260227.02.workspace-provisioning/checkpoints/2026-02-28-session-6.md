## Decisions Made

- **Option A (download-only optimization)**: CLI always uploads to storage (preserving `storage_key`), but also sets `local_path`. Runner reads from local path when in local mode. Simpler, lower risk, preserves execution history.
- **`allow_local_path` parameter naming**: Named for what it enables (allowing local path reads), not why (local mode). Keeps `inject_attachments` decoupled from deployment-mode semantics.
- **Direct read over symlink**: Chose to read bytes from `local_path` and write via `WorkspaceBackend.write_files()` rather than symlinking. Simpler, avoids cross-filesystem issues and modification-risk concerns, sufficient given 10MB attachment size limit.
- **CLI always sets `local_path`**: CLI unconditionally sets the field to the absolute source path. Runner decides whether to use it based on `is_local_mode()`. Decouples CLI from runner execution environment.

## Learnings

- The `getattr(attachment, "local_path", "")` pattern in Python is needed because proto field access on unset fields returns the default value (empty string), but `getattr` with a fallback is safer for mocked objects in tests
- Go stubs must be regenerated after any proto change that adds a field (`make go-stubs` which runs `buf generate` + `gazelle`)
