## Decisions Made

1. **`optional int32` for depth instead of `google.protobuf.Int32Value`**: The codebase has zero wrapper type usage. `optional` is the modern proto3 approach (available since 3.15) and provides identical presence-tracking semantics (`*int32` in Go, `HasField` in Python) without introducing a new import pattern.

2. **Separate `branch` + `commit` fields instead of single `ref`**: Workspace provisioning needs both concepts -- "which branch to clone" (efficient narrow fetch) and "which commit to pin to" (reproducibility). This intentionally diverges from the `Git` message in `skill/v1/synth.proto` which uses a single `ref` because skill synth is a different use case (fetch-and-forget).

3. **CEL expression for HTTPS URL validation**: Follows the established buf-validate CEL pattern used elsewhere in the codebase (e.g., `ApiResourceReference` kind checks).

4. **`oneof source` required on `WorkspaceSource`**: An empty `WorkspaceSource{}` is an invalid state. The "no workspace" case is represented by the absence of `workspace_source` on `SessionSpec`, not by an empty wrapper. Follows the `McpServerSpec.server_type` pattern.

5. **`WorkspaceSource` as wrapper message (not inline oneof on SessionSpec)**: Keeps workspace configuration self-contained and extensible for future workspace-level fields (e.g., TTL, name).

## Learnings

- The `make go-stubs` pipeline includes a `go-stubs-fix-structure` step that moves files from a nested `github.com/stigmer/stigmer/apis/stubs/go/` path to the correct flat structure. Running `buf generate` directly without the Makefile produces files in the wrong directory.
- Gazelle (`make go-stubs-generate-build-files`) automatically updates BUILD.bazel files, so manual BUILD.bazel edits are not needed after `make go-stubs`.
- Gazelle may touch unrelated BUILD.bazel files (dependency corrections) as a side effect of a full run.
