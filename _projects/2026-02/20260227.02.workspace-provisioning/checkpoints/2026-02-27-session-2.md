## Decisions Made

1. **Protocol (structural typing) over ABC**: `WorkspaceBackend` uses `typing.Protocol` with `@runtime_checkable`. This avoids forced inheritance and allows both implementations to satisfy the interface via duck-typing. Aligns with the codebase's existing use of protocols.

2. **`execute()` as a first-class protocol method**: Initially planned for Phase 2 (git clone), but included in Phase 0 because `SkillWriter` already needed mode-dependent command execution (chmod, diagnostic ls). Including it now eliminates one more category of mode checks.

3. **`write_files()` batch method**: Essential for Daytona performance. The SDK's `upload_files()` batches uploads in a single RPC, which is significantly faster than N individual `write_file()` calls for skill artifacts. `LocalWorkspaceBackend` implements it as a simple loop.

4. **In-memory ZIP extraction**: Both `SkillWriter` and `inject_attachments` had complex mode-specific ZIP handling (local: extract to filesystem, cloud: upload base64-encoded chunks). Unified to: extract in-memory → `write_files()`. This works within defined safety limits and dramatically simplifies the code.

5. **`initialize_workspace()` return tuple**: Returns `(backend, sandbox, is_new_sandbox)` — the sandbox reference is still needed by `execute_graphton.py` for agent configuration and lifecycle management, even though workspace I/O now goes through the backend.

6. **Path traversal guard on LocalWorkspaceBackend**: `_resolve()` uses `resolved.relative_to(root)` which raises `ValueError` on traversal attempts. This is defense-in-depth since callers also validate paths, but the backend should not blindly trust its inputs.

7. **Daytona SDK output mapping**: `sandbox.process.exec()` returns a combined `.output` field (not separate stdout/stderr). Mapped to `ExecuteResult(stdout=result.output, stderr="")` — consistent with protocol shape while accommodating SDK limitations.

## Learnings

- The Daytona SDK's `sandbox.process.exec()` returns an object with a combined `.output` attribute, not separate stdout/stderr. The `ExecuteResult` abstraction smooths over this SDK limitation.
- In-memory ZIP extraction is a powerful simplification. The original code had complex branching for "extract locally to disk" vs "read in Python, upload chunks to cloud." Extracting in-memory and using `write_files()` eliminates all of this complexity.
- The `initialize_workspace()` factory still needs to return the raw sandbox object because `execute_graphton.py` uses it for agent sandbox configuration (passing to the agent runtime). This will likely be further cleaned up in Phase 2/3.
- Pre-existing Bazel BUILD.bazel glob patterns (`glob(["worker/**/*.py"])`) automatically pick up new packages, so no BUILD.bazel edits were needed for the new `worker/workspace/` package.
