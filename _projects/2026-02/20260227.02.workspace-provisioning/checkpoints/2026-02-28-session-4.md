## Decisions Made

- **SourceType enum over string**: Plan's `source_type: str` replaced with proper enum to prevent invalid values
- **dict[str, str] for merged_env**: Plan said `dict[str, EnvironmentValue]` but the call site produces `dict[str, str]` — use the real type
- **tuple[str, ...] for consumed_keys**: Plan's `list[str]` allows mutation on a frozen dataclass — use tuple for true immutability
- **Deferred imports**: Source modules import types from `provisioner.py` which imports source modules — broke the cycle with deferred imports in `_dispatch()`, matching the existing `initialize_workspace` pattern
- **Non-empty directory guard**: Added pre-clone check since `git clone` into non-empty dir produces opaque errors

## Key Code Changes

- `worker/workspace/provisioner.py`: Domain types (SourceType, GitMetadata, ProvisionResult, WorkspaceProvisionError) + WorkspaceProvisioner class with dispatch logic and WORKSPACE_PROVISION_ prefix handling
- `worker/workspace/sources/git.py`: Most complex handler — token resolution, URL injection (github.com only), clone command construction (depth/branch/commit), post-clone metadata resolution, error classification (auth/network/branch/repo), token scrubbing
- `worker/workspace/sources/local_path.py`: Cloud rejection (AD-09 v3), path validation (absolute, exists, is_dir)
- `worker/workspace/sources/empty.py`: Trivial — returns backend.root_dir unchanged
- `worker/workspace/__init__.py`: Added exports for all new provisioner types

## Learnings

- The circular import between `provisioner.py` and `sources/*.py` was predictable but not caught during planning. Deferred imports in the dispatch method was the clean solution, matching existing codebase patterns.
- Duck-typing the proto messages in tests (mock classes with `HasField()`) keeps tests independent of generated stubs while accurately simulating proto behavior.
