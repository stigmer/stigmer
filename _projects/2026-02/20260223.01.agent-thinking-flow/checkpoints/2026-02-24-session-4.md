## Decisions Made

- **Adaptive vs Manual thinking**: Opus 4.6 gets `supports_adaptive_thinking=True` (mutually exclusive with `supports_thinking`). Anthropic deprecated `type: "enabled"` for Opus 4.6; it requires `type: "adaptive"` with an `effort` parameter.
- **DEFAULT_THINKING_EFFORT = "medium"**: Conservative default, similar to how `DEFAULT_THINKING_BUDGET = 10_000` is a platform default for manual thinking. Not user-configurable.
- **Keep early `resolve_or_passthrough()`**: The early model resolution call in `execute_graphton.py` is kept for logging/heartbeat diagnostics only. The actual model creation is now deferred to `create_deep_agent()` → `parse_model_string()`.
- **`llm_kwargs` pattern**: Provider-specific params (`api_key`, `base_url`) are collected in a dict and spread into `create_deep_agent()` via `**llm_kwargs`, which forwards them as `**model_kwargs` to `parse_model_string()`.

## Learnings

- The entire Phase 2 native thinking pipeline (StatusBuilder translation, CLI streaming) was built but never activated in production because `execute_graphton.py` was pre-building model instances, bypassing `parse_model_string()`. This fix activates it for all thinking-capable Anthropic models.
- `create_deep_agent()` already had the dual-path logic (string → `parse_model_string()` vs instance → use directly). The fix simply ensures we always take the string path.
- The echo behavior was Opus 4.6-specific because it is inherently the most verbose Claude model. Without `max_tokens=20000` constraint and without an internal thinking channel, it dumped everything into response text.
