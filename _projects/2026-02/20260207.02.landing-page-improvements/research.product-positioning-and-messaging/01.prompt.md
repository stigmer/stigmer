# Deep Research Request: Stigmer Product Positioning, Messaging & Landing Page Strategy

## Research Objective

We need strategic guidance on how to position and message **Stigmer**, an open-source agentic automation platform. We're redesigning our landing page and want to get the value proposition, messaging hierarchy, and use case examples right.

## Context: What is Stigmer?

Stigmer is an **open-source platform for building AI agents AND workflow orchestration**. It has two major capabilities:

### Capability 1: AI Agents
- Define agents in YAML or Go SDK
- Agents use MCP (Model Context Protocol) servers for tools (GitHub, Slack, filesystem, databases, etc.)
- Agents run in isolated sandboxes
- Session-based conversation memory

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Agent
metadata:
  name: code-reviewer
spec:
  instructions: "Review code for quality issues"
  mcpServers:
    - github
    - filesystem
```

### Capability 2: Workflow Orchestration
- Multi-step workflows with conditional logic, loops, and branching
- **Agent chaining**: One agent's output feeds into the next agent
- Built on Temporal for durability, automatic retries, and state management
- Supports CNCF Serverless Workflow specification
- Can mix agents with non-agent tasks

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Workflow
metadata:
  name: pr-review-pipeline
spec:
  tasks:
    - name: fetch-pr
      agent: github-analyst
      inputs:
        pr_url: "${workflow.inputs.pr_url}"
    
    - name: review-code
      agent: code-reviewer
      inputs:
        code: "${tasks.fetch-pr.output}"
    
    - name: post-comment
      agent: github-commenter
      inputs:
        review: "${tasks.review-code.output}"
```

### Technical Foundation
- **Local-first**: Runs entirely on your laptop with SQLite + Ollama (free local LLM)
- **Cloud-ready**: Same code deploys to Stigmer Cloud for production
- **gRPC APIs**: Call agents/workflows from any language (Go, Python, Java, TypeScript, Rust)
- **Temporal orchestration**: Durable execution, automatic retries, event sourcing
- **Apache 2.0**: Fully open source

## The Problem: Current Website Messaging

Our current landing page has several issues:

1. **Implementation-focused, not value-focused**: We lead with "sandboxing, orchestration, MCP security" instead of the problems we solve

2. **Agent-centric, ignoring workflows**: Website focuses almost entirely on agent creation, but workflow orchestration (multi-agent pipelines, BPMN-style processes) is equally important

3. **Generic placeholders**: Architecture diagram uses "App 1", "App 2" instead of concrete use cases

4. **No executable examples**: We describe features but don't show real workflows with clear inputs/outputs

5. **Missing the "why"**: We jump to "How It Works" without first establishing "Why Stigmer"
