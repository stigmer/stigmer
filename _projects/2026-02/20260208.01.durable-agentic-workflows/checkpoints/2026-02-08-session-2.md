## Decisions Made

### Major Decision: Skip Tool Ledger Implementation

**Rationale:**
- LangGraph checkpoints provide durability for 90%+ of cases
- The edge case (crash during tool execution before checkpoint) is rare
- Complexity cost of Redis-backed ledger exceeds benefit
- Tool idempotency is better solved at the tool level (API idempotency keys)

**Accepted Tradeoff:**
- Small window where tool may execute twice if crash occurs during tool execution
- Mitigated by documenting tool idempotency best practices

### Architecture Choice: Heartbeat-based Resume

**Approach:**
- Leverage existing Temporal heartbeat mechanism
- Include `thread_id` in heartbeat payload
- On retry, extract `thread_id` from `heartbeat_details`
- LangGraph handles checkpoint loading automatically

**Benefits:**
- Zero new infrastructure (no Redis, no new tables)
- Works with existing checkpointer (MongoDB/SQLite)
- Simple implementation (~70 lines of code)
- Reliable recovery mechanism

attempt = activity.info().attempt
heartbeat_details = activity.info().heartbeat_details
is_retry = attempt > 1 and heartbeat_details is not None

if is_retry:
    # Extract thread_id from last heartbeat for checkpoint resume
    last_heartbeat = heartbeat_details[0] if isinstance(heartbeat_details, (list, tuple)) else heartbeat_details
    
    if isinstance(last_heartbeat, dict) and "thread_id" in last_heartbeat:

## Learnings

### 1. LangGraph Checkpoint Mechanics
- LangGraph automatically loads checkpoint when invoked with existing `thread_id`
- No manual state loading needed
- Checkpoint saves happen after each significant step
- Works with MongoDB (cloud) and SQLite (local)

### 2. Temporal Heartbeat Pattern
- `heartbeat_details` is accessible via `activity.info().heartbeat_details`
- Can be tuple/list or single dict depending on heartbeat history
- Provides reliable cross-retry communication channel
- Zero additional infrastructure needed

### 3. Simplicity Over Completeness
- Perfect idempotency (tool ledger) would add significant complexity
- Checkpointing handles 90%+ of crash scenarios
- Remaining edge case is acceptable tradeoff
- Documentation helps tool authors handle critical cases
