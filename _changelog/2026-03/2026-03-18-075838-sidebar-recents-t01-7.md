# T01.7 — Sidebar Recents: Live Session List with Time Grouping

**Date**: March 18, 2026

## Summary

Populated the sidebar "Recents" section with live session data, replacing the static placeholder. Sessions are fetched via a new `useSessionList` SDK hook, grouped by time period ("Today", "Yesterday", "Previous 7 Days", "Previous 30 Days", "Older"), and rendered with active-session highlighting. This completes the final task (T01.7) of the session-first web UX project.

## Problem Statement

The sidebar had a hardcoded empty state placeholder where recent sessions should appear. Users who created sessions had no way to navigate back to them from the sidebar -- they could only reach past sessions by knowing the URL.

### Pain Points

- No session history in the sidebar -- users lost access to previous sessions after navigating away
- No visual indication of which session is currently active
- The sidebar "Recents" area was a dead zone with a static "No recent sessions" message regardless of actual session count

## Solution

Added a `useSessionList` data hook and `groupSessionsByTime` utility to the React SDK, then wired them into the Console sidebar with time-grouped rendering, active-session highlighting, and loading/error/empty states.

## Implementation Details

### SDK Layer (`@stigmer/react`)

**`useSessionList`** -- new data hook following the established `useSessionExecutions` pattern:
- Calls `stigmer.session.list(ListSessionsRequest)` with configurable `pageSize` (default 50) and optional `tags` filter
- `useEffect` + `useState` + `cancelled` ref + `fetchKey` for `refetch()`
- Stable `tags` reference via `useRef` + deep comparison to prevent spurious re-fetches
- Org scoping handled at transport level (consistent with all existing data hooks)

**`groupSessionsByTime`** -- pure utility function (no React dependency):
- Groups sessions into 5 time-based buckets using `timestampDate()` from `@bufbuild/protobuf/wkt`
- Empty groups omitted from output
- `now` parameter for deterministic testing
- Preserves input order within each group

### Console Layer (`client-apps/web`)

**`Sidebar.tsx`** -- rewired from placeholder to live data:
- `usePathname()` triggers `refetch()` on navigation changes (catches new session creation, session switches, returns to launcher)
- Active session extracted from URL and highlighted with `aria-current="page"`
- `SessionGroupList` renders time-grouped sections with group labels and clickable session items
- `RecentsSkeletons` (loading), `RecentsError` (inline error + empty state), `RecentsEmptyState` (no sessions)

### New SDK Exports

- `useSessionList`, `UseSessionListOptions`, `UseSessionListReturn`
- `groupSessionsByTime`, `SessionGroup`

## Benefits

- Users can navigate between sessions from the sidebar without remembering URLs
- Time grouping provides temporal orientation (matching Claude/ChatGPT patterns)
- Active session is visually distinct, reducing navigation confusion
- Platform builders get a reusable `useSessionList` hook and `groupSessionsByTime` utility for building their own session list UIs

## Impact

- **End users**: Sidebar is now functional -- the primary navigation path for session history
