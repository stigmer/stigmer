# Archive Existing Docs and Design Fresh Content Architecture

**Date**: March 22, 2026

## Summary

Archived all 116 legacy documentation files to `docs/_archive/` (preserving full git history) and replaced them with a fresh, platform-builder-oriented content architecture. Scaffolded 36 new `.mdx` files across 10 sections, wrote 3 seed pages that set the quality bar for all future documentation, and validated the entire surface passes Vale linting and Prettier formatting with zero errors.

## Problem Statement

Stigmer's `docs/` directory contained 112+ markdown files accumulated over months of rapid development. These files were internally focused, inconsistently structured, written for different audiences, and failed every quality gate (3,207 Vale errors, 6,956 warnings, 112 Prettier violations, 64 broken links). They couldn't serve as the foundation for a public documentation site.

### Pain Points

- No coherent information architecture: files scattered across `adr/`, `architecture/`, `product/`, `guides/`, `engineering/`, `implementation/`, `sdk/`
- Written for internal engineers, not platform builders (the target audience)
- Mixed levels of completeness: some files were thorough, many were stubs or drafts
- Domain terminology used inconsistently (lowercase "agent" vs capitalized "Agent")
- Existing content couldn't pass even basic linting — blocked CI integration
- No clear path for a documentation site to render this content

## Solution

A clean-break approach: archive everything, design a purpose-built content architecture, and write a small number of exemplary pages that establish voice, structure, and quality standards for the entire documentation surface.

## Implementation Details

### Phase 1: Archive (116 files)
- Moved all existing `docs/` content to `docs/_archive/` using `git mv` to preserve commit history
- Updated `.vale.ini` with a `[docs/_archive/**.{md,mdx}]` section that disables all style checks on archived content
- Created a `DOCS_SOURCES` variable in the Makefile using `find docs -path docs/_archive -prune -o \( -name '*.md' -o -name '*.mdx' \) -print` — all 5 docs targets share this variable
- Verified: `make lint-docs`, `make format-docs-check`, and `make check-links` all skip archived files

### Phase 2: Content Architecture (10 sections, 36 files)
- Designed around the platform builder journey: learn → understand → integrate → operate
- Sections: getting-started, concepts, integration, sdks, architecture, deployment, cli, reference, contributing
- Every section has an `index.mdx` with proper frontmatter (`title`, `description`)
- All placeholder pages include a descriptive heading and "under development" notice

### Phase 3: Seed Pages (3 files)
- **`docs/index.mdx`** — "What is Stigmer?": Resource model, Blueprint vs Runtime separation, four building blocks (Instructions, Tools, Knowledge, Delegation), platform builder benefits, Durable Execution explanation
- **`docs/getting-started/installation.mdx`** — Install via Homebrew/script/source, configure an LLM provider (Anthropic/OpenAI/Ollama), start and verify the local server
- **`docs/concepts/agents.mdx`** — Agents as declarative blueprints, 4-layer execution stack (Agent → Agent Instance → Session → Execution), building blocks, lifecycle control (pause/resume/cancel/terminate/recover), versioning, visibility

### Phase 4: Vale Tuning
- Disabled 4 rules that conflict with domain terminology: `Google.Headings`, `Microsoft.Terms`, `Microsoft.Avoid`, `Microsoft.HeadingPunctuation`
- Added 10 terms to custom vocabulary: Ollama, ADRs, backend, backends, namespaces, hardcoding, versionable, runbooks, auditable, autogenerated

### Phase 5: Validation
- `make lint-docs`: 0 errors, 0 warnings across 36 files
- `make format-docs-check`: all files pass
- Archive fully excluded from all tooling

## Benefits
