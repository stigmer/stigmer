# Execution Artifact Data Hooks and Content RPC

**Date**: March 20, 2026

## Summary

Added the data layer for execution artifact handling: a new `getArtifactContent` backend RPC for CORS-free content reading, two React hooks (`useExecutionArtifacts`, `useArtifactContent`), and four utility functions — establishing the SDK-first foundation for the Artifacts Widget and Apply Flow in Phase 2.

## Problem Statement

Execution artifacts (YAML files, scripts, configs) generated by agent runs had no programmatic access layer. The Console needed to display artifact content, detect Stigmer resources within YAML files, and offer one-click apply — all of which require reading artifact content.

### Pain Points

- No React hooks existed for accessing execution artifact metadata or content
- Direct browser `fetch()` to R2 pre-signed URLs introduces CORS dependency, breaking SDK consumers embedding Stigmer in their own domains
- No utility functions for common artifact operations (extension detection, text heuristics, expiration checks, human-readable sizes)
- `int64` proto fields (`size_bytes`) map to `bigint` in TypeScript, requiring careful handling in formatting utilities

## Solution

Introduced a three-layer approach following the SDK-first, headless-first architecture:

1. **Backend RPC** (`getArtifactContent`): Server-side proxy that reads from R2 and returns content bytes, eliminating client-side CORS concerns
2. **Derivation hook** (`useExecutionArtifacts`): Pure `useMemo` extraction of artifact metadata from an execution object
3. **Data-fetching hook** (`useArtifactContent`): Declarative hook that calls the new RPC, with null-skip pattern and refetch support
4. **Utility functions**: Four pure functions for artifact extension, text detection, expiration, and size formatting

## Implementation Details

### Proto Changes (`apis/`)

- **`io.proto`**: Added `GetArtifactContentRequest` (execution_id, storage_key, max_bytes) and `GetArtifactContentResponse` (content bytes, content_type, total_size_bytes, truncated) with full field documentation
- **`query.proto`**: Added `getArtifactContent` RPC to `AgentExecutionQueryController` with IAM authorization config (resource_kind: agent_execution, permission: can_view)
- Server enforces `max_bytes` (default 512KB) — truncation is server-side, not client-side

### TypeScript Stubs (Temporary Scaffolding)

- Manually added type definitions and schemas to `io_pb.ts`, `query_pb.ts`, `query_connect.ts`
- Manually added `getArtifactContent` method to `AgentExecutionClient` in `sdk/typescript/`
- These will be properly regenerated by `buf generate` + `stigmer-codegen`

### React SDK (`sdk/react/src/execution/`)

**`useExecutionArtifacts`** — Pure derivation hook:
- Input: `AgentExecution | null`
- Returns: `{ artifacts, hasArtifacts, artifactCount }`
- Pattern: Follows `useExecutionUsage` precedent — `useMemo` over execution reference

**`artifact-utils.ts`** — Four pure functions:
- `getArtifactExtension`: Extracts file extension from artifact name
- `isTextArtifact`: Heuristic check via extension set (yaml, json, txt, md, py, ts, etc.)
- `isArtifactExpired`: Checks `expiresAt` timestamp against `Date.now()`
- `formatArtifactSize`: Converts `bigint | number` bytes to human-readable string (B/KB/MB/GB)

**`useArtifactContent`** — Data-fetching hook:
- Input: `executionId: string | null`, `storageKey: string | null` (null = skip)
- Returns: `{ content, contentType, isTruncated, isLoading, error, refetch }`
- Uses `TextDecoder` to decode response bytes to string
- Error type: `string | null` (matches `useResourceList` pattern)
- Cleanup via `cancelled.current` ref pattern

### Barrel Exports

- `sdk/react/src/execution/index.ts`: All hooks and utilities
- `sdk/react/src/index.ts`: Re-exports including `ExecutionArtifact` type and `ExecutionArtifactKind` enum from protos

## Benefits

- **CORS-free content access**: Platform builders embedding Stigmer don't need to configure R2 CORS headers
- **Composable hooks**: Each hook has a single responsibility — derivation, fetching, and detection (T02.2) are independently importable
- **Headless-first**: All data access is via hooks — no UI coupling. Platform builders can use `useArtifactContent` without any Stigmer UI components
- **Type-safe**: Full TypeScript types from protobuf, including `bigint` handling for `size_bytes`
- **Consistent patterns**: Follows established conventions (`useExecutionUsage`, `useResourceList`) for return shapes and error handling

## Impact

- **SDK consumers**: Can now programmatically access artifact content and metadata
- **Console**: Foundation for ArtifactCard, ArtifactPreviewModal, and ArtifactsWidget (T02.4–T02.6)
- **Backend**: Requires new `getArtifactContent` handler implementation in `stigmer-cloud` (reads from R2)
- **Codegen**: Requires `buf generate` + `stigmer-codegen` run to replace manual scaffolding
