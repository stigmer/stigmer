# Positioning Document — Stigmer Content Strategy Phase 1

**Date**: March 31, 2026

## Summary

Created the positioning document that serves as the strategic foundation for all Stigmer messaging — sales website, documentation, README, conference talks, and social media. This is the first of five Phase 1 deliverables in the content strategy project, and every subsequent deliverable builds on the decisions made here.

## Problem Statement

After Phase 0 cleared all stale documentation and infrastructure-engineer-focused sales copy, the Stigmer sales site and docs had no messaging foundation. The site had placeholder copy ("AI Agent Platform") with no defined audience, no positioning statement, no competitive framing, and no tone guidance.

### Pain Points

- No agreed-upon audience definition — was Stigmer for infrastructure engineers, developers, or founders?
- Multiple conflicting category labels in the codebase ("agentic automation platform," "AI Agent Platform," "agent infrastructure")
- Cloud-first vs OSS-first positioning unresolved
- No framework for evaluating copy consistency across the sales site, docs, and README

## Solution

Created a comprehensive internal strategy document at `_projects/2026-03/20260331.01.content-strategy/design-decisions/positioning.md` with seven sections covering audience, positioning statement, messaging pillars, boundaries, competitive framing, headline options, and tone guidance.

## Implementation Details

### Strategic Decisions Resolved

1. **Audience**: Two concentric audiences — technical founders and engineering leads (primary, sales site) and developers (secondary, docs/quickstart)
2. **Category**: "AI Agent Platform" — validated as analyst-recognized category with Forrester, Gartner, and market research backing (~$1B market in 2025, $23B+ projected by 2029)
3. **Cloud-primary positioning**: Sales site leads with cloud ("sign up, get API key"), open source as trust signal, README stays developer-first
4. **Business-outcome headline**: All hero registers in business language; technical language in dedicated sections further down

### Messaging Framework

- **Headline**: "Build agents that work for your business"
- **Sub-headline**: "Teach them your domain. Connect your tools. Set your rules."
- **Three messaging pillars**: Knows Your Business (Skills) / Uses Your Tools (MCP) / Asks Before Acting (HITL)
- **Foundation pillar**: Built for Production (Temporal, gRPC, open source)

### Document Structure

Seven sections: Audience, Positioning Statement, Messaging Pillars, IS vs IS NOT, Competitive Framing, Headlines & Descriptions, Tone and Voice.

## Benefits

- Single source of truth for all Stigmer messaging decisions
- Clear audience definition prevents copy that targets the wrong reader
- Competitive framing gives consistent language for differentiation without naming competitors
- Tone guidance prevents voice inconsistency across sales site, docs, and README
- Headline and description variants at multiple lengths (tagline, one-sentence, one-paragraph, elevator pitch)

## Impact

- **Sales website**: Phase 2 can now draw directly from this document for all copy
- **Documentation**: Audience definition and voice guidance inform every page
- **README**: Explicitly scoped as a separate voice (developer-direct) from the sales site
- **Future deliverables**: Vocabulary guide, demo story, use cases, and information architecture all build on these decisions
