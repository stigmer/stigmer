# T01.9: Product Documentation — Eliminate org: local, Unify Org Context Docs

**Date**: March 3, 2026

## Summary

Eliminated all `org: local` references from documentation that feeds into skill generation, consolidated two overlapping CLI configuration docs into a single coherent document, and added documentation for the new unified organization context model (`--org` flag, `stigmer context`, `STIGMER_ORG_ID` injection, resolution priority chain).

## Problem Statement

The T01.6–T01.8 work eliminated all hardcoded `org: local` from CLI code, seedpack YAML, and skill docs. However, the product documentation and API resource docs still referenced `org: local` extensively — including the files directly attached as spotlight context to the skill generation scripts (`seedpack/tools/02_*.sh`, `03_*.sh`). Regenerating skills with stale docs would reintroduce the patterns that were just removed.

Additionally, the CLI configuration documentation was split across two overlapping files (`configuration.md` and `configuration-cascade.md`) and neither documented the new org context features from T01.7/T01.8.

### Pain Points

- Skill generation scripts attach `docs/product/what-is-agent.md`, `what-is-mcp-server.md`, and the full `apis/ai/stigmer/agentic/agent/docs/` and `mcpserver/docs/` directories — all contained stale `org: local`
- `docs/cli/configuration.md` had no mention of `context.organization`, `--org` flag, `stigmer context` commands, or `STIGMER_ORG_ID`
- `docs/cli/configuration-cascade.md` (400 lines) repeated most of `configuration.md` with no clear audience separation
- `resource-references.md` still documented `org` as "Required" despite T01.3 making it optional

## Solution

Three categories of changes:

1. **Product docs** (7 files): Replace `org: local` with appropriate pattern — `default` for getting-started metadata, omit org for cross-references (relative reference pattern from T01.3), `acme-corp` for illustrative examples
2. **API resource docs** (13 files): Same patterns, plus rewrite of `resource-references.md` to document relative vs absolute references, and update of all "Local Mode" / "Cloud Mode" prose to unified org model
3. **CLI config docs** (2 → 1 file): Consolidated into single `configuration.md` with new Organization Context section; deleted `configuration-cascade.md`

## Implementation Details

### Product docs (`docs/product/`)

- `what-is-organization.md` — Rewrote "Local Mode" / "Cloud Mode" sections into unified "Default Organization" section documenting auto-bootstrap, `stigmer context`, and the resolution chain
- `what-is-agent.md` — Cross-reference uses relative ref (no org), Getting Started uses `org: default`
- `what-is-mcp-server.md`, `what-is-project.md`, `what-is-skill.md`, `what-is-workflow.md` — Same pattern
- `docs/guides/uploading-skills.md` — Replaced local/cloud backend split with unified org context

### API resource docs (`apis/`)

- `agent/docs/resource-references.md` — Complete rewrite: org field from "Required" to optional, documented relative vs absolute references, updated validation rules
- `agent/docs/agent-resource-guide.md` — org field from "Depends" to "Recommended", removed local/cloud table
- `agent/docs/examples.md` — All examples use relative references; "Full-Featured Agent (Local Mode)" renamed to "Full-Featured Agent"; "Cloud Mode" section renamed to "Public Marketplace Agent"
- `agent/docs/validation-checklist.md` — Updated org guidance, fixed all example YAMLs
- `agent/docs/mcp-server-integration.md`, `skill-integration.md`, `sub-agents.md` — Cross-references use relative refs
- `mcpserver/docs/mcpserver-resource-guide.md`, `examples.md`, `tool-approval-policies.md`, `validation-checklist.md` — Same patterns
- `skill/docs/skill-resource-guide.md`, `examples.md` — Removed local/cloud table, relative refs

### CLI configuration consolidation

- New `docs/cli/configuration.md` — Added Organization Context section documenting: `--org` global flag, `stigmer context show/set --org`, `context.organization` config key, `STIGMER_ORG_ID` runtime injection, resolution chain
- Merged config precedence from cascade doc
- Consolidated env var reference table (added `STIGMER_ORG_ID`, `STIGMER_OUT_DIR`)
- Deleted `docs/cli/configuration-cascade.md`
- Updated `docs/README.md` link

## Benefits

- Skill regeneration will now produce clean output without `org: local` references
- Single source of truth for CLI configuration (one file, not two)
- `resource-references.md` accurately documents optional org and relative reference pattern
- No more "Local Mode" / "Cloud Mode" dichotomy in docs — unified model matches the codebase
