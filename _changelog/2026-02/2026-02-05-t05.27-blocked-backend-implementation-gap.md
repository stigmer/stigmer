# T05.27 Integration Tests - BLOCKED (Backend Implementation Gap)

**Date**: 2026-02-05  
**Status**: ⚠️ **BLOCKED**  
**Task**: T05.27 Integration Tests - End-to-End SDK to Deploy workflow testing  
**Reason**: Project entity handlers not implemented in OSS Go backend

---

## Issue Summary

**Discovery**: While attempting to run T05.27 integration tests, discovered that the Project entity backend handlers do not exist in the OSS Go backend (`stigmer/backend/services/stigmer-server`).

**Root Cause**: 
- Phase 5 plan (T05.0-T05.28) was designed for the **stigmer-cloud Java backend**
- Project handlers (T05.5-T05.11) were implemented in Java: `ProjectCommandController`, `ProjectQueryController`, `ProjectReconciliationService`
- These handlers were **never ported** to the OSS Go backend
- CLI has Project Track support (`stigmer apply`) but backend cannot handle Project RPCs

---

## What Exists vs What's Missing

### ✅ Implemented (OSS)

**CLI Side** (`stigmer/client-apps/cli`):
- ✅ T05.1-T05.4: Project package with applier, get, delete (Go)
- ✅ T05.21-T05.24: `stigmer apply` command with SDK synthesis (Go)
- ✅ T05.26: CLI unit tests (partial - 2/6 suites complete)

**Test Infrastructure** (`stigmer/test/e2e`):
- ✅ T05.27: Integration test files written (~24 tests across 6 files)
- ✅ Test fixtures created (6 SDK project examples in `testdata/project/`)
- ✅ Test helpers (`project_test_helpers.go`, `project_test_constants.go`)

### ❌ Missing (OSS)

**Backend Side** (`stigmer/backend/services/stigmer-server`):
- ❌ T05.0: Project proto types (ReconciliationSummary exists in proto but unused)
- ❌ T05.5: ProjectRepo (MongoDB/SQLite repository)
- ❌ T05.6-T05.11: Project handlers (Create, Update, Delete, Apply, Get, GetByReference)
- ❌ T05.12-T05.20: Reconciliation domain layer:
  - DependencyGraph, ReconciliationPlan value objects
  - DependencyDiscoverer (reflection-based)
  - DependencyGraphBuilder
  - ProjectReconciliationService
  - Diff algorithm, dependency ordering, orphan pruning
- ❌ T05.25: Backend unit tests (no tests because no code)

## Build/Compilation Fixes Applied

While investigating, fixed several build issues to enable compilation:

### 1. Proto Import Path Update
**File**: `backend/services/stigmer-server/pkg/query/search/handler/search_handler.go`
- **Changed**: `github.com/bufbuild/protovalidate-go` → `buf.build/go/protovalidate`
- **Reason**: Protovalidate package renamed/moved
- **Impact**: Search handler now compiles

### 2. Validator Type Fix
**File**: `backend/services/stigmer-server/pkg/query/search/handler/search_handler.go`
- **Changed**: `*protovalidate.Validator` → `protovalidate.Validator` (interface not pointer)
- **Reason**: API change in protovalidate
- **Impact**: Search handler validates requests correctly

### 3. Removed Dead Code
**File**: `backend/services/workflow-runner/pkg/converter/task_converters.go`
- **Removed**: References to `cfg.Scope` field (doesn't exist in proto)
- **Reason**: Proto definition evolved, field removed
- **Impact**: Workflow converter compiles

### 4. SQLite Store Type Assertion Fix
**File**: `backend/services/stigmer-server/pkg/server/server.go`
- **Changed**: `store.(*sqlite.Store).DB()` → `store.DB()`  
- **Reason**: Store is concrete type, not interface
- **Impact**: Search query store initialization works

### 5. Legacy Apply Stub
**File**: `client-apps/cli/cmd/stigmer/root/run_execute.go`
- **Added**: Stub for deprecated `ApplyCodeMode()` function
- **Reason**: `stigmer run` auto-discovery uses legacy code path

### 6. Test Helper Proto API Updates

- **Reason**: Proto definitions evolved
- **Impact**: Test helpers compile (tests still blocked by missing backend)

## Path Forward

### Option 1: Port Java Backend to Go (Large Effort)

**Estimate**: ~3-5 days of focused work

**Tasks**:
1. Port Project repository (SQLite) - 4-6 hours
2. Port Project handlers (Create, Update, Delete, Apply, Get, GetByReference) - 8-12 hours
3. Port reconciliation domain layer - 12-16 hours:
   - Value objects (DependencyGraph, ReconciliationPlan, etc.)
   - DependencyDiscoverer (proto reflection)
   - DependencyGraphBuilder
   - ProjectReconciliationService
   - Diff algorithm, dependency ordering, orphan pruning
4. Port backend unit tests (61 tests from Java) - 6-8 hours
5. Integration test verification (T05.27) - 2-3 hours

**Pros**:
- Completes Phase 5 for OSS
- Users can use Project Track
- Integration tests can run

**Cons**:
- Large effort (~40+ hours)
- Duplicates work already done in Java
- May have subtle bugs during port

### Option 2: Document as OSS/Cloud Feature Split

**Estimate**: 1-2 hours

**Tasks**:
1. Update documentation to clarify Project Track is cloud-only
2. Mark T05.27 as "cloud-only" or "future work"
3. Users use Atomic Track (`stigmer agent apply`, `stigmer workflow apply`) in OSS
4. Project Track available in stigmer-cloud

**Pros**:
- No implementation work
- Clear feature boundaries
- OSS still fully functional (Atomic Track)

**Cons**:
- Feature parity gap between OSS and cloud
- Users need to use different workflows
- Integration tests written but unusable

### Option 3: Hybrid Approach (Recommended)

**Estimate**: 4-6 hours

**Tasks**:
1. Document current state (this changelog)
2. Update T05.27 status to BLOCKED in tracker
3. Create follow-up task for backend port
4. Focus remaining Phase 5 effort on:
   - Complete T05.26 (CLI unit tests - 4 remaining suites)
   - T05.28 (Documentation)
5. Defer Project Track backend to Phase 6 or separate initiative

**Pros**:
- Acknowledges reality without blocking other work
- CLI code remains useful for future
- Clear next steps documented
- Can prioritize based on user demand

**Cons**:
- Phase 5 "incomplete" (but documented)
- Project Track unavailable in OSS temporarily
