# Workspace Awareness in Agent System Prompt (Phase 5)

**Date**: February 28, 2026

## Summary

Agents now receive a `## Workspace` section in their system prompt that describes the workspace they're operating in. This completes the workspace provisioning feature's prompt integration — agents know whether they're working in a cloned git repo, the user's local project directory, or an empty workspace, and receive appropriate guidance for each context.

## Problem Statement

After Phases 0–4 of the workspace provisioning project, the backend correctly provisions workspaces (git clone, local path validation, empty creation) and isolates platform files via the virtual mount. However, the agent itself had no awareness of its workspace context — it didn't know it was operating on a git repo, what branch it was on, or whether changes were persistent.

### Pain Points

- Agent couldn't guide the user about change persistence (local path = immediate, git repo = captured as artifacts)
- No exploration hints ("start by listing root directory") for newly cloned repositories
- Missing safety warning when operating directly on user's files (`local_path` source)
- The `workspace_description` field on `ProvisionResult` was generated by all three source handlers but never surfaced to the agent

## Solution

Inject a `## Workspace` section into the enhanced system prompt, positioned between the base instructions and the skills section. The section content comes from `ProvisionResult.workspace_description`, which is already generated by each source handler with context-appropriate guidance.

Additionally, fixed stale path references in graphton's `FILESYSTEM_CAPABILITY` constant that still pointed to pre-Phase 4 paths (`bin/skills/`, `inputs/`).

## Implementation Details

**New function** — `build_workspace_prompt_section()` in `execute_graphton.py`:
- Pure function: takes `ProvisionResult | None`, returns section string or empty string
- Follows the same extraction pattern as `inject_attachments` and `_auto_publish_written_files`
- Testable in isolation without the full activity function setup

**Prompt assembly ordering** — `instructions → Workspace → Skills → Input Files → Response Rules → Delegation Rules`:
- WHERE you work (workspace) before HOW you work (skills) before WHAT data you have (input files) before behavioral rules

**Path reference fix** — `prompt_enhancement.py` `FILESYSTEM_CAPABILITY`:
- `inputs/data.txt` → `.stigmer/inputs/data.txt`
- `bin/skills/my-skill/SKILL.md` → `.stigmer/skills/my-skill/SKILL.md`

**Backward compatible** — When provisioning is inactive (`provision_result` is `None`), no workspace section is added. Existing behavior unchanged.

## Benefits

- Agents give context-appropriate guidance to users (persistence warnings, exploration hints)
- System prompt now has complete workspace awareness matching the provisioning layer's capabilities
- Stale path references no longer contradict the actual skill/input file locations
- Clean, testable function follows established codebase patterns

## Impact

- **Agent behavior**: Agents operating in provisioned workspaces now have full context about their environment
- **User experience**: Users receive appropriate warnings (e.g., "operating directly on your files") and guidance (e.g., "start by listing root directory")
- **Codebase quality**: Eliminated stale path references that could confuse the LLM
