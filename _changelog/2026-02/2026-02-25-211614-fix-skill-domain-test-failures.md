# Fix Skill Domain Test Failures

**Date**: February 25, 2026

## Summary

Fixed all failing tests in the skill domain (controller + storage packages) by aligning test data with two schema evolutions: `org` became a required field on `PushSkillRequest` and `ApiResourceReference`, and `ExtractSkillMd` now validates YAML frontmatter in `SKILL.md`. Also resolved a test timeout caused by byte-by-byte ZIP writes and several pre-existing compression-ratio test data bugs.

## Problem Statement

After recent proto schema and business logic changes, approximately 35 tests across the skill domain were failing. These failures were blocking the `make check` CI gate and masking real regressions.

### Pain Points

- `PushSkillRequest.org` and `ApiResourceReference.org` gained `buf.validate` `required` constraints, but no test was providing the `org` field
- `ParseFrontmatter` now enforces that `SKILL.md` starts with `---` YAML frontmatter containing a kebab-case `name`, but test content used raw markdown headings
- `CreateLargeUncompressedZip` wrote 550MB byte-by-byte, causing a 30-second timeout panic
- Several negative tests ("empty name", "invalid name") were passing for the wrong reason — the missing `org` field triggered `InvalidArgument` before the intended validation could fire
- ZIP test helpers generated highly compressible content (repeated bytes), triggering compression-ratio safety checks before the intended size-limit validations

## Solution

Systematic, plan-driven fix of all affected tests with three design principles:

1. **Explicit content construction** — a new `ValidSkillContent(name, body)` helper builds frontmatter-compliant SKILL.md content; `CreateTestZip` remains a raw passthrough so negative tests can still inject invalid content
2. **Org everywhere** — every `PushSkillRequest` and `ApiResourceReference` in tests now carries `Org: "test-org"` (or a test-appropriate org value)
3. **Correct test data for security checks** — ZIP helpers now produce content with controlled compression ratios using PRNG-generated bytes, `zip.Store` headers, and varied printable text

## Implementation Details

### New Test Helper: `ValidSkillContent`

```go
func ValidSkillContent(name, body string) string {
    return fmt.Sprintf("---\nname: %s\n---\n%s", name, body)
}
```

Produces valid frontmatter without hiding complexity inside `CreateTestZip`. Every test that expects Push/Extract to succeed calls this explicitly, making intent visible in the test body.

### `createTestSkill` / `createTestAuditRecord` Signature Change

Both helper functions gained an `org` parameter, ensuring skills stored directly in the test DB have `Metadata.Org` set — critical for `GetByReference` tests that filter by org.

### Chunked ZIP Writes

`CreateLargeUncompressedZip` replaced its byte-by-byte loop with 1MB chunk writes using a pre-allocated buffer, reducing 550MB write time from >30s to ~40-60s.

### Compression-Ratio Fixes

| Helper | Before | After |
|--------|--------|-------|
| `CreateLargeUncompressedZip` | Sequential bytes → 369:1 | PRNG blocks (100B random / 924B zero per 1KB) → ~10:1 |
| `CreateOversizedZip` | Repeated `X` → 1028:1 | `zip.Store` method → 1:1 |
| `CreateZipWithOversizedSkillMd` | Repeated `A` → 982:1 | PRNG printable ASCII → ~1:1 |

### False-Positive Negative Tests Fixed

`TestPush_EmptyName`, `TestPush_EmptyArtifact`, `TestPush_InvalidName` now set `Org` so they reach the intended validation path. `TestPush_InvalidName` was restructured to test kebab-case violations in frontmatter. A new `TestPush_NoFrontmatter` and `TestPush_MissingOrg` were added for explicit negative coverage.

### Audit Timestamp Type Fix

Tests comparing `CreatedAt`/`UpdatedAt` were corrected to use `*timestamppb.Timestamp.AsTime()` instead of raw `int64`, matching the proto schema.

## Benefits

- **All 60+ skill domain tests pass** — `go test -race ./pkg/domain/skill/...` exits 0
- **No false positives** — negative tests now fail for the correct validation reason
- **Faster CI** — the large-ZIP test dropped from timeout to ~60s
- **Maintainable test data** — `ValidSkillContent` makes frontmatter requirements visible at every call site

## Impact

- **Skill controller tests**: all Push, Get, GetByReference, Delete, and integration tests green
- **Skill storage tests**: all ZIP extraction, validation, and security tests green
- **CI gate**: `make check` skill domain category unblocked

## Pre-Existing Bug Discovered

`setAuditFieldsReflect()` in `backend/libs/go/grpc/request/pipeline/steps/defaults.go` unconditionally sets `CreatedAt: now` even for "updated" events, meaning `created_at` is not preserved across updates. This affects all resource types. The `TestPush_Update_PreservesCreatedAt` test documents this limitation with a code comment.
