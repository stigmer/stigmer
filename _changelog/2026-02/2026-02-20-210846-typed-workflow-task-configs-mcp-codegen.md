# Typed Workflow Task Configs via MCP Codegen

**Date**: February 20, 2026

## Summary

Replaced the opaque `map[string]any` `TaskConfig` field in `WorkflowTaskInput` with 13 strongly-typed,
per-kind config structs generated entirely by the codegen pipeline. The change makes the MCP server's
workflow tool fully self-describing: an AI agent now sees exactly which fields are valid for each task
kind, with enum constraints on the `kind` field, and type-level documentation explaining the discriminated
union pattern. The `ToProto()` bridge validates the input, then serializes the typed config to
`structpb.Struct` via `protojson`, preserving full backend compatibility without touching any proto files.

## Problem Statement

The `WorkflowTaskInput` struct exposed to MCP clients had a single `TaskConfig map[string]any` field.
When the MCP server generated its JSON schema from this struct, the tool's task-config parameter was
described as "any JSON object" — offering no guidance whatsoever on what fields to set.

### Pain Points

- AI agents had no way to know which config fields are valid for `http_call` vs `wait` vs `agent_call`
- No field-level validation — bad configs only failed at the backend, with unhelpful error messages
- `kind` was an unconstrained string — agents had to guess valid enum values
- Hand-authoring typed config structs + `ToProto()` for 13 task types would be hundreds of lines of
  error-prone boilerplate that goes stale when protos change
- Protobuf circular dependencies (`ForTaskConfig`, `ForkTaskConfig`, `TryTaskConfig` all reference
  `WorkflowTask` back) made defining typed configs at the proto layer impractical

## Solution

**Proto stays untouched.** The `kind` + `google.protobuf.Struct` wire format is preserved. The change
lives entirely at the **MCP input type layer**, generated by the existing codegen pipeline:

1. **`proto2schema`** now extracts enum value names from proto descriptors (generic — applies to all domains)
2. **`generator`** now emits `jsonschema:"enum=val1|val2|..."` tags for any enum field (generic)
3. **A new `--expand-struct` CLI flag** drives struct expansion: the `task_config: struct` field is
   replaced with 13 typed pointer fields, one per task kind, named to exactly match the `kind` enum value
4. **A generated `switch` block** in `WorkflowTaskInput.ToProto()` validates that exactly one config
   field is populated and matches `kind`, then marshals it to `structpb.Struct` via `protojson`

## Implementation Details

### proto2schema enhancements (`tools/codegen/proto2schema/main.go`)

- Added `EnumValues []string` to `TypeSpec`
- In `extractScalarTypeSpec`: for `TYPE_ENUM` fields, iterate `enumDesc.GetValues()` and append value
  names, skipping the zero-value sentinel
- Added `TYPE_UINT32` → `TypeSpec{Kind: "uint32"}` mapping (needed by `DurationTaskConfig.Days` etc.)
- Added `google.protobuf.Timestamp` → `TypeSpec{Kind: "timestamp"}` mapping (needed by `WaitTaskConfig.Until`)

### generator enhancements (`tools/codegen/generator/main.go`)

- Added `EnumValues []string` to `TypeSpec` (mirrors proto2schema)
- Added `expandStructConfig` struct: `{structField, discriminatorField, configSchemaDir}`
- Added `--expand-struct=field:discriminator:dir` CLI flag
- `parseExpandStruct` loads all config schemas + their nested types from the specified directory, builds
  a `kindToEnum` mapping (e.g., `"HTTP_CALL"` → `"http_call"`) using word-subset matching

### MCP codegen enhancements (`tools/codegen/generator/mcp.go`)

- `buildJsonSchemaTag`: emit `enum=val1|val2|...` whenever `f.Type.EnumValues` is non-empty — generic
- `ensureMessageInputType`:
  - For `WorkflowTaskInput` (the expanded parent), adds a type-level struct comment explaining the
    discriminated union: *"Set `kind` to the task type and populate exactly one matching config field"*
  - When the struct field matches `expandStruct.structField`, emits N typed pointer fields instead of
    the struct field, one per loaded config schema
  - Each field description reads: *"Required when kind='X'. {original config description}"*
  - Adjusts `kind` field description to reinforce the pattern
- `genConfigToStructSwitch`: generates a `switch input.Kind` block that validates exactly one config
  field is set, then calls `input.SomeConfig.toProto()` + `protoToStruct()` to populate `result.TaskConfig`
- `genProtoToStructHelper`: generates a helper that converts any `proto.Message` to `*structpb.Struct`
  via `protojson.Marshal` (correct for nested Temporal workflow payloads)
- `genFieldAssignment`: added cases for `isTimestamp` (non-oneof) and `isTimestamp + oneofGroup`
  (e.g., `WaitTaskConfig.Until` which is in a `oneof wait_type`)
- New helpers: `typeHasExpandableField`, `expandedConfigField`, `ensureConfigInputType`

### Generated output (`mcp-server/gen/workflow/workflow_gen.go`)

Before — opaque blob:
```go
type WorkflowTaskInput struct {
    Name       string         `json:"name"`
    Kind       string         `json:"kind"`
    TaskConfig map[string]any `json:"task_config"`
    Export     *ExportInput   `json:"export,omitempty"`
    Flow       *FlowControlInput `json:"flow,omitempty"`
}
```

After — fully typed discriminated union:
```go
// WorkflowTaskInput: Set kind to the task type and populate exactly one matching config field
// (e.g. kind='http_call' -> set the http_call field). Exactly one config field must be set.
type WorkflowTaskInput struct {
    Name         string                       `json:"name" jsonschema:"required,..."`
    Kind         string                       `json:"kind" jsonschema:"required,enum=set_vars|http_call|grpc_call|...,description=..."`
    AgentCall    *AgentCallTaskConfigInput    `json:"agent_call,omitempty"    jsonschema:"description=Required when kind='agent_call'. ..."`
    ActivityCall *CallActivityTaskConfigInput `json:"activity_call,omitempty" jsonschema:"description=Required when kind='activity_call'. ..."`
    ForEach      *ForTaskConfigInput          `json:"for_each,omitempty"      jsonschema:"description=Required when kind='for_each'. ..."`
    Fork         *ForkTaskConfigInput         `json:"fork,omitempty"          jsonschema:"description=Required when kind='fork'. ..."`
    GrpcCall     *GrpcCallTaskConfigInput     `json:"grpc_call,omitempty"     jsonschema:"description=Required when kind='grpc_call'. ..."`
    HttpCall     *HttpCallTaskConfigInput     `json:"http_call,omitempty"     jsonschema:"description=Required when kind='http_call'. ..."`
    Listen       *ListenTaskConfigInput       `json:"listen,omitempty"        jsonschema:"description=Required when kind='listen'. ..."`
    RaiseError   *RaiseTaskConfigInput        `json:"raise_error,omitempty"   jsonschema:"description=Required when kind='raise_error'. ..."`
    RunWorkflow  *RunTaskConfigInput          `json:"run_workflow,omitempty"  jsonschema:"description=Required when kind='run_workflow'. ..."`
    SetVars      *SetTaskConfigInput          `json:"set_vars,omitempty"      jsonschema:"description=Required when kind='set_vars'. ..."`
    SwitchCase   *SwitchTaskConfigInput       `json:"switch_case,omitempty"   jsonschema:"description=Required when kind='switch_case'. ..."`
    TryCatch     *TryCatchTaskConfigInput     `json:"try_catch,omitempty"     jsonschema:"description=Required when kind='try_catch'. ..."`
    Wait         *WaitTaskConfigInput         `json:"wait,omitempty"          jsonschema:"description=Required when kind='wait'. ..."`
    Export       *ExportInput                 `json:"export,omitempty"`
    Flow         *FlowControlInput            `json:"flow,omitempty"`
}
```

## Benefits

- **AI agent discoverability**: Agents see exact field shapes and valid `kind` values in the JSON schema
- **Validation at input**: Wrong config fields are caught before any gRPC call is made
- **Zero proto coupling**: No circular dependency issues; proto wire format unchanged
- **Fully generated**: When protos change, running `make codegen-mcp` regenerates everything — no manual struct maintenance
- **Generic improvements**: Enum value extraction and `enum=` tag emission apply to ALL domains (agent, mcpserver, workflow), not just workflow
- **Handles edge cases**: `oneof` fields (WaitTaskConfig duration/until), `uint32` numeric types, `google.protobuf.Timestamp` → ISO 8601 string

## Impact

**MCP server consumers (AI agents):**
- The `apply_workflow` MCP tool now exposes a fully self-documenting schema for workflow tasks
- Agents know exactly which `kind` values exist and which config struct to populate for each

**Codegen pipeline:**
- `proto2schema` now generically extracts enum values — benefit extends to all future domains
- The `--expand-struct` flag is a reusable mechanism for any domain that uses `kind + struct` discriminated unions

**Backend compatibility:**
- Fully preserved — the proto wire format (`WorkflowTask.kind` + `WorkflowTask.task_config: Struct`) is unchanged
