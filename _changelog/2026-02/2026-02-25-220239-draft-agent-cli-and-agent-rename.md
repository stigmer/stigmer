# Add `stigmer draft agent` CLI Command and Rename System Agents

**Date**: February 25, 2026

## Summary

Implemented the `stigmer draft agent` CLI command that invokes the agent-creator system agent to generate Agent YAML files. Renamed all system agents to drop the redundant `-agent` suffix, following Kubernetes naming conventions where the resource kind provides the namespace. Fixed a bug where the `draft skill` command had a hardcoded org that would break in cloud mode.

## Problem Statement

The platform's agent creation workflow relied on manual YAML authoring or external tools (Cursor). The `stigmer draft skill` command existed for AI-assisted skill creation, but no equivalent existed for agent creation. Additionally, the system agent naming convention (`agent-creator-agent`, `skill-creator-agent`) was redundant and confusing since both the Agent kind and the Skill kind named `agent-creator` can coexist cleanly, just as Kubernetes Deployments and Services share names.

### Pain Points

- No CLI command to create agents using the platform's own agent-creator agent
- Agent names had redundant `-agent` suffix (e.g., `agent-creator-agent`)
- Same name used for both a skill and its wrapping agent caused human confusion with the suffix
- `draft skill` handler hardcoded `org = "local"`, which would fail in cloud mode
- The skill-creator agent was hand-written by Cursor instead of being generated by the platform's own agent-creator

## Solution

Three-phase approach: rename agents to drop suffix, fix the org resolution bug, then implement the new `draft agent` command mirroring the existing `draft skill` pattern. Added a dogfooding script that uses `stigmer draft agent` to regenerate the skill-creator agent YAML.

## Implementation Details

### Phase 1: Agent Rename

- `agent-creator-agent.yaml` -> `agent-creator.yaml` (metadata.name: `agent-creator`)
- `skill-creator-agent.yaml` -> `skill-creator.yaml` (metadata.name: `skill-creator`)
- Updated all references across seedpack tests, bootstrap tests, CLI constants, and doc comments

### Phase 1.5: Org Resolution Fix

- Removed the hardcoded `skillCreatorAgentOrg = "local"` constant from `draft_skill.go`
- Changed `draft_skill_handler.go` to use `orgID` returned by `connectToBackend()`, which already resolves correctly for both local and cloud backends via `resolveOrgID()`

### Phase 2: `stigmer draft agent` CLI Command

- `draft_agent.go`: Cobra command with identical flag surface as `draft skill`
- `draft_agent_handler.go`: Handler resolving the `agent-creator` agent using dynamic `orgID`
- `draft.go`: Registered `NewDraftAgentCommand()`, updated help text

### Phase 3: Dogfooding Script

- `03_draft_skill_creator.sh`: Uses `stigmer draft agent` to generate the skill-creator agent YAML
- Attaches proto schemas, the skill-creator skill, and the agent-creator agent YAML as context
- Outputs to a `_review/` directory for human review before promotion
- Added `tools/.gitignore` to exclude generated review artifacts

## Benefits

- **Dogfooding**: The platform can now create its own agents using its own agent-creator
- **Cloud-ready**: Org resolution works correctly for both local and cloud backends
- **Clean naming**: No more redundant `-agent` suffix; follows Kubernetes conventions
- **Symmetric CLI**: `stigmer draft skill` and `stigmer draft agent` provide parallel creation workflows

## Impact

- CLI users gain a new `stigmer draft agent` command
- Bootstrap will re-apply agents under new names on next server start (old names orphaned in existing DBs)
- Existing `draft skill` command now works correctly in cloud mode

## Related Work

- `02_draft_agent_creator.sh` (existing script that drafts the agent-creator skill)
- Seedpack bootstrap system (auto-discovers and applies renamed agents)
