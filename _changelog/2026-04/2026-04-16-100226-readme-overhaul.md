# README Overhaul — Align with Content Strategy

**Date**: April 16, 2026

## Summary

Restructured the root README.md to align with the content strategy positioning, fix all broken links, and present a clear above-the-fold story for GitHub visitors. Reduced from 425 lines to 255 lines by removing content that now lives on the docs site (T01–T03).

## Problem Statement

The README had accumulated structural debt: 10 broken links (pointing to removed architecture, guides, and getting-started pages), a tagline that drifted from the "AI agent platform" category, no badges, verbose LLM configuration details (~50 lines) that are now covered by the docs site, and only the Go SDK mentioned despite React and Ink SDKs being documented.

### Pain Points

- **10 of 18 links broken** — `docs/architecture/*`, `docs/guides/*`, and `docs/getting-started/local-mode.md` were all removed during the content strategy project but the README still pointed to them
- **Tagline drift** — "Build AI agents and workflows with zero infrastructure" didn't match the content strategy's "AI agent platform" category (Positioning Decision 2)
- **Redundant content** — LLM configuration, troubleshooting, managing the server, proto generation, and release instructions all duplicated content now covered by `local.mdx`, `server.mdx`, `config.mdx`, and `apis/README.md`
- **Missing SDKs** — Only Go SDK was mentioned; React SDK and Ink SDK (documented in T03) were absent
- **No trust signals** — No badges for license, community, or activity

## Solution

Three-tier restructure designed for GitHub's fold behavior, following the vocabulary guide's "README / GitHub" register (developer-direct, CLI-first, technical credibility).

## Implementation Details

### Tier 1 — Above the Fold

- **New tagline**: "An open-source AI agent platform." — leads with the positioning category, followed by developer-direct benefits
- **Badge row**: License (Apache 2.0), Discord, GitHub stars
- **Condensed Quick Start**: 4 commands (install, server, apply, run) with other install methods in a collapsible `<details>` block
- **"What is Stigmer?" section**: Three pillars (Skills, MCP Servers, Approval flows) in README register, plus gRPC/protobuf trust signal

### Tier 2 — Core Content

- **Kept**: Agent YAML example, Workflows (trimmed), Skills, MCP Servers, CLI command table (updated with `auth` and `connect`), Local vs Cloud comparison, Architecture diagram
- **Architecture fix**: Replaced "Graphton" (internal-only per vocabulary guide) with "LLM-powered agent execution"
- **Vocabulary fix**: Removed "CNCF Serverless Workflow" reference (reference-docs-only per vocabulary guide)

### Tier 3 — Footer

- **New SDKs table**: Go, React, and Ink SDKs with install commands and reference links
- **New Documentation section**: 6 valid links to live docs site pages (replacing 5 broken relative paths)
- **Trimmed Development**: Kept from-source build; removed proto generation and release instructions (contributor concerns)

### Content Removed

| Section | Rationale |
|---------|-----------|
| LLM Configuration details (~50 lines) | Covered by `local.mdx` + `server.mdx` + `config.mdx` |
| "Changing Your LLM Provider" | Covered by `stigmer server setup` docs |
| "Managing the Server" | Covered by `server.mdx` |
| Troubleshooting | Covered by `server.mdx` (logs, reset, status) |
| Proto Generation | Contributor concern; `apis/README.md` covers this |
| Releases | Contributor concern |
| Broken Documentation links | Replaced with valid docs site URLs |

## Benefits

- **Zero broken links** — every link verified against repo and docs site
- **40% smaller** — 255 lines vs 425 lines, no information loss (content moved to docs site)
- **Vocabulary-aligned** — all terms match the vocabulary guide's README column
- **All three SDKs represented** — Go, React, and Ink in a scannable table
- **Above-the-fold story** — tagline, badges, and Quick Start fit in ~40 lines

## Impact

- **GitHub visitors** see a clear, professional README with working links and the correct positioning
- **Content strategy alignment** — README now uses "AI agent platform" category, developer-direct register, and vocabulary-guide-compliant terminology
- **Docs site as canonical source** — README links to the docs site for detailed content, reducing duplication and drift
