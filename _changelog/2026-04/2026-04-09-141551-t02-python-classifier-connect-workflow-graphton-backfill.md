# T02: Python Classifier + Connect Workflow + Graphton Backfill

**Date**: April 9, 2026

## Summary

Implemented the structured-output LLM tool approval classifier, the `ConnectMcpServerWorkflow` that chains discovery with classification, fixed the broken approval policy chain to support five resolution levels, and added synchronous first-time-use and staleness-based backfill to the Graphton agent execution pipeline. This is the Python/agent-runner counterpart to the Java connect handler (T03) and proto model changes (T01).

## Problem Statement

After T01 replaced the old `discoverCapabilities` / `updateDiscoveredCapabilities` RPCs with a single `connect` RPC and moved tool approvals from spec to status, the Python agent-runner had several gaps:

### Pain Points

- No LLM classifier existed for tool approval policies — the old approach used a full agent session (expensive, slow)
- The `DiscoverMcpServerWorkflow` returned only capabilities, not approval policies
- `approval_policy.py` still referenced the deleted `spec.default_tool_approvals` field (renamed to `pinned_tool_approvals` in T01), silently breaking all MCP server-level approval policies
- No Graphton backfill — the first agent execution for an MCP server had no approval policies until a manual connect was triggered
- The Python gRPC client only had query-side stubs; command-side `connect()` was missing
- The workflow name `"stigmer/mcp-server/discover"` needed coordinated rename across Python, Go, and Java

## Solution

Eight coordinated changes across the agent-runner service (plus one-line renames in Go and Java):

1. **LLM Classifier** (`classify_tool_approvals.py`) — structured-output Pydantic model with economy-tier LLM
2. **Connect Workflow** — chains discover + classify activities
3. **5-Level Approval Chain** — fixed broken reference, added pinned and status layers
4. **gRPC Command Client** — `connect()` method for backfill RPC
5. **Graphton Backfill** — synchronous connect on first use or staleness (>24h)
6. **Worker Registration** — new workflow and activity
7. **Workflow Name Rename** — coordinated across Python, Go, Java
8. **Test Updates** — 311 tests updated, new tests for five-level chain

## Implementation Details

### Structured-Output LLM Classifier

First `with_structured_output` usage in the codebase. Uses `ModelRegistry.get_summarization_model()` for cost-effective classification. System prompt encodes four rules: read-only operations skip approval; create/modify, delete/destructive, and execute/invoke operations require it. Approval messages use `{{args.field}}` placeholders for dynamic rendering at tool invocation time.

### Five-Level Approval Policy Chain

Evaluated highest to lowest priority:
1. `auto_approve_all` — runtime bypass (AgentExecutionSpec)
2. `tool_approval_overrides` — per-agent customization (Agent.McpServerUsage)
3. `pinned_tool_approvals` — manual MCP server owner overrides (McpServerSpec)
4. `status.tool_approvals` — system-generated by LLM classifier (McpServerStatus)
5. `PLATFORM_TOOL_DEFAULTS` — hardcoded sandbox tool policies

Layers 3 and 4 are additive (union) — they can only require approval, never exempt. Exemptions happen at layer 2 via `ToolApprovalOverride.requires_approval = false`.

### Graphton Backfill with Staleness

During agent execution setup, after MCP servers are fetched but before the approval config is built, each server's `last_discovered_at` timestamp is checked. If it's unset (never connected) or older than 24 hours, the connect RPC is called synchronously. The updated server (with fresh tools and approval policies) replaces the stale version in memory. Failures are logged but never block agent execution.

## Benefits

- **Approval policies work again**: The broken `default_tool_approvals` reference was silently dropping all MCP server-level policies since T01. Fixed.
- **Automatic policy generation**: No manual connect needed — the Graphton backfill handles first-time-use automatically.
- **Fresh tools daily**: The 24-hour staleness threshold keeps tools and approval policies current without manual intervention.
- **Cost-effective classification**: Economy-tier LLM with structured output replaces the expensive deep agent session.
- **Clean precedence**: Five explicit levels with documented additive/exempt semantics.
