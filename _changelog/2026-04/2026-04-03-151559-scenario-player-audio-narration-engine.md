# ScenarioPlayer Audio Narration Engine

**Date**: April 3, 2026

## Summary

Added audio narration playback capabilities to the ScenarioPlayer demo engine. The component now supports an optional `narrationManifest` prop that enables synced audio playback with a mute/unmute toggle, while preserving the existing visual-only experience unchanged when no manifest is provided. Audio playback logic is extracted into a dedicated `useNarrationPlayback` custom hook.

## Problem Statement

The demo engine produces interactive playback scenarios that show how Stigmer features work through timed step animations. These demos are effective on the website but cannot be repurposed for social media content (LinkedIn, YouTube) because they lack audio narration. Adding narration requires the ScenarioPlayer to support audio playback synced to step progression.

### Pain Points

- Demo scenarios are visual-only — no way to add spoken narration for video content
- No infrastructure for audio playback in the demo engine
- No mechanism for step authors to specify narration text alongside step definitions
- No mute/unmute control for users who encounter audio on the docs site

## Solution

Extended the ScenarioPlayer with an audio narration layer that cleanly separates authored content from build artifacts:

- **Step authors** write `narration` text alongside step data (consumed by a TTS build script in a future phase)
- **A build script** (future Phase 2) generates audio files and a `NarrationManifest` mapping step indices to audio URLs and durations
- **ScenarioPlayer** accepts the manifest as an optional prop, manages audio playback through a custom hook, and renders a mute/unmute toggle

This design ensures the audio layer is entirely opt-in. Without a manifest, ScenarioPlayer behaves identically to before — no audio elements, no mute button, no timing changes.

## Implementation Details

### New files

- **`engine/narration.ts`** — Type definitions for `NarrationEntry` (src + durationMs) and `NarrationManifest` (array of entries mapped by step index). Used by both the runtime player and the build-time TTS script.

- **`engine/useNarrationPlayback.ts`** — Custom hook encapsulating all audio state and side effects:
  - Manages a single reusable `<audio>` element via ref
  - Plays the correct clip when the active step changes (if unmuted)
  - Pauses audio when the player pauses, stops on step jump
  - Handles browser autoplay policy by defaulting to muted and catching rejected `play()` promises with a `safePlay` helper
  - Completely inert when no manifest is provided

### Modified files

- **`engine/ScenarioPlayer.tsx`** (+33 lines):
  - `ScenarioStep<T>` extended with optional `narration?: string` field
  - `ScenarioPlayerProps<T>` extended with optional `narrationManifest?: NarrationManifest` prop
  - Integrated `useNarrationPlayback` hook
  - Renders hidden `<audio>` element conditionally
  - Added `VolumeX`/`Volume2` mute toggle button after transport controls, only visible when manifest is provided

### Design decision: manifest prop vs. inline narrationSrc

The original plan proposed putting `narrationSrc` (audio URL) directly on `ScenarioStep<T>`. We instead used a separate `narrationManifest` prop because audio URLs are build artifacts (generated by the TTS script), not authored content. This keeps step definitions clean — authors only write `narration` text, and the build pipeline produces the audio files and manifest separately.

## Benefits

- **Zero regression** — All 13 existing demo scenarios continue to work identically
- **Progressive enhancement** — Audio is a layer on top of the visual demo, not a replacement
- **Browser-safe** — Muted by default, autoplay policy handled gracefully
- **Clean separation** — Audio logic extracted to a focused hook, ScenarioPlayer stays readable
- **Future-ready** — The manifest structure supports dynamic step timing (Phase 4) and video export (Phase 5)

## Impact

- **Demo engine**: ScenarioPlayer is now audio-capable, ready for narration content and TTS generation
- **Step authors**: Can add `narration` text to step definitions (consumed by build script in Phase 2)
- **Docs site users**: Will see a mute/unmute toggle once scenarios have narration manifests
- **Content pipeline**: Foundation laid for video export of narrated demos for social media

## Related Work

- Phase 2 (TTS build script) will generate audio files and manifests consumed by this engine
- Phase 3 (narration content) will add narration text to all 10 playback scenarios
- Phase 4 (dynamic timing) will sync step durations with narration clip lengths
- Phase 5 (video export) will use Playwright + FFmpeg to produce MP4 files from narrated demos
