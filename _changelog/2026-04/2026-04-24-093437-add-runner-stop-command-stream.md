# Add Runner Stop via Command Stream

**Date**: April 24, 2026

## Summary

Added server-initiated graceful runner stop as a dedicated `stop` RPC on `RunnerCommandController`. The command routes through the existing bidirectional command stream to connected runners, with a direct STOPPED transition fallback for offline runners. Implementations span Proto, Go (OSS server + CLI daemon), Java (Cloud), and all SDKs via codegen.

## Problem Statement

Runners had no server-initiated shutdown mechanism. To stop a runner, a user had to SSH into the machine and kill the process manually. The web console and SDK had no way to trigger a graceful stop, which is essential for the Settings > Runners CRUD page and the upcoming `useStopRunner()` React hook.

### Pain Points

- No API surface for stopping runners remotely
- No graceful shutdown path via the existing command stream
- The existing `sendCommand` RPC uses `can_view` permission — insufficient for a destructive lifecycle operation
- Offline runners had no way to be marked as stopped without manual intervention

## Solution

A dedicated `rpc stop(RunnerStopInput) returns (Runner)` on `RunnerCommandController` with `can_edit` authorization, separate from the general-purpose `sendCommand`. The stop command is carried inside the bidi stream protocol (`RunnerCommandRequest.command.stop`) and reuses the existing `StreamRegistry.SendCommand` correlation infrastructure. Idempotent: stopping an already-stopped or failed runner is a no-op.

## Implementation Details

### Proto Changes (`apis/ai/stigmer/agentic/runner/v1/`)

- **`io.proto`**: Added `StopRunnerRequest` (reason), `StopRunnerResponse` (ack), `RunnerStopInput` (runner_id + reason). Extended `RunnerCommandRequest.command` oneof (field 3) and `RunnerCommandResponse.result` oneof (field 4).
- **`command.proto`**: Added `stop` RPC with `can_edit` permission on the runner resource.
- `RunnerSendCommandInput.command` left unchanged — stop is a lifecycle operation, not an operational command.

### Go Server (OSS) — `stop.go`

- Validates input, loads runner, returns as-is for STOPPED/FAILED (idempotent).
- Connected path: builds `RunnerCommandRequest` with `StopRunnerRequest`, sends via `StreamRegistry.SendCommand` (10s timeout), returns runner on ack. STOPPED transition happens asynchronously when the runner closes its stream.
- Offline path: directly updates runner to STOPPED with `stopped_at` timestamp.

### Go CLI Daemon

- `runner_stream_commands.go`: Added `commandResult` struct pairing response with `stopRequested` flag. Stop case returns `StopRunnerResponse` ack with `stopRequested = true`.
- `runner_stream.go`: `recvLoop` returns `ErrServerRequestedStop` after sending ack. `streamLoop` triggers graceful shutdown (STOPPED heartbeat + CloseSend). `Run` exits without reconnecting.

### Java Server (Cloud) — `RunnerStopHandler.java`

- `OperationHandlerV2<RunnerStopInput, Runner>` with FGA `can_edit` authorization.
- Three routing paths: local stream registry, Redis cross-pod coordinator, direct STOPPED fallback.

### SDKs

- TypeScript: `RunnerClient.stop(input)` auto-generated by codegen.
- Go: `RunnerClient.Stop(ctx, input)` auto-generated.
- Java, Python, Dart: stubs regenerated with stop support.

### Tests

- Go server: 6 cases (missing-id, not-found, already-stopped, failed, disconnected, connected).
- Go CLI daemon: 5 cases (dispatch ack, no-signal for other commands, recvLoop flow, full graceful shutdown).
- Java: 7 cases (not-found, already-stopped, failed, connected, offline, FGA-denied, empty-id).

## Benefits

- Users and admins can stop runners remotely from the web console or SDK
- Clean API: dedicated `stop` RPC with proper `can_edit` authorization (vs `can_view` for `sendCommand`)
- Graceful shutdown: runner acknowledges, sends STOPPED heartbeat, closes stream, exits
- Idempotent: safe to call multiple times without errors
- Offline handling: disconnected runners transition directly to STOPPED
- Foundation for T07's `useStopRunner()` React hook and T08's Settings > Runners CRUD

## Impact

- **SDK users**: Can call `stigmer.runner.stop({ runnerId, reason })` to stop runners programmatically
- **Web console**: Foundation for "Stop" button on Settings > Runners page (T08)
- **React SDK**: Foundation for `useStopRunner()` hook (T07)
- **CLI daemon**: Server-initiated stop follows the same graceful path as local SIGTERM
- **Platform**: Runners are now fully lifecycle-managed (create, connect, command, stop, delete)
