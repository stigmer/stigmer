# Demo Engine: Dynamic Step Timing and Narration Manifest Wiring

**Date**: April 3, 2026

## Summary

Added dynamic step timing to the ScenarioPlayer engine and wired narration manifests into all 10 playback scenarios. When a viewer unmutes a demo, steps now hold long enough for the narration audio to finish before advancing. This completes the audio narration feature end-to-end: narration text authored on steps, audio generated by Edge TTS, manifests loaded at runtime, audio played in sync with step progression, and timing extended to match clip duration.

## Problem Statement

The ScenarioPlayer had audio infrastructure (mute toggle, narration playback hook, audio element) but two critical pieces were missing:

### Pain Points

- No scenario loaded or passed a narration manifest, so the audio infrastructure was completely dormant — the mute toggle never appeared, no audio played
- Step timing was fixed at `delayMs` regardless of narration duration, so unmuted playback would cut off audio mid-sentence when advancing to the next step

## Solution

Three focused changes that complete the narration pipeline:

1. A `useNarrationManifest` hook that fetches the manifest JSON at runtime
2. A timing adjustment in ScenarioPlayer's auto-advance effect
3. Wiring the hook into all 10 playback scenarios

## Implementation Details

### Runtime manifest loading (`useNarrationManifest`)

A hook that fetches `/demos/{scenarioId}/manifest.json` on mount and returns `NarrationManifest | undefined`. Handles 404 silently so demos work whether or not `make generate-narration` has been run. The mute toggle only renders when the manifest is truthy, eliminating race conditions between manifest loading and user interaction.

### Dynamic step timing

The ScenarioPlayer auto-advance effect now computes:

```typescript
const delay = Math.max(baseDelay, narrationDuration);
```

- **Muted**: `narrationDuration` is 0, so timing is unchanged
- **Unmuted**: step holds until narration finishes; if the visual needs more time, visual timing wins
- **Mid-step mute toggle**: `muted` in the dependency array causes timer recalculation, syncing with the narration hook's restart/stop behavior

### Scenario wiring

All 10 playback scenario components now call `useNarrationManifest` with their directory name and pass the result to ScenarioPlayer. The 3 static detail views were not modified.

## Benefits

- Narration audio plays to completion before step advances — no clipped sentences
- Muted experience is unchanged — zero impact on existing visual-only demos
- Resilient to missing audio — demos work with or without `make generate-narration`
- Single hook call per scenario — minimal wiring, no boilerplate

## Impact

- **Demo engine**: ScenarioPlayer now has complete audio support (playback, timing, manifest loading)
- **All 10 playback scenarios**: Each gains a mute/unmute toggle and narrated audio playback
- **Build pipeline**: `make generate-narration` produces audio that is immediately consumable by the website
- **Phase 5 readiness**: The video export pipeline can now record demos with synced audio
