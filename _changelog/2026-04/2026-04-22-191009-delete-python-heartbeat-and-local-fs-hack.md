# Delete Python Heartbeat and Local Filesystem Hack

**Date**: April 22, 2026

## Summary

Removed the Python heartbeat emitter and the ad-hoc HTTP filesystem listing endpoint from the codebase. These were interim mechanisms now fully replaced by the bidirectional gRPC command stream (`RunnerCommandController.connect`) introduced in T02. This is a pure cleanup task — 1,400 lines deleted, zero new functionality.

## Problem Statement

With the bidi stream proto and codegen complete (T02), the old heartbeat path and local FS hack became dead code:

### Pain Points

- **Python heartbeat (`HeartbeatEmitter`)**: Called the now-deleted unary `heartbeat` RPC. The Go CLI daemon will own heartbeat responsibility over the bidi stream (T05).
- **Local FS HTTP endpoint (`GET /api/fs/list`)**: A same-origin hack on the CLI's embedded web console that exposed a directory listing API. This will be replaced by the proper `ListDirectory` command over the bidi stream, which works identically for local and remote runners.
- **`FolderBrowser` / `useFolderListing` React components**: SDK components coupled to the HTTP hack. Removing the endpoint without removing these components would leave broken UI paths.
- **`enableFolderBrowser` prop threading**: Wired through `SessionComposer` → `WorkspaceEditor` → `FolderBrowser`, plus two web app pages — all dead after the component removal.
- **`next.config.ts` dev proxy**: Rewrote `/api/fs/*` to `localhost:8234` for development; only existed to support the FS hack.

## Solution

Systematic deletion across five areas, each independently scoped:

1. **Python heartbeat** — delete `heartbeat.py`, `runner_client.py`; clean `worker.py` and `config.py`; update docstrings in `idle_watchdog.py` and `execution_tracker.py`.
2. **Go FS handler** — delete `api_fs.go`; remove route registration from `handler.go`; update `BUILD.bazel`.
3. **React SDK** — delete `useFolderListing.ts` and `FolderBrowser.tsx`; clean `WorkspaceEditor.tsx` and `SessionComposer.tsx`; update barrel exports.
4. **Web app** — remove `enableFolderBrowser` prop from `SessionLauncher.tsx` and `SessionPage.tsx`; remove rewrites from `next.config.ts`.
5. **Docs** — regenerated via `make gen-react-sdk-docs` pipeline (TypeDoc JSON → MDX).

### Key Decisions

- **`runner_id` removed from Python config**: Verified it was used exclusively for heartbeat enablement — not for task queue naming (`STIGMER_TASK_QUEUE` is independent) or execution registration.
- **`SessionComposer.tsx` updated**: Not in the original T01 plan but discovered during research — it threads `enableFolderBrowser` through to `WorkspaceEditor`.
- **Docs regenerated, not manually edited**: `workspace.mdx` and `composer.mdx` are auto-generated by `make gen-react-sdk-docs`. Ran the pipeline rather than editing the generated files.

## Benefits

- **-1,404 lines of dead code** removed from the codebase
- **Single path for filesystem browsing**: the `ListDirectory` command over the bidi stream (when T04-T07 are complete)
- **Cleaner Python worker**: no more runner-specific gRPC client or async heartbeat loop
- **Cleaner SDK public API**: removed 6 exports (`useFolderListing`, `FolderBrowser`, `FolderEntry`, `FolderListing`, `UseFolderListingReturn`, `FolderBrowserProps`) that were coupled to the HTTP hack

## Impact

- **Breaking change to `@stigmer/react`**: `useFolderListing`, `FolderBrowser`, and related types are removed from the public API. `enableFolderBrowser` prop removed from `WorkspaceEditorProps` and `SessionComposerProps`.
- **Python agent-runner**: no longer sends heartbeats. The Go CLI daemon (T05) will take over this responsibility.
- **Local folder browser temporarily unavailable**: the visual folder browser is gone; local path input reverts to a text field until T04-T07 deliver the gRPC-backed replacement.
