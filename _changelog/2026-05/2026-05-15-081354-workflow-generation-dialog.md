# Workflow Generation Dialog — SDK Components + Console Integration

**Date**: May 15, 2026

## Summary

Built the user-facing "Generate Workflow from Prompt" experience as T16 Batch 2. Users can now describe a workflow in natural language and get a complete, validated workflow YAML generated by an LLM — all through a two-phase dialog accessible from the Workflows list page in both web and desktop consoles.

## Problem Statement

After Batch 1 delivered the backend generation pipeline (`generateWorkflowFromPrompt` RPC with server-side prompt construction, validation-in-the-loop, and org context injection), there was no way for users to invoke it from the UI. The only path to generate a workflow was through the SDK TypeScript client programmatically.

### Pain Points

- Zero UI surface for the generation capability shipped in Batch 1
- Users had to know the SDK API to generate workflows from prompts
- No preview or review step before workflow creation
- Empty state on the Workflows list page only mentioned CLI or API

## Solution

Followed the SDK-first, headless-first architecture (DD-001, DD-003) to deliver the generation experience as reusable SDK components consumed by both console applications.

## Implementation Details

### Behavior Hook — `useGenerateWorkflowFlow`

New behavior hook in `sdk/react/src/workflow/` following the `useRunWorkflowFlow` pattern:
- Two-phase state machine: generation (`generateFromPrompt()`) then creation (`parseWorkflowYaml()` + `apply()`)
- `useRef`-stabilized callbacks for consumer-provided `onSuccess`/`onError`
- Client-side prompt validation (min 10 characters, matching proto constraint)
- Advanced options: model override and task kind hints (comma-separated string)
- Full error handling via `getUserMessage()` from `@stigmer/sdk`

### Styled Component — `WorkflowGenerateDialog`

Two-phase dialog in a single native `<dialog>` element:
- **Phase 1 (Input)**: Prompt textarea with example placeholder, collapsible "Advanced options" for model and task kind hints (progressive disclosure — Hick's Law), Cancel + Generate buttons
- **Phase 2 (Result)**: Model badge, explanation text, read-only YAML preview in `<pre>`, warnings banner, Close / Try Again / Create Workflow buttons
- Loading state with centered spinner and "Generating workflow... This may take 10-30 seconds" messaging
- `max-w-2xl` (wider than `WorkflowRunDialog`'s `max-w-lg`) to accommodate YAML preview
- Fully themed via `--stgm-*` design tokens, zero Console dependencies

### Console Integration (DD-016 Parity)

Both web and desktop `WorkflowListPage` files updated identically:
- "Generate" button with Sparkles icon in the page header
- `WorkflowGenerateDialog` wired with navigation on success, toast on error
- Empty state description updated to mention the Generate button
- `listVersion` incremented after creation to refresh the workflow list

## Benefits

- Users can generate workflows from natural language without leaving the console
- Two-phase review ensures users inspect the generated YAML before creation
- Progressive disclosure keeps the dialog simple for most users while exposing advanced options for power users
- SDK-first delivery means the hook and dialog are reusable by platform builders embedding Stigmer

## Impact

- **End users**: First in-app workflow creation path (previously CLI/API only)
- **Platform builders**: `useGenerateWorkflowFlow` and `WorkflowGenerateDialog` available as importable SDK components
- **DD-016 parity**: Web and desktop consoles have identical feature surface
