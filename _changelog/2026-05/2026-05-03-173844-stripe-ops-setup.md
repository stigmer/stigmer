# Stripe Operations Setup — Account, Secrets, and Deployment Wiring

**Date**: May 3, 2026

## Summary

Completed the manual operations setup required to make the Stripe billing integration production-ready. Created the Stripe account, configured tax settings, registered the webhook endpoint, and wired credentials into the deployment pipeline via Planton secrets and kustomize env var injection.

## Problem Statement

The billing system code (Phases 0-3.5) was fully implemented — Stripe Checkout, webhook handler, reconciliation cron — but the service couldn't actually process payments because no Stripe credentials were configured in the deployment environment.

### Pain Points

- Stripe API key and webhook signing secret had no path from Stripe Dashboard to the running pod
- No secrets group existed in Planton for Stripe credentials
- The kustomize base service.yaml had no `STIGMER_STRIPE_SECRET_KEY` or `STIGMER_STRIPE_WEBHOOK_SECRET` entries
- Webhook endpoint wasn't registered in Stripe Dashboard, so events would never arrive

## Solution

End-to-end ops wiring: Stripe Dashboard configuration, Planton secrets group creation, and kustomize deployment manifest updates.

## Implementation Details

### Stripe Dashboard Setup
- Created "Stigmer, Inc." account in Live mode
- Configured Stripe Tax: head office US (Indiana), preset product category "Digital products > Business and web services", automatic tax determination enabled
- Registered webhook endpoint with 4 event types: `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`

### Planton Secrets Group
- Created `stripe` secrets group (`secgrp_01kqpvrhxr1y0dw04pzwbr3n2z`) in Planton with two entries:
  - `prod.secret-key` — Stripe live API key (`sk_live_...`)
  - `prod.webhook-secret` — Webhook signing secret (`whsec_...`)
- Local YAML: `_ops/planton/service-hub/secrets-group/stripe.yaml`

### Kustomize Deployment Wiring
- Added to `backend/services/stigmer-service/_kustomize/base/service.yaml` under `spec.container.app.env.secrets`:
  - `STIGMER_STRIPE_SECRET_KEY` → `$secrets-group/stripe/prod.secret-key`
  - `STIGMER_STRIPE_WEBHOOK_SECRET` → `$secrets-group/stripe/prod.webhook-secret`
- These are read by `StripeConfig` via `application.yaml` properties `stigmer.stripe.secret-key` and `stigmer.stripe.webhook-secret`

### Architecture Decision
- Single Stripe account for all Stigmer products (shared API keys, Customers, tax config)
- Products differentiated at Stripe Product/Price level, not account level
- One webhook endpoint per service/environment, each with its own `whsec_` signing secret

## Benefits

- Next deployment of stigmer-service will have Stripe credentials injected as Kubernetes secrets
- `StripeClientProvider` will create the `StripeClient` bean (previously skipped when `secret-key` was empty)
- Stripe Checkout sessions can be created, webhooks will be received and verified
- Reconciliation cron can query Stripe API for missed webhooks

## Impact

- **stigmer-cloud**: 2 files changed — secrets group YAML + kustomize base service.yaml
- **Stripe Dashboard**: Account configured, webhook endpoint registered, tax enabled
- **Planton**: Secrets group created and available for deployment resolution
- **Production**: Stripe billing will be active on next deploy
