# Per-Task Codegen Reference Documentation

**Date**: May 17, 2026

## Summary

Added a new `--target=task-docs` codegen target that auto-generates one MDX reference page per workflow task kind (20 pages total), ensuring field-level task documentation stays in sync with proto definitions. This complements the handwritten narrative docs with exhaustive, auto-generated reference that is zero-maintenance.

## Problem Statement

The handwritten `docs/guides/workflow-tasks.mdx` covers "when to use" and key fields per task but does not provide exhaustive field-level reference. As the platform grows to 20 task kinds with nested types, enums, and validation rules, maintaining accurate field reference by hand is unsustainable and error-prone.

### Pain Points

- Field-level documentation drifts from proto definitions over time
- New fields added in protos don't automatically appear in docs
- Nested types (e.g., AgentExecutionConfig, EvalCriterion) are undocumented
- Enum values and validation constraints are scattered across proto files
- Output shapes are described inconsistently across tasks

## Solution

Extended the existing `tools/codegen/generator` to add a `task-docs` target that reads the same JSON schemas and sidecar YAML metadata used by the task registry, then generates per-task MDX reference pages with `<TypeTable>` field tables, nested types, enums, output shapes, and YAML examples.

## Implementation Details

- **New file**: `tools/codegen/generator/task_docs.go` (~370 lines of Go) implementing `runTaskDocsGeneration()`. Follows the established `sdk_docs.go` pattern: load schemas, merge with sidecar metadata, emit MDX with Fumadocs components.
- **Reused infrastructure**: `loadTaskSchemas()`, `loadSharedTypes()`, `loadSidecarMetadata()` from `task_registry.go`; `docEscapeMDX()`, `docStripInternal()`, `docFirstSentence()` from `sdk_docs.go`.
- **Wired dispatch**: Added `case "task-docs"` in `main.go` comprehensive mode switch.
- **Makefile targets**: `gen-task-docs` and `gen-task-docs-check` (diff-based CI gate), wired into `gen-sdk-docs` and `gen-sdk-docs-check`.
- **Sidecar metadata**: Leveraged existing YAML files at `apis/ai/stigmer/agentic/workflow/v1/tasks/meta/`; updated `documentation_url` paths to match generated output location.
- **Cross-linking**: Added `[Full reference ->]` links from each task section in the handwritten overview page to the corresponding generated reference page.

## Benefits

- **Zero maintenance**: 20 reference pages generated from proto schemas -- adding a field to a proto automatically updates the docs
- **CI-enforced freshness**: `make gen-task-docs-check` fails if generated docs are stale
- **Consistent format**: Every task page has the same structure: overview, kind string, YAML examples, TypeTable fields, nested types, enums, output shape, see-also links
- **Cross-linked**: Handwritten narrative docs link to generated reference; generated pages link back to guides

## Impact

- **Documentation users**: Complete field-level reference for all 20 task kinds, previously unavailable
- **Platform developers**: Adding new task fields or kinds automatically produces documentation
- **CI pipeline**: New check target catches documentation drift before merge
