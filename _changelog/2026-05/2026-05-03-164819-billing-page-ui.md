# Billing Page UI — Phase 3.4

**Date**: May 3, 2026

## Summary

Implemented the billing page UI across all three SDK layers, replacing the "Coming Soon" placeholder with a fully functional credit management interface. The implementation follows the SDK-first architecture: `BillingClient` in `@stigmer/sdk`, data/behavior hooks and styled components in `@stigmer/react`, and a thin Console page in `client-apps/web`.

## Problem Statement

The billing page at `/settings/billing` was a static "Coming Soon" placeholder. With Phases 3.1–3.3 complete (Stripe Customer management, Checkout integration, webhook handling), the backend is fully wired for credit purchases. Users had no way to view their credit balance, purchase credit packs, or review transaction history.

### Pain Points

- No visibility into credit balance or breakdown (available, promotional, purchased, reserved)
- No self-serve credit purchase flow despite backend Stripe Checkout integration being live
- No transaction history or ledger visibility for billing transparency
- No low-balance warnings despite the server-side threshold configuration

## Solution

Built the billing UI as an SDK-first feature following DD-001 (SDK-first development), DD-003 (headless-first), and DD-004 (zero framework deps in SDK). Every component is embeddable by platform builders — the Console is just one consumer.

## Implementation Details

### Layer 1 — `@stigmer/sdk`: BillingClient

Hand-written client (not code-generated, same pattern as `GitHubClient` and `SearchClient`) wrapping 5 user-facing RPCs:

- `getOrCreateBillingAccount(orgId)` — idempotent account provisioning
- `getBillingAccount(orgId)` — read-only account fetch
- `getCreditBalance(orgId)` — balance-only query
- `getCreditLedger({ orgId, page?, typeFilter? })` — paginated ledger with filters
- `createCreditCheckoutSession({ orgId, packId, successUrl, cancelUrl })` — Stripe Checkout redirect

Internal RPCs (authorizeExecution, reportLlmCallUsage, finalizeExecution) are excluded — they are called only by the Temporal workflow and agent runner.

### Layer 2 — `@stigmer/react`: Hooks + Components

**Data hooks** (following `useFetch` pattern):
- `useBillingAccount(orgId)` — primary hook returning full `BillingAccount` with embedded `CreditBalance`
- `useCreditLedger(orgId, options?)` — paginated ledger entries with type filtering

**Behavior hook** (following mutation pattern):
- `useCreateCheckoutSession()` — creates Stripe Checkout Session, redirects to checkout URL on success

**Styled components** (Tailwind + `--stgm-*` tokens, zero Console deps):
- `CreditBalanceCard` — prominent balance display with semantic colors (green/amber/red) and promotional/purchased/reserved breakdown
- `CreditPackGrid` — 3 credit pack cards (Starter $10, Growth $50, Team $200) with purchase buttons, disabled states
- `CreditLedgerTable` — paginated transaction history with type badges, signed amounts, running balance
- `LowBalanceBanner` — conditional warning when balance is below threshold
- `BillingSection` — top-level assembly with deployment mode gate, checkout success banner, org selection state

**Utilities**:
- `format.ts` — `formatCreditBalance`, `formatLedgerAmount`, `ledgerEntryLabel`, `isCredit`, `isHold`, `formatLedgerDate`
- `credit-packs.ts` — static pack catalog (`CREDIT_PACKS`), `formatPackPrice`, `formatCreditCount`

### Layer 3 — `client-apps/web`: Console Page

The billing page is now a thin "use client" wrapper (~25 lines) that:
- Reads `?checkout=success` from URL search params
- Renders `<BillingSection>` from `@stigmer/react`
- Handles dismiss by replacing the URL (removes query param via `history.replaceState`)

### Settings Navigation

Updated the "Billing & Usage" nav group description from "Subscription management and usage metrics" to "Credit management and usage metrics" — accurate to the credit-based model.

## Benefits

- **Full billing visibility**: Users can see their credit balance, breakdown, and transaction history
- **Self-serve purchases**: 3 credit packs purchasable via Stripe Checkout redirect
- **Real-time balance health**: Semantic colors and low-balance warnings guide user action
- **Platform builder ready**: Every component is independently importable and embeddable — hooks for full control, styled components for drop-in use
- **Type-safe end-to-end**: Proto types flow from `@stigmer/protos` through `BillingClient` to React hooks — no hand-written type duplication

## Impact

- **Users**: Can now manage billing, purchase credits, and track spend from the web console
- **Platform builders**: Can embed `<CreditBalanceCard>`, `<CreditPackGrid>`, or individual hooks into their own products
- **SDK surface**: 3 new hooks, 5 new styled components, 8 new format/catalog utilities, and 1 new API client added to the public API
