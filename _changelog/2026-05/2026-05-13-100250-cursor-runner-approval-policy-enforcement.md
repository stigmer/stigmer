# Cursor Runner: Connect Approval Policies to HITL Enforcement

**Date**: May 13, 2026

## Summary

Connected the cursor-runner's HITL (Human-in-the-Loop) tool approval system to the platform's MCP server approval policies. Previously, MCP tools executed without any approval gate despite policies existing in the database. Now the cursor-runner loads policies from each MCP server, evaluates them via the four-level merge chain, and enforces them through Cursor's preToolUse hook mechanism — matching the behavior already working in the LangGraph runner.

## Problem Statement

A beta user reported that tool approvals were not being triggered when using the Cursor harness with MCP servers. MongoDB investigation confirmed that the "planton" MCP server had 90+ tool approval policies populated, but none were being enforced.

### Pain Points

- MCP tool calls reported `name: "mcp"` (generic wrapper) instead of the actual tool name (e.g., `search_services`), making them invisible to the approval system
- The ToolCall proto lacked `requiresApproval`, `mcpServerSlug`, and `approvalMessage` fields, so the server-side `PendingApprovalComputer` never found pending approvals
- The hook script used a hardcoded allow-list of Cursor built-in tools instead of evaluating MCP server policies
- The approval state file used wildcard `{ name: "*" }` on reinvocation instead of matching specific approved tool call IDs
- The LangGraph runner implemented all of this correctly, creating a behavioral gap between the two harnesses

## Solution

Implemented the full approval policy pipeline in the cursor-runner, mirroring the proven patterns from the Python agent-runner while adapting to Cursor SDK's event model:

1. **Policy loading** — `mcp-resolver.ts` now fetches `status.toolApprovals` and `spec.pinnedToolApprovals` from each McpServer resource in the same request that loads connection config
2. **Policy merging** — `approval-policy.ts` implements the four-level chain: status defaults -> pinned overrides -> agent overrides -> auto_approve_all
3. **Hook enforcement** — `hook-script.ts` generates a JSON-driven policy lookup script instead of a hardcoded case statement
4. **MCP tool extraction** — `message-translator.ts` parses `providerIdentifier` and `toolName` from Cursor SDK's `event.args` when `event.name === "mcp"`
5. **Proto enrichment** — `buildToolCallProto()` sets `name` (actual), `mcpServerSlug`, `requiresApproval`, and `approvalMessage` with `{{args.field}}` placeholder resolution
6. **Connect backfill** — `connect-backfill.ts` triggers the connect RPC for MCP servers with empty discovered capabilities, matching the Graphton runner's backfill pattern

### Policy Merge Chain

The four-level priority system (documented in the `ToolCall` proto) is now enforced:

1. `McpServerStatus.tool_approvals` — system-generated by LLM classifier during connect
2. `McpServerSpec.pinned_tool_approvals` — manual overrides by server owner
3. `McpServerUsage.tool_approval_overrides` — per-agent with explicit `requires_approval` boolean
4. `AgentExecutionSpec.auto_approve_all` — runtime bypass (highest priority)

### MCP Tool Name Extraction

Cursor SDK reports MCP tool calls with `event.name === "mcp"` and packs the real identity into `event.args`:

```json
{
  "providerIdentifier": "planton",
  "toolName": "search_services",
  "args": { "input": { "search_text": "web" } }
}
```

The translator now extracts these to set `ToolCall.name = "search_services"` and `ToolCall.mcpServerSlug = "planton"` instead of the previous `name: "mcp"`.

## Benefits

- MCP tool approval policies are now enforced in the Cursor harness, matching LangGraph behavior
- The server-side `PendingApprovalComputer` can now detect pending approvals for Cursor executions
- The `SubmitApproval` RPC and the full HITL workflow (deny -> wait -> approve -> reinvoke) now works end-to-end
- Tool calls in the UI show actual MCP tool names and server context instead of generic "mcp"
- Approval messages with `{{args.field}}` placeholders provide contextual human-readable prompts

## Impact

- **Beta users**: Cursor harness sessions with MCP servers now properly gate destructive tools behind approval
- **Platform parity**: Cursor harness reaches feature parity with LangGraph for HITL tool approvals
- **Server-side**: No changes needed — all existing proto fields and server logic already supported this; only the cursor-runner was missing the implementation
