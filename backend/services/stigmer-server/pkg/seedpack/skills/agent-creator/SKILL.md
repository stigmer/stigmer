# Agent Creator

Produce valid, production-ready `agentic.stigmer.ai/v1` Agent YAML files. Follow every step
below in order. Never skip the resource-discovery phase.

---

## Mandatory Workflow

### Step 1 — Clarify intent

Ask for any missing information **before** writing YAML:

- What is the agent's purpose (1–2 sentences)?
- What external systems should it access (GitHub, Slack, databases, APIs…)?
- Does it need specialized knowledge (skills)?
- Does it need to delegate tasks to sub-agents?
- Are there environment variables or secrets required?
- Should any tools require human approval before execution?

Ask the **most important missing questions first**; do not overwhelm the user.  
If intent is ambiguous — stop and ask. Never assume.

---

### Step 2 — Query the platform for real resources

**Never invent MCP server slugs or skill slugs.** Always discover them from the platform
before writing references into the YAML.

#### 2a — Find MCP servers

```
# Broad discovery
search(query: "<domain> e.g. github, slack, postgres")

# Targeted lookup once you have a slug candidate
get_mcp_server(org: "local", slug: "<candidate-slug>")
```

- Capture the **exact slug**, available tool names, and whether the tools need approval.
- If no relevant MCP server exists → **tell the user** and ask how to proceed (create one
  first, or continue without it). Do not fabricate a reference.

#### 2b — Find skills

```
search(query: "<domain> e.g. code-review, api-design")

get_skill(org: "local", slug: "<candidate-slug>")
```

- Capture the **exact slug** and `version` tag if the user wants a pinned version.
- If no relevant skill exists → **tell the user** and ask how to proceed.

---

### Step 3 — Draft the YAML

Use only resources confirmed in Step 2. Follow the canonical structure:

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Agent
metadata:
  name: <human-readable name>          # required
  # slug: <auto-generated if omitted>   # optional: lowercase-alphanumeric-hyphens
  # labels:                             # optional
  #   team: engineering
  # tags:                               # optional
  #   - code-review
spec:
  description: "<1-2 sentence summary>" # required
  # icon_url: "https://…"               # optional
  instructions: |                       # required; ≥10 chars
    You are …
  mcp_server_usages: []   # omit section if none
  skill_refs: []          # omit section if none
  sub_agents: []          # omit section if none
  env_spec: {}            # omit section if none
```

See `references/field-reference.md` for every field's rules and types.  
See `references/examples.md` for complete annotated YAML examples.

---

### Step 4 — Validate before presenting

Run every check in `references/validation-checklist.md` mentally before showing the YAML.
Fix all failures. Present a clean, production-ready YAML.

---

### Step 5 — Present output and next steps

1. Show the final YAML in a fenced code block.
2. Call out any resources that **do not exist yet** on the platform and explain what the
   user must create first.
3. Give the apply command:
   ```bash
   stigmer agent apply agent.yaml
   # or dry-run first:
   stigmer agent apply agent.yaml --dry-run
   ```
4. Offer to iterate — ask if adjustments are needed.

---

## Key Rules (never violate)

| Rule | Detail |
|------|--------|
| **Query first** | Use `search` / `get_mcp_server` / `get_skill` before every reference. |
| **Ask, don't assume** | Unclear intent or missing resource → pause and ask the user. |
| **Exact slugs only** | Slugs are `[a-z0-9][a-z0-9-]*`, max 63 chars, starts with a letter. |
| **kind values are lowercase** | `kind: skill`, `kind: mcp_server` — never capitalized. |
| **instructions ≥ 10 chars** | Both parent and sub-agent instructions must satisfy this. |
| **Sub-agent tools ⊆ parent tools** | A sub-agent can only restrict, never expand, the parent's tool list. |
| **Sub-agent mcp_server matches parent slug** | `mcp_access[].mcp_server` must equal a slug in `mcp_server_usages`. |
| **Unique MCP slugs per agent** | Each slug appears at most once in `mcp_server_usages`. |
| **org is always required on refs** | Default org for local resources: `local`. |
| **Never set `status`** | It is system-managed; omit it entirely from user-authored YAML. |
