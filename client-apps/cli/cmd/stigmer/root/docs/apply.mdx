Apply resource definitions to the Stigmer backend.

`stigmer apply` is the primary way to deploy agents, workflows, MCP servers,
and skills. It operates in three modes depending on how you invoke it:

- **File mode** (`-f`): Apply individual YAML resource files or directories.
- **Declarative mode**: Detect a `stigmer.yaml` project file, scan for resources, and apply them with project-level tracking.
- **SDK mode**: When `stigmer.yaml` has an `entry_point`, run the SDK to synthesize resources programmatically.

Without `-f`, the CLI looks for `stigmer.yaml` in the current directory (or
the path specified by `--config`). If `entry_point` is set, SDK mode runs.
Otherwise, declarative mode scans the directory for YAML resource files.

### Common patterns

```bash
# Apply a single resource file
stigmer apply -f agent.yaml

# Apply all resources in a directory
stigmer apply -f ./manifests/

# Deploy a project (scans cwd for stigmer.yaml)
stigmer apply

# Preview changes without applying
stigmer apply --dry-run
```

### File mode

Apply individual YAML files or entire directories of resources. Supports
agents, workflows, MCP servers, and multi-document YAML (separated by `---`).

```bash
# Apply a single file
stigmer apply -f agent.yaml

# Apply a workflow with dry-run
stigmer apply -f workflow.yaml --dry-run

# Apply all YAML files in a directory
stigmer apply -f ./manifests/
```

### Declarative mode

When no `-f` flag is provided, the CLI looks for a `stigmer.yaml` project
configuration file. It scans the directory for YAML resource files and applies
them with project-level tracking.

```bash
# Deploy from the current directory
stigmer apply

# Deploy from a specific project directory
stigmer apply --config /path/to/project/

# Deploy and prune orphaned resources
stigmer apply --prune

# Skip orphan pruning
stigmer apply --prune=false
```

Declarative mode tracks which resources belong to the project. When you remove
a resource file and re-apply with `--prune`, the orphaned resource is deleted
from the backend.

### Dry run

Use `--dry-run` to preview what would be applied without making changes. The
CLI validates resource definitions and reports what would be created, updated,
or deleted.

```bash
stigmer apply --dry-run
stigmer apply -f agent.yaml --dry-run
```

## Examples

### Deploy a project

```bash
cd my-stigmer-project/
stigmer apply
```

The CLI finds `stigmer.yaml`, discovers all YAML resources in the directory,
and applies them to the backend.

### Apply a single agent definition

```bash
stigmer apply -f agent.yaml
```

Creates or updates the agent defined in the file. The CLI auto-detects the
resource kind from the YAML `kind` field.

### Deploy to a specific organization

```bash
stigmer apply -f agent.yaml --org acme-corp
```

### CI/CD deployment with machine-readable output

```bash
stigmer apply --json --dry-run && stigmer apply --json
```

Use `--json` for structured output in CI pipelines. Run with `--dry-run`
first to validate, then apply.
