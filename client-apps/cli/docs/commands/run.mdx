Execute an agent by reference, or browse agents interactively.

When you run `stigmer run` without arguments, an interactive picker lets you
search and select from available agents. With a reference argument, the CLI
resolves it as an agent slug, `org/slug`, or agent ID.

The command streams agent output to your terminal in real time — you see
messages, tool calls, and approval prompts as they happen. For scripting and
CI pipelines, use `--json` to receive newline-delimited event objects instead.

### Common patterns

```bash
# Browse and select an agent interactively
stigmer run

# Run by slug
stigmer run my-agent

# Run by org-qualified slug
stigmer run acme-corp/code-reviewer

# Run with an initial prompt
stigmer run my-agent -m "Summarize the Q4 earnings report"
```

### Values for this conversation

Keys your agent and its tools need normally come from your vault
(`stigmer vault set-secret <NAME> --mine`), so a run needs no flags. To hand a
run a value of its own, four flags work together. The values are kept sealed on
the new conversation, used ahead of every vault, never shown again, and
destroyed with the conversation:

| Flag | Purpose |
|------|---------|
| `--env KEY=VALUE` | A value for this conversation (repeatable) |
| `--secret KEY=VALUE` | The same, for a value that reads as a secret (repeatable) |
| `--env-file PATH` | Load values from a dotenv-style file (repeatable) |
| `--secret-file PATH` | Load secret values from a file (repeatable) |

**Precedence** (highest to lowest):

1. `--env` and `--secret` flags (inline values)
2. Later `--env-file` / `--secret-file` flags
3. Earlier `--env-file` / `--secret-file` flags

A variable with no value (`KEY=` in a dotenv file) is left out, and a notice on
stderr names it (never a value). A run takes at most 100 variables: more is
refused before anything is sent, so save the rest in a vault the run uses.

```bash
# Inline values
stigmer run my-agent --env API_URL=https://api.example.com --env DEBUG=true

# An inline secret
stigmer run my-agent --secret API_KEY=sk_live_xxx

# Load from files
stigmer run my-agent --env-file .env --secret-file .env.secrets

# Mix files and inline overrides
stigmer run my-agent --env-file .env --secret DB_PASSWORD=xxx
```

### Workspaces

Give your agent access to code repositories or local directories. Multiple
`--workspace` flags create a multi-root workspace (VS Code model).

```bash
# Local directory
stigmer run code-reviewer -w . -m "Review my project"

# Git repository
stigmer run code-reviewer --workspace https://github.com/acme/app -m "Review"

# Pin to a specific branch or commit
stigmer run code-reviewer --workspace https://github.com/acme/app --branch feature/auth

# Multiple workspaces
stigmer run my-agent -w ./frontend -w ./backend
```

`--branch` and `--commit` apply only when a single git workspace is provided.

### File attachments

Attach files as input to the agent. Files under 4 MB are embedded inline;
larger files are uploaded to the artifact store automatically.

```bash
stigmer run data-analyzer --attach ./report.csv -m "Analyze this data"
stigmer run my-agent --attach ./image.png --attach ./spec.pdf
```

### Output modes

| Flag | Behavior |
|------|----------|
| _(default)_ | Interactive terminal UI powered by [`@stigmer/ink`](/docs/sdk/ink/cli-integration) |
| `--json` | Newline-delimited JSON events for scripting and CI |
| `--detach` | Start the run and return immediately |

Use `--json` when piping output to other tools:

```bash
stigmer run my-agent --json -m "Process data" | jq '.payload.content'
```

Use `--detach` for a fire-and-forget run. The CLI prints the session ID
and exits. Check progress with `stigmer get session <id>`.

```bash
stigmer run my-agent --detach -m "Generate weekly report"
```

### Run options

| Flag | Purpose |
|------|---------|
| `--model` | Override the LLM model (e.g., `claude-sonnet-4-6`) |
| `--harness` | Choose the execution engine for the new session (`native` or `cursor`) |
| `--auto-approve` | Approve all tool executions without prompting (bypasses approval policies) |
| `--approve-default` | Auto-resolve approval prompts in non-interactive mode (`approve`, `skip`, `reject`) |
| `--verbose`, `-v` | Show run IDs and phase transitions in the TUI transcript |

```bash
# Use a specific model
stigmer run my-agent --model claude-opus-4.6 -m "Analyze this codebase"

# Skip all approval prompts (use with caution)
stigmer run my-agent --auto-approve -m "Deploy to staging"
```

### Choosing a harness

The harness is the engine that executes your session: `native` (Stigmer's
own runtime, the default) or `cursor` (the Cursor engine, billed at its
premium tier). A session keeps its harness for life — `stigmer resume`
always continues on the engine the session started with.

You rarely need the flag. If your account declares a default harness
(Account settings → Execution defaults, or `default_harness` on your
identity account), `stigmer run` applies it automatically on Stigmer Cloud,
and an omitted `--model` fills from your default model for that harness.
The flag is the per-run override:

```bash
# Start a cursor-harness session explicitly
stigmer run code-reviewer --harness cursor -w . -m "Review my changes"

# Force one native run without changing your cursor account default
stigmer run my-agent --harness native -m "Quick question"
```

When a session starts on the cursor harness, the session header says so —
you always see the engine before output streams.

## Examples

### Interactive agent selection

```bash
stigmer run
```

A search picker appears. Type to filter agents by name or description. Select
an agent and start a conversation.

### Run with a message

```bash
stigmer run my-agent -m "Summarize the Q4 earnings report"
```

The agent receives the message and streams its response to the terminal.

### CI/CD pipeline with JSON output

```bash
stigmer run my-agent --json -m "Run integration tests" \
  --env-file .ci.env \
  --auto-approve \
  | jq -r 'select(.type == "message") | .payload.content'
```

Stream events as JSON for programmatic consumption. Each line is a complete
JSON object. Combine with `--auto-approve` to run without human interaction.

### Git repository review

```bash
stigmer run code-reviewer \
  --workspace https://github.com/acme/app \
  --branch main \
  -m "Review the latest changes for security issues"
```

The agent clones the repository, checks out the specified branch, and
performs the review with full access to the codebase.

### Fire-and-forget run

```bash
stigmer run report-generator --detach -m "Generate the monthly report"
```

The CLI prints the session ID and exits immediately. Use
[`stigmer get session`](./get) to check progress, or
[`stigmer resume`](./resume) to re-attach to the live stream.
