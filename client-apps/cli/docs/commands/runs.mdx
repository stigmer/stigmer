Manage run lifecycle and observability.

`stigmer runs` controls the lifecycle of runs and exposes their logs, traces and
scores. A run is addressed by its ID, `run_<ulid>`.

The group is plural because `stigmer run` starts a run; `stigmer runs` manages
one that already exists.

The subcommands fall into three areas:

- **Lifecycle** — `cancel` interrupts the run's conversation: the run and every
  other unfinished turn of its session stop, and the command names each turn it
  stopped; `terminate` force-stops it immediately without cleanup (and cannot be
  recovered); `pause` checkpoints a run in progress; `resume` continues a paused
  one from its last checkpoint.
- **Observability** — `logs` lists or follows a run's events, one line each;
  `trace` shows its tool calls and how each ended, or lists its events as JSON
  or YAML; `scores` shows how good a finished run was: each person's thumbs, the
  run-health checks, the AI judge and, on an eval run's try, each check of its
  case ([Scores](/docs/concepts/scores)); `to-eval-case` turns a run into a test
  case, written into a local `evals/` folder or added to an eval.
- **Approval** — `approve` answers a tool call the run waits on: allow it, deny
  it with a reason the agent reads, or allow it and every waiting call of its
  kind for the rest of the turn.

## Examples

### Cancel and terminate

```bash
# Cancel a run: every unfinished turn of its conversation stops
stigmer runs cancel run_01abc123

# Force-stop immediately (unrecoverable)
stigmer runs terminate run_01xyz789 --reason "stuck run"
```

### Pause and resume

```bash
stigmer runs pause run_01abc123 --reason "investigating issue"
stigmer runs resume run_01abc123
```

### Stream logs and inspect a trace

```bash
# Follow a run's events until it ends
stigmer runs logs run_01abc123 --follow

# List the run's events as YAML
stigmer runs trace run_01abc123 -o yaml
```

### Read a run's scores

```bash
# People's thumbs, the run-health checks and the AI judge, one row per score
stigmer runs scores run_01abc123

# The scores as JSON, for a script
stigmer runs scores run_01abc123 -o json
```

### Turn a run into a test case

```bash
# Write the case into evals/<name from the request>/
stigmer runs to-eval-case run_01abc123

# Name the case, and also check that the plugin's review skill fired
stigmer runs to-eval-case run_01abc123 --name finds-the-bug --skill thermos:review

# Add the case to an eval as a new version instead
stigmer runs to-eval-case run_01abc123 --eval variance-reporter-evals
```

Stigmer builds the case from the run: the request as `prompt.md`, the
conversation before it as `history.jsonl` when there was one, each MCP tool's
answer as a mock, and `graders/criteria.md`, whose FAIL line names what went
wrong (the AI judge's reason, else an eval run's failing check, else your
thumbs-down comment); write its PASS line yourself. What the case leaves out is
printed beside it. An existing case directory is never overwritten, and an eval
refuses a case name it already holds. See
[Test agents and plugins with evals](/docs/guides/evals/test-with-evals#turn-a-conversation-into-a-case).

### Approve a waiting run

```bash
# Allow the one tool call the run waits on
stigmer runs approve run_01xyz789

# Deny a named call (its tool_use_id, from `stigmer runs logs`) with a reason
stigmer runs approve run_01xyz789 --tool-call run_01xyz789.toolu_abc --action deny --comment "not on prod"

# Allow it and every waiting call of its kind for the rest of the turn
stigmer runs approve run_01xyz789 --tool-call run_01xyz789.toolu_abc --action allow-all
```
