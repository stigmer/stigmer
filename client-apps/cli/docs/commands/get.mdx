Retrieve a resource by type and reference.

`stigmer get` fetches a single resource from the Stigmer backend and displays
its details. You specify the resource type and a reference — either a slug, an
`org/slug` qualified name, or a resource ID. A slug the resource was renamed
away from keeps finding it for 30 days after the rename, and the output shows
the current slug.

{/* AUTO_USAGE */}

### Common patterns

```bash
# Get an agent by slug
stigmer get agent my-agent

# Get by org-qualified slug
stigmer get agent acme-corp/code-reviewer

# Get by resource ID
stigmer get agent agt_abc123

# Output as YAML
stigmer get agent my-agent --output yaml
```

### Versions

Agents keep every version an apply records. Show the history, or fetch one
version by its content hash or a tag:

```bash
# The version history, newest first; * marks the current version
stigmer get agent acme-corp/code-reviewer --version-history

# The agent as the version tagged "stable" stored it
stigmer get agent acme-corp/code-reviewer --version stable
```

### Supported resource types

| Type          | Aliases                                | Reference formats                                    |
| ------------- | -------------------------------------- | ---------------------------------------------------- |
| Agent         | `agent`, `agt`, `agents`               | slug, org/slug, ID                                   |
| API Key       | `apikey`, `key`                        | ID only                                              |
| Channel       | `channel`, `chn`                       | slug, org/slug, ID                                   |
| Channel App   | `channel-app`, `channelapp`, `chapp`   | slug, org/slug, ID                                   |
| Eval Run      | `eval-run`, `evr`, `eval-runs`         | ID only                                              |
| Organization  | `organization`, `org`, `organizations` | slug, ID                                             |
| Routine       | `routine`, `rtn`, `routines`           | slug, org/slug, ID                                   |
| Run           | `run`, `runs`                          | ID only                                              |
| Score         | `score`, `scr`, `scores`               | ID only                                              |
| Scoring Rule  | `scoring-rule`, `srl`, `scoring-rules` | ID only                                              |
| Skill         | `skill`, `skills`                      | slug, org/slug, ID                                   |
| Vault         | `vault`, `vlt`, `vaults`               | slug, org/slug, ID (entry names only, never a value) |

### Output formats

Use `--output` to control the display format:

| Format  | Use case                         |
| ------- | -------------------------------- |
| `table` | Human-readable table (default)   |
| `yaml`  | Full resource definition as YAML |
| `json`  | Full resource definition as JSON |

```bash
# Export an agent definition as YAML
stigmer get agent my-agent --output yaml > agent.yaml

# Pipe JSON to jq for field extraction
stigmer get agent my-agent --output json | jq '.spec.instructions'
```

## Examples

### Inspect an agent

```bash
stigmer get agent my-agent
```

### Check run status and artifacts

```bash
stigmer get run run_01abc123
```

Runs are referenced by ID only (not slugs). The output includes artifacts
produced by the agent.

### Export a resource definition

```bash
stigmer get agent my-agent --output yaml > agent-backup.yaml
```

The file holds the whole resource, its `metadata.id` and `metadata.etag`
included. `stigmer apply -f agent-backup.yaml` later restores it as written,
however much the agent changed since: an applied file drops the etag. Keep the
`metadata.id` in the file and edit `metadata.slug` to rename the agent.

A restored file names the resources it references by slug, as a file does: a
skill renamed since resolves under its old slug for 30 days, and a slug that
another skill has taken since names that skill.
