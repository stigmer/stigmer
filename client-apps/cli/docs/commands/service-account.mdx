Create, list and delete your Organization's service accounts, and list their API keys.

A service account is your Organization's own account for automation: a CI job or
a script acts as it through API keys created for it, so the automation keeps
working when the person who set it up leaves, and what it creates names the
service account as its creator. It holds one Organization role (admin, member or
viewer, never owner) and works only in its Organization. Only the Organization's
admins manage service accounts. The commands act in the Organization `--org`
names, then `STIGMER_ORG`, then your context.

{/* AUTO_USAGE */}

### Common patterns

```bash
# Create a service account with the Member role
stigmer service-account create ci-deploy

# Create one with another role
stigmer service-account create release-bot --role admin

# Give it a key (shown once)
stigmer apikey create --service-account ci-deploy --name github-actions

# List the Organization's service accounts, newest first
stigmer service-account list

# List one's API keys; revoke one with: stigmer delete apikey <id>
stigmer service-account keys ci-deploy

# Delete one; every key it has stops working at once
stigmer service-account delete ci-deploy
```

{/* AUTO_FLAGS */}

### Deleting a service account

Deleting a service account ends every API key it has at once, and it loses every
role it holds. What it created stays with the Organization. The command asks
first on a terminal; off a terminal it deletes nothing unless you pass
`--force`.

## Examples

### Set up CI to act as a service account

```bash
stigmer service-account create ci-deploy --role member
stigmer apikey create --service-account ci-deploy --name github-actions --expires-in 90d
```

Save the displayed key as a CI secret named `STIGMER_API_KEY`.

### Delete one from a script

```bash
stigmer service-account delete ci-deploy --force
```
