Connect to a plugin's MCP server and list its tools.

`stigmer connect plugin <plugin>` lists the tools one of a plugin's MCP servers
offers right now, reached as you: a runner of your organization starts or calls
the server with the keys and sign-ins in your own vault (My vault), and the
answer is printed. Nothing is stored; run it again whenever you want the
current list. A tool the server marks destructive is shown with
`[destructive]`: a turn asks a person before calling it.

### Choosing the server

A plugin with one MCP server needs no more than its name. A plugin with
several is refused with their names; pick one with `--server <name>`, the
server's key in the plugin's MCP configuration.

### Signing in

A server that signs in (an address that answers with an OAuth challenge) uses
the login saved in My vault at its address. When there is none, the command
opens the login page in your browser (the `BROWSER` command when you set one,
as `stigmer auth login` does) and waits until the sign-in is saved, then lists
the tools. Where no browser can open (an SSH session, a machine with no
display), it prints the login page's address instead: open it in a browser on
any device, and the command finishes the same way. A server that also accepts a
pasted key is satisfied by a key saved under its login key:

```bash
stigmer vault set-secret LINEAR_TOKEN --mine
stigmer connect plugin linear
```

Off an interactive terminal (CI, pipes) the command stops with these ways
instead of waiting for a browser. `--env` is refused, naming the vault
command: keys are never given on the command line.

### Signing in again

A saved login can stop working: it expired and could not be renewed, or you
revoked it at the login server. The listing then fails in the server's words
and ends with the way to a fresh one:

```text
If your login has expired or was revoked, run stigmer connect plugin linear --sign-in-again.
```

`--sign-in-again` runs the same browser sign-in even though My vault holds a
login at the server's address, and the new login replaces the saved one. The
console's plugin page offers the same as **Sign in again** beside a saved
login. To remove a login without signing in again, run
`stigmer vault remove-connection <address>`; `stigmer get plugin <name>` prints
each server's address and whether you are signed in to it.

### Missing keys

A key the server reads and none of your vaults hold fails the listing naming
the key. Save it in My vault and run the command again.

### Dry run

`--dry-run` lists the tools from this machine, without a runner: a local
program is started here with your shell's environment, and an address is
called with the plugin's headers. A `${VAR}` placeholder in a program's
arguments or a header resolves from your shell, else from the plugin's
declared default, and a missing one fails naming the variable. A server that
accepts only a sign-in cannot be listed this way, because its token lives in
your vault on the server.

```bash
FILESYSTEM_ALLOWED_DIR="$HOME/projects" \
  stigmer connect plugin filesystem --dry-run
```

`--timeout` bounds the dry run's discovery, in seconds.

## Examples

### List a plugin's tools

```bash
stigmer connect plugin linear
```

### Pick one of several servers

```bash
stigmer connect plugin acme-tools --server issues
```

### Replace a login that stopped working

```bash
stigmer connect plugin linear --sign-in-again
```

### Name the plugin's organization

```bash
stigmer connect plugin platform/github
```
