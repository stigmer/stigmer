Connect to external services and discover their capabilities.

`stigmer connect` lets you connect to MCP servers, discover their tools and
resource templates, and push the results to the Stigmer backend. This is how
you teach Stigmer what an MCP server can do — the discovered capabilities
become available to agents at runtime.

### How connection works

For **stdio-based servers**, the CLI spawns the server process locally.
Environment variables from your shell are passed through, so credentials
(e.g., `GITHUB_TOKEN`) never leave your machine. Note that stdio servers are
local-runner-only: connecting one while authenticated to Stigmer Cloud is
refused, because cloud compute never spawns stdio subprocesses. Use
`--dry-run` (which runs entirely on your machine) or connect against a local
`stigmer server`.

For **HTTP-based servers**, the CLI connects to the configured URL directly.

### Passing credentials

Use `--env` to pass credentials the MCP server needs. Values are merged on
top of your shell environment (`--env` wins on collision).

```bash
# Single credential
stigmer connect mcp-server planton --env PLANTON_API_KEY=pk-xxx

# Multiple credentials
stigmer connect mcp-server my-server \
  --env GITHUB_TOKEN=ghp-xxx \
  --env API_URL=https://api.example.com
```

You can also export variables in your shell before running the command.
`--env` is more convenient and mirrors `stigmer run` and `stigmer draft`.

### Environment variable placeholders

A server's command arguments (stdio) and HTTP headers may reference declared
environment variables using `${VAR_NAME}` syntax. For example, the filesystem
server takes its allowed directory as an argument:

```yaml validate-as="McpServer.spec"
stdio:
  command: npx
  args:
    - "-y"
    - "@modelcontextprotocol/server-filesystem"
    - "${FILESYSTEM_ALLOWED_DIR}"
env:
  FILESYSTEM_ALLOWED_DIR:
    description: Root directory the server is allowed to access
```

Placeholders are resolved from the same values `--env` and your shell provide
(the variable must be declared under the server's `env`). Resolution is strict
and identical between `--dry-run` and a real connect: a missing variable
produces a clear error naming the variable, rather than passing a literal
`${VAR}` to the server.

```bash
stigmer connect mcp-server mcp-server-filesystem \
  --dry-run --env FILESYSTEM_ALLOWED_DIR="$HOME/projects"
```

### Dry run

Use `--dry-run` to preview discovered capabilities without pushing them
to the backend.

```bash
stigmer connect mcp-server github --dry-run
```

## Examples

### Discover tools from a GitHub MCP server

```bash
stigmer connect mcp-server github
```

Connects to the GitHub MCP server, lists its tools, and pushes them to
the Stigmer backend.

### Connect with an organization-qualified slug

```bash
stigmer connect mcp-server stigmer/mcp-server-stigmer
```

### Bound the wait

```bash
stigmer connect mcp-server my-server --timeout 90
```

The value is a number of seconds. `--timeout` always bounds `--dry-run`'s
local discovery; for a real connect it bounds the wait only when set
explicitly — the connect keeps running server-side and persists its result,
so a timeout here means "stop waiting", not "the connect failed". Without an
explicit `--timeout`, a real connect waits for the server to finish (sandbox
start, discovery, and tool classification can take a few minutes).
