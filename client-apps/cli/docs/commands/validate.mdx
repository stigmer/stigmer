Validate resource YAML files, or a plugin directory, without applying them.

`stigmer validate` checks that your resource files contain valid YAML with a
correct schema. It supports agents, workflows, and MCP servers. The
resource type is auto-detected from the `kind` field in the YAML.

It also validates a plugin directory: a folder with a `plugin.json`,
`.cursor-plugin/plugin.json`, `.claude-plugin/plugin.json` or
`.codex-plugin/plugin.json` manifest, in the open Agent Plugins format or the
Cursor, Claude Code or Codex dialect. Validation reports what an install would
produce (skills, MCP servers, sub-agents, variables), every warning, and every
component Stigmer does not install, or refuses the plugin with one sentence per
problem.

Use this command before `stigmer apply` to catch errors early — especially
useful in CI pipelines.

### Common patterns

```bash
# Validate a single file
stigmer validate -f agent.yaml

# Validate all YAML files in a directory
stigmer validate -f ./manifests/

# Validate a plugin directory, in any dialect
stigmer validate -f ./my-plugin/
```

### What gets validated

- YAML syntax
- Required fields (apiVersion, kind, metadata, spec)
- Resource-specific schema rules per kind
- Multi-document YAML (`---` separated)
- For a plugin directory: the manifest, every `SKILL.md`, the MCP server
  configuration, every sub-agent file, the declared variables, and the
  `ai.stigmer/` overlay documents

### Supported inputs

| Input | Behavior |
|-------|----------|
| Single `.yaml` / `.yml` file | Validate one resource definition |
| Directory path | Validate all YAML files in the directory |
| Multi-document YAML | Validate each document separately |
| Plugin directory | Read the plugin as an install would and report or refuse it |

### Validating a plugin

A directory that holds a plugin manifest is read as a plugin, not as a folder
of YAML files. The output lists what Stigmer would install and what it leaves
behind:

```text
✓ Plugin 'github' is valid

Plugin:
  Name         github
  Version      1.0.0
  Format       Cursor plugin
  Manifests    .cursor-plugin/plugin.json
  Files        6 read, 0 excluded by ignore rules

Installs:
  Skills         none
  MCP servers    1: github (http)
  Sub-agents     none
  Variables      1: GITHUB_PERSONAL_ACCESS_TOKEN

Not installed:
  - assets (assets/)
  - logo (.cursor-plugin/plugin.json#logo)
```

A plugin Stigmer cannot install exits with code 2 and lists every problem, so
you fix them in one pass. Files excluded by `.gitignore`, `.stigmerignore` and
the built-in security defaults are excluded here exactly as a push would
exclude them. With `--json`, the normalised plugin is emitted under `data`.

## Examples

### Validate before deploying

```bash
stigmer validate -f agent.yaml && stigmer apply -f agent.yaml
```

Run validation first, then apply only if it passes.

### Validate a directory of resources

```bash
stigmer validate -f ./manifests/
```

Checks every YAML file in the directory.

### CI pipeline validation

```bash
stigmer validate -f ./manifests/ || exit 1
```

Exit with a non-zero code if any file fails validation.
