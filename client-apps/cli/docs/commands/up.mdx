Start the local Stigmer stack.

`stigmer up` brings up the complete local stack — managed Temporal, the
control-plane `stigmer-server`, and a unified execution runner — as a
supervised background daemon. This is the quickstart command for local
development: no cloud account needed.

On first run the CLI acquires the `stigmer-server` and runner packages at the
matching version, then bootstraps the backend: it creates the `stigmer`
organization and installs the official marketplace's default plugins into it,
so a default agent is available immediately. An install that still carries the
system content an older release seeded is retired on this run, and the CLI
reports what was removed and what was kept because one of your agents still
references it.

Use `stigmer up server` to start only the control plane (Temporal and
`stigmer-server`) when you manage your own runners — for example, the desktop
app with an embedded runner, your own customer code, or cloud sandboxes.

{/* AUTO_USAGE */}

### Common patterns

```bash
# Start the full local stack (server, runner, Temporal)
stigmer up

# Start only the control plane (no runners)
stigmer up server

# Check what is running
stigmer status

# Stop everything
stigmer down
```

## Examples

### Start the full local stack

```bash
stigmer up
```

The first run may take a moment while the server, runner, and the official
plugin catalogue are downloaded and verified. Subsequent runs start immediately.

### Start only the control plane

```bash
stigmer up server
```

Starts Temporal and `stigmer-server` without any runner processes. Use this
when a separate process (desktop app, your own code, or a cloud sandbox)
provides the runner.

### Inspect and tear down

```bash
stigmer status   # show component health and the effective LLM configuration
stigmer down     # stop the stack
```
