Manage Stigmer CLI configuration.

`stigmer config` reads and writes settings stored in `~/.stigmer/config.yaml`.
This includes backend selection (local vs cloud), organization context,
LLM provider settings, and execution options.

Configuration priority (highest to lowest):

1. CLI flags
2. Environment variables
3. Config file

{/* AUTO_USAGE */}

### Common patterns

```bash
# List all configuration values
stigmer config list

# Get a specific value
stigmer config get llm.provider

# Set a value
stigmer config set llm.provider anthropic

# Show the config file path
stigmer config path

# Switch backend
stigmer config backend set cloud

# Set active organization
stigmer config context set --org my-org
```

### Named backends

Beyond the built-in `local` and `cloud` backends, you can register any
self-hosted Stigmer server as a named backend. Each backend keeps its own
endpoint and its own credentials, so switching never clobbers another
backend's login.

```bash
# Register a self-hosted server (mint the key with `stigmer apikey create`)
stigmer config backend add staging --endpoint stigmer.example.com:7234 --api-key stk_...

# Switch between backends
stigmer config backend use staging
stigmer config backend use cloud
stigmer config backend use local

# See what is configured
stigmer config backend list
stigmer config backend status

# Remove one (switch away from it first)
stigmer config backend remove staging
```

Backend types:

- `selfhost` (the default for `add`) — any OSS Stigmer server. Its
  credential is an API key (`--api-key`, or the `STIGMER_API_KEY`
  environment variable per invocation). A server running without
  authentication needs no credential at all.
- `cloud` — a Stigmer Cloud endpoint. Its credential is the browser login
  (`stigmer auth login`).

### Available configuration keys

| Key | Purpose |
|-----|---------|
| `execution.mode` | Agent execution mode (`local`, `sandbox`, `auto`) |
| `execution.sandbox_image` | Docker image for sandbox execution |
| `llm.provider` | LLM provider (`anthropic`) |
| `llm.model` | Optional model override (defaults to the platform-selected model) |
