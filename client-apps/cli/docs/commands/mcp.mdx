Install an MCP server as a plugin of its own.

An agent lists its own MCP servers under `spec.mcp_servers`, which only an
organization's admins may add or change; anywhere else, a server lives in a
plugin. `stigmer mcp add <name> <url>` is the short way to a plugin holding one
server, as Claude Code's `claude mcp add` adds one: it
writes a plugin named `<name>` whose MCP configuration names one server,
`<name>`, at `<url>`, and installs it in your organization exactly as
`stigmer install` installs a plugin. Use it like any other plugin:
`stigmer run --plugin <name>` for a conversation, or list it under an agent's
`spec.plugins`.

`stigmer mcp-server` is a different command: it starts Stigmer's own MCP
server for your IDE.

### Headers and keys

`--header NAME=VALUE` adds a header sent with every request; repeat it for
more. A value may name a key in your vault as `${NAME}`: the plugin then
declares the key, and each conversation reads it from the vaults it uses. The
value is never written into the plugin.

```bash
stigmer vault set-secret ACME_TOKEN --mine
stigmer mcp add acme https://mcp.acme.example/mcp --header 'Authorization=Bearer ${ACME_TOKEN}'
```

An address that answers with an OAuth challenge is a server you sign in to:
the install's `Next` section names `stigmer connect plugin <name>`, which runs
the sign-in and lists the tools.

### Adding again

Running `mcp add` again with the name of a plugin it made changes that plugin:
the same address, headers and description change nothing, and a new address,
new headers or `--description` upgrade it. The upgrade keeps what you do not
give again: the plugin's visibility (unless `--visibility` is given) and its
description (unless `--description` is). Agents and conversations that use the
plugin reach the new address from their next message. A login is kept per
address, so after a change of address you sign in again with
`stigmer connect plugin <name>`.

`mcp add` changes only a plugin of one server and nothing else, read from the
installed plugin's own files. A plugin pushed from a folder (skills, hooks,
several servers, or any other file) is refused rather than replaced by one
server, naming what it holds: change its folder and run
`stigmer push plugin <folder>`. To replace it with one server anyway, remove
it first with `stigmer delete plugin <name>`. `--dry-run` says which it would
do: install, change, or refuse.

A plugin's name never changes: it is part of every tool name its agents use
(`mcp__plugin_<name>_…`). To use another name, add the server again under that
name, move your agents to it, and remove the old plugin.

## Examples

### Add a server and use it in a conversation

```bash
stigmer mcp add linear https://mcp.linear.app/mcp
stigmer connect plugin linear
stigmer run --plugin linear -m "What's on my plate this week?"
```

### See the plugin without installing it

```bash
stigmer mcp add linear https://mcp.linear.app/mcp --dry-run
```

### Point a server at a new address

```bash
stigmer mcp add linear https://mcp.linear.app/v2/mcp --dry-run
stigmer mcp add linear https://mcp.linear.app/v2/mcp
stigmer connect plugin linear
```
