## What you'll build

On the last page your backend ran the variance report job. Now the customer runs
it themselves, inside your product. Your backend signs them in to Stigmer with
the service account's key, your React app shows them the chat, and they upload
the ledger and get the report back on the page.

The moment to watch for: a person signed in to your app, not you, uploads a
ledger and sees the report appear among the conversation's files.

**Time**: about 20 minutes. **Prerequisites**:

- A Stigmer that signs its callers in: Stigmer Cloud, or a server of your own
  with [sign-in turned on](/docs/guides/self-hosting/authentication). This works
  in every edition. The Stigmer that `stigmer up` starts trusts every caller, so
  it has no one to sign in, and it refuses to make sign-in tokens.
- The `report-backend` service account's key from
  [Do the same job from your app](/docs/getting-started/call-from-your-app), as
  `STIGMER_API_KEY`, with your Organization's slug as `STIGMER_ORG`.
- The `variance-reporter` Agent and `ledger.csv` from
  [Your first agent job](/docs/getting-started/quickstart), and Node.js 22.13 or
  newer.

<Steps>
<Step>

## Let your users in

Your Organization's **embedding settings** decide what happens the first time
your backend signs a user in. In the console, open **Settings → Embedding** and
turn on **Create accounts on sign-in** with the sign-in role **member**, so each
of your users gets a Stigmer account that can start conversations.

</Step>
<Step>

## Create the app

Skip this step if you're adding the chat to an app you already have. Otherwise,
make one with Vite and add the SDK:

```bash
npm create vite@latest my-app -- --template react-ts
cd my-app
npm install
npm install @stigmer/react-sdk @stigmer/client @stigmer/apis @bufbuild/protobuf
```

`@stigmer/react-sdk` holds the chat and needs React 19, which the Vite template
already uses.

</Step>
<Step>

## Sign your user in from your backend

Your backend already knows who is signed in to your product. For that person, it
asks Stigmer for a short-lived token, using the service account's key, which
never reaches the browser. Create `server.ts`:

```typescript title="server.ts"
import { createServer } from "node:http";
import { createNodeClient } from "@stigmer/client/node";

const stigmer = createNodeClient({
  baseUrl: process.env.STIGMER_URL ?? "https://api.stigmer.ai",
  apiKey: process.env.STIGMER_API_KEY!,
});

createServer(async (req, res) => {
  if (req.url !== "/api/stigmer-token") {
    res.writeHead(404).end();
    return;
  }
  // Your product's own sign-in says who this request is from.
  const user = { id: "user_123", email: "dana@example.com", name: "Dana" };
  const { accessToken, expiresAt } = await stigmer.tokens.mintUserToken({
    org: process.env.STIGMER_ORG!,
    userId: user.id,
    userEmail: user.email,
    userName: user.name,
  });
  res.writeHead(200, { "content-type": "application/json" });
  res.end(JSON.stringify({ accessToken, expiresAt: expiresAt.toISOString() }));
}).listen(3001);
```

The fixed `user` stands in for your sign-in. Pass a stable ID, such as your user
table's primary key: every token minted for the same ID belongs to the same
Stigmer account.

Send the app's `/api` requests to this server while you develop. Replace
`vite.config.ts`:

```typescript title="vite.config.ts"
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
  server: { proxy: { "/api": "http://localhost:3001" } },
});
```

</Step>
<Step>

## Show the chat

Replace `src/App.tsx`:

```tsx title="src/App.tsx"
import { Stigmer, createTokenCache } from "@stigmer/client";
import { AgentChat, StigmerProvider } from "@stigmer/react-sdk/chat";
import "@stigmer/react-sdk/styles.css";

const org = import.meta.env.VITE_STIGMER_ORG;

const tokens = createTokenCache(async () => {
  const res = await fetch("/api/stigmer-token");
  return res.json();
});

const stigmer = new Stigmer({
  baseUrl: import.meta.env.VITE_STIGMER_URL ?? "https://api.stigmer.ai",
  getAccessToken: tokens.getAccessToken,
});

export default function App() {
  return (
    <StigmerProvider client={stigmer}>
      <main style={{ height: "100vh" }}>
        <AgentChat agent={`${org}/variance-reporter`} />
      </main>
    </StigmerProvider>
  );
}
```

- `createTokenCache` asks your backend for a token once, and again only when it
  is a minute from its `expiresAt`. When your user signs out, call
  `tokens.invalidate()`, so the next person to sign in never gets their token.
- `AgentChat` is where your user writes the first message and attaches files.
  When they send it, Stigmer starts a Session (a conversation), and the same
  component shows it as it happens, with the files given to it and the files the
  Agent saved.
- The chat is for a person signed in to your product. It stays with the Agent
  you named: your user can't swap it for another or change its tools.
- `variant="panel"` fills a column you dock beside your page, and
  `variant="popup"` puts a button in the corner that opens the chat. While the
  popup is closed, its button says what the Agent is doing.
- To reopen the conversation after a reload, keep the ID `onSessionChange` hands
  you, and pass it back as `defaultSessionId`.

</Step>
<Step>

## Run the job as your user

Start your backend, then the app, in two terminals:

```bash
npx tsx server.ts
```

```bash
VITE_STIGMER_ORG=$STIGMER_ORG npm run dev
```

For a server of your own, set `STIGMER_URL` and `VITE_STIGMER_URL` to its
address.

Open `http://localhost:5173`. Attach `ledger.csv` in the message box, write
"Review this quarter's ledger." and send it. While the Agent works, one line
above the message box says what it is doing and for how long. When it finishes,
the turn closes with what it made: `variance-report.md` under **Made**, ready to
open in place.

</Step>
</Steps>

## What just happened

Your user did the job in your product. Your backend vouched for them with a
token it minted, so Stigmer knew who they were without a sign-in of its own. The
conversation is theirs: it belongs to their Stigmer account, and the report came
back to them.

Before you ship, list your app's address under **Allowed origins** in the
embedding settings, so tokens only work from your pages. The
[sign-in guide](/docs/guides/authentication/product-users) has the details, the
errors and the other SDKs. The components take your product's look through
[theming](/docs/sdk/theme/theming).

The chat on this page is for people signed in to your product. For a chat open
to anyone visiting your site, signed in or not, give the Agent a chat link and
put the `<stigmer-agent>` element on your page, as
[Embed an Agent](/docs/guides/channels/embed-an-agent) shows. Stigmer Cloud
serves it.
