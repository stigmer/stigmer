## What you'll build

An accounting product's customer uploads a ledger, and an Agent works through it
and hands back a variance report as a file. You'll play both parts from your
terminal: create the Agent, give it the ledger, and open the report it saved.

The moment to watch for is the last step: a file you didn't write appears in
your folder, made by the Agent from the ledger you gave it.

**Time**: about 10 minutes. **Prerequisites**: macOS or Linux, and an
[Anthropic API key](https://console.anthropic.com/). The two places you can run
this, your own machine or Stigmer Cloud, differ only in the second step.

<Step>

## Start Stigmer and add your model key

Agents run on your model key. Pick where Stigmer runs; the steps after this one
are the same in both places.

<Tabs items={["On your machine", "Stigmer Cloud"]} groupId="stigmer-target" persist>
<Tab value="On your machine">

Put your key in the shell, then start Stigmer:

```bash
export ANTHROPIC_API_KEY=<your Anthropic API key>
stigmer up
```

`stigmer up` starts the server, the console and the runner (where your Agents
run) in the background, with nothing to sign in to. It reads the key from your
shell. To save the key instead of exporting it each time, run `stigmer setup`
once.

</Tab>
<Tab value="Stigmer Cloud">

Sign in from the CLI:

```bash
stigmer auth login
```

In the [console](https://app.stigmer.ai), open **Settings → Provider keys** and
add your Anthropic key to your Organization (your team's account). Then point
the CLI at that Organization:

```bash
stigmer config context set --org <your-org>
```

</Tab>
</Tabs>

</Step>
<Step>

## Create the Agent

An Agent is the definition of a job: what it does and how. Create
`variance-reporter.yaml`:

```yaml title="variance-reporter.yaml"
apiVersion: agentic.stigmer.ai/v1
kind: Agent
metadata:
  name: variance-reporter
spec:
  description: Turns a customer's ledger into a variance report.
  instructions: |
    You review a customer's quarterly ledger. Each row has an account,
    its budget and its actual amount.

    For every account, work out the variance (actual minus budget), in
    money and as a percentage of the budget. Flag each account that is
    more than 10% over or under budget, and say in one line what could
    explain it.

    Save the report as variance-report.md in your outputs folder: a
    two-sentence summary, then one table of every account, flagged
    accounts first.
```

Send it to Stigmer:

```bash
stigmer apply -f variance-reporter.yaml
```

The last instruction is the one that matters for this page: whatever the Agent
saves in its outputs folder comes back to whoever started the job.

</Step>
<Step>

## Make the customer's ledger

Create `ledger.csv`, the file your customer would upload:

```csv title="ledger.csv"
account,budget,actual
Revenue,120000,131500
Cost of goods sold,48000,55200
Salaries,36000,36400
Marketing,9000,14100
Software,4000,3900
Travel,3000,1200
```

</Step>
<Step>

## Give the Agent the job

```bash
stigmer run variance-reporter --attach ledger.csv --download ./out -m "Review this quarter's ledger."
```

`--attach` hands the ledger to the Agent with the message. The Agent's reply
streams into your terminal while it works, and when it finishes, `--download`
saves what it handed back into `./out`.

</Step>
<Step>

## Open the report

```bash
cat out/variance-report.md
```

The Agent wrote this file. Its words differ from run to run, but it reads
something like this:

```md
# Q3 variance report

Revenue came in 9.6% over budget. Cost of goods sold and marketing ran well
over, and travel well under.

| Account            | Budget  | Actual  | Variance | %      | Flag  |
| ------------------ | ------- | ------- | -------- | ------ | ----- |
| Marketing          | 9,000   | 14,100  | +5,100   | +56.7% | Over  |
| Travel             | 3,000   | 1,200   | -1,800   | -60.0% | Under |
| Cost of goods sold | 48,000  | 55,200  | +7,200   | +15.0% | Over  |
| Revenue            | 120,000 | 131,500 | +11,500  | +9.6%  |       |
| Salaries           | 36,000  | 36,400  | +400     | +1.1%  |       |
| Software           | 4,000   | 3,900   | -100     | -2.5%  |       |
```

</Step>

## What just happened

You gave an Agent a job and it handed back a file. Stigmer started a Session (a
conversation) on your Agent, put the ledger where the Agent could read it, and
ran the turn on your model key. The Agent saved its report in its outputs
folder, and Stigmer returned it as a file of that Session. `--download` fetched
it, the same way your product will fetch it for a customer.

The terminal was only the way in. The CLI made the same calls your product's
code can make, which is the next page.
