## What you'll build

A running AI Agent on your machine. You'll install Stigmer, define an Agent in
YAML, and talk to it from your terminal. Everything stays local—the server uses
SQLite and connects to your own LLM provider.

**Time**: ~5 minutes **Prerequisites**: macOS or Linux, an
[Anthropic API key](https://console.anthropic.com/)

<Callout type="info">
  Want managed cloud instead? See the [Cloud
  Quickstart](/docs/getting-started/quickstart).
</Callout>

## Install Stigmer

<Tabs items={["Homebrew", "Shell script", "npm"]}>
  <Tab value="Homebrew">```bash brew install stigmer/tap/stigmer ```</Tab>
  <Tab value="Shell script">
    ```bash curl -fsSL https://stigmer.ai/install.sh | sh ``` No prerequisites —
    the installer bundles its own Node.js runtime under `~/.stigmer`.
  </Tab>
  <Tab value="npm">
    ```bash npm install -g @stigmer/cli ``` Requires Node.js 22.13 or newer.
  </Tab>
</Tabs>

Verify the installation:

```bash
stigmer version
```

</Step>
<Step>

## Start the server

```bash
stigmer server
```

On first run, Stigmer asks for your Anthropic API key — local agents run on
Claude models, and the best current model is picked for you automatically. If
`ANTHROPIC_API_KEY` is already set in your shell, it's used without prompting.

Once configured, the server starts. You'll see:

```
Web console available at http://localhost:8234
```

Leave this terminal running and open a new one for the next steps.

<Callout type="info">
  Run `stigmer server setup` at any time to update your API key.
</Callout>

</Step>
<Step>

## Create your Agent

Create a file called `agent.yaml`:

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Agent
metadata:
  name: my-first-agent
spec:
  instructions: |
    You are a helpful assistant. Answer questions clearly
    and concisely. When you don't know something, say so.
```

Apply it to the server:

```bash
stigmer apply -f agent.yaml
```

</Step>
<Step>

## Run it

```bash
stigmer run my-first-agent -m "What can you help me with?"
```

The Agent responds in your terminal. You defined an Agent as a YAML resource,
applied it to the local server, and ran it—all from the command line.

</Step>
</Steps>

## What just happened

Stigmer treats Agents as **declarative resources**. You described what the Agent
should do in a YAML file, applied it to the server, and ran it. The same pattern
works for Skills, MCP Servers, and every other Stigmer resource.

Your local server also runs a web console at
[`http://localhost:8234`](http://localhost:8234). The next tutorials use this
console to create Skills, connect tools, and build Agents — the same experience
as Stigmer Cloud, running on your machine.

Right now your Agent gives generic answers. It doesn't know anything specific to
your business. The next tutorial fixes that.

import { Stigmer } from "@stigmer/sdk";

<Tab value="Go">

```bash
mkdir stigmer-quickstart && cd stigmer-quickstart
go mod init stigmer-quickstart
go get github.com/stigmer/stigmer/sdk/go/v3
```

Create `main.go`:

```go
package main

import (
	"context"
	"fmt"
	"io"
	"log"
	"time"

	stigmer "github.com/stigmer/stigmer/sdk/go/v3"
)

func main() {
	client, err := stigmer.NewClient(
		stigmer.WithBaseURL("localhost:7234"),
		stigmer.WithInsecure(),
	)
	if err != nil {
		log.Fatal(err)
	}
	defer client.Close()
```
