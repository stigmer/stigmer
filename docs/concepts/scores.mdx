Reading a whole conversation is the only way to know whether an Agent did a good
job, and what you decide is lost the moment you close the tab. A **Score**
writes it down. Each [run](/docs/concepts/agents#blueprint-vs-runtime) that
completes can carry scores, and anyone who can see the run sees them.

A run carries up to three kinds of score:

- **Feedback**: a person's thumbs up or thumbs down on the final answer, with an
  optional comment. For example, Priya marks last night's triage run "down:
  picked the wrong label".
- **Run health**: a free check Stigmer runs on its own as soon as a run
  completes. It asks no AI model, so it costs nothing.
- **AI grading**: an AI judge's verdict on whether the run did its task and made
  nothing up, for Agents whose maintainers switch it on.

## Feedback

Under the Agent's final answer in the console there are thumbs up and down and a
comment box (500 characters at most). Each person rates a run once; rating again
changes your rating rather than adding a second one. Only you can change your
rating, and you can delete it.

Only a completed run can be rated. A run that failed or was cancelled has no
final answer to judge.

## Run health

When a run completes, Stigmer checks it for three things:

| Check                         | Flags a run when                                                                                                        |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `no-repeated-calls`           | The Agent called the same tool with the same inputs and got the same result three or more times in a row: it was stuck. |
| `last-action-succeeded`       | The run completed, but its last tool call failed or was interrupted.                                                    |
| `structured-output-delivered` | The run was asked for an answer in a fixed shape and gave none.                                                         |

A check that does not apply to a run (a run that called no tools, or one not
asked for a fixed shape) is marked not applicable. The run passes when every
check that applies passes. A run with a problem shows a flag that opens to the
reason, for example "ended on a failed action: create_ticket (step 7)". A reason
is built from counts, tool names and step numbers, and never quotes what anyone
typed.

Run health is graded shortly after the run completes, so a score can appear a
moment after the final answer does. If grading cannot run, the run's score says
**not graded** with the reason. A run that could not be graded never reads as a
failure.

Each run-health score records the version of the checks that produced it, so
results from a later version of the checks are never mixed with earlier ones.

## AI grading

An AI judge reads a finished run and answers two standard questions:

| Rubric            | Fails a run when                                                                                                                    |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `did-the-task`    | The final answer does something other than what was asked, or only part of it without saying so.                                    |
| `made-nothing-up` | The answer claims an action, outcome or fact that the run's own tool calls do not show. Not applicable when it makes no such claim. |

Each rubric passes, fails or does not apply, with a reason. The run passes when
no rubric fails. For example, Priya's triage Agent finishes a run, the run shows
**Judge: grading…**, and a minute later **Judge: 1 of 2 failed**, which opens to
"said the ticket was assigned, but the assign call failed" and the model that
graded it.

AI grading is off until someone who can edit the Agent switches it on in the
Agent's **Quality** tab. There they choose:

- **How many runs to grade**: one in N runs, from every run to one in a hundred.
  Which runs are picked is fixed by each run's id.
- **A monthly limit**: the most grading may spend in a calendar month (UTC), in
  US dollars of estimated model cost. Each grade sets aside its maximum cost,
  $0.25, before it starts, so a limit below $0.25 grades no run.
- **The judge's model**: the platform's default unless you pick one.

The judge's cost is charged to the Organization the run belongs to, as a run of
its own, never to the graded run. When the limit is reached or the Organization
is out of credit, the run says **not graded: spending limit reached** or **not
graded: out of credit**, and the Quality tab shows the same reason. A run that
could not be graded never reads as a failure. The tab also shows this month's
spend and how many runs were graded.

In Stigmer Cloud the judge acts as a system account of the Organization. On a
self-hosted Stigmer with sign-in, it acts as the person who switched grading on,
and grades only the runs that person can see: a run they cannot see says **not
graded: grading cannot act for this agent**.

The judge sees the run's request, its tool calls and its final answer, and has
no tools of its own: it cannot act on what it reads. Its instructions and the
rubrics are Stigmer's, the same in every Organization, and each judge score
records their version. The judge's own conversation is deleted as soon as the
grade is recorded.

A run's text can still try to sway the judge, so treat a grade as a signal to
look closer, not a final verdict.

## Who sees scores

Scores follow the run. Whoever can see the run sees all of its scores:

- the person who owns the conversation;
- the people it is shared with;
- the reviewers of a channel conversation, such as an Agent connected to Slack.

Nobody else does. An Organization's admins do not see the scores of a personal
conversation, just as they do not see the conversation itself. The owner of the
conversation can delete any score on it. Scores are deleted with their run, with
the conversation, and with the Organization.

The console shows scores to people working in it. Pages built for someone else's
product, such as an embedded chat or a share link, show none.

## Reading scores from the CLI

```bash
# Each person's thumbs, the run-health checks and the judge, one row per score
stigmer runs scores run_01abc123

# The same scores as JSON, for a script
stigmer runs scores run_01abc123 -o json

# One score by its id
stigmer get score scr_01abc123

# An Agent's AI grading settings by the evaluator's id, and switching it off
stigmer get evaluator evl_01abc123
stigmer delete evaluator evl_01abc123
```
