If you built on Claude Managed Agents, most of what you know carries over.
Agents, Environments, Sessions and their events keep their names in Stigmer, an
Environment takes Managed Agents' fields as they are, and code that reads a
session's events with Anthropic's SDK reads a Stigmer Session's the same way.
This page maps each Managed Agents idea to its Stigmer counterpart, and says so
plainly where Stigmer has none.

## What carries over in your code

Your Environment definitions carry over field by field. Code that lists, follows
and answers a session's events with Anthropic's SDK works against a Stigmer
Session the same way: Stigmer serves those events on Managed Agents' own paths,
and [Use Anthropic's SDK](/docs/sdk/managed-agents) says how to point the SDK at
Stigmer and which events Stigmer writes differently. Sessions themselves are
created through Stigmer's API or its console, not Anthropic's SDK.

## What Stigmer adds

Beyond the counterparts above, Stigmer:

- gives each of your customers an Organization of their own, on the editions
  that include it
  ([Give each customer their own organization](/docs/getting-started/one-organization-per-customer));
- puts an Agent in front of people through a chat link, Slack or WhatsApp
  ([Channels](/docs/concepts/channels));
- shares each Agent, Skill and conversation with roles you know from Google
  Drive or GitHub ([Sharing and access](/docs/concepts/sharing-and-access));
- runs whole on your own servers, the control plane and the session history as
  well as the agent's computer
  ([Self-hosting](/docs/guides/self-hosting/overview));
- lets each Session choose its engine, Stigmer's own or Cursor's
  ([Harnesses](/docs/concepts/harnesses));
- installs plugins in the format Claude Code, Cursor and Codex already use
  ([Plugins](/docs/concepts/plugins)).
