## Overview

Stigmer Cloud charges for the platform, never for tokens. Your Organization is
on a plan, and a paid plan costs a flat monthly fee that Stripe invoices to the
card on file. Every model call your Agents make runs on your Organization's own
provider key, on every plan, so your model provider bills those calls to you
directly and Stigmer adds nothing to them.

Self-hosted Stigmer (open source) has no billing; see
[Self-hosting](#self-hosting).

## Plans

| Plan     | Monthly fee                                          | Includes                                                                     |
| -------- | ---------------------------------------------------- | ---------------------------------------------------------------------------- |
| Free     | $0                                                   | Channels and sharing                                                         |
| Team     | $99                                                  | Teams, channels and sharing, with email support                              |
| Business | $499, plus $25 for each child organization past five | Everything in Team, child organizations for your customers, priority support |

Every Organization starts on Free and stays there until an admin picks a paid
plan in **Settings → Billing**. Picking a paid plan needs a saved card, which
the same page asks for. A
[child organization](/docs/guides/authentication/federation/child-organizations#billing)
runs on its parent's plan and has no plan or invoice of its own.

### How a plan is invoiced

A paid plan runs in monthly billing periods from the day you subscribe. At the
end of each period, Stripe invoices the period's fee and charges it to your
Organization's saved card, with tax added where it applies. The invoice has the
plan's fee and, on Business, a line for the child organizations past the five
the plan includes. It never has a line for model usage.

- **Changing plans** takes effect at once: the current period ends and a new one
  starts on the new plan, and each part of the month is billed on the plan it
  ran on, prorated by its length.
- **Canceling** keeps the plan until the end of the period you've paid for; then
  the Organization returns to Free.
- **A failed payment** keeps the plan while Stripe retries the card. If Stripe's
  retries end without a payment, the Organization returns to Free.

Your card and your past invoices are managed through the **Stripe Customer
Portal**, opened from **Settings → Billing**, where you can add, update or
remove a card without leaving the Stigmer billing flow.

## Model calls run on your own keys

Every model call a native Agent run makes runs on your Organization's own
Anthropic or OpenAI key, or on your own compatible endpoint, on every plan. An
admin adds the keys in **Settings → Provider keys**. Cursor-harness runs work
the same way, on your Organization's own Cursor key, and Cursor bills them to
that key's plan. Stigmer never runs a model call on a key of its own.

A run whose model needs a provider your Organization has no key for is refused
before it starts. This holds for every run, including evals, AI grading, shared
Agents and channels, which all run on the keys of the Organization that owns the
Agent. See [Model provider keys](/docs/guides/integrations/model-provider-keys).

## The model catalog

The model catalog lists every model Stigmer supports, with each provider's list
prices: the same numbers as on the providers' own pricing pages. Stigmer never
marks them up and never charges them; they're there so that every edition can
estimate what a run costs and stop it at your cost cap (see
[Set a cost cap](#set-a-cost-cap)).

Stigmer Cloud keeps the catalog as an audited revision history and serves the
current version publicly at `/api/v1/public/model-registry`. Self-hosted Stigmer
servers ship with a bundled copy and refresh it from that endpoint every hour
when they have connectivity, so local model pickers stay current without
upgrades. Air-gapped installs keep the bundled copy; set
`STIGMER_MODEL_REGISTRY_REFRESH=off` to turn the refresh off.

## Optimizing your costs

What your Agents spend on models is provider token cost, on your own provider
bill: your model provider's for native runs, Cursor's for Cursor runs. The
biggest savings come from sending fewer tokens, reusing cached ones, and
matching the model and harness to the job. The levers below are ordered by
impact.

### Reuse the prompt with caching

Anthropic models bill cached prefix tokens at a fraction of the normal rate: a
**cache read costs about one-tenth of the input rate**, and a **cache write
about 1.25× input**. Re-reading a stable prefix (system instructions, Skills,
earlier turns) therefore costs about **90% less** than sending it fresh, and the
advantage compounds as a Session grows.

- **Native** gives you explicit control: the harness sets cache breakpoints on
  the stable prefix, and every follow-up turn re-reads it.
- **Cursor** caches automatically and opaquely — you benefit without configuring
  anything, but with less control over what is cached.

Keep the stable part of your prompt (instructions, Skills) first and the
variable part (the user's message) last, so the cacheable prefix stays constant
across turns.

### Pick the harness for the job

Neither harness carries a Stigmer charge, so harness choice is about
**capability and cost**. On Cursor Teams plans, Cursor adds a small per-token
fee, the **Cursor Token Rate**, to non-Auto requests, billed to the plan of the
key the run uses; Auto and the Composer pool are exempt.

| If you need…                                | Prefer | Why                                                            |
| ------------------------------------------- | ------ | -------------------------------------------------------------- |
| The lowest cost on a given model            | Native | Your provider's own rate, with no Cursor token rate            |
| The widest model catalog or a cheaper model | Native | All supported providers; downgrade the model for simple tasks  |
| Built-in coding tools (edit, shell, search) | Cursor | The tooling is worth the added per-call context and token rate |

Reach for Cursor when you want its coding tooling — not as a default, since a
Cursor model that carries the token rate is cheaper to run on native. See
[Harnesses](/docs/concepts/harnesses) for the full capability comparison.

### Match the model to the task

Within a harness, model choice is usually the largest single lever — premium
models can cost an order of magnitude more per token than economy ones. Use a
small, cheap model for routine work (classification, short replies, summaries)
and reserve premium models for genuinely hard reasoning. The
[model catalog](#the-model-catalog) lists each model's provider list price. Set
the model once in the Agent's
[run settings](/docs/concepts/agents#run-settings), and every conversation on it
starts there.

### Manage Session and turn length

A Session resends its accumulated context on every turn, so cost grows with
conversation length:

- Start a fresh Session for an unrelated task instead of extending a long one.
- Attach only the Skills and tools a Session needs — every attached Skill is
  tokens on every turn.
- Lean on caching so the growing prefix is re-read cheaply rather than re-billed
  at full rate.

### Set a cost cap

Every run spends on your own provider accounts (Anthropic, OpenAI or Cursor), so
set budgets there too. Within Stigmer, a cost cap on each run (`max_cost_usd` in
an Agent's [run settings](/docs/concepts/agents#run-settings)) stops a message
once its estimated cost, at the catalog's list prices, reaches the cap. A
channel or a share can lower that cap for the conversations it carries, never
raise it, and an eval takes a spending limit of its own (`max_cost_usd` on the
eval).

## Self-hosting

Stigmer is fully open source under Apache 2.0. When you self-host, there is no
billing — you pay your own LLM provider costs directly. Billing only applies
when using Stigmer Cloud at [`app.stigmer.ai`](https://app.stigmer.ai).
