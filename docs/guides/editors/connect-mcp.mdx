There are two ways to give an AI tool Stigmer, and one question decides which
fits: **does your agent have a terminal?**

- **Yes: Claude Code, Codex, Cursor.** Install
  [Stigmer's plugin](#the-plugin-for-coding-agents). It answers any question
  about Stigmer from these docs, sets Stigmer up for your project, and builds,
  runs and ships your agents. It works on any Stigmer the command line reaches:
  Stigmer Cloud, your own server, or `stigmer up` on your machine.
- **No: Claude Desktop, claude.ai.** Add
  [the hosted connector](#the-hosted-connector-for-apps-without-a-terminal) at
  `https://mcp.stigmer.ai`. It reaches Stigmer Cloud, and you sign in through
  the browser.

Both give the assistant the same tools: searching your Agents and Skills,
reading these docs, creating and running Agents, and reading what their runs
did.

## The plugin, for coding agents

The plugin is one folder that Claude Code, Codex and Cursor each read. It
brings:

- **Skills**, the instructions your coding agent follows for each job: answering
  questions from the live docs and citing the page, setting Stigmer up,
  designing and running agents, putting them in your product, and running your
  own server and organization.
- **Stigmer's tool server**, `stigmer mcp-server`, started from the
  [command line](/docs/cli/commands/mcp-server) on its own sign-in. Nothing to
  paste: the plugin acts on whichever Stigmer you signed the command line in to.
- **A guard**, in Claude Code: it asks you before anything that can't be undone
  or is yours to give (deleting an Agent or Skill, cancelling a run, answering a
  run's approval), even after you allowed the plugin's tools. In Cursor it asks
  before a `stigmer` command forced past its own question or one that answers a
  run's approval, and Cursor's own tool approval asks before the plugin's tools.
  Codex asks from the tools' own marks.

It needs the command line, signed in:

```bash
npm install -g @stigmer/cli
stigmer auth login
```

`stigmer up` starts a local Stigmer instead, with no sign-in.

<Tab value="Claude Code">

```bash
claude plugin install stigmer --marketplace stigmer/coding-agent-plugin
```

Inside Claude Code, `/plugin` lists it once the marketplace is added.

</Tab>
<Tab value="Codex">

```bash
codex plugin marketplace add stigmer/coding-agent-plugin
codex plugin add stigmer@stigmer
```

</Tab>

```bash
git clone https://github.com/stigmer/coding-agent-plugin ~/.cursor/plugins/local/stigmer
```

</Tab>

Then ask for what you want, in plain words: "how do I give our CI a key that can
run agents but not change them?", "run invoice-checker on this file", "set up
Stigmer for this project".

<Callout type="info">
  You don't need the plugin to start. [Set up Stigmer with your coding
  agent](/docs/getting-started/coding-agent) works from one pasted prompt, and
  the plugin keeps Stigmer in your coding agent afterwards.
</Callout>

## The hosted connector, for apps without a terminal

Stigmer Cloud runs the same tool server at `https://mcp.stigmer.ai`. An app that
can't run the command line, such as Claude Desktop, connects to it and signs in
through the browser. It reaches Stigmer Cloud (`app.stigmer.ai`) only; for your
own server, use the plugin, or run
[`stigmer mcp-server`](/docs/cli/commands/mcp-server) yourself.

In Claude Desktop:

1. Open **Settings → Connectors**.
2. Click **Add custom connector**.
3. Enter `https://mcp.stigmer.ai` as the URL and confirm.
4. Complete the browser sign-in when prompted.

Claude Desktop registers itself and obtains a token through Stigmer's OAuth
flow. Over the hosted connector, a file on your machine can't be attached to a
run; the command line's `stigmer run <agent> --attach` does that.

<Callout type="info">
  The OAuth flow signs you in through Stigmer's primary identity provider. If
  your organization brings its own identity provider, use [an API key in a
  header](#an-api-key-in-a-header) instead.
</Callout>

## An API key in a header

An editor that should reach Stigmer Cloud without the command line can send a
Stigmer API key with every call instead.

<Steps>
<Step>

## Get your API key

1. Open [`app.stigmer.ai`](https://app.stigmer.ai) and go to **Settings → API
   Keys**.
2. Click **New API key**, give it a name (for example, `my-editor`), and create
   it.
3. Copy the key and keep it somewhere safe. It is shown **only once** and starts
   with `stk_`.

<Callout type="warn">
  Treat your API key like a password. Never commit it to a repository or share
  it in plain text.
</Callout>

</Step>
<Step>

## Add the connector

Replace `stk_your_api_key` with the key you just created.

<Tabs items={["Claude Code", "Cursor"]}>
<Tab value="Claude Code">

Run this in your terminal (not inside the Claude Code prompt):

```bash
claude mcp add --transport http stigmer https://mcp.stigmer.ai \
  --header "Authorization: Bearer stk_your_api_key"
```

<Callout type="info">
  On Claude Code 2.1.1+ you can also use the JSON form:

```bash
claude mcp add-json stigmer '{"type":"http","url":"https://mcp.stigmer.ai","headers":{"Authorization":"Bearer stk_your_api_key"}}'
```

</Callout>

</Tab>
<Tab value="Cursor">

Create or edit `.cursor/mcp.json` in your repository (or `~/.cursor/mcp.json`
for all repositories):

```json
{
  "mcpServers": {
    "stigmer": {
      "url": "https://mcp.stigmer.ai",
      "headers": { "Authorization": "Bearer stk_your_api_key" }
    }
  }
}
```

Reload Cursor. The Stigmer connector appears in **Settings → MCP**.

</Tab>
</Tabs>

</Step>
<Step>

## Verify the connection

Ask your assistant to do something that requires Stigmer. For example:

```
List the agents in my Stigmer organization.
```

If the connector is wired up correctly, the assistant calls Stigmer and returns
your resources. In Claude Code you can also run `/mcp` to confirm `stigmer` is
connected.

</Step>
</Steps>

## What your assistant can make

When your assistant authors Skills and MCP servers to share, it writes a plugin:
the same folder Cursor, Claude Code and Codex read, with a `skills/` directory
and an `mcp.json`. Installing that folder on Stigmer is one command or one
upload — see [Install a plugin](/docs/plugins/install-a-plugin). An Agent it
applies can also carry MCP servers of its own in `mcp_servers`
([Give an agent its own MCP server](/docs/guides/integrations/connect-an-mcp-server#give-an-agent-its-own-mcp-server)).
