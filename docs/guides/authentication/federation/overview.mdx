title: Identity federation
description:
  Let users access Stigmer with their existing credentials. Choose between
  automatic JIT provisioning, explicit manual provisioning, or self-managed SSO.

Identity federation lets users access Stigmer with tokens issued by an external
authentication system. You register your auth provider as an Identity Provider,
and Stigmer trusts its tokens.

Federation supports three provisioning modes:

- **JIT provisioning** — Stigmer creates accounts and grants roles automatically
  when a user authenticates with a valid JWT. Your backend only registers the
  Identity Provider. Best for platforms where all authenticated users should
  have Stigmer access.
- **Manual provisioning** — Your platform backend creates federated accounts and
  grants roles via the API before users can authenticate. Best for platforms
  that need to control exactly who gets access and when.
- **Self-managed SSO** — Your team members sign in to the Stigmer web console
  through your Organization's Identity Provider. Accounts are created
  automatically on first login.

## When you need this

You're building a platform on Stigmer and your users already authenticate
through your own OIDC-compatible provider (Auth0, Okta, Entra ID, AWS Cognito,
or any custom OIDC server). You want those users to interact with Stigmer
Agents, Sessions, and other resources without a separate Stigmer login.

<Callout type="info">
  **Don't have an OIDC provider?** Use a
  [PlatformClient](/docs/guides/authentication/platform-client/overview)
  instead. Your backend mints Stigmer tokens per user — no Identity Provider
  registration or JWKS endpoint needed.
</Callout>

## What you'll build

By the end of this guide, your platform's users will call the Stigmer API using
JWTs from your auth provider. Stigmer validates each token, resolves the user's
identity, checks access, and processes the request — no separate Stigmer
credentials needed.

## Choose your provisioning mode

|                      | JIT (automatic)                               | Manual (explicit)                              | SSO                                  |
| -------------------- | --------------------------------------------- | ---------------------------------------------- | ------------------------------------ |
| **Who it's for**     | Platform API integrations                     | Platform API integrations                      | Self-managed Organizations           |
| **Account creation** | Automatic on first JWT                        | Your backend calls `createFederatedAccount`    | Automatic on first web login         |
| **Role assignment**  | Automatic (configurable role)                 | Your backend creates IAM Policies              | Automatic (viewer)                   |
| **Setup steps**      | Register IdP with JIT enabled                 | Register IdP, provision accounts, grant access | Register IdP with SSO enabled        |
| **Use when**         | All authenticated users should access Stigmer | You need gated, explicit access control        | Team members need web console access |

The setup and runtime differ by provisioning mode. With **manual provisioning**,
your backend performs all four steps above before users authenticate. With **JIT
provisioning**, your backend only registers the Identity Provider (step

1. — Stigmer handles steps 2 and 3 automatically when a user first
   authenticates. Step 4 is the same regardless of mode: present a JWT, Stigmer
   validates it against your Identity Provider's JWKS endpoint, resolves the
   caller to a federated account, and checks IAM Policies.

## Prerequisites

Before starting, you need:

- A **Stigmer Organization** (either self-managed or platform-managed)
- An **API key** with admin access to that Organization
- An **OIDC-compatible auth provider** with:
  - A JWKS endpoint URL (typically `https://your-domain/.well-known/jwks.json`)
  - The issuer URL (the `iss` claim value in your JWTs)
  - The audience value (the `aud` claim your provider puts in tokens intended
    for Stigmer)

## Self-managed SSO

If your Organization is self-managed and you want team members to sign in to the
Stigmer web console through your own Identity Provider, you can enable SSO.
Stigmer creates accounts automatically on first login and assigns a viewer role.

## Multi-tenant platforms

The steps above cover federation for a single Organization. If your platform
serves multiple customers and each customer needs isolated resources, you create
a separate Organization per tenant. With JIT provisioning and `tenantOrgClaim`,
Stigmer can automatically route users to their tenant Organization based on a
JWT claim.
