Stigmer Desktop manages runner processes on your machine. You can interact with
runners in three ways: from the Settings page inside the app, from the system
tray menu, and through `stigmer://` deep links triggered by the web console.

## Start a runner from the app

1. Open **Settings > Runners**.
2. Click **Start Runner**.
3. Choose a name (optional — the app generates one if you leave it blank) and a
   runtime (**native** or **Docker**).
4. Click **Start**.

The app starts the runner through its bundled CLI sidecar. Within a few seconds,
the runner appears in the list with a **Ready** phase badge. It is now connected
to the server and accepting executions.

<Callout type="info">
  The bundled CLI is the same `stigmer` binary you would use from the terminal.
  The desktop app runs it as a background process — you do not need to install
  the CLI separately.
</Callout>

## Start a runner from the browser

The web console can launch a local runner on your machine through a deep link.
When you click **Launch Local Runner** in the console, the following happens:

1. The web console asks the server for a short-lived **launch token**.
2. The browser opens a `stigmer://launch-runner?token=...` URL.
3. The operating system routes the URL to Stigmer Desktop (or launches it first
   if it is not already running).
4. The app exchanges the token for runner credentials and starts the runner
   through the CLI sidecar.
5. The runner connects to the server and begins sending heartbeats. A toast
   notification confirms the runner is active.

If the desktop app is not running when you click the link, the OS launches it.
The app queues the deep link until you are signed in, then processes it
automatically.

<Callout type="tip">
  The launch token is single-use and expires after 60 seconds. If the desktop
  app takes longer to start (cold launch on a slow machine), click **Launch
  Local Runner** again to generate a fresh token.
</Callout>

## System tray

When you close the Stigmer Desktop window, the app stays running in the system
tray. Your runners keep executing — nothing stops. Click the tray icon to see:

- A list of active runners with their name and phase
- **Stop All Runners** — sends a stop command to every running runner
- **Open Stigmer** — brings the main window back
- **Quit Stigmer** — stops all runners and exits the app

The tray gives you an at-a-glance status of your runners without opening the
full app.

## Notifications

Stigmer Desktop sends native OS notifications for runner lifecycle events:

| Event              | Notification                       | When                                       |
| ------------------ | ---------------------------------- | ------------------------------------------ |
| **Runner started** | "dev-macbook is now running"       | A runner finishes starting and connects    |
| **Runner stopped** | "dev-macbook has stopped (exit 0)" | A runner disconnects or is stopped         |
| **Runner error**   | "dev-macbook: connection refused"  | A runner encounters an unrecoverable error |

Notifications only fire when the Stigmer window is **not focused** — if you are
already looking at the app, you see the status change in real time and do not
need an alert.

## Stop a runner

You can stop a runner from three places:

- **Settings > Runners** — Open the action menu on a runner row and select
  **Stop**. The runner transitions to the Stopped phase.
- **System tray** — Click **Stop All Runners** to stop every active runner at
  once.
- **Web console** — Stop a runner from the web console's Settings > Runners
  page. The stop command reaches the runner through the server's command stream,
  regardless of whether the command came from the browser or the desktop app.

In all cases, the server sends a stop command through the bidirectional command
stream. The runner process shuts down gracefully, and the resource stays in the
Stopped phase. If you start the same runner again later, it reuses the existing
resource — the runner's identity persists across restarts.
