Stigmer is one platform that runs three ways:

- **Stigmer open source** is free under Apache 2.0. You run it yourself, on a
  laptop, one server or Kubernetes, for one Organization.
- **Stigmer Enterprise** is the same server with a license key, on your own
  infrastructure: many Organizations, Teams and invitations, federation with
  other identity providers, and the access history. Its code is public in the
  repository's `ee/` directory under the Stigmer Enterprise License, and running
  it in production needs an annual license.
- **Stigmer Cloud** is the managed service. Stigmer runs the platform for you,
  with hosted sign-in, channels, plans and billing, and the operations behind
  them.

The contracts are identical in all three. Your Agents, Skills, and the CLI and
SDKs that drive them work against each — moving between them is a configuration
change, not a rewrite. In every edition your Agents run on your own model
provider key: Stigmer runs no model of its own.

## The short answer

**Choose Stigmer open source if:**

- Your data or compliance posture requires everything on your infrastructure.
- You already operate Postgres and Docker (or Kubernetes) and want full control.
- One team uses the server, and your own OIDC provider handles sign-in.
- You want your model calls never to leave your infrastructure.

**Choose Stigmer Enterprise if:**

- Everything must stay on your infrastructure, and you need more than one
  Organization.
- You need Teams, invitations, per-resource sharing or the access history.
- People sign in through more than one identity provider you trust.

**Choose Stigmer Cloud if:**

- You want to build with Agents today, not operate a platform.
- You need multiple Organizations or per-resource permissions without running a
  server.
- You want Agents reachable in Slack and WhatsApp.
- You want a managed platform rather than operating infrastructure.

## What Stigmer open source includes

Open source is not a trial edition. The
[Docker Compose stack](/docs/guides/self-hosting/docker-compose) runs the
complete platform — the server, a real Temporal server, Postgres, and the runner
that executes your Agents — with durable state in volumes you own and back up.

- **The full platform contract.** Every Agent, Skill, Session, and MCP server
  capability works exactly as it does on Stigmer Cloud, through the same API,
  CLI, and SDKs.
- **Authentication on your terms.** Point the server at any OIDC provider you
  control — Keycloak, Okta, Auth0, Dex — give your automation a
  [service account](/docs/guides/authentication/service-accounts) and its API
  keys, and let your product's backend
  [mint tokens for its own users](/docs/guides/authentication/product-users)
  with an admin service account's key. See
  [Enable authentication](/docs/guides/self-hosting/authentication).
- **Your LLM relationships.** You bring your own provider API keys and pay
  providers directly. There is no Stigmer billing when you self-host — see
  [Billing](/docs/concepts/billing#self-hosting).
- **Sandbox isolation as configuration.** The server can start execution
  sandboxes through pluggable isolation drivers — local process, Docker, or
  Kubernetes. Isolation is off by default: the stock Docker Compose stack runs
  the runner as a single trust domain, as its setup guide states up front.
- **One Organization, one team.** Everyone who signs in joins it as a member.
  Owners and admins author Skills and Plugins, and Agents too; members run them,
  create Agents of their own while the Organization allows it (on by default),
  and make a routine for an Agent only when they may edit it; giving an Agent a
  chat link is an admin's act. Each person's Sessions, vault and API keys are
  their own. Roles are per Organization; there is no per-resource sharing, so a
  shared vault is shared with every member or with none. The server does not
  stop a signed-in person from creating a second Organization, but one is the
  shape open source is built for.

## What Stigmer Enterprise adds

Stigmer Enterprise is the open-source server with a license key, run from the
same [Helm chart](/docs/guides/self-hosting/kubernetes) or the Enterprise image,
on Postgres. A verified key turns on:

- **Many Organizations.** As many as the license allows, and the operator may
  list who may create one.
- **Teams and invitations.** Share an Agent, a Skill or another resource with a
  person or a Team, and invite people into an Organization.
- **Identity federation.** Trust the tokens of the platforms and identity
  providers you name, so their people reach Stigmer without separate accounts.
- **The [access history](/docs/guides/authentication/access-history).** Who gave
  whom access to what, and when, kept for as long as the operator sets.
- **Control over outbound addresses.** Which addresses the server may dial when
  it reaches a URL a person wrote.

Without a key, the Enterprise server is the open-source server exactly. When a
license ends, the server keeps every person, Organization and record and refuses
only growth until a renewed key is pasted. The chart's
[Enterprise settings](https://github.com/stigmer/stigmer/blob/main/deploy/helm/stigmer/README.md#stigmer-enterprise)
list each switch; a license key comes through
[Contact Sales](https://stigmer.ai/contact-sales).

## What Stigmer Cloud adds

Stigmer Cloud runs the same platform as Stigmer Enterprise, with its many
Organizations, Teams, sharing and
[identity federation](/docs/guides/authentication/federation/overview), and
layers on what only a managed, multi-tenant service has:

- **Hosted sign-in.** People sign in at app.stigmer.ai, with no identity
  provider of your own to run.
- **Channels.** Agents that talk to your users
  [in Slack and WhatsApp](/docs/guides/channels/connect-slack) — webhook
  delivery, provider apps, and outbound messaging are cloud infrastructure.
- **Model calls on your own keys, counted.** LLM calls route through the managed
  proxy on your Organization's own provider keys (or your own compatible
  endpoint), with every call's tokens counted and never priced; the provider
  bills you directly. See
  [Model provider keys](/docs/guides/integrations/model-provider-keys).
- **Plans and billing.** Free to start, then flat monthly plans; see
  [Billing](/docs/concepts/billing).
- **Someone else on call.** Upgrades, backups, scaling, and sandbox isolation
  are operated for you.

The boundary is deliberate: capabilities land in open source when a team
self-hosting Stigmer for itself needs them, in Stigmer Enterprise when a company
runs it for many teams of its own, and in Stigmer Cloud when they only exist
because Stigmer runs the platform as a service.

## Know the limitations

One honest caveat before you commit to self-hosting today:

- **Two production packagings, no operator.** [Docker Compose](./docker-compose)
  for one server and a [Helm chart](./kubernetes) for Kubernetes run Stigmer for
  real; `stigmer up` and the [all-in-one image](./all-in-one) are for building
  and trying it on a laptop. There is no operator for the stack itself, and
  nothing in it needs one.
