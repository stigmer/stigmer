A plugin carries its own test cases, in Claude Code's plugin-eval format (see
[Test a plugin with evals](/docs/guides/plugins/test-a-plugin-with-evals)). An
Agent that uses plugins can be measured on those same cases: each plugin's cases
run on **your Agent**, with its own instructions, Skills and subagents, so you
see how the Agent handles what each plugin was built for.

An **Eval Run** on an Agent runs the cases of every plugin the Agent uses,
several times each, on the Agent's own model or on the models you name. For each
plugin and each case you get the score and whether every try passed, and every
try is a real conversation. The eval run is stamped with the Agent's version, so
after you change the Agent's instructions you run it again and compare the two,
case by case: "the refund cases went from 0.8 to 1.0, the tracker cases stayed
at 0.9."

An eval run can also **compare a plugin**: each case runs on the Agent with the
plugin and without it, and you see the difference the plugin makes to your
Agent. Acme's support Agent uses a refund-policy plugin; comparing it answers
"does the Agent handle refunds better with the plugin than without it?". The
plugin compared may be one the Agent uses, or one it does not use yet.

An Agent has no test cases of its own: the cases stay in the plugins. An Agent
that uses no plugin has nothing to run until you compare one.

## What runs, and at which versions

The eval run runs the Agent at one version: its current version, unless you name
another by its tag or its version hash. Each plugin runs at the version the
Agent uses it at: the version the Agent's reference names, or, when it names
none, the version installed when the eval run starts. A compared plugin the
Agent does not use runs at its installed version. The eval run records each one.

Every try runs at those versions to the end of the eval run. Saving a new
version of the Agent, or updating a plugin, while the eval run runs does not
change the tries still to come: a try pins the Agent and every plugin it uses,
as an open conversation keeps the Agent version it started on.

Whose cases run: the compared plugin's when you compare one, else every plugin
the Agent uses. You can choose instead (`--cases-from`), among the plugins a try
loads: a case runs only with the plugin it was written for.

With no plugin compared, each case runs in one arm: the Agent with all its
plugins. With one compared, each case runs with the plugin and, unless you turn
the comparison off, without it, and gets a `Δ`, the difference between the two.
Without the plugin means without it anywhere in the turn: neither the Agent nor
any of its subagents loads it, and the try's run records what it loaded. A case
passes when its score reaches the threshold, 1.0 by default, and **pass^k**
tells you whether every one of its tries scored 1.0.

A plugin's cases were written for the plugin. On an Agent with its own
instructions, a case can fail because the Agent was told to do something else.
That is a finding about your Agent, and when a case does not apply to it, leave
the case out with the case filters (`--case`, `--tag`).

## The model, and the tools a try may use

With no model named, each try runs the Agent as it runs in a conversation: on
its own engine, model, speed tier, and thinking setting. A model named in the
case's own files is not used, and the case notes so.

When you name models, each case runs on each of them instead. A try that names a
model runs without the Agent's tier and thinking choices, as any conversation
that names a model does, so for the Agent as its users meet it, leave the model
to the Agent.

A try may use the tools its case grants within the format's read-only set, plus
the tools the eval run allows, within the Agent's own tool lists. That is the
rule of every eval run: the cases' checks were written for that setting, and no
try stops to ask for approval. So the Agent's Skills, its hand-offs to
subagents, and any other tool it works with run in a try only when the case
lists them or the eval allows them: name them in **Allowed tools**
(`--allow-tools Skill Agent`), and the case's notes name each tool it asked for
and did not get.

The MCP servers of the case's own plugin follow its mocks, as in an eval run on
a plugin. The servers of the Agent's other plugins, and the servers written in
the Agent's own `mcp_servers`, are off in that case's tries, unless the eval run
runs real servers: a try never acts through a connection its case did not mock.

## Start an eval run in the console

On the Agent's page, open the **Evals** tab. **Run evals** is shown to people
who can edit the Agent. It holds the models (none runs the Agent as it runs),
**Compare with a plugin** (none by default), whose cases run, tries per case,
the cost limit, and the allowed tools. An Agent that uses no plugin says where
cases live, and runs once you compare a plugin.

Each past eval run is listed with the Agent version it ran, the plugin it
compared, and its overall score. An eval run's results show one section per
plugin, with the plugin version its tries ran, each case's score, pass^k and
tries (with and without the compared plugin, and the `Δ`, when it compared one),
and every try links to its conversation. **Compare** puts two eval runs of the
Agent side by side, case by case, labelled with both Agent versions, and marks a
plugin whose version differs between the two, since a plugin updated between two
eval runs changes its cases' scores as well as the Agent does.

## Start an eval run from the CLI

Name the Agent, and a version after `@` when you want one other than its current
version:

```bash
stigmer eval run --agent support-desk
stigmer eval run --agent support-desk@v3
stigmer eval run --agent support-desk --cases-from refund-policy --runs 5
stigmer eval run --agent support-desk --plugin refund-policy
```

The command creates the eval run, follows it, and prints one table per plugin
and model, headed by the Agent's version and each plugin's version, the compared
plugin marked. `--plugin` names the plugin compared; `--cases-from <plugin>`,
repeated, chooses whose cases run. It takes the other options of an eval run on
a plugin (`--case`, `--tag`, `--runs`, `--model`, `--ablation`, `--threshold`,
`--max-cost-usd`, `--concurrency`, `--allow-tools`, `--judge-model`, `--mocks`,
`--real-mcp-servers`, `--allow-real-servers`, `--no-scaffold`, `--json`,
`--no-wait`); `--ablation none` keeps a compared plugin in one arm. The exit
codes are those of [`stigmer eval run`](/docs/cli/commands/eval).

```bash
stigmer eval cancel evr_01j9...
stigmer get eval-run evr_01j9...
stigmer delete eval-run evr_01j9...
```

Cancelling stops the tries in flight and keeps the results of the tries that
finished. Delete refuses an eval run that is still running; deleting one deletes
its tries' conversations, runs and scores, and deleting the Agent deletes its
eval runs.

`--json` writes the result file: the Agent and its version, the eval run's
totals, and one block per plugin, each in Claude Code's result-file shape for
that plugin's cases, so a script that gates on Claude Code's file reads
`plugins[i]` unchanged.

## Who sees an eval run, and who pays

The Agent's editors start, cancel, and delete its eval runs; comparing a plugin
the Agent does not use also takes being able to see that plugin. The Agent's
viewers in its own Organization read them. A viewer in a child Organization, who
can use a parent's shared Agent, does not see its eval runs: a try spends the
Organization's money and may act with its connections.

In Stigmer Cloud every viewer of the Agent in its Organization opens each try's
conversation, read-only. In self-hosted open source the tries belong to the eval
run's creator, and the Agent's other viewers read the eval run, its results and
each try's scores. Tries are kept out of the conversation lists, the Agent's own
included.

The Agent's Organization pays for every try and every AI-graded check, on its
own provider keys. A try is a run of the Agent, so it counts in the Agent's
usage. The vaults an eval run names are shared vaults, as on a plugin, and the
cost limit works the same way.
