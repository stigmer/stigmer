---
title: Install from a marketplace
description:
  Add Cursor's, Claude Code's, Codex's or your own plugin marketplace and
  install any plugin it offers by name.
---

A marketplace is a catalogue of plugins: a directory tree with a marketplace
file at its root that lists the plugins it offers and where each one lives in
the tree. Cursor, Claude Code and Codex publish theirs this way, and Stigmer
reads all three unchanged, plus its own. Once a marketplace is added, you
install any plugin it offers by name, and the plugin lands exactly as if you had
[pushed its folder](/docs/guides/plugins/install-a-plugin) yourself.

The official marketplace is built in. A fresh `stigmer up` installs its default
set, which is where the `assistant` Agent a new install answers with comes from.

## Add a marketplace

Point `stigmer marketplace add` at a public GitHub repository, as `owner/repo`
or as the URL a browser shows:

```bash
stigmer marketplace add cursor/plugins
```

```text
✓ Added marketplace 'cursor-plugins' (github.com/cursor/plugins), offering 79 plugins

  See what it offers with: stigmer marketplace show cursor-plugins
  Install from it with:     stigmer install cursor-plugins/<plugin>
```

The CLI reads the marketplace once before recording it, so a repository that is
not a marketplace is refused now rather than on your first install. The name it
is recorded under is the one the marketplace file gives itself; pass
`--name <name>` to choose your own. Pin a branch, tag or commit with
`owner/repo@ref`; without one, the repository's default branch is read.

A marketplace on your own machine is a directory:

```bash
stigmer marketplace add ./my-plugins
```

## See what it offers

```bash
stigmer marketplace show cursor-plugins
```

```text
✓ Marketplace 'cursor-plugins' offers 79 plugins

Marketplace
  Name         cursor-plugins
  Source       github.com/cursor/plugins
  Description  Official Cursor plugin marketplace: developer tools, framework rules, MCP integrations, and agent skills
  Owner        Cursor
  Format       .cursor-plugin/marketplace.json

Plugins
  - thermos@1.0.0  Keeps long-running agent sessions warm
  - github@1.0.0   GitHub repositories, issues and pull requests
  ...
```

`show` reads the marketplace's source every time (nothing is cached), so what it
lists is what the tree holds now. `stigmer marketplace list` is offline and
shows the marketplaces you have configured.

## Install a plugin

```bash
stigmer install cursor-plugins/thermos
```

```text
✓ Installed plugin 'thermos' (2 skills, 0 MCP servers, 1 agent)

Plugin
  ID           plg_01j9...
  Slug         thermos
  Version      1.0.0
  Digest       3f9a2c1e
  Format       Cursor plugin
  Size         12.4 KB
  Marketplace  cursor-plugins (github.com/cursor/plugins)

Installed
  Skills   thermos-warmup, thermos-checkin
  Agents   thermos
```

The plugin's folder is read from the marketplace's tree and pushed as one
archive, so `stigmer install cursor-plugins/thermos` and
`stigmer push plugin ./plugins/thermos` from a checkout of the same repository
produce the same plugin with the same digest. From here on, the plugin behaves
as [Install a plugin](/docs/guides/plugins/install-a-plugin) describes: the
Agent is `thermos`, its members are the plugin's to redefine, and
`stigmer delete plugin thermos` removes everything it installed.

A few forms of the ref:

```bash
# A bare name is searched across every configured marketplace;
# exactly one must offer it.
stigmer install thermos

# Pin the version the marketplace must offer; a different one refuses.
stigmer install cursor-plugins/thermos@1.0.0

# See what would install without pushing anything.
stigmer install cursor-plugins/thermos --dry-run

# Into another Organization, visible to the whole org.
stigmer --org my-org install cursor-plugins/thermos --visibility org
```

When two marketplaces offer the same name, the bare form refuses and names both,
so the answer never depends on the order you added them in. A path (`./thermos`)
is not a ref; install a folder with `stigmer push plugin`.

## What the server knows

Nothing. A marketplace is configuration on your machine, kept under
`marketplaces` in `~/.stigmer/config.yaml`; the server only ever receives the
plugin archive the CLI pushes from it. Two consequences follow:

- Nothing records which marketplace a plugin came from. A plugin is identified
  by its name in your Organization, so installing `thermos` from a second
  marketplace upgrades the `thermos` you installed from the first.
- Removing a marketplace (`stigmer marketplace remove cursor-plugins`) changes
  nothing on the server. The plugins you installed from it stay until you
  `stigmer delete plugin` them.

## The official marketplace and `stigmer up`

The official marketplace ships with the CLI: the `plugins/` tree of the Stigmer
repository when you run from a checkout, and the `@stigmer/plugins` package at
the CLI's own version otherwise, so the content a fresh install bootstraps with
matches the server that installs it. Its marketplace file names a `defaults`
list, and `stigmer up` installs those into the system Organization on every
start: a default that is already installed at the same content is skipped, one
whose content changed with a new CLI release is upgraded, so a second `up`
pushes nothing.

Today the default set is one plugin, `assistant`, the Agent a fresh install
answers with. `stigmer marketplace show stigmer` lists what the official
marketplace offers; `stigmer install stigmer/<name>` installs one of them into
your own Organization.

<Callout type="info">
  Upgrading a local stack that predates plugins retires the system content an
  older release installed: its Agents, Skills, MCP Servers and Workflows are
  removed, except any that one of your own Agents still references, and `stigmer
  up` reports what went and what it kept and why. `assistant` is then installed
  from the official marketplace under a new ID. Sessions and channels that were
  bound to the old `assistant` lose their Agent; start a new Session on the new
  one.
</Callout>

## Limits, stated

- A GitHub marketplace is read at the repository root, where every vendor keeps
  its marketplace file; private repositories are not supported.
- Entries whose `source` is a remote (a URL, another repository, an npm package)
  are listed under "Not offered" by `show` and cannot be installed; Stigmer
  installs from the tree it fetched.
- A marketplace is fetched on every `show` and `install`. Cursor's is about 5
  MB; a marketplace that is a whole repository (Codex's) is larger.
