---
title: The marketplace file
description:
  The four marketplace file dialects Stigmer reads, the one shape they reduce
  to, and what makes an entry installable.
---

A marketplace is a directory tree with a marketplace file at its root. Stigmer
reads four dialects of that file into one shape; this page is the contract. For
how to add a marketplace and install from it, see
[Install from a marketplace](/docs/guides/plugins/install-from-a-marketplace).

## Locations

Stigmer looks for the marketplace file in these locations, in this precedence,
and reads only the first it finds (a tree carrying two dialects' files describes
one catalogue twice):

| Location                           | Dialect     |
| ---------------------------------- | ----------- |
| `marketplace.json`                 | Stigmer     |
| `.claude-plugin/marketplace.json`  | Claude Code |
| `.cursor-plugin/marketplace.json`  | Cursor      |
| `.agents/plugins/marketplace.json` | Codex       |

The file is JSON, at most 1 MiB.

## The shape every dialect reduces to

| Field                   | Meaning                                                                                                                                                                                                        |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`                  | The marketplace's identifier: lowercase letters, digits, `.` and `-`, at most 64 characters. The default name `stigmer marketplace add` records it under, and the prefix in `stigmer install <name>/<plugin>`. |
| `description`           | One line about the catalogue. Stigmer's file carries it at the top level; Cursor's and Claude Code's under `metadata.description`; Codex carries none.                                                         |
| `owner`                 | `{ name, email, url }`, all optional.                                                                                                                                                                          |
| `plugins[]`             | The entries, in file order. Each has a `name` (the plugin name rule, unique in the file) and a `source`.                                                                                                       |
| `plugins[].description` | The catalogue's own one line for the entry; `stigmer marketplace show` prefers the plugin manifest's description when the entry has one.                                                                       |

A marketplace installs nothing by itself: every entry waits for someone to run
`stigmer install` or pick it in the console. A field that names entries to
install unasked, such as Codex's `policy.installation: INSTALLED_BY_DEFAULT` or
the `defaults` list older Stigmer files carried, is read past.

### Sources

A `source` names the plugin's directory relative to the marketplace root:
`thermos`, `./thermos`, `third_party/github/`, or `.` for the root itself.
Claude Code's `metadata.pluginRoot` is prepended to every relative source;
Codex's `{ "source": "local", "path": "./thermos" }` object is the same
directory. A source may not be absolute, contain `..` or a backslash, or use a
glob.

Every other form (a URL, Claude Code's `github`, `url`, `npm` and `git-subdir`
objects, Codex's non-`local` sources) names a remote Stigmer does not fetch. The
entry is dropped with a warning and listed under "Not offered"; nothing is
invented in its place.

## What makes an entry installable

An entry is offered when its directory exists in the tree and holds a plugin
manifest at its root (`plugin.json`, `.claude-plugin/plugin.json`,
`.cursor-plugin/plugin.json` or `.codex-plugin/plugin.json`). An entry whose
directory is missing, or whose directory is not a plugin, is dropped with its
own warning. The plugin itself is then read exactly as
[`stigmer validate -f`](/docs/cli/commands/validate) reads a folder, so an entry
that validates installs.

## Two error postures

A broken marketplace **file** refuses the whole marketplace: it cannot be read,
has no `name` or no `plugins`, lists two entries with one name, or names a
source that escapes the tree. A catalogue that cannot be trusted as a whole is
not offered at all, and the refusal lists every problem at once.

An **entry** that cannot be installed is dropped with a warning, and the rest of
the marketplace stands: a public catalogue of eighty plugins with one bad entry
still offers seventy-nine. A marketplace's own test suite should assert zero
warnings so its publisher hears about the one.

## Stigmer's own file

```json
{
  "name": "stigmer",
  "description": "Stigmer's official plugin catalogue.",
  "owner": { "name": "Stigmer", "url": "https://stigmer.ai" },
  "plugins": [
    { "name": "linear", "source": "./linear" },
    { "name": "thermos", "source": "./thermos" }
  ]
}
```

Descriptions of the plugins come from each plugin's own manifest at read time,
so nothing is written twice. The official marketplace lives at `plugins/` in the
Stigmer repository and is published as `@stigmer/plugins` at every release; a
marketplace you publish for your own team can use the same file at the root of
any repository or directory.
