The tool library is a curated catalog of MCP servers that your Agents can use.
Each entry is a vetted integration — GitHub, PostgreSQL, Slack, Stripe, and
dozens more — ready to connect in a single action. This guide walks through the
marketplace-to-connected-tools process.

<Callout type="info">
  New to tools in Stigmer? Start with the [Tools concept
  page](/docs/concepts/tools) for the foundational model before following this
  guide.
</Callout>

## Browse the tool library

The Library section of the web console shows your MCP servers in a card grid.
Each card displays the server's name, a short description, and the Organization
it belongs to. Public servers from the curated catalog appear alongside any
custom servers your team has created.

The catalog organizes servers into categories:

| Category                 | Examples                          |
| ------------------------ | --------------------------------- |
| **Developer tools**      | GitHub, GitLab, filesystem        |
| **Databases**            | PostgreSQL, MongoDB, Redis, MySQL |
| **Communication**        | Slack, Linear                     |
| **Search**               | Fetch, Brave Search               |
| **Cloud infrastructure** | AWS, Cloudflare, Terraform        |
| **Web automation**       | Playwright                        |
| **Monitoring**           | Sentry                            |
| **Payments**             | Stripe                            |
| **Design**               | Figma                             |
| **Productivity**         | Notion, Google Maps               |

Each server definition includes tags for search and filtering, a link to its
source repository, and the transport type — stdio (local process) or HTTP
(remote service). You can inspect the implementation before connecting.

## Connect an MCP server

When you open a server's detail view and click **Connect**, Stigmer performs
three steps in a single action:

1. **Discovers tools** — Connects to the live server and enumerates every tool
   it exposes, capturing names, descriptions, and input schemas.
2. **Classifies approval policies** — A lightweight model evaluates each tool to
   determine whether it should run automatically or require human approval.
3. **Stores the results** — Discovered tools and their approval classifications
   are saved on the MCP Server's status, ready for any Agent that references it.

The whole process takes a few seconds. When it finishes, the detail view updates
to show the discovered tools and their approval policies.

## What changes after connecting

### Tools tab

The tools tab lists every tool the server exposes. Each entry shows the tool's
name and description — the same information the Agent sees when deciding which
tool to call. In the demo above, PostgreSQL exposes five tools: `query`,
`list_tables`, `describe_table`, `explain_query`, and `execute_sql`.

### Policies tab

The policies tab shows the approval classification for each tool. Read-only
tools like `query` and `list_tables` are classified for automatic approval — the
Agent can call them without pausing. Tools with side effects, like
`execute_sql`, are flagged for human approval.

These classifications come in two tiers:

- **Pinned approvals** are set by the server author in the MCP Server
  definition. They never change on reconnect.
- **Classified approvals** are generated by the classifier each time you
  connect. New tools are classified automatically.

Pinned policies always take precedence. You can override any classification by
editing the MCP Server definition or adding `tool_approval_overrides` on your
Agent.

## Authentication patterns at a glance

Some servers need credentials to reach the systems behind them. Three patterns
cover the range:

| Pattern                   | When it applies                                                      | What happens on Connect                                        |
| ------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------- |
| **No credentials**        | The server works without authentication (Fetch, Playwright)          | Connects immediately — no extra steps                          |
| **Environment variables** | The server uses API keys or connection strings (PostgreSQL, MongoDB) | You enter the value in the credential form before connecting   |
| **OAuth**                 | The server uses OAuth with a vendor like GitHub, Slack, or Figma     | Stigmer redirects you through the OAuth flow to obtain a token |

<Callout type="info">
  OAuth patterns — including automatic discovery (DCR) and vendor-specific flows
  — are covered in depth in the [OAuth for
  tools](/docs/guides/integrations/oauth-for-tools) guide. Organization-level
  credential overrides are in [Bring Your Own OAuth
  App](/docs/guides/integrations/bring-your-own-oauth).
</Callout>

## Wire tools to your Agent

Once an MCP server is connected, reference it from your Agent definition using
`mcp_server_usages`:

```yaml
spec:
  mcp_server_usages:
    - mcp_server_ref:
        kind: mcp_server
        slug: mcp-server-postgres
      enabled_tools:
        - query
        - list_tables
        - describe_table
```

Each usage entry controls which tools the Agent can call. An empty
`enabled_tools` list means all discovered tools are available. You can also add
`tool_approval_overrides` to customize approval behavior per Agent.

For a hands-on guide to wiring tools to an Agent and running a Session, see the
[Connect your tools](/docs/getting-started/connect-tools) tutorial.
