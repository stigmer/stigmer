  Author, run, and operate Stigmer Workflows — declarative pipelines that
  orchestrate AI tasks, tool calls, branching, loops, and human approvals.
---

A Workflow is a declarative pipeline that orchestrates a sequence of tasks — LLM
calls, Agent invocations, HTTP and gRPC requests, branching, loops, and
human-in-the-loop approvals — into a single repeatable automation. Workflows are
defined in YAML and run on Stigmer's Temporal-backed Workflow Runner.

If you're new to the underlying model, start with the
[Workflows concept page](/docs/concepts/workflows). For a hands-on introduction,
follow the [Workflow Quick Start](/docs/getting-started/first-workflow).

## The Workflow journey

These guides follow the lifecycle of a Workflow:

1. **Author** the Workflow YAML — see
   [Workflow Authoring](/docs/guides/workflows/authoring).
2. **Compose tasks** from the available task types — see
   [Task Types](/docs/guides/workflows/task-types).
3. **Apply proven patterns** for common automations — see
   [Workflow Patterns](/docs/guides/workflows/patterns).
4. **Run and operate** executions in production — see
   [Workflow Execution](/docs/guides/workflows/execution).
