determines the shape of `task_config` and what the task does at runtime. This
page groups all 20 task types by category; each card links to a full reference
with configuration fields, YAML examples, and output shapes. For general task
structure (`name`, `export`, `flow`), see the
[Authoring Guide](/docs/guides/workflows/authoring#defining-tasks).

## Choosing between similar tasks

Several task types overlap at the edges. These are the distinctions that matter:

- **`llm_call` vs `agent_call`** — `llm_call` for stateless, tool-free LLM work;
  it is faster and cheaper. `agent_call` when the step needs tool access,
  Skills, MCP servers, or multi-turn autonomy.
- **`eval` vs `validate` vs `llm_call`** — `eval` for systematic quality
  assessment with an LLM judge. `validate` for schema and structural checks.
  `llm_call` for freeform analysis.
- **`transform` vs `set_vars`** — `transform` for structured data reshaping with
  JQ, JSONata, or templates. `set_vars` for simple variable assignment.
- **`notification` vs `human_input` vs `emit_event`** — `notification` for
  fire-and-forget messages to humans. `human_input` when you need the recipient
  to respond before the workflow continues. `emit_event` for machine-to-machine
  event routing.
