---
title: Create a chat link
description:
  Give an Agent a hosted chat page — for your Organization's members, or for
  anyone with the link — and embed it on your own site.
---

A chat link gives your Agent a hosted chat page. It is one of the Agent's
[channels](/docs/concepts/channels), beside Slack and WhatsApp. You choose who
can use it: only signed-in members of your Organization, the default, or anyone
with the link (no Stigmer account needed). This guide shows you how to create a
chat link, pick the audience, send the link, and embed the chat on your own
website.

A chat link lets people chat with the Agent. Who may see how the Agent is set up
or change it is a separate setting, **Manage access** on the Agent:
[Sharing and access](/docs/concepts/sharing-and-access) explains both.

<Callout type="warn">
  Public links can be forwarded and indexed by search engines. Only give an
  Agent a public link when its knowledge is safe to show to anyone on the
  internet — for internal knowledge, use the **Organization members** audience.
</Callout>

## Create a chat link

You must be an admin of the Agent's Organization to create a chat link. A chat
link runs the Agent on the Organization's provider keys for anyone who holds it,
so it is an admin-level decision; members who can edit the Agent but are not
admins do not see **Add channel** or **Create a chat link**.

1. Open your Agent in the web console under **Library → Agents**.
2. Open the **Channels** tab.
3. Click **Add channel → Chat link** (on a tab with no channels yet, **Create a
   chat link**), keep the suggested name and slug (or pick your own), and
   confirm.

The link is live the moment you create it. It names the chat link by its
permanent ID:

```
https://app.stigmer.ai/chat/chn_01j9z3k8f2q4m6n7p8r9s0t1v2
```

A link made before chat links became channels carries an `ash_` ID instead, and
keeps working. Because the link carries only the ID, renaming your Organization
never breaks it, and nobody who later takes your Organization's old name can
take the link over. The slug names the chat link inside your Organization — in
its manifest and the API — and is not part of the link. It defaults to the
Agent's slug. Click **Copy** to copy the link, or **Open** to try it yourself.

## Manage chat links

The **Channels** tab lists every chat link of the Agent you can see, with its
link, audience, and status, beside the Agent's Slack and WhatsApp channels. An
Agent can carry several chat links — say, one for your docs site and one for a
partner — and each is its own channel with its own link, audience, embed
origins, visitor messages, and tool credentials. Every chat link of an Agent
lives in the Agent's own Organization.

On its card you can copy the link and turn it off or on with the switch; its
menu has **Edit** (the dialog), **Reset link** on public links, and **Delete**.
Turning it off stops the link immediately while keeping the configuration;
deleting removes the chat link and its configuration for good.

## Choose who can chat

Below the chat link's on/off switch, pick the audience:

- **Organization members** — only signed-in members of your Organization can
  chat. Anyone else — including someone the link was forwarded to — sees the
  same "not found" page as for an Agent that never existed. This is the default.
- **Anyone with the link** — anyone who opens the link can chat, with no
  account. Choose it for product assistants, public help pages, and demos; a
  link reaches the internet only when you pick it.

The **Organization members** audience is built for internal knowledge Agents.
Stigmer checks membership on every message, so when someone leaves your
Organization, their access ends with their membership — there is no lingering
link to hunt down. The link itself is safe to forward: it shows nothing to
non-members.

When a member opens an org-members-only link without being signed in, the page
offers **Sign in if you have access**. After signing in, they land back on the
chat.

Embedding is available for the public audience only: embeds serve anonymous
visitors, and an org-members-only Agent requires a signed-in member.

## Who pays for chat-link conversations

Conversations over the chat link run on your Organization's own
[provider keys](/docs/guides/integrations/model-provider-keys), for visitors on
a public link and for members on an org-members-only one, and your model
provider bills them to you.

Stigmer protects your spend automatically:

- Visitors are rate limited, per visitor and across your whole Organization.
- Each conversation has a turn limit and an inactivity timeout.
- The Agent's [cost cap](/docs/concepts/billing#set-a-cost-cap), if you set one,
  stops any one message at it.
- If your Organization has no key for the Agent's model, visitors read that the
  Agent isn't set up to answer yet, and nothing runs.

## Customize visitor messages

When a visitor hits a limit, Stigmer shows a short explanation. You can replace
the default wording in the **Link** tab under **Customize visitor messages**.
There are three messages:

| Message                | Shown when                                    |
| ---------------------- | --------------------------------------------- |
| **Rate limited**       | A visitor sends messages faster than allowed  |
| **Unavailable**        | The Agent is temporarily unavailable          |
| **Conversation ended** | A conversation reaches its turn or time limit |

Leave a message empty to keep the platform default.

## Embed the chat on your site

The **Embed** tab gives you a two-line snippet you can paste into any web page:

```html
<script src="https://app.stigmer.ai/embed.js" async></script>
<stigmer-agent channel="chn_01j9z3k8f2q4m6n7p8r9s0t1v2"></stigmer-agent>
```

Under **Allowed embed origins**, list the websites that may embed your Agent
(for example `https://acme.com`). An empty list allows any site; adding origins
restricts embedding to those sites. See
[Embed an Agent](/docs/guides/channels/embed-an-agent) for sizing, theming, and
how origin restrictions behave.

## Give the chat link its tool credentials

If your Agent uses MCP servers, its tools need credentials — API keys and logins
kept in a [vault](/docs/concepts/vaults). A visitor's chat has no person behind
it, so it uses only the vaults attached to the chat link, never anyone's own
vault, and a visitor brings no keys of their own. Attach the vaults the Agent
needs to a public chat link:

1. Have an Organization admin create a shared vault with only the credentials
   the Agent needs.
2. Make it usable by whoever attaches it: give it **Organization** visibility
   under **Settings → Vaults**, or, on Stigmer Cloud, grant **Can use** to that
   person or their Team. A new shared vault is usable only by the Organization's
   admins until then.
3. Attach it under **Tool credentials** in the chat link's dialog. You can
   attach a vault only if you may use it, and each visitor message checks again
   that you still may.

A run that needs a key no attached vault holds is refused before it starts,
naming the key. Your own vault and your sign-ins are never used by a chat link.
Organization-audience chat links take no vaults: members' chats use their own.

### Tool approvals never reach visitors

Some tools require human approval before they run, by default or because the
Agent's hooks ask about them. A visitor is not an approver: they never see
approval prompts, tool names, or platform mechanics. When a gated tool comes up
in a visitor's chat, the platform skips it automatically and the Agent explains
in plain language what it could not do — the chat always gets a reply. A call
the Agent's hooks refuse is refused here as anywhere.

For actions the visitor's own request authorizes — booking their appointment,
exporting their variance report — design the Agent to confirm the specifics in
conversation first ("I'm about to book Monday 10 AM — shall I go ahead?"), and
use a tool that runs without approval: an MCP tool its server does not mark
destructive and the Agent's hooks do not ask about. Keep truly destructive
operations marked: for visitors they are skipped, which is exactly right — a
stranger with your link should not be able to trigger them at all. To keep the
Agent away from a tool entirely, leave it out of the Agent's `tools` list.

## Reset a public link

A public link sometimes travels further than you meant it to — a forwarded
email, a message pasted into the wrong channel, a page a search engine picked
up. **Reset link** in the **Link** tab kills the current link and gives you a
new one, without turning the chat link off or deleting it.

After a reset, the link carries a secret key:

```
https://app.stigmer.ai/chat/chn_01j9z3k8f2q4m6n7p8r9s0t1v2?k=<key>
```

- The old link — including the plain one without a key — stops working
  immediately. Visitors in the middle of a conversation are cut off on their
  next message.
- A dead link shows the same "not found" page as an Agent that never existed.
- Reset again at any time to issue a fresh key and kill the previous one.
- The embed snippet changes too: re-copy it from the **Embed** tab after a reset
  so your website keeps working.

Stigmer stores the key on the server side, outside anything a YAML manifest
carries — applying a manifest, whether the Agent's or the chat link's, never
removes or changes it. Resetting is only offered for public links; an
org-members-only link needs no reset, because access ends with membership.

<Callout>
  A reset link is still a public link: anyone who has the new URL can chat.
  Reset cuts off the audience the old link reached; it does not add
  authentication. For that, switch the audience to **Organization members**.
</Callout>

## Turn a chat link off

Turn the switch off in the dialog — or on the link's card in the **Channels**
tab — to revoke the link. The public page stops working immediately — visitors
see the same "not found" page as for an Agent that never existed. Pausing keeps
the chat link's configuration for when you turn it back on; **Delete** in the
card's menu removes the chat link entirely.

## A chat link to another Organization's Agent

A chat link always lives in the Agent's own Organization: its link, the provider
keys it runs on and its credentials are that Organization's. To offer another
Organization's Agent from yours, install the Plugin that carries it — the
installed Agent is your Organization's copy, upgrades with the Plugin, and can
have a chat link like any Agent you built. See
[Install from a marketplace](/docs/guides/plugins/install-from-a-marketplace).

<Callout>
  Chat links to another Organization's Agent created before this rule no longer
  serve visitors; their links show the same "not found" page as an Agent that
  never existed. Remove them through the API or the CLI, or leave them: they
  cost nothing.
</Callout>

## From the CLI

You can also manage a chat link from the terminal:

```bash
# A chat link for your organization's members only (the default for a new link)
stigmer channel link acme-corp/internal-helper

# A public chat link; prints the link and the embed snippet
stigmer channel link acme-corp/variance-reporter --audience public

# Reset the public link (the old link stops working immediately)
stigmer channel link acme-corp/variance-reporter --reset-link

# Revoke the link
stigmer channel link acme-corp/variance-reporter --off
```

The CLI changes only what you ask it to — your allowed origins, visitor
messages, and audience stay as you set them here. A plain toggle never turns an
org-members-only link back into a public one. Visitor chat is served by Stigmer
Cloud, so a link from a local backend won't serve visitors. See the
[`stigmer channel` reference](/docs/cli/commands/channel) for all flags.

## Manage the chat link declaratively

The chat link lives in its own resource — a `Channel` of type `web` — separate
from the Agent it points at. If you manage resources with YAML manifests, manage
the link the same way:

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Channel
metadata:
  name: internal-helper-web
  org: acme-corp
spec:
  agent_ref:
    kind: agent
    org: acme-corp
    slug: internal-helper
  enabled: true
  web:
    audience: channel_audience_org
```

Apply it with `stigmer apply -f chat-link.yaml`. Because the link is a separate
resource, applying your Agent's manifest never changes the chat link — and
applying the link never changes the Agent. `metadata.org` and `agent_ref.org`
name the same Organization: a link lives where its Agent lives.

<Callout type="warn">
  An apply replaces the link's settings as a whole, and a missing `audience`
  means Organization members. Keep `audience: channel_audience_public` in every
  apply of a public link — a manifest that omits it makes the link
  organization-only.
</Callout>

See the [Channel reference](/docs/sdk/resources/channel) for every field,
including embed origins, visitor messages, and tool credentials.

## Go further with the SDK

The **Developer** tab shows the path beyond the hosted page: mint tokens for
your own users with an admin service account's key and the Stigmer SDK. That
gives you your own authentication, branding, and UI on the same Agent runtime.
See [Sign your product's users in](/docs/guides/authentication/product-users) to
get started.
