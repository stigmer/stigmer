title: Cloud mode (auto)
description:
  When no local runner is started, Stigmer provisions compute on demand. Learn
  how cloud mode works and when to use it in your platform integration.
---

Cloud mode is the zero-setup option. When a Session needs compute and no runner
is available, Stigmer provisions an ephemeral cloud runner on demand. No
`stigmer up` command is needed. No sidecar. No Docker. The platform handles
everything.

## When to use cloud mode

Cloud mode is the right choice when:

- Your users do not want to manage local infrastructure
- You want a zero-configuration experience for your end users
- You need burst capacity beyond what local runners can provide
- Your app is a web application without a local sidecar

If your desktop app does not start a local runner, cloud mode is the automatic
fallback. You can present this to your users as "cloud mode" or "automatic."

## How it works

1. A user starts a Session and sends a message.
2. Stigmer checks for an available runner. If no runner is specified and none is
   bound to the Session, the platform provisions a cloud runner automatically.
3. The cloud runner starts, picks up the execution, and processes it.
4. After the execution completes and no new work arrives, the cloud runner is
   cleaned up automatically.

Cloud runners are labeled `stigmer.ai/system-managed` and do not appear in the
Session composer's runner picker. They appear in the admin runner list in
**Settings > Runners** for visibility.

## No configuration needed

There are no flags or environment variables to set for cloud mode. It is the
default behavior when:

- No local runner is running
- No runner is explicitly selected in the Session
- The Session is not already bound to a specific runner

## Session binding

Once a Session uses a runner, subsequent messages in that Session route to the
same runner. This applies to both local and cloud runners.

If the bound runner is no longer available (for example, a cloud runner was
cleaned up after being idle), the Session falls back to automatic provisioning
and a new cloud runner is created.

## Combining modes

Your app can offer all three modes to users:

- **Local** for users who want full host access and data privacy
- **Sandbox** for users who want isolation without cloud dependency
- **Cloud** for users who want zero-setup

A typical pattern: your app starts with cloud mode (no sidecar needed), then
offers local or sandbox mode as an option for users who want more control. Users
who never configure a local runner get cloud mode automatically.
