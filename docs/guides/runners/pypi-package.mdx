  Install the agent-runner as a Python package with pip. Run it as a standalone

The `stigmer-runner` package on [PyPI](https://pypi.org/project/stigmer-runner/)
lets you install and run the agent-runner with pip. Use this when you want the
runner as a Python dependency in your own project, when Docker is not available,
or when you need fine-grained control over the Python environment.

If you want Docker isolation instead, see
[Deploy with Docker](/docs/guides/runners/docker-deployment). If you want the
CLI to handle everything, see
[Start a local runner](/docs/guides/runners/local-runner).

## Install

```bash
pip install stigmer-runner
```

This installs the runner and its dependencies (`graphton`, `stigmer-protos`,
`temporalio`, `langgraph`, and others). Python 3.11 or later is required.

<Callout type="tip">
  Use a virtual environment to keep the runner's dependencies isolated from your
  system Python.
</Callout>

```bash
python -m venv .venv
source .venv/bin/activate
pip install stigmer-runner
```

## Configure

The runner reads all configuration from environment variables. The minimum
depends on your backend.

**Stigmer Cloud:**

```bash
export STIGMER_TOKEN=stk_your_api_key
export STIGMER_BACKEND_ENDPOINT=api.stigmer.ai:443
```

**Local server** (`stigmer up server`):

```bash
export MODE=local
```

You can also put these in a `.env` file in your working directory — the runner
loads it automatically on startup.

```ini
# .env
MODE=local
STIGMER_LLM_PROVIDER=ollama
STIGMER_LLM_MODEL=qwen2.5-coder:7b
```

For the full list of variables, see the
[environment variable reference](/docs/guides/runners/environment-variables).

## Run

The package installs a `stigmer-runner` console script:

```bash
stigmer-runner
```

Or run it as a Python module:

```bash
python -m stigmer_runner
```

Both commands do the same thing: load configuration from the environment,
connect to Temporal, register with the Stigmer backend, and start polling for
executions. The runner logs to stdout. It keeps running until you stop it with
`Ctrl+C` or send `SIGTERM`.

Once connected, the runner appears in **Settings > Runners** in the web console
with a **Ready** phase badge.

## Verify

Check that the runner registered successfully:

1. Open the Stigmer web console.
2. Go to **Settings > Runners**.
3. Your runner should appear with a **Ready** status.

If the runner does not appear, check the terminal output for connection errors.
Common issues:

| Symptom                                | Cause                                 | Fix                                                       |
| -------------------------------------- | ------------------------------------- | --------------------------------------------------------- |
| `Missing required credential`          | `STIGMER_TOKEN` not set in cloud mode | Set `STIGMER_TOKEN` or `STIGMER_API_KEY`                  |
| `Connection refused` to Temporal       | Wrong `TEMPORAL_SERVICE_ADDRESS`      | Verify the address and that Temporal is reachable         |
| `Connection refused` to backend        | Wrong `STIGMER_BACKEND_ENDPOINT`      | Verify the address and that the Stigmer server is running |
| Runner starts but stays in **Pending** | Heartbeat not reaching server         | Check network connectivity and firewall rules             |

## Run as a service

For production, run the runner under a process manager so it restarts on failure
and starts on boot.

### systemd (Linux)

Create a unit file at `/etc/systemd/system/stigmer-runner.service`:

```ini
[Unit]
Description=Stigmer Agent Runner
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=stigmer
EnvironmentFile=/etc/stigmer/runner.env
ExecStart=/opt/stigmer-runner/.venv/bin/stigmer-runner
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Enable and start:

```bash
sudo systemctl enable stigmer-runner
sudo systemctl start stigmer-runner
```

Put your environment variables in `/etc/stigmer/runner.env`:

```ini
STIGMER_TOKEN=stk_your_api_key
STIGMER_BACKEND_ENDPOINT=api.stigmer.ai:443
```

## When to use this vs Docker vs CLI

| Consideration           | PyPI package                                | Docker                        | CLI                      |
| ----------------------- | ------------------------------------------- | ----------------------------- | ------------------------ |
| **Python environment**  | Your own venv                               | Bundled in image              | Managed by CLI           |
| **System dependencies** | You install them                            | Bundled in image              | Managed by CLI           |
| **Custom Python deps**  | `pip install` them                          | Extend the image              | Not supported            |
| **Isolation**           | Process-level                               | Container-level               | Process-level            |
| **Orchestration**       | systemd, supervisor                         | Docker, Kubernetes            | Terminal, `stigmer down` |
| **Best for**            | Python-native stacks, embedding in your app | Production, CI/CD, Kubernetes | Development, quick start |
