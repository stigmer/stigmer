title: Environment variables
description:
  Complete reference for every environment variable the agent-runner process
  reads. Organized by category with local and cloud mode defaults.
---

The agent-runner reads all configuration from environment variables. When you
start a runner through the CLI or the desktop app, the CLI sets these variables
automatically. When you deploy the runner as a
[Docker container](/docs/guides/runners/docker-deployment) or a
[PyPI package](/docs/guides/runners/pypi-package), you set them yourself.

Variables marked **required** must be set explicitly. Variables with defaults
work without configuration — the default depends on the runner's [mode](#mode).

## Mode

The `MODE` variable controls which defaults apply. Most variables change their
default based on mode.

| Value   | Meaning                                                                                |
| ------- | -------------------------------------------------------------------------------------- |
| `local` | Runner connects to a local Stigmer server. Auth is relaxed, workspace is `./workspace` |
| `cloud` | Runner connects to cloud infrastructure. Auth is required, workspace is `/workspace`   |

If `MODE` is not set, the runner defaults to `cloud`.

## Core

| Variable                       | Description                                                                                        | Local default     | Cloud default    |
| ------------------------------ | -------------------------------------------------------------------------------------------------- | ----------------- | ---------------- |
| `MODE`                         | Execution mode                                                                                     | —                 | `cloud`          |
| `STIGMER_TOKEN`                | Auth credential (JWT or `stk_*` API key). **Required in cloud mode.**                              | `dummy-local-key` | —                |
| `STIGMER_API_KEY`              | Alias for `STIGMER_TOKEN` (backward compatibility)                                                 | —                 | —                |
| `STIGMER_BACKEND_ENDPOINT`     | gRPC address of the Stigmer server                                                                 | `localhost:50051` | `localhost:8080` |
| `STIGMER_PROXY_ENDPOINT`       | Side-channel proxy URL. When set, LLM keys and checkpoint/artifact storage route through the proxy | —                 | —                |
| `STIGMER_IDLE_TIMEOUT_SECONDS` | Shut down after this many idle seconds. Disabled when unset or `<= 0`                              | —                 | —                |

## Temporal

The runner connects to a [Temporal](https://temporal.io) server to receive
execution tasks.

| Variable                                     | Description                                                         | Default          |
| -------------------------------------------- | ------------------------------------------------------------------- | ---------------- |
| `TEMPORAL_SERVICE_ADDRESS`                   | Temporal server address                                             | `localhost:7233` |
| `TEMPORAL_NAMESPACE`                         | Temporal namespace                                                  | `default`        |
| `STIGMER_TASK_QUEUE`                         | Task queue the runner polls (set by launcher for per-runner queues) | —                |
| `TEMPORAL_AGENT_EXECUTION_RUNNER_TASK_QUEUE` | Legacy fallback for task queue                                      | —                |
| `TEMPORAL_MAX_CONCURRENCY`                   | Maximum concurrent activity executions                              | `10`             |

If neither `STIGMER_TASK_QUEUE` nor `TEMPORAL_AGENT_EXECUTION_RUNNER_TASK_QUEUE`
is set, the runner uses `agent_execution_runner` as the default queue.

## LLM

The runner calls an LLM provider during agent execution. Defaults change based
on mode.

| Variable                  | Description                                       | Local default            | Cloud default       |
| ------------------------- | ------------------------------------------------- | ------------------------ | ------------------- |
| `STIGMER_LLM_PROVIDER`    | LLM provider (`anthropic`, `ollama`, or `openai`) | `ollama`                 | `anthropic`         |
| `STIGMER_LLM_MODEL`       | Model name                                        | `qwen2.5-coder:7b`       | `claude-sonnet-4.5` |
| `STIGMER_LLM_BASE_URL`    | Provider base URL                                 | `http://localhost:11434` | —                   |
| `OLLAMA_BASE_URL`         | Alias for `STIGMER_LLM_BASE_URL` (Ollama compat)  | `http://localhost:11434` | —                   |
| `STIGMER_LLM_API_KEY`     | API key for Anthropic or OpenAI                   | —                        | —                   |
| `ANTHROPIC_API_KEY`       | Alias for `STIGMER_LLM_API_KEY` (backward compat) | —                        | —                   |
| `STIGMER_LLM_MAX_TOKENS`  | Override default max tokens                       | `8192`                   | `20000`             |
| `STIGMER_LLM_TEMPERATURE` | Override default temperature                      | `0.0`                    | —                   |

When `STIGMER_PROXY_ENDPOINT` is set, LLM calls route through the proxy and
provider API keys are not required on the runner.

## Checkpointer

The checkpointer persists LangGraph state for approval flows and conversation
continuity.

| Variable                           | Description                                                    | Local default                | Cloud default         |
| ---------------------------------- | -------------------------------------------------------------- | ---------------------------- | --------------------- |
| `STIGMER_CHECKPOINTER_TYPE`        | Storage backend (`memory`, `sqlite`, `mongodb`, `http`)        | `sqlite`                     | `mongodb`             |
| `STIGMER_CHECKPOINTER_SQLITE_PATH` | Path for SQLite database file                                  | `./checkpoints/langgraph.db` | —                     |
| `STIGMER_CHECKPOINTER_MONGODB_URI` | MongoDB connection string. **Required when type is `mongodb`** | —                            | —                     |
| `STIGMER_CHECKPOINTER_MONGODB_DB`  | MongoDB database name                                          | `stigmer_checkpoints`        | `stigmer_checkpoints` |
| `STIGMER_CHECKPOINTER_TTL`         | Checkpoint expiration in seconds                               | —                            | —                     |

The `http` type routes checkpoint storage through the side-channel proxy. It
requires `STIGMER_PROXY_ENDPOINT` and `STIGMER_TOKEN`.

## Workspace and sandbox

| Variable                    | Description                                                   | Local default                                | Cloud default |
| --------------------------- | ------------------------------------------------------------- | -------------------------------------------- | ------------- |
| `STIGMER_EXECUTION_MODE`    | How agent commands run (`local`, `sandbox`, or `auto`)        | `local`                                      | `local`       |
| `WORKSPACE_ROOT_DIR`        | Root directory for agent workspaces                           | `./workspace`                                | `/workspace`  |
| `STIGMER_SANDBOX_IMAGE`     | Docker image for sandbox execution                            | `ghcr.io/stigmer/agent-sandbox-basic:latest` | same          |
| `STIGMER_SANDBOX_AUTO_PULL` | Pull sandbox image if missing (`true` or `false`)             | `true`                                       | `true`        |
| `STIGMER_SANDBOX_CLEANUP`   | Remove sandbox containers after execution (`true` or `false`) | `true`                                       | `true`        |
| `STIGMER_SANDBOX_TTL`       | Container reuse TTL in seconds                                | `3600`                                       | `3600`        |

## Artifact storage

| Variable                                        | Description                                 | Local default            | Cloud default |
| ----------------------------------------------- | ------------------------------------------- | ------------------------ | ------------- |
| `ARTIFACT_STORAGE_TYPE`                         | Storage backend (`local`, `r2`, or `proxy`) | `local`                  | `r2`          |
| `LOCAL_ARTIFACT_PATH`                           | Base path for local artifact storage        | `/var/stigmer/artifacts` | same          |
| `LOCAL_ARTIFACT_SERVE_URL`                      | Base URL for serving local artifacts        | `http://localhost:7235`  | same          |
| `AGENT_EXECUTION_ARTIFACT_R2_ENDPOINT`          | R2 endpoint URL                             | —                        | —             |
| `AGENT_EXECUTION_ARTIFACT_R2_ACCESS_KEY_ID`     | R2 access key                               | —                        | —             |
| `AGENT_EXECUTION_ARTIFACT_R2_SECRET_ACCESS_KEY` | R2 secret key                               | —                        | —             |
| `AGENT_EXECUTION_ARTIFACT_R2_BUCKET`            | R2 bucket name                              | —                        | —             |
| `AGENT_EXECUTION_ARTIFACT_R2_REGION`            | R2 region                                   | `auto`                   | `auto`        |

When `ARTIFACT_STORAGE_TYPE` is `r2`, the four `R2_*` variables (endpoint,
access key, secret key, bucket) are all required.

The `proxy` type routes artifact storage through the side-channel proxy. It
requires `STIGMER_PROXY_ENDPOINT` and `STIGMER_TOKEN`.

## Logging

| Variable    | Description          | Default |
| ----------- | -------------------- | ------- |
| `LOG_LEVEL` | Python logging level | `INFO`  |

## Minimum viable configuration

A runner connecting to Stigmer Cloud needs two variables:

```bash
STIGMER_TOKEN=stk_your_api_key
STIGMER_BACKEND_ENDPOINT=api.stigmer.ai:443
```

A runner connecting to a local server (`stigmer up server`) needs only:

```bash
MODE=local
```

For self-hosted deployments where you run your own Temporal server, also set
`TEMPORAL_SERVICE_ADDRESS` to your Temporal frontend address.

Everything else uses mode-aware defaults.
