title: Streaming
description: Follow a Session's events as they arrive.
---

A Session's output is one ordered log of events, in the Claude Managed Agents
event format. The Agent's messages, its tool uses and their results, the calls
waiting for an approval, and each run's phase are all events in that log.
`streamEvents` follows it: with `after_seq` set, it first sends every stored
event after that place, then each new one as it's appended, with none missing
and none repeated.

The stream follows the whole Session, not one run. Your code decides when to
stop reading, usually when the run it follows has ended.

If you are new to streaming, the
[Quickstart](/docs/getting-started/quickstart) walks through a minimal loop.
This guide covers the production patterns you need after that.

Code written for Claude Managed Agents can read and answer the same log with
Anthropic's own SDK: see [Use Anthropic's SDK](/docs/sdk/managed-agents).

## Follow a run

Create a run, then stream its Session from the start (`after_seq` 0). Keep the
events of your run, print what the Agent does, and stop when the run's
`stigmer.run.status` event says it ended.

<SDKTabs>
<Tab value="TypeScript">
```typescript
import { followSession } from "@stigmer/client";

const ended = ["completed", "failed", "cancelled", "terminated"];
for await (const frame of followSession(stigmer, sessionId)) {
  if (frame.frame.case !== "event") continue;
  const { runId: eventRunId, threadId, event } = frame.frame.value;
  if (eventRunId !== runId || threadId !== "") continue;

  if (event.case === "agentMessage") {
    console.log(event.value.content.map((block) => block.text).join(""));
  } else if (event.case === "agentToolUse") {
    console.log(`Tool: ${event.value.name}`);
  } else if (event.case === "stigmerRunStatus" && ended.includes(event.value.phase)) {
    if (event.value.phase === "failed") console.error("Run failed:", event.value.error);
    break;
  }
}
```

`followSession` wraps `streamEvents`: it streams from the start by default and
reconnects from the last event it delivered when the stream drops.
</Tab>
<Tab value="Go">
```go
stream, err := client.Session.StreamEvents(ctx, &sessionv1.StreamSessionEventsRequest{
    SessionId: sessionID,
    AfterSeq:  proto.Int64(0),
})
if err != nil {
    log.Fatal(err)
}

for {
    frame, err := stream.Recv()
    if err != nil {
        log.Fatal(err)
    }
    event := frame.GetEvent()
    if event.GetRunId() != runID || event.GetThreadId() != "" {
        continue
    }
    switch {
    case event.GetAgentMessage() != nil:
        for _, block := range event.GetAgentMessage().GetContent() {
            fmt.Print(block.GetText())
        }
        fmt.Println()
    case event.GetAgentToolUse() != nil:
        fmt.Printf("Tool: %s\n", event.GetAgentToolUse().GetName())
    case event.GetStigmerRunStatus() != nil:
        if status := event.GetStigmerRunStatus(); turnEnded(status.GetPhase()) {
            if status.GetPhase() == "failed" {
                log.Fatalf("Run failed: %s", status.GetError())
            }
            return
        }
    }
}
```

`sessionv1` is
`go.stigmer.ai/sdk/proto/ai/stigmer/agentic/session/v1`, and
`proto` is `google.golang.org/protobuf/proto`. `turnEnded` is defined in
[Detect the end of a run](#detect-the-end-of-a-run).
</Tab>
<Tab value="Python">
```python
from ai.stigmer.agentic.session.v1 import io_pb2

request = io_pb2.StreamSessionEventsRequest(session_id=session_id, after_seq=0)
for frame in client.sessions.stream_events(request):
    event = frame.event
    if event.run_id != run_id or event.thread_id:
        continue
    kind = event.WhichOneof("event")

    if kind == "agent_message":
        print("".join(block.text for block in event.agent_message.content))
    elif kind == "agent_tool_use":
        print(f"Tool: {event.agent_tool_use.name}")
    elif kind == "stigmer_run_status" and is_ended(event.stigmer_run_status.phase):
        if event.stigmer_run_status.phase == "failed":
            print(f"Run failed: {event.stigmer_run_status.error}")
        break
```

`is_ended` is defined in [Detect the end of a run](#detect-the-end-of-a-run).
</Tab>
<Tab value="Java">
```java
var stream = client.session.streamEvents(StreamSessionEventsRequest.newBuilder()
    .setSessionId(sessionId)
    .setAfterSeq(0)
    .build());

    var event = stream.next().getEvent();
    if (!event.getRunId().equals(runId) || !event.getThreadId().isEmpty()) {
        continue;
    }
    if (event.hasAgentMessage()) {
        for (var block : event.getAgentMessage().getContentList()) {
            System.out.print(block.getText());
        }
        System.out.println();
    } else if (event.hasAgentToolUse()) {
        System.out.println("Tool: " + event.getAgentToolUse().getName());
    } else if (event.hasStigmerRunStatus() && isEnded(event.getStigmerRunStatus().getPhase())) {
        if (event.getStigmerRunStatus().getPhase().equals("failed")) {
            System.err.println("Run failed: " + event.getStigmerRunStatus().getError());
        }
        break;
    }
}
```

`StreamSessionEventsRequest` is in `ai.stigmer.agentic.session.v1`. `isEnded` is
defined in [Detect the end of a run](#detect-the-end-of-a-run).
</Tab>
</SDKTabs>

## Read the events

Each event carries its place in the log (`seq`), the run it belongs to
(`run_id`), and its thread (`thread_id`). The thread is empty for the Agent's
own events; a subagent's events carry the id of the `task` call that started
it. The events you read most often:

| Event | What it says |
| --- | --- |
| `user.message` | The message that started a run. |
| `agent.message` | Text the Agent wrote. `content` is a list of blocks; join the `text` blocks. |
| `agent.thinking` | The Agent thought. The `stigmer.agent.thinking` event that follows carries the text. |
| `agent.tool_use`, `agent.mcp_tool_use` | A tool call: its `name`, `input`, and `evaluated_permission` (`ask` when it waits for an approval). Its `id` is the `tool_use_id` an answer names. |
| `agent.tool_result`, `agent.mcp_tool_result` | A call's result, naming the call it answers. |
| `stigmer.tool_result.full_output` | Where a large result is stored whole. The result event holds its head. |
| `stigmer.permission.asked` | A call waits for a person's answer, with the message to show them. |
| `session.status_idle` | The Session stopped working. A `stop_reason` of `requires_action` names the calls that wait. |
| `stigmer.run.status` | A run's phase changed. See [Detect the end of a run](#detect-the-end-of-a-run). |
| `session.error` | A run hit an error. |

A type that starts with `stigmer.` is one of Stigmer's own;
[Stigmer's own events](#stigmers-own-events) lists each with its reason.

<Callout type="info">
  For every event type and field, see
  [Session > SessionEvent](/docs/sdk/resources/session#sessionevent).
</Callout>

In TypeScript, the SDK folds events into the conversation for you.
`SessionLog` (or `foldSession` for a list of events) turns them into runs, each
with its items in order, the calls waiting for an answer (`asks`), its to-do
list, its status, and its final `answer`:

```typescript
import { SessionLog, followSession } from "@stigmer/client";

const log = new SessionLog();
for await (const frame of followSession(stigmer, sessionId)) {
  if (!log.applyFrame(frame)) continue;
  const turn = log.snapshot().turns.find((t) => t.runId === runId);
  if (turn?.ended) {
    console.log(turn.answer);
    break;
  }
}
```

## Stigmer's own events

Every event whose type starts with `stigmer.` carries something Claude Managed
Agents' format has no place for. Each is optional: a client that skips them all
still follows the whole conversation, and nothing waits on one of them.
[Anthropic's SDK](/docs/sdk/managed-agents) never receives them.

**Written by** says who may add the event to the log. A runner can't write an
event the server writes.

| Event | What it says | Why Managed Agents has none | Written by |
| --- | --- | --- | --- |
| `stigmer.agent.thinking` | The text of the Agent's thinking. It follows its `agent.thinking`. | Their `agent.thinking` carries no text, only that the Agent thought. | Runner |
| `stigmer.permission.asked` | Why a tool call waits for a person: the message to show them, and the rule or hook that asked. | A tool call has no field for why it waits or what asked. Claude Code shows a hook's reason, and this event carries it. | Runner |
| `stigmer.permission.grant` | A person allowed every call of one kind (a built-in category, an MCP server, or the hook that asked) for the rest of the turn. | They allow a kind of call only by a fixed policy set on the agent. This is Claude Code's "don't ask again", given during the conversation. | Server |
| `stigmer.harness.note` | A line the platform added in its own voice, for example that its tools are off for this turn. | It isn't the Agent's words, so it can't be an `agent.message`. | Runner |
| `stigmer.agent.structured_output` | The answer in the JSON schema the run asked for. | They have no output schema on an agent or a session. | Runner |
| `stigmer.memory.recalled` | Which of the Agent's memories the turn recalled. | Their memory is files the agent reads with its tools, which show as tool calls. Stigmer recalls memories into the turn before the model runs, so no tool call shows it. | Runner |
| `stigmer.file_review.changes` | The files a turn changed, offered to keep or undo. Only in a Session with file review on. | Their format has no Keep and Undo after an agent's edits, as Cursor and Copilot offer. Review is off by default and never makes a turn wait. | Runner |
| `stigmer.file_review.decided` | A person kept or undid a turn's changes, or one of its files. | The same review. | Server |
| `stigmer.file_review.reconciled` | The undone files were put back. | The same review. | Runner |
| `stigmer.run.status` | A run changed phase: it started, waits, paused, or ended and how. | Stigmer keeps each turn as a run, which billing, routines and channels key on. The Session's status speaks for the whole Session and says nothing when one run ends while another still works. | Server |
| `stigmer.tool_result.full_output` | Where the whole output of a tool result too large to keep inline is stored. The result holds its head. | A field can't be added to their `agent.tool_result`. | Runner |
| `stigmer.tool_output_delta` (preview) | A piece of a running tool's output. Streamed when you name it in `event_deltas`, and never stored. | They preview only the Agent's message and thinking. This shows a long command's output as it runs. | Runner |

Where Stigmer's Managed Agents events mean something slightly different, and
which of their events Stigmer never writes, is in
[Use Anthropic's SDK](/docs/sdk/managed-agents#where-stigmers-events-differ).

## Detect the end of a run

The newest `stigmer.run.status` event of a run gives its phase. These phases
end it:

| Phase | Meaning |
| --- | --- |
| `completed` | The Agent finished. |
| `failed` | The run hit an error. `error` holds the reason. |
| `cancelled` | Someone stopped the run. |
| `terminated` | The platform stopped the run (timeout, budget, or force-kill). |

These phases don't:

| Phase | Meaning |
| --- | --- |
| `pending` | Queued, waiting for a runner. |
| `running` | The Agent is working. |
| `waiting` | A call waits for an approval. See [Answer a call that waits](#answer-a-call-that-waits). |
| `paused` | Paused, and can be resumed. |

<SDKTabs>
<Tab value="TypeScript">
```typescript
import { TURN_ENDED_PHASES, type TurnPhase } from "@stigmer/client";

function isEnded(phase: string): boolean {
  return TURN_ENDED_PHASES.has(phase as TurnPhase);
}
```
</Tab>
<Tab value="Go">
```go
func turnEnded(phase string) bool {
    switch phase {
    case "completed", "failed", "cancelled", "terminated":
        return true
    }
    return false
}
```
</Tab>
<Tab value="Python">
```python
ENDED_PHASES = {"completed", "failed", "cancelled", "terminated"}

def is_ended(phase: str) -> bool:
    return phase in ENDED_PHASES
```
</Tab>
<Tab value="Java">
```java
static boolean isEnded(String phase) {
    return Set.of("completed", "failed", "cancelled", "terminated").contains(phase);
}
```
</Tab>
</SDKTabs>

## Answer a call that waits

A call that needs a person's answer is a tool use with `evaluated_permission`
`ask`. The log records a `stigmer.permission.asked` event for it, the run's
phase becomes `waiting`, and the Session goes idle with `requires_action`. Answer
each waiting call on the Session with `confirmToolUse`, naming it by its
`tool_use_id`. `allow` runs the call; `deny` refuses it, and the Agent reads
your `deny_message` and adapts. The run resumes once every waiting call is
answered.

<SDKTabs>
<Tab value="TypeScript">
```typescript
import { create } from "@bufbuild/protobuf";
import { ConfirmToolUseInputSchema } from "@stigmer/apis/ai/stigmer/agentic/session/v1/io_pb";

await stigmer.session.confirmToolUse(
  create(ConfirmToolUseInputSchema, {
    sessionId,
    toolUseId,
    result: "deny",
    denyMessage: "Use the staging database instead.",
  }),
);
```

`waitForTurn` follows a Session until a run ends or waits. When its `phase` is
`waiting`, answer each of its `asks`, then call it again with its `lastSeq`.
`sendAndWait` starts the run and waits in one call.
</Tab>
<Tab value="Go">
```go
_, err := client.Session.ConfirmToolUse(ctx, &sessionv1.ConfirmToolUseInput{
    SessionId:   sessionID,
    ToolUseId:   toolUseID,
    Result:      "deny",
    DenyMessage: "Use the staging database instead.",
})
if err != nil {
    log.Fatal(err)
}
```
</Tab>
<Tab value="Python">
```python
client.sessions.confirm_tool_use(io_pb2.ConfirmToolUseInput(
    session_id=session_id,
    tool_use_id=tool_use_id,
    result="deny",
    deny_message="Use the staging database instead.",

```
</Tab>
<Tab value="Java">
```java

    .setSessionId(sessionId)
    .setToolUseId(toolUseId)
    .setResult("deny")
    .setDenyMessage("Use the staging database instead.")
    .build());
```
</Tab>
</SDKTabs>

To allow a call and every call of its kind for the rest of the run (its built-in
category, its MCP server, or the hook that asked), call `grantPermission` with
the same `session_id` and `tool_use_id`.

## Resume a dropped stream

Transport errors (network failures, server unavailability) surface as SDK
errors while you read. Remember the `seq` of the last event you handled, and
reopen the stream with `after_seq` set to it: the stream sends what you missed,
then continues. A server that is restarting ends its streams with
`UNAVAILABLE`; resume the same way. A reader that falls behind the log only
lags, and its stream is never ended for it. Wait a moment between attempts.

<SDKTabs>
<Tab value="TypeScript">

`followSession` resumes for you, waiting longer after each failure in a row.
It throws only when a retry can't help, such as a Session you can't read:

```typescript
import { followSession, isNotFound } from "@stigmer/client";

try {
  for await (const frame of followSession(stigmer, sessionId)) {
    // process frame
  }
} catch (err) {
  if (isNotFound(err)) {
    console.error("The Session does not exist");
  }
  throw err;
}
```

</Tab>
<Tab value="Go">
```go
var lastSeq int64
for {
    stream, err := client.Session.StreamEvents(ctx, &sessionv1.StreamSessionEventsRequest{
        SessionId: sessionID,
        AfterSeq:  proto.Int64(lastSeq),
    })
    if err != nil {
        log.Fatal(err)
    }
    for {
        frame, err := stream.Recv()
        var sErr *stigmer.Error
        if err == io.EOF || (errors.As(err, &sErr) &&
            (sErr.Code == stigmer.CodeUnavailable || sErr.Code == stigmer.CodeResourceExhausted)) {
            break // reopen after lastSeq
        }
        if err != nil {
            log.Fatal(err)
        }
        if event := frame.GetEvent(); event != nil {
            lastSeq = event.GetSeq()
            // process event
        }
    }
    time.Sleep(time.Second)
}
```
</Tab>
<Tab value="Python">
```python
import time

from stigmer import ErrorCode, StigmerError, is_retryable

last_seq = 0
while True:
    request = io_pb2.StreamSessionEventsRequest(session_id=session_id, after_seq=last_seq)
    try:
        for frame in client.sessions.stream_events(request):
            if frame.WhichOneof("frame") == "event":
                last_seq = frame.event.seq
                # process frame.event
    except StigmerError as err:
        if not (is_retryable(err) or err.code == ErrorCode.RESOURCE_EXHAUSTED):
            raise
    time.sleep(1)
```
</Tab>
<Tab value="Java">
```java
long lastSeq = 0;
while (true) {
    var request = StreamSessionEventsRequest.newBuilder()
        .setSessionId(sessionId)
        .setAfterSeq(lastSeq)
        .build();
    try {
        var stream = client.session.streamEvents(request);
        while (stream.hasNext()) {
            var frame = stream.next();
            if (frame.hasEvent()) {
                lastSeq = frame.getEvent().getSeq();
                // process frame.getEvent()
            }
        }
    } catch (StigmerException e) {
        if (!e.isRetryable() && e.getCode() != ErrorCode.RESOURCE_EXHAUSTED) {
            throw e;
        }
    }
    Thread.sleep(1000);
}
```
</Tab>
</SDKTabs>

A failed run is not a transport error. The log records it as a
`stigmer.run.status` event with phase `failed` and the reason in `error`, and
the stream continues.

For more on error classification, see
[SDK Overview > Error handling](/docs/sdk/overview#error-handling).

## Show text as it's written

Stored events arrive once they're complete. To show a message while the Agent
writes it, ask for previews with `event_deltas` (`agent.message`,
`agent.thinking`, or `stigmer.tool_output_delta` for a running tool's output).
The stream then also sends `event_start` and `event_delta` frames. The stored
event that follows carries the same `id` and replaces the preview.

In TypeScript, pass `previews` to `followSession`, and let `SessionLog` place
each preview:

```typescript
import { ALL_SESSION_PREVIEWS, SessionLog, followSession } from "@stigmer/client";

const log = new SessionLog();
for await (const frame of followSession(stigmer, sessionId, {
  previews: ALL_SESSION_PREVIEWS,
})) {
  if (log.applyFrame(frame)) render(log.snapshot());
}
```

## Stop following

To stop reading before the run finishes, end the stream from the client side.

<SDKTabs>
<Tab value="TypeScript">

Pass an `AbortSignal` to `followSession`. Abort the controller to end the
stream:

```typescript
const controller = new AbortController();
setTimeout(() => controller.abort(), 30_000);

for await (const frame of followSession(stigmer, sessionId, {
  signal: controller.signal,
})) {
  // process frame
}
```

</Tab>
<Tab value="Go">

Cancel the `context.Context` to close the stream:

```go
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()

stream, err := client.Session.StreamEvents(ctx, request)
if err != nil {
    log.Fatal(err)
}
for {
    frame, err := stream.Recv()
    if err != nil {
        break
    }
    // process frame
}
```

</Tab>
<Tab value="Python">

Break out of the iterator to stop reading. The underlying gRPC channel cleans
up when the iterator is garbage collected:

```python
for frame in client.sessions.stream_events(request):
    if should_stop():
        break
```

</Tab>
<Tab value="Java">

Break out of the iteration loop. The underlying gRPC stream cleans up when the
`StigmerStream` is garbage collected:

```java
var stream = client.session.streamEvents(request);
while (stream.hasNext()) {
    var frame = stream.next();
    if (shouldStop()) {
        break;
    }
}
```

</Tab>
</SDKTabs>

<Callout type="warn">
  Ending a stream stops your client from receiving events. It does not stop the
  run. To stop it, call the Session's
  [`interrupt`](/docs/sdk/resources/session#interrupt), which stops every
  unfinished run of the Session.
</Callout>
