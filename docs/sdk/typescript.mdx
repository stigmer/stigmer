`@stigmer/client` is the official TypeScript client for the Stigmer API. It
provides typed resource clients, structured error handling, and
server-streaming support, and runs in Node.js and the browser.

## Installation

```bash
npm install @stigmer/client
```

## Create a client

On the server, authenticate with an API key from an environment variable:

```typescript
import { Stigmer } from "@stigmer/client";

const stigmer = new Stigmer({
  baseUrl: "https://api.stigmer.ai",
  apiKey: process.env.STIGMER_API_KEY!,
});
```

In a CI job or a script, use a service account's key, not a person's: see
[SDK Overview > Automation](/docs/sdk/overview#automation).

In the browser, never use an API key. Pass `getAccessToken` instead — a
callback that returns each user's JWT:

```typescript
declare function fetchTokenFromAuthProvider(): Promise<string>;
// ---cut---
import { Stigmer } from "@stigmer/client";

const stigmer = new Stigmer({
  baseUrl: "https://api.stigmer.ai",
  getAccessToken: () => fetchTokenFromAuthProvider(),
});
```

Provide exactly one of `apiKey` or `getAccessToken`. See
[SDK Overview > Authentication](/docs/sdk/overview#authentication) for the
full comparison of authentication methods, and the
[Authentication guide](/docs/guides/authentication/overview) for setting up
identity federation or minted user tokens.

## Make your first call

Every resource has its own client with methods like `get`, `create`, `list`,
`apply`, `update`, `rename`, and `delete`
([Update and apply](/docs/sdk/overview#update-and-apply)). TypeScript uses singular camelCase accessors:

```typescript
declare const id: string;
// ---cut---
import { isNotFound } from "@stigmer/client";

try {
  const agent = await stigmer.agent.get(id);
  console.log(agent.metadata?.name);
} catch (err) {
  if (isNotFound(err)) {
    console.log("Agent does not exist");
  } else {
    throw err;
  }
}
```

## Act as one of your users

When your backend starts work that belongs to a person signed in to your
product, build a second client on a token minted for them, kept in a token
cache. What that client starts (a Session, a run, an upload) is the person's.
The service account's client mints; the cache mints again only shortly before
the token expires.

```typescript
declare const admin: import("@stigmer/client").Stigmer;
declare const userId: string;
// ---cut---
import { createTokenCache } from "@stigmer/client";
import { createNodeClient } from "@stigmer/client/node";

const tokens = createTokenCache(() =>
  admin.tokens.mintUserToken({ org: "acme", userId }),
);
const asUser = createNodeClient({
  baseUrl: "https://api.stigmer.ai",
  getAccessToken: tokens.getAccessToken,
});
```

`admin` is the client built on the service account's key.

The whole flow, and what the person's role allows, is in
[From your backend, as the user](/docs/guides/authentication/product-users#from-your-backend-as-the-user).

## Your app's own tools

Give the Agent tools your app answers itself. Say your app has a form that
registers a service: the Agent calls the tool with what it found, your app opens
the form prefilled, and once your user submits it, your app answers and the
Agent carries on. Declare the tools when you create the Session:

```typescript
import { defineCustomTool } from "@stigmer/client";

const registrationForm = defineCustomTool({
  name: "show_registration_form",
  description: "Open the service registration form beside the chat, prefilled.",
  inputSchema: {
    type: "object",
    properties: { service: { type: "string" }, repo: { type: "string" } },
    required: ["service"],
  },
});

const session = await stigmer.session.create({
  name: "register-payments",
  org: "acme",
  agentRef: { org: "acme", slug: "platform-helper" },
  customTools: [registrationForm],
});
```

A call of the tool waits for your app's answer, as a call waits for an approval.
[Answer a call of your app's own tool](/docs/sdk/streaming#answer-a-call-of-your-apps-own-tool)
shows how to find the waiting calls and answer one. Only the Session's owner
answers, so answer from your backend with a client built for the person, as
above. The server checks each tool when the Session is created, and
[Sessions](/docs/concepts/sessions#your-apps-own-tools) lists the rules.
