A Grant gives a specific permission to a principal on a resource. It
binds three elements: WHO (principal), WHAT (resource), and HOW (relation).
Grants are the source of truth for authorization in Stigmer.

```yaml
apiVersion: iam.stigmer.ai/v1
kind: Grant
metadata:
  name: alice-org-admin
  org: acme
spec:
  principal:
    kind: identity_account
    id: ia_alice-123
  resource:
    kind: organization
    id: org_acme-456
  relation: admin
```

### listAccessHistory

List an organization's access history: every time someone was given or lost access to the organization or to a resource in it, who did it, why, and when.

Without after_sequence the entries come newest first, for people reading what happened lately. With after_sequence they come oldest first, starting just after that entry, for a tool that keeps its own copy: it asks for what came after the last entry it holds. Each organization numbers its entries from 1 in the order they happened, with no gaps above the oldest kept entry, so a reader that resumes after entry N never misses one the server still keeps.

A server may keep the history for a limited time, set by its operator. It then removes the oldest entries first and never reuses a number: every page says how many days the server keeps the history (retention_days, 0 for good) and the oldest number it still holds (oldest_sequence), so a tool can tell entries that were removed from entries it missed.

Only the organization's owners and administrators may read it, and a parent organization's administrators for a child, since they are administrators in every child. Whoever may read it reads all of it. The Enterprise and Cloud editions keep the history; an open-source server keeps none and answers UNIMPLEMENTED. A host may refuse the read for its own reasons, such as a plan that does not include it.

### revokeOrgAccess

Remove a person from an organization.

Removes every role the identity account holds on the organization, then every grant it holds on the organization's resources: what was shared with it (agents, vaults, sessions and the rest) and its team memberships. From that moment it reaches nothing in the organization. What it created stays with the organization and is still recorded as its work; the authorization model admits a person to their own work only while they hold a role in the organization, so it becomes theirs again only if they are invited back. What was shared with them does not come back.

### IdentityAccountProvisioningMode

IdentityAccountProvisioningMode defines how an identity account was created.

| Value | Description |
|-------|-------------|
| `direct` | User signed up directly via Stigmer's own authentication tenant. |
| `federated` | Account was created by the platform for federated authentication via a FederationIssuer. |
| `machine` | Machine-to-machine client credentials account for inter-service communication. |
| `app_user` | A person who signs in from an organization's own product: the product's backend asks for their token with TokenService.mintUserToken, and Stigmer signs it. |
| `service_account` | An organization's own non-person account: the principal its automation (a CI job, a script, an integration) acts as, so the automation keeps working when the person who set it up leaves. |

### AccessChange

AccessChange says what happened to someone's access.

| Value | Description |
|-------|-------------|
| `granted` | Access was given. |
| `revoked` | Access was taken away. |

### AccessChangeCause

AccessChangeCause says why someone's access changed.

| Value | Description |
|-------|-------------|
| `grant` | Someone gave a person, a team or a group a role. |
| `revoke` | Someone took a role away. |
| `structural` | The server recorded what creating a resource implies: its creator's ownership, or the audience its visibility opens it to. |
| `organization_access_revoked` | Someone removed a person from the organization. |
| `left_organization` | A person left the organization, and the server took away what they still held on its resources. |
| `resource_deleted` | A resource was deleted, and its access with it. |
| `organization_created` | A person created the organization and became its owner. |
| `first_sign_in` | A person signed in for the first time and was given the roles the server's membership rules grant. |
| `role_reconciliation` | The server gave existing accounts the roles its membership rules would have given them. |
| `operator_ownership` | The server's operator became owner of an organization nobody owned. |
| `platform_client_grant` | A person who signed in through a platform client was given the organization role that client granted. |
| `service_account_created` | An administrator created a service account with its role in the organization. |
