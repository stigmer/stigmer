A Routine is a saved agent invocation: the agent and the message each run
starts from, an optional cron expression in the classic 5-field form (or an
`@daily`-style shorthand), the IANA time zone the routine keeps, and whether
it is enabled. Each run starts a fresh conversation with the current date and
time in the routine's time zone appended to the message, so the agent knows
when it is. Every run acts as the routine's owner, the account that created
it, and only the owner changes what it runs. Firing observations (next fire
time, last run, failure streak, and any platform pause reason) live in
status; applying a manifest never touches them. Disabling a routine stops it
while keeping the routine and its history; deleting it, or its agent, stops
it permanently without touching past runs.

A routine with a `cron` runs on its schedule. `fire` runs it once,
immediately, with an optional `text` the run receives after the message,
marked as information from whoever started it rather than instructions. Its
owner and the Participants the owner grants may fire it. A fire records on
status but does not feed the failure streak; a disabled routine refuses, and
a platform-paused routine may still be fired, which is how its owner tests a
fix before `resume`.

In the open-source edition, routines fire while `stigmer up` is running.
The daemon is user-session scoped: after a reboot, nothing fires until you
run `stigmer up` again. A fire missed while the daemon (or your laptop) was
down lands within the 60-minute catch-up window once it returns, and is
skipped entirely after that.

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Routine
metadata:
  name: daily-fee-reminders
  org: workshop
spec:
  cron: "0 9 * * *"
  time_zone: Asia/Kolkata
  enabled: true
  agent:
    agent_ref:
      kind: agent
      org: workshop
      slug: support-agent
    message: Send fee reminders to members whose dues fall in the next 3 days.
```

### update

Update a routine: the fields update_mask names change, every other field keeps its stored value.

The referenced agent is immutable; the schedule, time zone, enablement and the message may change. Only the routine's owner may change what it runs (anything in spec but switching it off); whoever else may manage it may switch it off, rename, relabel or delete it, and is refused otherwise with PERMISSION_DENIED. Status (firing observations, the platform pause) is never touched by updates: use resume to clear a platform pause.

resource.metadata.id names the routine; apply finds one by slug. The slug changes only through rename, and a mask naming a field another door owns, or a path the routine does not have, is refused with INVALID_ARGUMENT naming the path.

An update is refused with ABORTED carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"):

- ETAG_MISMATCH — resource.metadata.etag is set and the routine changed since that etag was read: read it again and make the change again. No metadata. - WRITE_CONFLICT — the routine kept changing while the update was being saved: try again. No metadata.

### fire

Fire a routine once, immediately, and answer with the run's real outcome.

The run acts as the routine's owner and starts a new conversation, with the routine's message. `text`, when set, is appended inside a block that tells the agent it is information from whoever started the run, not instructions: the routine's own message decides what to do with it. Each call is its own run, even two in one second; a caller that retries starts a second run.

The fire runs synchronously through the standard run create pipeline (every launch gate runs), and the result names what happened: the created run's id, or the refusing gate's own copy verbatim. status.last_fire_at and status.last_run_id record a started run. A fire does NOT feed the failure streak: the streak is the schedule's unattended health signal, and a test fire of a broken routine must not race its owner to the pause threshold.

A disabled routine refuses (enable it first). A platform-paused routine MAY be fired: a test fire is exactly how an owner verifies a fix before resuming; resume remains the one path that clears the pause. A routine started by hand as often as the server allows in an hour (30 by default) refuses until the hour has room again; the routine's own schedule is never limited by it.

### rename

Rename a routine: change its slug, the name people type.

The routine keeps its id, so everything that names it keeps working, and every answer names it by the new slug. The old slug keeps leading to the routine for reading for 30 days, during which no other routine of the organization can take it and this one can take it back; then it is released. A write that names the old slug is refused with SLUG_RENAMED (see apply). A slug another routine holds is refused with ALREADY_EXISTS, and one another routine was recently renamed away from with SLUG_RESERVED (see create).

Its schedule keeps its times; a conversation an earlier run started keeps the name it was given then.

### RoutineFireOutcome

What one routine fire produced.

| Value | Description |
|-------|-------------|
| `ROUTINE_FIRE_OUTCOME_STARTED` | A run was created (or idempotently re-found) and is running. |
| `ROUTINE_FIRE_OUTCOME_REFUSED` | A launch gate refused the run deterministically; reason carries the gate's copy verbatim. |
| `ROUTINE_FIRE_OUTCOME_TARGET_MISSING` | The routine's agent_ref no longer resolves. |
| `ROUTINE_FIRE_OUTCOME_SKIPPED` | The fire no-opped: the row was deleted, disabled, or paused between the fire being recorded and the run starting. |
| `ROUTINE_FIRE_OUTCOME_COMPLETED` | The tracked run reached RUN_COMPLETED. |
| `ROUTINE_FIRE_OUTCOME_FAILED` | The tracked run ended terminal-but-not-completed (failed, cancelled, or terminated); reason names the terminal phase. |
| `ROUTINE_FIRE_OUTCOME_TIMED_OUT` | The tracked run outlived the fire's tracking budget. |
