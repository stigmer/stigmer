An Eval is a set of test cases for an agent: an `evals/` folder in Claude Code's
plugin-eval format, pushed whole. Each case is a request a user might type, plus
checks such as "the reply mentions the renamed function" or a pass-or-fail
rubric for an AI judge.

Every push of a changed folder is a new version, reachable by its digest or by a
tag; pushing the same folder again changes nothing. An eval is visible to its
whole organization by default, or kept private to its owner. Push one with
`stigmer push eval`, and get a version back with `stigmer download eval`.

Run an eval on an agent with `stigmer eval run --agent <agent> --eval <eval>`,
or pick it on the agent's Evals tab. Its cases run on the agent with its own
instructions and the plugins it attaches; a mock folder stands in for the
agent's server of that name, or a plugin's server by the name the turn gives it
(`plugin_<plugin>_<server>`), and a mock that names no server of the agent is
listed as not used. The eval run is stamped with the eval's version, so its
results stay tied to the cases that produced them. Whoever may view an eval may
run it on an agent they may edit. The eval run is the agent's: every viewer of
the agent in its organization reads its results, the cases' names, mocks and
conversations included, so running a private eval shares what those tries show
with them.

A conversation that went wrong becomes a case of an eval: **Make a test case**
on the run in the console, or `stigmer runs to-eval-case <run> --eval <eval>`,
adds it as a new version. The case resumes the conversation before the bad turn,
its tool answers stand in for the real servers, and its rubric starts from why
the run went wrong. The shape below is what `get` returns.

### buildCaseFromRun

Build an eval case from a run, to keep on disk or push in an eval.

The case is the turn the run answered: its request as the prompt, the conversation before it as the case's history (so the case resumes where the person was), each MCP tool answer the run got as a fixed mock under the server name the turn gave it, and a rubric to fill in, seeded with why the run went wrong (an AI judge's failing reason, or the caller's own thumbs-down note). It never carries a verdict of its own.

Error Cases:

- NOT_FOUND: no such run - PERMISSION_DENIED: the caller may not view the run - FAILED_PRECONDITION: the run has not ended - RESOURCE_EXHAUSTED: the case is too large to answer inline; add it to an eval with addCaseFromRun, which writes it on the server

### rename

Rename an eval: change its slug.

The eval keeps its id, its versions and its grants, and every answer names it by the new slug. The old slug keeps leading to the eval for reading for 30 days, during which no other eval of the organization can take it and this one can take it back; then it is released. A push that names the old slug is refused with SLUG_RENAMED. A slug another eval holds is refused with ALREADY_EXISTS, and one another eval was recently renamed away from with SLUG_RESERVED.
