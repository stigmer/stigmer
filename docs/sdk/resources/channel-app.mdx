A ChannelApp registers your own messaging-platform app (a Slack app or a
Meta app with WhatsApp Business access) for serving Slack and WhatsApp channels.
Channels that reference a ChannelApp via `spec.app_ref` install through
your app: for Slack this replaces the shared Stigmer app so the bot
carries your name and icon and multiple agents can serve the same
workspace; for WhatsApp a ChannelApp is the only install path. Secret
fields are encrypted at rest and redacted in responses.

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: ChannelApp
metadata:
  name: Acme Support Bot
  slug: acme-support-bot
  org: acme
spec:
  slack:
    client_id: "1234567890.abcdef"
    client_secret: "8f742a..."
    signing_secret: "9c31b8..."
```

A WhatsApp ChannelApp carries the Meta app's credentials and the verify
token you configure on its webhook:

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: ChannelApp
metadata:
  name: Acme WhatsApp
  slug: acme-whatsapp
  org: acme
spec:
  whatsapp:
    app_id: "735281906457812"
    app_secret: "e21c94..."
    access_token: "EAAKZB..."
    verify_token: "a-long-random-string"
```

### apply

Create or update a channel app.

If the resource does not exist, creates a new channel app. If the resource exists, updates the existing channel app. Sending the redaction marker for a secret field preserves the stored value.

A request that carries metadata.id of a channel app in its organization updates that channel app, and its slug changes only through rename. A slug the channel app was renamed away from, named without the channel app's id, is refused with FAILED_PRECONDITION carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"), because a write by a name that stops resolving after 30 days would later make a second channel app:

- SLUG_RENAMED — the slug was renamed: it still leads to the same channel app for reading, but a write names its current slug. Metadata: slug (the one the request named).

### update

Update a channel app: the fields update_mask names change, every other field keeps its stored value.

Sending the redaction marker for a secret field preserves the stored value; the provider arm is immutable.

resource.metadata.id names the channel app; apply finds one by slug. The slug changes only through rename, and a mask naming a field another door owns, or a path the channel app does not have, is refused with INVALID_ARGUMENT naming the path.

An update is refused with ABORTED carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"):

- ETAG_MISMATCH — resource.metadata.etag is set and the channel app changed since that etag was read: read it again and make the change again. No metadata. - WRITE_CONFLICT — the channel app kept changing while the update was being saved: try again. No metadata.

### rename

Rename a channel app: change its slug, the name people type.

The channel app keeps its id, so everything that names it keeps working, and every answer names it by the new slug. The old slug keeps leading to the channel app for reading for 30 days, during which no other channel app of the organization can take it and this one can take it back; then it is released. A write that names the old slug is refused with SLUG_RENAMED (see apply). A slug another channel app holds is refused with ALREADY_EXISTS, and one another channel app was recently renamed away from with SLUG_RESERVED (see create).

Its webhook URLs name its id, so nothing registered with Slack or Meta changes.
