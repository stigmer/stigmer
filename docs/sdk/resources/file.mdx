A File is a file uploaded once and named by its id (`file_01j…`): a screenshot
given to a conversation, a spreadsheet a routine reads every night, a document
kept for later. Its bytes never change; uploading again makes a new File. A
File uploaded into a conversation belongs to it and is seen by everyone who can
see the conversation; any other File is private to its uploader until shared.
Files are uploaded through the API, not written as YAML: inline for a small
file, or through a short-lived upload URL for one up to 500 MB.

An agent returns a File by saving it in its outputs folder, `.stigmer/outputs/`:
when the turn ends, everything new or changed there becomes a File of the
conversation, written by that turn, with `output_path` saying where it was
saved, so two files of one name in two folders are two Files. Files the agent
edits in the workspace are not returned this way. A message names its files by
id (`RunSpec.file_ids`); a conversation lists the ones it holds in its
`resources`. [Files](/docs/concepts/files) explains how a file reaches the
agent and how it compares with Claude's Files API.

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: File
metadata:
  id: file_01j9x7k2m4q8r3t5v6w7y8z9a0
  name: q3-ledger.xlsx
  org: acme
spec:
  filename: q3-ledger.xlsx
  mime_type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
status:
  size_bytes: 48213
```

### update

Update a File's labels and tags: the fields update_mask names change, every other field keeps its stored value. A File's name, type and bytes never change, so any other path is refused with INVALID_ARGUMENT.

An update is refused with ABORTED carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"):

- ETAG_MISMATCH — resource.metadata.etag is set and the File changed since that etag was read: read it again and make the change again. No metadata. - WRITE_CONFLICT — the File kept changing while the update was being saved: try again. No metadata.

### upload

Upload a File: its bytes inline, or the reference of bytes already put to a URL createUploadUrl returned. Returns the File with its new id.

With session_id, the File belongs to that conversation: whoever may send it a message may upload into it, and org must be the conversation's organization (FAILED_PRECONDITION otherwise). Without it, the File is the uploader's own, private until shared, and any member or guest of the organization may upload one.

A file over the server's limit (500 MB unless the operator set another) is refused with INVALID_ARGUMENT. An upload_ref that is unknown, expired or already used is refused with FAILED_PRECONDITION, and so is one whose bytes differ in size from the size createUploadUrl was given.
