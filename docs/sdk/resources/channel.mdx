A Channel is a way people reach an agent. Its type says which: `web` (a
hosted chat link and the chat widget for your own site), `slack` (a Slack
workspace) or `whatsapp` (a WhatsApp Business number). Every type declares
the agent it serves, whether serving is enabled, the shared vaults that
supply the agent's tool credentials, and the per-turn run settings; each
type adds its own settings. An agent has as many channels as it needs, and
deleting the agent deletes them.

A web channel's chat link is `/chat/<channel id>`: it names the channel
only by its permanent ID, so renaming the organization or the channel never
breaks it. The audience says who may chat there (anyone with the link, or
the organization's members), `allowed_origins` limits which sites may embed
the widget, and `messages` overrides what visitors see when a limit refuses
them.

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Channel
metadata:
  name: support-agent-web
  org: workshop
spec:
  agent_ref:
    kind: agent
    org: workshop
    slug: support-agent
  enabled: true
  web:
    audience: channel_audience_public
    allowed_origins:
      - "https://docs.example.com"
    messages:
      rate_limited: "You're sending messages too quickly — give it a moment."
  vaults:
    - kind: vault
      org: workshop
      slug: support-tools
```

A Slack channel installs through the shared Stigmer app unless `app_ref`
names your own ChannelApp. The workspace's identity and credentials are
produced by the install and live in status, so applying a manifest never
touches them.

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Channel
metadata:
  name: support-agent-slack
  org: workshop
spec:
  agent_ref:
    kind: agent
    org: workshop
    slug: support-agent
  enabled: true
  slack: {}
```

A WhatsApp channel names the Business phone number it serves and always
installs through your own Meta app. It is reply-only until its owner sets
`proactive_messaging_enabled`, which lets the agent send business-initiated
messages (reminders, notifications) through `sendMessage`:

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Channel
metadata:
  name: support-agent-whatsapp
  org: workshop
spec:
  agent_ref:
    kind: agent
    org: workshop
    slug: support-agent
  enabled: true
  whatsapp:
    phone_number_id: "106540352242922"
    app_ref:
      kind: channel_app
      org: workshop
      slug: acme-whatsapp
    proactive_messaging_enabled: true
```

### getAgentProfile

Get the public profile of the agent a web channel serves, by the channel's id.

This is the resolution path for the hosted chat page: anonymous visitors (no Stigmer account, no token) resolve a chat link to the trimmed ChannelAgentProfile, never the full Agent, whose spec carries the system prompt and MCP wiring.

Returns NOT_FOUND when the channel does not exist, is not a web channel, is disabled, has the org audience (anonymous callers must not be able to distinguish an org-internal link from a nonexistent one; use getAgentProfileForMember instead), or the link is locked and link_token does not match the channel's current status.web.link_token. The same NOT_FOUND answers when the channel's organization no longer exists. The cases are deliberately indistinguishable so an unshared, revoked, or rotated URL leaks nothing. Returns INVALID_ARGUMENT when channel_id is empty.

### create

Create a channel.

Making a channel is a spending decision: conversations arriving over it call models on the channel's organization's own provider keys, and the providers bill the organization for them.

A channel created without a name takes the slug `&lt;agent slug&gt;-&lt;type&gt;` (for example `support-agent-web`) and the name `&lt;agent name&gt; (&lt;Type&gt;)`.

A slug another channel of the organization holds is refused with ALREADY_EXISTS. A slug another channel was renamed away from, which still leads to it for 30 days, is refused with ALREADY_EXISTS carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"):

- SLUG_RESERVED — another channel held the slug until a recent rename, and it still leads there. Metadata: slug.

### update

Update a channel: the fields update_mask names change, every other field keeps its stored value.

The referenced agent and the channel's type are immutable; status (the link token, install facts) is never touched by updates. A mask naming a web channel's audience or the vaults replaces them whole: an empty audience makes the link organization-only, and empty vaults detach them (both fail closed).

resource.metadata.id names the channel; apply finds one by slug. The slug changes only through rename, and a mask naming a field another door owns, or a path the channel does not have, is refused with INVALID_ARGUMENT naming the path.

### ChannelDeliveryStatus

|-------|-------------|

### ChannelAttemptFailureKind

ChannelAttemptFailureKind classifies WHY a send attempt reached status failed — and with it, whether the failure's stored explanation was authored for the conversation surface (attempt_detail) or is an operator-only diagnostic (last_error).

| Value | Description |
|-------|-------------|
| `attempt_refused` | The provider terminally refused the send; attempt_detail carries the platform's mapped human explanation (e.g. the 24-hour customer-service-window copy for WhatsApp code 131047). |
| `attempt_errored` | A technical failure (transport error, unexpected provider error, unresolvable credentials — exhausted retries or unattemptable at the first try). |
| `attempt_withdrawn` | The platform withdrew the send for a structural reason; attempt_detail carries the short fact ("channel deleted", "run no longer exists"). |
