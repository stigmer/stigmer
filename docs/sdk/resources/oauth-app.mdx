An OAuthApp registers your Organization's OAuth client credentials with an
external vendor (Slack, GitHub, Figma, etc.) so Stigmer can acquire access
tokens on behalf of users. It lists the addresses it signs in to: a sign-in at
one of them, by anyone in the Organization, uses this app, ahead of Stigmer's
built-in app for the address and of the address's own login server. Each address
belongs to one app in an Organization.

```yaml
apiVersion: iam.stigmer.ai/v1
kind: OAuthApp
metadata:
  name: Slack OAuth
  slug: slack-oauth
  org: acme
spec:
  provider: "Slack"
  client_id: "1234567890.abcdef"
  client_secret: "xoxs-..."
  authorization_url: "https://slack.com/oauth/v2/authorize"
  token_url: "https://slack.com/api/oauth.v2.access"
  scopes: ["channels:read", "chat:write"]
  addresses: ["https://mcp.slack.com/mcp"]
```

### update

Update an OAuth app: the fields update_mask names change, every other field keeps its stored value.

resource.metadata.id names the OAuth app; apply finds one by slug. The slug changes only through rename, and a mask naming a field another door owns, or a path the OAuth app does not have, is refused with INVALID_ARGUMENT naming the path.

An update is refused with ABORTED carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"):

- ETAG_MISMATCH — resource.metadata.etag is set and the OAuth app changed since that etag was read: read it again and make the change again. No metadata. - WRITE_CONFLICT — the OAuth app kept changing while the update was being saved: try again. No metadata.

### rename

Rename an OAuth app: change its slug, the name people type.

The OAuth app keeps its id, so everything that names it keeps working, and every answer names it by the new slug. The old slug keeps leading to the OAuth app for reading for 30 days, during which no other OAuth app of the organization can take it and this one can take it back; then it is released. A write that names the old slug is refused with SLUG_RENAMED (see apply). A slug another OAuth app holds is refused with ALREADY_EXISTS, and one another OAuth app was recently renamed away from with SLUG_RESERVED (see create).

Its addresses and its redirect URI do not name its slug, so sign-ins through it are unchanged.
