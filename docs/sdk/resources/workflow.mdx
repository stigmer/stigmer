A Workflow defines a multi-step task orchestration. It declares the sequence of
tasks to execute, including HTTP calls, gRPC calls, conditional branching,
parallel execution, error handling, and AI agent invocations.

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Workflow
metadata:
  name: data-pipeline
  slug: data-pipeline
spec:
  description: "Fetches data from an API, processes it, and notifies on completion"
  document:
    dsl: "1.0.0"
    namespace: acme
    name: data-pipeline
    version: "1.0.0"
  tasks:
    - name: fetchData
      kind: http_call
      task_config:
        method: GET
        endpoint:
          uri: "https://api.example.com/data"
      export:
        as: "${.}"
    - name: processResults
      kind: agent_call
      task_config:
        agent: acme/data-analyst
        message: "Analyze this data: ${ $context.fetchData.body }"
```

### ValidationState

ValidationState represents the current state of serverless workflow validation.

| Value | Description |
|-------|-------------|
| `PENDING` | Validation is pending and has not yet completed. |
| `VALID` | Validation completed successfully and the workflow structure is valid. |
| `INVALID` | Validation completed but found errors in the workflow structure. |
| `FAILED` | Validation process failed due to a system error (not a user error). |

### WorkflowTaskKind

WorkflowTaskKind defines the supported task types in a workflow.

| Value | Description |
|-------|-------------|
| `set_vars` | Set variables in workflow state. |
| `http_call` | Make an HTTP request (GET, POST, PUT, DELETE, PATCH). |
| `grpc_call` | Make a gRPC request to an external service. |
| `activity_call` | Execute an activity. |
| `switch_case` | Branch conditionally based on expressions. |
| `for_each` | Iterate over a collection, executing tasks for each item. |
| `fork` | Execute multiple branches in parallel. |
| `try_catch` | Handle errors with try/catch logic. |
| `listen` | Wait for external signals or events. |
| `wait` | Pause execution for a duration or until a timestamp. |
| `raise_error` | Raise an error to terminate or trigger error handling. |
| `run_workflow` | Execute a sub-workflow. |
| `agent_call` | Invoke an AI agent as a workflow task. |
| `llm_call` | Direct LLM call for classification, extraction, scoring, or routing. |
| `transform` | Deterministic data transformation using JQ, JSONata, or template engines. |
| `human_input` | Workflow-level approval gate for human input, review, or sign-off. |
| `validate` | Schema and business-rule validation checkpoint. |
| `emit_event` | Emit a CloudEvents-formatted event for external consumers or other workflows. |
| `notification` | Send a notification to humans through a channel (Slack, email, Discord, etc.). |
