A ScoringRule switches AI grading on for one agent. While it is enabled, Stigmer
sends a sample of the agent's completed runs to an AI judge with four standard
rubrics, "did the task", "made nothing up", "did only what was asked" and "asked
when unclear", and records the verdict as a score on each graded run. The sample
rate and a monthly spending limit bound how many runs are graded and what
grading costs.

Access is the agent's: whoever can edit the agent changes its grading, and
whoever can see the agent sees the settings and this month's spend, members of
child organizations included when the agent is shared with them.

You switch grading on from the agent's Quality tab in the console; an
scoring rule is never authored as a manifest. The shape below is what `get` and
`getByAgent` return.

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: ScoringRule
metadata:
  name: srl_01j5q3k7m8r2s4tnz2hfp0q0h2
  org: acme
spec:
  agent_id: agt_01j5q3k7m8r2s4tnz2hfp0q0a7
  enabled: true
  sample_rate: 0.1
  monthly_limit_usd: 10
status:
  period: 2026-10
  spent_usd: 1.84
  reserved_usd: 0.25
  graded: 41
  not_graded: 2
```

### update

Update a scoring rule: the fields update_mask names change, every other field keeps its stored value.

Its settings are whether it is enabled, its sample rate, its monthly limit and its model. The agent it grades stays as created, and this month's spend and counts are kept.

resource.metadata.id names the scoring rule; apply finds one by slug. The slug changes only through rename, and a mask naming a field another door owns, or a path the scoring rule does not have, is refused with INVALID_ARGUMENT naming the path.

An update is refused with ABORTED carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"):

- ETAG_MISMATCH — resource.metadata.etag is set and the scoring rule changed since that etag was read: read it again and make the change again. No metadata. - WRITE_CONFLICT — the scoring rule kept changing while the update was being saved: try again. No metadata.
