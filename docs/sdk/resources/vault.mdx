A Vault holds the logins and secrets your runs use. Logins are matched to a
tool by its address and secrets by their name; saved values can be replaced
but are never shown again. Everyone has their own My vault, and an
organization's admins can create shared vaults for a team.

A login is saved by signing in to a tool or by pasting a token, and serves
every tool at that address. A run reads My vault only when its conversation
includes it (`include_my_vault`), or when a Routine its owner created names it
and the Routine's Agent is of the owner's own Organization.

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Vault
metadata:
  name: Ledger keys
spec:
  description: "The finance team's ledger key"
  external_id: "customer-1234"
```

### create

Create a shared vault in an organization.

The vault belongs to the organization and starts empty. It starts private, so only the organization's admins may use it until it is shared, unless it is created with organization visibility (metadata.visibility), which shares it with every member at once.

A slug another vault of the organization holds is refused with ALREADY_EXISTS. A slug another vault was renamed away from, which still leads to it for 30 days, is refused with ALREADY_EXISTS carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"):

### update

Update a vault: the fields update_mask names change, every other field keeps its stored value.

Its name, description and external id may change. Entries are kept as stored: change them with setSecrets, removeSecrets, setConnection and removeConnections.

resource.metadata.id names the vault; apply finds one by slug. The slug changes only through rename, and a mask naming a field another door owns, or a path the vault does not have, is refused with INVALID_ARGUMENT naming the path.

An update is refused with ABORTED carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"):

- ETAG_MISMATCH — resource.metadata.etag is set and the vault changed since that etag was read: read it again and make the change again. No metadata. - WRITE_CONFLICT — the vault kept changing while the update was being saved: try again. No metadata.

### rename

Rename a vault: change its slug, the name people type.

The vault keeps its id, so everything that names it keeps working, and every answer names it by the new slug. The old slug keeps leading to the vault for reading for 30 days, during which no other vault of the organization can take it and this one can take it back; then it is released. A write that names the old slug is refused with SLUG_RENAMED (see update). A slug another vault holds is refused with ALREADY_EXISTS, and one another vault was recently renamed away from with SLUG_RESERVED (see create).

My vault is named after its person and is never renamed: renaming it is refused with INVALID_ARGUMENT, and so is a slug that starts with my-vault, as on create.
