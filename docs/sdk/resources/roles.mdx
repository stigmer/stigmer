Every kind of resource that can be shared declares, in the API contract, the roles that
can be granted on it and what each role allows there. This page is generated from those
declarations, so it says what the server enforces.
[Sharing and access](/docs/concepts/sharing-and-access) explains the model.

- **General access** decides who in the organization reaches a resource without being
  added to it: Private, Organization or Child organizations, where the kind offers them.
- **A role** decides what one person, or one team, may do with it.
- **Editions.** The open-source edition grants roles on the organization only. Granting a
  role on one resource to a person or a team is a feature of the Enterprise and Cloud
  editions.
- **Starting a conversation** also needs the organization's Member role or higher. An
  organization Viewer who is a Viewer of an Agent sees how the Agent is set up and starts
  no conversation with it.
- **An organization's admins** own every Agent, Skill and Plugin in it, whatever its
  general access.

## Organization

Served by every edition. [API reference](/docs/sdk/resources/organization)

**General access**: none; it is shared only through the roles below.

| Role | What it allows |
| --- | --- |
| Owner | Everything, including deleting the organization and choosing its owners |
| Admin | Manage people, settings, billing, and the organization's agents and tools; cannot read private conversations, delete the organization or change its owners |
| Member | Start conversations with the agents shared with them, and create agents when the organization allows it |
| Viewer | See what is shared with the organization; cannot start conversations |

Never granted to a team.
