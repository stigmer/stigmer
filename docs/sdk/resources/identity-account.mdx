An IdentityAccount represents a user or machine principal in Stigmer. It is the
core identity primitive for authentication and authorization. Accounts can be
direct (signed up via Stigmer, machine credentials included), federated
(provisioned through an external identity provider), an app user (minted by an
organization's own product) or a service account.

```yaml
apiVersion: iam.stigmer.ai/v1
kind: IdentityAccount
metadata:
  name: alice
spec:
  idp_id: "auth0|abc123def456"
  email: alice@example.com
  first_name: Alice
  last_name: Smith
  provisioning_mode: direct
```

### update

Update an identity account: the fields update_mask names change, every other field keeps its stored value.

resource.metadata.id names the identity account; apply finds one by slug. The slug changes only through rename, and a mask naming a field another door owns, or a path the identity account does not have, is refused with INVALID_ARGUMENT naming the path.

An update is refused with ABORTED carrying a google.rpc.ErrorInfo detail (domain "stigmer.ai"):

- ETAG_MISMATCH — resource.metadata.etag is set and the identity account changed since that etag was read: read it again and make the change again. No metadata. - WRITE_CONFLICT — the identity account kept changing while the update was being saved: try again. No metadata.

### createServiceAccount

Create a service account: an organization's own non-person account for automation, holding one organization role.

The account belongs to `org` for its whole life. It holds `role` on the organization (admin, member or viewer; never owner) and acts only through API keys created for it with ApiKeyCommandController.createForServiceAccount. Its name is unique among the organization's service accounts; a name in use answers ALREADY_EXISTS. A server running without sign-in answers FAILED_PRECONDITION, since no key could authenticate there.

### deprovisionFederatedAccount

Deprovision a federated identity account by revoking access or deleting it.

Looks up the account by natural key (federation_issuer_ref + external_sub). When delete_account is false, revokes all its grants in the organization. ### provisionMyAccount

Provision the caller's own identity account.

The first-sign-in step every client runs when whoAmI() returns NOT_FOUND: the console's identity gate, `stigmer auth login` and `stigmer auth whoami`, and the SDK's ensureMyIdentityAccount. Derives the account from the caller's token and the userinfo endpoint of the issuer that vouched for it. Idempotent: returns the existing account on retry. A caller another lane vouched for (an organization's federation issuer, a product minting its users' tokens, a system lane) already has the account that lane provisions, and is refused PERMISSION_DENIED.

### IamRole

IamRole defines the roles that can be assigned to principals on resources via Grants.

| Value | Description |
|-------|-------------|
| `owner` | Full control of the resource, including deleting it and deciding who has access. |
| `admin` | Administers an organization: its people, settings and resources, short of its owners, its deletion and its private conversations. |
| `member` | Belongs to an organization or a team. |
| `viewer` | Sees the resource and changes nothing. |
| `participant` | A person who takes part in a conversation: reads it and sends messages. |
| `editor` | Editor of a blueprint (an agent): may change its definition and do whatever a viewer can, and may not delete it, change its visibility, give it a chat link or another channel, or decide who else has access. |
| `user` | May use a shared vault: the runs of a person who holds it use the vault's logins and secrets. |

### IdentityAccountProvisioningMode

IdentityAccountProvisioningMode defines how an identity account was created.

| Value | Description |
|-------|-------------|
| `direct` | User signed up directly via Stigmer's own authentication tenant. |
| `federated` | Account was created by the platform for federated authentication via a FederationIssuer. |
| `app_user` | A person who signs in from an organization's own product: the product's backend asks for their token with TokenService.mintUserToken, and Stigmer signs it. |
| `service_account` | An organization's own non-person account: the principal its automation (a CI job, a script, an integration) acts as, so the automation keeps working when the person who set it up leaves. |
