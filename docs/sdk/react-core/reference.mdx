## Contexts and providers

### DeploymentModeContext

React context for the current deployment mode.

Separated from the provider to mirror the `StigmerContext` / `context.ts`
pattern and avoid circular imports.

Defaults to `"cloud"` so existing consumers who don't pass
`deploymentMode` to `StigmerProvider` see all features enabled.


### FetchCacheProvider

Provides a `FetchCache` instance to descendant `useFetch` hooks.

Mount this component **above** any remount boundary (e.g. above a
`key`-driven session switch) so that cached data survives when child
components unmount and remount. Without this provider, `useFetch`
works exactly as before — no cache, no behavior change.

```tsx
// In your app shell (above the session key boundary):
<FetchCacheProvider>
  <SessionPageInner key={activeSessionId} id={activeSessionId} />
</FetchCacheProvider>
```

```tsx
// With custom limits:
<FetchCacheProvider maxEntries={50} ttl={120_000}>
  <App />
</FetchCacheProvider>
```


### FileReviewContext

Context that supplies the session's file reviews to the tool rows.


### StigmerContext

React context for the Stigmer SDK client instance.

Separated from the provider component to prevent circular imports:
both the provider and consumer hooks import from this file.

The context value is `null` when no provider is mounted. Consumer hooks
throw in this case to surface wiring mistakes during development.


## Hooks

### useAgentSearch

Data hook that searches agents available to the user.

Lists the organization's agents, newest first, while nothing is typed
and searches them once something is, with a debounce, loading/error
tracking, and cancellation-safe fetching. Platform builders use this
when they want full control over rendering; the `AgentPicker`
styled component uses it internally. Results are the given
organization's agents the caller may read.

This is a Layer 1 building-block hook used by both platform builders
(Profile A) and direct Stigmer users (Profile B). Platform builders
can use it standalone to build custom agent selection UIs. The
Stigmer Console composes it via higher-level orchestration hooks.

```tsx
const { results, isLoading, query, setQuery } = useAgentSearch("acme");
```

### useArtifactDownloadUrl

Data hook that resolves a **fresh** presigned download URL for the content
stored under a run's storage key (a tool call's offloaded output, or one
side of a captured file change) on demand via
`stigmer.run.getArtifactDownloadUrl()`. A File's link is minted with
`useFileDownloadUrl` instead.

Presigned URLs expire, so the URL is minted at view time from the stable
`storageKey`: it is always valid, and works for every historical run (the
`storageKey` never expires).

Use this for surfaces that genuinely need a URL — an `<img src>` for an
offloaded screenshot, or a direct browser download of large or binary
output. For text that should render in-app, prefer `useArtifactContent`
(CORS-safe, no presign).

The URL is cached cross-mount by `storageKey`, so repeated renders
and remounts reuse the same minted URL instead of re-hitting the API.

Pass `enabled: false` (or `null` for either id) to skip fetching — consistent
with the `useArtifactContent(null, null)` convention.

### useCreateRun

Behavior hook that wraps `run.create()` and `run.sendMessage()` with

### useDeploymentMode

Read the deployment mode from the nearest `StigmerProvider`.

Returns `"local"` for Stigmer (the open-source edition), `"enterprise"`
for Stigmer Enterprise and `"cloud"` for Stigmer Cloud. Ask it a TIER

### useFileChangeContent

Behavior hook that resolves a `DisplayFileChange`'s before/after sides to the
text the diff renderer needs.

Small bodies are carried inline on the proto and returned with zero cost.
Large bodies were offloaded to the run's storage by the runner

`useArtifactContent` through the server proxy (CORS-safe). The fetch's

### useFileReviewRowChange

The captured change a write row should render as its inline diff, or
`null` to keep the row's own content view: no review for its turn, a path
miss, a capture the runs do not hold, or a non-reviewable change (see
`fileReviewRowChange`).

The diff sibling of `useFileReviewRowState`: both match the row's
path against the same turn's review, so a row's badge and its diff always
describe the same file.

The review state a file-edit row should badge, or `null` for no badge (no

### useResourceAvailable

Check whether a given `ApiResourceKind` is served by the connected
edition.

Combines the deployment mode from context with the proto-derived tier
metadata via `isResourceAvailable`: a kind is served when the
edition ranks at or above the kind's minimum edition (oss < enterprise <
cloud).

```tsx
const available = useResourceAvailable(ApiResourceKind.api_key);
if (!available) return <CloudFeatureNotice>...</CloudFeatureNotice>;
```

### useSessionEvents

Behavior hook that follows one session's event log and folds it: the whole
stored log first, then each event as it is appended, plus the live
previews (a message as it is written, a thinking as it starts, a running
tool's output). One `followSession` per session, from `@stigmer/client`.

- Frames fold into the store as they arrive and publish at most once per
  animation frame, inside `startTransition`, so a long replay or a burst
  of token previews never blocks typing.
- A dropped stream reconnects from the last event it delivered, with
  jittered backoff, for as long as the outage lasts (stigmer#2418); the
  conversation stays visible (`isReconnecting`). A stream that stayed
  open 30 s starts the backoff over, so an idle close re-opens at once.
- A shown tab or a returned network cuts a backoff wait short, and so
  does `UseSessionEventsReturn.wake`.
- A refusal (the session is gone, access was withdrawn) ends the follow
  with `error`.
- A follow that opens and stays silent is reconnected once, then
  `connectTimedOut` is surfaced.

A session follow never completes on its own: a turn ending is read from
the fold (`Turn.ended`), never from the stream.

Pass `null` to follow nothing. A new id resets the fold.
