## Hooks

### useCanCreateFile

Mirrors the server's File upload bar, `can_create_file` on the
organization (its members and guests hold it), so an Upload affordance
never appears to someone whose upload would be refused.

`allowed` stays `false` while the check is in flight, so the button never
shows and then vanishes; after that the check's fail-open answer holds,
so an outage of the check never hides the affordance, and the server
refuses an upload the answer missed. On a server without sign-in every
check answers allowed.

Pass `null` for `org` while it loads: `allowed` stays `false`.

### createFileColumns

Column set for the Library's Files workbench, shared by every console so
the list renders identically everywhere: the File's name, its type, its
size, who can see it, and when it was uploaded. Each row is a full
`File` from the direct query (`createFileListFn`).

Columns are not sortable: the direct query has one fixed server-side
order (newest first), and a sort affordance that did nothing would lie.

```tsx
function createFileColumns(): WorkbenchColumnDef<File>[]
```

Build a `ResourceWorkbench` data source over the Library's Files.
Consumers type their workbench as `ResourceWorkbench<File>` and pass
`getItemId={(f) => f.metadata?.id}`.

(render the workbench with `searchable={false}`).
