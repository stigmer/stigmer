`@stigmer/react` provides React hooks and UI components for every domain in the
Stigmer API. The hooks manage data fetching, mutations, and real-time streaming.
The components render the same views used in the Stigmer Console — session
composers, message threads, approval cards, and resource detail panels.

This package requires a configured `@stigmer/sdk` client. See
[SDK Overview](/docs/sdk) for client setup and authentication.

## Installation

```bash
npm install @stigmer/react @stigmer/sdk @stigmer/protos @bufbuild/protobuf
```

`@stigmer/protos` provides the protocol buffer types that hooks and components
use. `@bufbuild/protobuf` is its runtime dependency.

`react` and `react-dom` 19+ must already be installed.

<Callout type="info">
  `@base-ui/react` is an optional peer dependency used by components that
  render overlays and dropdowns. Install it if your package manager reports a
  missing peer dependency warning.
</Callout>

## Setup

### Server-side and internal tools

Use an API key when the Stigmer client runs on the server (Next.js Server
Components, Node.js backends, internal dashboards). The key stays in a
server-side environment variable and never reaches the browser.

Import the stylesheet, create a client, and wrap your component tree in
`StigmerProvider`:

```tsx
import { Stigmer } from "@stigmer/sdk";
import { StigmerProvider } from "@stigmer/react";
import "@stigmer/react/styles.css";

const client = new Stigmer({
  baseUrl: "https://api.stigmer.ai",
  apiKey: process.env.STIGMER_API_KEY!,
});

function App() {
  return (
    <StigmerProvider client={client}>
      {/* your app */}
    </StigmerProvider>
  );
}
```

`StigmerProvider` renders a `<div class="stgm">` wrapper that scopes all
Stigmer styles. The CSS does not leak into the host application.

### Browser authentication

API keys are secret credentials (`sk_`). Do not embed them in client-side
JavaScript — they would be visible to anyone who opens the browser's developer
tools.

For browser apps, use `getAccessToken` to pass each user's JWT from your
authentication provider (Auth0, Okta, Cognito, Entra ID, or any OIDC
provider):

```tsx
import { useMemo } from "react";
import { Stigmer } from "@stigmer/sdk";
import { StigmerProvider } from "@stigmer/react";
import "@stigmer/react/styles.css";
import { useAuth } from "./your-auth-provider";

function App() {
  const { getAccessToken } = useAuth();

  const client = useMemo(
    () =>
      new Stigmer({
        baseUrl: "https://api.stigmer.ai",
        getAccessToken,
      }),
    [getAccessToken],
  );

  return (
    <StigmerProvider client={client}>
      {/* your app */}
    </StigmerProvider>
  );
}
```

The SDK calls `getAccessToken` on every request and sends the JWT as
`Authorization: Bearer`. Stigmer validates it against your registered Identity
Provider's JWKS endpoint.

**One-time setup:** Register your auth provider as an
[Identity Provider](/docs/guides/federation/register-identity-provider) with JIT
provisioning enabled. Stigmer then creates accounts and grants roles
automatically on first authentication — no per-user provisioning required.

See the [federation guide](/docs/guides/federation/overview) for the full
walkthrough.

<Callout type="info">
  **Which auth method should I use?** Use `apiKey` when the client runs on
  the server (SSR, backend scripts, CLI tools). Use `getAccessToken` when the
  client runs in the browser. See
  [SDK Overview > Authentication](/docs/sdk#authentication) for details.
</Callout>

Any descendant component can access the SDK client with `useStigmer()`:

```tsx
import { useStigmer } from "@stigmer/react";

function MyComponent() {
  const stigmer = useStigmer();
  // stigmer.agent.list(), stigmer.session.create(), etc.
}
```

## Deployment mode

`StigmerProvider` accepts a `deploymentMode` prop that controls which features
are available:

| Mode | Backend | Effect |
|------|---------|--------|
| `"cloud"` | Stigmer Cloud | All features enabled. Default. |
| `"local"` | Local Go CLI (OSS) | Cloud-only features (API keys, IAM, identity providers) are hidden. |

Two hooks read the deployment mode from context:

- **`useDeploymentMode()`** — returns the current mode (`"local"` or
  `"cloud"`).
- **`useResourceAvailable(kind)`** — returns `true` if the given
  `ApiResourceKind` is available in the current mode.

When a feature requires Stigmer Cloud, render `CloudFeatureNotice` to show a
contextual message:

```tsx
import {
  useResourceAvailable,
  ApiResourceKind,
  CloudFeatureNotice,
  ApiKeyListPanel,
} from "@stigmer/react";

function ApiKeySection() {
  const available = useResourceAvailable(ApiResourceKind.api_key);
  if (!available) return <CloudFeatureNotice />;
  return <ApiKeyListPanel />;
}
```

## StigmerProvider

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `client` | `Stigmer` | — | Configured SDK client instance. Required. |
| `deploymentMode` | `"local" \| "cloud"` | `"cloud"` | Backend deployment mode. Controls feature availability. |
| `preset` | `ThemePresetId` | — | Theme preset from `@stigmer/theme`. Applies preset design tokens to all descendant components. |
| `className` | `string` | — | Additional CSS classes on the scoping wrapper. |
| `children` | `ReactNode` | — | Application tree. |
