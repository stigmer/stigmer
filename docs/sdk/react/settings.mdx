## Hooks

### useSettingsNavGroups

Permission-aware settings navigation: [`SETTINGS_NAV_GROUPS`](#settings_nav_groups)
for everyone, plus [`PLATFORM_SETTINGS_NAV_GROUP`](#platform_settings_nav_group) appended when
the caller holds `can_manage_model_pricing` on `platform:stigmer`
(i.e. is a platform operator).

The check runs fail-closed — the opposite of the `useCheckPermission`
default — because navigation is *discoverability*, not *capability*:
an action gate can safely fail open (the server re-checks every
request), but an operator-only nav entry must not appear while the
check is loading, when it errors, or on deployments where the IAM
service (and the surface it points to) does not exist.

Gating is deliberately group-level on this single permission — it is
the only operator console surface today. If a second platform surface
with a different permission arrives, extend [`SettingsNavItem`](#settingsnavitem)
with a per-item `requiredPermission` and filter here, rather than
adding more one-off hooks.

**Signature**

```tsx
function useSettingsNavGroups(): readonly SettingsNavGroup[]
```

```tsx
const groups = useSettingsNavGroups();
return groups.map((group) => <NavGroup key={group.label} group={group} />);
```


## Components

### ApiKeysSection

Settings section for listing and creating organization API keys.


### ChannelAppsSection

Settings section for the organization's channel apps — customer-owned
provider apps (Slack apps, Meta WhatsApp apps) that agent channels
install through. For Slack that replaces the shared Stigmer app (bring
your own app: your bot name and icon, and one agent per app per
workspace, so multiple agents can serve one workspace); for WhatsApp a
channel app is the only way — there is no platform Meta app (DD-WA-2).

After registering an app here, the connect dialog on any agent's
Channels tab offers it as the serving app.

## Types

### PLATFORM_SETTINGS_NAV_GROUP

Stigmer-internal platform-operator navigation group.

Deliberately NOT part of [`SETTINGS_NAV_GROUPS`](#settings_nav_groups): that constant
means "groups every signed-in user sees", and its members must never
change based on who is looking. This group is appended for platform
operators only — use [`useSettingsNavGroups`](#usesettingsnavgroups) to get the
permission-aware list instead of composing the two by hand.
