### useModelReadiness

Data hook: which models can run for `org`, as the server judges it
(`PlatformQueryController.getModelReadiness`). Each provider's standing,
and per model on each engine the provider it needs and that provider's.

The answer is read from the same rule the server refuses a run by, so a
model reported missing is one whose run would be refused, and one
reported served or unknown is not refused for its provider. Every member
of the organization may ask. `org` null or empty skips the read (a guest,
who cannot ask, passes null).

### useModelRegistry

Data hook that exposes the platform model registry with grouping
and lookup helpers.

Pure data layer — no rendering, no side effects. Platform builders
who want full control over rendering import this hook and build
their own UI.

The model data is fetched from the public model registry API by
[`StigmerProvider`](/docs/sdk/react/core#stigmerprovider) and cached in context. During loading,
`isLoading` is `true` and `models` is empty.

**Modes:**
- `options.harness` set — that harness's own models, excluding disabled providers
- `options.harness` omitted — unified: every harness's, excluding disabled providers

### ModelSelector

Combined harness + model picker with a compact trigger button.

Shows a harness dropdown at the top of the popover (when not locked
to a single harness), followed by a curated model list scoped to
the selected harness. Supports search and progressive disclosure
via "Show All Models."

The trigger button displays the current selection in compact format:
`Harness · Model Name ▾` (or just `Model Name ▾` when harness is locked).

**Service tier (#357).** When the consumer opts in via
`ModelSelectorProps.onServiceTierChange` and the selected model
prices a fast variant, a "Fast tier" switch renders in the options area
at the TOP of the popover — the first thing visible on open, mirroring
Cursor's own options panel (Jakob's Law: our users already know that
layout). Deliberately not a per-row affordance: row-level chips crowd
the rows and collide with the "Fast/Fastest" speed badge, and an
interactive element inside `role="option"` is an ARIA authoring error
(option children are presentational). An active fast tier persists
across switches between fast-capable models — the visible badge and
switch keep the state honest — and resets only for models with no fast
variant, where it would be refused at create time.

**Thinking mode (#772).** The same options-area pattern for the second
variant dimension: opting in via
`ModelSelectorProps.onThinkingModeChange` renders a "Thinking"
switch for models declaring a thinking form, on either harness, shown on
and locked for a model that always thinks.
Capability-gated rather than priced-variant-gated — thinking bills at
base per-token rates and costs more only through extra reasoning
(output) tokens. Persistence and reset rules mirror the fast tier's.

## Types

### CostTier

Pricing bracket for a model.

- `economy` — lowest-cost models suitable for high-volume or latency-sensitive tasks
- `standard` — balanced cost-to-capability, the default choice for most workloads
- `premium` — highest-capability models for complex reasoning or critical tasks


### DEFAULT_HARNESS

Platform default — resolves to the Stigmer harness (`"stigmer"`).


### DEFAULT_MODEL_ID

Model ID used when no user preference is set (native harness).


### DISABLED_PROVIDERS

Providers whose models should be hidden from the UI.

The model entries themselves stay in the registry so backend
compatibility is preserved. The useModelRegistry hook filters
them out before anything reaches a component.

To re-enable a provider, simply remove it from this set.

### Provider

LLM provider identifier. Each provider maps to a distinct inference
backend. The model registry uses this for grouping in the
"Show All" expanded view.


### ProviderAvailability

Where a provider stands for an organization.

- `served`: a run that needs it is started. `source` says by what: the
  organization's own key, its parent organization's key (`parentOrg`
  names it), or the runners this server hands its runs to (a laptop's
  `stigmer setup` key, a cloud backend, a gateway).
- `missing`: a run that needs it is refused at create. `scope` says what
  is missing it: the organization (an admin adds a key) or the runners
  (whoever runs them configures one).
- `unknown`: the server cannot see its runners' settings; nothing is
  refused for it, and the runner's own error is the backstop.


### providerFace

The act a card offers for a provider in `availability`, for `viewer`.

```tsx
function providerFace(availability: ProviderAvailability, viewer: ProviderViewer): ProviderFace
```


### ProviderFace

What a card offers for its provider, from the server's report and who is
looking:

- `served`: nothing to fix (an admin may still replace or remove an own key).
- `admin-form`: missing from the organization, and the person may manage
  its keys: the key form.
- `member-line`: missing from the organization, and the person may not:
  who connects it.
- `local-command`: missing from the runners of a server on this machine:
  the command that gives the runner its key.
- `runners-line`: missing from the runners of a server elsewhere: whoever
  runs them gives them one.
- `unknown`: the server cannot see its runners; the key is configured
  where the runner runs, and nothing is refused here.

### thinkingLocked

Whether the model always thinks (`ModelInfo.thinkingRequired`):
its switch shows on and cannot be turned off, and a submit carries
"enabled" for it, never "disabled", which the server refuses for such a
model.

```tsx

```


### thinkingSelectable

Whether the thinking switch may act on this model: the model's registry
entry declares a thinking form (`ModelInfo.thinkingCapable`). The
entry belongs to the harness the model runs on, so the answer holds on
either harness; there is no separate harness check. The one gate every
control and submit path uses, so a switch never renders where the server
would refuse the selection.

```tsx
function thinkingSelectable(model: ModelInfo): boolean
```

### VisionLimits
