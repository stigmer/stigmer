## Hooks

### useModelRegistry

Data hook that exposes the platform model registry with grouping
and lookup helpers.

Pure data layer — no rendering, no side effects. Platform builders
who want full control over rendering import this hook and build
their own UI.

**Modes:**
- `options.harness === "cursor"` — Cursor-harness models only
- `options.harness === "native"` — native models, excluding disabled providers
- `options.harness` omitted — unified: both harnesses, excluding disabled providers

### HarnessSelector

Compact segmented control for choosing the session execution engine.

Renders two mutually exclusive options — "Stigmer" (native) and
"Cursor" (premium) — as adjacent pill segments. The Cursor segment
carries a subtle premium tier indicator.

Built as a `radiogroup` with full arrow-key navigation and ARIA
semantics. All visual properties flow through `--stgm-*` tokens.

Platform builders who need different rendering use
[`HarnessOption`](#harnessoption) and [`HARNESS_LABELS`](#harness_labels) directly.

### ModelSelector

Cursor-style model picker: a flat searchable list inside a popover.

Shows a curated list of featured models by default. The user can
expand via "Show All Models" or type to search the full catalog.

Each model row shows the display name, an engine tag
("Stigmer" / "Cursor"), and a cost-tier indicator.

In unified mode (no `harness` prop), selecting a model implicitly
resolves the harness via `ModelSelectorProps.onHarnessResolved`.

## Types

### CostTier

Pricing bracket for a model.

- `economy` — lowest-cost models suitable for high-volume or latency-sensitive tasks
- `standard` — balanced cost-to-capability, the default choice for most workloads
- `premium` — highest-capability models for complex reasoning or critical tasks


### DEFAULT_CURSOR_MODEL_ID

Model ID used when the Cursor harness is selected and no user preference is set.


### DEFAULT_HARNESS

Platform default — resolves to the native engine.


### DEFAULT_MODEL_ID

Model ID used when no user preference is set (native harness).


### DISABLED_PROVIDERS

Providers whose models should be hidden from the UI.

The model entries themselves stay in MODEL_REGISTRY so backend
compatibility is preserved. The useModelRegistry hook filters
them out before anything reaches a component.

To re-enable a provider, simply remove it from this set.


### fromProtoHarness

Convert a proto `Harness` enum to a [`HarnessOption`](#harnessoption) string.

`UNSPECIFIED` and any unknown values map to `"native"`.

```tsx
function fromProtoHarness(h: Harness): HarnessOption
```


### HARNESS_LABELS

User-facing labels for each harness option.


### HarnessOption

String literal alias for the proto `Harness` enum.

Used on component props and hook options so platform builders
do not need to import proto enums to use the SDK.


### MODEL_REGISTRY

Static catalog of all platform-supported LLM models.

Each entry carries the metadata needed for model selection UI.
[`useModelRegistry`](#usemodelregistry) filters out disabled providers and provides
lookup helpers on top of this list.

### modelKey

Build a compound key that uniquely identifies a model across harnesses.

The same underlying model name (e.g. `claude-4.6-sonnet`) can exist in
both native and cursor harnesses. The compound key disambiguates.

```tsx
function modelKey(harness: HarnessOption, modelId: string): string
```


### parseModelKey

Parse a compound key back into its `(harness, modelId)` parts.
Returns `undefined` for malformed keys.

```tsx
function parseModelKey(key: string): { harness: HarnessOption; modelId: string } | undefined
```


### Provider

LLM provider identifier. Each provider maps to a distinct inference
backend (or intermediary, in the case of Cursor-served third-party
models). The [`MODEL_REGISTRY`](#model_registry) uses this for grouping in the
"Show All" expanded view.
