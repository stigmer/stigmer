## Hooks

### useAttachments

Behavior hook that manages file attachments for agent executions.

Handles the full lifecycle: file validation, upload via
`stigmer.agentExecution.uploadAttachment()`, progress tracking,
error handling, and retry. Produces `AttachmentInput[]` ready
for execution creation.

Files are uploaded immediately on selection so the `storageKey`
is available by the time the user submits their message.

Platform builders who want custom attachment UI import this hook
directly. The [`SessionComposer`](/docs/sdk/react/composer#sessioncomposer) styled component uses it
internally.

### AttachmentChipList

Renders a horizontal list of compact attachment chips showing
filename, size, upload status, and remove/retry actions.

Designed to sit between the context chips and toolbar in
[`SessionComposer`](/docs/sdk/react/composer#sessioncomposer), but usable standalone by platform builders
who compose their own attachment UI.

### AttachmentEntry

State for a single file being managed by the hook.

The `id` is a stable string generated at add-time, used as a React
key and for removal. The same `File` added twice produces two
independent entries with distinct IDs.

### AttachmentPhase

Lifecycle phase of a single attachment managed by [`useAttachments`](#useattachments).

- `uploading` — bytes are being sent to the server
- `ready` — upload succeeded, `storageKey` is available
- `error` — upload failed, `error` describes the failure


### detectContentType

Detects the MIME content type for a file.

Prefers the browser-provided `File.type` when available and
non-empty. Falls back to extension-based detection mirroring the
CLI's `detectContentType` function. Returns
`"application/octet-stream"` when neither source yields a result.

```tsx
function detectContentType(file: File): string
```


### formatFileSize

Formats a byte count as a human-readable string (e.g., `"2.3 MB"`).

Uses base-1024 (binary) units with one decimal place, consistent
with [`formatArtifactSize`](/docs/sdk/react/execution#formatartifactsize) in the artifact utilities.

```tsx
function formatFileSize(bytes: number): string
```


### MAX_ATTACHMENT_BYTES

Maximum attachment size in bytes (10 MB).

Matches the CLI's `maxAttachmentSize` and the gRPC server's
`MaxRecvMsgSize`. Files exceeding this limit are rejected before
upload to avoid wasting bandwidth on requests that will fail.
