### useActiveOrgId

Convenience accessor: returns the active org's system ID (`metadata.id`),
or an empty string when no org is selected.

Every request field that names the active org (`org`, `metadata.org`, a
reference's `org`) carries this id, and stored resources name their org
by it, so comparisons against `metadata.org` use it too. It never
changes, unlike the human-readable slug returned by
[`useActiveOrgSlug`](#useactiveorgslug), which is for display and URLs.

### useCanonicalOrgSlug

Answers the slug a URL's org segment should read, or `null` when the
segment already reads it or the answer is not known.

- A segment equal to the current slug of one of the person's
  organizations, or of the one they have open, is canonical: `null`,
  with no request.
- A segment equal to one of those organizations' ids answers that
  organization's slug, with no request.
- Any other segment is looked up once (the server resolves an id or an
  old slug to the organization); its slug is answered when it differs.
  A lookup the server refuses answers `null`.

Waits for [`OrgProvider`](#orgprovider)'s list to load, and answers `null` when no
provider is mounted.

### useOrgGate

Headless behavior hook that derives the org-gate state from
[`useOrg`](#useorg).

1. **`bypassed`** — `isBypassed` is true; the gate is inactive.
2. **`loading`** — the initial org list fetch is in flight.
3. **`error`** — the org fetch failed; `message` carries the reason.
4. **`no-orgs`** — no organizations exist; the consumer should show an
   onboarding form.
5. **`ready`** — at least one org exists; render the app.

A pure derivation, deliberately: the organization list is final by the
time this hook runs. Where a server creates an organization on first
sign-in (Stigmer Cloud), it does so inside `provisionMyAccount`,
before the identity gate ahead of this one reports ready — so there is
nothing to wait for, and an empty list means the person creates their
first organization now. (The hook once polled for that organization for
ten seconds, a relic of an earlier asynchronous provisioner; on a server
that never provisions one, every first sign-in paid the full wait.)

The consumer computes `isBypassed` using framework-specific APIs and
passes it in, keeping this hook free of routing dependencies.

### OrgProvider

Provides organization context to the component tree.

Fetches the authenticated user's organizations via
`stigmer.organization.listMine()` (every page), manages the active
organization selection, and persists the choice to `localStorage`
under the key `stigmer:activeOrg` by the organization's id.

The active organization may be one outside that list which the person
can read: a parent organization's admins are admins in each of its
children without belonging to them, and open one from the parent's
Child organizations list. A remembered (or `refresh`-named) organization
the list does not hold is read once with `stigmer.organization.get()`:
answered, it stays active; refused (the person can no longer read it,
or it is gone), the first listed organization is selected; any other
failure is the provider's `error`, so the person is never moved quietly
into another organization.

Must be rendered inside a [`StigmerProvider`](/docs/sdk/react/core#stigmerprovider). Mount it BELOW
`FetchCacheProvider` (when one is used): switching the active org clears
the nearest fetch cache, so view state cached under the previous org
context — session and run entries are keyed by id, not org — can
never bleed into the new one. Navigation on switch stays the host's
responsibility via `OrgSwitcher`'s `onOrgChanged` callback.

```tsx
<StigmerProvider client={client}>
  <FetchCacheProvider>
    <OrgProvider>
      <App />
    </OrgProvider>
  </FetchCacheProvider>
</StigmerProvider>
```

### OrgSwitcher

}
