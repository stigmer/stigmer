## Hooks

### useChannelAgentProfile

Data hook that fetches a chat link's agent profile by the web
channel's id, the one identity a hosted chat link carries
(`/chat/<channel id>`). The profile names the agent's organization
(`org`) and slug.

By default this hook calls the channel's `getAgentProfile` endpoint, which is
**public** — it requires no authentication. The server returns a
trimmed projection safe for anonymous visitors: name, description,
icon, and the channel's agent reference (version included) a session
starts on (a name, not a capability — session creation still requires
an authorized token, e.g. a guest token from `createGuestAuth`).
With `{ audience: "org" }` it calls the authenticated
`getAgentProfileForMember` endpoint instead, which resolves
org-members-only web channels for a signed-in member.

**Unanswered-link handling:** the server answers NOT_FOUND for "this
agent does not exist", "this chat link is off", and (on the
member path) "you are not a member of this organization" — all
indistinguishable by design so a chat URL leaks nothing. The hook
maps that to `profile === null` without raising an error, matching
`useAgent`'s not-found convention:
`profile === null && !isLoading && !error` means unavailable.

Pass `null` for `channelId` to skip fetching (stable no-op) — useful
while route params are still resolving.

**Note**: Although authentication is not required by the server,
the hook still requires a `StigmerProvider` ancestor because it
needs the transport configuration (API base URL) to make the
request.

### useChatLinkToolReadiness

Chat-link wrapper over [`useToolCredentialsReadiness`](/docs/sdk/react/vault#usetoolcredentialsreadiness): checks
whether a tool-using agent's credentials will work for a chat link's
visitors — i.e. whether the link names vaults (`vaults`) and each
one is a shared vault.

The check runs only when the link is enabled with a public audience
(org-audience links reject bindings at the proto boundary), the

### useRotateChannelLink

Behavior hook that rotates a web channel's chat-link token.

Wraps the `stigmer.channel.rotateLink()` RPC (authorized by the
channel's `can_edit`) with loading and error state management. The
server generates the token — there is nothing to supply — and the
previous link stops working the moment the call resolves, including
for visitors mid-conversation. The token lives in the web arm of
`status.typeStatus` (server-owned; this RPC is its sole writer), so it
is never part of a draft and survives every apply.

The hook is stateless with respect to the channel — adopt the returned
channel (or refetch) so the UI shows the new tokened link, matching the
`useSaveChannel` convention.

Pass `null` for `channelId` to produce a stable no-op (useful while the
channel is still loading, or before the agent has a chat link — there
is no token to rotate until a web channel exists).

## Components

### ChatLinkDialog

The dialog for one chat link of an agent: create it (name/slug step), then
toggle serving, copy the hosted chat link, copy an embeddable snippet,
manage allowed embed origins, bind tool credentials for visitors,
customize visitor refusal messages, and discover how to sign a
product's own users in through the SDK.

A chat link is a distinct consent from marketplace visibility:
visibility governs who can *read* the blueprint; a chat link governs who
can *chat* with the running agent — billed to the org that owns the
link. The dialog states who pays before creation and next to the
toggle, so a link never surprises.

A chat link is a **web Channel** (the `web` type of the Channel kind), and
an agent can carry N of them — each with its own URL, audience,
origins, credentials, and link token. The dialog edits exactly the
channel it is given; it never resolves "the" chat link of an agent. A
create is a strict create (`useCreateChannel`); every later save names
the complete draft on the channel as loaded (`useSaveChannel`), and
the local draft is refreshed from every returned channel, so the
dialog never drifts from the server.

Built on the native `<dialog>` element for focus trapping and escape
handling, matching the SDK's modal convention ([`ManageAccessDialog`](/docs/sdk/react/access#manageaccessdialog)).
All visual properties flow through `--stgm-*` design tokens.

Most hosts mount it via [`ChannelsPanel`](/docs/sdk/react/channel#channelspanel) (the agent's Channels tab).
Render it directly only when you own the open-state.

### VisitorChat

The complete chat experience for a chat link's visitors —
the organism behind an agent's hosted chat page and embeds.

Resolves the agent's public profile (name, description, icon, and
the channel's agent reference) via [`useChannelAgentProfile`](#usechannelagentprofile), then
renders the session organisms with `audience="guest"`: a pure chat
surface with no configuration pickers, pinned to the channel's agent
reference exactly as the profile gives it, version included, so the
session binds synchronously on mount and runs the version the channel
names.

Handles all states: loading, unavailable (the agent does not exist
or its link is off — indistinguishable by design), transient errors
(with retry), and the live chat.

**Auth contract:** requires a `StigmerProvider` whose client can
chat with this agent. For public chat links (the default), pair with
`createGuestAuth({ baseUrl, channelId })` from `@stigmer/client` —
the profile fetch is public and sessions use the guest token the
provider mints on demand. For org-members-only chat links, pass
`linkAudience="org"` and a client carrying the signed-in
member's own token; the presentation stays the same pure chat.

## Types

### ChatLinkAudience

Who can chat with an agent over its hosted chat link.

- `"public"` — anyone with the link; visitors are anonymous guests.
- `"org"` — signed-in members of the owning organization only.
  Membership is checked on every conversation turn, so access ends the
  moment a member leaves the org.


### chatLinkAudienceFromProto

Maps a proto `ChannelAudience` to the SDK's string union.
Only an explicit public audience is "public": unspecified means the
organization's members by contract, so a chat link reaches the internet
only when someone chose "Anyone with the link".

### webChannelCreateInput

The SDK input that creates `agent`'s web channel from a draft. The
channel lives in the agent's own organization: its URL, billing and
credential bindings all belong to the organization that owns the agent,
and the server refuses an `agent_ref` in any other. To give people a chat
link to another organization's agent, install the plugin that carries
it and make the link on the installed copy.

Without an identity the server names the channel: slug
`<agent slug>-web`, name `<agent name> (Web)`.

```tsx
function webChannelCreateInput(agent: Agent, draft: WebChannelDraft, identity?: WebChannelCreateIdentity): ChannelInput
```

```tsx
const { createChannel } = useCreateChannel();
const created = await createChannel(
  webChannelCreateInput(agent, { ...draftFromWebChannel(null), enabled: true }, { name, slug }),
);
```

### webChannelPatch

The edit a draft makes to a web channel, for `useSaveChannel().update`:
the fields named (every draft field when `fields` is omitted) and no
other, so a teammate's change to another field stays. The web settings
are named one by one (`spec.web.audience`, `spec.web.allowed_origins`,
`spec.web.messages`), never the web arm whole.

```tsx
function webChannelPatch(draft: WebChannelDraft, fields?: readonly keyof WebChannelDraft[]): Partial<ChannelInput>
```

```tsx
const { update } = useSaveChannel();
const persisted = await update(channel, webChannelPatch(draft));
// the web arm of persisted.status.typeStatus carries the live link token
```
