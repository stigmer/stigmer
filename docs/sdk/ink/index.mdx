`@stigmer/ink-ui` provides terminal UI components for rendering Stigmer agent
sessions in the terminal. It is built on [Ink](https://github.com/vadimdemedes/ink)
(React for CLIs) and shares its hook layer with `@stigmer/react-sdk`: both are
built on `@stigmer/react-core`, so the hooks for sessions, runs, streaming and
approvals work identically, without the browser kit's components.

The package includes a provider, pre-built components for every part of a
session (message threads, tool calls, approvals, progress indicators, todo
lists, usage), and two composed views that assemble them into a complete
terminal experience.

## Installation

```bash
npm install @stigmer/ink-ui @stigmer/react-core @stigmer/client @stigmer/apis @bufbuild/protobuf ink react
```

`ink` and `react` 19+ are peer dependencies, and so is `@stigmer/react-core`,
the hooks the kit's views and your own read, so both share one copy.
`@stigmer/apis` provides the protocol buffer types. `@bufbuild/protobuf` is its
runtime dependency.

## Quick start

Send a message to an agent, show its work in the terminal, and get control back
when the turn ends:

```ts
import { createNodeClient, runInTerminal } from "@stigmer/ink-ui";

const client = createNodeClient({
  baseUrl: process.env.STIGMER_BASE_URL ?? "http://localhost:7234",
  apiKey: process.env.STIGMER_API_KEY,
});
const outcome = await runInTerminal(client, {
  org: "acme",
  sessionSpec: { agentRef: { org: "acme", slug: "release-checker" } },
  message: "Check v2.3 is safe to ship",
});
process.exitCode = outcome.exitCode;
```

The agent's messages, tool calls and approvals stream as `stigmer run` shows
them, and the approvals take `y`, `a` or `n`. `runInTerminal` resolves with the
turn's outcome (`phase`, `answer`, `structuredOutput`, `error`, the folded
`turn`) and an exit code from the table in
[Embed in your CLI](/docs/sdk/ink/cli-integration). Its options:

| Option | Default | What it does |
|--------|---------|--------------|
| `until` | `"turn"` | `"exit"` keeps the conversation open for follow-ups until Ctrl+C. |
| `approveDefault` | `"deny"` | How approvals are settled off a terminal, where no one can answer. |
| `approveSetting` | `approveDefault: "approve"` | The setting the view names when it settles one; pass your own flag, such as `--yes`. |
| `theme` | Stigmer's | Your colours by role (below). |
| `signal` | none | Stops waiting at once; the run goes on, and the exit code is 130. |
| `mode` | `"agent"` | `"plan"` for read-only follow-ups. |

A turn that cannot start (no server, a refused key) is written to stderr in
words a person can act on, and the promise rejects with a `TerminalRunError`
that carries the exit code. The library installs no signal handlers: stop it
with `signal`.

To watch a session you already have, render `SessionApp`:

```tsx
import { render } from "ink";
import { SessionApp } from "@stigmer/ink-ui";

render(
  <SessionApp
    sessionId="ses-abc123"
    org="my-org"
    baseUrl="https://api.stigmer.ai"
    apiKey={process.env.STIGMER_API_KEY}
  />
);
```

## On a terminal and off one

`terminalMode` decides two things before anything renders. The screen is live
when stdout is a terminal, `TERM` is not `dumb` and `CI` is unset. A person can
answer when the screen is live and stdin is a terminal too.

Off a terminal the view is read-only: nothing reads keys, the final frame is
written once when the turn ends, each approval is settled by `approveDefault`
(denied unless you say otherwise, and the view says which), and a file review
waits for a terminal. `SessionView` takes the same decision as its `canAnswer`
prop, and reads Ink's own raw-mode support when you leave it out.

## Colours

The kit draws Stigmer's look: black and white, with colour only for success,
warnings and errors. Pass your own by role, to `runInTerminal` or the provider:

```tsx
<InkStigmerProvider client={client} theme={{ accent: "magenta" }}>
```

The roles are `accent` (prompts, the selected row, spinners), `muted`,
`success`, `warning` and `danger`; each takes an Ink colour name or a hex value.
Your own components read them with `useInkTheme()` or `useRoles()`.

Replies are drawn in weight alone (bold, italic, dim, underline), with no
colour, so they read on a light and a dark terminal. If your own colours differ
between the two, pass the theme as a function of the background:

```tsx
await runInTerminal(client, input, {
  theme: (background) => ({ accent: background === "light" ? "#5b21b6" : "#c4b5fd" }),
});
```

`runInTerminal` asks the terminal for its background (an OSC 11 query, at most
100 ms, falling back to `COLORFGBG`) only when the theme is a function. With your
own provider, call `detectBackground()` first and pass its answer as the
provider's `background`.

## What the session draws

What can no longer change is written once into the terminal's scrollback: the
person's message, each finished block of a reply, a tool group whose calls
returned, a finished subagent. Only what is still changing redraws in place, so
a long turn never clears the screen or the scrollback above it. What is being
written follows a resize; what is already in the scrollback keeps the width it
was written at.

Thinking shows as one dim line, "✻ Thinking" while it streams and "✻ Thought"
once done; Ctrl+O shows all of it. Just above the reply box, `WorkingLine` says
what the turn is doing and for how long ("⠋ Running a command · 1m 12s"), from
the same `describeTurnActivity` the browser's activity line reads. A completed
turn leaves "✻ Worked for 1m 12s"; a failed or stopped one keeps its badge.

## Provider and transport

For more control, create the client yourself and wrap your tree in
`InkStigmerProvider`:

```tsx
import { render } from "ink";
import { InkStigmerProvider, createNodeClient } from "@stigmer/ink-ui";

const client = createNodeClient({
  baseUrl: "https://api.stigmer.ai",
  apiKey: process.env.STIGMER_API_KEY,
});

render(
  <InkStigmerProvider client={client}>
    {/* your terminal components */}
  </InkStigmerProvider>
);
```

`InkStigmerProvider` provides the same React contexts as `StigmerProvider` from
`@stigmer/react-sdk`, but without the DOM `<div>` wrapper used for CSS scoping
(terminals do not need it).

`createNodeClient` uses `@connectrpc/connect-node` for native HTTP/2 transport.
It is re-exported from `@stigmer/client/node` for convenience.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `client` | `Stigmer` | — | Configured SDK client instance. Required. |
| `deploymentMode` | `"local" \| "cloud"` | `"cloud"` | Backend deployment mode. Controls feature availability. |
| `theme` | `Partial<InkTheme>` | Stigmer's | Colours by role, over the monochrome default. |
| `children` | `ReactNode` | — | Application tree. |

## Using the conversation hooks

Every hook `@stigmer/react-core` exports works under `InkStigmerProvider`. This
is the main reason to choose `@stigmer/ink-ui` over building a terminal UI from
scratch: you get the complete data layer for free.

```tsx
import { useSessionConversation } from "@stigmer/react-core";
import { InkStigmerProvider, createNodeClient } from "@stigmer/ink-ui";
import { Box, Text } from "ink";

function MySessionView({ sessionId, org }: { sessionId: string; org: string }) {
  const conv = useSessionConversation(sessionId, org);

  if (conv.isLoading) return <Text>Loading...</Text>;

  // Each turn is the session's events folded; its answer is the text of the
  // agent's last message.
  const lastAnswer = conv.turns.at(-1)?.answer ?? "";

  return (
    <Box flexDirection="column">
      <Text>{lastAnswer || "No messages yet"}</Text>
    </Box>
  );
}
```

The [React SDK Reference](/docs/sdk/react) documents these hooks, because the
React kit re-exports them; hooks that belong to the React kit's components are
not in `@stigmer/react-core`. A hook reads data from the same `StigmerContext`
and `DeploymentModeContext` that `InkStigmerProvider` provides.

## Composing custom views

When `SessionApp` or `SessionView` do not fit your layout, compose the
individual components directly:

```tsx
import { render } from "ink";
import {
  InkStigmerProvider,
  createNodeClient,
  MessageThread,
  WorkingLine,
  FollowUpInput,
} from "@stigmer/ink-ui";
import { useSessionConversation } from "@stigmer/react-core";
import { Box } from "ink";

function CustomView({ sessionId, org }: { sessionId: string; org: string }) {
  const conv = useSessionConversation(sessionId, org);

  return (
    <Box flexDirection="column">
      <MessageThread
        turns={conv.turns}
        runs={conv.runs}
        onAnswerToolUse={conv.answerToolUse}
        answeringToolUseIds={conv.answeringToolUseIds}
      />
      {conv.activePhase != null && (
        <WorkingLine turn={conv.activeTurn} isSlow={conv.isSlow} isStopping={conv.isStopping} />
      )}
      <FollowUpInput
        onSubmit={(msg) => conv.sendFollowUp(msg)}
        isSubmitting={conv.isSending}
        disabled={!conv.canSendFollowUp}
      />
    </Box>
  );
}
```

Every component listed in the [Reference](/docs/sdk/ink/reference) can be used
independently. `MessageThread` builds the full conversation thread.
`MessageEntry` renders a single message and `Markdown` a markdown text.
`ToolCallGroup` and `ToolCallItem` handle tool call display. `ApprovalPrompt`
renders the HITL approval UI.

## CLI integration

A tool in another language spawns the package's binary, `stigmer-ink`, and reads
its exit code:

```bash
stigmer-ink --agent acme/release-checker --message "Check v2.3 is safe to ship"
```

It reads the key from `STIGMER_API_KEY`. See
[Embed in your CLI](/docs/sdk/ink/cli-integration) for a bridge in Go, Python
and Rust, run as written against a local server.
