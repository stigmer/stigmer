  Run a Stigmer agent from a Go, Python or Rust command-line tool with the

---

`@stigmer/ink-ui` ships a binary, `stigmer-ink`, that runs one agent turn in the
terminal and exits with how it ended. Your tool spawns it as a child process,
hands it the terminal, and reads its exit code. It works from any language that
can spawn a process, and it needs nothing from your language but that.

A JavaScript or TypeScript tool can skip the child process and call
`runInTerminal` from the same package: see the
[package README](https://github.com/stigmer/stigmer/tree/main/sdk/ink#readme).

**Prerequisites**: Node.js 18 or later on the machine that runs your tool, and a
Stigmer server. This page uses the one `stigmer up` starts on your machine; the
[quickstart](/docs/getting-started/quickstart) sets it up.

## What the binary does

`stigmer-ink --agent <org>/<slug> --message <text>` starts a new conversation
with the agent, shows its work as `stigmer run` does, and exits when the turn
ends:

- On a terminal, the agent's approvals are prompts: `y` approves, `a` approves
  that kind of action for the rest of the turn, `n` denies.
- Off a terminal (a pipe, a CI log) it prints the conversation once, at the end,
  and denies every approval, saying so. `--approve-default approve` approves
  them instead; use it only for an agent you trust to run unattended.
- `--session <id> --org <org> --message <text>` sends into a conversation you
  already have, and `--session <id> --org <org>` alone watches one until you
  press Ctrl+C.

It reads the API key from `STIGMER_API_KEY` and the server from
`STIGMER_BASE_URL` (default `http://localhost:7234`). Keep the key in the
environment: `--api-key` works, but every user of the machine can read a
process's arguments.

| Exit code | Meaning                                                   |
| --------- | --------------------------------------------------------- |
| 0         | The turn completed                                        |
| 1         | The turn failed, was cancelled or was terminated          |
| 2         | Usage: the arguments were wrong                           |
| 3         | Cannot connect to the server                              |
| 4         | Not signed in, or not allowed                             |
| 5         | The session or agent was not found                        |
| 130       | Interrupted: Ctrl+C, or SIGINT or SIGTERM sent to it      |

These are the `stigmer` CLI's codes too.

## Install it and start a server

```bash
npm install --global @stigmer/ink-ui
stigmer-ink --help
```

Start Stigmer with your model key in the shell:

```bash
export ANTHROPIC_API_KEY=<your Anthropic API key>
stigmer up
```

## Create the agent

The bridges below run an agent that checks a release. Create
`release-checker.yaml`:

```yaml title="release-checker.yaml"
apiVersion: agentic.stigmer.ai/v1
kind: Agent
metadata:
  name: release-checker
spec:
  description: Checks that a release is safe to ship.
  instructions: |
    You check a release before it ships. Run the project's checks with the
    shell, then say in one line whether the release is safe to ship and why.
```

Send it to Stigmer:

```bash
stigmer apply -f release-checker.yaml
```

The agent runs commands, so each one waits for a person to approve it: on a
terminal you see the prompt, and off one the binary denies it.

## Go

```go title="go.mod"
module releasecheck

go 1.22
```

```go title="main.go"
package main

import (
	"errors"
	"os"
	"os/exec"
	"strings"
)

func main() {
	message := strings.Join(os.Args[1:], " ")
	cmd := exec.Command("stigmer-ink",
		"--agent", "stigmer/release-checker",
		"--message", message)
	// The child takes the terminal; the key and server come from the environment.
	cmd.Stdin, cmd.Stdout, cmd.Stderr = os.Stdin, os.Stdout, os.Stderr
	err := cmd.Run()
	var exit *exec.ExitError
	if errors.As(err, &exit) {
		code := exit.ExitCode()
		if code < 0 { // stopped by a signal
			code = 130
		}
		os.Exit(code)
	}
	if err != nil {
		os.Stderr.WriteString("could not start stigmer-ink: " + err.Error() + "\n")
		os.Exit(1)
	}
}
```

```bash
go run . Check v2.3 is safe to ship
```

## Python

```python title="bridge.py"
import subprocess
import sys

message = " ".join(sys.argv[1:])
# The child takes the terminal; the key and server come from the environment.
result = subprocess.run(
    ["stigmer-ink", "--agent", "stigmer/release-checker", "--message", message]
)
# A child stopped by a signal has a negative return code.
sys.exit(130 if result.returncode < 0 else result.returncode)
```

```bash
python3 bridge.py Check v2.3 is safe to ship
```

## Rust

```toml title="Cargo.toml"
[package]
name = "release-check"
version = "0.1.0"
edition = "2021"
```

```rust title="src/main.rs"
use std::process::{exit, Command};

fn main() {
    let message = std::env::args().skip(1).collect::<Vec<_>>().join(" ");
    // The child takes the terminal; the key and server come from the environment.
    let status = Command::new("stigmer-ink")
        .args(["--agent", "stigmer/release-checker", "--message", &message])
        .status()
        .unwrap_or_else(|err| {
            eprintln!("could not start stigmer-ink: {err}");
            exit(1)
        });
    exit(status.code().unwrap_or(130));
}
```

```bash
cargo run --quiet -- Check v2.3 is safe to ship
```

A child stopped by a signal has no exit code of its own, so each bridge exits
130 for it, as the table says.

## Against Stigmer Cloud

Point the binary at the hosted API and an agent in your Organization, with a key
you created there:

```text
export STIGMER_BASE_URL=https://api.stigmer.ai
export STIGMER_API_KEY=stk_...
stigmer-ink --agent your-org/release-checker --message "Check v2.3 is safe to ship"
```

## When the binary is not enough

The binary shows Stigmer's terminal view and nothing else. To put the
conversation inside your own frame, or to read the turn's answer and structured
output in code, write the tool in TypeScript with `runInTerminal`, or compose
the components yourself: [Ink SDK](/docs/sdk/ink).
