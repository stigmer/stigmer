### InkStigmerProvider

Stigmer provider for Ink (terminal) environments.

Provides the same React contexts as `StigmerProvider` from
`@stigmer/react-sdk`, but without the DOM `<div>` wrapper used for
CSS scoping (which is not applicable in a terminal).

### createNodeTransport

Re-exported from `@stigmer/client/node`. See [SDK Overview](/docs/sdk/overview) for full documentation.

Create a Node.js transport (gRPC-web by default, native gRPC opt-in).

The interceptor chain matches the browser transport for consistent
behavior across runtimes:
1. Auth — attaches `Authorization: Bearer <token>`
2. RPC metadata — annotates errors with method name and service path
3. Error strip — removes gRPC status-code prefixes from messages

The browser-specific auth-redirect interceptor (`onUnauthenticated`)
is intentionally omitted — Node.js consumers handle auth failures
through error handling, not UI redirects.

The wire protocol is chosen by `NodeClientConfig.protocol`
(default `"grpc-web"` over HTTP/2); pass `"grpc"` for native gRPC when
dialing a gRPC endpoint directly.

### ApprovalPrompt

HITL approval prompt for a tool use that waits for a person.

Displays the tool, its intent and sanitized arguments, then presents
Approve / Approve all / Deny, navigable via arrow keys or shortcut keys
(y/a/n). Enter confirms the highlighted option. Approve all (a) grants the
call's CLASS for the rest of the turn (its MCP server, or its file edit /
delete / shell category) — other classes keep asking; the label names that
class. Deny (n) opens a one-line reason the agent reads: Enter sends it
(empty sends none), Esc goes back.

### blockReasonNote

The honest, one-line reason a file cannot be kept as-is, or `null` when it
is fully reviewable. Mirrors the web card's per-file block-reason copy so

### changeSetLineStats

Sums a set's per-file `linesAdded`/`linesRemoved` into one aggregate, for
the set-level `+N −M` beside the prompt header and the settled record
summary. Counts every file regardless of verdict — it reports what
changed, not what was kept. A file with no counts (binary,
secret-withheld) contributes zero, so the aggregate honestly understates
rather than guessing.


### FileChangeProgressBar

The terminal analogue of the web's non-interactive "N files changing…" strip
(`@stigmer/react-sdk` `FileChangeProgressBar`), for a turn that is still running.

WHY IT EXISTS. The transcript streams per-edit tool rows, but a change made by
a shell command (a `sed`, a build step) has no tool row, and there is no
running net-of-many-edits rollup until the turn ends. This strip fills that
gap: a compact, non-interactive count of the workspace delta accumulating
during the turn, sitting where the `FileReviewPrompt` will later appear. The
two are mutually exclusive per turn (progress shows while CAPTURING; the prompt
once AWAITING_REVIEW), so the strip hands off cleanly to the prompt.

NEVER A DECISION SURFACE. Progress is non-authoritative and carries no file
bodies — it is never reviewable or decidable, and it owns no keyboard input.
The reviewed diff is the turn-boundary candidate (`FileReviewPrompt`). A
secret-like path is surfaced by name with its counts withheld (zeroed), so the
`+N −M` stat renders nothing for it. The quiet/dim register (no border)
distinguishes it from the loud, bordered decision prompt.

### FileDiffBody

The terminal analogue of `@stigmer/react-sdk`'s `FileChangeDiff` — the whole-file
branch. Renders a single `CapturedFileChange`'s unified diff for review in the
terminal.

A capture is always whole-file (the candidate carries the byte-exact
before and after), so this handles only that case: it resolves the before/after text via the shared `useFileChangeContent` behavior
hook (inline bodies cost nothing; offloaded bodies are fetched lazily through
the server proxy) and diffs them with the shared pure `computeDiff` — the SAME
engine the web renders, so the terminal and web diffs are line-for-line
identical and cannot drift.

Renders body-only (no filename caption): the caller's selected row already
names the file and shows its `+N −M`, so a header here would just repeat what
the reviewer read one line up.

**Requires an `InkStigmerProvider` ancestor.** `useFileChangeContent` reads the
Stigmer client via `useStigmer()` (to dereference offloaded diff bytes), which
throws outside a provider. In a live session this always holds — `SessionView`
renders under `InkStigmerProvider`.

The `+N −M` stat for one file (or a whole set), in the diff colour vocabulary.

### FileReviewPrompt

The terminal file-review decision surface — the linear-log analogue of the
web's composer-docked `FileReviewDock`/`FileReviewCard`.

Renders `N files awaiting review` and, gated by `changeSetReviewability`:
bulk Approve/Keep all + Reject all (a complete set is keepable as-is; a
binary-only set is kept with an acknowledgement; a blocked set can only be
undone in bulk), plus a per-file mode (`f`) for keeping/discarding each file
— the only way to resolve a blocked or mixed set, since the server refuses a
whole-set keep unless every file is complete. Decisions carry the same
digests (the set's aggregate digest / the file's digest) and the
acknowledgement semantics as the web.

Keyboard: `a` approve/keep all · `r` reject all · `f` per-file mode; in
per-file mode ↑/↓ move, `k` keep, `d` discard, `esc` back. Input is gated by
`isActive` so only one decision surface owns the keyboard at a time.

### MessageThread

Renders a continuous conversation thread from a session's folded turns in

Composes `MessageEntry`, `ToolCallGroup`, `SubagentBlock`,

  }}
/>

## Utilities

### renderMarkdown

Render a markdown string to ANSI-styled terminal output.

Uses `marked` with `marked-terminal` to produce styled text suitable
for display in a terminal. Supports headings, code blocks (with syntax
highlighting), lists, bold/italic, links, tables, and blockquotes.

```tsx
import { renderMarkdown } from "@stigmer/ink-ui";

const ansi = renderMarkdown("**Hello** from the agent!");
process.stdout.write(ansi);
```
