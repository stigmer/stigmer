Start and manage the Stigmer server in local mode.

Running `stigmer server` starts all the components needed to run agents locally:
the Stigmer server, Temporal (for durable execution), and the agent-runner. On
first run, an interactive setup wizard prompts you to choose an LLM provider
(Anthropic, OpenAI, or Ollama).

The server listens on `localhost:7234` and includes an embedded web console you
can open with `--open` or by visiting `http://localhost:7234` in your browser.

## Usage

```bash
stigmer server [flags]
```

### Common patterns

```bash
# Start the server (interactive setup on first run)
stigmer server

# Start and open the web console
stigmer server --open

# Start in sandbox execution mode
stigmer server --execution-mode sandbox

# Start without the embedded web console
stigmer server --no-web
```

### Execution modes

Control how agents execute on your local server:

| Mode      | Behavior                                                 |
| --------- | -------------------------------------------------------- |
| `local`   | Agents run directly on the host machine (default)        |
| `sandbox` | Agents run in isolated Docker containers                 |
| `auto`    | Use sandbox when Docker is available, fall back to local |

```bash
# Run agents in sandboxed containers
stigmer server --execution-mode sandbox

# Use a custom sandbox image
stigmer server --execution-mode sandbox --sandbox-image my-custom:latest
```

### Sandbox options

When using sandbox execution mode, these options control container behavior:

| Flag                  | Default                                      | Purpose                                 |
| --------------------- | -------------------------------------------- | --------------------------------------- |
| `--sandbox-image`     | `ghcr.io/stigmer/agent-sandbox-basic:latest` | Docker image for sandbox containers     |
| `--sandbox-auto-pull` | `true`                                       | Pull the image automatically if missing |
| `--sandbox-cleanup`   | `true`                                       | Remove containers after execution       |
| `--sandbox-ttl`       | `3600`                                       | Container reuse TTL in seconds          |

## Examples

### First-time setup

```bash
stigmer server
```

The setup wizard guides you through choosing an LLM provider and entering your
API key. Configuration is saved to `~/.stigmer/config.yaml`.

### Restart with a different execution mode

```bash
stigmer server stop
stigmer server --execution-mode sandbox
```

### Check server status

```bash
stigmer server status
```

Shows whether the server is running, its PID, and the configured LLM provider.

### Reconfigure the LLM provider

```bash
stigmer server setup
```

Re-runs the LLM provider setup wizard without restarting the server.

### Reset to a fresh state

```bash
stigmer server reset
```

Stops the server, clears all local data, and restarts with a clean state. Use
this when you want to start over.

### stigmer server logs

View logs from the Stigmer server daemon.

By default, streams logs in real-time from all components (like kubectl logs
-f). Use --follow=false to disable streaming and only show recent logs. Use
--tail to limit how many existing lines to show before streaming (default: 50).
Use --stderr to view error logs (note: stigmer-server logs go to stderr by
default). Use --component to select a specific component (stigmer-server,
agent-runner, or workflow-runner). Use --all to view logs from all components in
a single interleaved stream (defaults to stderr).

```bash
stigmer server logs [flags]
```

| Flag                | Type     | Default          | Description                                                                   |
| ------------------- | -------- | ---------------- | ----------------------------------------------------------------------------- |
| `--all`             | `bool`   | `true`           | Show logs from all components (interleaved by timestamp, defaults to stderr)  |
| `--component`, `-c` | `string` | `stigmer-server` | Component to show logs for (stigmer-server, agent-runner, or workflow-runner) |
| `--follow`, `-f`    | `bool`   | `true`           | Stream logs in real-time (like kubectl logs -f)                               |
| `--stderr`          | `bool`   |                  | Show stderr logs instead of stdout (note: stigmer-server logs go to stderr)   |
| `--tail`, `-n`      | `int`    | `50`             | Number of recent lines to show before streaming (0 = all lines)               |

### stigmer server reset

Stop all services and remove all persistent state — the SQLite database, skill
artifacts, sessions, runtimes, Temporal state, logs, and downloaded binaries —
then automatically restart the server fresh.

Configuration (config.yaml) is preserved by default. Use --include-config to
also remove it; the setup wizard will run again on next start.

```bash
stigmer server reset [flags]
```

| Flag               | Type   | Default | Description                                               |
| ------------------ | ------ | ------- | --------------------------------------------------------- |
| `--force`          | `bool` |         | Skip confirmation prompt                                  |
| `--include-config` | `bool` |         | Also remove configuration (API keys, backend preferences) |

### stigmer server setup

Run the interactive setup wizard to configure your LLM provider.

This re-runs the same wizard shown on first startup. Use it to switch between
Anthropic, OpenAI, Ollama, or to add an API key after skipping initial setup.

After changing the provider, restart the server to apply: stigmer server stop &&
stigmer server

```bash
stigmer server setup
```
