Install a plugin from a source by name.

`stigmer install` takes the name of a plugin in a source, reads the plugin's
folder from that source's tree, and pushes it to your organization exactly as
`stigmer push plugin <dir>` would push the same folder from disk. Stigmer
materializes the plugin's skills, MCP servers, agent and workflows as one unit;
a plugin installs as an agent, as tools for your agents, or both. Installing
again with a changed plugin upgrades it, and installing an unchanged one changes
nothing.

## Usage

```bash
stigmer install <ref> [flags]
```

### Common patterns

```bash
# Install from the official catalogue by name
stigmer install linear

# Install from a source you added, naming it
stigmer install acme-plugins/thermos

# Pin the version the source must offer
stigmer install acme-plugins/thermos@1.0.0

# See what would install, without pushing
stigmer install acme-plugins/thermos --dry-run

# Install into a specific organization, visible to the whole org
stigmer --org my-org install acme-plugins/thermos --visibility org
```

### What the install leaves to do

The output ends with a `Next` section, one line per MCP server the plugin
installed: a server that signs in with OAuth and has no sign-in in your
organization yet names the command that runs it
(`stigmer connect mcp-server <server>`, which opens the console's sign-in and
waits for it); a server already signed in says so; a server that wants an API
key names the variables and where they are asked (the agent's first session when
the plugin installed an agent, `stigmer connect mcp-server <server> --env`
otherwise). A plugin that installed tools and no agent ends with the one thing
still missing: an agent that lists the servers under `mcp_server_usages`, or the
plugin's page in the console, whose **Add to an agent** does it. Under `--json`
the same facts are `data.next`.

### The ref

A ref is `[marketplace/]name[@version]`.

- **`name`** is the plugin's name in the marketplace file, the same characters a
  plugin name allows (lowercase letters, digits, `.` and `-`).
- **`marketplace/`** names one of your configured sources
  (`stigmer marketplace list`). Without it, every configured source is searched
  and the name must be offered by exactly one; when two offer it, the command
  refuses and names both, so the answer never depends on the order you added
  them in.
- **`@version`** asserts the version the plugin's manifest declares. A source's
  tree holds one version of each plugin, so the ref either names it or is
  refused with the version on offer.

A path (`./thermos`, `/tmp/plugin`) is not a ref: install a folder with
`stigmer push plugin <dir>`.

### What a source is

A source is a directory tree with a marketplace file at its root: the convention
Cursor (`.cursor-plugin/marketplace.json`), Claude Code
(`.claude-plugin/marketplace.json`) and Codex
(`.agents/plugins/marketplace.json`) publish, and Stigmer's own
(`marketplace.json`). `stigmer install` reads all four. Stigmer's official
catalogue is the one built-in source; add your own with
`stigmer marketplace add`.

Nothing on the server records which source a plugin came from: a plugin is
identified by its name in your organization, so installing `thermos` from a
second source upgrades the `thermos` you installed from the first.

### Removing

There is no `uninstall`. `stigmer delete plugin <name>` removes the plugin and
everything it installed, the one delete verb across kinds.
