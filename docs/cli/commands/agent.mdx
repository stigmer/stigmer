Evaluate an agent with the `evals/` test cases of the plugins it uses, and read
how its runs are graded.

`stigmer agent eval` runs the cases in the `evals/` folder of every plugin an
agent uses on the agent itself, with its own instructions, Skills and subagents.
Each plugin's cases run at the version the agent uses it at, several times each,
in one arm: the agent with all its plugins, with no without-plugin comparison.
Each case gets a score and whether every try passed (`PASS^k`), and every try is
a conversation. The eval is stamped with the agent's version, so two versions'
results compare case by case.

The agent is one in your organization, named as `support-desk`,
`acme/support-desk` or its ID, and runs at its current version;
`support-desk@<version>` runs the version with that tag or version hash. With no
`--model`, each case runs on the agent as it runs: its own engine, model and
settings. A model named with `--model` runs without the agent's own tier and
thinking settings, as any conversation that names a model does. A try gets only
the tools its case and `--allow-tools` grant, within the agent's own: name the
agent's working tools there (`--allow-tools Skill Agent`).

## Usage

```bash
stigmer agent
```

### Common patterns

```bash
# Run every plugin's cases three times on the agent as it runs
stigmer agent eval support-desk

# Run a tagged version, and only one plugin's cases, five times each
stigmer agent eval support-desk@v3 --plugin refund-policy --runs 5

# Let the tries use the agent's Skills and subagents (name the agent first)
stigmer agent eval support-desk --allow-tools Skill Agent

# Write the result document for a script, and gate on the exit code
stigmer agent eval support-desk --json results.json

# Start and return; read it later
stigmer agent eval support-desk --no-wait
stigmer get agent-eval aev_01abc123

# Cancel a running eval
stigmer agent eval cancel aev_01abc123

# How the agent's runs were graded over the last 30 days, per version
stigmer agent quality support-desk

# The last week's failed grades, newest first
stigmer agent quality support-desk --days 7 --flagged --limit 50
```

### Output and exit codes

The command prints a line as each try finishes, then one table per plugin and
model, headed by the agent's slug and version hash, the plugin's slug and
version digest, and the model. A plugin whose cases did not run is listed under
its heading with the reason. The exit codes are those of
[`stigmer plugin eval`](/docs/cli/commands/plugin): 0 when every case that ran
reached the threshold, 1 when one did not, no case ran, or the eval could not
start, 2 for a partial run, 3 and 4 for a connection or sign-in failure, and 130
when the eval was cancelled. See
[Test an agent with its plugins' evals](/docs/guides/plugins/test-an-agent-with-its-plugins-evals)
for the versions that run, the tools a try may use, and the result file.

### How the agent's runs are graded

`stigmer agent quality` counts the grades of the agent's runs in your
organization over the last `--days` days (1 to 90, default 30, UTC): the
platform's run-health checks, the AI judge's rubrics where AI grading is on, and
people's thumbs. It prints the window's totals (the health and judge pass rates
with their counts, each rubric's, the thumbs up and down), then one row per
agent version, named by its tag or its short version hash. When newer checks or
rubrics replaced older ones within the window, only the current ones are
counted, and the output says older ones exist. `--flagged` lists the failed
grades of the runs you can open instead, newest first, with the names of the
failed checks or rubric items. `-o json` and `-o yaml` print the report, or the
flagged grades, as the API returns them.

## Subcommands

### stigmer agent eval

run the evals/ cases of the plugins an agent attaches, on the agent, and score
them

```bash
stigmer agent eval <agent> [flags]
```

| Flag                   | Type          | Default | Description                                                                                                                 |
| ---------------------- | ------------- | ------- | --------------------------------------------------------------------------------------------------------------------------- |
| `--allow-real-servers` | `bool`        |         | also start the plugins' real MCP servers that no mock answers                                                               |
| `--allow-tools`        | `stringArray` |         | tools every try may use beyond its case's own, in Claude Code's names (name the agent's working tools, as Skill and Agent)  |
| `--case`               | `string`      |         | run only the cases whose name matches this glob                                                                             |
| `--concurrency`, `-j`  | `string`      |         | tries running at once, 1 to 8 (default 1)                                                                                   |
| `--json`               | `string`      |         | print the result document, or write it to a path ending in .json; no progress or table                                      |
| `--judge-model`        | `string`      |         | the model AI-graded checks use (default: the platform's judge model)                                                        |
| `--max-cost-usd`       | `string`      |         | the most the eval may spend, in estimated US dollars (default 5)                                                            |
| `--mocks`              | `string`      |         | record answers MCP calls from the suites' mocks (the default); off runs every server for real                               |
| `--model`              | `string`      |         | run on this engine and model in place of the agent's own, as native/claude-sonnet-4-6 or cursor/gpt-5 (repeatable, up to 6) |
| `--no-scaffold`        | `bool`        |         | skip each case's scaffold script, listing such a case as not run                                                            |
| `--no-wait`            | `bool`        |         | start the eval, print its id, and return                                                                                    |
| `--plugin`             | `string`      |         | run only this plugin's cases; the agent must attach it (repeatable; default: every plugin it attaches)                      |
| `--real-mcp-servers`   | `bool`        |         | the same as --mocks off                                                                                                     |
| `--runs`               | `string`      |         | tries per case and model, 1 to 50 (default: each case's runs, else 3)                                                       |
| `--scaffold`           | `bool`        |         | accepted for Claude Code's command lines; a scaffold always runs, in the try's own sandbox                                  |
| `--tag`                | `stringArray` |         | run only the cases with any of these tags (repeatable)                                                                      |
| `--threshold`          | `string`      |         | the score from 0 to 1 a case needs to pass (default 1)                                                                      |

### stigmer agent quality

show how an agent's runs in your organization were graded (run health, the AI
judge, people's thumbs), in total and per version

```bash
stigmer agent quality <agent> [flags]
```

| Flag             | Type     | Default | Description                                                                                                      |
| ---------------- | -------- | ------- | ---------------------------------------------------------------------------------------------------------------- |
| `--agreement`    | `bool`   |         | show, per AI judge rubric, how its verdicts compare with people's thumbs on the same runs, instead of the totals |
| `--days`         | `string` |         | days to count, ending today (UTC), 1 to 90 (default 30)                                                          |
| `--flagged`      | `bool`   |         | list the failed grades of the runs you can open, newest first, instead of the totals                             |
| `--limit`        | `string` |         | with --flagged, the most failed grades to list (default 20; 0 lists them all)                                    |
| `--output`, `-o` | `string` |         | output format: table, json, or yaml                                                                              |
