Execute an agent by reference, or browse agents interactively.

When you run `stigmer run` without arguments, an interactive picker lets you
search and select from available agents. With a reference argument, the CLI
resolves it as an agent slug, `org/slug`, or agent ID.

The command streams agent output to your terminal in real time — you see
messages, tool calls, and approval prompts as they happen. For scripting and CI
pipelines, use `--json` to receive newline-delimited event objects instead.

## Usage

```bash
stigmer run [agent] [flags]
```

### Common patterns

```bash
# Browse and select an agent interactively
stigmer run

# Run by slug
stigmer run my-agent

# Run by org-qualified slug
stigmer run acme-corp/variance-reporter

# Run with an initial prompt
stigmer run my-agent -m "Summarize the Q4 earnings report"
```

### Vaults this conversation uses

A run takes no keys on the command line. The keys your agent and its tools need
come from vaults: each turn uses your own My vault first, then the shared vaults
you name with `--vault`, in the order given; the first vault holding a key wins.
Save a key once and every later run finds it:

```bash
stigmer vault set-secret OPENAI_API_KEY --mine
```

| Flag            | Purpose                                                                      |
| --------------- | ---------------------------------------------------------------------------- |
| `--vault REF`   | A shared vault the conversation uses, by id, `org/slug` or slug (repeatable) |
| `--no-my-vault` | Leave your My vault out: the conversation uses only the `--vault` vaults     |

The conversation keeps this choice: `stigmer resume` continues it with the
vaults it was started with.

```bash
# Your own keys (the default)
stigmer run my-agent

# Your keys, then the team's ledger keys
stigmer run my-agent --vault ledger-keys

# The team's keys only
stigmer run my-agent --vault acme/ci-keys --no-my-vault
```

### Plugins this conversation uses

`--plugin REF` adds a plugin to the conversation, by id, `org/slug` or slug;
repeat it for more. The conversation gets the plugin's skills, agents, MCP
servers' tools and hooks, beside the agent's own; with no agent, the built-in
assistant runs with them. Like the vaults, the conversation keeps the plugins it
was started with.

```bash
# The assistant with one MCP server's tools
stigmer mcp add linear https://mcp.linear.app/mcp
stigmer run --plugin linear -m "What's on my plate this week?"

# An agent with two more plugins
stigmer run my-agent --plugin linear --plugin platform/github
```

### Environment this conversation runs in

`--environment REF` names the environment the conversation's sandbox runs in, by
id, `org/slug` or slug: the packages it installs and the websites it may reach.
Without it, the conversation runs in its agent's default environment, else its
organization's, else the server's standard sandbox. Like the vaults, the
conversation keeps the environment it was started with.

An environment applies only to a conversation in a sandbox the server starts.
Where the conversation runs on your own machine, or the server starts no
sandboxes, the server refuses an environment you name, and says so.

```bash
# Run in the data-science environment
stigmer run my-agent --environment data-science -m "Plot last week's signups"

# An environment your organization's parent shares with it
stigmer run my-agent --environment platform/base-tools
```

### Workspaces

Give your agent access to code repositories or local directories. Multiple
`--workspace` flags create a multi-root workspace (VS Code model).

```bash
# Local directory
stigmer run variance-reporter -w . -m "Report Q3's variances"

# Git repository
stigmer run variance-reporter --workspace https://github.com/acme/books -m "Report Q3's variances"

# Pin to a specific branch or commit
stigmer run variance-reporter --workspace https://github.com/acme/books --branch q3-close

# Multiple workspaces
stigmer run my-agent -w ./frontend -w ./backend
```

`--branch` and `--commit` apply only when a single git workspace is provided.

### Attach files

Give the agent files with your message. Each attached file is uploaded as a File
and sent with the message: the model sees an image as an image and any other
file as a document, and the agent finds every one under `.stigmer/uploads/` on
this turn and every later one. A message carries at most 20 files.

Attach a folder to give the conversation a whole tree: every file in it is
uploaded and kept under `.stigmer/uploads/<folder>/` with its relative path,
without being shown in the message. Hidden files and symbolic links are skipped,
and a conversation holds at most 500 files.

A file inside a local `--workspace` folder is not uploaded: the agent is pointed
to it where it is.

```bash
stigmer run data-analyzer --attach ./report.csv -m "Analyze this data"
stigmer run my-agent --attach ./image.png --attach ./spec.pdf
stigmer run my-agent --attach ./q3-ledgers -m "Reconcile these"
```

A file already uploaded (`stigmer file upload`, or the console's Library) is
named by its id with `--file-id`, without sending its bytes again. The
conversation gets its own copy, and the File stays yours to name again. Files
named this way count toward the message's 20 with the attached ones.

```bash
stigmer run finance-analyst --file-id file_01abc123 -m "Explain the Q3 variance"
```

### Output modes

| Flag        | Behavior                                                                              |
| ----------- | ------------------------------------------------------------------------------------- |
| _(default)_ | Interactive terminal UI powered by [`@stigmer/ink-ui`](/docs/sdk/ink/cli-integration) |
| `--json`    | One JSON line per session event (Claude Managed Agents events) for scripting and CI   |
| `--detach`  | Start the run and return immediately                                                  |

Use `--json` when piping output to other tools. Each line is one event of the
session's log, in Claude Managed Agents' JSON (`type`, `id`, `processed_at` and
the event's own fields); Stigmer's own events keep their `stigmer.*` type:

```bash
stigmer run my-agent --json -m "Process data" \
  | jq -r 'select(.type == "agent.message") | .content[].text'
```

Use `--detach` for a fire-and-forget run. The CLI prints the session ID and
exits. Check progress with `stigmer get session <id>`.

```bash
stigmer run my-agent --detach -m "Generate weekly report"
```

### In the session

On a terminal, `stigmer run` and `stigmer resume` open the session and keep it
open for follow-ups. The agent works on the server, so leaving is not stopping:

| Key                               | What it does                                                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Enter                             | Send the message                                                                                                                |
| `\` then Enter, Ctrl+J, Alt+Enter | Start a new line (Shift+Enter too, where the terminal reports it)                                                               |
| Up, Down                          | Earlier messages, kept per directory                                                                                            |
| Esc                               | Stop the agent's turn; a second Esc while it stops ends it now                                                                  |
| Ctrl+C                            | Clear the message; on an empty one, press twice to leave. The agent keeps working, and `stigmer resume <session-id>` comes back |
| Shift+Tab, Ctrl+T                 | Switch plan and agent mode                                                                                                      |
| Ctrl+O                            | Expand tool calls and thinking                                                                                                  |
| `?`                               | List the keys and commands                                                                                                      |

Type `/` for the commands: `/help`, `/mode plan` or `/mode agent`, `/stop` and
`/exit`. Type `@` to mention a file in the session's local folder
(`--workspace <dir>`): it is sent as a reference the agent reads in place.

### Run options

| Flag                | Purpose                                                                                                                                                                                                                       |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--model`           | Override the LLM model (e.g., `claude-sonnet-4-6`)                                                                                                                                                                            |
| `--harness`         | Choose the harness for the new session: `"stigmer"` or `"claude"` (Claude Agent)                                                                                                                                              |
| `--auto-approve`    | Approve all tool executions without prompting (bypasses approval policies)                                                                                                                                                    |
| `--approve-default` | Answer every tool call that asks, in non-interactive mode: `allow`, `deny`, or `allow-all` (allow it and every waiting call of its kind for the rest of the turn); unset denies each one, and the agent carries on without it |
| `--verbose`, `-v`   | Show run IDs and phase transitions in the TUI transcript                                                                                                                                                                      |

```bash
# Use a specific model
stigmer run my-agent --model claude-opus-4.6 -m "Analyze this codebase"

# Skip all approval prompts (use with caution)
stigmer run my-agent --auto-approve -m "Deploy to staging"
```

### Choosing a harness

The harness is the agent loop that runs your session: `"stigmer"` (Stigmer:
Stigmer's own harness, the default; it runs any catalog model, open source end
to end) or `"claude"` (Claude Agent: Anthropic's Claude Agent SDK; it runs
Claude models on your organization's own Anthropic key). A session keeps its
harness for life — `stigmer resume` always continues on the harness the session
started with.

You rarely need the flag. If your account declares a default harness (Account
settings → Execution defaults, or `default_harness` on your identity account),
`stigmer run` applies it automatically on Stigmer Cloud, and an omitted
`--model` fills from your default model for that harness. The flag is the
per-run override:

```bash
# Start a Claude Agent session explicitly
stigmer run variance-reporter --harness claude -w . -m "Report Q3's variances"

# Force one Stigmer run without changing your account's claude default
stigmer run my-agent --harness stigmer -m "Quick question"
```

When a session starts on the Claude Agent harness, the session header says so
(`Harness: Claude Agent`) — you always see the harness before output streams.

## Examples

### Interactive agent selection

```bash
stigmer run
```

A search picker appears. Type to filter agents by name or description. Select an
agent and start a conversation.

### Run with a message

```bash
stigmer run my-agent -m "Summarize the Q4 earnings report"
```

The agent receives the message and streams its response to the terminal.

### CI/CD pipeline with JSON output

```bash
stigmer run my-agent --json -m "Run integration tests" \
  --vault ci-keys \
  --auto-approve \
  | jq -r 'select(.type == "agent.message") | .content[].text'
```

Stream the session's events as JSON for programmatic consumption. Each line is
one complete event. Combine with `--auto-approve` to run without human
interaction.

### Git repository workspace

```bash
stigmer run variance-reporter \
  --workspace https://github.com/acme/books \
  --branch main \
  -m "Report Q3's variances from the ledgers in this repository"
```

The agent clones the repository, checks out the specified branch, and does the
job with full access to its files.

### Fire-and-forget run

```bash
stigmer run report-generator --detach -m "Generate the monthly report"
```

The CLI prints the session ID and exits immediately. Use
[`stigmer get session`](./get) to check progress, or
[`stigmer resume`](./resume) to re-attach to the live stream.
