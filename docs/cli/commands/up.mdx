Start the local Stigmer stack.

`stigmer up` brings up the complete local stack — managed Temporal, the
control-plane `stigmer-server`, and a unified execution runner — as a supervised
background daemon. This is the quickstart command for local development: no
cloud account needed.

On first run the CLI acquires the `stigmer-server` and runner packages at the
matching version. The server holds everything you create in one place of its
own, which it sets up the first time it starts, so no command asks you where
anything goes. Nothing else is installed: a conversation started with no agent
runs the built-in assistant, so a fresh install answers its first message at
once.

Before it calls agents ready, `stigmer up` checks the Anthropic key the runner
will use with Anthropic (or with the gateway in `ANTHROPIC_BASE_URL`), and the
card says what it found: `key checked just now`, `key not checked` when
Anthropic didn't answer, or `not ready  anthropic key rejected`. In a terminal,
when there's no key or the saved one is rejected, it asks for one first (press
Enter to skip), so the key you paste reaches the runner in this start. It never
asks when output isn't a terminal or with `--json` or `--quiet`, and never
prompts over an exported `ANTHROPIC_API_KEY`.

`stigmer up` returns once the runner is ready to take runs, so the first
`stigmer run` after it is picked up at once. When a part of the stack does not
start, it stops everything it started, exits non-zero, and says which part
failed, why, its last lines and how to see its full log, for example
`runner did not start: the runner exited with code 78 before it was ready`.

Use `stigmer up server` to start only the control plane (Temporal and
`stigmer-server`) when you manage your own runners — for example, the desktop
app with an embedded runner, your own customer code, or cloud sandboxes.

## Usage

```bash
stigmer up [flags]
```

### Common patterns

```bash
# Start the full local stack (server, runner, Temporal)
stigmer up

# Start only the control plane (no runners)
stigmer up server

# Check what is running
stigmer status

# Stop everything
stigmer down
```

## Examples

### Start the full local stack

```bash
stigmer up
```

The first run may take a moment while the server and runner are downloaded and
verified. Subsequent runs start immediately.

### Start only the control plane

```bash
stigmer up server
```

Starts Temporal and `stigmer-server` without any runner processes. Use this when
a separate process (desktop app, your own code, or a cloud sandbox) provides the
runner.

### Inspect and tear down

```bash
stigmer status   # show component health and the effective LLM configuration
stigmer down     # stop the stack
```

A stack that is already running, or still starting, is left alone: `stigmer up`
says so and exits. Stop it first with `stigmer down`.
