Make the configured backend a ready Stigmer.

A backend is ready when the `stigmer` organization exists. No default content is
installed: a conversation started with no agent runs the built-in assistant, so
a ready backend answers its first message without a single plugin. The official
marketplace's `defaults` list, which this command would install, is empty.
`stigmer up` does this for the local stack on its own; `stigmer bootstrap` is
for every other shape: a self-hosted server behind Docker Compose or Helm, or an
operator provisioning the hosted platform.

The command is idempotent. The organization is created only when it is missing;
a second run over a ready backend changes nothing. The command never deletes
anything.

## Usage

```bash
stigmer bootstrap [flags]
```

| Flag      | Type   | Default | Description                |
| --------- | ------ | ------- | -------------------------- |
| `--json`  | `bool` |         | emit the result as JSON    |
| `--quiet` | `bool` |         | print only the status line |

## Examples

### Bootstrap a self-hosted server

```bash
stigmer config backend add prod --endpoint stigmer.example.com:443 --api-key stk_...
stigmer config backend use prod
stigmer bootstrap
```

### Check a backend is ready from a script

```bash
stigmer bootstrap --json
```

The JSON carries a `System organization` section (`created` or `present`) and an
empty `Default plugins` section (the catalogue installs nothing by default).
