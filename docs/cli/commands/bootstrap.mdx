Make the configured backend ready for the CLI.

A backend is ready when the `stigmer` organization exists: the one the CLI uses
on a local or self-hosted backend when a command names none. Nothing else is
installed: a conversation started with no agent runs the built-in assistant, so
a ready backend answers its first message without a single plugin. `stigmer up`
does this for the local stack on its own; `stigmer bootstrap` is for a raw
self-hosted server behind Docker Compose or Helm, whether authentication is on
or off.

A team that created its organization in the console needs no bootstrap: point
the CLI at that organization with [`stigmer config context set --org`](./config)
instead.

The command is idempotent. The organization is created only when it is missing;
a second run over a ready backend changes nothing. The command never deletes
anything.

## Usage

```bash
stigmer bootstrap [flags]
```

| Flag      | Type   | Default | Description                |
| --------- | ------ | ------- | -------------------------- |
| `--json`  | `bool` |         | emit the result as JSON    |
| `--quiet` | `bool` |         | print only the status line |

## Examples

### Bootstrap a self-hosted server from a script

```bash
stigmer config backend add prod --endpoint stigmer.example.com:443 --api-key stk_...
stigmer config backend use prod
stigmer bootstrap
```

### Check a backend is ready

```bash
stigmer bootstrap --json
```

The JSON carries one `Organization` section: the slug, and its state, `created`
or `present`.
