Apply resource definitions to the Stigmer backend.

`stigmer apply` is the primary way to deploy agents, workflows, MCP servers, and
skills. It operates in two modes depending on what you point it at:

- **File mode** (`-f`): Apply individual YAML resource files or a directory of
  them.
- **Plugin mode**: When the path (or the working directory) holds a plugin
  manifest, the folder installs as one plugin, the same way
  `stigmer push plugin` does.

A folder of resources that belong together is a plugin. Run `stigmer apply` in
it, or `stigmer push plugin <dir>`, and every resource it carries lands as one
unit that can be upgraded and removed together.

## Usage

```bash
stigmer apply [flags]
```

### Common patterns

```bash
# Apply a single resource file
stigmer apply -f agent.yaml

# Apply all resources in a directory
stigmer apply -f ./manifests/

# Install the plugin in the current directory
stigmer apply

# Preview changes without applying
stigmer apply --dry-run
```

## Options

| Flag           | Type     | Default | Description                                                           |
| -------------- | -------- | ------- | --------------------------------------------------------------------- |
| `--dry-run`    | `bool`   |         | validate without applying                                             |
| `--file`, `-f` | `string` |         | path to a YAML file, a directory of YAML files, or a plugin directory |
| `--json`       | `bool`   |         | emit the result as JSON                                               |
| `--quiet`      | `bool`   |         | print only the status line                                            |

### File mode

Apply individual YAML files or entire directories of resources. Supports agents,
workflows, MCP servers, and multi-document YAML (separated by `---`).

```bash
# Apply a single file
stigmer apply -f agent.yaml

# Apply a workflow with dry-run
stigmer apply -f workflow.yaml --dry-run

# Apply all YAML files in a directory
stigmer apply -f ./manifests/
```

### Plugin mode

A directory whose root carries a plugin manifest (`plugin.json`,
`.cursor-plugin/plugin.json`, `.claude-plugin/plugin.json` or
`.codex-plugin/plugin.json`) is applied as a plugin: read, packaged and pushed
exactly as `stigmer push plugin <dir>` would. Its resources become the plugin's
members and are upgraded or removed with it.

```bash
# Install the plugin in the current directory
stigmer apply

# Install a plugin folder by path
stigmer apply -f ./my-plugin/
```

### Dry run

Use `--dry-run` to preview what would be applied without making changes. The CLI
validates resource definitions and reports what would be created or updated.

```bash
stigmer apply --dry-run
stigmer apply -f agent.yaml --dry-run
```

## Examples

### Apply a single agent definition

```bash
stigmer apply -f agent.yaml
```

Creates or updates the agent defined in the file. The CLI auto-detects the
resource kind from the YAML `kind` field.

### Deploy to a specific organization

```bash
stigmer apply -f agent.yaml --org acme-corp
```

### CI/CD deployment with machine-readable output

```bash
stigmer apply -f ./manifests/ --json --dry-run && stigmer apply -f ./manifests/ --json
```

Use `--json` for structured output in CI pipelines. Run with `--dry-run` first
to validate, then apply.
