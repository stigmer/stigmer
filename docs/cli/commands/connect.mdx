Connect to a plugin's MCP server and list its tools.

`stigmer connect plugin <plugin>` lists the tools one of a plugin's MCP servers
offers right now, reached as you: a runner of your organization starts or calls
the server with the keys and sign-ins in your own vault (My vault), and the
answer is printed. Nothing is stored; run it again whenever you want the current
list. A tool the server marks destructive is shown with `[destructive]`: a turn
asks a person before calling it.

## Usage

```bash
stigmer connect
```

## Subcommands

### stigmer connect plugin

list the tools one of a plugin's MCP servers offers, signing in first when it
needs one

```bash
stigmer connect plugin <plugin> [flags]
```

| Flag        | Type     | Default | Description                                                                        |
| ----------- | -------- | ------- | ---------------------------------------------------------------------------------- |
| `--dry-run` | `bool`   |         | list the tools from this machine, with your shell's environment, without a runner  |
| `--server`  | `string` |         | the MCP server, by its name in the plugin (needed when the plugin carries several) |
| `--timeout` | `string` | `30`    | bound --dry-run's local discovery                                                  |

### Choosing the server

A plugin with one MCP server needs no more than its name. A plugin with several
is refused with their names; pick one with `--server <name>`, the server's key
in the plugin's MCP configuration.

### Signing in

A server that signs in (an address that answers with an OAuth challenge) uses
the login saved in My vault at its address. When there is none, the command
opens the login page in your browser and waits until the sign-in is saved, then
lists the tools. A server that also accepts a pasted key is satisfied by a key
saved under its login key:

```bash
stigmer vault set-secret LINEAR_TOKEN --mine
stigmer connect plugin linear
```

Off an interactive terminal (CI, pipes) the command stops with these ways
instead of waiting for a browser. `--env` is refused, naming the vault command:
keys are never given on the command line.

### Missing keys

A key the server reads and none of your vaults hold fails the listing naming the
key. Save it in My vault and run the command again.

### Dry run

`--dry-run` lists the tools from this machine, without a runner: a local program
is started here with your shell's environment, and an address is called with the
plugin's headers. A `${VAR}` placeholder in a program's arguments or a header
resolves from your shell, else from the plugin's declared default, and a missing
one fails naming the variable. A server that accepts only a sign-in cannot be
listed this way, because its token lives in your vault on the server.

```bash
FILESYSTEM_ALLOWED_DIR="$HOME/projects" \
  stigmer connect plugin filesystem --dry-run
```

`--timeout` bounds the dry run's discovery, in seconds.

## Examples

### List a plugin's tools

```bash
stigmer connect plugin linear
```

### Pick one of several servers

```bash
stigmer connect plugin acme-tools --server issues
```

### Name the plugin's organization

```bash
stigmer connect plugin platform/github
```
