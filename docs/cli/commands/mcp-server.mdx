Start the MCP server that exposes Stigmer resources to AI coding assistants.

The MCP (Model Context Protocol) server lets tools like Cursor, Claude Desktop,
and Windsurf search, list, and inspect agents, skills, and workflows stored in
Stigmer. By default the server runs in STDIO mode — the MCP client spawns this
process and communicates over stdin/stdout.

When running via the CLI, the server address and API key are automatically
resolved from `~/.stigmer/config.yaml`. Local backends connect without
authentication; cloud backends use the stored token.

## Usage

```bash
stigmer mcp-server [flags]
```

### Common patterns

```bash
# Start in STDIO mode (default — what MCP clients spawn)
stigmer mcp-server

# Start in HTTP mode on a custom port
stigmer mcp-server --transport http --port 9090

# Start with debug logging
stigmer mcp-server --log-level debug
```

### Hosted remote server (mcp.stigmer.ai)

Stigmer Cloud runs this server as a hosted MCP endpoint so you do not have to
run it locally:

```
https://mcp.stigmer.ai
```

It supports two authentication styles that work side by side:

**Manual header (any client, any identity provider).** The server forwards your
`Authorization: Bearer <token>` header unchanged to `stigmer-server`, which
validates it. `<token>` can be a Stigmer API key (`stk_…`, created with
`stigmer apikey create`) or an access token from your organization's identity
provider. Point any MCP client that supports remote HTTP servers with custom
headers at the endpoint:

```json
{
  "mcpServers": {
    "stigmer": {
      "url": "https://mcp.stigmer.ai",
      "headers": { "Authorization": "Bearer stk_your_api_key" }
    }
  }
}
```

**OAuth connector (Claude Desktop, claude.ai, and other OAuth-only clients).**
The endpoint also implements OAuth 2.0 discovery (RFC 9728): it advertises an
authorization server so clients that only support an "Add custom connector" GUI
can sign in without a manually-supplied header. Paste `https://mcp.stigmer.ai`
into the connector dialog and complete the browser sign-in — the client
registers itself and obtains a token automatically.

This OAuth path signs you in through Stigmer's primary identity provider
(Auth0). If your organization brings its own identity provider, use the manual
header above (or run the server locally over STDIO) until per-org OAuth
discovery is available. The two styles are independent: enabling OAuth discovery
does not change the manual-header behavior.
