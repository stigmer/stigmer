Start many agents at the same moment on the server you are connected to, and see
how many started, how long each waited for a sandbox, and which were refused and
why. Use it to size a self-hosted fleet, or to check what happens when a whole
team starts an agent at once.

It makes one agent of its own (`load-test-<suffix>`, told to reply with one
word), starts every run together, each in a new conversation of its own, and
watches each one. When the burst is over it deletes every conversation it made,
and the agent, even when you press Ctrl-C. Nothing of yours is touched.

Each run spends real money on your model provider. `--max-usd` is the whole
burst's budget ($1 by default), split evenly across the runs: each run stops
once its own estimate reaches its share. One model call can go past a share, so
the bill can come in a little above the budget. The report adds up what the runs
say they spent.

## Usage

```bash
stigmer load-test [flags]
```

### Common patterns

```bash
# Start 25 agents at once on the active server
stigmer load-test --agents 25

# A bigger burst on a cheaper model, as JSON for a script
stigmer load-test --agents 100 --model claude-haiku-4-5 --max-usd 2 -o json > burst.json
```

## Options

| Flag             | Type     | Default | Description                                                                        |
| ---------------- | -------- | ------- | ---------------------------------------------------------------------------------- |
| `--agents`       | `string` |         | how many agents to start at the same moment (required)                             |
| `--max-usd`      | `string` |         | the whole burst's budget in US dollars, split evenly across the runs (default 1)   |
| `--message`      | `string` |         | what each agent is asked (default "Say hello in one word.")                        |
| `--model`        | `string` |         | the model each run uses; the agent's default when unset                            |
| `--output`, `-o` | `string` |         | output format: table, json, or yaml                                                |
| `--wait-minutes` | `string` |         | how long to watch for runs to start before calling them still waiting (default 20) |

### Reading the report

Each run gets one row. **START** says whether the agent started: `started`,
`refused` (the server answered the request with an error, quoted in the
summary), `wait ran out` (no sandbox had room within the server's wait),
`never started` (another ending before it started), or `still waiting` (the
watch, `--wait-minutes`, ended first).

**TO START** is the time from the server accepting the message to the agent
starting, from the server's own clock. **WAITED FOR A SANDBOX** is the longest
wait the server reported for the run while every sandbox was busy; the server's
own figure can be up to 15 seconds longer, so it reads `≥`. Only a fleet that
can run out of room (the Agent Substrate sandbox driver) ever reports a wait;
when no run did, the summary says so in its own line.

The summary counts each start, gives the median, 90th percentile and longest of
both times, groups the refusals by the server's own words, and adds up the
spend. `-o json` and `-o yaml` print the same report as one document, with each
run's ids and times in milliseconds.

The command exits 0 when the burst ran and was reported, whatever it found. It
exits 1 when the cleanup could not delete something, after listing it, and 130
after Ctrl-C, once the cleanup ran.
