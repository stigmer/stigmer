Manage the lifecycle of agent and workflow executions.

The execution type (agent vs workflow) is auto-detected from the ID prefix:

- Agent executions: aex\_`<ulid>`
- Workflow executions: wex\_`<ulid>`

### Lifecycle

cancel Gracefully cancel a running execution terminate Force-stop an execution
immediately pause Pause a running execution resume Resume a paused execution

### Observability

logs Stream or view execution event logs trace Show execution task structure and
timing

### Approval

approve Submit approval for a waiting execution

## Usage

```bash
stigmer execution
```

# Cancel a workflow execution
stigmer execution cancel wex_01abc123

## Subcommands

### stigmer execution approve

Submit an approval decision for an execution waiting on human input.

For workflow executions (wex\_): Requires --task and --outcome flags. Use
--data-file to submit form data for custom outcomes.

For agent executions (aex\_): Requires --tool-call and --action flags.

```bash
stigmer execution approve <execution-id> [flags]
```

| Flag          | Type     | Default   | Description                                         |
| ------------- | -------- | --------- | --------------------------------------------------- |
| `--action`    | `string` | `approve` | approval action: approve or deny (agent executions) |
| `--comment`   | `string` |           | approval comment                                    |
| `--data-file` | `string` |           | JSON file with form data (workflow executions)      |
| `--outcome`   | `string` | `approve` | approval outcome (workflow executions)              |
| `--task`      | `string` |           | task name to approve (workflow executions)          |
| `--tool-call` | `string` |           | tool call ID to approve (agent executions)          |

```bash
# Approve a workflow task
stigmer execution approve wex_01abc123 --task review --outcome approve

# Deny a workflow task with comment
stigmer execution approve wex_01abc123 --task review --outcome deny --comment "needs changes"

# Approve with form data
stigmer execution approve wex_01abc123 --task review --outcome approved --data-file form.json

# Approve an agent tool call
stigmer execution approve aex_01xyz789 --tool-call tc_abc --action approve

# Deny an agent tool call
stigmer execution approve aex_01xyz789 --tool-call tc_abc --action deny
```

### stigmer execution cancel

Cancel a running agent or workflow execution gracefully.

The execution type is auto-detected from the ID prefix (aex* or wex*). A
cancelled execution will stop at its next safe point and transition to the
"cancelled" phase.

```bash
stigmer execution cancel <execution-id> [flags]
```

| Flag       | Type     | Default | Description             |
| ---------- | -------- | ------- | ----------------------- |
| `--reason` | `string` |         | reason for cancellation |

```bash
stigmer execution cancel aex_01abc123
stigmer execution cancel wex_01xyz789 --reason "no longer needed"
```

### stigmer execution logs

View event logs for an agent or workflow execution.

By default shows recent events. Use --follow to stream live events. For workflow
executions, use --task to filter events by task name.

```bash
stigmer execution logs <execution-id> [flags]
```

| Flag             | Type     | Default | Description                                |
| ---------------- | -------- | ------- | ------------------------------------------ |
| `--follow`, `-f` | `bool`   |         | stream live events                         |
| `--task`         | `string` |         | filter events by task name (workflow only) |

```bash
# Show recent events
stigmer execution logs wex_01abc123

# Stream live events
stigmer execution logs wex_01abc123 --follow

# Filter by task name
stigmer execution logs wex_01abc123 --task validate_email

# Stream agent execution messages
stigmer execution logs aex_01xyz789 --follow
```

### stigmer execution pause

Pause a running agent or workflow execution.

A paused execution can be resumed later with 'stigmer execution resume'. Running
activities are gracefully stopped and checkpoints are saved.

```bash
stigmer execution pause <execution-id> [flags]
```

| Flag       | Type     | Default | Description        |
| ---------- | -------- | ------- | ------------------ |
| `--reason` | `string` |         | reason for pausing |

```bash
stigmer execution pause aex_01abc123
stigmer execution pause wex_01xyz789 --reason "waiting for review"
```

### stigmer execution resume

Resume a previously paused agent or workflow execution.

The execution continues from its last checkpoint.

```bash
stigmer execution resume <execution-id>
```

```bash
stigmer execution resume aex_01abc123
stigmer execution resume wex_01xyz789
```

### stigmer execution terminate

Terminate an execution immediately without cleanup.

Unlike cancel, terminate does not wait for a safe stopping point. The execution
transitions directly to "terminated" phase. Terminated executions cannot be
recovered.

```bash
stigmer execution terminate <execution-id> [flags]
```

| Flag       | Type     | Default | Description            |
| ---------- | -------- | ------- | ---------------------- |
| `--reason` | `string` |         | reason for termination |

```bash
stigmer execution terminate aex_01abc123
stigmer execution terminate wex_01xyz789 --reason "stuck execution"
```

### stigmer execution trace

Show the execution structure as a task tree with status and timing.

For workflow executions: shows task DAG with status, timing, and errors. For
agent executions: shows tool call timeline.

Use --output yaml|json for structured data output.

```bash
stigmer execution trace <execution-id> [flags]
```

| Flag             | Type     | Default | Description                      |
| ---------------- | -------- | ------- | -------------------------------- |
| `--output`, `-o` | `string` | `table` | output format: table, yaml, json |

```bash
# Show workflow execution trace
stigmer execution trace wex_01abc123

# Show agent execution trace
stigmer execution trace aex_01xyz789

# Output as YAML
stigmer execution trace wex_01abc123 -o yaml
```
