Save the keys and sign-ins your runs use, as credentials that belong to you or
to your organization.

A credential holds named values: a field named `OPENAI_API_KEY` fills the key of
the same name that an agent, an MCP server or a git host needs. Your own
credentials are used by the runs you start, for whatever they serve. An
organization's credential is created by an admin, used by the people and teams
the admin allows, and is write-only: its values can be replaced, never read
back.

A credential is created with its values and never applied from a file, because a
secret does not belong in a manifest. Reading and deleting use the unified
verbs: `stigmer get credential`, `stigmer list credentials` and
`stigmer delete credential`.

## Usage

```bash
stigmer credential
```

### Common patterns

```bash
# Save your own OpenAI key, read from your shell so it stays out of history
stigmer credential create OpenAI --from-env OPENAI_API_KEY

# Save your Linear key and use it whenever an agent calls the Linear server
stigmer credential create Linear --field LINEAR_API_KEY=lin_api_xxx \
  --serves mcp-server:linear

# Save the organization's Datadog key for the incident agent (admins)
stigmer credential create "Datadog (on-call)" --org-owned \
  --from-env DD_API_KEY --plain DD_SITE=datadoghq.com \
  --serves agent:incident-agent

# Replace one value, keeping the rest
stigmer credential set-fields openai-3f9a --from-env OPENAI_API_KEY

# Print one value of your own credential
stigmer credential reveal openai-3f9a OPENAI_API_KEY

# See the credentials you may use (via unified verb)
stigmer list credentials
```

### Values

| Flag                | Stored as                                                   |
| ------------------- | ----------------------------------------------------------- |
| `--field KEY=VALUE` | A secret: encrypted at rest and redacted when read          |
| `--from-env KEY`    | A secret, read from your shell's `KEY` environment variable |
| `--plain KEY=VALUE` | Plain configuration, stored and shown as it is              |

`stigmer credential reveal` prints a secret of your own credential, one field at
a time.

Each flag is repeatable, and a key may be given once. A field name is letters,
digits and underscores, not starting with a digit. Prefer `--from-env` for a
secret: a value typed on the command line stays in your shell's history.

### What a credential serves

`--serves` names what the credential is used for by default, and is repeatable:

| Target        | Example                |
| ------------- | ---------------------- |
| An agent      | `agent:incident-agent` |
| An MCP server | `mcp-server:linear`    |
| A git host    | `git-host:github.com`  |

An agent or MCP server may be named as `org/slug`. At most one of your
credentials, and one of the organization's, may serve the same target. When a
run starts, a key it needs comes from your own credential serving the agent,
server or host first, then from an organization credential serving it that you
may use. A run with nobody behind it, such as a schedule's, uses the credentials
assigned on the schedule instead.

### Names

The name is how you tell your credentials apart. The slug is made from the name
with a short random ending, so two people's `OpenAI` credentials never collide.
Use the slug, `org/slug` or the `cred_` id to name a credential in the other
commands.
