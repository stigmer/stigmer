Push an artifact to the Stigmer registry.

`stigmer push` packages and uploads two kinds of artifact. A **skill** is a
directory holding a `SKILL.md`, pushed from a local directory or directly from a
remote git repository. A **plugin** is a directory in the Agent Plugins, Cursor,
Claude Code or Codex layout; pushing it installs the plugin, or upgrades it when
it is already installed, and Stigmer materializes its skills, MCP servers, agent
and workflows in your organization as one unit.

## Usage

```bash
stigmer push <type> [path] [flags]
```

### Common patterns

```bash
# Push a skill from the current directory
stigmer push skill

# Push from a specific directory
stigmer push skill ./my-skill/

# Push with a version tag
stigmer push skill --tag v1.2.0

# Preview without pushing
stigmer push skill --dry-run

# Install a plugin from its folder (or upgrade the installed one)
stigmer push plugin ./thermos

# See what a plugin would install, offline
stigmer push plugin ./thermos --dry-run
```

### Plugins

`stigmer push plugin <dir>` reads the folder the way `stigmer validate -f <dir>`
does, refuses offline with the same sentences, and pushes the whole folder as
one archive. The plugin's version is its manifest's `version`, so `--tag` does
not apply; `--visibility` sets the level for the plugin and every resource it
installs. Pushing an unchanged folder again changes nothing. The resources a
plugin installs are the plugin's to redefine: edit the plugin and push it again
rather than editing them directly, or compose your own agent over its skills and
servers. `stigmer delete plugin <name>` removes everything it installed.

### Source modes

**Local push** (default): Packages the current directory (or the path you
specify). The CLI reads `SKILL.md` to identify the artifact and respects
`.gitignore` patterns for file filtering.

```bash
# Push from current directory
stigmer push skill

# Push from a specific path
stigmer push skill ./my-skill/
```

**Remote push**: Push directly from a git repository without cloning locally.
Use `--subdir` when the artifact lives in a subdirectory of the repo.

```bash
# Push from a git repository
stigmer push skill --git-url https://github.com/acme/skills --subdir api-validator

# Push a specific version
stigmer push skill --git-url https://github.com/acme/skills --git-ref v2.0.0
```

**Archive push**: Push a ZIP you already built, byte-for-byte. The registered
version hash is the SHA-256 of the file itself, so it matches any checksum your
release pipeline published for the artifact. The archive must contain `SKILL.md`
at its root; packaging flags (`--ignore`, `--include`, `--no-gitignore`) don't
apply since packaging already happened.

```bash
# Push a pre-packaged skill archive as-is
stigmer push skill --archive dist/my-skill.zip --tag v1.2.3 -m "release v1.2.3"

# Validate the archive without pushing
stigmer push skill --archive dist/my-skill.zip --dry-run
```

### Version identity

A skill version is identified by the SHA-256 of its uploaded ZIP, and the CLI
packages directories deterministically (sorted entries, fixed timestamps):
pushing unchanged content produces the same bytes — and therefore the same
version — no matter when or where the push runs. A CI job that pushes on every
merge only registers a new version when the skill's content actually changed;
unchanged pushes report `Status: unchanged`.

### File filtering

By default, the CLI respects `.gitignore` patterns. Use `--ignore` and
`--include` to customize:

```bash
# Ignore additional patterns
stigmer push skill --ignore "*.test.md" --ignore "drafts/"

# Force-include files that would be ignored
stigmer push skill --include "data/*.csv"

# Disable gitignore entirely
stigmer push skill --no-gitignore
```
