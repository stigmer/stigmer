# CLI Quickstart

You will install the Stigmer CLI, define an Agent in YAML, deploy it to your local StigmerServer, and run it. By the end, you will have a working Agent that responds to prompts using the tools and instructions you gave it.

---

## Prerequisites

Before you begin, make sure you have:

- [ ] **macOS or Linux** (Windows is not yet supported)
- [ ] **Docker** running on your machine (the AgentRunner runs in a container)

<details>
<summary>Install Docker</summary>

```bash
# macOS
brew install --cask docker

# Linux
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
```

Start Docker Desktop (macOS) or the Docker daemon (Linux), then verify:

```bash
docker info
```

</details>

---

## Step 1: Install the Stigmer CLI

```bash
# macOS / Linux
brew install stigmer/tap/stigmer
```

If you do not use Homebrew, download the binary directly:

```bash
curl -sSL https://stigmer.ai/install.sh | bash
```

Verify the installation:

```bash
stigmer version
```

Expected output:

```text
stigmer version 0.x.x
```

---

## Step 2: Create your first agent

Create a file named `agent.yaml` with the following contents:

```yaml
apiVersion: agentic.stigmer.ai/v1
kind: Agent
metadata:
  name: my-assistant
  org: default
spec:
  description: "A helpful assistant that answers questions clearly and concisely"
  instructions: |
    You are a helpful assistant.
    Answer questions clearly, concisely, and accurately.
    When you do not know the answer, say so.
```

Key fields:

| Field | Purpose |
| ----- | ------- |
| `metadata.name` | Unique identifier for the agent within the Organization |
| `metadata.org` | The Organization this agent belongs to (`default` for local mode) |
| `spec.instructions` | The system prompt that defines agent behavior |
| `spec.description` | Human-readable summary shown in agent listings |

---

## Step 3: Deploy the agent

```bash
stigmer apply -f agent.yaml
```

This command sends the agent definition to your local StigmerServer. On first run, the server starts automatically — no manual `stigmer server start` required.

Expected output:

```text
✓ Agent my-assistant created
```

---

## Step 4: Run the agent

```bash
stigmer run my-assistant "What is Stigmer?"
```

The CLI creates an AgentExecution, streams the response in real time, and exits when the agent finishes.

Expected output:

```text
Stigmer is an open-source platform for building, running, and managing
AI agents and automation workflows...
```

The exact response depends on the LLM model configured on your server (local Ollama by default).

---

## Verify it works

List your agents to confirm the deployment:

```bash
stigmer list agents
```

You should see output similar to:

```text
AGENT ID          NAME            CREATED
agt-abc123        my-assistant    2026-03-21 10:30:00
```

If `stigmer list agents` returns an empty list, check that `stigmer apply -f agent.yaml` completed without errors. If the server failed to start, run `stigmer server start --debug` to see detailed logs.

---

## What you built

In this quickstart, you:

- Installed the Stigmer CLI on your machine
- Defined an Agent as a declarative YAML resource
- Deployed the agent to your local StigmerServer with `stigmer apply`
- Ran the agent and received a streamed response with `stigmer run`
- Verified the agent appears in your agent inventory

The Agent YAML you wrote is portable — the same file works on your laptop and in Stigmer Cloud without changes. Only the environment binding (credentials, LLM provider) differs between local and production.
