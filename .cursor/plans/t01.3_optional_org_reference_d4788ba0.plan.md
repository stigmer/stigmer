# T01.3: Make `org` Optional in `ApiResourceReference`

## Domain Analysis (Architect Review)

### The Critique

`ApiResourceReference` currently serves two semantically distinct roles:

- **Authoring references** (user-facing): `skill_refs`, `mcp_server_usages` in agent specs — where org should be relative/inferrable from context
- **System references** (machine-facing): `getByReference` RPC inputs, `ProjectSpec.members`, `ReconciliationSummary` — where org is always resolved/absolute

Making `org` optional at the type level affects both contexts simultaneously. In strict DDD terms, these could be different value objects with different invariants.

### Why a Single Type Is Correct Here

Splitting into two types would be over-engineering. The semantics are clear and established:

- Empty `org` = "resolve from context" (same pattern as the `version` field, where empty means "resolve to latest")
- The server normalizes at write time (T01.4), so all stored and returned references are always absolute
- The proto-level optionality is a wire-format convention, not a domain invariant violation

The existing codebase already uses this exact pattern in two places:

- `ApiResourceReference.version` (line 89 of [io.proto](apis/ai/stigmer/commons/apiresource/io.proto)): `^$|^latest$|...`
- `SearchRequest.org` (line 71 of [search/v1/io.proto](apis/ai/stigmer/search/v1/io.proto)): `^$|^[a-z][a-z0-9-]*$`

### Downstream Safety Analysis

The change is **backward compatible** — every existing reference with an explicit `org` continues to pass validation. The relaxation only allows *additionally* empty `org`:

- **Server backend**: `[load_by_reference.go](backend/libs/go/grpc/request/pipeline/steps/load_by_reference.go)` already handles empty org gracefully (slug-only lookup when org is empty). No server code changes needed.
- **CLI**: CLI appliers already fill `metadata.Org` from `resolveApplyOrganization()`, and `[buildResourceReference()](client-apps/cli/cmd/stigmer/root/apply_file_handlers.go)` copies `metadata.Org`. No CLI code changes needed.
- **RPC inputs**: `getByReference` RPCs technically accept empty org after this change, but every caller (CLI, internal) always resolves org before calling. No practical risk.
- **buf lint**: `FIELD_NOT_REQUIRED` is already excepted in [buf.yaml](apis/buf.yaml) line 13.
- **buf breaking**: Annotation changes don't trigger proto-level breaking change detection.

## The Change

**Single file**: `[apis/ai/stigmer/commons/apiresource/io.proto](apis/ai/stigmer/commons/apiresource/io.proto)`, lines 47-59

### Current

```proto
message ApiResourceReference {
  // Organization that owns the referenced resource. Required.
  // Format: lowercase alphanumeric with hyphens, must start with a letter (e.g., "stigmer", "acme-corp").
  // Length: 1-63 characters.
  string org = 1 [
    (buf.validate.field).required = true,
    (buf.validate.field).string.pattern = "^[a-z][a-z0-9-]*$",
    (buf.validate.field).string.min_len = 1,
    (buf.validate.field).string.max_len = 63
  ];
```

### Proposed

```proto
message ApiResourceReference {
  // Organization that owns the referenced resource.
  //
  // When non-empty: must be a valid org slug (lowercase alphanumeric with hyphens,
  // starts with a letter, 1-63 characters). Example: "stigmer", "acme-corp".
  //
  // When empty: the reference is relative — the server resolves it to the parent
  // resource's organization at write time. All stored and returned references
  // always have org populated (absolute form).
  //
  // Use empty org for same-org references (the common case).
  // Use explicit org for cross-org references (e.g., marketplace resources).
  string org = 1 [
    (buf.validate.field).string.max_len = 63,
    (buf.validate.field).string.pattern = "^$|^[a-z][a-z0-9-]*$"
  ];
```

### What Changes in Validation


| Constraint        | Before              | After         | Rationale                                                          |
| ----------------- | ------------------- | ------------- | ------------------------------------------------------------------ |
| `required = true` | Present             | **Removed**   | Empty org is now valid                                             |
| `pattern`         | `^[a-z][a-z0-9-]*$` | `^$           | ^[a-z][a-z0-9-]*$`                                                 |
| `min_len = 1`     | Present             | **Removed**   | Redundant — non-empty branch of pattern already enforces >= 1 char |
| `max_len = 63`    | Present             | **Unchanged** | Still applies when non-empty                                       |
